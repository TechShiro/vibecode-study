Grid & Constraint Puzzles

When the state you mutate is the board itself: mark a cell, place a queen, pencil in a digit — explore — then erase. Plus the line between "TLE" and "accepted": pruning, and knowing when backtracking is secretly DP.

Mission link: Word Search and N-Queens are canonical onsite questions; Sudoku Solver is the classic "can you code under pressure" screen. This is the final lesson of the 3-lesson backtracking track. Mission

1 · The one idea

So far path was a private list. In puzzles, the shared mutable state is the input structure itself: choose = write into the board (mark a visited cell, place a 'Q', fill a digit), explore = recurse, unchoose = erase your write. Two upgrades make these pass instead of TLE: (1) check constraints before recursing, never generate-then-validate at the leaves; and (2) make each check O(1) by maintaining occupancy sets/arrays (columns, diagonals, rows/boxes) alongside the board instead of rescanning it.

Recognition trigger "Does this word exist in the grid" (path through adjacent cells, no cell reused), "place n things so none attack / conflict," "fill the board so every row/column/region is valid." The state is 2-D, moves are local, and a placement can invalidate later placements — that feedback loop (place → maybe dead end → undo) is backtracking's home turf.

2 · Core template — Word Search (LC 79)

DFS from every cell; consume one matching character per step; mark the current cell in-place so the path can't reuse it; restore it on the way out. The board is the visited set. 

boolean exist(char[][] board, String word) {
    for (int r = 0; r < board.length; r++)
        for (int c = 0; c < board[0].length; c++)
            if (dfs(board, word, r, c, 0)) return true;   // try every start cell
    return false;
}

boolean dfs(char[][] b, String w, int r, int c, int i) {
    if (i == w.length()) return true;     // consumed the whole word → found
    if (r < 0 || c < 0 || r >= b.length || c >= b[0].length
        || b[r][c] != w.charAt(i))        // out of bounds, wrong char, or '#' (visited)
        return false;
    char saved = b[r][c];
    b[r][c] = '#';                        // CHOOSE: mark in place — no separate visited[][]
    boolean found = dfs(b, w, r + 1, c, i + 1) || dfs(b, w, r - 1, c, i + 1)
                 || dfs(b, w, r, c + 1, i + 1) || dfs(b, w, r, c - 1, i + 1);
    b[r][c] = saved;                      // UNCHOOSE: ALWAYS restore, found or not
    return found;
}

Time O(m·n·3L) — m·n starts, and after the first step each cell has at most 3 unvisited neighbors (you can't go back where you came from), depth L = word length. Space O(L) recursion. Note the short-circuit ||: the first successful direction stops the rest — free pruning.

The unmark bug If you restore the cell only on failure (or forget it inside an early return), later searches see a board littered with '#' and miss real answers. Structure the code so the restore line is unconditionally after the recursive calls — like above — and it can't be skipped.

Case: N-Queens — column & diagonal sets (LC 51)

Key modeling move: exactly one queen per row, so recurse row by row and only choose the column. Geometry fact: cells on the same "\" diagonal share r − c; cells on the same "/" diagonal share r + c. Three boolean arrays make "is this square attacked?" O(1) — no board scanning. 

List<List<String>> res = new ArrayList<>();
boolean[] cols, d1, d2;                   // d1: r-c (offset by n-1), d2: r+c
int[] queenCol;                           // queenCol[r] = chosen column in row r

List<List<String>> solveNQueens(int n) {
    cols = new boolean[n];
    d1 = new boolean[2 * n - 1];
    d2 = new boolean[2 * n - 1];
    queenCol = new int[n];
    bt(0, n);
    return res;
}
void bt(int r, int n) {
    if (r == n) { res.add(build(n)); return; }        // all n rows filled → solution
    for (int c = 0; c < n; c++) {
        if (cols[c] || d1[r - c + n - 1] || d2[r + c]) continue; // attacked → prune, O(1)
        cols[c] = d1[r - c + n - 1] = d2[r + c] = true;          // CHOOSE: occupy 3 lines
        queenCol[r] = c;
        bt(r + 1, n);                                            // EXPLORE next row
        cols[c] = d1[r - c + n - 1] = d2[r + c] = false;         // UNCHOOSE: free all 3
    }
}
List<String> build(int n) {               // render queenCol[] as the board strings
    List<String> rows = new ArrayList<>();
    for (int r = 0; r < n; r++) {
        char[] row = new char[n];
        Arrays.fill(row, '.');
        row[queenCol[r]] = 'Q';
        rows.add(new String(row));
    }
    return rows;
}

Time O(n!) branch bound (row r has ≤ n−r safe columns), each solution rendered in O(n²). Space O(n). LC 52 (N-Queens II) is this code with a counter instead of build().

Case: Sudoku Solver — find one solution and stop (LC 37)

New wrinkle: you don't want all solutions, just one. So the recursion returns boolean and success propagates up immediately — a true from below means "don't undo, don't try more digits, we're done." 

boolean solve(char[][] b) {
    for (int r = 0; r < 9; r++)
        for (int c = 0; c < 9; c++) {
            if (b[r][c] != '.') continue;             // find the next empty cell
            for (char d = '1'; d <= '9'; d++) {
                if (!ok(b, r, c, d)) continue;        // prune before recursing
                b[r][c] = d;                          // CHOOSE
                if (solve(b)) return true;            // solved below → LEAVE d in place, bubble up
                b[r][c] = '.';                        // UNCHOOSE only on failure
            }
            return false;                             // empty cell, no digit fits → dead branch
        }
    return true;                                      // no empty cell left → board solved
}
boolean ok(char[][] b, int r, int c, char d) {
    for (int i = 0; i < 9; i++) {
        if (b[r][i] == d || b[i][c] == d) return false;          // row + column
        if (b[3 * (r / 3) + i / 3][3 * (c / 3) + i % 3] == d)    // 3×3 box
            return false;
    }
    return true;
}

Time O(9E) worst case over E empty cells — fine for a fixed 9×9; say "bounded exponential, heavily pruned in practice." Space O(E) recursion. Speed-up worth mentioning: keep boolean[9][9] rowHas/colHas/boxHas (or int bitmasks) so ok() becomes O(1), exactly the N-Queens trick.

The two Sudoku bugs everyone writes (1) Not returning after success: if you recurse without if (solve(b)) return true;, the unwind erases the solved board. Success must skip the unchoose. (2) Missing the return false after the digit loop: an empty cell where nothing fits must fail the branch — falling through to the next cell "solves" an unsolvable board.

4 · Pruning: the difference between TLE and pass

All three problems above are exponential in theory; they pass because invalid branches die at birth. The hierarchy, weakest to strongest:

  • Generate-then-validate (never do this): build every complete candidate, test at the leaf. Generate Parentheses this way is 22n instead of Catalan; N-Queens becomes nn.
  • Check before recursing: the if (!ok(...)) continue; guard. Kills a whole subtree per rejected choice. This is the default you should always write.
  • O(1) checks via auxiliary state: occupancy arrays (N-Queens cols/d1/d2, Sudoku bitmasks). Same tree, each node 10–100× cheaper.
  • Feasibility bounds: "can the remainder even work?" — LC 93's remaining-length check, LC 77's n − (k − size) + 1 loop bound, LC 39's sorted break. These skip branches that are legal now but doomed later.

In an interview, narrate the prune as you write it — pruning insight is what's actually being graded on these questions.

5 · When backtracking is really DP in disguise

Word Break (LC 139): "can s be split into dictionary words?" The natural code is Palindrome-Partitioning backtracking that returns a boolean. It TLEs on inputs like "aaaa…b" — because the subproblem "can the suffix starting at start be split?" is recomputed exponentially many times. But that subproblem depends only on start: n distinct states. Memoize and it collapses to O(n²)-ish: 

Boolean[] memo;                           // memo[start]: can s[start..] be segmented?
boolean wordBreak(String s, List<String> dict) {
    memo = new Boolean[s.length()];
    return bt(s, 0, new HashSet<>(dict));
}
boolean bt(String s, int start, Set<String> dict) {
    if (start == s.length()) return true;
    if (memo[start] != null) return memo[start];      // seen this suffix → reuse
    for (int end = start + 1; end <= s.length(); end++)
        if (dict.contains(s.substring(start, end)) && bt(s, end, dict))
            return memo[start] = true;
    return memo[start] = false;                       // cache failures too — that's the speedup
}

The litmus test: if the question asks for all solutions, the output is exponential and backtracking is correct as-is (memoizing can't help — LC 131, 46, 51). If it asks for a boolean, a count, or a best value, and your recursion's state is a small tuple (an index, a remaining amount), the subproblems overlap → memoize → you're doing top-down DP. Backtracking explores a tree; DP notices the tree keeps revisiting the same nodes and collapses it into a DAG.

6 · Edge-case checklist

  • Restore in-place marks unconditionally (LC 79). Put the restore after the recursion block, never inside a conditional or before an early return path.
  • 1×1 board, word longer than cell count, first char mismatch everywhere — the bounds/char guard at the top of dfs handles all of these; keep it as the first lines.
  • Diagonal indexing: r − c ranges over negative values — offset by n − 1; both diagonal arrays have size 2n − 1. An ArrayIndexOutOfBounds here means you forgot the offset.
  • Stop-at-first vs collect-all: boolean-returning recursion with if (rec()) return true; for one solution (LC 37, 79); void recursion that records and keeps going for all solutions (LC 51). Mixing the two either misses answers or destroys the found one.
  • Sudoku's return false after trying all digits on an empty cell — omitting it silently skips unsolvable cells.
  • n = 1 N-Queens is solvable (answer ["Q"]); n = 2, 3 have zero solutions — an empty result list is valid output, not a bug.
  • Before memoizing, confirm the state is self-contained: memo keyed by start is only valid if the answer for that suffix doesn't depend on the path taken to reach it. True in Word Break; false in Word Search (the visited cells differ per path) — which is why LC 79 can't be memoized.
