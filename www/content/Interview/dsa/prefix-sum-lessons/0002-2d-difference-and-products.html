2D Prefix Sums, Difference Arrays & Prefix Products

The same odometer trick generalized: rectangles by inclusion-exclusion, bulk range updates by bookending, and "sum" swapped for product or XOR.

Mission link: Range Sum 2D and Product Except Self are two of the most-asked "easy-medium" screens at Meta and Amazon — fast, clean solutions here buy time for the hard question. This is Lesson 2 of the 2-lesson prefix-sum track. Mission

1 · The one idea

Lesson 1's engine was: precompute cumulative values so a query becomes arithmetic on two of them. That engine has three more gears. 2D: a cumulative rectangle table answers any sub-rectangle sum with four lookups (inclusion-exclusion). Inverse: a difference array is a prefix sum run backwards — record range updates as two endpoint marks, then one prefix pass materializes them all. Other operators: anything with an inverse or a "cancel" works — products (divide, or prefix×suffix), XOR (its own inverse).

Recognition trigger 2D prefix: "sum of a sub-rectangle / region", many queries, immutable matrix. Difference array: "apply k range updates (add v to [l, r]) then report the final array" — booking seats, flight bookings, meeting-room loads. Prefix product / XOR: "product of everything except me", "XOR of a subarray", division forbidden.

2 · Core template — 2D prefix sum (LC 304)

Define S[r][c] = sum of the rectangle from (0,0) to (r−1,c−1) — again one extra row and column of zeros so there's no special-casing at the edges. Build and query both use the same picture: big rectangle − strip above − strip left + doubly-subtracted corner. 

class NumMatrix {
    private final int[][] S;                       // S[r][c] = sum of matrix[0..r-1][0..c-1]
    public NumMatrix(int[][] m) {
        int R = m.length, C = m[0].length;
        S = new int[R + 1][C + 1];                 // padded row 0 / col 0 stay zero — no edge cases
        for (int r = 1; r <= R; r++)
            for (int c = 1; c <= C; c++)
                S[r][c] = m[r-1][c-1] + S[r-1][c] + S[r][c-1] - S[r-1][c-1];
                // cell + above + left − overlap (counted twice)
    }
    public int sumRegion(int r1, int c1, int r2, int c2) {   // inclusive corners
        return S[r2+1][c2+1] - S[r1][c2+1] - S[r2+1][c1] + S[r1][c1];
        // whole − top strip − left strip + corner A added back
    }
}

Time O(R·C) build, O(1) per query. Space O(R·C). The +1 padding is the same n+1 convention from Lesson 1, now in two dimensions.

Case: difference array — range updates in O(1) each (LC 1109)

Naive: adding v to every seat in [l, r], for each of k bookings, is O(k·n). Insight: a prefix pass turns "point marks" into "running effect". So mark only the endpoints: +v where the effect starts, −v just after it ends. One final prefix sum sweeps left to right, switching each booking on at l and off after r. It's the exact inverse of Lesson 1: there we differenced prefix sums to read ranges; here we prefix-sum differences to write them. 

int[] corpFlightBookings(int[][] bookings, int n) {
    int[] d = new int[n + 1];              // one extra slot so r+1 never overflows
    for (int[] b : bookings) {             // b = {l, r, v}, 1-indexed flights
        d[b[0] - 1] += b[2];               // effect switches ON at l
        d[b[1]]     -= b[2];               // and OFF just after r  (index r+1−1 = b[1])
    }
    int[] ans = new int[n];
    int run = 0;
    for (int i = 0; i < n; i++) {
        run += d[i];                       // prefix pass materializes all updates at once
        ans[i] = run;
    }
    return ans;
}

Time O(n + k) instead of O(n·k). Space O(n). This is the go-to whenever all updates happen before any read.

Case: Product of Array Except Self (LC 238)

ans[i] = product of everything left of i × product of everything right of i. Division would be easy but is banned (and breaks on zeros). So do two sweeps: fill ans with prefix products going left→right, then multiply in suffix products going right→left, carried in a single variable — O(1) extra space. 

int[] productExceptSelf(int[] a) {
    int n = a.length;
    int[] ans = new int[n];
    ans[0] = 1;                            // empty prefix product = 1 (the multiplicative "0")
    for (int i = 1; i < n; i++)
        ans[i] = ans[i - 1] * a[i - 1];    // ans[i] = product of a[0..i-1]
    int suffix = 1;                        // product of a[i+1..n-1], built on the way back
    for (int i = n - 1; i >= 0; i--) {
        ans[i] *= suffix;                  // left product × right product
        suffix *= a[i];                    // extend suffix AFTER using it (excludes a[i])
    }
    return ans;
}

Time O(n). Space O(1) beyond the output. The prefix/suffix pair pattern also cracks "best split point" problems: precompute something-from-the-left and something-from-the-right, then scan the seam.

Case: prefix XOR — subarray XOR in O(1) (LC 1310)

XOR cancels itself (x ^ x = 0), so it has a built-in "subtraction". Define X[k] = XOR of the first k elements; then everything before i cancels out of X[j+1] ^ X[i], leaving exactly the subarray: 

int[] xorQueries(int[] a, int[][] queries) {
    int n = a.length;
    int[] X = new int[n + 1];              // X[0] = 0 — the empty prefix again
    for (int k = 0; k < n; k++)
        X[k + 1] = X[k] ^ a[k];
    int[] ans = new int[queries.length];
    for (int q = 0; q < queries.length; q++)
        ans[q] = X[queries[q][1] + 1] ^ X[queries[q][0]]; // xor(i..j) = X[j+1] ^ X[i]
    return ans;
}

Time O(n + q). Space O(n). Bonus: the Lesson-1 HashMap dial works here too — LC 1442 counts pairs with equal prefix-XOR exactly like LC 974 counts equal remainders.

What generalizes and what doesn't Prefix-and-subtract needs an inverse: sum has minus, XOR has itself, product has divide (but zeros kill it — hence prefix×suffix). min/max have no inverse, so "range min via prefix mins" doesn't exist — that's sparse-table / segment-tree territory. Saying this unprompted is an interview signal.

4 · Edge-case checklist

  • 2D padding: size the table (R+1)×(C+1) and shift reads by +1, or you'll be guarding r−1 < 0 everywhere. Sign errors in the 4-term formula: exactly two minuses and one plus.
  • Difference array bounds: the −v goes at r+1 — allocate n+1 so the last range doesn't overflow. Watch 1-indexed inputs (LC 1109's flights are 1..n).
  • Difference arrays are write-then-read. If reads interleave with updates, you need a Fenwick/segment tree instead.
  • LC 238 zeros: the division "solution" dies on zeros; prefix×suffix handles any number of zeros for free.
  • Suffix update order: in LC 238's second pass, use suffix before multiplying a[i] into it — swapping the two lines includes a[i] in its own answer.
  • Overflow: 2D sums of 10⁴ cells × 10⁵ values need long; products overflow fastest of all — check constraints before trusting int.
