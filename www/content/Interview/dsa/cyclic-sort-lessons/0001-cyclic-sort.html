Cyclic Sort

When an array of n numbers only contains values from 1 to n, each value has exactly one home: index value−1. Swap everything home in O(n), and the missing and duplicate numbers expose themselves.

Mission link: "find the missing/duplicate number in O(n) time and O(1) space" is an OA staple precisely because sorting and HashSets are the obvious — and disqualified — answers. First Missing Positive (LC 41) is a genuine hard that this one pattern turns into ten lines. This is the only lesson in the Cyclic Sort track. Mission

1 · The one idea

How do you find the missing number in an array? Naive: sort it, O(n log n), then scan. Or dump everything into a HashSet, O(n) time but O(n) space. Cyclic sort gets O(n) time and O(1) space by exploiting one fact the general-purpose tools ignore: the values are index-sized. If every value is in [1..n] and the array has length n, then value v belongs at index v−1 — a perfect one-to-one pairing between values and slots. So walk the array; whenever the number under your finger isn't home, swap it to its home. After one pass the array is sorted — and any slot whose resident is wrong points straight at a missing value, while the squatter sitting there is a duplicate.

Recognition trigger The constraint line says "n integers in the range [1, n]" (or [0, n]) and the question is "find the missing / duplicate / all missing / all duplicates," especially with "O(1) extra space" or "without modifying... wait, you may modify the array." Range-bounded values + length-matched array = every value has a home index. That sentence in the constraints IS the pattern announcement — most people skim past it.

2 · Core template — swap into place

The loop looks O(n²) — a while inside a for — but it isn't. Count swaps, not iterations: every swap puts at least one value into its final home forever, and there are only n homes, so at most n swaps total across the whole run. The for-loop adds n more steps. O(n) overall. 

// Cyclic sort: values 1..n, each belongs at index value-1.
void cyclicSort(int[] a) {
    int i = 0;
    while (i < a.length) {
        int home = a[i] - 1;             // where the value under the finger belongs
        if (a[i] != a[home]) {           // not home yet (and home doesn't already hold a copy)
            int t = a[i]; a[i] = a[home]; a[home] = t; // send it home; inspect the newcomer next
        } else {
            i++;                         // a[i] is home (or its home is occupied by its twin) → move on
        }
    }
}                                        // afterwards: a[i] == i+1 wherever possible

Time O(n) — each swap homes a value permanently; ≤ n swaps + n pointer advances. Space O(1) — all swapping happens inside the input array.

Why the guard is a[i] != a[home] and not a[i] != i + 1 With duplicates, checking "is the current value in the right slot" infinite-loops: two copies of 3 will swap with each other forever. Checking "does my home already hold my value" breaks the cycle — if your twin is already home, you stop trying and step past. This one guard is what lets the same template power every duplicate-finding problem below.

Worked example — dry run

a = [3, 1, 5, 4, 2]:

i=0: a[0]=3, home=2, a[2]=5 ≠ 3 → swap → [5, 1, 3, 4, 2] i=0: a[0]=5, home=4, a[4]=2 ≠ 5 → swap → [2, 1, 3, 4, 5] i=0: a[0]=2, home=1, a[1]=1 ≠ 2 → swap → [1, 2, 3, 4, 5] i=0: a[0]=1 is home → i++ … indexes 1–4 all home already → done 3 swaps for 5 elements — i stalled at 0, but every swap homed someone for good

3 · All the cases

Every problem below is "cyclic-sort first, then read the answer off the misplaced slots." The variation is only in what range the values span and what you report.

Case: Missing Number (LC 268) — range [0..n], one value homeless

n distinct numbers drawn from [0..n] — one is missing. Range starts at 0, so home is index value itself. The quirk: value n exists but there's no index n. Let it sit wherever; it never satisfies the swap condition anyway (its home is out of bounds — treat it as "can't go home, skip"). After sorting, the first index whose resident is wrong is the missing number; if all match, the missing one is n. 

int missingNumber(int[] a) {
    int i = 0, n = a.length;
    while (i < n) {
        if (a[i] < n && a[i] != a[a[i]]) {  // a[i]==n has no home — skip it
            int t = a[i]; a[i] = a[t]; a[t] = t; // home for value v is index v (0-based range)
        } else i++;
    }
    for (i = 0; i < n; i++)
        if (a[i] != i) return i;         // slot i lacks its owner → i is missing
    return n;                            // 0..n-1 all present → n is the missing one
}

Time O(n), Space O(1). (XOR and Gauss-sum also solve 268 — you saw XOR in the Bit Manipulation track — but cyclic sort is the version that scales to "find ALL missing" where XOR can't.)

Case: Find All Numbers Disappeared (LC 448)

Values in [1..n], some appear twice, some never. Cyclic-sort, then sweep: every slot that doesn't hold its owner names a missing value. 

List<Integer> findDisappearedNumbers(int[] a) {
    int i = 0;
    while (i < a.length) {
        int home = a[i] - 1;
        if (a[i] != a[home]) { int t = a[i]; a[i] = a[home]; a[home] = t; }
        else i++;                        // the duplicate-safe guard from the core template
    }
    List<Integer> res = new ArrayList<>();
    for (i = 0; i < a.length; i++)
        if (a[i] != i + 1) res.add(i + 1); // slot i is squatted by a dup → owner i+1 never arrived
    return res;
}

Time O(n), Space O(1) beyond the output list.

Case: Find All Duplicates (LC 442) — same sort, read the other column

Identical setup, opposite question. After the sort, a mismatched slot a[i] != i+1 tells you two things at once: i+1 is missing (LC 448's answer) and the squatter a[i] is a duplicate (LC 442's answer) — it couldn't go home because its twin was already there. 

List<Integer> findDuplicates(int[] a) {
    int i = 0;
    while (i < a.length) {               // sort phase: byte-for-byte the same as LC 448
        int home = a[i] - 1;
        if (a[i] != a[home]) { int t = a[i]; a[i] = a[home]; a[home] = t; }
        else i++;
    }
    List<Integer> res = new ArrayList<>();
    for (i = 0; i < a.length; i++)
        if (a[i] != i + 1) res.add(a[i]); // report the SQUATTER this time, not the slot
    return res;
}

Time O(n), Space O(1) beyond output. One sort, two problems — that's the pattern's whole sales pitch.

Case: Find the Duplicate Number (LC 287) — cyclic-sort view

n+1 values in [1..n], exactly one value repeated. If modifying the array is allowed, cyclic sort nails it: sort, and the value stranded at index n (or the first mismatch) is the duplicate. 

int findDuplicate(int[] a) {
    int i = 0;
    while (i < a.length) {
        int home = a[i] - 1;
        if (a[i] != a[home]) { int t = a[i]; a[i] = a[home]; a[home] = t; }
        else i++;
    }
    for (i = 0; i < a.length; i++)
        if (a[i] != i + 1) return a[i];  // the value that couldn't go home — its twin beat it there
    return -1;                           // unreachable: a duplicate is guaranteed
}

Time O(n), Space O(1). Caveat: the official LC 287 forbids modifying the array — the by-the-book answer is Floyd's cycle detection (Fast & Slow Pointers track). Know both; say the trade-off out loud: cyclic sort is simpler but mutates, Floyd is read-only.

Case: Set Mismatch (LC 645) — duplicate and missing in one shot

One value duplicated, one lost. After sorting, exactly one slot is wrong — and it answers both questions: the resident is the duplicate, the index+1 is the missing. 

int[] findErrorNums(int[] a) {
    int i = 0;
    while (i < a.length) {
        int home = a[i] - 1;
        if (a[i] != a[home]) { int t = a[i]; a[i] = a[home]; a[home] = t; }
        else i++;
    }
    for (i = 0; i < a.length; i++)
        if (a[i] != i + 1)
            return new int[]{a[i], i + 1}; // {duplicate squatter, missing owner}
    return new int[0];
}

Time O(n), Space O(1).

Boss: First Missing Positive (LC 41)

Unsorted array, any int values (negatives, zeros, huge numbers), find the smallest missing positive in O(n)/O(1). This is a LeetCode Hard, and it's the same ten lines. The unlock: the answer must lie in [1 .. n+1] — n slots can cover at most the values 1..n, so something in that range (or n+1 exactly) is free. Therefore every value outside [1..n] is noise: don't swap it anywhere, just step past it. Cyclic-sort the values that do fit, then the first wrong slot names the answer. 

int firstMissingPositive(int[] a) {
    int n = a.length, i = 0;
    while (i < n) {
        int v = a[i];
        if (v >= 1 && v <= n && a[v - 1] != v) {  // in range AND home not already correct
            int t = a[v - 1]; a[v - 1] = v; a[i] = t; // send v home; re-inspect what came back
        } else i++;                      // noise (≤0, >n) or already settled → skip
    }
    for (i = 0; i < n; i++)
        if (a[i] != i + 1) return i + 1; // first unowned slot = smallest missing positive
    return n + 1;                        // perfect 1..n permutation → answer is n+1
}

Time O(n), Space O(1). Interviewers accept nothing less for this problem — sort is O(n log n), HashSet is O(n) space; both get the follow-up "can you do better?"

One template, six problems Notice what actually varied: LC 268 shifts the range to [0..n]; LC 41 filters junk before swapping; everything else is the identical sort followed by reading either the slot index (missing) or the squatter value (duplicate) in the final sweep. Learn the swap loop once, then each problem is just "which column do I report?"

4 · Edge-case checklist

  • Guard with a[i] != a[home], never a[i] != i+1 — the twin-already-home check is the only thing standing between you and an infinite swap loop on duplicates.
  • After a swap, do NOT advance i — the value that just arrived at i is unexamined and may itself need to travel. Only i++ when the current slot is settled.
  • Range off-by-one — values [1..n] → home v−1; values [0..n] (LC 268) → home v, and the value n is homeless: skip it.
  • Bounds-check before indexing (LC 41) — a[v-1] with v = −5 or v = 10⁹ throws; the in-range test must come first in the condition (short-circuit order matters).
  • All-settled input — a perfect permutation means the final sweep finds nothing: return n (LC 268) or n+1 (LC 41), not −1.
  • Mutation allowed? — cyclic sort destroys the input order. LC 287 officially forbids it (use Floyd); OAs often don't care, but ask your interviewer before scrambling their array.
  • n = 0 / n = 1 — empty array in LC 41 must return 1; the loops handle it, but confirm your final return does too.
