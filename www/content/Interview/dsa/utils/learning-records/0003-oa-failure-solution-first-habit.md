# OA failure reveals solution-first study habit → switch to retrieval protocol

Date: 2026-07-02.

## What happened
Learner took a real OA on 2026-07-01: 3 DSA questions, solved none, couldn't even
start an approach. Self-diagnosed their actual method: for most problems (including
the graph practice ladders) they read the solution FIRST, understand it, then type
the same code into LeetCode. So their ~100 "solved" reflects comprehension, not
generation — the OA tests generation under time pressure, a skill never practiced.

## Diagnosis
Classic illusion of competence: recognizing a solution ≠ producing one. The
missing skills are (1) a repeatable opening move for an unseen problem
(constraints → complexity budget → pattern shortlist → brute force first) and
(2) retrieval practice (attempt before peeking, layered hints, re-solve from
blank after 1–3 days).

## Method change agreed (enforce in every future practice session)
1. 25-min genuine attempt before ANY solution. Brute force counts as progress.
2. Stuck → hint layer only (pattern tag / first editorial line), then retry.
3. Full solution read → close it → rewrite from memory → RE-SOLVE from blank
   in 2–3 days. A problem doesn't count as solved until the blank re-solve passes.
4. Problem log: pattern, trigger words, what I missed. Review before new sessions.
5. Weekly timed 3-question mock OA (90 min) to train pressure, not just skill.
6. Re-solve the graph-ladder problems from blank before adding new ones.

## Implication for teaching
Lessons stay as the template/recognition library, but practice prompts from me
should now be "attempt first, tell me your approach in words, THEN we discuss" —
never hand an approach before they've stated constraints + brute force. Ask for
their OA questions when available and dissect the recognition step together.
