Trie (Prefix Tree) — Basics

A tree where each edge is a letter and each root-to-node path is a prefix — so any prefix question about a dictionary of any size costs O(word length), not O(dictionary size).

Mission link: "implement Trie" and its wildcard/dictionary variants are staple OA questions, and the structure unlocks two famous hard problems in Lesson 2. This is Lesson 1 of the 2-lesson trie track. Mission

1 · The one idea

Store a dictionary as a tree keyed by characters: the root is the empty string, and following edges c → a → t lands on the node representing prefix "cat". Words sharing a prefix share that path — that's the compression and the power. Any operation phrased "…with this prefix" walks one path of length L, so insert, exact search, and prefix search are all O(L), no matter whether the trie holds ten words or ten million. A boolean isEnd on a node marks "a whole word ends here," distinguishing the word "car" from the mere prefix "car" inside "carpet".

Recognition trigger "Prefix", "starts with", autocomplete, dictionary lookups repeated many times, "search many words in one structure/grid", "shortest root/replace words". If you're about to loop for (String w : dict) if (w.startsWith(p)) — that O(N·L) scan is the trie's cue. (Bit trick: treating numbers as 30-bit strings gives a binary trie for max-XOR — Lesson 2.)

2 · Core template — Implement Trie (LC 208)

The node holds a children array indexed by c - 'a' and the isEnd flag. All three operations are the same walk: follow child links one character at a time, creating nodes (insert) or returning false on a missing link (search/startsWith). 

class Trie {
    static class TrieNode {
        TrieNode[] children = new TrieNode[26]; // lowercase a–z; children[c-'a']
        boolean isEnd = false;                  // a complete word terminates at this node
    }
    private final TrieNode root = new TrieNode(); // root = empty prefix

    public void insert(String word) {
        TrieNode cur = root;
        for (char c : word.toCharArray()) {
            int i = c - 'a';
            if (cur.children[i] == null)
                cur.children[i] = new TrieNode(); // lay track as we go
            cur = cur.children[i];
        }
        cur.isEnd = true;                       // mark ONLY the last node
    }

    public boolean search(String word) {        // whole-word match
        TrieNode n = walk(word);
        return n != null && n.isEnd;            // path exists AND a word ends there
    }

    public boolean startsWith(String prefix) {  // prefix match
        return walk(prefix) != null;            // path existing is enough — ignore isEnd
    }

    private TrieNode walk(String s) {           // shared walker: node for s, or null
        TrieNode cur = root;
        for (char c : s.toCharArray()) {
            cur = cur.children[c - 'a'];
            if (cur == null) return null;       // missing link → s isn't in the trie
        }
        return cur;
    }
}

Time O(L) per insert/search/startsWith, L = word length. Space O(total characters inserted × 26 slots) worst case — shared prefixes cost nothing extra.

children[26] array vs HashMap — the trade-off

TrieNode[26] arrayMap<Character, TrieNode>
Child lookupO(1), a raw index — fastestO(1) amortized, with hashing overhead
Memory26 refs per node even if 1 child is used — wasteful for sparse triesPays only for children that exist
AlphabetFixed & small (a–z). Unicode/digits/mixed case → array blows upAny alphabet, no remapping
Interview defaultUse this when the problem says lowercase a–z (most do)Use for unknown/large alphabets, or when memory is flagged
isEnd is the whole point — don't skip it After inserting "carpet", the node for "car" exists but isEnd is false there. search("car") must return false while startsWith("car") returns true. The classic bug is search returning "path exists" — which silently turns it into startsWith.

Case: Add and Search Word — '.' wildcard (LC 211)

add is plain insert. search meets '.', which matches any character — so instead of following one link, try all 26 and succeed if any branch does. That turns the linear walk into a DFS over (node, position-in-pattern). 

class WordDictionary {
    TrieNode root = new TrieNode();       // same TrieNode as the core

    public void addWord(String word) { /* identical to Trie.insert */ }

    public boolean search(String word) { return dfs(word, 0, root); }

    private boolean dfs(String w, int i, TrieNode node) {
        if (node == null) return false;   // walked off the trie
        if (i == w.length()) return node.isEnd; // pattern consumed → is a word ending HERE?
        char c = w.charAt(i);
        if (c == '.') {
            for (TrieNode child : node.children)      // '.' = branch into every live child
                if (child != null && dfs(w, i + 1, child)) return true;
            return false;
        }
        return dfs(w, i + 1, node.children[c - 'a']); // literal char = normal single step
    }
}

Time O(L) for literal-only queries; worst case O(26d·L) with d dots (in practice bounded by trie size — a query of all dots visits every node of that depth). Space O(L) recursion.

Case: Replace Words (LC 648)

Given root words and a sentence, replace each word with its shortest root prefix. Insert all roots into a trie; for each sentence word, walk character by character and return as soon as you hit an isEnd node — walking in order guarantees the first hit is the shortest. 

String replaceWords(List<String> dictionary, String sentence) {
    TrieNode root = new TrieNode();
    for (String r : dictionary) insert(root, r);       // core insert
    StringBuilder sb = new StringBuilder();
    for (String word : sentence.split(" ")) {
        if (sb.length() > 0) sb.append(' ');
        sb.append(shortestRoot(root, word));
    }
    return sb.toString();
}
String shortestRoot(TrieNode root, String word) {
    TrieNode cur = root;
    for (int i = 0; i < word.length(); i++) {
        cur = cur.children[word.charAt(i) - 'a'];
        if (cur == null) return word;         // no root prefixes this word — keep it
        if (cur.isEnd) return word.substring(0, i + 1); // FIRST isEnd = shortest root: stop
    }
    return word;                              // word ran out before any root ended
}

Time O(total root chars) to build + O(total sentence chars) to scan. Space O(total root chars × 26).

Case: Longest Word in Dictionary (LC 720)

Find the longest word buildable one character at a time, where every prefix is also a word ("world" needs "w","wo","wor","worl" all present). In trie terms: the deepest node reachable through isEnd-only nodes. Insert everything, then DFS refusing to enter any child with isEnd == false; iterate children a→z so ties resolve to the lexicographically smaller word for free. 

String longestWord(String[] words) {
    TrieNode root = new TrieNode();
    for (String w : words) insert(root, w);
    return dfs(root, new StringBuilder(), "");
}
String dfs(TrieNode node, StringBuilder path, String best) {
    if (path.length() > best.length()) best = path.toString(); // strictly longer wins; a→z order settles ties
    for (int i = 0; i < 26; i++) {
        TrieNode child = node.children[i];
        if (child != null && child.isEnd) {   // only step onto complete words — the chain rule
            path.append((char) ('a' + i));
            best = dfs(child, path, best);
            path.deleteCharAt(path.length() - 1); // backtrack
        }
    }
    return best;
}

Time O(total chars) build + O(total chars) DFS. Space O(total chars × 26).

4 · Edge-case checklist

  • search vs startsWith: same walk, but search additionally requires isEnd. Returning path-exists from search is the classic 208 bug.
  • Mark isEnd only on the last node — never along the way — and never unset it when inserting a longer word over a shorter one ("car" then "carpet" must leave both findable).
  • Duplicate inserts are harmless: the walk finds every node already present and re-sets isEnd.
  • One word a prefix of another ("app", "apple"): both live on one path with two isEnd marks. Most trie edge cases are this shape.
  • Empty string: walking zero chars returns the root — startsWith("") is true; search("") is whatever root.isEnd is (LC never inserts it).
  • Alphabet assumptions: c - 'a' assumes lowercase a–z. Uppercase, digits, or Unicode → resize the array or switch to a HashMap.
  • Wildcard at the end (LC 211, e.g. "ca."): the pattern-consumed check must still test isEnd — '.' matches a character, not "anything including nothing".
