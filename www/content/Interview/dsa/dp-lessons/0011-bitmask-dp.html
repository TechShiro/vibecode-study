DP Track · Lesson 11 of 12 · a subset is just an int

Bitmask DP

When n ≤ ~20, every subset of your items fits in one integer — so "best answer for this subset" becomes a plain array lookup: dp[mask].

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 11 of the 12-lesson DP track. Mission

1 · The one idea

"Try every permutation" is n! — dead at n = 12. But the optimal way to finish usually depends only on which items are already used, not the order you used them in. Encode that set as an int (bit i set ⇔ item i used) and you collapse n! orderings into 2ⁿ states. The killer convenience: every proper submask of mask is a smaller number, so a simple ascending loop for (mask = 0 .. 2ⁿ−1) visits states in valid dependency order — no topological sorting needed.

Recognition trigger n ≤ ~20 (the constraint IS the hint) + "assign / visit / partition / cover all of them", or "every ordering would work but n! is too big". Small n plus a set-shaped question — "which subset is used so far" — means bitmask DP. If order-within-the-set matters (routes), add a second dimension: dp[mask][last].

2 · The bit toolkit (2-minute recap — you'll use all six)

// CHECK — is item i in the subset?
boolean in = ((mask >> i) & 1) == 1;     // or: (mask & (1 << i)) != 0 — NEVER == 1, the bit's value is 2^i
// SET — add item i (idempotent: safe if already present)
mask |= (1 << i);
// CLEAR — remove item i (idempotent: safe if already absent)
mask &= ~(1 << i);
// TOGGLE — flip item i (add if absent, remove if present; only use XOR to "remove" when you KNOW it's set)
mask ^= (1 << i);
// POPCOUNT — how many items chosen: a free progress counter (hardware instruction, O(1))
int size = Integer.bitCount(mask);
// ITERATE the set bits without scanning all n positions:
for (int m = mask; m != 0; m &= (m - 1)) {        // m &= m-1 strips the LOWEST set bit each round
    int i = Integer.numberOfTrailingZeros(m);      // index of that bit → "item i is in the subset"
}
int low  = mask & (-mask);               // isolate the lowest set bit as a mask (two's complement trick)
int full = (1 << n) - 1;                 // the "everything chosen" mask: n ones
Trap — 1 << i is an int shift 1 << 31 is Integer.MIN_VALUE (negative!), and Java silently shifts by i % 32, so 1 << 32 == 1 — no error, just wrong answers. The moment a mask can hold more than 31 items (e.g. a team mask over 60 people in LC 1125), switch to long and write 1L << i / Long.bitCount. For DP state masks this never bites (n ≤ 20 by construction), but for masks stored as values it's the classic silent bug.

3 · State · Recurrence · Base case

  • State: dp[mask] = best answer when exactly the items in mask are used. For routes: dp[mask][last] = best way to visit set mask ending at last.
  • Recurrence: extend by one element — dp[mask | (1<<j)] = best(dp[mask] + cost of adding j) for each unused j. In assignment problems, who gets item j is implied by Integer.bitCount(mask) — person k is served k-th.
  • Base case: dp[0] = 0 (nothing used); TSP: dp[1][0] = 0 (standing at the start city, only it visited).
  • Order: masks ascending 0 .. 2ⁿ−1 — submasks are numerically smaller, so predecessors are always ready.
  • Answer: dp[full]; TSP tour: min over last of dp[full][last] + dist[last][0].

4 · Core templates

Assignment: dp[mask] — "who's used so far"

// Min cost to assign n jobs to n people, cost[person][job]. Person index = bitCount(mask).
int assign(int[][] cost) {
    int n = cost.length, full = (1 << n) - 1;
    int[] dp = new int[1 << n];
    Arrays.fill(dp, Integer.MAX_VALUE / 2);       // "infinity" that survives an addition
    dp[0] = 0;
    for (int mask = 0; mask < full; mask++) {     // ascending = dependency order for free
        if (dp[mask] >= Integer.MAX_VALUE / 2) continue;
        int person = Integer.bitCount(mask);      // people 0..person-1 already served
        for (int j = 0; j < n; j++)
            if ((mask & (1 << j)) == 0)           // job j still free → give it to `person`
                dp[mask | (1 << j)] = Math.min(dp[mask | (1 << j)], dp[mask] + cost[person][j]);
    }
    return dp[full];
}

Time O(2ⁿ · n). Space O(2ⁿ). n = 20 → ~2·10⁷ ops: fine. n = 25 → 8·10⁸: not fine. Check the constraint.

Routes: dp[mask][last] — TSP / shortest Hamiltonian path

// Cheapest tour: start at 0, visit every city once, return to 0.
int tsp(int[][] dist) {
    int n = dist.length, full = (1 << n) - 1;
    int[][] dp = new int[1 << n][n];              // dp[mask][last] = cheapest path over `mask` ending at `last`
    for (int[] row : dp) Arrays.fill(row, Integer.MAX_VALUE / 2);
    dp[1][0] = 0;                                 // base: at city 0, {0} visited — NOT dp[0]
    for (int mask = 1; mask <= full; mask++)
        for (int last = 0; last < n; last++) {
            if ((mask & (1 << last)) == 0 || dp[mask][last] >= Integer.MAX_VALUE / 2) continue;
            for (int next = 0; next < n; next++)
                if ((mask & (1 << next)) == 0)    // extend the path by one unvisited city
                    dp[mask | (1 << next)][next] =
                        Math.min(dp[mask | (1 << next)][next], dp[mask][last] + dist[last][next]);
        }
    int best = Integer.MAX_VALUE;
    for (int last = 1; last < n; last++)
        best = Math.min(best, dp[full][last] + dist[last][0]);  // close the tour
    return best;
}

Time O(2ⁿ · n²). Space O(2ⁿ · n). For a Hamiltonian path (no return), seed dp[1<<i][i] = 0 for every start i and skip the closing edge. This template is CP-classic; LeetCode dresses it up as LC 943 (Find the Shortest Superstring — overlap costs instead of distances) and LC 847 (Shortest Path Visiting All Nodes — same (mask, node) state, but BFS because revisits are allowed).

Trap — when order matters, dp[mask] alone is not enough The cost of adding city next depends on where you are now — that's why the state needs the extra last dimension. If you catch yourself writing dp[mask] + dist[?][next] and don't know what to put for ?, that's the signal: you dropped the last dimension.

Practice — free-tier LeetCode

  • LC 943 · Find the Shortest Superstring (Hard) — pure dp[mask][last]: precompute pairwise overlaps, then this exact template with "cost of adding j after last = len(j) − overlap(last, j)"; reconstruct the path from parent pointers.
  • LC 847 · Shortest Path Visiting All Nodes (Hard) — same (mask, node) state, but nodes may be revisited, so run BFS over states instead of an ascending-mask DP; start with all (1<<i, i) seeded at distance 0.
  • LC 996 · Number of Squareful Arrays (Hard) — dp[mask][last] that counts orderings instead of minimizing cost; only append j if nums[last]+nums[j] is a perfect square, then divide out duplicate-value permutations.

Partition to K Equal Sum Subsets (698)

boolean canPartitionKSubsets(int[] nums, int k) {
    int sum = Arrays.stream(nums).sum();
    if (sum % k != 0) return false;
    int target = sum / k, n = nums.length;
    int[] rem = new int[1 << n];              // rem[mask] = current bucket's fill; -1 = unreachable
    Arrays.fill(rem, -1);
    rem[0] = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        if (rem[mask] < 0) continue;          // skip unreachable states
        for (int i = 0; i < n; i++)
            if ((mask & (1 << i)) == 0 && rem[mask] + nums[i] <= target)   // never overfill a bucket
                rem[mask | (1 << i)] = (rem[mask] + nums[i]) % target;     // hit target → next bucket starts at 0
    }
    return rem[(1 << n) - 1] == 0;            // all used AND last bucket exactly full
}

Time O(2ⁿ · n). Space O(2ⁿ). The trick that makes one bucket's fill enough state: buckets are interchangeable, so you only ever fill one bucket at a time — when it hits target the % target rolls it to 0 and the next bucket implicitly begins.

Minimum XOR Sum (1879) — bitCount as the hidden index

int minimumXORSum(int[] a, int[] b) {
    int n = a.length;
    int[] dp = new int[1 << n];
    Arrays.fill(dp, Integer.MAX_VALUE);
    dp[0] = 0;
    for (int mask = 1; mask < (1 << n); mask++) {
        int i = Integer.bitCount(mask) - 1;   // a[0..i] are paired ⇔ |mask| elements of b used
        for (int j = 0; j < n; j++)
            if ((mask & (1 << j)) != 0)       // b[j] was the LAST one paired — undo it
                dp[mask] = Math.min(dp[mask], dp[mask ^ (1 << j)] + (a[i] ^ b[j]));
    }
    return dp[(1 << n) - 1];
}

Time O(2ⁿ · n). Space O(2ⁿ). This is the assignment template written "pull-style" (each state asks its predecessors) instead of "push-style" (each state feeds its successors) — both are fine; pick one and stay consistent. bitCount(mask) − 1 works because pairing is done in a-index order: if k elements of b are used, then a[0..k−1] are exactly the ones paired.

Practice — free-tier LeetCode

  • LC 1879 · Minimum XOR Sum of Two Arrays (Hard) — the code above; n ≤ 14 is the give-away that n! matching is meant to become 2ⁿ.
  • LC 1947 · Maximum Compatibility Score Sum (Medium) — identical assignment shape, just maximize a score matrix instead of minimizing XOR; the gentlest first drill.
  • LC 526 · Beautiful Arrangement (Medium) — assignment where you count valid pairings: dp value becomes a count, position = bitCount(mask), and the divisibility test filters which j may extend.

Number of Ways to Wear Different Hats (1434) — mask the smaller side

40 hats means 2⁴⁰ hat-masks — dead on arrival. But there are at most 10 people, and 2¹⁰ = 1024. So flip the roles: the hats become the sequence you walk (like items in a knapsack) and the people become the mask. State: dp[mask] after considering hats 1..h = number of ways to have satisfied exactly the people in mask. Transition per hat h: either nobody wears it (state carries over) or exactly one not-yet-satisfied person who likes h wears it. Base: dp[0] = 1 before any hats; answer: dp[full] after hat 40. 

int numberWays(List<List<Integer>> hats) {
    int MOD = 1_000_000_007, n = hats.size(), full = (1 << n) - 1;
    List<List<Integer>> wearers = new ArrayList<>();   // invert the input: wearers.get(h) = people who like hat h
    for (int h = 0; h <= 40; h++) wearers.add(new ArrayList<>());
    for (int p = 0; p < n; p++)
        for (int h : hats.get(p)) wearers.get(h).add(p);
    long[] dp = new long[1 << n];
    dp[0] = 1;                                          // no hats considered, nobody satisfied yet
    for (int h = 1; h <= 40; h++) {                     // hats are the linear "time" axis
        long[] next = dp.clone();                       // option A: nobody wears hat h — carry every state over
        for (int mask = 0; mask <= full; mask++) {
            if (dp[mask] == 0) continue;
            for (int p : wearers.get(h))
                if ((mask & (1 << p)) == 0)             // option B: p (still hatless) wears hat h
                    next[mask | (1 << p)] = (next[mask | (1 << p)] + dp[mask]) % MOD;
        }
        dp = next;                                      // hat h fully processed
    }
    return (int) dp[full];
}

Time O(40 · 2ⁿ · n) ≈ 4·10⁵ for n = 10. Space O(2ⁿ).

Trap — update in place and one hat gets worn twice The next = dp.clone() is load-bearing. If you write into dp while still reading dp for the same hat, a state you just created (person p wearing h) can be extended again within the same hat — giving hat h to two people. Read from the old layer, write to the new one.

Smallest Sufficient Team (1125) — the dp value is a mask too

// skillOf[p] = bitmask of required skills person p covers (m required skills, m ≤ 16).
long[] dp = new long[1 << m];                 // dp[skills] = smallest team (person-bits in a long), -1 = unset
Arrays.fill(dp, -1);
dp[0] = 0;
for (int mask = 0; mask < (1 << m); mask++) {
    if (dp[mask] < 0) continue;
    for (int p = 0; p < people; p++) {
        int with = mask | skillOf[p];         // skills covered after hiring p
        long team = dp[mask] | (1L << p);
        if (dp[with] < 0 || Long.bitCount(team) < Long.bitCount(dp[with]))
            dp[with] = team;                  // keep the smaller team per skill-set
    }
}
// decode dp[(1 << m) - 1]'s set bits into the answer array

Note the asymmetry: 60 people would need 2⁶⁰ — impossible. But skills ≤ 16 → 2¹⁶ states. Always mask the smaller side — the same trick as LC 1434 (mask the ≤10 people, iterate the ≤40 hats). Time O(2ᵐ · people). Space O(2ᵐ). Two more things to notice: the dp value is itself a bitmask (the team, in a long because people can exceed 31 — hence 1L << p), and mask | skillOf[p] may stay equal to mask (p adds nothing new) — the bitCount comparison quietly rejects that, so no infinite loop and no bloated teams.

Maximum Students Taking Exam (1349) — row-by-row masks (broken profile)

Here the mask is not "which items are used overall" — it's the seating pattern of one row, and the DP walks the rows the way 1D DP walks indices. State: dp[r][prev] = max students seated in rows 0..r−1 given row r−1 was seated exactly as prev. Transition: try every mask cur for row r that (1) uses only intact seats, (2) has no two adjacent students, (3) has no diagonal conflict with prev. Base: dp[0][0] = 0 (before any rows, the "previous row" is empty). Answer: max over dp[m][·]. Columns ≤ 8, so at most 2⁸ = 256 masks per row — tiny. 

int maxStudents(char[][] seats) {
    int m = seats.length, n = seats[0].length, full = (1 << n) - 1;
    int[] ok = new int[m];                                // ok[r] = bitmask of intact ('.') seats in row r
    for (int r = 0; r < m; r++)
        for (int c = 0; c < n; c++)
            if (seats[r][c] == '.') ok[r] |= (1 << c);
    int[][] dp = new int[m + 1][1 << n];
    for (int[] row : dp) Arrays.fill(row, -1);            // -1 = "previous row never seated this way"
    dp[0][0] = 0;
    for (int r = 0; r < m; r++)
        for (int prev = 0; prev <= full; prev++) {
            if (dp[r][prev] < 0) continue;                // unreachable predecessor — skip
            for (int cur = 0; cur <= full; cur++) {
                if ((cur & ~ok[r]) != 0) continue;        // someone on a broken seat
                if ((cur & (cur << 1)) != 0) continue;    // two students side by side in this row
                if ((cur & (prev << 1)) != 0              // upper-left diagonal conflict…
                 || (cur & (prev >> 1)) != 0) continue;   // …and upper-right — you need BOTH shifts
                dp[r + 1][cur] = Math.max(dp[r + 1][cur], dp[r][prev] + Integer.bitCount(cur));
            }
        }
    int best = 0;
    for (int mask = 0; mask <= full; mask++) best = Math.max(best, dp[m][mask]);
    return best;
}

Time O(m · 4ⁿ) over row-mask pairs (n = columns ≤ 8 → 8·256·256 ≈ 5·10⁵). Space O(m · 2ⁿ), or O(2ⁿ) with two rolling rows. To trim the cur loop to valid seatings only, enumerate submasks of ok[r] with the idiom below — that's exactly where the 3ⁿ trick earns its keep.

Trap — one shift checks only one diagonal cur & (prev << 1) alone passes tests where the cheater sits to the other diagonal. A student at column c conflicts with previous-row students at c−1 and c+1, so you must test both prev << 1 and prev >> 1. Same-row adjacency is the self-check cur & (cur << 1) — one shift suffices there because the pair is symmetric.

Submask enumeration — the O(3ⁿ) idiom

for (int sub = mask; sub > 0; sub = (sub - 1) & mask) {
    // visits every non-empty submask of `mask`, in decreasing order
    // (sub-1) drops the lowest set bit and floods below it; & mask re-confines to mask's bits
}

Why it works: sub − 1 flips sub's lowest set bit to 0 and floods 1s below it; & mask then erases every bit outside mask. The effect: "count down" but only through numbers whose bits all lie inside mask — which is exactly the set of submasks, visited in decreasing order.

Cost over all masks: Σ 2^popcount(mask) = 3ⁿ — each element independently lands in one of three buckets: (in mask & in sub), (in mask, not in sub), (not in mask). So the nested "for every mask, for every submask" pattern is O(3ⁿ), not the lazy 2ⁿ·2ⁿ = 4ⁿ estimate. For n = 16 that's 4·10⁷ vs 4·10⁹ — the difference between accepted and TLE.

When you need it: when one transition consumes a whole group at once rather than one element — "peel off a valid subset and recurse on the rest": dp[mask] = best over valid sub ⊆ mask of dp[mask ^ sub] + cost(sub). Typical: partition people into work sessions (LC 1986), hand out whole quantities to customers (LC 1655), or enumerate only the legal row-seatings inside ok[r] in LC 1349. Precompute cost(sub)/validity for all 2ⁿ subsets first, then run the 3ⁿ loop.

Trap — sub >= 0 loops forever When sub reaches 0, the next step computes (0 − 1) & mask = mask — you're back at the start. The sub > 0 condition is what terminates the loop, which also means the empty submask is never visited: if ∅ is a legal choice (e.g. an empty row seating in 1349), handle it explicitly outside the loop.

Worked example — dry run

TSP on 4 cities. Distance matrix (symmetric): d[0][1]=10, d[0][2]=15, d[0][3]=20, d[1][2]=35, d[1][3]=25, d[2][3]=30. Masks written as 3210 bits.

base: dp[0001][0] = 0 — at city 0, only 0 visited mask 0001 expands: dp[0011][1]=10 · dp[0101][2]=15 · dp[1001][3]=20 mask 0011 (end 1): dp[0111][2]=10+35=45 · dp[1011][3]=10+25=35 mask 0101 (end 2): dp[0111][1]=15+35=50 · dp[1101][3]=15+30=45 mask 1001 (end 3): dp[1011][1]=20+25=45 · dp[1101][2]=20+30=50 mask 1011 (end 3, path 0→1→3): dp[1111][2] = min(∞, 35+30) = 65 also dp[1111][1]=70 (via 1101 end 3) · dp[1111][3]=75 (via 0111) close tour: min(70+10, 65+15, 75+20) = min(80, 80, 95) = 80

6 · Edge-case checklist

  • Seed the right base: TSP starts at dp[1][0] = 0 (city 0 already visited), not dp[0]. Off-by-one masks are the classic bug.
  • Infinity discipline: fill with Integer.MAX_VALUE / 2 (or check-before-add) so INF + dist doesn't overflow into a "great" negative value.
  • Skip unreachable states (dp[mask] == INF / -1) before expanding — correctness in 698, speed everywhere.
  • Mask the smaller side. 2⁴⁰ hats is impossible; 2¹⁰ people is trivial (1434, 1125).
  • Memory before time: dp[2²⁰][20] ints ≈ 80 MB — may exceed limits. Consider dp[mask]-only formulations, or n ≤ 16 problems.
  • 1 << i with i ≥ 31: 1 << 31 is negative and Java shifts by i % 32 with no warning — shift a 1L when the mask lives in a long (1125's team mask over up to 60 people).
  • Submask loop and the empty set: sub = (sub-1) & mask stops at 0 — handle the empty submask separately if it's a legal choice.
