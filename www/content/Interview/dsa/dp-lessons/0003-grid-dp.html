DP Track · Lesson 03 of 12 · the DAG you fill row by row

Grid DP (2D paths)

A robot that only moves right/down is a DAG in disguise — and index order is its topological sort. No BFS, no queue: just two nested loops.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 3 of the 12-lesson DP track. Mission

1 · The one idea

In a grid where moves go right/down, dp[r][c] depends on a constant set of already-filled neighbors — usually top (dp[r-1][c]) and left (dp[r][c-1]). Grid DP is graph DP on a DAG whose edges point right and down, so row-major iteration IS a topological order: by the time you reach a cell, everything it needs is done. And since each row only reads the row above, one rolling 1D array usually replaces the whole table.

Recognition trigger "Unique paths", "min/max path sum", a robot moving right/down only, "largest square/rectangle in a matrix", triangle of numbers. The tell: a 2D structure where legal moves never go backwards — that's the DAG. (If moves go in all 4 directions, it's a graph problem — BFS/Dijkstra, not grid DP.)

2 · State · Recurrence · Base case

The framework, instantiated for Unique Paths (LC 62) — count right/down paths from top-left to bottom-right of an m×n grid:

StepFor Unique Paths
1 · Statedp[r][c] = number of paths from (0,0) to (r,c)
2 · Recurrencedp[r][c] = dp[r-1][c] + dp[r][c-1] — you arrived from above or from the left
3 · Base casesFirst row and first column = 1 (a single straight path)
4 · OrderRow-major: r then c, both ascending — a topological order of the DAG
5 · Answerdp[m-1][n-1] — for path problems; "best square/subarray anywhere" answers are a max over all cells
The direction of the fill = the direction of the dependencies Ask "which cells does dp[r][c] read?" and iterate so those are computed first. Top+left → fill top-left → bottom-right. Dungeon Game's state reads below and right → fill backwards. Getting this backwards is the #1 grid-DP bug.

3 · Core template — Unique Paths (62)

// Bottom-up 2D — see the whole table.
int uniquePaths(int m, int n) {
    int[][] dp = new int[m][n];                  // dp[r][c] = paths from (0,0) to (r,c)
    for (int r = 0; r < m; r++)
        for (int c = 0; c < n; c++)
            dp[r][c] = (r == 0 || c == 0) ? 1    // edges: only one straight-line way
                     : dp[r - 1][c] + dp[r][c - 1];
    return dp[m - 1][n - 1];
}
// Rolling 1D — each row only reads the row above, so keep one row.
int uniquePaths(int m, int n) {
    int[] dp = new int[n];
    Arrays.fill(dp, 1);                          // row 0
    for (int r = 1; r < m; r++)
        for (int c = 1; c < n; c++)
            dp[c] += dp[c - 1];                  // dp[c] (not yet overwritten) = top; dp[c-1] (fresh) = left
    return dp[n - 1];
}

Time O(m·n) · Space O(n) rolled (O(m·n) with the table). The left-to-right update order is what makes dp[c-1] "this row" and dp[c] "last row" — hold that thought until knapsack (Lesson 4), where flipping this order is the whole subject.

Unique Paths II (63) — obstacles

One rule change: an obstacle cell carries 0 paths — including obstacles on the first row/column, which block everything beyond them (so the "edges are all 1" shortcut from LC 62 is now a bug). Same state, same top+left recurrence; just zero the cell before adding. Time O(m·n), space O(n) rolled.

int uniquePathsWithObstacles(int[][] g) {
    int m = g.length, n = g[0].length;
    int[] dp = new int[n];
    dp[0] = 1 - g[0][0];                         // blocked start → 0 paths everywhere
    for (int r = 0; r < m; r++)
        for (int c = 0; c < n; c++) {
            if (g[r][c] == 1) dp[c] = 0;         // obstacle kills every path through it — even on edges
            else if (c > 0) dp[c] += dp[c - 1];  // top (old dp[c]) + left (new dp[c-1])
        }
    return dp[n - 1];
}

Minimum Path Sum (64)

Swap "sum of counts" for "min of costs": dp[r][c] = cheapest total to reach (r,c) = grid[r][c] + min(top, left). Base cases are forced marches along the first row and column. Same fill order, same rolling row, Time O(m·n), space O(n).

int minPathSum(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[] dp = new int[n];
    dp[0] = grid[0][0];
    for (int c = 1; c < n; c++) dp[c] = dp[c - 1] + grid[0][c];   // row 0: forced march right
    for (int r = 1; r < m; r++) {
        dp[0] += grid[r][0];                     // left edge: can only come from above
        for (int c = 1; c < n; c++)
            dp[c] = grid[r][c] + Math.min(dp[c], dp[c - 1]);      // cheaper of top vs left
    }
    return dp[n - 1];
}

Triangle (120) — bottom-up from the last row

Rows widen by one each level, so filled top-down the state fans out and the answer ends up as a min-scan of the last row. Fill bottom-up instead: each cell takes its value plus the cheaper of its two children below, and the answer condenses to a single number at the apex. A virtual all-zero row below the base erases every edge case. Time O(n²), space O(n).

int minimumTotal(List<List<Integer>> tri) {
    int n = tri.size();
    int[] dp = new int[n + 1];                   // virtual all-zero row below the base
    for (int r = n - 1; r >= 0; r--)
        for (int c = 0; c <= r; c++)
            dp[c] = tri.get(r).get(c) + Math.min(dp[c], dp[c + 1]);  // two children below
    return dp[0];                                // apex holds the answer — no scan of the last row needed
}

Maximal Square (221) — min of three neighbors + 1

A different question — no path at all. dp[r][c] = side of the largest all-ones square whose bottom-right corner sits here: a square can only extend as far as the weakest of its top, left, and diagonal neighbors allows, hence min of three + 1. The answer is a max over all cells, not the bottom-right corner. Time O(m·n), space O(m·n) (rolls to O(n) with one saved diagonal).

int maximalSquare(char[][] mat) {
    int m = mat.length, n = mat[0].length, best = 0;
    int[][] dp = new int[m + 1][n + 1];          // dp[r][c] = side of largest square whose bottom-right is (r-1,c-1)
    for (int r = 1; r <= m; r++)                 // padded row/col 0 stay 0 → no bounds checks
        for (int c = 1; c <= n; c++)
            if (mat[r - 1][c - 1] == '1') {
                dp[r][c] = 1 + Math.min(dp[r - 1][c - 1],          // a square is only as big as
                               Math.min(dp[r - 1][c], dp[r][c - 1]));  // its weakest neighbor allows
                best = Math.max(best, dp[r][c]);
            }
    return best * best;                          // they ask AREA — returning the side is the classic slip
}

Dungeon Game (174) — why forward fails

Forward "best health so far" can't work: two paths reaching a cell might have (health 10, needed 2) vs (health 5, needed 1) — neither dominates, so no single forward number summarizes the past. But the future is summarizable: define need[r][c] = minimum HP required on entering (r,c) to reach the princess alive. That reads from below/right, so anchor at the princess and fill backwards.

int calculateMinimumHP(int[][] d) {
    int m = d.length, n = d[0].length;
    int[][] need = new int[m][n];
    for (int r = m - 1; r >= 0; r--)
        for (int c = n - 1; c >= 0; c--) {
            int next = (r == m - 1 && c == n - 1) ? 1              // leave the princess cell with ≥ 1 HP
                     : (r == m - 1) ? need[r][c + 1]
                     : (c == n - 1) ? need[r + 1][c]
                     : Math.min(need[r + 1][c], need[r][c + 1]);   // easier of the two onward paths
            need[r][c] = Math.max(1, next - d[r][c]);              // clamp: HP may never drop to 0, and surplus doesn't bank
        }
    return need[0][0];
}

Time O(m·n) · Space O(m·n) (rolls to O(n) — need only reads the row below).

Cherry Pickup II (1463) — states multiply (advanced)

Two robots descend one row per step, so the row is a shared clock and the state must carry both columns: (row, c1, c2). The recurrence maxes over the 3 × 3 combinations of column moves from the row above; base case is the two top corners; the answer is the best value over all column pairs in the last row. The framework didn't change — the state just grew a dimension. Time O(m·n²·9), space O(n²) rolled.

// Two robots descend together → state (row, c1, c2). Same framework, bigger table.
int cherryPickup(int[][] grid) {
    int m = grid.length, n = grid[0].length;
    int[][] dp = new int[n][n];                  // dp[c1][c2] = best cherries so far, robots at c1 and c2
    for (int[] row : dp) Arrays.fill(row, -1);   // -1 = unreachable pairing
    dp[0][n - 1] = grid[0][0] + grid[0][n - 1];  // base: corners of row 0
    for (int r = 1; r < m; r++) {
        int[][] nd = new int[n][n];
        for (int[] row : nd) Arrays.fill(row, -1);
        for (int c1 = 0; c1 < n; c1++)
            for (int c2 = 0; c2 < n; c2++) {
                if (dp[c1][c2] < 0) continue;
                for (int d1 = -1; d1 <= 1; d1++)                   // 3 × 3 = 9 move combos
                    for (int d2 = -1; d2 <= 1; d2++) {
                        int a = c1 + d1, b = c2 + d2;
                        if (a < 0 || a >= n || b < 0 || b >= n) continue;
                        int gain = grid[r][a] + (a == b ? 0 : grid[r][b]);  // shared cell counts once
                        nd[a][b] = Math.max(nd[a][b], dp[c1][c2] + gain);
                    }
            }
        dp = nd;
    }
    int best = 0;
    for (int[] row : dp) for (int v : row) best = Math.max(best, v);
    return best;                                 // O(m · n² · 9) — the framework scaled, not changed
}
Two classic Cherry Pickup II bugs Counting the shared cell twice when c1 == c2 (the a == b ? 0 : … guard), and letting unreachable pairings default to 0 — a 0 reads as "reachable with zero cherries" and corrupts every max downstream. Initialize to −1 and continue past negatives.

Longest Common Subsequence (1143) — preview: a grid whose axes are strings

The bridge to Lesson 5. State: dp[i][j] = LCS length of the first i chars of a and the first j chars of b. If the two current characters match, extend the diagonal: dp[i-1][j-1] + 1; otherwise skip one character from either string: max(top, left). Base case: row 0 and column 0 are 0 (an empty prefix shares nothing). Same three neighbor reads as Maximal Square, same row-major fill.

int longestCommonSubsequence(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];          // dp[i][j] = LCS of a[0..i) and b[0..j); padded row/col 0 = empty prefix = 0
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            dp[i][j] = (a.charAt(i - 1) == b.charAt(j - 1))
                     ? dp[i - 1][j - 1] + 1                        // match: extend the diagonal
                     : Math.max(dp[i - 1][j], dp[i][j - 1]);       // mismatch: drop a char from one string
    return dp[m][n];
}

Time O(m·n) · Space O(m·n), rolls to O(n) — the same rolling-row argument as Unique Paths.

THE two-string DP bug: the off-by-one The table is (m+1) × (n+1) but the strings are 0-indexed, so cell (i, j) compares a.charAt(i - 1) with b.charAt(j - 1). Mixing "index into dp" with "index into string" is the single most common wrong-answer in the whole LCS family — Lesson 5 will drill it.
Bridge to Lesson 5 — LCS is a grid Same three neighbor reads as Maximal Square, same row-major fill, only the axes changed from grid coordinates to two strings. If grid DP feels solid, two-string DP is a re-labeling exercise — and one template there covers a dozen problems.

Worked example — dry run

Minimum Path Sum on grid = [[1,3,1],[1,5,1],[4,2,1]]. Fill dp[r][c] = grid[r][c] + min(top, left) row by row:

row 0 (forced right): dp = [1, 1+3=4, 4+1=5] row 1, c=0 (forced down): 1 + 1 = 2 row 1, c=1: 5 + min(top 4, left 2) = 7 row 1, c=2: 1 + min(top 5, left 7) = 6 — the top path wins here row 2: 2+4=6; 2 + min(7, 6) = 8; 1 + min(6, 8) = 7 return dp[2][2] = 7 (path 1→3→1→1→1)

5 · Edge-case checklist

  • Obstacle on the start or goal cell (63): answer is 0 — and obstacles on the first row/column block everything beyond them, which the "edges are all 1" shortcut silently gets wrong.
  • 1×1 grid / single row / single column: the recurrence never fires; make sure base-case code alone produces the right answer.
  • Rolling-row update order: left→right keeps old dp[c] = top and new dp[c-1] = left. Reversing the inner loop breaks it here — yet is exactly what 0/1 knapsack will require (Lesson 4).
  • Dungeon Game clamps at 1: Math.max(1, …) — a huge potion can't bank health below the 1-HP floor. Forgetting the clamp is the classic wrong-answer.
  • Maximal Square returns area, not side: best * best. And the answer is a max over all cells, not the corner.
  • Path counts overflow: sums of counts grow combinatorially — use long or the required modulus when constraints allow big grids.
  • Padded tables (221): size [m+1][n+1] and shift reads to mat[r-1][c-1] — cleaner than four boundary branches, but keep the off-by-one straight.
