Two-string DP: the LCS family

Longest Common Subsequence is not one problem — it's a template. Match → diagonal + 1; mismatch → best of skip-left / skip-up. Change what "match" and "skip" cost and you get Edit Distance, Distinct Subsequences, and regex matching.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 5 of the 12-lesson DP track. Mission

1 · The one idea

With two strings, the state is a pair of prefixes: dp[i][j] = answer for s1[0..i) vs s2[0..j). Every transition asks one question — do the last characters s1[i-1] and s2[j-1] agree? Match: extend the diagonal, dp[i-1][j-1]. Mismatch: combine the "skip one character" neighbors dp[i-1][j] / dp[i][j-1] (or pay an edit cost). That single question, re-costed, is the entire family.

Recognition trigger TWO strings + any of "common / convert / delete / distance / interleave / match / supersequence". The moment both inputs are strings and the answer depends on aligning them, draw the (m+1) × (n+1) table and ask the match/mismatch question.

3 · Core template

LCS (LC 1143) — the full 2D table

int longestCommonSubsequence(String s1, String s2) {
    int m = s1.length(), n = s2.length();
    int[][] dp = new int[m + 1][n + 1];      // row 0 / col 0 = vs empty string = 0
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            if (s1.charAt(i - 1) == s2.charAt(j - 1))
                dp[i][j] = dp[i - 1][j - 1] + 1;                  // match → extend diagonal
            else
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);  // skip one last char
    return dp[m][n];
}
// Rolling 1D: each row reads only the previous row → keep two rows, swap.
int[] prev = new int[n + 1], cur = new int[n + 1];
for (int i = 1; i <= m; i++) {
    for (int j = 1; j <= n; j++)
        cur[j] = s1.charAt(i - 1) == s2.charAt(j - 1)
               ? prev[j - 1] + 1                  // prev[j-1] = the diagonal
               : Math.max(prev[j], cur[j - 1]);
    int[] t = prev; prev = cur; cur = t;          // swap references, no reallocation
}
return prev[n];

Time O(m·n). Space O(m·n) full table, O(n) rolled. Keep the full table if you must reconstruct the subsequence (walk back from dp[m][n]).

Edit Distance (72) — the three edit operations, one per neighbor

int minDistance(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 0; i <= m; i++) dp[i][0] = i;   // vs empty b: delete all i chars
    for (int j = 0; j <= n; j++) dp[0][j] = j;   // vs empty a: insert all j chars
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                     ? dp[i - 1][j - 1]                          // chars agree — free move
                     : 1 + Math.min(dp[i - 1][j - 1],            // replace  (↖)
                           Math.min(dp[i - 1][j],                // delete a[i-1]  (↑)
                                    dp[i][j - 1]));              // insert b[j-1]  (←)
    return dp[m][n];
}

Time O(m·n). Space O(m·n), rolls to O(n) exactly like LCS (only the previous row is read).

583, 712 and 1092 — arithmetic on top of LCS, no new table shape

Three problems that look scary but are the LCS table wearing a hat. 583: both strings delete down to their LCS, so the answer is pure arithmetic. 1092: a shortest supersequence contains each string once but shares the LCS only once — length is arithmetic, and the actual string comes from walking the LCS table back from dp[m][n] (emit the diagonal char on match, else move toward the larger neighbor emitting the skipped char). 712: 583 with weights — every delete costs the character's ASCII value, so the base row/column become prefix ASCII sums instead of 0, 1, 2, … 

// LC 583: keep the LCS, delete everything else from both strings.
return m + n - 2 * lcs(word1, word2);
// LC 1092 (length): the supersequence shares the LCS once.
// length = m + n - lcs;  the actual string = walk the LCS table back from dp[m][n].
// LC 712 — dp[i][j] = min ASCII sum deleted to equalize a[0..i) and b[0..j).
int minimumDeleteSum(String a, String b) {
    int m = a.length(), n = b.length();
    int[][] dp = new int[m + 1][n + 1];
    for (int i = 1; i <= m; i++) dp[i][0] = dp[i - 1][0] + a.charAt(i - 1);  // vs empty b: delete a's whole prefix, ASCII-weighted
    for (int j = 1; j <= n; j++) dp[0][j] = dp[0][j - 1] + b.charAt(j - 1);
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++)
            dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                     ? dp[i - 1][j - 1]                              // match — keep both, pay nothing
                     : Math.min(dp[i - 1][j] + a.charAt(i - 1),      // delete a[i-1], pay its ASCII
                                dp[i][j - 1] + b.charAt(j - 1));     // delete b[j-1], pay its ASCII
    return dp[m][n];
}

Time O(m·n). Space O(m·n), rolls to O(n).

Trap In 712 the base row/column are NOT 0, 1, 2, … — they are running ASCII sums (dp[i][0] = dp[i-1][0] + a.charAt(i-1)). Copying Edit Distance's dp[i][0] = i seeding here compiles fine and fails on the first test with unequal leftover prefixes.

Distinct Subsequences (115) — the counting variant

// dp[i][j] = #ways to form t[0..j) from s[0..i).
long[][] dp = new long[m + 1][n + 1];
for (int i = 0; i <= m; i++) dp[i][0] = 1;       // empty target: one way — delete everything
for (int i = 1; i <= m; i++)
    for (int j = 1; j <= n; j++) {
        dp[i][j] = dp[i - 1][j];                 // never use s[i-1]
        if (s.charAt(i - 1) == t.charAt(j - 1))
            dp[i][j] += dp[i - 1][j - 1];        // use s[i-1] to match t[j-1]
    }
return (int) dp[m][n];

Time O(m·n). Space O(m·n), rolls to O(n) with prev/cur rows. Compute in long — intermediate counts overflow int even when the final answer fits.

Is Subsequence (392) — when NOT to DP

// A greedy pointer scan is O(m+n), beats the O(m·n) table. If only feasibility of
// one alignment direction is asked, reach for two pointers first.
int i = 0;
for (int j = 0; j < t.length() && i < s.length(); j++)
    if (s.charAt(i) == t.charAt(j)) i++;
return i == s.length();

Time O(m + n). Space O(1). The DP table only earns its O(m·n) when you need to count, optimize a cost, or answer the follow-up with many queries.

Interleaving String (97) — boolean OR over the same grid

// dp[i][j] = can s3[0..i+j) be woven from s1[0..i) and s2[0..j)?
if (m + n != s3.length()) return false;
boolean[][] dp = new boolean[m + 1][n + 1];
dp[0][0] = true;
for (int i = 0; i <= m; i++)
    for (int j = 0; j <= n; j++) {
        if (i > 0 && dp[i - 1][j] && s1.charAt(i - 1) == s3.charAt(i + j - 1)) dp[i][j] = true;
        if (j > 0 && dp[i][j - 1] && s2.charAt(j - 1) == s3.charAt(i + j - 1)) dp[i][j] = true;
    }
return dp[m][n];

Time O(m·n). Space O(m·n), rolls to O(n) — dp[i][j] reads only the row above and the cell to the left.

Regex (10) vs Wildcard (44) — the two '*' recurrences, side by side

Both are boolean grids on the same axes — dp[i][j] = does s[0..i) match pattern p[0..j)? — and both stand or fall on one column-0/row-0 insight: dp[0][0] = true (empty matches empty), column 0 below that is all false (a non-empty s never matches an empty pattern), and row 0 must be seeded because star-bearing patterns can match the empty string. The recurrences differ only in what '*' means: 

// LC 10 — '*' modifies the PRECEDING element p[j-2] ("zero or more of it"):
//   zero copies:   dp[i][j] = dp[i][j-2]          (erase "x*" from the pattern)
//   one more copy: dp[i][j] |= dp[i-1][j]   if s[i-1] matches p[j-2] ('.' matches any)

// LC 44 — '*' stands ALONE and matches any run, possibly empty:
//   match empty:   dp[i][j] = dp[i][j-1]
//   swallow s[i-1]: dp[i][j] |= dp[i-1][j]   (star stays active for the next char)
// LC 10 — Regular Expression Matching, bottom-up.
boolean isMatch(String s, String p) {
    int m = s.length(), n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 2; j <= n; j++)                       // seed row 0: "a*", "a*b*" can match ""
        if (p.charAt(j - 1) == '*') dp[0][j] = dp[0][j - 2];
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*') {
                dp[i][j] = dp[i][j - 2];               // zero copies of p[j-2]
                if (fits(s.charAt(i - 1), p.charAt(j - 2)))
                    dp[i][j] |= dp[i - 1][j];          // one more copy — consume s[i-1], keep "x*"
            } else if (fits(s.charAt(i - 1), pc)) {
                dp[i][j] = dp[i - 1][j - 1];           // plain char or '.' — the LCS diagonal move
            }                                          // else stays false
        }
    return dp[m][n];
}
boolean fits(char sc, char pc) { return pc == '.' || pc == sc; }
// LC 44 — Wildcard Matching, bottom-up. Same skeleton, simpler star.
boolean isMatch(String s, String p) {
    int m = s.length(), n = p.length();
    boolean[][] dp = new boolean[m + 1][n + 1];
    dp[0][0] = true;
    for (int j = 1; j <= n && p.charAt(j - 1) == '*'; j++)
        dp[0][j] = true;                               // only a LEADING run of stars matches ""
    for (int i = 1; i <= m; i++)
        for (int j = 1; j <= n; j++) {
            char pc = p.charAt(j - 1);
            if (pc == '*')
                dp[i][j] = dp[i][j - 1] || dp[i - 1][j];   // match empty ← | swallow s[i-1] ↑
            else if (pc == '?' || pc == s.charAt(i - 1))
                dp[i][j] = dp[i - 1][j - 1];               // exact char or '?' — diagonal
        }
    return dp[m][n];
}

Time O(m·n) for both. Space O(m·n), rolls to O(n) (each cell reads ↑, ←, and for LC 10 the same-row j−2).

The two stars are different animals Regex '*' (LC 10) is a quantifier — it never matches anything itself, it says "zero or more copies of the preceding element". That's why its zero-copies move jumps TWO pattern columns (dp[i][j-2] erases the pair "x*"), and why the one-more-copy move must re-check s[i-1] against p[j-2], not p[j-1]. Wildcard '*' (LC 44) is a matcher in its own right — a standalone token that eats any sequence, so its moves are one column left (match empty) or one row up (swallow another char). If you remember one sentence: regex star looks back at its neighbor; wildcard star acts alone.
Trap — the row-0 seeding new boolean[m+1][n+1] is all-false, and that default is WRONG for row 0: in LC 10, "a*b*" matches "" (seed dp[0][j] = dp[0][j-2] at each star); in LC 44, "***" matches "" (seed while the pattern's prefix is all stars — and stop at the first non-star). Skip the seeding and every star-only pattern against an empty or short string fails silently.

Worked example — dry run

LCS of s1 = "abcde" (rows) and s2 = "ace" (columns). Three diagonal matches — a, c, e — each bump the value by 1; every other cell copies its best neighbor:

row a: match at column a → dp[1][1] = dp[0][0] + 1; the 1 propagates right row b: 'b' matches nothing in "ace" → whole row copies from above: 0 1 1 1 row c: match at column c → dp[3][2] = dp[2][1] + 1 = 2 row d: no match → copies: 0 1 2 2 row e: match at column e → dp[5][3] = dp[4][2] + 1 = 3 answer dp[5][3] = 3; walk-back through the three match cells spells "ace"

5 · Edge-case checklist

  • Off-by-one everywhere: dp[i][j] is about prefixes of length i, j — the characters compared are charAt(i-1), charAt(j-1). Mixing these up is the family's #1 bug.
  • Base row/col differ per problem: 0 for LCS, i/j for Edit Distance, 1s down column 0 for 115, star-seeded row 0 for 10/44. Never assume all-zero.
  • Match ≠ forced take in counting problems: 115 adds the skip case and the match case.
  • Rolling array + diagonal: in 1-row compression the diagonal dp[i-1][j-1] gets overwritten — keep prev[]/cur[] (or a saved prevDiag temp).
  • Empty strings: the template handles them via row/col 0 — but only if you seeded those correctly.
  • 97 length guard: if m + n != s3.length(), return false before touching the table.
  • Counting overflow: 115 can exceed int mid-table — compute in long.
  • Don't auto-DP: 392 falls to two pointers in O(m+n). Check for a greedy scan before building a table.
