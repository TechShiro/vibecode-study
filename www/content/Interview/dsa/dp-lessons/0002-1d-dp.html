1D DP on Sequences

One array in, one dp array over it. House Robber is the template; eight classic problems are that template with one twist each.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 2 of the 12-lesson DP track. Mission

1 · The one idea

For a single array or string, define dp[i] = the best answer for the prefix ending at (or up to) index i. The recurrence pulls from O(1) earlier states — dp[i-1], dp[i-2] — or occasionally all O(i) of them. Scan left→right once, and the giant space of subsets/decodings/subarrays collapses into n cheap decisions, because everything the future needs to know about the past fits in one or two numbers.

Recognition trigger A single array or string + "max sum / count the ways / min cost" scanning left→right, especially with an adjacency constraint ("can't pick neighbors", "digit pairs decode together", "contiguous subarray"). If choice at i is constrained only by choices at i-1/i-2, it's 1D DP.

2 · State · Recurrence · Base case

The framework from Lesson 1, instantiated for House Robber (LC 198) — rob non-adjacent houses, maximize loot:

StepFor House Robber
1 · Statedp[i] = max loot obtainable from houses 0..i (rob house i or not — both included)
2 · Recurrencedp[i] = max(dp[i-1], dp[i-2] + nums[i]) — skip house i, or rob it (then i-1 is off-limits)
3 · Base casesdp[0] = nums[0], dp[1] = max(nums[0], nums[1])
4 · Orderi ascending — each state only looks back
5 · Answerdp[n-1] (but for "ending here" states like Kadane, the answer is the max over all dp[i] — always ask which)
The state sentence is the whole game "Best up to i" and "best ending exactly at i" are different states with different answers. House Robber is "up to i" (answer at dp[n-1]); Kadane is "ending at i" (answer is the max over all i). Say the sentence out loud before writing the loop — most wrong 1D DP is a mis-stated state.

3 · Core template — House Robber (198)

// Full table first — see the state.
int rob(int[] nums) {
    int n = nums.length;
    if (n == 1) return nums[0];
    int[] dp = new int[n];
    dp[0] = nums[0];
    dp[1] = Math.max(nums[0], nums[1]);
    for (int i = 2; i < n; i++)
        dp[i] = Math.max(dp[i - 1],              // skip house i
                         dp[i - 2] + nums[i]);   // rob house i → i-1 forbidden
    return dp[n - 1];
}
// Interview-final form: the recurrence looks back 2 → roll to two variables.
int rob(int[] nums) {
    int prev2 = 0, prev1 = 0;                    // dp[i-2], dp[i-1]; zeros = "no houses yet"
    for (int x : nums) {
        int cur = Math.max(prev1, prev2 + x);
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}

Time O(n) · Space O(1) rolled (O(n) with the table). The zero-seeded rolling version even handles n=1 without a special case.

House Robber II (213) — the circle trick

Same state and recurrence as 198 — only the boundary changed: house 0 and house n−1 are now adjacent, so no plan may rob both. Every valid circular plan therefore lives in one of two linear worlds: "house n−1 untouched" (rob on 0..n−2) or "house 0 untouched" (rob on 1..n−1). Run the linear template on each range and take the max. Time O(n) · Space O(1). 

int rob(int[] nums) {
    int n = nums.length;
    if (n == 1) return nums[0];
    return Math.max(robLine(nums, 0, n - 2),     // case A: house n-1 never robbed
                    robLine(nums, 1, n - 1));    // case B: house 0 never robbed
}                                                // every valid circular plan lies in A or B
int robLine(int[] nums, int lo, int hi) {
    int prev2 = 0, prev1 = 0;
    for (int i = lo; i <= hi; i++) {
        int cur = Math.max(prev1, prev2 + nums[i]);
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}

Decode Ways (91) — counting with '0' traps

Same shape, different verb: max becomes +. State: dp[i] = number of ways to decode the prefix of length i. The last decoded token is either one digit (valid unless it's '0') or two digits (valid only for 10–26), so dp[i] = dp[i-1]·[1-digit ok] + dp[i-2]·[2-digit ok]. Base: dp[0] = 1 — one way to decode the empty prefix. Time O(n) · Space O(1) rolled. 

int numDecodings(String s) {
    int n = s.length();
    if (s.charAt(0) == '0') return 0;            // "0..." decodes to nothing
    int prev2 = 1, prev1 = 1;                    // dp[0]=1 (empty prefix), dp[1]=1
    for (int i = 2; i <= n; i++) {               // dp[i] = ways to decode s[0..i)
        int cur = 0;
        if (s.charAt(i - 1) != '0') cur += prev1;            // take 1 digit — '0' alone is invalid
        int two = (s.charAt(i - 2) - '0') * 10 + (s.charAt(i - 1) - '0');
        if (two >= 10 && two <= 26) cur += prev2;            // take 2 digits — "06" fails (6 < 10)
        prev2 = prev1; prev1 = cur;
    }
    return prev1;
}
dp[0] = 1 is not a hack Setting the empty prefix to 1 way feels arbitrary until a two-digit take at i = 2 needs it: decoding "12" as one token contributes dp[0] ways. Seed it 0 and every count that goes through a leading pair silently vanishes. Counting DPs almost always base at 1, not 0.

Maximum Subarray (53) — Kadane

The state flips to "ending exactly at i": dp[i] = best sum of a subarray whose last element is nums[i]. At each step you either extend the previous run or restart — dp[i] = max(nums[i], dp[i-1] + nums[i]) — and because the answer can end anywhere, a separate best takes the max over all i. Base: dp[0] = nums[0]. Time O(n) · Space O(1). 

int maxSubArray(int[] nums) {
    int endingHere = nums[0], best = nums[0];    // seed with nums[0], NOT 0 — all-negative arrays
    for (int i = 1; i < nums.length; i++) {
        endingHere = Math.max(nums[i], endingHere + nums[i]);  // restart here, or extend the run
        best = Math.max(best, endingHere);       // answer = max over ALL "ending here" states
    }
    return best;
}

Maximum Product Subarray (152) — carry the min too

Kadane's shape, but multiplication breaks the single-track state: a negative number turns the smallest product ending here into tomorrow's largest. So carry two states — max product ending at i and min product ending at i — and on a negative element swap them before extending. Bases are both nums[0]; answer is the max over all i. Time O(n) · Space O(1). 

int maxProduct(int[] nums) {
    int max = nums[0], min = nums[0], best = nums[0];
    for (int i = 1; i < nums.length; i++) {
        int x = nums[i];
        if (x < 0) { int t = max; max = min; min = t; }  // negative flips the extremes
        max = Math.max(x, max * x);              // best product ending here
        min = Math.min(x, min * x);              // worst — tomorrow's negative makes it the best
        best = Math.max(best, max);
    }
    return best;
}

Delete and Earn (740) — reduce to House Robber

No new DP — a reduction. Taking one copy of value v forces you to take every copy (they're free once v±1 are dead), so bucket the input: gain[v] = v × count(v). Now "taking v deletes v−1" is exactly the adjacency constraint of House Robber, on the value line instead of the house line. State, recurrence, bases: identical to 198. Time O(n + V) · Space O(V), V = max value (10⁴ here). 

int deleteAndEarn(int[] nums) {
    int[] gain = new int[10001];                 // gain[v] = v * count(v): take ALL copies of v at once
    for (int x : nums) gain[x] += x;
    int prev2 = 0, prev1 = 0;                    // taking v deletes v-1 → "adjacent" on the value line
    for (int v = 0; v <= 10000; v++) {
        int cur = Math.max(prev1, prev2 + gain[v]);
        prev2 = prev1; prev1 = cur;
    }
    return prev1;                                // literally rob(gain) — spotting reductions is a skill
}

Jump Game (55) — when to abandon DP

The honest DP first: dp[i] = "is index i reachable?", true if any earlier j has dp[j] and j + nums[j] >= i. That's a look-back over all O(i) earlier states → O(n²) total. It's correct — but notice the state is just a boolean, and the transition only asks "did anything before me reach this far?". One running integer answers that for every i at once. 

// The DP you'd write on autopilot — correct, O(n²) time, O(n) space:
boolean canJump(int[] nums) {
    int n = nums.length;
    boolean[] dp = new boolean[n];               // dp[i] = can we reach index i?
    dp[0] = true;                                // base: we start at index 0
    for (int i = 1; i < n; i++)
        for (int j = 0; j < i; j++)              // any earlier reachable j that jumps to/past i
            if (dp[j] && j + nums[j] >= i) { dp[i] = true; break; }
    return dp[n - 1];
}
// The whole dp[] collapses into one number — greedy, O(n) time, O(1) space:
boolean canJump(int[] nums) {
    int reach = 0;                               // farthest index reachable so far
    for (int i = 0; i < nums.length; i++) {
        if (i > reach) return false;             // stranded before reaching i
        reach = Math.max(reach, i + nums[i]);
    }
    return true;
}                                                // greedy is safe here: only "how far", nothing to trade off
Knowing when NOT to DP If the state you defined is a monotone boolean ("reachable?") and the transition is "does anything before me satisfy X", a single running maximum usually replaces the whole table. In an interview, name the O(n²) DP in one sentence, then present the O(n) greedy — that contrast is exactly what the interviewer is fishing for on LC 55.

Word Break (139) — dp over prefixes

The look-back stops being O(1): dp[i] = "can the prefix s[0..i) be segmented into dictionary words?" — true if some split point j has dp[j] true and s[j..i) in the dictionary. Base: dp[0] = true, the empty prefix. This "last word / last piece" scan over all j is the bridge to string DP in Lesson 5. Time O(n²) splits × substring cost · Space O(n). 

boolean wordBreak(String s, List<String> wordDict) {
    Set<String> dict = new HashSet<>(wordDict);
    int n = s.length();
    boolean[] dp = new boolean[n + 1];           // dp[i] = can s[0..i) be segmented?
    dp[0] = true;                                // empty prefix — the base every string DP starts from
    for (int i = 1; i <= n; i++)
        for (int j = i - 1; j >= 0; j--)         // last word = s[j..i)
            if (dp[j] && dict.contains(s.substring(j, i))) { dp[i] = true; break; }
    return dp[n];
}                                                // O(n²) states×splits (×substring cost) — fine for n ≤ 300

5 · Edge-case checklist

  • n = 1 / n = 2: touching dp[1] on a length-1 array throws. Zero-seeded rolling variables (prev2 = prev1 = 0) dodge this; explicit tables need guards. LC 213 requires the n == 1 check — both runs would see an empty range.
  • All-negative array (53): initialize with nums[0], not 0 — the empty subarray isn't allowed, so [-3, -1, -2] must return −1.
  • '0' in Decode Ways: leading '0' → 0 ways; "06" is invalid as a pair (< 10); a '0' not preceded by 1 or 2 (e.g. "30") kills every decoding — cur becomes 0 and correctly stays 0.
  • Zeros in Max Product (152): max(x, max*x) restarts at the element, so zeros reset both trackers naturally — don't special-case them.
  • Prefix-indexed dp (91, 139): when dp[i] means "prefix of length i", size the array n+1 and remember dp[i] pairs with character s.charAt(i-1).
  • "Up to i" vs "ending at i": for ending-at states the answer is max over all i, not dp[n-1].
