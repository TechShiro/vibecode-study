State-machine DP

Every stock problem — and paint, fence, and wiggle problems too — is a tiny automaton: a handful of named states and the legal moves between them. Draw it first; the recurrence is just the arrows.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 8 of the 12-lesson DP track. Mission

1 · The one idea

At each index you are in one of a few named states — holding a stock, free to buy, in cooldown, last house painted red. The rules of the problem are edges between states, forming a small automaton. Then dp[i][state] = best value at index i while in that state, and each transition reads straight off an arrow. When the state count is constant, the whole table rolls into a few variables: O(n) time, O(1) space. The entire six-problem stock series is one automaton with edges added or removed.

Recognition trigger Buy/sell with rules ("cooldown", "transaction fee", "at most k transactions"), alternating constraints ("no two adjacent same color", "up then down"), or any scan where the legal move today depends on which mode you were in yesterday — not on the whole history. If you can name yesterday's modes on your fingers, it's state-machine DP.

2 · State · Recurrence · Base case

PartFor the stock family (2-state core)
Statehold[i] = max profit after day i while holding a share; free[i] = max profit after day i holding nothing.
Recurrencefree[i] = max(free[i-1], hold[i-1] + p) (rest, or sell); hold[i] = max(hold[i-1], free[i-1] − p) (rest, or buy). Variants only rewire which state a buy may come from, or add a fee/counter.
Base casefree = 0 (no trades yet), hold = −∞ (holding before any buy is impossible — mark unreachable).
OrderOne left→right pass over prices; day i reads only day i−1 → roll the table into scalars.
AnswerBest value over the states where you hold nothing at the end (you never finish rich while still holding).

3 · Core template

The general stock automaton — LC 122 (unlimited transactions)

int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;         // -∞: holding before buying is unreachable. /2 avoids overflow on +p
    int free = 0;                             // profit 0, holding nothing
    for (int p : prices) {
        int prevFree = free;                  // snapshot: both updates must read YESTERDAY's values
        free = Math.max(free, hold + p);      // rest, or sell today
        hold = Math.max(hold, prevFree - p);  // rest, or buy today
    }
    return free;                              // finish holding nothing
}

Time O(n). Space O(1) — the 2-state table rolled into two ints. Every problem below is this template with edges rewired: cooldown inserts a forced third state, fee taxes the sell edge, "at most k" clones the machine k times, paint problems rename the states to colors.

The method: draw before you code On paper, in 30 seconds: circles for states, arrows for legal moves, each arrow labeled with its profit/cost. One max per incoming arrow set — that is the entire recurrence. Interviewers at Google explicitly reward this: narrating the automaton is the explanation.

One transaction (121) — delete the re-buy arrow

Same two states as the core machine, one arrow changed: with a single transaction allowed, a buy must come from profit 0 (you've never traded), so the buy edge reads a constant instead of free: hold = max(hold, −p). Base case and answer are unchanged (hold = −∞, free = 0, return free). Squint and hold is just "minus the running minimum price" — the famous one-pass solution and the automaton are the same algorithm wearing different clothes.

int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;         // best profit while holding the ONE share = −(min price so far)
    int free = 0;                             // best profit after selling it (or never trading)
    for (int p : prices) {
        free = Math.max(free, hold + p);      // sell today
        hold = Math.max(hold, -p);            // buy today — funded by 0, NOT by free (no snapshot needed: −p is a constant)
    }
    return free;
}

Time O(n), Space O(1).

Trap Writing hold = max(hold, free − p) out of habit silently re-enables unlimited transactions — you've built LC 122. On [1,2,1,2] that returns 2 instead of 1. The entire difference between 121 and 122 is which state funds the buy.

Cooldown (309) — the three-state machine

int maxProfit(int[] prices) {
    int hold = Integer.MIN_VALUE / 2;         // holding a share
    int sold = Integer.MIN_VALUE / 2;         // sold TODAY → tomorrow is a forced cooldown
    int rest = 0;                             // free to buy (≥1 day since selling)
    for (int p : prices) {
        int prevSold = sold;
        sold = hold + p;                      // sell today (only exit from hold)
        hold = Math.max(hold, rest - p);      // keep holding, or buy — ONLY from rest, never from sold
        rest = Math.max(rest, prevSold);      // stay free, or finish yesterday's cooldown
    }
    return Math.max(sold, rest);              // end holding nothing (either just-sold or free)
}

Time O(n), Space O(1) — the 3-state table rolled into three ints.

Fee (714) — tax one edge

int maxProfit(int[] prices, int fee) {
    int hold = Integer.MIN_VALUE / 2, free = 0;
    for (int p : prices) {
        int prevFree = free;
        free = Math.max(free, hold + p - fee);  // the ONLY change vs LC 122: fee on the sell arrow
        hold = Math.max(hold, prevFree - p);
    }
    return free;
}

Time O(n), Space O(1). Note the snapshot is load-bearing here: without prevFree, a same-day buy-after-sell dodges half the fee.

At most 2 transactions (123) — chain two machines in series

Two copies of the one-transaction machine, wired end to end: machine #2's buy is funded by machine #1's sell. State = four scalars hold1 / sell1 / hold2 / sell2; recurrence is each machine's usual pair of arrows, except hold2 reads sell1. Base case: both holds −∞, both sells 0. Answer: sell2 — it dominates sell1 because a same-price buy-and-sell is a free no-op, so "at most 2" includes "exactly 1" and "zero" automatically.

int maxProfit(int[] prices) {
    int hold1 = Integer.MIN_VALUE / 2, sell1 = 0;  // machine #1: first buy / first sell
    int hold2 = Integer.MIN_VALUE / 2, sell2 = 0;  // machine #2: may only buy out of sell1
    for (int p : prices) {
        sell2 = Math.max(sell2, hold2 + p);        // update last stage first ⇒ every line reads yesterday's values
        hold2 = Math.max(hold2, sell1 - p);        // second buy spends the first sale's profit
        sell1 = Math.max(sell1, hold1 + p);
        hold1 = Math.max(hold1, -p);               // first buy funded by 0 — this line IS LC 121
    }
    return sell2;
}

Time O(n), Space O(1) — four ints instead of a dp[n][4] table.

Trap Forward order (hold1 first) also happens to pass here, because a same-day chained trade earns exactly 0 and never beats the max. Don't learn that habit — the identical sloppiness is a wrong answer in 309 and 714. Update last stage first, always.

At most k transactions (188) — clone the machine k times

int maxProfit(int k, int[] prices) {
    int n = prices.length;
    if (k >= n / 2) {                          // a transaction needs ≥2 days ⇒ cap never binds:
        int profit = 0;                         // collapse to unlimited (LC 122 greedy form)
        for (int i = 1; i < n; i++) profit += Math.max(0, prices[i] - prices[i - 1]);
        return profit;
    }
    int[] hold = new int[k + 1], free = new int[k + 1];
    Arrays.fill(hold, Integer.MIN_VALUE / 2);  // free[j]=0: zero profit with ≤j transactions used
    for (int p : prices)
        for (int j = k; j >= 1; j--) {         // j = transactions used so far (counted at buy)
            free[j] = Math.max(free[j], hold[j] + p);
            hold[j] = Math.max(hold[j], free[j - 1] - p);  // buying starts transaction j
        }
    return free[k];
}

Time O(nk), Space O(k). Without the k ≥ n/2 collapse, huge k values TLE you for no reason — a favorite hidden test.

Minimum Falling Path Sum (931) — states are columns, moves are adjacent

First non-stock rename. Walking down the matrix, the only thing tomorrow cares about is which column you stand in — so the states are the m columns. State: dp[c] = min path sum reaching column c of the current row. Recurrence: entering column c is allowed from c−1, c, or c+1 of the previous row, so take the min of those (≤ 3 incoming arrows per state). Base case: the first row itself; answer: min over the last row.

int minFallingPathSum(int[][] matrix) {
    int n = matrix.length;
    int[] dp = matrix[0].clone();              // dp[c] = min cost so far, standing in column c
    for (int r = 1; r < n; r++) {
        int[] ndp = new int[n];
        for (int c = 0; c < n; c++) {
            int best = dp[c];                              // straight down
            if (c > 0)     best = Math.min(best, dp[c - 1]); // from upper-left
            if (c + 1 < n) best = Math.min(best, dp[c + 1]); // from upper-right
            ndp[c] = matrix[r][c] + best;
        }
        dp = ndp;                              // commit the row from the previous row's snapshot
    }
    int ans = Integer.MAX_VALUE;
    for (int v : dp) ans = Math.min(ans, v);
    return ans;
}

Time O(n·m) — each of the n·m cells looks at ≤ 3 arrows. Space O(m).

Minimum Falling Path Sum II (1289) — states are columns, not trades

This is the classic "Paint House" machine with n colors: each row you pick one column, and the next row must pick a different one. State = the column your last pick used.

int minFallingPathSum(int[][] grid) {
    int m = grid[0].length;
    int[] dp = new int[m];                     // dp[c] = min cost so far, given the LAST row picked column c
    for (int[] row : grid) {
        int[] ndp = new int[m];
        for (int c = 0; c < m; c++) {
            int best = Integer.MAX_VALUE;      // pick column c ⇒ previous row used any OTHER column
            for (int pc = 0; pc < m; pc++)
                if (pc != c) best = Math.min(best, dp[pc]);
            ndp[c] = row[c] + best;
        }
        dp = ndp;                              // commit the whole row together (same snapshot rule)
    }
    int ans = Integer.MAX_VALUE;
    for (int v : dp) ans = Math.min(ans, v);
    return ans;
}

Time O(n·m²), Space O(m). Interview upgrade: carry only the previous row's smallest and second-smallest values (use the second when the columns collide) → O(n·m). That min-over-others trick is the follow-up interviewers are fishing for.

Paint the N×3 grid (1411) — a counting automaton

There are exactly 12 valid single rows, and they split into two classes: two-colored aba (6 of them) and three-colored abc (6 of them). The class alone determines how many compatible rows can come next — list them once by hand: after an aba row you can place 3 aba rows and 2 abc rows; after an abc row, 2 of each. So the state is just the class of the last row, the recurrence multiplies counts along the arrows, the base case is row 1 (aba = abc = 6), and the answer is aba + abc. Same machine as the stocks — but the arrows multiply and add counts instead of maximizing profit.

int numOfWays(int n) {
    final int MOD = 1_000_000_007;
    long aba = 6, abc = 6;                     // row 1: 6 two-color patterns, 6 three-color patterns
    for (int i = 2; i <= n; i++) {
        long nAba = (3 * aba + 2 * abc) % MOD; // each aba row admits 3 aba successors; each abc admits 2
        long nAbc = (2 * aba + 2 * abc) % MOD; // both classes admit 2 abc successors
        aba = nAba;                            // same snapshot rule: both lines read the OLD pair
        abc = nAbc;
    }
    return (int) ((aba + abc) % MOD);
}

Time O(n), Space O(1) — two longs.

Trap Counting DPs overflow where profit DPs don't: with int and no % MOD each step, the counts wrap within a few dozen rows. Keep longs and reduce every iteration — not just at the end.

Wiggle Subsequence (376) — up/down states

int wiggleMaxLength(int[] nums) {
    int up = 1, down = 1;                      // longest wiggle ending on a rise / a fall
    for (int i = 1; i < nums.length; i++) {
        if (nums[i] > nums[i - 1]) up = down + 1;    // a rise must follow a fall
        else if (nums[i] < nums[i - 1]) down = up + 1;
    }                                          // equal ⇒ neither state moves
    return Math.max(up, down);
}

Time O(n), Space O(1). This greedy-looking two-liner is dp[i][up/down] rolled flat: up = longest wiggle so far ending on a rise, and a rise can only extend a sequence that last fell — that's the whole automaton.

Worked example — dry run

LC 309 with prices = [1, 2, 3, 0, 2]. First the automaton — this drawing is the solution:

init hold=−∞ sold=−∞ rest=0 p=1 → hold=−1 (buy from rest) sold=−∞ rest=0 p=2 → hold=−1 sold=1 (−1+2) rest=0 p=3 → hold=−1 sold=2 (−1+3) rest=1 (yesterday's sold) p=0 → hold=1 (rest 1 − 0: rebuy after cooldown!) sold=−1 rest=2 p=2 → hold=1 sold=3 (1+2) rest=2 answer = max(sold, rest) = 3 (buy@1 sell@3, cooldown, buy@0 sell@2)

The interesting day is p=0: selling at 3 happened on day 2, day 3 would be the cooldown — but because rest already banked profit 1 from the day-1 sale, buying at 0 from rest is legal and sets up the final sell at 2.

5 · Edge-case checklist

  • Snapshot before updating. All states must read yesterday's values; updating free then reading it for hold in the same iteration silently allows buy-and-sell on the same day. (In LC 122 that happens to be harmless; in 714 and 309 it's a wrong answer.)
  • Initialize unreachable states to −∞ — and use Integer.MIN_VALUE / 2, because MIN_VALUE + p overflows to a huge positive number.
  • Finish holding nothing: the answer is over sell-side states; returning hold means you paid for a share you never sold.
  • LC 188: collapse k ≥ n/2 to unlimited, or a test with k = 10⁹ TLEs / blows memory.
  • Empty or 1-element prices: answer 0 — the loops handle it if free starts at 0.
  • Wiggle equal neighbors: nums[i] == nums[i-1] advances neither state — an else instead of else if breaks it.
  • Falling Path II (1289): compute the whole next row from the previous row's snapshot; updating in place lets a row "see" itself.
