Knapsack: 0/1, unbounded & the loop-order rule

Items + capacity is the most reusable DP shape in interviews. Master two loop rules — descending vs ascending, items-outer vs target-outer — and eight LC problems collapse into one template.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 4 of the 12-lesson DP track. Mission

1 · The one idea

You have items and a capacity (weight limit, target sum, amount). The state is "(items considered so far, capacity used)". 0/1 knapsack: each item usable at most once → in the 1D version, iterate capacity descending. Unbounded knapsack: items reusable → iterate capacity ascending. And when counting: items in the outer loop counts combinations; capacity/target in the outer loop counts permutations. The loop structure is the semantics.

Recognition trigger "Pick a subset with sum/weight ≤ or = target" · "fewest coins to make amount" · "number of ways to make amount" · "partition the array into two halves". The moment a problem is choose items under a budget, you are in knapsack territory — decide 0/1 vs unbounded first.

2 · State · Recurrence · Base case

PartFor the knapsack family
Statedp[i][c] = best answer (max value / true / #ways) using the first i items with capacity c. 1D version drops i: dp[c].
RecurrenceSkip item i: dp[i-1][c]. Take it: dp[i-1][c-w] (0/1 — previous row) or dp[i][c-w] (unbounded — same row). Combine with max / OR / +.
Base casedp[0] = 0 (max), true (feasibility), or 1 (counting: one way to make 0 — pick nothing). Everything else 0/false/∞.
OrderItems outer. Capacity inner: descending for 0/1, ascending for unbounded. Permutation counts flip: target outer, items inner.
Answerdp[W] (or dp[target]) after all items are processed.

3 · Core template

0/1 knapsack — 2D, then compressed to 1D descending

// dp[i][c] = max value using the first i items within capacity c.
int knapsack(int[] w, int[] val, int W) {
    int n = w.length;
    int[][] dp = new int[n + 1][W + 1];      // row 0 and column 0 stay 0 — the base case
    for (int i = 1; i <= n; i++)
        for (int c = 0; c <= W; c++) {
            dp[i][c] = dp[i - 1][c];         // choice 1: skip item i-1
            if (c >= w[i - 1])               // choice 2: take it ONCE — read the PREVIOUS row
                dp[i][c] = Math.max(dp[i][c], dp[i - 1][c - w[i - 1]] + val[i - 1]);
        }
    return dp[n][W];
}
// 1D: row i only reads row i-1, so keep one row. Capacity must DESCEND so that
// dp[c - w[i]] is still the previous item's value — ascending would let item i feed itself.
int[] dp = new int[W + 1];
for (int i = 0; i < n; i++)
    for (int c = W; c >= w[i]; c--)          // DESCENDING ⇒ each item used at most once
        dp[c] = Math.max(dp[c], dp[c - w[i]] + val[i]);
return dp[W];

Time O(n·W). Space O(W) after compression. Note: pseudo-polynomial — W is a value, not an input length.

Unbounded — Coin Change (LC 322, min coins) and Coin Change II (LC 518, count ways)

int coinChange(int[] coins, int amount) {
    int[] dp = new int[amount + 1];
    Arrays.fill(dp, amount + 1);             // "infinity" that survives the +1 without overflow
    dp[0] = 0;
    for (int coin : coins)
        for (int a = coin; a <= amount; a++) // ASCENDING ⇒ coin may be reused
            dp[a] = Math.min(dp[a], dp[a - coin] + 1);
    return dp[amount] > amount ? -1 : dp[amount];
}
int change(int amount, int[] coins) {
    int[] dp = new int[amount + 1];
    dp[0] = 1;                               // one way to make 0: choose nothing
    for (int coin : coins)                   // coins OUTER ⇒ counts COMBINATIONS ({1,2} == {2,1})
        for (int a = coin; a <= amount; a++)
            dp[a] += dp[a - coin];
    return dp[amount];
}

Time O(#coins · amount). Space O(amount) for both.

Practice — free-tier LeetCode

  • LC 322 · Coin Change (Medium, Google-reported) — implement the min template above verbatim; the whole exercise is the ascending loop + the amount + 1 infinity + the −1 check.
  • LC 518 · Coin Change II (Medium) — the counting twin: swap min for +=, base dp[0] = 1, coins stay in the OUTER loop so {2,5} and {5,2} count once.
  • LC 983 · Minimum Cost For Tickets (Medium) — unbounded min over days instead of coins: dp[day] = cheapest cover, three "coins" (1/7/30-day passes) reusable, skip non-travel days for free.
The loop-order rule — memorize this box 0/1 vs unbounded: capacity descending = each item once; ascending = reuse allowed. Combinations vs permutations (counting): items outer = order ignored (LC 518); target outer, items inner = every ordering counted separately (LC 377).

Partition Equal Subset Sum (416) — the canonical boolean 0/1

boolean canPartition(int[] nums) {
    int total = 0;
    for (int x : nums) total += x;
    if (total % 2 == 1) return false;        // odd sum can never split evenly
    int target = total / 2;
    boolean[] dp = new boolean[target + 1];
    dp[0] = true;
    for (int x : nums)
        for (int j = target; j >= x; j--)    // 0/1 → descending
            dp[j] = dp[j] || dp[j - x];
    return dp[target];
}

Target Sum (494) — algebra first, then subset-sum count

// Let P = sum of the + group. P − (total − P) = target  ⇒  P = (total + target) / 2.
int findTargetSumWays(int[] nums, int target) {
    int total = 0;
    for (int x : nums) total += x;
    int s = total + target;
    if (s < 0 || s % 2 == 1) return 0;       // no valid P exists
    int[] dp = new int[s / 2 + 1];
    dp[0] = 1;
    for (int x : nums)
        for (int j = s / 2; j >= x; j--)     // 0/1 COUNT: same shape, += instead of ||
            dp[j] += dp[j - x];
    return dp[s / 2];
}

Last Stone Weight II (1049) — "minimize the difference" is subset-sum in disguise

// Smashing stones = splitting into two piles; answer = S1 − S2 = total − 2·S2.
// Maximize the smaller pile: 0/1 knapsack, capacity total/2, value = weight.
int[] dp = new int[total / 2 + 1];
for (int s : stones)
    for (int j = total / 2; j >= s; j--)
        dp[j] = Math.max(dp[j], dp[j - s] + s);
return total - 2 * dp[total / 2];

Perfect Squares (279) — unbounded min with implicit coins

Nobody hands you a coin array here — the coins are the perfect squares 1, 4, 9, …, ⌊√n⌋², and each may be used any number of times. So this is LC 322 verbatim: state dp[a] = fewest squares summing to a; recurrence dp[a] = min over squares q² ≤ a of dp[a − q²] + 1; base dp[0] = 0; capacity ascending because reuse is allowed. One real difference from 322: since 1 is a square, every amount is reachable — there is no −1 branch to write. 

int numSquares(int n) {
    int[] dp = new int[n + 1];
    Arrays.fill(dp, n);                      // safe "infinity": n ones always work, so dp[a] ≤ n
    dp[0] = 0;
    for (int q = 1; q * q <= n; q++)         // implicit coin q² — generate, don't store
        for (int a = q * q; a <= n; a++)     // ASCENDING ⇒ each square reusable
            dp[a] = Math.min(dp[a], dp[a - q * q] + 1);
    return dp[n];
}

Time O(n·√n) — √n implicit coins, each sweeping the amount axis once. Space O(n).

Trap — copying 322's infinity blindly If you fill with Integer.MAX_VALUE and an amount were ever unreachable, dp[a − q²] + 1 overflows to negative and wins the min. Here reachability saves you, but the habit is the bug: pick an infinity that survives +1 (n here, amount + 1 in 322). Bonus flex for the follow-up: Lagrange's four-square theorem says the answer is always 1–4, so an O(√n) math check exists — say it, but the interviewer expects the DP.

Coin Change II (518) vs Combination Sum IV (377) — side by side

// LC 518 — COMBINATIONS: coins outer. Coin 2 is never revisited after coin 5,
// so 2+5 and 5+2 are counted as ONE way.
for (int coin : coins)
    for (int a = coin; a <= amount; a++)
        dp[a] += dp[a - coin];

// LC 377 — PERMUTATIONS: target outer. At EVERY amount, every num can be the
// last element, so 1+2 and 2+1 are counted as TWO ways.
for (int a = 1; a <= target; a++)
    for (int x : nums)
        if (a >= x) dp[a] += dp[a - x];

Ones and Zeroes (474) — a 2D capacity, both descending

// dp[z][o] = max #strings using at most z zeros and o ones.
int[][] dp = new int[m + 1][n + 1];
for (String s : strs) {
    int zeros = 0, ones = 0;
    for (char ch : s.toCharArray()) { if (ch == '0') zeros++; else ones++; }
    for (int z = m; z >= zeros; z--)         // each string once ⇒ BOTH capacities descend
        for (int o = n; o >= ones; o--)
            dp[z][o] = Math.max(dp[z][o], dp[z - zeros][o - ones] + 1);
}
return dp[m][n];

Worked example — dry run

LC 416 on nums = [1, 5, 11, 5]. Total = 22 → target = 11. Boolean dp[0..11], dp[0] = true. Watch what the loop direction does while processing the very first item, 1:

start: dp = {0} (only dp[0] = T) item 1: j = 11…1 → dp[1] ← dp[0]. Reachable sums {0, 1} item 5: j = 11…5 → dp[6] ← dp[1], dp[5] ← dp[0]. Sums {0, 1, 5, 6} item 11: j = 11 → dp[11] ← dp[0] = T. Sums {0, 1, 5, 6, 11} item 5: j = 11…5 → dp[10] ← dp[5]; dp[11] already T. Sums {0, 1, 5, 6, 10, 11} dp[11] = true → partition exists: {11} vs {1, 5, 5} ✓

5 · Edge-case checklist

  • Loop direction: the #1 knapsack bug. 0/1 → capacity descending; unbounded → ascending. If your subset-sum says true too often, you wrote ascending.
  • Counting base case is dp[0] = 1, not 0 — "one way to make zero: take nothing."
  • 416 / 494 parity guards: odd total → false; (total + target) odd or negative → 0 ways. Check before allocating dp.
  • 322's "infinity": use amount + 1, not Integer.MAX_VALUE — MAX_VALUE + 1 overflows to negative and wins the min.
  • Zeros and negatives: a weight-0 item in an ascending loop is an infinite loop of logic (dp[a] += dp[a] forever conceptually); negative nums break array indexing — 494 handles them via the algebra, not the loop.
  • Counting overflow: 377 fits in int per constraints, but state it; use long when counts can exceed 2³¹.
  • Inner-loop lower bound: start at w[i] (or stop when j < w[i]) — going below just wastes iterations or crashes on j - w[i].
