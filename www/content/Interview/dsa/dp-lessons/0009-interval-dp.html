Interval DP (& game DP)

When the state is a whole subarray i..j, the winning trick is to pick the last operation — the last balloon burst, the last cut — so the two sides stop interfering with each other.

Mission link: DP is ~15% of Google intern questions and your self-identified gap. This is Lesson 9 of the 12-lesson DP track. Mission

1 · The one idea

dp[i][j] = the answer for the subarray/substring i..j. The transition picks a split point k inside the interval — but here's the counter-intuitive move that makes it work: let k be the LAST operation performed, not the first. If the balloon at k is the last one burst in (i, j), then while everything else pops, the boundaries i and j stay alive — so (i, k) and (k, j) are completely independent subproblems. Fill intervals by increasing length; three nested loops give the typical O(n³). Game problems ride the same state with a minimax twist.

Recognition trigger "burst / merge / remove / cut / print over a range", the cost of an operation depends on what's still standing around it, "minimum cost to reduce the whole thing to one piece" — or two players alternately taking from the ends of an array. If a first-move decomposition leaks information between the two halves, flip it: decompose on the last move.

2 · State · Recurrence · Base case

PartFor Burst Balloons (the template carrier)
Statedp[i][j] = max coins from bursting every balloon strictly inside the open interval (i, j), with padded boundaries a[i], a[j] still alive.
Recurrencedp[i][j] = max over k in (i, j) of dp[i][k] + a[i]·a[k]·a[j] + dp[k][j] — k is the LAST balloon burst, so its neighbors at that moment are exactly the boundaries.
Base caseAdjacent indices: dp[i][i+1] = 0 — nothing strictly inside.
OrderBy increasing interval length; dp[i][j] only reads strictly shorter intervals.
Answerdp[0][n+1] — the full padded range.

3 · Core template

Burst Balloons (312) — pad with 1s, choose the last balloon

int maxCoins(int[] nums) {
    int n = nums.length;
    int[] a = new int[n + 2];
    a[0] = a[n + 1] = 1;                          // virtual 1-balloons: bursting an edge balloon pays 1·x·y
    for (int i = 0; i < n; i++) a[i + 1] = nums[i];

    int[][] dp = new int[n + 2][n + 2];           // dp[i][j] = max coins from the OPEN interval (i, j)
    for (int len = 2; len <= n + 1; len++)        // len = j - i; len 1 (adjacent) stays 0 = base case
        for (int i = 0; i + len <= n + 1; i++) {
            int j = i + len;
            for (int k = i + 1; k < j; k++)       // k = LAST balloon to burst inside (i, j)
                dp[i][j] = Math.max(dp[i][j],
                    dp[i][k] + a[i] * a[k] * a[j] + dp[k][j]);
        }                                         // when k pops last, its neighbors ARE a[i] and a[j]
    return dp[0][n + 1];
}

Time O(n³) — n² intervals × n split points. Space O(n²). No rolling array here: dp[i][j] reads both a shorter-left and a shorter-right interval, so the whole triangle stays live. A top-down memo on (i, j) is equally valid and sometimes easier to write — same complexity, and handy when many intervals are unreachable.

Why "first balloon" fails — the trap that defines this family Try defining dp[i][j] with k as the first balloon burst: the moment k pops, the balloons on the left and right of k become adjacent — the two halves now interact, and the state no longer describes an intact contiguous range. Choosing the last operation freezes the boundaries and cuts the dependency. Whenever an interval DP feels impossible, ask: "what if I fix the last move instead of the first?"

Matrix Chain Multiplication — the mother template

// n matrices; matrix i has dimensions p[i-1] × p[i]. Minimize scalar multiplications.
int matrixChain(int[] p) {
    int n = p.length - 1;
    int[][] dp = new int[n + 1][n + 1];           // dp[i][j] = min cost to multiply matrices i..j (CLOSED, 1-based)
    for (int len = 2; len <= n; len++)
        for (int i = 1; i + len - 1 <= n; i++) {
            int j = i + len - 1;
            dp[i][j] = Integer.MAX_VALUE;
            for (int k = i; k < j; k++)           // LAST multiply joins (i..k)·(k+1..j)
                dp[i][j] = Math.min(dp[i][j],
                    dp[i][k] + dp[k + 1][j] + p[i - 1] * p[k] * p[j]);
        }
    return dp[1][n];                              // dp[i][i] = 0: one matrix needs no multiply
}

Note the closed-interval flavor: subranges are i..k and k+1..j. Burst Balloons uses the open-interval flavor ((i,k) and (k,j) share the point k) because the last element k contributes cost with both boundaries. Pick the flavor where the pieces don't overlap and don't leave gaps.

Minimum Cost to Cut a Stick (1547) — MCM in a costume

int minCost(int n, int[] cuts) {
    int m = cuts.length;
    int[] c = new int[m + 2];
    System.arraycopy(cuts, 0, c, 1, m);
    c[m + 1] = n;                                  // c[0] = 0 and c[m+1] = n are the stick's ends
    Arrays.sort(c);
    int[][] dp = new int[m + 2][m + 2];            // dp[i][j] = min cost to make all cuts strictly inside (c[i], c[j])
    for (int len = 2; len <= m + 1; len++)
        for (int i = 0; i + len <= m + 1; i++) {
            int j = i + len;
            dp[i][j] = Integer.MAX_VALUE;
            for (int k = i + 1; k < j; k++)        // k = FIRST cut here — every cut in (i,j) costs the same c[j]−c[i]
                dp[i][j] = Math.min(dp[i][j],
                    dp[i][k] + dp[k][j] + c[j] - c[i]);
        }
    return dp[0][m + 1];
}

Key insight: the DP runs over the cut positions (≤ 100 of them), never over the stick length (up to 10⁶). Whenever n is huge but the "interesting points" are few, re-index the interval DP onto the interesting points.

Guess Number Higher or Lower II (375) — adversarial: min of max

int getMoneyAmount(int n) {
    int[][] dp = new int[n + 2][n + 2];            // dp[i][j] = $ guaranteeing a win on range i..j; len ≤ 1 → 0
    for (int len = 2; len <= n; len++)
        for (int i = 1; i + len - 1 <= n; i++) {
            int j = i + len - 1;
            dp[i][j] = Integer.MAX_VALUE;
            for (int k = i; k <= j; k++)           // guess k, pay k; adversary answers with the WORSE side
                dp[i][j] = Math.min(dp[i][j],
                    k + Math.max(dp[i][k - 1], dp[k + 1][j]));
        }
    return dp[1][n];
}

Time O(n³), Space O(n²) — the same three-loop skeleton, but the inner combine is min over k of (k + max(left, right)): you pick the guess, the adversary picks which side the secret is on. Whenever a problem says "guarantee a win no matter what", expect a max nested inside your min.

Game DP — Predict the Winner (486); Stone Game (877) is the same code

boolean predictTheWinner(int[] nums) {
    int n = nums.length;
    int[][] dp = new int[n][n];                    // dp[i][j] = best (my score − opponent's) for the player TO MOVE on i..j
    for (int i = 0; i < n; i++) dp[i][i] = nums[i];
    for (int len = 2; len <= n; len++)
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i][j] = Math.max(nums[i] - dp[i + 1][j],   // take left; opponent's best diff flips sign
                                nums[j] - dp[i][j - 1]);  // take right
        }
    return dp[0][n - 1] >= 0;                      // first player wins (or ties) iff diff ≥ 0
}

The score difference trick collapses "track both players' totals" into one number: whatever the opponent achieves on the remaining interval is subtracted, because the roles alternate. Stone Game (877) is this verbatim — plus a party trick: with an even pile count and odd total, the first player can always win (return true), but say the DP too; the follow-ups (1140, 1406) have no such shortcut.

Minimum Score Triangulation (1039) — MCM with a triangle cost

Triangulate a convex polygon with vertex values v[0..n-1] so the total of each triangle's vertex product is minimal. The interval view: in any triangulation, the edge between vertices i and j is a side of exactly one triangle — call its third vertex k. Fixing that triangle (the "last piece" laid on edge i–j) splits the polygon into the chains i..k and k..j, which triangulate independently. So dp[i][j] = min score for the sub-polygon on vertices i..j; any stretch of fewer than 3 vertices holds no triangle and costs 0 — that's the base case.

int minScoreTriangulation(int[] v) {
    int n = v.length;
    int[][] dp = new int[n][n];                // dp[i][j] = min score for the sub-polygon on vertices i..j
    for (int len = 3; len <= n; len++)         // len = vertex count j−i+1; len < 3 stays 0 = base case
        for (int i = 0; i + len - 1 < n; i++) {
            int j = i + len - 1;
            dp[i][j] = Integer.MAX_VALUE;
            for (int k = i + 1; k < j; k++)    // k = third vertex of the triangle resting on edge (i, j)
                dp[i][j] = Math.min(dp[i][j],
                    dp[i][k] + v[i] * v[k] * v[j] + dp[k][j]);
        }
    return dp[0][n - 1];
}

Time O(n³), Space O(n²). Note the open-interval sharing: k belongs to both subproblems (dp[i][k] and dp[k][j]), exactly like Burst Balloons — the chains share their endpoint vertices with the chosen triangle. The cost line v[i]·v[k]·v[j] is even the same shape as the balloon product.

Strange Printer (664) — merge-style: equal characters share a stroke

The printer prints a run of one character per turn, and later turns may overwrite parts of earlier ones. Minimum turns to produce s? State: dp[i][j] = min turns to print s[i..j]. Baseline: give s[i] its own stroke and handle the rest — 1 + dp[i+1][j]. The saving move: if some s[k] == s[i] inside the interval, the stroke that lays down s[i] can be stretched right to also lay down position k (the middle gets overwritten later anyway), so k's character costs nothing extra: dp[i][j] = dp[i+1][k-1] + dp[k][j]. The first stroke counted inside dp[k][j] is the same physical stroke as i's — that's why no +1 appears in the merge branch. Base cases: one character = 1 turn, empty interval = 0.

char[] c;
Integer[][] memo;

int strangePrinter(String s) {
    c = s.toCharArray();
    int n = c.length;
    memo = new Integer[n][n];
    return prints(0, n - 1);
}

int prints(int i, int j) {
    if (i > j) return 0;                      // empty interval: nothing to print
    if (memo[i][j] != null) return memo[i][j];
    int best = 1 + prints(i + 1, j);          // worst case: s[i] gets its own dedicated stroke
    for (int k = i + 1; k <= j; k++)
        if (c[k] == c[i])                     // merge: stretch s[i]'s stroke to also paint position k…
            best = Math.min(best,
                prints(i + 1, k - 1)          // …print the middle over it later…
                + prints(k, j));              // …and s[k]'s "first stroke" here IS s[i]'s stroke
    return memo[i][j] = best;
}

Time O(n³) — n² states × n merge candidates. Space O(n²). Top-down memo suits this one: many (i, j) pairs are never reached, and the merge recurrence is far easier to state recursively than as loop bounds. A free speed-up that changes no answers: collapse consecutive duplicates first ("aaabbb" → "ab") — equal neighbors always share a stroke.

Classic bug — paying for the shared stroke twice Writing the merge branch as 1 + prints(i+1, k-1) + prints(k, j) double-counts: the whole point is that s[k]'s stroke inside prints(k, j) already is s[i]'s stroke. Also note k = i+1 makes the middle interval empty — the i > j → 0 guard is what keeps that call honest, so never "optimize" it away.

Read the winning line backwards: the best plan bursts balloon 8 last (earning 1·8·1 with only the padding left), and dp[0][4]=159 recursively says balloon 3 pops last among {3,1,5} while 8 still stands as the right boundary. The "last move" framing turns an ordering nightmare into table lookups.

5 · Edge-case checklist

  • Loop by length, not by i then j — iterating i ascending and j ascending reads intervals that aren't computed yet. Length-first is the only safe default.
  • Open vs closed intervals: Burst Balloons/1547 use open (i, j) with shared endpoint k; MCM/486 use closed i..j with split k / k+1. Mixing flavors double-counts or drops the element at k.
  • Padding: forgetting the virtual 1s (312) or the stick ends 0 and n (1547) breaks every boundary product. Pad first, then never special-case edges again.
  • Zeros and negatives: balloons worth 0 are handled by the max; but if a problem allows negative values, initializing dp to 0 silently forbids "do the operations anyway" — initialize to −∞/+∞ and relax properly.
  • MAX_VALUE sentinel + addition = overflow: in min-flavored variants (MCM, 375, 1547), never add to an unrelaxed Integer.MAX_VALUE cell — structure loops so every interval of length ≥ the base is relaxed at least once, or use / 2 sentinels.
  • Game DP sign discipline: the difference flips exactly once per move — nums[i] − dp[i+1][j]. Writing + dp models a cooperative opponent and returns nonsense.
  • Complexity sanity check: O(n³) means n ≤ ~500. If n is 10⁵, interval DP is the wrong tool — re-read the constraints before committing.
