Two Pointers Track · Lesson 2 of 3 · reader/writer compaction and in-place partitioning

Same-Direction Pointers & Partition

One pointer reads every element; a slower pointer writes only the keepers. In-place array rewrites in O(n) time, O(1) space — no shifting, no second array.

Mission link: "do it in place with O(1) extra memory" is the exact sentence OA graders use to force this pattern — LC 26, 283, and 75 are among the most-asked easy/mediums at big tech. This is Lesson 2 of the 3-lesson Two Pointers track. Mission

1 · The one idea

Suppose you must remove elements from an array in place. The naive move — delete one, shift everything after it left — costs O(n) per deletion, O(n²) total. The fix: stop shifting and start rewriting. Run a fast pointer read over every element, and keep a slow pointer write marking the end of the "good" prefix. When read finds a keeper, copy it to write and advance write. Every element is touched once — O(n) — and the invariant "everything in [0, write) is exactly the answer so far" holds at every step. The same slow/fast idea, with swaps instead of copies, partitions an array into regions (zeroes vs non-zeroes, three colors) in one pass.

Recognition trigger "Remove / keep / move elements in place," "return the new length," "O(1) extra space," "relative order preserved," or "sort an array of only k distinct values." Also: merging or transforming two sorted arrays — same two-pointer machinery, one pointer per array. Whenever your first instinct is "build a second array and copy the survivors," ask if a write pointer can do it in place.

2 · Core template — Remove Duplicates from Sorted Array (LC 26)

Sorted array; keep each value once, in place, return the count. Because it's sorted, duplicates are adjacent — so an element is a keeper exactly when it differs from the last thing we wrote. 

// LC 26: reader/writer compaction. Everything in [0, write) is deduped and final.
int removeDuplicates(int[] a) {
    int write = 1;                       // a[0] is always kept; first free slot is 1
    for (int read = 1; read < a.length; read++) {
        if (a[read] != a[write - 1]) {   // differs from the LAST KEPT value → keeper
            a[write] = a[read];          // write it into the good prefix
            write++;
        }                                // duplicate → read moves on, write stays
    }
    return write;                        // length of the deduped prefix; a[write..] is garbage
}

Time O(n) — one pass. Space O(1) — the array is its own output buffer. Note write ≤ read always, so the write never clobbers something the reader still needs.

Worked example — dry run

a = [1, 1, 2, 2, 3]:

write=1 read=1: a[1]=1 == a[0]=1 → dup, skip write=1 read=2: a[2]=2 != 1 → a[1]=2, write→2 array [1,2,2,2,3] write=2 read=3: a[3]=2 == a[1]=2 → dup, skip write=2 read=4: a[4]=3 != 2 → a[2]=3, write→3 array [1,2,3,2,3] return 3 — prefix [1,2,3] is the answer; the tail is ignored garbage

Case: Move Zeroes (LC 283)

Push all zeroes to the back, keep the other numbers in order, in place. Same skeleton — the keeper test is now != 0 — but swap instead of copy, so the zeroes automatically end up in the tail and you don't need a second fill pass. 

void moveZeroes(int[] a) {
    int write = 0;                       // next slot for a non-zero
    for (int read = 0; read < a.length; read++) {
        if (a[read] != 0) {              // keeper
            int t = a[write]; a[write] = a[read]; a[read] = t; // swap: the zero (if any) jumps back
            write++;
        }
    }
}                                        // invariant: [0,write) non-zero in order, [write,read) all zero

Time O(n), Space O(1). (Copy-then-fill-zeroes also works; the swap version does it in one pass and generalizes to Sort Colors.)

Case: Merge Sorted Array (LC 88) — write from the back

nums1 has m real values plus n empty slots; merge sorted nums2 (n values) into it in place. Merging front-to-back overwrites nums1 values you haven't read yet. The trick: the free space is at the end, so write the largest element into the last slot and walk backwards. The writer can never catch up to the unread data. 

void merge(int[] nums1, int m, int[] nums2, int n) {
    int i = m - 1, j = n - 1;            // last REAL element of each array
    int w = m + n - 1;                   // last slot overall — write backwards from here
    while (j >= 0) {                     // when nums2 is drained, nums1's rest is already in place
        if (i >= 0 && nums1[i] > nums2[j])
            nums1[w--] = nums1[i--];     // bigger tail wins the slot
        else
            nums1[w--] = nums2[j--];
    }
}

Time O(m + n), Space O(1). The loop condition is j >= 0, not i >= 0: leftover nums1 elements are already sorted in position, but leftover nums2 elements still need copying.

Case: Squares of a Sorted Array (LC 977)

Square a sorted array (may contain negatives), return sorted. Naive: square then sort, O(n log n). Insight: after squaring, the largest values live at the two ends of the original array (most negative or most positive). So read with converging pointers from both ends, and write the winner backwards into a result array — largest first. 

int[] sortedSquares(int[] a) {
    int n = a.length;
    int[] res = new int[n];
    int l = 0, r = n - 1;
    for (int w = n - 1; w >= 0; w--) {   // fill result from the BACK (biggest square first)
        int ls = a[l] * a[l], rs = a[r] * a[r];
        if (ls > rs) { res[w] = ls; l++; }  // left end (very negative) wins
        else         { res[w] = rs; r--; }
    }
    return res;
}

Time O(n), Space O(n) for the output (required anyway). This one blends both lessons: opposite-ends readers, same-direction writer.

Case: Sort Colors / Dutch National Flag (LC 75)

Array of 0s, 1s, 2s — sort in one pass, O(1) space. Three pointers carve the array into four zones: [0, lo) all 0s, [lo, mid) all 1s, [mid, hi] unknown, (hi, n) all 2s. Look at a[mid] and shrink the unknown zone by one each step. 

void sortColors(int[] a) {
    int lo = 0, mid = 0, hi = a.length - 1;
    while (mid <= hi) {                  // unknown zone is [mid..hi]; loop until it's empty
        if (a[mid] == 0) {
            int t = a[lo]; a[lo] = a[mid]; a[mid] = t;
            lo++; mid++;                 // swapped-in value came from the 1s zone → already classified → mid++ OK
        } else if (a[mid] == 1) {
            mid++;                       // 1 is already in its zone
        } else {                         // a[mid] == 2
            int t = a[mid]; a[mid] = a[hi]; a[hi] = t;
            hi--;                        // DON'T mid++ — the value swapped in from hi is UNSEEN
        }
    }
}

Time O(n), Space O(1). Naive alternatives: any sort O(n log n), or counting sort O(n) but two passes — the interviewer wants this one-pass version.

The Dutch-flag bug everyone writes once After swapping a 2 to the back, do not advance mid — the element that arrived from hi is unexamined and could be a 0 that still needs to travel left. After swapping a 0 to the front, advancing mid IS safe, because whatever sat at lo was already classified (it's a 1, or lo == mid). Asymmetric on purpose.

4 · Edge-case checklist

  • Empty and length-1 arrays — LC 26 with write = 1 on an empty array would crash if you don't guard, or just start the pattern at index 0 where safe. Check constraints (LC 26 guarantees n ≥ 1).
  • Compare against the last written value (a[write-1]), not a[read-1] — with "keep at most 2 duplicates" (LC 80) that distinction is the whole problem.
  • All-keepers / all-rejects inputs — array of all zeroes for LC 283, strictly increasing array for LC 26. The pointers should just glide through; verify no swap-with-self issues (swapping a[i] with itself is harmless).
  • LC 88: loop on j >= 0 — if you loop while i >= 0 too and exit early, unmerged nums2 values are silently dropped. And never merge front-to-back: you overwrite unread data.
  • LC 75: mid <= hi, not < — the element at hi itself is still unclassified.
  • Return value vs mutation — LC 26 returns a length and the grader only reads that prefix; LC 283 returns void. Read the contract.
  • Stability — reader/writer copy preserves relative order (LC 283 requires it); Dutch-flag swapping does not. Know which the problem demands.
