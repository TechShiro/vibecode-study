The K-Sum Family

Fix the outer numbers with loops, sort once so the innermost pair falls to the Lesson-1 template — and learn the dedup-skip idiom that makes "no duplicate triplets" trivial.

Mission link: 3Sum (LC 15) is one of the most-asked interview questions in existence — Meta, Amazon, and Google all use it, and the dedup handling is exactly what separates a hire from a no-hire. This is Lesson 3 of the 3-lesson Two Pointers track. Mission

1 · The one idea

You know 2Sum on a sorted array is O(n) with opposite-ends pointers (Lesson 1). Every k-sum problem reduces to that: sort once, fix the first k−2 numbers with nested loops, and solve the last two with the two-pointer template. 3Sum = one outer loop + 2Sum inside → O(n²). 4Sum = two outer loops + 2Sum → O(n³). Compare the naives: 3 nested loops for 3Sum is O(n³); the sort buys you a factor of n. Sorting also solves the "no duplicate triplets" requirement for free — equal values sit adjacent, so skipping repeats at each level guarantees uniqueness without a HashSet.

Recognition trigger "Find all triplets / quadruplets that sum to X," "no duplicate triplets allowed," "closest sum to target." Any pair/triple/k-tuple sum question where the array is unsorted but sorting is allowed (you return values or sums, not original indices). If original indices are required (LC 1, Two Sum), sorting destroys them — use a HashMap instead. That's the fork in the road.

2 · Core template — 3Sum (LC 15)

All unique triplets summing to 0. Sort. For each anchor i, run 2Sum on the suffix (i, n−1] targeting −a[i]. Three dedup skips keep the output unique: one at the anchor, and one on each inner pointer after recording a hit. 

// LC 15: sort + anchor + two pointers. O(n^2) time, O(1) extra space (ignoring output).
List<List<Integer>> threeSum(int[] a) {
    Arrays.sort(a);                          // O(n log n), dwarfed by the O(n^2) scan
    List<List<Integer>> res = new ArrayList<>();
    for (int i = 0; i < a.length - 2; i++) {
        if (a[i] > 0) break;                 // smallest element positive → no zero-sum possible; done
        if (i > 0 && a[i] == a[i - 1]) continue; // DEDUP anchor: same anchor value → same triplets
        int l = i + 1, r = a.length - 1;     // 2Sum on the suffix, target -a[i]
        while (l < r) {
            int sum = a[i] + a[l] + a[r];
            if (sum < 0) l++;                // Lesson-1 elimination: a[l] is dead
            else if (sum > 0) r--;
            else {
                res.add(List.of(a[i], a[l], a[r]));
                l++; r--;                    // keep searching — more pairs may hit the target
                while (l < r && a[l] == a[l - 1]) l++; // DEDUP inner: hop over repeated values
                while (l < r && a[r] == a[r + 1]) r--;
            }
        }
    }
    return res;
}

Time O(n²) — n anchors × O(n) two-pointer sweep. Space O(1) beyond the output (sort is in place). The naive triple loop plus HashSet-of-triplets is O(n³) and a red flag in interviews.

Worked example — dry run

a = [-1, 0, 1, 2, -1, -4] → sorted [-4, -1, -1, 0, 1, 2]:

i=0 (-4): l=1(-1) r=5(2) sum=-3<0→l++ … no pair reaches +4 → nothing i=1 (-1): l=2(-1) r=5(2) sum=0 → hit [-1,-1,2]; l→3, r→4; sum=-1+0+1=0 → hit [-1,0,1] i=2 (-1): a[2]==a[1] → skip anchor — its triplets were already found at i=1 i=3 (0): l=4(1) r=5(2) sum=3>0→r-- → l==r, stop. Result: [[-1,-1,2], [-1,0,1]]
The dedup-skip idiom — memorize its two placements Anchor level: if (i > start && a[i] == a[i-1]) continue; — skip a value you've already anchored on. Inner level: after recording a hit, slide l and r past clones. Never skip the anchor with a[i] == a[i+1] — that would forbid triplets that legitimately use duplicates, like [-1, -1, 2]. Compare backwards, not forwards.

Case: 3Sum Closest (LC 16)

Return the single triplet sum closest to target. Same anchor + two-pointer skeleton, but there's no "found it" case to collect — every step just updates the champion. Since only one number is returned, duplicate suppression is unnecessary. If the sum ever equals target exactly, nothing can beat it — return immediately. 

int threeSumClosest(int[] a, int target) {
    Arrays.sort(a);
    int best = a[0] + a[1] + a[2];           // seed with a real triplet, not MAX_VALUE hacks
    for (int i = 0; i < a.length - 2; i++) {
        int l = i + 1, r = a.length - 1;
        while (l < r) {
            int sum = a[i] + a[l] + a[r];
            if (sum == target) return sum;   // distance 0 — can't do better
            if (Math.abs(sum - target) < Math.abs(best - target))
                best = sum;                  // new champion
            if (sum < target) l++; else r--; // same elimination move as plain 3Sum
        }
    }
    return best;
}

Time O(n²), Space O(1).

Case: 4Sum (LC 18) — the generalization

Two anchor loops around the same 2Sum core. Everything you know scales: dedup-skip at each anchor level (always comparing against the previous index at that level's start), two pointers innermost. New danger: with values up to 10⁹ and a target that can be extreme, four ints can overflow — sum in long. 

List<List<Integer>> fourSum(int[] a, int target) {
    Arrays.sort(a);
    List<List<Integer>> res = new ArrayList<>();
    int n = a.length;
    for (int i = 0; i < n - 3; i++) {
        if (i > 0 && a[i] == a[i - 1]) continue;       // dedup anchor 1
        for (int j = i + 1; j < n - 2; j++) {
            if (j > i + 1 && a[j] == a[j - 1]) continue; // dedup anchor 2 — note j > i+1, NOT j > 0
            int l = j + 1, r = n - 1;
            while (l < r) {
                long sum = (long) a[i] + a[j] + a[l] + a[r]; // long: 4 ints can overflow int
                if (sum < target) l++;
                else if (sum > target) r--;
                else {
                    res.add(List.of(a[i], a[j], a[l], a[r]));
                    l++; r--;
                    while (l < r && a[l] == a[l - 1]) l++; // inner dedup, same as 3Sum
                    while (l < r && a[r] == a[r + 1]) r--;
                }
            }
        }
    }
    return res;
}

Time O(n³), Space O(1) beyond output. The pattern generalizes: kSum = k−2 anchor loops + one two-pointer sweep = O(nk−1). Interviewers love asking "now do it for k" — answer: recurse, peeling one anchor per level until k = 2.

The j > i + 1 subtlety The second anchor's dedup guard is j > i + 1, not j > 0. At j == i + 1, a[j] == a[i] is legal — the quadruplet genuinely uses two equal values (e.g. [2, 2, …]). Only skip j when it repeats a value already tried in the j loop itself. This mirrors "compare backwards at your own level" from the 3Sum tip — each loop level dedups independently, starting one past its own start.

4 · Edge-case checklist

  • Fewer than k elements — loops with bounds like i < n - 2 handle n < 3 by never running; don't add special cases that break this.
  • All same values — [0,0,0,0] must yield exactly one triplet [0,0,0]. If your skips are misplaced you'll emit it three times (or zero times).
  • Dedup direction — compare against the previous index at the same level (a[i] == a[i-1], guarded by i > levelStart); comparing forward forbids valid duplicate-using answers.
  • Inner skips only after a hit — skipping duplicates on every iteration of the while loop can jump past the one pair that sums to target.
  • Overflow (LC 18) — cast the first operand: (long) a[i] + a[j] + …; casting the finished int sum is too late.
  • Sorting vs indices — k-sum problems return values, so sorting is fine. If a problem wants original indices, sorting breaks it — switch to a HashMap (LC 1).
  • Early exits — in 3Sum, a[i] > 0 ends everything (sorted → all further sums positive). In 3Sum Closest, an exact hit returns immediately. Cheap points with the interviewer.
