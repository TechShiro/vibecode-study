Fast & Slow Pointers — Cycle Detection

Two runners on the same track: if it loops, the fast one must lap the slow one. Cycles, midpoints, and "does this sequence repeat?" — all in O(1) space.

Mission link: Linked List Cycle is a classic 10-minute screener, and its follow-up (find the cycle start) filters out everyone who memorized without understanding. This is Lesson 1 of the 2-lesson Fast & Slow track. Mission

1 · The one idea

Run two pointers from the head: slow moves 1 step per tick, fast moves 2. In a straight list, fast hits null and you're done — no cycle. In a cyclic list, both eventually orbit the loop, and since fast gains on slow by exactly one node per tick, the gap between them shrinks 1, 0 — they must collide, they can't jump over each other. That's Floyd's tortoise & hare: cycle detection with two pointers and zero extra memory, where a HashSet would cost O(n).

Recognition trigger "Does the linked list have a cycle," "find where the cycle begins," "middle of the list," or any process that repeats deterministically — like repeatedly applying a function to a number (Happy Number). If each state has exactly one successor and the state space is finite, the trajectory either terminates or cycles — and Floyd's detects which, in O(1) space.

2 · Core template — Floyd's cycle detection (LC 141)

boolean hasCycle(ListNode head) {
    ListNode slow = head, fast = head;       // both start at head
    while (fast != null && fast.next != null) { // fast does the null-checking for both
        slow = slow.next;                    // tortoise: 1 step
        fast = fast.next.next;               // hare: 2 steps
        if (slow == fast) return true;       // collision ⇒ cycle (compare AFTER moving)
    }
    return false;                            // fast fell off the end ⇒ straight list
}

Time O(n) — slow walks at most n + cycle-length steps before collision. Space O(1). Compare with == (same node object), never .val — values can repeat.

Why they MUST meet (the one-liner proof) Once both pointers are inside the cycle, look at the gap from fast to slow measured along the cycle. Each tick, slow moves 1 and fast moves 2, so the gap shrinks by exactly 1 per tick. A gap that shrinks by 1 hits 0 — it can't skip from 1 to −1. Collision guaranteed within one lap.

Case: Linked List Cycle II — find the entrance (LC 142)

Phase 1 is the template. Phase 2: reset slow to head, keep fast at the collision point, and advance both one step at a time. Where they meet is the cycle's first node. 

ListNode detectCycle(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {  // phase 1: find any meeting point
        slow = slow.next;
        fast = fast.next.next;
        if (slow == fast) {                      // collided somewhere inside the cycle
            slow = head;                         // phase 2: reset ONE pointer to head
            while (slow != fast) {               // both now walk at speed 1
                slow = slow.next;
                fast = fast.next;
            }
            return slow;                         // meeting point = cycle entrance
        }
    }
    return null;                                 // no cycle
}

Time O(n), Space O(1).

The reset-to-head proof sketch (interviewers ask) Let a = distance head → cycle entrance, b = entrance → collision point (along the cycle), c = cycle length. At collision, slow has walked a + b; fast has walked 2(a + b) and the same path plus whole laps: a + b + k·c. Setting them equal: 2(a+b) = a + b + k·c ⇒ a + b = k·c ⇒ a = k·c − b. So walking a steps from the head lands exactly where walking a steps from the collision point does: b + a = k·c ≡ the entrance (whole laps vanish). Hence: reset one pointer to head, step both by 1, and they meet precisely at the entrance.

Case: Middle of the Linked List (LC 876)

Same race, no cycle: when fast exhausts the list, slow has covered exactly half. This is the "find mid" step you'll reuse in Reorder List and Palindrome List (Lesson 2). 

ListNode middleNode(ListNode head) {
    ListNode slow = head, fast = head;
    while (fast != null && fast.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    return slow;   // odd n: exact middle; even n: SECOND of the two middles
}

Time O(n), Space O(1).

Which middle? The guard decides With an even-length list, while (fast != null && fast.next != null) leaves slow on the second middle (what LC 876 wants), while while (fast.next != null && fast.next.next != null) leaves slow on the first middle (what you want before cutting a list in half, e.g. LC 143/234 — the first half keeps the extra node). Pick deliberately; dry-run on a 4-node list to confirm.

Case: Happy Number (LC 202) — Floyd's without a list

Repeatedly replace n by the sum of the squares of its digits; n is "happy" if this reaches 1. Since each value has exactly one successor and values stay bounded, the sequence either hits 1 or falls into a loop. That's a linked list in disguise — next(n) is the pointer. Run the same two-speed race instead of storing seen values in a HashSet. 

boolean isHappy(int n) {
    int slow = n, fast = next(n);            // fast starts one step ahead (values, not nodes)
    while (fast != 1 && slow != fast) {
        slow = next(slow);                   // 1 application
        fast = next(next(fast));             // 2 applications
    }
    return fast == 1;                        // reached 1 → happy; collided → trapped in a loop
}
int next(int n) {                            // "the arrow": sum of squared digits
    int sum = 0;
    while (n > 0) { int d = n % 10; sum += d * d; n /= 10; }
    return sum;
}

Time O(log n) per next call, bounded total. Space O(1) — the whole point versus the HashSet version.

4 · Edge-case checklist

  • Null-check via fast only: fast != null && fast.next != null covers slow too (slow trails fast). Checking fast.next.next without checking fast.next first NPEs on even-length lists.
  • Compare after moving. Both start at head, so an at-the-top equality check "detects" a cycle in every non-empty list. Move first, then test slow == fast.
  • Node identity, not value: slow == fast compares references. Lists can contain duplicate values; .val comparison gives false positives.
  • Empty / 1-node list: the guard fails immediately → no cycle, and for LC 876 a 1-node list returns itself. The template needs no special cases — but say so.
  • Phase 2 speed (LC 142): after the reset, BOTH pointers move one step. Leaving fast at double speed breaks the a = k·c − b algebra.
  • Even-length middle: know which guard gives which middle (see the trap above) — it's the difference between a right answer and an off-by-one in LC 143/234.
  • Collision point ≠ entrance. Where they first meet is some point inside the cycle, generally not the start — that's exactly why LC 142 needs phase 2.
