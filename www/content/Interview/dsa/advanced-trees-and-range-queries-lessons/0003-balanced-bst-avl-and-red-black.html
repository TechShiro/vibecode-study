Balanced BSTs: AVL & Red-Black Trees

Preventing degenerate linked-list trees using tree rotations and color invariants.

Track goal: Master advanced competitive structures from 0 level. Lesson 3 of 3 in Advanced Trees. Index

1 · The One Idea

If you insert sorted numbers [1, 2, 3, 4, 5] into a regular Binary Search Tree (BST), the tree degenerates into a single long stick (linked list) with depth $N$. Search time degrades from $O(\log N)$ to $O(N)$! Self-Balancing BSTs rebalance themselves after every insertion and deletion using Tree Rotations (Left Rotation and Right Rotation), mathematically guaranteeing height remains strictly bounded by $O(\log N)$.

2 · AVL Trees (Strict Balance)

For every node, the Balance Factor is: $ ext{Height}( ext{left}) - ext{Height}( ext{right}) \in \{-1, 0, +1\}$. If an insertion causes balance factor to become $\pm 2$, one of four rotations restores balance in $O(1)$ time:

  1. Left-Left (LL): Single Right Rotation.
  2. Right-Right (RR): Single Left Rotation.
  3. Left-Right (LR): Left Rotate on child, then Right Rotate on parent.
  4. Right-Left (RL): Right Rotate on child, then Left Rotate on parent.

3 · Red-Black Trees (Relaxed Balance — Used by Java TreeMap & C++ std::map)

AVL trees balance so strictly that frequent insertions cause excessive rotations. Red-Black Trees relax the balance rule, guaranteeing height $\le 2 \log_2(N+1)$ with faster insertion/deletion performance:

  • Every node is colored either Red or Black.
  • The root is always Black.
  • No two Red nodes can be adjacent (A Red parent cannot have a Red child).
  • Every path from root to leaf contains the exact same number of Black nodes (Black Height invariant).
