Iterative Traversals & Level Order

Recursion's call stack is just a stack — so build it yourself. Then swap the stack for a queue and the traversal flips from depth-first to level-by-level.

Mission link: "print the tree level by level" and its variants (zigzag, right side view) are OA staples, and interviewers love asking for the iterative version to test if you understand the machinery. Lesson 2 of 6. Mission

1 · The one idea

Recursive traversal works because the call stack remembers every node you must come back to. Replace it with an explicit Deque<TreeNode> and you get the same traversal with no recursion — immune to stack overflow, pausable mid-stream (crucial for Kth Smallest, Lesson 5). And here's the deeper insight: the container decides the order. A stack (LIFO) dives deep — DFS. A queue (FIFO) sweeps wide — BFS, i.e. level order. Same loop, different container, completely different traversal.

Recognition trigger Queue/BFS: "level by level", "level averages", "zigzag", "right side view", "deepest/widest level", "minimum depth". Explicit stack: "iterative", "without recursion", tree too deep for the call stack, or you need to pause a traversal (kth element, BST iterator LC 173). Morris: the rare "O(1) space" follow-up.

2 · Core template

Core A — iterative in-order (the "slide left, pop, go right" loop)

The naive attempt — push root, pop, push children — gives pre-order-ish output, not in-order, because in-order must defer a node until its whole left spine is consumed. So the loop does exactly what recursion did: slide down the left spine pushing everything, pop (that's the visit), then step into the popped node's right subtree. 

// Iterative in-order. Time O(n), Space O(h) for the stack.
List<Integer> inorderTraversal(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) {          // slide down the LEFT spine…
            stack.push(cur);           // …remembering every node passed
            cur = cur.left;
        }
        cur = stack.pop();             // leftmost unvisited node
        out.add(cur.val);              // VISIT — this is the in-order moment
        cur = cur.right;               // now do its right subtree the same way
    }
    return out;
}

Time O(n) — each node pushed and popped once. Space O(h).

Core B — level order with the level-size loop (LC 102)

A queue alone gives you nodes in breadth-first order, but mixed across levels. The level-size idiom separates them: snapshot q.size() at the top of each round — that count is exactly the current level — and drain only that many before starting the next round. This idiom is the backbone of every level-order variant. 

// BFS level order. Time O(n), Space O(w) where w = max level width (up to n/2).
List<List<Integer>> levelOrder(TreeNode root) {
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();           // ★ freeze the level size BEFORE draining
        List<Integer> level = new ArrayList<>();
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            level.add(n.val);
            if (n.left  != null) q.offer(n.left);   // children join the NEXT level
            if (n.right != null) q.offer(n.right);
        }
        out.add(level);
    }
    return out;
}

Worked example — dry run (level order)

tree: 3 / (9, 20) / (20 → 15, 7) — q = [3] size=1: poll 3 → level [3]; offer 9, 20 → q = [9, 20] size=2: poll 9 (no kids), poll 20 → level [9, 20]; offer 15, 7 → q = [15, 7] size=2: poll 15, poll 7 → level [15, 7]; q empty → stop output: [[3], [9, 20], [15, 7]]
The level-size bug Writing for (int i = 0; i < q.size(); i++) re-reads the size while you're adding children, smearing levels together. Always snapshot: int size = q.size(); first, then loop to size. This is the #1 BFS bug in interviews.

Case: iterative pre-order (LC 144)

Pre-order is the easy one: visiting happens at pop time, so just push children after visiting — right first, so left pops first (LIFO).

List<Integer> preorderTraversal(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Deque<TreeNode> stack = new ArrayDeque<>();
    stack.push(root);
    while (!stack.isEmpty()) {
        TreeNode n = stack.pop();
        out.add(n.val);                          // visit on pop
        if (n.right != null) stack.push(n.right); // right pushed FIRST…
        if (n.left  != null) stack.push(n.left);  // …so left pops first
    }
    return out;
}

Case: Zigzag level order (LC 103)

Exactly Core B plus a direction flag. Cleanest trick: build each level in a LinkedList and addFirst on right-to-left levels — no reversing pass.

List<List<Integer>> zigzagLevelOrder(TreeNode root) {
    List<List<Integer>> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    boolean leftToRight = true;
    while (!q.isEmpty()) {
        int size = q.size();
        LinkedList<Integer> level = new LinkedList<>();
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            if (leftToRight) level.addLast(n.val);
            else             level.addFirst(n.val); // reversed insertion, O(1)
            if (n.left  != null) q.offer(n.left);   // queue order NEVER changes —
            if (n.right != null) q.offer(n.right);  // only the output direction does
        }
        out.add(level);
        leftToRight = !leftToRight;
    }
    return out;
}

Case: Right Side View (LC 199)

Standing to the tree's right, you see one node per level: the level's last node. Run Core B and record the value only when i == size - 1.

List<Integer> rightSideView(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    if (root == null) return out;
    Queue<TreeNode> q = new ArrayDeque<>();
    q.offer(root);
    while (!q.isEmpty()) {
        int size = q.size();
        for (int i = 0; i < size; i++) {
            TreeNode n = q.poll();
            if (i == size - 1) out.add(n.val);   // rightmost of THIS level
            if (n.left  != null) q.offer(n.left);
            if (n.right != null) q.offer(n.right);
        }
    }
    return out;
}
Not just the right children A deep left subtree "peeks out" past a shallow right subtree, so the view can include left-side nodes. That's why you take the last node per level, not just follow right pointers down.

Case: Morris in-order — O(1) space (know the idea)

Both stack and recursion cost O(h). Morris gets O(1) by temporarily rewiring the tree: before diving into a left subtree, find the current node's in-order predecessor (rightmost node of that left subtree) and point its null right at the current node — a return "thread". When traversal later climbs back up that thread, it removes it and visits. Every edge is walked at most twice, so still O(n) time. 

List<Integer> morrisInorder(TreeNode root) {
    List<Integer> out = new ArrayList<>();
    TreeNode cur = root;
    while (cur != null) {
        if (cur.left == null) {            // no left subtree → visit and go right
            out.add(cur.val);
            cur = cur.right;               // may follow a thread back up — that's the point
        } else {
            TreeNode pred = cur.left;      // find in-order predecessor…
            while (pred.right != null && pred.right != cur)
                pred = pred.right;         // …rightmost node of left subtree
            if (pred.right == null) {
                pred.right = cur;          // lay the thread, then dive left
                cur = cur.left;
            } else {
                pred.right = null;         // second arrival: remove thread,
                out.add(cur.val);          // visit, and move right
                cur = cur.right;
            }
        }
    }
    return out;
}

In an interview, describing the threading idea and the O(n)/O(1) bounds is usually enough — code it only if asked.

4 · Edge-case checklist

  • Empty root — check root == null before offering to the queue; ArrayDeque throws on null elements.
  • Snapshot q.size() before the inner loop — the #1 level-order bug (see trap above).
  • Iterative pre-order push order — right before left. Reversed, your output mirrors the tree.
  • Iterative in-order loop condition — needs cur != null || !stack.isEmpty(). Stack-empty alone quits too early while cur still points into an unexplored right subtree.
  • Zigzag: never reverse the queue — enqueue left/right normally every level; only the output insertion direction alternates.
  • Right side view ≠ right children — take the last node per BFS level.
  • Morris mutates the tree mid-flight — threads are removed by the end, but never run it concurrently or bail out early with threads still planted.
  • BFS space is O(width), not O(height) — a complete tree's bottom level holds ~n/2 nodes.
