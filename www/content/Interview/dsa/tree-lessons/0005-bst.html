Binary Search Trees

One extra invariant — left < node < right, everywhere — turns a tree into a sorted structure with O(h) search, insert, and delete. Every BST problem is about exploiting or preserving that invariant.

Mission link: Validate BST (98) is one of the most-failed medium questions in OAs because of one specific misconception this lesson kills. Kth Smallest (230) and Delete (450) round out the standard BST screen. Lesson 5 of 6. Mission

1 · The one idea

A BST's property is global, not local: every node in the left subtree — not just the left child — is smaller than the node, and every node in the right subtree is larger. That global ordering buys you three superpowers: (1) search is a walk — compare and go one way, O(h); (2) in-order traversal is sorted — instant answers to "kth smallest / successor / sorted output"; (3) structure mirrors order — the middle of a sorted array makes a balanced root. Nearly every BST problem uses exactly one of these three.

Recognition trigger The words "binary search tree" or "BST" in the problem. Then route: validate / kth / sorted / successor → in-order; search / insert / delete / LCA → compare-and-descend walk; build a balanced BST → middle-of-range as root. If the problem gives a plain binary tree, none of these shortcuts apply — that's the trap direction.

2 · Core template

Core A — Validate BST with min/max bounds (LC 98)

The naive check — node.left.val < node.val < node.right.val at each node — is the famous wrong answer. It's local; the property is global. Counterexample: root 5, left child 3, and 3's right child 6. Every parent-child pair looks fine, but 6 sits in root's left subtree while being > 5. The fix: pass down the window of allowed values — descending left tightens the upper bound, descending right tightens the lower bound. 

// Each node must lie strictly inside (lo, hi). Time O(n), Space O(h).
boolean isValidBST(TreeNode root) {
    return valid(root, null, null);        // null = unbounded (avoids MIN/MAX_VALUE traps)
}
boolean valid(TreeNode n, Integer lo, Integer hi) {
    if (n == null) return true;
    if (lo != null && n.val <= lo) return false;  // must be > every ancestor we went right from
    if (hi != null && n.val >= hi) return false;  // must be < every ancestor we went left from
    return valid(n.left,  lo, n.val)       // going left: my value caps the window above
        && valid(n.right, n.val, hi);      // going right: my value floors it below
}

Equivalent alternative: run an in-order traversal and check the output is strictly increasing (keep a prev pointer). Same O(n) — know both, say both.

Worked example — dry run (the counterexample)

tree: 5 / (3, 8); 3 / (1, 6) — node 6 is the intruder valid(5, −∞, +∞) ✓ → left recurses with window (−∞, 5) valid(3, −∞, 5) ✓ → right recurses with window (3, 5) valid(6, 3, 5): 6 ≥ hi=5 → false — caught! the local check would have passed 6 (it's > its parent 3); the WINDOW remembers ancestor 5

Core B — the BST walk (search / insert / LCA share it)

// Search: the shape of every BST operation. Time O(h), Space O(1).
TreeNode searchBST(TreeNode root, int val) {
    TreeNode cur = root;
    while (cur != null && cur.val != val)
        cur = val < cur.val ? cur.left : cur.right;  // one comparison, one direction
    return cur;                            // node or null — never both sides explored
}

Time O(h) — log n balanced, n degenerate. Space O(1) iterative.

Case: Kth Smallest (LC 230) — in-order with an early exit

In-order visits BST values in ascending order, so the kth visit is the answer. The iterative stack version (Lesson 2's Core A) is the better interview answer because it stops — no traversing the rest of the tree, O(h + k) instead of O(n). 

int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) { stack.push(cur); cur = cur.left; }
        cur = stack.pop();                 // next-smallest value, in order
        if (--k == 0) return cur.val;      // kth visit → done, rest of tree untouched
        cur = cur.right;
    }
    return -1;                             // unreachable if k is valid
}

Case: Insert into a BST (LC 701)

Walk as if searching for the value; the null you fall off at is exactly where the new leaf belongs. No rebalancing asked on LeetCode.

TreeNode insertIntoBST(TreeNode root, int val) {
    if (root == null) return new TreeNode(val);   // fell off the tree → new leaf lives here
    if (val < root.val) root.left  = insertIntoBST(root.left,  val);
    else                root.right = insertIntoBST(root.right, val);
    return root;                                  // re-hang the (possibly updated) child
}

Case: Delete from a BST (LC 450) — the three-child-count split

Deleting is the hard one. Find the node with the BST walk, then split on how many children it has: zero → remove it (return null); one → splice the child into its place; two → you can't just remove it, so overwrite its value with its in-order successor (smallest node in the right subtree — the next value in sorted order), then delete that successor from the right subtree. The successor has no left child by definition, so the recursive delete bottoms out in an easy case. 

TreeNode deleteNode(TreeNode root, int key) {
    if (root == null) return null;
    if (key < root.val)      root.left  = deleteNode(root.left,  key);  // BST walk…
    else if (key > root.val) root.right = deleteNode(root.right, key);
    else {                                        // found the node to delete
        if (root.left == null)  return root.right; // 0 or 1 child: splice past me
        if (root.right == null) return root.left;
        TreeNode succ = root.right;               // 2 children: find in-order successor —
        while (succ.left != null) succ = succ.left; // leftmost of right subtree
        root.val = succ.val;                      // adopt successor's value…
        root.right = deleteNode(root.right, succ.val); // …and delete it (easy case)
    }
    return root;
}

Time O(h). Space O(h) recursion.

Case: Sorted Array → Balanced BST (LC 108)

Superpower #3: sorted order ⟺ in-order shape. Pick the middle element as root — half the values on each side — and recurse. Balance falls out automatically because both halves shrink at the same rate. 

TreeNode sortedArrayToBST(int[] nums) {
    return build(nums, 0, nums.length - 1);
}
TreeNode build(int[] a, int lo, int hi) {
    if (lo > hi) return null;              // empty range → empty subtree
    int mid = lo + (hi - lo) / 2;          // middle = root → halves stay equal-sized
    TreeNode n = new TreeNode(a[mid]);
    n.left  = build(a, lo, mid - 1);
    n.right = build(a, mid + 1, hi);
    return n;
}

Time O(n). Space O(log n) recursion (the result tree is balanced by construction).

Case: inorder successor (the idea behind LC 285)

Two situations, both walk-based, no full traversal:

// Successor of node x = the next value in sorted order.
// Case 1: x has a right subtree → successor is its LEFTMOST node.
// Case 2: no right subtree → walk from the root; the successor is the
//         last node where you turned LEFT (smallest ancestor above x).
TreeNode successor(TreeNode root, TreeNode x) {
    TreeNode succ = null;
    while (root != null) {
        if (x.val < root.val) { succ = root; root = root.left; }  // turning left: candidate
        else root = root.right;            // x is here or right — no new candidate
    }
    return succ;                           // covers BOTH cases in one O(h) walk
}

4 · Edge-case checklist

  • The local-check trap (LC 98): comparing only with direct children passes invalid trees. The bound must travel down from every ancestor.
  • Duplicates fail validation — LC 98 requires strictly less/greater, so <=/>= against the bounds, not </>.
  • Bounds that overflow: node values can be Integer.MIN_VALUE/MAX_VALUE, so seed with null (or long bounds), never int min/max sentinels.
  • Delete with two children: after copying the successor's value, delete the successor from the right subtree — deleting by key from the whole tree can hit the wrong duplicate.
  • Insert/delete must re-hang children: the root.left = f(root.left) shape is what stitches the modified subtree back in. Calling f without assigning silently discards the change.
  • All BST ops are O(h), not O(log n) — say "O(h), which is O(log n) if balanced" in interviews; a degenerate BST is a linked list.
  • Kth smallest: decrement on pop, not on push — pops happen in sorted order, pushes don't.
  • LC 108 empty array → lo > hi base case returns null; also the leaf case (lo == hi) needs no special handling.
