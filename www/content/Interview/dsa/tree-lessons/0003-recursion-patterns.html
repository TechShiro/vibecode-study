Recursion Patterns on Trees

Eight famous problems, one template: ask each child a question, combine their answers with the current node, return the result upward.

Mission link: Max Depth, Invert, Same Tree, Symmetric, and Path Sum are the most-assigned easy/medium tree questions in big-tech OAs — this single template solves all of them. Lesson 3 of 6. Mission

1 · The one idea

Lesson 1 traversed trees to collect nodes. This lesson computes with them. The pattern: define what your function returns for any subtree, trust recursion to produce that answer for left and right (the leap of faith), then combine the two child answers with the current node in O(1). Because children are consumed before the parent, this is structurally post-order — and it's why post-order is the workhorse of tree interviews. Naively you might recompute subtree facts repeatedly (e.g. calling a separate height() inside every node's check — O(n²)); the fix is always the same: make the recursion return everything the parent needs in one pass — O(n).

Recognition trigger The question asks for a single fact about the whole tree: its depth, diameter, whether it's balanced / symmetric / equal to another tree, whether a path with some property exists. Formula: "answer(tree) = f(answer(left), answer(right), root)". If you can fill in f, the problem is finished.

2 · Core template

// The compute-from-children skeleton. Time O(n) — each node does O(1) work
// on top of its children's answers. Space O(h) recursion stack.
ReturnType solve(TreeNode node) {
    if (node == null) return BASE;          // 1. what is the answer for an empty tree?
    ReturnType left  = solve(node.left);    // 2. trust recursion for the left subtree
    ReturnType right = solve(node.right);   // 3. …and the right subtree
    return combine(left, right, node);      // 4. O(1) merge — the only creative step
}

Instantiated for Maximum Depth (LC 104), the "hello world" of the pattern:

int maxDepth(TreeNode node) {
    if (node == null) return 0;             // empty tree has depth 0
    int left  = maxDepth(node.left);
    int right = maxDepth(node.right);
    return 1 + Math.max(left, right);       // me + my taller child
}

Time O(n). Space O(h).

Worked example — dry run

tree: 3 / (9, 20), 20 / (15, 7) maxDepth(9): children null → return 1 + max(0, 0) = 1 maxDepth(15) = 1, maxDepth(7) = 1 (leaves) maxDepth(20) = 1 + max(1, 1) = 2 maxDepth(3) = 1 + max(1, 2) = 3 ✓ answers flow UP: leaves resolve first, root last — post-order

Case: Diameter (LC 543) — return one thing, track another

Diameter = longest path between any two nodes, measured in edges. Through any node, the best path is height(left) + height(right). The subtlety: the value a node returns upward (its height — a path can't fork) differs from the value it contributes to the answer (L + R). Keep a global best. This "value up vs answer global" idiom stars again in Max Path Sum (Lesson 4). 

int best = 0;
int diameterOfBinaryTree(TreeNode root) {
    height(root);
    return best;
}
int height(TreeNode n) {
    if (n == null) return 0;
    int l = height(n.left), r = height(n.right);
    best = Math.max(best, l + r);       // full path THROUGH n (edges) — answer candidate
    return 1 + Math.max(l, r);          // but only one arm continues upward
}

Case: Balanced Binary Tree (LC 110) — the poison value

Naive: at every node call a separate height() — O(n²) on a skewed tree. One-pass fix: the recursion returns height, but −1 means "already unbalanced below me" and propagates straight up. 

boolean isBalanced(TreeNode root) {
    return check(root) != -1;
}
int check(TreeNode n) {                  // returns height, or -1 = poison
    if (n == null) return 0;
    int l = check(n.left);
    if (l == -1) return -1;              // short-circuit: no need to look further
    int r = check(n.right);
    if (r == -1) return -1;
    if (Math.abs(l - r) > 1) return -1;  // unbalanced HERE → poison upward
    return 1 + Math.max(l, r);
}

Case: Invert Binary Tree (LC 226)

TreeNode invertTree(TreeNode root) {
    if (root == null) return null;
    TreeNode left  = invertTree(root.left);   // inverted left subtree
    TreeNode right = invertTree(root.right);  // inverted right subtree
    root.left = right;                        // swap them under me
    root.right = left;
    return root;
}

Case: Same Tree (LC 100) — lock-step recursion on two trees

boolean isSameTree(TreeNode p, TreeNode q) {
    if (p == null && q == null) return true;   // both empty: match
    if (p == null || q == null) return false;  // one empty: shape differs
    return p.val == q.val
        && isSameTree(p.left, q.left)          // corresponding children in lock-step
        && isSameTree(p.right, q.right);
}

Case: Symmetric Tree (LC 101) — Same Tree, mirrored

A tree is symmetric iff its left subtree mirrors its right. "Mirror" = same-tree with the child comparison crossed.

boolean isSymmetric(TreeNode root) {
    return root == null || mirror(root.left, root.right);
}
boolean mirror(TreeNode a, TreeNode b) {
    if (a == null && b == null) return true;
    if (a == null || b == null) return false;
    return a.val == b.val
        && mirror(a.left, b.right)             // outer pair ↔ outer pair
        && mirror(a.right, b.left);            // inner pair ↔ inner pair — the crossing
}

Case: Path Sum (LC 112) — information flows DOWN

A twist on the template: instead of combining child answers, you pass the remaining target down and decide at a leaf. Down-flowing parameters + up-flowing booleans is a very common hybrid. 

boolean hasPathSum(TreeNode n, int target) {
    if (n == null) return false;                     // empty path can't hit target
    if (n.left == null && n.right == null)           // LEAF: the decision point
        return target == n.val;
    return hasPathSum(n.left,  target - n.val)       // subtract me, ask the kids
        || hasPathSum(n.right, target - n.val);
}

Case: Path Sum II (LC 113) — collect the paths (backtracking)

List<List<Integer>> pathSum(TreeNode root, int target) {
    List<List<Integer>> out = new ArrayList<>();
    dfs(root, target, new ArrayList<>(), out);
    return out;
}
void dfs(TreeNode n, int target, List<Integer> path, List<List<Integer>> out) {
    if (n == null) return;
    path.add(n.val);                                 // choose
    if (n.left == null && n.right == null && target == n.val)
        out.add(new ArrayList<>(path));              // COPY — path keeps mutating
    else {
        dfs(n.left,  target - n.val, path, out);     // explore
        dfs(n.right, target - n.val, path, out);
    }
    path.remove(path.size() - 1);                    // un-choose (backtrack)
}
Two classic Path Sum traps (1) Checking target == 0 at a null node counts one-child nodes as path ends — the check must live at a leaf (both children null). Values can be negative, so you can't prune early either. (2) In 113, adding path itself (not a copy) to the output means every stored "path" later mutates into an empty list.

4 · Edge-case checklist

  • Base case = empty tree, chosen so combine works unmodified. Depth 0, true for equality checks, false for path existence.
  • Leaf vs. null: "root-to-leaf" problems must test left == null && right == null — a null child is NOT a leaf.
  • Negative values kill "stop when sum exceeds target" pruning — traverse fully.
  • Diameter counts edges, not nodes — hence l + r with heights, no +1. Re-derive on a 3-node tree if unsure.
  • O(n²) smell: a helper like height() called inside another recursion. Fold both facts into one return (poison value or small tuple class).
  • Global fields need resetting if the judge reuses your object across tests — or wrap state in a one-element array passed down.
  • Two-tree recursion: handle the (null, null) and (null, non-null) cases before touching .val.
