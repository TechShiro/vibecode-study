LCA & Path Problems

Two of the most-asked medium/hard tree questions share one engine: a post-order pass where each node reports something useful upward while the real answer is assembled on the side.

Mission link: LCA (236) is a top-5 tree interview question at Meta/Amazon/Google, and Max Path Sum (124) is the canonical "hard tree" screen. Both fall to Lesson 3's template plus one idiom. Lesson 4 of 6. Mission

1 · The one idea

Both problems in this lesson are about paths that bend. The lowest common ancestor of p and q is the node where the path between them bends from "going up" to "going down". The maximum path sum is achieved at some node where two downward arms join. In both cases a single recursion answers a simpler question per subtree ("do you contain p or q?" / "what's your best downward arm?"), and the bend — the real answer — is detected at the node where the two child reports meet. That's the "value up, answer global" idiom from Diameter, now at full power.

Recognition trigger "Lowest/deepest common ancestor", "distance between two nodes", "longest/maximum path" where the path may pass through a node (not root-to-leaf). Whenever a path could enter from one child and leave through the other, you need: return the one-arm value up, combine two arms into a global answer at the bend.

2 · Core template

Core A — Lowest Common Ancestor (LC 236)

Naive approach: find the root-to-p path and root-to-q path as lists, then compare — works, O(n) but clunky and two passes. The one-pass insight: ask each subtree "do you contain p or q (or an already-found LCA)?" and let three tiny rules decide: 

// Returns: p or q if found in this subtree, the LCA if both were found
// below here, or null if this subtree contains neither.
// Time O(n), Space O(h).
TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    if (root == null || root == p || root == q)
        return root;                       // found a target (or ran out) → report it up
    TreeNode left  = lowestCommonAncestor(root.left,  p, q);
    TreeNode right = lowestCommonAncestor(root.right, p, q);
    if (left != null && right != null)
        return root;                       // p and q split here → I am the bend → LCA
    return left != null ? left : right;    // pass up whichever side found something
}

Why root == p returns immediately without searching below: if q is inside p's subtree, then p itself is the LCA — an ancestor of q and (by LeetCode's definition, a node is its own ancestor) of p. Either way, reporting p upward is correct.

Worked example — dry run

lca(3): recurse left into 5 lca(6) hits root == p → returns 6 lca(2) hits root == q → returns 2 at 5: left = 6, right = 2 — BOTH non-null → return 5 (the bend) at 3: left = 5, right = null (subtree of 1 has neither) → pass 5 up answer: 5 ✓

Core B — Binary Tree Maximum Path Sum (LC 124), post-order DP

A "path" here is any chain of connected nodes — it may start and end anywhere, and it bends at exactly one highest node. Think of it as DP on the tree: for each node compute gain(n) = the best sum of a path that starts at n and goes straight down one side. That's the value passed up. The candidate answer at n is n.val + gain(left) + gain(right) — both arms joined at the bend — which goes into a global max. 

// Time O(n), Space O(h). The classic "value up vs answer global" problem.
int best = Integer.MIN_VALUE;              // answer may be negative — don't init to 0

int maxPathSum(TreeNode root) {
    gain(root);
    return best;
}
int gain(TreeNode n) {                     // best DOWNWARD arm starting at n
    if (n == null) return 0;
    int l = Math.max(gain(n.left),  0);    // a negative arm? drop it — take 0 instead
    int r = Math.max(gain(n.right), 0);
    best = Math.max(best, n.val + l + r);  // ANSWER: path bending at n, both arms
    return n.val + Math.max(l, r);         // VALUE UP: parent can extend only one arm
}
The "value up vs answer global" idiom — name it, own it When a path may bend, no single return value can carry it upward (the parent can't use a bent path). So split the roles: return the extendable one-arm value; record the complete two-arm candidate in a global. Diameter (543) = this with arm-length instead of arm-sum. Longest Univalue Path (687) = this with a matching-value condition. Once you see the split, all three are the same problem.

Case: LCA of a BST (LC 235) — use the ordering, skip the search

In a BST you don't need to find p and q — their values tell you where they are. If both are smaller than the current node, the LCA is in the left subtree; both bigger, right; otherwise the current node splits them (or equals one of them) and IS the LCA. No recursion needed at all. 

// Time O(h), Space O(1) — iterative walk, no stack.
TreeNode lowestCommonAncestor(TreeNode root, TreeNode p, TreeNode q) {
    TreeNode cur = root;
    while (cur != null) {
        if (p.val < cur.val && q.val < cur.val)
            cur = cur.left;                // both targets live left → descend left
        else if (p.val > cur.val && q.val > cur.val)
            cur = cur.right;               // both live right → descend right
        else
            return cur;                    // split point (or equals p/q) → LCA
    }
    return null;
}
Interview contrast worth saying out loud "In a general tree I must search both sides — O(n). In a BST the ordering tells me which single direction to walk — O(h), iterative, O(1) space." Stating this contrast unprompted is an easy signal of depth.

Case: Max Path Sum — why clamp at 0, why init best to −∞

Two lines of LC 124 carry all the difficulty; here they are isolated:

int l = Math.max(gain(n.left), 0);
// A downward arm summing to -7 HURTS any path that includes it.
// "Take the arm or leave it" — max with 0 models leaving it.

int best = Integer.MIN_VALUE;
// Tree = [-3] → answer is -3 (a path must contain ≥ 1 node).
// Initializing best = 0 would wrongly report an empty path's sum.

Note the asymmetry: arms may be dropped (clamped to 0), but the node n.val itself is never dropped from its own candidate — the path bending at n must include n. The all-negative tree still produces the correct "least bad single node" because every node's n.val + 0 + 0 is offered to best.

Case: distance between two nodes (common follow-up)

Once you own LCA, "distance from p to q" is free: dist(p, q) = depth(p) + depth(q) − 2 · depth(LCA) — find the LCA, then measure each depth from it. Interviewers use this as the follow-up to check you understand why the LCA is the bend.

4 · Edge-case checklist

  • p is an ancestor of q — the LCA is p itself. Core A handles it via the early return at root == p; don't "fix" that line.
  • Both problems guarantee p and q exist in the tree (LC 236's contract). If existence isn't guaranteed, you must verify — the early-return trick can report p without ever confirming q.
  • LCA-BST: compare values, not references — and mind strict inequalities so the split case catches cur == p.
  • Max path sum with all negatives — clamping arms is right, but best must start at Integer.MIN_VALUE, and the node's own value is never clamped.
  • Single-node tree — LCA(p, p) = p; max path sum = that node's value.
  • Don't return the bent value upward — return n.val + l + r instead of n.val + max(l, r) silently double-counts and is the most common 124 bug.
  • Deep trees — both cores recurse to depth h; on 10⁵-node chains mention the iterative escape hatch.
