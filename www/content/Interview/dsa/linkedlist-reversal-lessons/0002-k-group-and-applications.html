Reverse Nodes in k-Group & Applications

One flip-loop, deployed in groups, in rotations, and welded to other patterns — everything a linked-list round can throw at you.

Mission link: LC 25 is a "hard" that big-tech screens love precisely because it's Lesson 1's template plus careful stitching — pure execution under pressure. This is Lesson 2 of the 2-lesson LinkedList Reversal track. Mission

1 · The one idea

Lesson 1 gave you the flip-loop. Real interview problems wrap it: reverse every k nodes (count first, flip only full groups), rotate a list (no flipping at all — cut and re-tie a ring), or combine reversal with another pattern (find-mid + reverse + merge = Reorder List). The skill being tested is no longer the loop — it's bookkeeping at the seams: who points at the group, who does the group point at.

Recognition trigger "Reverse in groups of k," "rotate right by k," "reorder / fold the list," "add numbers stored in lists." Whenever a linked-list problem needs surgery beyond one pass of value-reading, reach for: dummy node, a groupPrev anchor, and the Lesson-1 flip-loop as a subroutine.

2 · Core — Reverse Nodes in k-Group (LC 25), the boss

Per group: (1) probe k nodes ahead — if the group is short, leave it untouched; (2) flip exactly k arrows with the standard loop, letting cur land on the next group's head; (3) stitch: the anchor before the group points at the group's new head (prev), and the group's old head — now its tail — points at cur. That old head is the next anchor. 

ListNode reverseKGroup(ListNode head, int k) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode groupPrev = dummy;              // anchor: node just before the current group

    while (true) {
        ListNode kth = groupPrev;            // 1. PROBE: is there a full group of k?
        for (int i = 0; i < k && kth != null; i++) kth = kth.next;
        if (kth == null) break;              // fewer than k left → leave the tail as-is

        ListNode groupNext = kth.next;       // first node AFTER this group
        ListNode prev = groupNext;           // 2. FLIP: seed prev with groupNext…
        ListNode cur  = groupPrev.next;      //    …so the k-th flip auto-connects the back seam
        while (cur != groupNext) {           // standard Lesson-1 loop, k times
            ListNode next = cur.next;
            cur.next = prev;
            prev = cur;
            cur  = next;
        }
        ListNode newAnchor = groupPrev.next; // old group head = new group tail
        groupPrev.next = kth;                // 3. STITCH front seam: anchor → new head (kth)
        groupPrev = newAnchor;               // advance anchor to the group's tail
    }
    return dummy.next;
}

Time O(n) — every node is probed once and flipped once. Space O(1).

The seed trick Seeding prev = groupNext (instead of null) means the group's old head ends up pointing at groupNext automatically — the back seam stitches itself, and you only wire the front seam by hand. One line, one whole class of bugs gone.

Dry run: k = 2 on 1 → 2 → 3 → 4 → 5

dummy→1→2→3→4→5, groupPrev = dummy probe: kth = 2, groupNext = 3; flip 1,2 seeded with 3 → 2→1→3; stitch dummy→2; anchor = 1 probe from 1: kth = 4, groupNext = 5; flip 3,4 → 4→3→5; stitch 1→4; anchor = 3 probe from 3: kth = null after 1 step past 5 → short group, break result: 2→1→4→3→5 (last group of one left alone)

Case: Rotate List (LC 61)

Rotating right by k moves the last k % n nodes to the front. Cleanest surgery: walk to the tail counting n, tie tail to head (a temporary ring), then cut the ring after node n − k % n. Two seams, zero flips. 

ListNode rotateRight(ListNode head, int k) {
    if (head == null || head.next == null || k == 0) return head;
    ListNode tail = head;
    int n = 1;
    while (tail.next != null) { tail = tail.next; n++; } // find tail + length
    k %= n;                                  // k may be huge (k = 2·10⁹, n = 3)
    if (k == 0) return head;                 // full rotations = no-op
    tail.next = head;                        // close the ring
    ListNode newTail = head;
    for (int i = 1; i < n - k; i++) newTail = newTail.next; // new tail = node n−k
    ListNode newHead = newTail.next;
    newTail.next = null;                     // cut the ring — forget this and you loop forever
    return newHead;
}

Time O(n), Space O(1).

Case: Reorder List (LC 143) — the three-pattern combo

Turn a₁→a₂→…→aₙ into a₁→aₙ→a₂→aₙ₋₁→…. No single trick does this; it's an assembly: find the middle with fast & slow pointers (full story in Fast & Slow Lesson 1), reverse the back half with Lesson 1's loop, then zip-merge the two halves alternately. Interviewers love it because it audits three patterns in one question. 

void reorderList(ListNode head) {
    // 1. find middle (slow lands on mid for odd n, left-mid's right for even)
    ListNode slow = head, fast = head;
    while (fast.next != null && fast.next.next != null) {
        slow = slow.next;
        fast = fast.next.next;
    }
    // 2. detach + reverse the second half
    ListNode second = slow.next;
    slow.next = null;                        // SEVER — or the zip creates a cycle
    ListNode prev = null;
    while (second != null) {
        ListNode next = second.next;
        second.next = prev;
        prev = second;
        second = next;
    }
    // 3. zip-merge: first half is ≥ as long, so it drives the loop
    ListNode p1 = head, p2 = prev;
    while (p2 != null) {
        ListNode n1 = p1.next, n2 = p2.next;
        p1.next = p2;                        // a₁ → aₙ
        p2.next = n1;                        // aₙ → a₂
        p1 = n1;
        p2 = n2;
    }
}

Time O(n), Space O(1) — versus the lazy O(n)-space "dump into ArrayList and rebuild," which is exactly what the in-place constraint forbids.

Case: Add Two Numbers (LC 2)

Digits are stored reversed (least significant first), so you add left-to-right like grade-school arithmetic — no reversal needed. Dummy node builds the result; one carry variable rides along. (The follow-up LC 445 stores digits most-significant first — there you reverse both inputs first, then run this exact code.) 

ListNode addTwoNumbers(ListNode l1, ListNode l2) {
    ListNode dummy = new ListNode(0);
    ListNode tail = dummy;
    int carry = 0;
    while (l1 != null || l2 != null || carry != 0) { // keep going while ANYTHING remains
        int sum = carry;
        if (l1 != null) { sum += l1.val; l1 = l1.next; }
        if (l2 != null) { sum += l2.val; l2 = l2.next; }
        carry = sum / 10;
        tail.next = new ListNode(sum % 10);
        tail = tail.next;
    }
    return dummy.next;
}

Time O(max(m, n)), Space O(1) beyond the output. The || carry != 0 in the loop guard is what emits the final carry digit (99 + 1 = 100 has more digits than either input).

4 · Edge-case checklist

  • Short last group (LC 25): probe first, flip only if k nodes exist. Flipping then un-flipping is a rewrite waiting to happen.
  • k ≥ n (LC 61): take k %= n before anything else, and treat k == 0 as a no-op. Forgetting the modulo TLEs on k = 2·10⁹.
  • Cut every ring you tie. LC 61's newTail.next = null, LC 143's slow.next = null. A missing sever = an infinite loop that looks like a "working" submission until the judge times out.
  • Anchor advancement (LC 25): the next anchor is the group's old head (its new tail) — capture it before restitching, or you'll advance into the wrong node.
  • Zip-merge loop condition (LC 143): drive on p2 != null — the first half is never shorter, so it can't run out first.
  • Final carry (LC 2): loop while carry != 0 too, or 5+5 returns 0 instead of 0→1.
  • Lists of different lengths (LC 2): null-check each list independently inside the loop; don't require both.
