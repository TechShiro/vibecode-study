LinkedList In-place Reversal

Flip the arrows of a linked list one node at a time, using three pointers and zero extra memory — the single most-asked linked-list move in big-tech screens.

Mission link: reversal is the atom inside a dozen linked-list interview questions (k-group, palindrome, reorder). This is Lesson 1 of the 2-lesson LinkedList Reversal track. Mission

1 · The one idea

A singly linked list is just nodes with one-way arrows. To reverse it in place, you walk the list once and flip each arrow to point backwards. The catch: the moment you flip cur.next, you lose your road forward. So you carry three pointers — prev (already-reversed part), cur (the node being flipped), and next (a saved copy of the road ahead). Save, flip, slide. That's the whole pattern.

Recognition trigger "Reverse a list / sublist / every k nodes," "swap adjacent nodes," "reorder," or any linked-list problem that says in place or O(1) space. If your first instinct is "copy values into an ArrayList," the interviewer wants this pattern instead. Pointer-rewiring is the test.

2 · Core template — three pointers

Reverse Linked List (LC 206). Memorize this loop body as one chant: save next, flip, slide prev, slide cur.

ListNode reverseList(ListNode head) {
    ListNode prev = null;            // reversed part so far (starts empty)
    ListNode cur  = head;            // node whose arrow we're flipping now
    while (cur != null) {
        ListNode next = cur.next;    // 1. SAVE the road ahead before we cut it
        cur.next = prev;             // 2. FLIP the arrow backwards
        prev = cur;                  // 3. SLIDE prev up
        cur  = next;                 // 4. SLIDE cur up
    }
    return prev;                     // cur fell off the end; prev is the new head
}

Time O(n) — one pass, four pointer writes per node. Space O(1) — three local pointers, no matter how long the list.

Dry run on 1 → 2 → 3 → null

start: prev=null, cur=1    list: 1→2→3→∅ iter 1: next=2; 1.next=null; prev=1, cur=2    null←1  2→3→∅ iter 2: next=3; 2.next=1; prev=2, cur=3    null←1←2  3→∅ iter 3: next=null; 3.next=2; prev=3, cur=null    null←1←2←3 cur == null → stop. return prev = 3    result: 3→2→1→∅
The one bug everyone writes Flipping before saving: cur.next = prev; then cur = cur.next; walks you backwards into the reversed part — infinite loop or instant termination. The save (next = cur.next) must be the first line of the loop body. Always.

Recursive version (know it, prefer iterative)

Recurse to the tail, then rewire on the way back up: for each node, make its child point back at it and sever its own forward arrow. The reversed head is the old tail, found at the recursion's bottom and passed up unchanged. 

ListNode reverseRec(ListNode head) {
    if (head == null || head.next == null) return head; // empty or tail → new head
    ListNode newHead = reverseRec(head.next);  // reverse everything after me
    head.next.next = head;           // my child now points back at me
    head.next = null;                // sever my old forward arrow (I may be the new tail)
    return newHead;                  // old tail bubbles up untouched
}

Time O(n). Space O(n) recursion stack — say this out loud in an interview; on a 10⁵-node list it can StackOverflow, which is why iterative wins.

The dummy-node idiom

Whenever the head itself might change or be deleted (partial reversal, pair swaps, deletions), prepend a throwaway node: ListNode dummy = new ListNode(0); dummy.next = head;. Now every real node — including the old head — has a predecessor, so there are no special cases. Return dummy.next at the end. You'll use this in both cases below and constantly in Lesson 2.

3 · All the cases

Same flip-loop every time; what changes is which slice you reverse and how you stitch it back.

CaseProblemWhat changes
Reverse the whole listLC 206The bare template. Return prev.
Reverse a sublist [left, right]LC 92Walk to the node before left, reverse exactly right−left+1 nodes, stitch both ends. Dummy node mandatory.
Swap adjacent pairsLC 24Reversal in groups of 2 — rewire three arrows per pair, advance two nodes. Mini-preview of k-group (Lesson 2).

Case: Reverse Linked List II — sublist only (LC 92)

Reverse positions left..right (1-indexed) in one pass. Three phases: walk to the anchor before the window, flip inside the window with the standard loop, stitch the two seams. After the flip, prev is the window's new front and cur is the first node after it; the old window-start (saved as tail) is now the window's back. 

ListNode reverseBetween(ListNode head, int left, int right) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode before = dummy;             // will end at the node just BEFORE position left
    for (int i = 1; i < left; i++) before = before.next;

    ListNode prev = null, cur = before.next;
    ListNode tail = cur;                 // window's first node → becomes its LAST after flip
    for (int i = 0; i < right - left + 1; i++) {  // standard flip, exactly window-size times
        ListNode next = cur.next;
        cur.next = prev;
        prev = cur;
        cur  = next;
    }
    before.next = prev;                  // stitch front seam: anchor → new window head
    tail.next   = cur;                   // stitch back seam: new window tail → rest of list
    return dummy.next;                   // dummy absorbed the left == 1 case for free
}

Time O(n), Space O(1). Without the dummy, left == 1 (window includes the head) needs its own branch — with it, nothing special happens.

Case: Swap Nodes in Pairs (LC 24)

Groups of two: for each pair (a, b) hanging off anchor p, rewire p → b → a → rest, then advance the anchor to a (now the pair's second node). Draw the three arrows before coding — it's a stitching exercise, not a loop exercise. 

ListNode swapPairs(ListNode head) {
    ListNode dummy = new ListNode(0);
    dummy.next = head;
    ListNode p = dummy;                  // anchor sitting just before the current pair
    while (p.next != null && p.next.next != null) { // a full pair exists
        ListNode a = p.next;             // first of the pair
        ListNode b = a.next;             // second of the pair
        a.next = b.next;                 // a → rest
        b.next = a;                      // b → a
        p.next = b;                      // anchor → b (pair now swapped)
        p = a;                           // a is the pair's new tail → next anchor
    }
    return dummy.next;
}

Time O(n), Space O(1). An odd leftover node fails the while guard and stays put — exactly what the problem wants.

4 · Edge-case checklist

  • Empty list and single node. The template handles both (loop body never runs / runs once) — but say it out loud: head == null and head.next == null.
  • Save before you flip. next = cur.next is line 1 of the loop body, non-negotiable.
  • Return prev, not cur. At loop exit cur is null; the new head lives in prev.
  • Head might move → dummy node. LC 92 with left == 1, LC 24 always (head becomes the second node). Return dummy.next.
  • Sever the seam. In partial reversals the old sub-head becomes a sub-tail — if you forget to point it at the remainder (or at null in the recursive version), you create a cycle. Test by printing the result list.
  • Recursion depth. Recursive reversal is O(n) stack; mention it and default to iterative.
  • Count, don't null-check, inside a window (LC 92): the flip loop runs exactly right − left + 1 times; the list doesn't end there.
