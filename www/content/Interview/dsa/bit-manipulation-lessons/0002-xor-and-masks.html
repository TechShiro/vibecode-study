XOR & Masks

One operator that makes duplicates annihilate each other, and one loop that enumerates every subset of a set — the two ideas behind a shelf of "impossible without the trick" problems.

Mission link: the Single Number family is pure recognition — with the XOR properties you solve LC 136 in one line; without them you burn 20 minutes on a HashMap. This is Lesson 2 of the 2-lesson Bit Manipulation track. Mission

1 · The one idea

XOR is addition without carrying — per bit, "are they different?". Two properties do all the work: self-inverse (a ^ a = 0, and a ^ 0 = a) and order-free (commutative + associative). XOR a whole array and you can mentally reorder it so every duplicate pair sits together and vanishes — whatever appears an even number of times evaporates; whatever's left is the XOR of the odd ones out. Separately, an int can be a set: bit i set ⇔ element i included — so counting 0 … 2ⁿ−1 enumerates every subset of an n-element set.

Recognition trigger "Every element appears twice except…" (or three times, or two exceptions), "find missing/duplicate without extra space," "add without +," swap/parity tricks — that's XOR. "All subsets / all combinations of ≤ 20 items," "assign workers to tasks," TSP-sized n — that's bitmask enumeration.

2 · Core — XOR fold (LC 136)

int singleNumber(int[] nums) {
    int x = 0;                 // 0 is XOR's identity
    for (int v : nums) x ^= v; // pairs annihilate (a ^ a = 0), order irrelevant
    return x;                  // the survivor: the one element with odd count
}

Time O(n), Space O(1) — the constraints (linear time, no extra memory) exist precisely to disqualify the HashMap answer.

nums = [4, 1, 2, 1, 2] — XOR is order-free, so regroup mentally: (1 ^ 1) ^ (2 ^ 2) ^ 4  =  0 ^ 0 ^ 4  =  4 every even-count value self-destructs; the odd one out survives

Bonus party tricks from the same properties: in-place swap (a ^= b; b ^= a; a ^= b;) and "XOR undo" — if c = a ^ b, then c ^ a = b. The undo is how XOR prefix arrays answer range-XOR queries.

Case: Single Number III — two loners (LC 260)

Folding everything yields d = a ^ b — the two answers mashed together. Any set bit of d is a position where a and b disagree; grab the lowest via d & −d (Lesson 1) and partition the array into "numbers with that bit set" vs "not." Each loner lands in a different bucket, each pair lands together in one bucket — so each bucket is a fresh LC 136. 

int[] singleNumberIII(int[] nums) {
    int d = 0;
    for (int v : nums) d ^= v;       // d = a ^ b (pairs gone)
    int bit = d & -d;                // lowest bit where a, b differ (d ≠ 0 since a ≠ b)
    int a = 0, b = 0;
    for (int v : nums) {             // split by that bit → two LC 136 instances
        if ((v & bit) != 0) a ^= v;
        else                b ^= v;
    }
    return new int[]{a, b};
}

Time O(n), Space O(1). Note for the pedantic: d & −d is safe even when d's lowest set bit is bit 31 (d = Integer.MIN_VALUE) — the overflow wraps exactly right.

Case: Single Number II — loner among triples (LC 137)

Pairs die under XOR; triples don't. Zoom into one bit position: across the array, that position's 1s count is 3k (from the triples) plus 0 or 1 (from the loner). So count mod 3 per position and reassemble the loner bit by bit. 

int singleNumberII(int[] nums) {
    int res = 0;
    for (int i = 0; i < 32; i++) {           // each bit position independently
        int cnt = 0;
        for (int v : nums) cnt += (v >> i) & 1; // how many numbers have bit i set?
        if (cnt % 3 != 0) res |= (1 << i);   // leftover 1 belongs to the loner
    }
    return res;                              // works for negatives too — bit 31 is just a bit
}

Time O(32n), Space O(1). Generalizes: everyone appears k times except one → count mod k. (A two-variable DFA version exists — ones, twos — mention it, derive this one.)

Case: Sum of Two Integers without + (LC 371)

Grade-school addition, split in two: XOR adds each column ignoring carries; (a & b) << 1 computes exactly the carries (a column carries when both bits are 1, into the next column). Repeat until no carry remains — each pass pushes the carry at least one bit left, so it dies within 32 rounds. 

int getSum(int a, int b) {
    while (b != 0) {
        int carry = (a & b) << 1;  // both-1 columns generate a carry one place left
        a = a ^ b;                 // carry-less column sums
        b = carry;                 // re-add the carries next round
    }
    return a;
}

Time O(32) = O(1), Space O(1). Two's complement makes negatives free — no sign special-casing.

Case: Subsets via bitmask enumeration (LC 78)

n ≤ ~20 elements → represent a subset as an n-bit mask and just count. Mask m's bit j answers "is nums[j] in this subset?" — 2ⁿ masks, 2ⁿ subsets, no recursion, no backtracking. 

List<List<Integer>> subsets(int[] nums) {
    int n = nums.length;
    List<List<Integer>> res = new ArrayList<>();
    for (int m = 0; m < (1 << n); m++) {     // every mask 0 .. 2ⁿ−1 IS a subset
        List<Integer> cur = new ArrayList<>();
        for (int j = 0; j < n; j++)
            if ((m >> j & 1) == 1) cur.add(nums[j]); // bit j set → include nums[j]
        res.add(cur);
    }
    return res;
}

Time O(n · 2ⁿ), Space O(n · 2ⁿ) for the output — both unavoidable, since that's the answer's size.

Submask iteration — the one loop to know before Bitmask DP

Sometimes you need every subset of a mask m (e.g. "which sub-team of the available people handles this task?"). The idiom: 

for (int s = m; s > 0; s = (s - 1) & m) {
    // visit non-empty submask s of m (add s == 0 after the loop if needed)
}

s − 1 counts down; & m snaps back to bits allowed by m — together they visit every submask in decreasing order, and summed over all m the total work is O(3ⁿ), far below the naive O(4ⁿ). This loop plus a DP table over masks is the whole engine of Bitmask DP (TSP, assignment problems) — file the idiom now, spend it there.

4 · Edge-case checklist

  • XOR kills even counts only. Triples survive (hence LC 137's mod-3 counting). Before folding, confirm the "everything else appears exactly twice" premise.
  • Split bit must be a differing bit (LC 260): any set bit of a ^ b works; d & −d is just the convenient lowest. d is never 0 because the two loners are distinct.
  • Negatives in LC 137: loop all 32 bits including bit 31; res |= (1 << 31) correctly rebuilds a negative loner. Summing counts into a long "to be safe" is unnecessary — cnt ≤ n fits an int.
  • Mask width (LC 78): 1 << n as an int is fine for n ≤ 30; n = 32 wraps to 1 (shift mod 32 — Lesson 1's trap). LeetCode caps n at 10, but say it.
  • Submask loop and s = 0: the canonical loop stops before the empty submask; append it manually when the empty set is a legal choice.
  • LC 371 in other languages: Java ints overflow silently (good here); Python's unbounded ints make the same code hang without a 32-bit mask — worth mentioning if asked "would this port?".
  • XOR swap aliasing: a ^= b; b ^= a; a ^= b; zeroes both if a and b are the same variable (e.g. swap(arr, i, i)). Cute trick, real bug — prefer a temp in production.
