Bit Manipulation — Operators & Tricks

An int is 32 switches. Learn the six operators and a handful of one-line tricks, and a whole category of OA questions becomes free points.

Mission link: bit questions are OA favorites because they're short to state, short to solve, and brutal if you've never seen the tricks. This is Lesson 1 of the 2-lesson Bit Manipulation track. Mission

1 · The one idea

A Java int is a row of 32 bits — treat it as a set of 32 booleans you can read, flip, and combine in a single CPU instruction. Everything in this track reduces to three moves: build a mask (1 << i) to talk about bit i, combine masks with & | ^, and exploit two magic identities — x & (x−1) clears the lowest set bit, x & −x isolates it.

Recognition trigger "Without extra space," "count the 1 bits / set bits," "power of two," parity, "toggle/check the i-th bit," XOR anywhere in the statement, or n ≤ 20 hinting at subset masks (Lesson 2). Also any "clever O(1) space" ask where a boolean array feels natural — the int IS the boolean array.

Java-specific traps (1) >> on a negative number stays negative forever — loops like while (n != 0) n >>= 1; never end for n < 0. Use >>> when treating the int as raw bits. (2) Shift amounts wrap mod 32 for int: 1 << 32 == 1, not 0. (3) & binds looser than == — write (x & 1) == 1, never x & 1 == 1 (compile error or wrong grouping).

Two's complement in 30 seconds

Negative numbers are stored as −x = ~x + 1 (flip all bits, add one). Consequences worth knowing cold: the top bit is the sign; −1 is all 32 ones (0xFFFFFFFF); range is −2³¹ … 2³¹−1 (so Math.abs(Integer.MIN_VALUE) overflows and stays negative); and — the payoff — x and −x agree on exactly one set bit: the lowest one. Everything below that bit is zero in both; everything above is complementary. That single fact powers x & −x.

The essential arsenal

// ---- the two magic identities ----
x & (x - 1)        // CLEAR lowest set bit:  0b10110 → 0b10100
x & -x             // ISOLATE lowest set bit: 0b10110 → 0b00010

// ---- talk to bit i via the mask (1 << i) ----
(x >> i & 1) == 1  // GET   bit i (or: (x & (1 << i)) != 0 — never == 1!)
x | (1 << i)       // SET   bit i to 1
x & ~(1 << i)      // CLEAR bit i to 0
x ^ (1 << i)       // TOGGLE bit i

// ---- ready-made masks ----
(1 << k) - 1       // lowest k bits all 1:  k=4 → 0b1111
x & ((1 << k) - 1) // keep only the lowest k bits of x

// ---- instant checks ----
(x & 1) == 1                    // odd?
x > 0 && (x & (x - 1)) == 0     // power of two? (exactly one set bit)

Why x & (x−1) works: subtracting 1 flips the lowest set bit to 0 and every bit below it to 1 (the borrow ripples up to it); ANDing wipes that whole tail. Each application removes exactly one set bit — which turns "count the bits" into "count the loop iterations." All O(1) time and space.

Case: Number of 1 Bits (LC 191)

int hammingWeight(int n) {
    int count = 0;
    while (n != 0) {           // != 0, NOT > 0 — n may be "negative" (raw bits)
        n &= n - 1;            // kill the lowest set bit
        count++;
    }
    return count;              // loop ran once per set bit
}

Time O(k) where k = number of set bits (≤ 32; beats checking all 32 positions). Space O(1). Production shortcut to mention: Integer.bitCount(n).

Case: Power of Two (LC 231)

boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0; // exactly one set bit, and positive
}

Time/Space O(1). The n > 0 guard matters twice: 0 has no set bits yet passes the AND test, and Integer.MIN_VALUE has exactly one set bit but is negative.

Case: Reverse Bits (LC 190)

int reverseBits(int n) {
    int res = 0;
    for (int i = 0; i < 32; i++) {
        res = (res << 1) | (n & 1);  // make room, append n's lowest bit
        n >>>= 1;                    // >>> — logical shift; >> loops forever on negatives
    }
    return res;
}

Time O(32) = O(1), Space O(1). Fixed 32 iterations — don't loop "while n != 0," or leading zeros of the input never become trailing bits of the output.

Case: Missing Number (LC 268)

Array holds n distinct numbers from 0..n; one is missing. XOR every index and every value together with n: each present number appears twice (once as value, once as index) and cancels; the missing one appears once — as an index/in the range — and survives. This is Lesson 2's headline property making a cameo. 

int missingNumber(int[] nums) {
    int x = nums.length;             // seed with n (the index that has no slot)
    for (int i = 0; i < nums.length; i++)
        x ^= i ^ nums[i];            // pairs annihilate; the loner remains
    return x;
}

Time O(n), Space O(1). The Gauss-sum alternative n(n+1)/2 − sum also works; XOR sidesteps any overflow conversation entirely.

Case: Counting Bits (LC 338) — the DP link

Count set bits for every i in 0..n. Running LC 191 n times is O(n·k); one observation makes it O(n): i & (i−1) is i with its lowest set bit removed — a smaller number whose count you already computed. Classic DP shape: recurrence on a smaller subproblem, table filled left to right. 

int[] countBits(int n) {
    int[] dp = new int[n + 1];       // dp[0] = 0
    for (int i = 1; i <= n; i++)
        dp[i] = dp[i & (i - 1)] + 1; // = count(i minus its lowest set bit) + that bit
    return dp;
}

Time O(n), Space O(n) for the answer itself. Equivalent recurrence: dp[i] = dp[i >> 1] + (i & 1) — same idea, dropping the lowest bit by shifting.

4 · Edge-case checklist

  • Negative inputs: loop on n != 0, shift with >>>. The pair of bugs (n > 0 guard, >> shift) each turn LC 191/190 into an infinite loop.
  • Zero: not a power of two; has zero set bits; x & −x gives 0, not a bit. Check n > 0 before trusting the identities.
  • Integer.MIN_VALUE: one set bit but negative; its negation overflows to itself. Any "abs then bit-trick" plan dies here.
  • Operator precedence: parenthesize every mask test — (x & m) != 0. Also prefer != 0 over == 1: for i > 0 the extracted mask is 1 << i, not 1.
  • Shift-by-32 wraps: 1 << 32 == 1 (amounts are taken mod 32 for int, mod 64 for long). Building a 32-bit all-ones mask is -1, not (1 << 32) − 1.
  • Fixed-width iteration (LC 190): always 32 rounds; the input's leading zeros are the output's trailing zeros.
  • Know the library: Integer.bitCount, Integer.toBinaryString (great for debugging), Integer.lowestOneBit (= x & −x). Use them to verify your hand-rolled versions.
