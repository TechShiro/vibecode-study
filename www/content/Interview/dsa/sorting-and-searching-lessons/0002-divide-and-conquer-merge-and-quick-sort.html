Divide & Conquer: Merge Sort & Quick Sort

Guaranteed O(N log N) stability vs cache-friendly in-place partitioning and O(N) QuickSelect.

Track goal: Master sorting and searching foundations from 0 level. This is Lesson 2 of 3 in Sorting & Searching. Index

1 · The One Idea

Both Merge Sort and Quick Sort follow the Divide-and-Conquer paradigm, but they execute it in reverse:

  • Merge Sort: Does zero work on the way down (splits array in half blindly); does 100% of the work on the way up (merging two sorted halves in $O(N)$ time). Guaranteed $O(N \log N)$ in all cases, stable, but requires $O(N)$ auxiliary RAM.
  • Quick Sort: Does 100% of the work on the way down (partitions around a pivot so left < pivot < right); does zero work on the way up. Blazingly fast in-place cache locality, but risks $O(N^2)$ worst case on sorted inputs unless randomized pivots are used.

2 · Merge Sort Implementation & Inversion Counting

public class MergeSort {
    public static void sort(int[] arr, int left, int right) {
        if (left >= right) return;
        int mid = left + (right - left) / 2;
        sort(arr, left, mid);
        sort(arr, mid + 1, right);
        merge(arr, left, mid, right);
    }

    private static void merge(int[] arr, int left, int mid, int right) {
        int[] temp = new int[right - left + 1];
        int i = left, j = mid + 1, k = 0;

        while (i <= mid && j <= right) {
            if (arr[i] <= arr[j]) temp[k++] = arr[i++];
            else temp[k++] = arr[j++];
        }
        while (i <= mid) temp[k++] = arr[i++];
        while (j <= right) temp[k++] = arr[j++];

        System.arraycopy(temp, 0, arr, left, temp.length);
    }
}

3 · QuickSelect: Finding K-th Smallest Element in Expected O(N)

Why sort the entire array if you only need the 5th smallest number? QuickSelect partitions the array around a pivot: if pivot lands at index $K$, return immediately! If pivot index > $K$, recurse only on the left partition! Average recurrence: $T(N) = T(N/2) + O(N) = \mathbf{O(N) ext{ Time}}$!
