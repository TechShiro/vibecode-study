Comparison Sorts & Sorting Stability

Bubble, Selection, and Insertion Sort — and why Insertion Sort powers modern hybrid sorting engines.

Track goal: Master sorting and searching foundations from 0 level. This is Lesson 1 of 3 in Sorting & Searching. Index

1 · The One Idea

Any sorting algorithm that decides element order exclusively through pairwise comparisons (a < b) has an unyielding mathematical lower bound of $\Omega(N \log N)$ comparisons in the worst case (proven via Decision Tree depth). Among the elementary $O(N^2)$ sorts, Insertion Sort has a superpower: if an array is already nearly sorted (few inversions), it runs in blistering O(N) linear time, which is why modern production sorting engines (Java's TimSort, C++ std::sort) switch to Insertion Sort for small sub-arrays!

2 · What is Sorting Stability & Why Does It Matter?

A sorting algorithm is Stable if elements with equal keys appear in the sorted output in the exact same relative order as they appeared in the input.

Real-World Application Imagine an e-commerce list of products already sorted alphabetically by Name. A user clicks: "Sort by Price". If the sorting algorithm is Stable (like Merge Sort or Insertion Sort), products with identical prices will remain neatly sorted by Name! If Unstable (like Quick Sort or Heap Sort), their alphabetical order is scrambled into chaos!
