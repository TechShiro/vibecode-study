The Top-K Family

Five famous problems, one template — plus Quickselect, the O(n) party trick interviewers ask for as the follow-up, and bucket sort, the O(n) answer when the key is a frequency.

Mission link: LC 215, 347, and 973 are among the most-reported OA/phone-screen questions at Amazon, Meta, and Google. This is Lesson 2 of the 3-lesson Top-K / Heap track. Mission

1 · The one idea

Every problem here is "find the k best under some scoring function" — value, frequency, distance. Three engines solve all of them: the size-k heap from Lesson 1 (O(n log k), works on streams), Quickselect (O(n) average, in-place, needs the whole array), and bucket sort (O(n), only when the score is a bounded integer like a frequency ≤ n). Your job in an interview is to (1) name the scoring function, (2) pick the engine, (3) state why.

Recognition trigger "k largest", "k most frequent", "k closest to origin", "kth largest", "sort by frequency". The scoring function changes (value / count / squared distance) but the skeleton never does. Follow-up "can you beat O(n log k)?" → Quickselect (kth of an array) or bucket sort (frequency-scored). Follow-up "what if it's a stream?" → the heap is the only survivor.

2 · Core template A — Kth Largest via size-k min-heap (LC 215)

int findKthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>(); // MIN-heap: eviction door for the k largest
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();  // evict the weakest of the current k
    }
    return heap.peek();                    // smallest survivor = kth largest
}

Time O(n log k) · Space O(k). This is Lesson 1's template verbatim — recognized, not re-derived.

3 · Core template B — Quickselect, the O(n) follow-up

Quicksort recurses into both halves; Quickselect recurses into one. Partition the array around a pivot so smaller values sit left and larger sit right — the pivot lands at its final sorted index p. If p is the index you want, done; otherwise recurse only into the side that contains it. Cost: n + n/2 + n/4 + … = O(n) average. Worst case O(n²) on adversarial pivots — say "randomized pivot fixes that in expectation" and the interviewer relaxes. 

int findKthLargest(int[] nums, int k) {
    return quickselect(nums, 0, nums.length - 1, nums.length - k); // kth largest = index n−k in sorted order
}
int quickselect(int[] a, int lo, int hi, int target) {
    while (true) {
        if (lo == hi) return a[lo];
        int p = partition(a, lo, hi);      // pivot's final sorted index
        if (p == target) return a[p];
        if (p < target) lo = p + 1;        // answer is right of the pivot
        else            hi = p - 1;        // answer is left — recurse ONE side only
    }
}
int partition(int[] a, int lo, int hi) {   // Lomuto: pivot = a[hi]
    int r = lo + (int)(Math.random() * (hi - lo + 1));
    swap(a, r, hi);                        // randomize → O(n) expected, kills sorted-input worst case
    int pivot = a[hi], i = lo;             // i = next slot for a "small" element
    for (int j = lo; j < hi; j++)
        if (a[j] < pivot) swap(a, i++, j); // smaller-than-pivot values compact to the left
    swap(a, i, hi);                        // pivot drops into its final index i
    return i;
}
void swap(int[] a, int i, int j) { int t = a[i]; a[i] = a[j]; a[j] = t; }

Time O(n) average, O(n²) worst · Space O(1) — in-place, iterative. Note it mutates the input.

Partition walkthrough — dry run

a = [3, 1, 5, 2, 4], k = 2 → target index 5 − 2 = 3. Say the random swap picks pivot 4 (moved to the end → [3,1,5,2,4]):

pivot = 4, i = 0 (next slot for a value < 4) j=0: a[0]=3 < 4 → swap(0,0), i→1 — [3,1,5,2,4] j=1: a[1]=1 < 4 → swap(1,1), i→2 — [3,1,5,2,4] j=2: a[2]=5 ≥ 4 → skip (5 stays in the "big" zone) j=3: a[3]=2 < 4 → swap(2,3), i→3 — [3,1,2,5,4] final: swap(i=3, hi=4) → [3,1,2,4,5] — pivot 4 lands at index 3 p = 3 = target → return 4. One partition, no recursion needed. (4 is the 2nd largest ✓)

Case: Top K Frequent Elements — heap on a score (LC 347)

The heap stores {value, freq} pairs and the comparator ranks by freq — the first time the heap's contents and its ordering key differ. This is the shape most Top-K interview questions take.

int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int x : nums) count.merge(x, 1, Integer::sum);   // score every value: O(n)

    PriorityQueue<int[]> heap =                            // {value, freq}, MIN-heap BY FREQ
        new PriorityQueue<>((a, b) -> Integer.compare(a[1], b[1]));
    for (Map.Entry<Integer, Integer> e : count.entrySet()) {
        heap.offer(new int[]{e.getKey(), e.getValue()});
        if (heap.size() > k) heap.poll();                 // evict the least frequent of the k
    }
    int[] res = new int[k];
    for (int i = 0; i < k; i++) res[i] = heap.poll()[0];  // O(m log k), m = distinct values
    return res;
}

Case: Top K Frequent — O(n) bucket sort alternative (LC 347)

A frequency can't exceed n, so frequencies are a bounded score: index an array of buckets by frequency and walk it from the top. No comparisons, no log factor.

int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> count = new HashMap<>();
    for (int x : nums) count.merge(x, 1, Integer::sum);

    List<Integer>[] bucket = new List[nums.length + 1];   // bucket[f] = values appearing exactly f times
    for (Map.Entry<Integer, Integer> e : count.entrySet()) {
        int f = e.getValue();
        if (bucket[f] == null) bucket[f] = new ArrayList<>();
        bucket[f].add(e.getKey());
    }
    int[] res = new int[k]; int i = 0;
    for (int f = nums.length; f >= 1 && i < k; f--)       // walk highest frequency down
        if (bucket[f] != null)
            for (int v : bucket[f]) { res[i++] = v; if (i == k) break; }
    return res;                                            // O(n) time, O(n) space — beats the heap
}

Case: K Closest Points to Origin — size-k MAX-heap (LC 973)

"Closest" = k smallest distances → the mirror template: max-heap, evict the farthest. And never take the square root — x²+y² preserves order and stays in integers.

int[][] kClosest(int[][] points, int k) {
    PriorityQueue<int[]> heap = new PriorityQueue<>(      // MAX-heap by squared distance
        (a, b) -> Integer.compare(b[0]*b[0] + b[1]*b[1],
                                  a[0]*a[0] + a[1]*a[1]));
    for (int[] p : points) {
        heap.offer(p);
        if (heap.size() > k) heap.poll();                 // evict the FARTHEST of the current k
    }
    return heap.toArray(new int[0][]);                    // any order accepted. O(n log k) / O(k)
}

Case: Kth Largest in a Stream — the heap becomes state (LC 703)

class KthLargest {
    private final PriorityQueue<Integer> heap = new PriorityQueue<>(); // size-k min-heap, lives forever
    private final int k;
    public KthLargest(int k, int[] nums) {
        this.k = k;
        for (int x : nums) add(x);         // reuse add() — nums.length may be < k, that's fine
    }
    public int add(int val) {
        heap.offer(val);
        if (heap.size() > k) heap.poll();
        return heap.peek();                // kth largest so far — O(log k) per add
    }
}

Case: Sort Characters by Frequency — drain the whole heap (LC 451)

Here k = every distinct character, so no size cap — count, max-heap by frequency, drain, rebuild.

String frequencySort(String s) {
    int[] cnt = new int[128];
    for (char c : s.toCharArray()) cnt[c]++;              // ASCII counting — score in O(n)
    PriorityQueue<Character> heap = new PriorityQueue<>(  // MAX-heap by count
        (a, b) -> Integer.compare(cnt[b], cnt[a]));
    for (char c = 0; c < 128; c++) if (cnt[c] > 0) heap.offer(c);
    StringBuilder sb = new StringBuilder();
    while (!heap.isEmpty()) {
        char c = heap.poll();                             // most frequent remaining
        for (int i = 0; i < cnt[c]; i++) sb.append(c);    // append it cnt[c] times
    }
    return sb.toString();  // O(n + d log d), d ≤ 128. Bucket-by-frequency gives O(n) here too.
}

5 · Decision guide — heap vs sort vs quickselect vs bucket

EngineTimeSpacePick it when
Full sortO(n log n)O(1)–O(n)k ≈ n, or you need everything ordered anyway. Simplest to write; mention it, then beat it.
Size-k heapO(n log k)O(k)k ≪ n, streaming input, memory-bounded, or online "kth so far" queries (703). The default answer.
QuickselectO(n) avg, O(n²) worstO(1)Whole array in hand, single kth/top-k query, mutation allowed. The "can you do better?" answer for 215.
Bucket sortO(n)O(n)The score is a bounded integer — frequencies (347, 451). Guaranteed linear, no randomness.
Interview script Lead with the size-k heap and its O(n log k) — it's robust and streams. When asked "can you do better?", offer Quickselect O(n) average for a one-shot kth, or bucket sort O(n) if the score is a frequency. Naming the trade-offs (stream vs mutate vs bounded score) is worth more than any single implementation.

6 · Edge-case checklist

  • Comparator direction, again: k largest → min-heap, k smallest/closest → max-heap. In 347/973 the comparator ranks by the score slot, not the value — double-check which index you compare.
  • Quickselect index math: kth largest = sorted index n − k; kth smallest = index k − 1. Off-by-one here fails hidden tests silently.
  • Randomize the pivot (or shuffle first) — LeetCode's 215 test set includes sorted/equal arrays that drive fixed-pivot Lomuto to O(n²) TLE.
  • Distance overflow: in 973, x²+y² fits int for |x|,|y| ≤ 10⁴, but say "I'd use long for larger coordinates." Never compare doubles from Math.sqrt.
  • 703 constructor may pass fewer than k numbers — routing the constructor through add() handles it; peek() is only meaningful once size == k (the problem guarantees k−1+ elements before the first add).
  • 347 heap holds distinct values (m entries), not n — the log factor is log k on m offers. Don't offer raw array elements.
  • Bucket array size n+1 — a value can appear exactly n times; size-n buckets miss index n.
