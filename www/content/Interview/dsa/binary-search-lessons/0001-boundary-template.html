Binary Search as a Boundary Finder

Forget "find the target in a sorted array." Binary search finds the boundary where a monotonic yes/no question flips from NO to YES — and once you see it that way, every variant is the same six lines.

Mission link: binary search shows up in ~1 of every 5 big-tech OA sets, and the #1 failure mode is off-by-one bugs under time pressure. This is Lesson 1 of the 3-lesson binary search track. Mission

1 · The one idea

Take any yes/no question p(i) over indices 0..n-1 that is monotonic: once it becomes true, it stays true. The answers look like F F F F T T T — a wall of falses, then a wall of trues. Binary search is the O(log n) way to find the first T. That's it. "Find 7 in a sorted array" is just the question p(i) = (nums[i] >= 7): the first T is where 7 lives (or where it would be inserted). Every problem in this track — classic search, rotated arrays, "minimum days to make bouquets" — is choosing the right predicate and reading off the boundary.

Recognition trigger A sorted (or otherwise monotonic) structure + any of: "find the target," "find the first/last occurrence," "where would X be inserted," "first version that is bad," "largest k such that…". If you can phrase the problem as "the answers to some yes/no question go F…F T…T — find the flip", this template fires. O(log n) expected when n ≤ 10⁹-ish or the input is explicitly sorted.

2 · Core template — first true, lo < hi

Search range [lo, hi] where hi = n (one past the end — "n" means "the predicate is never true, the answer is off the right edge"). Invariant: the first true is always inside [lo, hi]. Each step halves the range; when lo == hi the range has one candidate left, and that's the answer. 

// Find the smallest i in [0, n] such that p(i) is true; returns n if p is never true.
int firstTrue(int n, IntPredicate p) {
    int lo = 0, hi = n;                  // answer lives in [lo, hi]; hi = n means "no true exists"
    while (lo < hi) {                    // stop when exactly one candidate remains
        int mid = lo + (hi - lo) / 2;    // overflow-safe midpoint (see trap below)
        if (p.test(mid)) hi = mid;       // mid is true → first true is mid OR earlier → keep mid
        else lo = mid + 1;               // mid is false → first true is strictly after mid
    }
    return lo;                           // lo == hi == the boundary
}

// lowerBound: first index with nums[i] >= target — the workhorse instance of firstTrue.
int lowerBound(int[] nums, int target) {
    int lo = 0, hi = nums.length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] >= target) hi = mid;
        else lo = mid + 1;
    }
    return lo;                           // may be nums.length → target > everything
}

Time O(log n) — the range halves every iteration. Space O(1).

Why this template kills off-by-one bugs Three mechanical guarantees: (1) hi = mid (not mid - 1) and lo = mid + 1 — the range strictly shrinks every iteration, so it can't loop forever. (2) The loop is lo < hi, so it exits with lo == hi — there is exactly one answer variable, no "is it lo or hi or lo+1?" guessing. (3) The invariant "first true ∈ [lo, hi]" is easy to re-derive under pressure: true mid → keep it (hi = mid); false mid → discard it (lo = mid + 1). Compare that to the classic lo <= hi / hi = mid - 1 version, where the answer might be in lo, hi, or gone entirely.
The overflow guard: mid = lo + (hi - lo) / 2 (lo + hi) / 2 overflows int when lo + hi > 2³¹ − 1. On array indices you'll rarely hit it, but in Lesson 3 you'll binary-search value ranges up to 10⁹ where lo + hi overflows easily — and it's a famous historical bug (it sat in the JDK's own Arrays.binarySearch for nine years). Write lo + (hi - lo) / 2 every time, by reflex.

Worked example — dry run

lowerBound(nums, 7) on nums = [1, 3, 5, 7, 7, 9]. Predicate: nums[i] >= 7, so answers are F F F T T T. Expected boundary: index 3.

lo=0, hi=6 — first true somewhere in [0, 6] mid=3 → nums[3]=7 ≥ 7 → T → hi=3 (keep mid: it might BE the first true) lo=0, hi=3 → mid=1 → nums[1]=3 ≥ 7? F → lo=2 (discard mid) lo=2, hi=3 → mid=2 → nums[2]=5 ≥ 7? F → lo=3 lo=3 == hi=3 → return 3 — the FIRST 7, not a random one

3 · All the cases

Every case is firstTrue with a different predicate, plus at most two lines of post-processing.

Case: Classic Binary Search (LC 704)

Find the boundary, then check what's standing there. No special-casing "found vs not found" inside the loop.

int search(int[] nums, int target) {
    int lo = lowerBound(nums, target);           // first index with nums[i] >= target
    return (lo < nums.length && nums[lo] == target) ? lo : -1;
    // lo == nums.length → target beyond everything; nums[lo] > target → target absent
}

Case: Search Insert Position (LC 35)

The insertion index of target is exactly "first index whose value is ≥ target" — the boundary itself, no post-check needed. One line: return lowerBound(nums, target);. This is why the template returns n when the target is bigger than everything: appending at the end is the correct insert position.

Case: Find First and Last Position (LC 34)

Run the same boundary search twice. First occurrence of t = lowerBound(t). Last occurrence = one before the first index that is ≥ t+1 (i.e., the first element strictly greater than t — an upper bound for free, no second template to memorize).

int[] searchRange(int[] nums, int target) {
    int first = lowerBound(nums, target);        // first i with nums[i] >= target
    if (first == nums.length || nums[first] != target)
        return new int[]{-1, -1};                // target not present at all
    int last = lowerBound(nums, target + 1) - 1; // first i with nums[i] > target, minus one
    return new int[]{first, last};
}

Case: First Bad Version (LC 278)

Versions 1..n; once a version is bad, all later ones are bad — the problem statement literally hands you the monotonic predicate (F F … F T T … T). Note the search space is values 1..n, not array indices, so lo starts at 1 and hi at n (a bad version is guaranteed to exist, so no n+1 sentinel needed).

int firstBadVersion(int n) {
    int lo = 1, hi = n;                  // answer guaranteed in [1, n]
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;    // lo + hi could be ~2·10⁹ → the guard matters HERE
        if (isBadVersion(mid)) hi = mid; // bad → first bad is mid or earlier
        else lo = mid + 1;               // good → first bad is after mid
    }
    return lo;
}

Case: Sqrt(x) (LC 69)

No array anywhere — you binary-search the number line. Wanted: floor(√x) = the last m with m² ≤ x. Last-false and first-true are neighbors, so: find the first m with m² > x, subtract 1. This "last true = firstTrue(opposite) − 1" move is the same trick as LC 34's last position, and it's the bridge to Lesson 3.

int mySqrt(int x) {
    int lo = 0, hi = 46341;              // 46341² > 2³¹−1, so first-true exists in range
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if ((long) mid * mid > x) hi = mid; // cast BEFORE multiplying — mid*mid overflows int
        else lo = mid + 1;
    }
    return lo - 1;                       // first m with m² > x, minus 1 = floor(sqrt(x))
}

4 · Edge-case checklist

  • lo can come back as n. Always bounds-check before reading nums[lo] — the boundary "off the right edge" is a legal answer meaning "predicate never true."
  • Midpoint overflow. lo + (hi - lo) / 2, always. And in value-space predicates, cast before multiplying: (long) mid * mid, not (long)(mid * mid) — the second one overflows first, then casts the garbage.
  • Verify the predicate is monotonic before you search. If the T/F answers can go T then F then T, the template returns nonsense. This one sentence is 80% of "why is my binary search wrong."
  • Initial hi: n vs n − 1. Use n when "no true exists" is possible (LC 35, 704); use the last real candidate when an answer is guaranteed (LC 278).
  • Empty array: lo = hi = 0, loop never runs, returns 0. The template handles it — your post-check (lo < nums.length) must too.
  • Never write lo = mid in this template. With mid rounding down, lo = mid when hi = lo + 1 makes no progress → infinite loop. lo = mid + 1 / hi = mid is the safe pair.
  • Duplicates are free. lowerBound lands on the first equal element by construction — no extra handling, unlike the classic template.
