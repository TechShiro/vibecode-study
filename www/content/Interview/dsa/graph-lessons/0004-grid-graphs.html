Graph Track · Lesson 04 of 09 · a 2-D grid is just a graph

Grid Graphs (Matrix as a Graph)

Stop seeing a matrix. See a graph whose nodes are cells and whose edges are the four cells next door — then DFS and BFS from Lessons 02 & 03 solve the entire island family unchanged.

Mission link: grid problems are the most common graph questions in a Google intern OA, and the whole island family is reported live. Recognize them in < 60s and code every case in Java bug-free. This is Lesson 4 of the 9-lesson graph track. Mission

1 · The one idea

A grid int[][] g with R rows and C columns is a graph — you just never get handed an adjacency list. Each cell (r,c) is a node; its edges are the in-bounds cells immediately around it: 4 (up/down/left/right) or, when diagonals count, 8. There is no buildAdj step because the neighbors are computed on the fly from an int[][] dirs offset array. Once you accept that, every island/region problem is the DFS/BFS you already know, with two decisions to make: which traversal (DFS for connectivity/area, BFS for shortest/multi-source) and how to mark visited (mutate the grid in place, or carry a boolean[][]).

Recognition trigger A 2-D grid plus "islands / regions / connected land", "area / largest blob", "flood fill", "surrounded / enclosed / closed", or "nearest / distance to the closest X". Relationships between adjacent cells → grid graph. "Connected / how many groups / how big" → DFS. "Shortest / nearest / spread from many sources" → multi-source BFS (Lesson 03).

2 · Core template — 4-directional neighbor iteration

The spine of every grid graph is a dirs array plus one bounds check. Memorize it; everything below is this loop with a different rule for what counts as "land" and what you do when you arrive. 

static final int[][] DIRS = {{-1,0},{1,0},{0,-1},{0,1}}; // up, down, left, right

// flood one connected blob of '1's, marking visited IN PLACE
void dfs(char[][] g, int r, int c) {
    int R = g.length, C = g[0].length;
    if (r < 0 || r >= R || c < 0 || c >= C) return; // bounds guard FIRST — Java won't wrap
    if (g[r][c] != '1') return;                       // water or already-visited → stop
    g[r][c] = '0';                                    // MARK BEFORE recursing (sink the cell)
    for (int[] d : DIRS)
        dfs(g, r + d[0], c + d[1]);                   // recurse into all 4 neighbors
}

Time O(R·C) — each cell is entered a constant number of times. Space O(R·C) worst case for the recursion stack (a grid that is one giant blob is a path of length R·C). The dirs-array form is shorter and less bug-prone than four hand-written if branches, and extends to 8 directions by one line.

Two equivalent guard styles — pick one and be consistent You can bounds-check before the recursive call (push the guard into the callee, as above) or bounds-check the neighbor before you recurse (guard in the caller, as the BFS cases do). Both are correct. The in-callee style is shorter for DFS; the in-caller style reads cleaner for BFS where you only enqueue valid neighbors. Don't mix them in one function.
The #1 grid-graph bug — mark BEFORE you recurse / enqueue Mark a cell visited at the moment you commit to it, not after exploring. In DFS, set g[r][c]='0' on the way in; in BFS, mark the neighbor in the same breath as q.offer(...). Mark late and the same cell is visited from several directions — exponential blowup, wrong counts, or a stack overflow. (Same sin as the BFS enqueue/dequeue bug from Lesson 03.)

3 · In-place marking vs a visited[][] array

Two ways to remember "I've been here." Know the trade-off cold — interviewers ask.

 Mutate the grid in placeSeparate boolean[][] seen
Extra spaceO(1)O(R·C)
Preserves inputNo — destroys the gridYes
HowOverwrite land with water ('1'→'0'), or a sentinel like 2if (!seen[nr][nc]) { seen[nr][nc]=true; ... }
Use whenYou're allowed to mutate and want O(1) space (the usual interview win)The grid must survive, or values are unbounded so no safe sentinel exists
Default to in-place when allowed Sinking land to water is the canonical island idiom and earns the O(1)-space line on your complexity analysis. If the interviewer says "don't modify the input," restore it afterward or switch to boolean[][] — and say so out loud.

Case: Number of Islands (LC 200) — scan + sink

int numIslands(char[][] g) {
    int R = g.length, C = g[0].length, count = 0;
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (g[r][c] == '1') {   // a cell not yet sunk → new island
                count++;
                dfs(g, r, c);       // sink its entire blob to '0'
            }
    return count;
}
// dfs is the core template from §2

Time O(R·C). Space O(R·C) recursion worst case — swap the DFS for a queue-based BFS if a 10⁶-cell single blob risks a stack overflow.

Worked example — dry run

Grid 3×4 ('1' = land, '0' = water). Scan cells row-major; each unvisited land cell bumps the counter and launches a DFS that sinks its whole blob to '0':

first unvisited land at (0,0) → islands=1; dfs sinks {(0,0),(0,1),(1,0)} to '0' scan continues past (0,1),(1,0) — already sunk → skip; (0,2),(0,3),(1,1),(1,2) are water → skip next unvisited land at (1,3) → islands=2; dfs sinks {(1,3),(2,3),(2,2)} to '0' scan finishes the last row — all land already sunk → skip scan completes → return 2

Case: Max Area of Island (LC 695) — DFS that returns a count

int maxAreaOfIsland(int[][] g) {
    int R = g.length, C = g[0].length, best = 0;
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (g[r][c] == 1) best = Math.max(best, area(g, r, c));
    return best;
}
int area(int[][] g, int r, int c) {
    if (r < 0 || r >= g.length || c < 0 || c >= g[0].length || g[r][c] != 1)
        return 0;                       // out of bounds or not land → contributes 0
    g[r][c] = 0;                        // mark BEFORE recursing
    int sum = 1;                        // this cell
    for (int[] d : DIRS) sum += area(g, r + d[0], c + d[1]);
    return sum;                         // 1 + areas of the four sub-explorations
}
The reusable idiom: a DFS that returns a value Counting area, perimeter, or "does this blob touch the border?" are all the same shape — the DFS returns a number/flag and the parent aggregates it. Mark visited first, then add 1 + the four recursive results. This pattern carries straight into LC 1254 and 1905 below.

Case: Flood Fill (LC 733) — guard the no-op recolor

int[][] floodFill(int[][] img, int sr, int sc, int color) {
    if (img[sr][sc] != color) fill(img, sr, sc, color, img[sr][sc]);
    return img;                         // else new==old → recolor is a no-op, skip to avoid infinite recursion
}
void fill(int[][] img, int r, int c, int color, int start) {
    int R = img.length, C = img[0].length;
    if (r < 0 || r >= R || c < 0 || c >= C || img[r][c] != start) return;
    img[r][c] = color;                  // recolor = mark visited (changes what the guard checks)
    for (int[] d : DIRS) fill(img, r + d[0], c + d[1], color, start);
}
Marking must change what the guard tests If color == start, recoloring doesn't change img[r][c], so the != start guard never fires and the recursion loops forever. The outer if (img[sr][sc] != color) guard kills it. Generalize: the visited mark must alter a value your stop-condition reads.

Case: Surrounded Regions (LC 130) — DFS from the borders inward

Flip every 'O' region not touching an edge to 'X'. Inverting the question is the trick: instead of testing each region for border contact, DFS from the borders first to mark all edge-connected 'O's as safe (temporary '#'), then sweep once — surviving 'O's are enclosed, '#'s revert. 

void solve(char[][] b) {
    int R = b.length, C = b[0].length;
    for (int r = 0; r < R; r++) { guard(b, r, 0); guard(b, r, C - 1); }   // left & right edges
    for (int c = 0; c < C; c++) { guard(b, 0, c); guard(b, R - 1, c); }   // top & bottom edges
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++) {
            if (b[r][c] == 'O') b[r][c] = 'X';   // enclosed → flip
            else if (b[r][c] == '#') b[r][c] = 'O'; // border-connected → restore
        }
}
void guard(char[][] b, int r, int c) {           // mark this 'O' region as edge-safe
    if (r < 0 || r >= b.length || c < 0 || c >= b[0].length || b[r][c] != 'O') return;
    b[r][c] = '#';
    for (int[] d : DIRS) guard(b, r + d[0], c + d[1]);
}
"Anything touching the border is special" → seed from the border This border-first move is its own mini-pattern (Pacific-Atlantic LC 417 is the same idea). When edge contact decides the answer, traverse from the edges first and invert the question. The next case reuses it directly.

Case: Number of Closed Islands (LC 1254) — sink border land, then count

// here 0 = land, 1 = water (LC 1254's convention)
int closedIsland(int[][] g) {
    int R = g.length, C = g[0].length;
    for (int r = 0; r < R; r++) { sink(g, r, 0); sink(g, r, C - 1); }     // drown edge-touching land
    for (int c = 0; c < C; c++) { sink(g, 0, c); sink(g, R - 1, c); }
    int count = 0;
    for (int r = 1; r < R - 1; r++)
        for (int c = 1; c < C - 1; c++)
            if (g[r][c] == 0) { count++; sink(g, r, c); } // only interior land survives → closed
    return count;
}
void sink(int[][] g, int r, int c) {
    if (r < 0 || r >= g.length || c < 0 || c >= g[0].length || g[r][c] != 0) return;
    g[r][c] = 1;                        // turn land to water = mark visited
    for (int[] d : DIRS) sink(g, r + d[0], c + d[1]);
}
Closed = "Number of Islands after removing border-touching ones" Same scan-and-sink as LC 200; the only addition is the border pre-pass that eliminates open islands. Count Sub Islands (LC 1905) is the sibling: explore each island of grid2 and AND together "is the matching grid1 cell also land?" across the whole blob — if any cell fails, the sub-island doesn't count.

Case: Walls and Gates (LC 286) — multi-source BFS from every gate

Fill each empty room with its distance to the nearest gate. Don't BFS from each empty cell (O((R·C)²)). Instead seed all gates at once and BFS outward — the first time the frontier reaches a room is, by BFS's level guarantee, its nearest-gate distance. (Multi-source BFS from Lesson 03; LC 542 "01 Matrix" is the same move.) 

static final int INF = Integer.MAX_VALUE;     // LC 286: -1 = wall, 0 = gate, INF = empty room
void wallsAndGates(int[][] rooms) {
    int R = rooms.length, C = rooms[0].length;
    Queue<int[]> q = new ArrayDeque<>();
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (rooms[r][c] == 0) q.offer(new int[]{r, c});  // seed EVERY gate
    while (!q.isEmpty()) {
        int[] cell = q.poll();
        int r = cell[0], c = cell[1];
        for (int[] d : DIRS) {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C || rooms[nr][nc] != INF)
                continue;                          // out of bounds, wall, or already filled
            rooms[nr][nc] = rooms[r][c] + 1;        // MARK + set distance at enqueue time
            q.offer(new int[]{nr, nc});
        }
    }
}

Time O(R·C) — each room is filled exactly once (the != INF test is the visited check). Space O(R·C) for the queue.

Why DFS would be wrong here DFS's first arrival at a room can be via a long detour, so it would record a non-minimal distance. BFS expands by distance, so first arrival = shortest. "Nearest / shortest / spread" on a grid → BFS, every time (Lesson 03's rule, applied here).

5 · Edge-case checklist

  • Bounds order in the if → test nr,nc in range before reading g[nr][nc]. Java throws ArrayIndexOutOfBounds; it does not wrap negatives. Short-circuit || makes the order load-bearing.
  • Mark BEFORE recursing / enqueuing → mark on the way in (DFS) or at offer time (BFS), never after. Late marking = re-visits, blow-ups, wrong counts.
  • In-place mutation vs visited[][] → in-place is O(1) space but destroys input; restore it or use a boolean grid when the input must survive or values are unbounded.
  • Flood fill same start/target color → the no-op recolor never marks anything → infinite recursion. Guard color != start.
  • 4 vs 8 directions → re-read the problem: "horizontally or vertically" = 4; "including diagonally" = 8. Wrong dirs silently merges or splits islands.
  • Empty grid → guard g.length == 0 || g[0].length == 0 before reading g[0].length, or you crash on the dimension read itself.
  • Recursion depth → a single component covering a 10⁶-cell grid can overflow the call stack; switch the DFS for an explicit stack or BFS queue.
