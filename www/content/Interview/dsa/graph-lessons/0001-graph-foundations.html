1 · The one idea

A graph is just nodes (vertices, V) + connections (edges, E). Trees, grids, linked lists, "course prerequisites", "word ladders", "friend networks" — all graphs. 99% of interview problems never hand you a graph object: they hand you raw edges (int[][] edges) or an implicit structure (a grid, a dictionary of words), and step 1 is always to turn that into an adjacency list you can traverse.

Recognition trigger "connected / reachable / path / cycle / islands / network / prerequisites / shortest steps." Anything about relationships between things. The moment you see edges, a grid, or "A depends on B", you are in graph territory — build the adjacency list first.

3 · Three ways to store a graph

RepresentationJava typeSpace"Is u→v an edge?""Neighbors of u?"
Adjacency list ← defaultList<List<Integer>>O(V+E)O(degree)O(degree) — fast
Adjacency matrixint[][] / boolean[][]O(V²)O(1) — fastO(V) — slow
Edge list (raw input)int[][] edgesO(E)O(E)O(E) — slow
Default to the adjacency list Real graphs are sparse (E ≪ V²), and traversal asks "give me u's neighbors" constantly — exactly what a list does in O(degree). Use a matrix only when V is small (≤ ~500) and you query "is there an edge?" a lot, or the problem literally gives you a matrix (e.g. LC 547 Provinces).

Build an adjacency list from an edge list — the move you do every single time

// Input: n nodes (0..n-1) and edges[i] = {u, v}. UNDIRECTED graph.
List<List<Integer>> buildAdj(int n, int[][] edges) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());  // one empty list PER node — don't skip this
    for (int[] e : edges) {
        adj.get(e[0]).add(e[1]);
        adj.get(e[1]).add(e[0]);   // BOTH directions because undirected. Directed? delete this line.
    }
    return adj;
}

Time O(V+E) to build. Space O(V+E). This is the first 4 lines of nearly every graph solution you will write at Google.

The #1 build bug Forgetting the for (i<n) adj.add(new ArrayList<>()) seed loop → adj.get(u) throws IndexOutOfBounds. And forgetting the second add on an undirected graph silently makes half your edges disappear — the bug that "passes 3 test cases then fails."

When nodes aren't 0..n-1 (strings, sparse ids) → use a Map

// e.g. nodes are airport codes. Map<node, neighbors>.
Map<String, List<String>> adj = new HashMap<>();
for (String[] e : edges) {
    adj.computeIfAbsent(e[0], k -> new ArrayList<>()).add(e[1]);
    // computeIfAbsent = "get the list, or create+insert an empty one first, then return it"
}

Weighted graph? Store int[]{neighbor, weight} instead of a bare Integer: List<List<int[]>> adj. You'll use this in Lesson 07 (Dijkstra).

4 · Putting it together: count connected components

The "hello world" of graphs — LC 547 / 323 directly. Build adjacency, then launch a DFS/BFS from every unvisited node; each launch discovers one whole component.

int countComponents(int n, int[][] edges) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }

    boolean[] visited = new boolean[n];
    int components = 0;
    for (int i = 0; i < n; i++) {
        if (!visited[i]) {
            components++;          // found a new island → explore all of it
            dfs(i, adj, visited);  // (full DFS is Lesson 02)
        }
    }
    return components;
}
void dfs(int node, List<List<Integer>> adj, boolean[] visited) {
    visited[node] = true;
    for (int nei : adj.get(node))
        if (!visited[nei]) dfs(nei, adj, visited);
}

Time O(V+E). Space O(V+E) adjacency + O(V) visited + O(V) recursion stack.

Worked example — dry run

Input: n = 5, edges = {{0,1},{1,2},{3,4}} (undirected). Build the adjacency list, then sweep nodes 0..4, launching a DFS from each unvisited one:

i=0 unvisited → components=1; dfs(0) walks 0→1→2, marks all three visited i=1 already visited → skip i=2 already visited → skip i=3 unvisited → components=2; dfs(3) walks 3→4, marks both visited i=4 already visited → skip loop ends → return 2

5 · Edge-case checklist

  • Undirected → add the edge both ways. Half your edges vanish otherwise.
  • Seed one empty list per node before adding edges, or adj.get(u) crashes.
  • Disconnected graph: a single DFS/BFS won't reach every node — loop over all nodes and launch from each unvisited one.
  • Self-loops / duplicate edges: the visited check handles them, but know they can exist.
  • Recursion depth: a path-graph of 10⁵ nodes can StackOverflow a recursive DFS → use an explicit stack (Lesson 02).
  • 0-indexed vs 1-indexed nodes: many problems label nodes 1..n — size your arrays n+1 or subtract 1.
