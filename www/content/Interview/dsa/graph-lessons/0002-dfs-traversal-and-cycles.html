Depth-First Search

One recursive idea — dive as deep as you can, then back out — solves connectivity, islands, all-paths, and both flavors of cycle detection. The variations are bookkeeping on top of one template.

Mission link: graphs are ~25% of Google intern questions, and DFS is the workhorse — Clone Graph, Number of Islands and Pacific Atlantic are all Google-reported. This is Lesson 2 of the 9-lesson graph track. Mission

1 · The one idea

DFS commits to one neighbor, follows it as far as it goes, and only backtracks when it dead-ends — "deep before wide." Mechanically it's a visited set plus either the call stack (recursion) or an explicit Deque used as a stack. The visited set is what makes a graph DFS terminate where a tree DFS needs no such guard. The same five lines run on graphs, grids (a grid is a graph with 4 implicit neighbors), and trees.

Recognition trigger "connected / path exists / all paths / cycle / islands / regions / flood / count groups." If the question is about whether you can reach something, enumerating reachable things, or detecting a loop — and shortest distance is NOT asked — DFS fires. The instant you hear "minimum steps / fewest moves," switch to BFS (Lesson 03).

2 · Core template

Adjacency as List<List<Integer>> plus a boolean[] visited. Mark on entry, recurse into every unvisited neighbor. To make it count components or sweep a disconnected graph, wrap it in a loop over all nodes (Lesson 01). 

// recursive graph DFS — the move you build everything else on
void dfs(int node, List<List<Integer>> adj, boolean[] visited) {
    visited[node] = true;            // mark ON ENTRY, before recursing
    for (int nei : adj.get(node)) {
        if (!visited[nei])
            dfs(nei, adj, visited);  // go deep into this branch first
    }
}

// driver: handles a disconnected graph by launching from every unvisited node
int countComponents(int n, List<List<Integer>> adj) {
    boolean[] visited = new boolean[n];
    int components = 0;
    for (int i = 0; i < n; i++)
        if (!visited[i]) { components++; dfs(i, adj, visited); }
    return components;
}

Time O(V + E) — each vertex marked once, each edge inspected once. Space O(V) for visited + O(V) worst-case recursion stack (a path graph). On a grid that's O(rows·cols).

Worked example — dry run

Input: n = 5, edges = {{0,1},{0,2},{1,3},{2,4}} (undirected, tree-shaped). Run dfs(0) and watch the recursion dive deep, hit a leaf, backtrack, then take the next branch:

dfs(0): mark 0 visited → order = [0] 0's first unvisited neighbor is 1 → dfs(1): mark 1 → order = [0, 1] 1's first unvisited neighbor is 3 → dfs(3): mark 3 → order = [0, 1, 3] 3 has no unvisited neighbors (leaf) → return to dfs(1) dfs(1) has no more neighbors → return to dfs(0) 0's next unvisited neighbor is 2 → dfs(2): mark 2 → order = [0, 1, 3, 2] 2's first unvisited neighbor is 4 → dfs(4): mark 4 → order = [0, 1, 3, 2, 4] 4 is a leaf → unwind all the way out; every node visited final visited order → [0, 1, 3, 2, 4]

Iterative DFS with an explicit stack

Identical traversal, but the stack is yours instead of the JVM's. Reach for this when the graph can be deep enough to blow the call stack (see the trap). 

// same O(V+E); marks on POP. Push-time marking also works and avoids dup stack entries.
void dfsIterative(int start, List<List<Integer>> adj, boolean[] visited) {
    Deque<Integer> stack = new ArrayDeque<>();
    stack.push(start);
    while (!stack.isEmpty()) {
        int node = stack.pop();
        if (visited[node]) continue; // a node can be pushed by several neighbors
        visited[node] = true;
        for (int nei : adj.get(node))
            if (!visited[nei]) stack.push(nei);
    }
}
Recursion depth → StackOverflow A path-shaped graph of 10⁵ nodes recurses 10⁵ deep and overflows the JVM call stack (default ~10⁴–10⁵ frames). Competitive inputs and adversarial test cases love this shape. When V can be large and the graph can be a long chain, switch to the explicit-stack version above — same complexity, heap-allocated stack, no overflow.

Case: Number of Islands — grid DFS, in-place marking (LC 200) ★

A grid is a graph: each '1' cell's neighbors are its 4 orthogonal '1' neighbors. Instead of a visited array, overwrite each visited land cell with '0' — sinking the island as you walk it. 

int numIslands(char[][] grid) {
    int R = grid.length, C = grid[0].length, count = 0;
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (grid[r][c] == '1') { count++; sink(grid, r, c); } // each launch = one island
    return count;
}
void sink(char[][] grid, int r, int c) {
    if (r < 0 || r >= grid.length || c < 0 || c >= grid[0].length || grid[r][c] != '1')
        return;                      // bounds + "is it land" guard rolled into one
    grid[r][c] = '0';                // mark visited by sinking it
    sink(grid, r + 1, c);
    sink(grid, r - 1, c);
    sink(grid, r, c + 1);
    sink(grid, r, c - 1);
}

Time O(R·C) — each cell visited once. Space O(R·C) worst-case recursion depth (one giant island that snakes through the whole grid).

Case: Clone Graph — the map is visited AND the clone (LC 133) ★

The classic Google phone-screen question. A Map<Node,Node> from original → copy does double duty: "have I cloned this node?" is just "is it a key?", and it returns the existing clone so shared neighbors aren't duplicated. 

// class Node { int val; List<Node> neighbors; }
Map<Node, Node> seen = new HashMap<>();
Node cloneGraph(Node node) {
    if (node == null) return null;
    if (seen.containsKey(node)) return seen.get(node); // already cloned → return it (cycle-safe)
    Node copy = new Node(node.val);
    seen.put(node, copy);            // register BEFORE recursing, or cycles loop forever
    for (Node nei : node.neighbors)
        copy.neighbors.add(cloneGraph(nei));
    return copy;
}

Time O(V + E). Space O(V) for the map + recursion stack.

Register the clone before you recurse If you put seen.put(node, copy) after the neighbor loop, a cycle (A→B→A) re-enters cloneGraph(A) before A is registered, clones A again, and recurses forever. Put it in the map the instant you create it.

Case: Number of Provinces / Connected Components (LC 547 / 323)

LC 547 hands you an adjacency matrix isConnected[i][j]; LC 323 hands you an edge list. Either way the answer is "how many DFS launches cover the graph" — identical to the driver in §2. 

int findCircleNum(int[][] isConnected) {
    int n = isConnected.length;
    boolean[] visited = new boolean[n];
    int provinces = 0;
    for (int i = 0; i < n; i++)
        if (!visited[i]) { provinces++; dfsMatrix(isConnected, visited, i); }
    return provinces;
}
void dfsMatrix(int[][] g, boolean[] visited, int u) {
    visited[u] = true;
    for (int v = 0; v < g.length; v++)
        if (g[u][v] == 1 && !visited[v]) dfsMatrix(g, visited, v); // neighbor = a 1 in row u
}

Time O(V²) here because the matrix forces scanning a full row per node (use an adjacency list for O(V+E) on sparse input). Space O(V).

Case: Cycle detection — UNDIRECTED (pass the parent)

In an undirected graph every edge u–v shows up in both lists, so DFS always sees the edge straight back to where it came from. That is not a cycle — skip it by passing the parent. A visited node that is not the parent means a real cycle. 

boolean hasCycleUndirected(int n, List<List<Integer>> adj) {
    boolean[] visited = new boolean[n];
    for (int i = 0; i < n; i++)            // disconnected → check every component
        if (!visited[i] && dfs(i, -1, adj, visited)) return true;
    return false;
}
boolean dfs(int node, int parent, List<List<Integer>> adj, boolean[] visited) {
    visited[node] = true;
    for (int nei : adj.get(node)) {
        if (!visited[nei]) {
            if (dfs(nei, node, adj, visited)) return true;
        } else if (nei != parent) {       // visited & not where we came from = cycle
            return true;
        }
    }
    return false;
}

Time O(V + E). Space O(V).

Parent-skip breaks on duplicate edges The nei != parent trick assumes at most one edge between two nodes. If the input can contain a parallel edge (u–v listed twice), two distinct edges to the parent are a real 2-cycle — and parent-skip wrongly ignores it. When multi-edges are possible, skip a single edge to the parent by id/count, or use Union-Find (Lesson on DSU) instead.

Case: Cycle detection — DIRECTED (3-color / onStack)

In a directed graph a plain visited flag is insufficient: re-reaching an already-finished node is fine (a diamond A→B→D, A→C→D has no cycle), but re-reaching a node that is still on the current path is a back-edge = cycle. You must distinguish "done" from "in progress." Two equivalent encodings: a 3-color array (0 white / 1 gray-on-stack / 2 black-done), or a visited[] plus onStack[]. 

// color: 0 = unvisited, 1 = in current DFS path (gray), 2 = fully explored (black)
boolean hasCycleDirected(int n, List<List<Integer>> adj) {
    int[] color = new int[n];
    for (int i = 0; i < n; i++)
        if (color[i] == 0 && dfs(i, adj, color)) return true;
    return false;
}
boolean dfs(int node, List<List<Integer>> adj, int[] color) {
    color[node] = 1;                 // gray: entered, still on the stack
    for (int nei : adj.get(node)) {
        if (color[nei] == 1) return true;          // edge to a gray node = back-edge = cycle
        if (color[nei] == 0 && dfs(nei, adj, color)) return true;
        // color[nei] == 2 (black) → safe, already fully explored
    }
    color[node] = 2;                 // black: leaving — done with this node
    return false;
}

Time O(V + E). Space O(V). This is exactly the cycle check inside Course Schedule (LC 207) — "can finish" ⇔ "the prerequisite digraph has no cycle."

Case: All Paths from Source to Target — DFS + backtracking (LC 797)

Enumeration, not just reachability: build the current path on entry, recurse, then undo the choice on exit so siblings start clean. The input is a DAG, so no visited set is needed. 

List<List<Integer>> allPathsSourceTarget(int[][] graph) {
    List<List<Integer>> res = new ArrayList<>();
    List<Integer> path = new ArrayList<>();
    path.add(0);                     // start node is always on the path
    dfs(graph, 0, path, res);
    return res;
}
void dfs(int[][] graph, int node, List<Integer> path, List<List<Integer>> res) {
    if (node == graph.length - 1) {  // reached target n-1
        res.add(new ArrayList<>(path)); // COPY — path keeps mutating
        return;
    }
    for (int nei : graph[node]) {
        path.add(nei);               // choose
        dfs(graph, nei, path, res);  // explore
        path.remove(path.size() - 1);// un-choose (backtrack) — restore for the next sibling
    }
}

Time O(2V·V) worst case — exponentially many paths, each up to length V to copy. Space O(V) recursion + path (excluding output).

Case: Pacific Atlantic Water Flow — DFS inward from both borders (LC 417) ★

A Google-reported favorite, and the inversion is the trick: don't ask "can this cell flow to both oceans?" (DFS from every cell = O((R·C)²)). Instead flood uphill inward from each ocean's border, marking every cell that ocean can reach. The answer is the intersection of the two reachable sets — one O(R·C) pass per ocean. 

List<List<Integer>> pacificAtlantic(int[][] h) {
    int R = h.length, C = h[0].length;
    boolean[][] pac = new boolean[R][C], atl = new boolean[R][C];
    for (int r = 0; r < R; r++) { flow(h, pac, r, 0); flow(h, atl, r, C - 1); }   // left/right edges
    for (int c = 0; c < C; c++) { flow(h, pac, 0, c); flow(h, atl, R - 1, c); }   // top/bottom edges
    List<List<Integer>> res = new ArrayList<>();
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++)
            if (pac[r][c] && atl[r][c]) res.add(List.of(r, c)); // reachable by BOTH
    return res;
}
void flow(int[][] h, boolean[][] seen, int r, int c) {
    seen[r][c] = true;
    int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
    for (int[] d : dirs) {
        int nr = r + d[0], nc = c + d[1];
        if (nr >= 0 && nr < h.length && nc >= 0 && nc < h[0].length
                && !seen[nr][nc] && h[nr][nc] >= h[r][c]) // flow uphill: only step to >= height
            flow(h, seen, nr, nc);
    }
}

Time O(R·C) — each cell entered at most once per ocean. Space O(R·C) for the two boolean grids + recursion.

Case: Surrounded Regions — DFS from the border to mark survivors (LC 130)

Same border-seed inversion. An 'O' region survives only if it touches the edge. So DFS from every border 'O', temporarily marking the connected survivors; then in one sweep flip the rest to 'X' and restore the survivors. 

void solve(char[][] board) {
    int R = board.length, C = board[0].length;
    for (int r = 0; r < R; r++) { guard(board, r, 0); guard(board, r, C - 1); }
    for (int c = 0; c < C; c++) { guard(board, 0, c); guard(board, R - 1, c); }
    for (int r = 0; r < R; r++)
        for (int c = 0; c < C; c++) {
            if (board[r][c] == 'O') board[r][c] = 'X'; // not reached from border → captured
            else if (board[r][c] == 'S') board[r][c] = 'O'; // survivor → restore
        }
}
void guard(char[][] board, int r, int c) {
    if (r < 0 || r >= board.length || c < 0 || c >= board[0].length || board[r][c] != 'O')
        return;
    board[r][c] = 'S';               // mark border-connected 'O' as a survivor
    guard(board, r + 1, c); guard(board, r - 1, c);
    guard(board, r, c + 1); guard(board, r, c - 1);
}

Time O(R·C). Space O(R·C) recursion worst case.

4 · Edge-case checklist

  • Deep / chain-shaped graph → StackOverflow. A 10⁵-node path overflows recursion. Use the explicit-stack DFS when V is large and the shape can be linear.
  • Undirected cycle: parent-skip with parallel edges. nei != parent wrongly ignores a real 2-cycle formed by a duplicate edge. Skip one edge by count, or use Union-Find.
  • Directed cycle needs onStack, not just visited. Re-reaching a finished (black) node is fine; re-reaching a node still on the path (gray) is the cycle. Plain visited can't tell them apart.
  • All-paths: restore the path on exit. Forgetting path.remove(size-1) leaks earlier choices into sibling branches. And store a copy in the result — the path keeps mutating.
  • Disconnected graph. One DFS reaches one component. Loop over every node and launch from each unvisited one, or you miss whole components (and cycles in them).
  • Clone Graph: register before recursing. Put the new node in the map the moment you create it, or cycles recurse forever.
  • Grid in-place marking. Mutating the grid as your visited set is fine when allowed; if the grid must be preserved, restore it or use a separate boolean[][].
