Weighted Shortest Paths (Dijkstra & friends)

BFS only finds shortest paths when every edge costs 1. Add weights and you need a greedy min-heap (Dijkstra) — or a different tool when weights can be 0/1 or negative.

Mission link: Weighted shortest path is a top Google-interview graph theme (Network Delay, Cheapest Flights). This is Lesson 7 of the 9-lesson graph track. Mission
Prerequisite — the Java you'll lean on Dijkstra lives or dies on PriorityQueue<int[]> with the right comparator, and the heap comparator direction is the classic bug. If that's fuzzy, do Java 03: PriorityQueue & Comparators first.

1 · The one idea

On an unweighted graph, BFS works because every edge advances distance by exactly 1, so the frontier is naturally sorted by distance. The moment edges carry different costs, that guarantee breaks: the fewest-edges path is no longer the cheapest path. You now need an algorithm that always expands the cheapest-known node next. That algorithm is Dijkstra — BFS with a min-heap replacing the plain queue. Two special cases get cheaper or stronger tools: edges of weight 0 or 1 → 0-1 BFS (a deque), and negative edges → Bellman-Ford (which Dijkstra cannot handle and which also detects negative cycles). Need all pairs at once → Floyd-Warshall.

Recognition trigger "Minimum cost / cheapest / shortest time / least effort" where moves carry different weights. If the problem says "fewest steps/edges," that's plain BFS (Lesson 03). If it says "cheapest" with non-negative weights, Dijkstra fires. Negative weights or "detect a negative cycle" → Bellman-Ford.

3 · Core template — Dijkstra

Carry a dist[] array (best cost known to each node, all Integer.MAX_VALUE at first) and a min-heap of {node, distSoFar} ordered by distSoFar. Pop the cheapest node, relax its edges, push improved neighbors. The one subtlety that trips everyone is lazy deletion: Java's PriorityQueue can't update a key in place, so we leave stale entries in the heap and skip them on pop. 

// adjacency: adj.get(u) = list of {neighbor, weight}
int dijkstra(int n, List<List<int[]>> adj, int src, int dst) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    // min-heap ordered by distance-so-far (a[1]). WRONG direction = the classic bug.
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{src, 0});       // {node, dist}
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int u = top[0], d = top[1];
        if (d > dist[u]) continue;     // LAZY DELETION — stale entry, already improved
        if (u == dst) return d;        // first pop of a node IS its final distance
        for (int[] e : adj.get(u)) {
            int v = e[0], w = e[1];
            if (dist[u] + w < dist[v]) {
                dist[v] = dist[u] + w; // relax
                pq.offer(new int[]{v, dist[v]}); // push the improved entry
            }
        }
    }
    return -1;                          // dst unreachable
}

Time O(E log V) — each edge can push one heap entry, each pop/push is O(log V). Space O(V + E) for the adjacency list, dist[], and up to O(E) heap entries.

Worked example — dry run

Input: source 0, undirected weighted edges (0,1,4) (0,2,1) (2,1,2) (2,3,5) (1,3,1) (3,4,3). The highlighted edges form the shortest-path tree:

init dist = [0, ∞, ∞, ∞, ∞]; heap = [(0, dist 0)] pop 0 (d=0) → relax: dist[1]=4, dist[2]=1 pop 2 (d=1) → relax: dist[1]=min(4, 1+2)=3, dist[3]=6 pop 1 (d=3) → relax: dist[3]=min(6, 3+1)=4 pop stale (1, d=4) → 4 > dist[1]=3 → skip (lazy deletion) pop 3 (d=4) → relax: dist[4]=7 pop 4 (d=7) → no improvement; heap drains → done final dist = {0:0, 2:1, 1:3, 3:4, 4:7}
Why the if (d > dist[u]) continue; line matters We never decrease-key; we just push a fresh, cheaper entry and let the old one rot in the heap. When the stale (larger) entry finally pops, d exceeds the already-finalized dist[u], so we skip it. Without this guard you'd re-relax from outdated distances — slower, and a magnet for subtle bugs. The first time a node is popped without being skipped, its distance is final (greedy invariant) — that's why Dijkstra can early-return at dst.
Negative edges break Dijkstra — silently Dijkstra's correctness rests on "once popped, a node's distance never improves." A negative edge can make a later, cheaper path to an already-finalized node — but Dijkstra has moved on and will never revisit it, so it returns a wrong answer with no error. Negative weights ⇒ Bellman-Ford, full stop.

Case: Unweighted BFS (refresher) — the baseline, no heap

When every edge costs the same (weight 1), you don't need a heap at all — a plain queue visits nodes in distance order for free. This is the Lesson 03 pattern; it lives here only as the contrast that makes Dijkstra necessary. The rule: the first time you reach a node is its shortest distance, so you visit each node once and never relax. 

int bfsShortest(List<List<Integer>> adj, int src, int dst) {
    int[] dist = new int[adj.size()];
    Arrays.fill(dist, -1);              // -1 = unvisited (doubles as the visited flag)
    dist[src] = 0;
    Queue<Integer> q = new ArrayDeque<>();
    q.offer(src);
    while (!q.isEmpty()) {
        int u = q.poll();
        if (u == dst) return dist[u];   // first arrival = shortest (uniform cost)
        for (int v : adj.get(u)) {
            if (dist[v] == -1) {        // visit once — no min-heap, no relaxation
                dist[v] = dist[u] + 1;
                q.offer(v);
            }
        }
    }
    return -1;                          // dst unreachable
}

Time O(V + E). Space O(V). Multi-source variant: seed the queue with all starting cells at distance 0 and let the wavefronts expand together.

Case: Network Delay Time (LC 743) — Dijkstra to all nodes ★

"How long until every node gets the signal?" = run Dijkstra from the source, then the answer is the largest finalized distance (the last node to hear it). If any node stays MAX_VALUE, it's unreachable → return -1. 

int networkDelayTime(int[][] times, int n, int k) {
    List<List<int[]>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>()); // nodes are 1..n
    for (int[] t : times) adj.get(t[0]).add(new int[]{t[1], t[2]}); // {to, weight}, DIRECTED

    int[] dist = new int[n + 1];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[k] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]);
    pq.offer(new int[]{k, 0});
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int u = top[0], d = top[1];
        if (d > dist[u]) continue;
        for (int[] e : adj.get(u)) {
            if (d + e[1] < dist[e[0]]) {
                dist[e[0]] = d + e[1];
                pq.offer(new int[]{e[0], dist[e[0]]});
            }
        }
    }
    int ans = 0;
    for (int i = 1; i <= n; i++) {
        if (dist[i] == Integer.MAX_VALUE) return -1; // someone never hears it
        ans = Math.max(ans, dist[i]);
    }
    return ans;
}

Time O(E log V). Space O(V + E).

Case: Path With Minimum Effort (LC 1631) — minimize the MAX edge

Here "effort" is the largest height difference along the path, not the sum. Dijkstra still works — just change the relaxation: a candidate path's cost is max(costToHere, edgeWeight). This is a "minimax path," and the heap stays ordered by that running max. 

int minimumEffortPath(int[][] heights) {
    int R = heights.length, C = heights[0].length;
    int[][] effort = new int[R][C];
    for (int[] row : effort) Arrays.fill(row, Integer.MAX_VALUE);
    effort[0][0] = 0;
    int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[2] - b[2]); // {r, c, effort}
    pq.offer(new int[]{0, 0, 0});
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int r = top[0], c = top[1], e = top[2];
        if (e > effort[r][c]) continue;            // stale entry
        if (r == R - 1 && c == C - 1) return e;     // first pop of target = answer
        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nr >= R || nc < 0 || nc >= C) continue;
            int diff = Math.abs(heights[nr][nc] - heights[r][c]);
            int ne = Math.max(e, diff);             // minimax: cost = worst edge so far
            if (ne < effort[nr][nc]) {
                effort[nr][nc] = ne;
                pq.offer(new int[]{nr, nc, ne});
            }
        }
    }
    return 0;
}

Time O(R·C·log(R·C)). Space O(R·C). LC 778 (Swim in Rising Water) is the same minimax pattern — cost is max(time, grid[nr][nc]) instead of a height diff.

Case: Swim in Rising Water (LC 778) — minimax on a grid

int swimInWater(int[][] grid) {
    int n = grid.length;
    boolean[][] done = new boolean[n][n];
    int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[2] - b[2]); // {r, c, time}
    pq.offer(new int[]{0, 0, grid[0][0]});
    while (!pq.isEmpty()) {
        int[] top = pq.poll();
        int r = top[0], c = top[1], t = top[2];
        if (done[r][c]) continue;                   // finalized = lowest time wins
        done[r][c] = true;
        if (r == n - 1 && c == n - 1) return t;     // earliest time to reach corner
        for (int[] d : dirs) {
            int nr = r + d[0], nc = c + d[1];
            if (nr < 0 || nr >= n || nc < 0 || nc >= n || done[nr][nc]) continue;
            pq.offer(new int[]{nr, nc, Math.max(t, grid[nr][nc])});
        }
    }
    return -1;
}

Time O(n²·log n). Space O(n²). (Here a boolean done[][] replaces the dist array — once a cell pops it's final, so we skip repeats.)

Case: Cheapest Flights Within K Stops (LC 787) — why plain Dijkstra fails ★

Why plain Dijkstra is wrong here Dijkstra finalizes each node at its globally cheapest distance and never revisits it. But the cheapest way to reach a node might use too many stops, while a pricier route uses fewer and is the only one that can extend within budget. Once Dijkstra finalizes the cheap-but-stop-heavy version, it discards the route you actually needed. The fix: the state is (node, stopsUsed), not just node — or relax exactly K+1 times à la Bellman-Ford.

The cleanest answer is Bellman-Ford bounded to K+1 edges: relax all edges K+1 times, each round using a frozen snapshot of the previous round's costs so a single round can't chain multiple flights.

int findCheapestPrice(int n, int[][] flights, int src, int dst, int k) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    for (int i = 0; i <= k; i++) {                  // at most k+1 edges = k stops
        int[] snap = dist.clone();                  // freeze: this round uses last round's costs
        for (int[] f : flights) {
            int u = f[0], v = f[1], w = f[2];
            if (snap[u] != Integer.MAX_VALUE && snap[u] + w < dist[v]) {
                dist[v] = snap[u] + w;
            }
        }
    }
    return dist[dst] == Integer.MAX_VALUE ? -1 : dist[dst];
}

Time O(K · E). Space O(V). The Dijkstra-on-state alternative pushes {node, cost, stopsUsed} and only expands while stopsUsed <= k — correct too, but the bounded Bellman-Ford is shorter and the snap clone is the part everyone forgets (without it, one round chains many hops).

Case: 0-1 BFS — deque instead of a heap

When weights are only 0 or 1, skip the log factor: push 0-weight relaxations to the front of a deque, 1-weight relaxations to the back. The deque stays sorted by distance (only two live values), giving O(V + E) — Dijkstra's invariant without the heap. 

Deque<int[]> dq = new ArrayDeque<>();   // {node, dist}
dist[src] = 0;
dq.offerFirst(new int[]{src, 0});
while (!dq.isEmpty()) {
    int[] cur = dq.pollFirst();
    int u = cur[0];
    if (cur[1] > dist[u]) continue;     // same stale-skip idea
    for (int[] e : adj.get(u)) {        // e = {neighbor, weight in {0,1}}
        int v = e[0], w = e[1];
        if (dist[u] + w < dist[v]) {
            dist[v] = dist[u] + w;
            if (w == 0) dq.offerFirst(new int[]{v, dist[v]}); // 0-edge → front
            else        dq.offerLast(new int[]{v, dist[v]});  // 1-edge → back
        }
    }
}

Time O(V + E). Space O(V).

Practice — free-tier LeetCode

  • LC 2290 · Minimum Obstacle Removal to Reach Corner (Hard) — the textbook 0-1 BFS. Stepping into an empty cell is a 0-edge (push front), into an obstacle is a 1-edge (push back). The deque keeps cells sorted by obstacles-removed; the first pop of the corner is the answer.
  • LC 1368 · Minimum Cost to Make at Least One Valid Path in a Grid (Hard) — each cell has a sign pointing one way: following the arrow costs 0, changing direction costs 1. Model those as 0/1 edges and run the same deque. Rated Hard, but the 0-1 BFS lens makes it mechanical.

Case: Bellman-Ford — negative edges & negative-cycle detection

Relax all edges V−1 times (any shortest path has at most V−1 edges). Then run one more pass: if anything still relaxes, a negative cycle is reachable and "shortest path" is undefined (you could loop forever getting cheaper). 

long[] bellmanFord(int n, int[][] edges, int src) {
    long[] dist = new long[n];
    Arrays.fill(dist, Long.MAX_VALUE);  // long: sums of weights can overflow int
    dist[src] = 0;
    for (int i = 0; i < n - 1; i++) {   // V-1 relaxation passes
        for (int[] e : edges) {
            int u = e[0], v = e[1], w = e[2];
            if (dist[u] != Long.MAX_VALUE && dist[u] + w < dist[v])
                dist[v] = dist[u] + w;
        }
    }
    for (int[] e : edges) {             // one extra pass = negative-cycle check
        int u = e[0], v = e[1], w = e[2];
        if (dist[u] != Long.MAX_VALUE && dist[u] + w < dist[v])
            throw new IllegalStateException("negative cycle reachable from src");
    }
    return dist;
}

Time O(V · E). Space O(V).

Practice — free-tier LeetCode (pure negative-edge problems are scarce on the free tier; these two are the standard Bellman-Ford drills — both appear elsewhere in this lesson, so re-solve them with the relaxation template rather than their default solution):

  • LC 787 · Cheapest Flights Within K Stops (Medium) — bounded Bellman-Ford, worked above. Relax all edges K+1 times over a frozen snap of the previous round's costs so one round can't chain multiple hops. This is the canonical free-tier Bellman-Ford problem — rebuild it from a blank file.
  • LC 743 · Network Delay Time (Medium) — shown earlier as Dijkstra, but re-solve it with vanilla Bellman-Ford: relax every edge V−1 times, then answer = max dist[] (or -1 if any stays MAX). Best drill for internalizing the relaxation loop without a heap.
All pairs in one shot — Floyd-Warshall (brief) When V is small (≲ 400) and you want every pair's shortest distance, Floyd-Warshall is three nested loops over a dist[i][j] matrix: dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]) with k as the outermost loop. Time O(V³), Space O(V²). It handles negative edges (no negative cycles) and is the go-to when the problem is really "answer many source-destination queries."

Case: Floyd-Warshall — all-pairs shortest path

When you need the shortest distance between every pair of nodes — usually because the problem fires many source→destination queries — run Floyd-Warshall once and read answers off a matrix. Seed dist[i][j] with direct edge weights (0 on the diagonal, a large INF sentinel elsewhere), then let every node k act as a possible intermediate. The loop order is the whole trick: k must be the outermost loop, or you relax through half-finished paths. 

void floydWarshall(int[][] dist, int n) {   // dist pre-seeded: edge weights, 0 on diagonal, INF else
    for (int k = 0; k < n; k++)             // intermediate node — OUTERMOST
        for (int i = 0; i < n; i++)
            for (int j = 0; j < n; j++)
                if (dist[i][k] != INF && dist[k][j] != INF   // guard: skip if either leg is unreachable (avoids INF overflow)
                        && dist[i][k] + dist[k][j] < dist[i][j])
                    dist[i][j] = dist[i][k] + dist[k][j];    // route i→j through k is cheaper
}

Time O(V³). Space O(V²). Handles negative edges (no negative cycles); a negative dist[i][i] after the run signals a negative cycle through i. Use it only when V is small (≲ 400) — beyond that O(V³) is too slow and you'd run Dijkstra once per source instead.

Practice — free-tier LeetCode

  • LC 1334 · Find the City With the Smallest Number of Neighbors at a Threshold Distance (Medium) — the canonical Floyd-Warshall problem. Build the all-pairs matrix, then for each city count how many others sit within the distance threshold and pick the best (ties → highest index). V ≤ 100, so O(V³) is comfortable.
  • LC 1462 · Course Schedule IV (Medium) — reachability, not distance: run the same triple loop over a boolean reach[i][j] (reach[i][j] |= reach[i][k] && reach[k][j]) to get the transitive closure, then answer each prerequisite query in O(1).

5 · Edge-case checklist

  • Negative edges break Dijkstra — a later cheaper path to a finalized node is never reconsidered. Use Bellman-Ford instead.
  • Stale heap entries — Java's PQ can't decrease-key; you push duplicates and if (d > dist[u]) continue; skips the outdated ones. Forgetting this guard re-relaxes from stale costs.
  • Revisiting with a smaller dist — relax only when dist[u] + w < dist[v]; a boolean visited (instead of a dist array) silently locks in the first, possibly non-optimal, arrival.
  • Overflow — adding to Integer.MAX_VALUE wraps negative. Guard with dist[u] != MAX before dist[u] + w, or use long for the running sums.
  • Disconnected / unreachable nodes — they stay MAX_VALUE; check for it before reporting an answer (LC 743 returns -1).
  • Comparator direction — (a,b) -> a[1] - b[1] is a min-heap. Reversing it makes a max-heap and quietly returns garbage.
  • Constraint in the state — "within K stops / at most T fuel" must live in the heap/DP state, or Dijkstra's greediness discards the route you need (LC 787).
