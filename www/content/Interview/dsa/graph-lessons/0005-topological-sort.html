Topological Sort

Line up the nodes of a directed acyclic graph so every dependency comes before the thing that needs it — and if you can't, you've just proven there's a cycle.

Mission link: graphs are ~25% of Google intern questions, and "ordering with prerequisites" is a favorite. This is Lesson 5 of the 9-lesson graph track. Mission

1 · The one idea

A topological order is a linear arrangement of a directed graph's nodes such that for every edge u → v, u appears before v. Think "do prerequisites first." Such an order exists if and only if the graph is a DAG (directed, acyclic). The moment a cycle exists — A needs B, B needs C, C needs A — no node can legally go first, so no order exists. That makes topological sort the cleanest directed-cycle detector you have: try to order it; if you can't place everyone, there's a cycle.

Recognition trigger "Ordering / prerequisites / build order / dependencies / schedule," or "is this a valid DAG?" Anything where X must come before Y and you must produce a sequence (or just decide whether one is possible). Edges are directed. If the question is "can you finish / is it possible," you only need the cycle check; if it's "give the order," you emit the sequence.

2 · Two cores

There are two standard ways to topologically sort. Know both — interviewers ask you to contrast them, and some problems (peeling leaves, counting levels) are natural extensions of the first.

Core A — Kahn's algorithm (BFS on indegrees)

Count how many edges point into each node (its indegree). A node with indegree 0 has no unmet prerequisites, so it can go next. Emit it, "remove" it by decrementing its neighbors' indegrees, and any neighbor that hits 0 joins the queue. If you emit fewer than n nodes, the leftovers are trapped in a cycle. 

// Kahn's algorithm: produce a topological order, or detect a cycle.
int[] kahn(int n, int[][] edges) {       // edge {u, v} means u -> v (u before v)
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[n];
    for (int[] e : edges) {
        adj.get(e[0]).add(e[1]);
        indeg[e[1]]++;                   // v gains one incoming edge
    }
    Queue<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < n; i++)
        if (indeg[i] == 0) q.offer(i);   // seed EVERY indegree-0 node (handles disconnected DAGs)
    int[] order = new int[n];
    int idx = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        order[idx++] = u;                // u has no unmet prereqs → emit it
        for (int v : adj.get(u))
            if (--indeg[v] == 0) q.offer(v); // removing u frees v
    }
    return idx == n ? order : new int[0]; // idx < n → some nodes never reached 0 → CYCLE
}

Time O(V + E) — each node enqueued once, each edge relaxed once. Space O(V + E) for the adjacency list, indegree array, and queue.

Worked example — dry run

Course Schedule II (LC 210) via Kahn's. Input: numCourses = 4, directed edges 0→1, 0→2, 1→3, 2→3 (take 0 before 1 and 2; take 1 and 2 before 3). Count indegrees, seed the queue with every indegree-0 node, then pop-emit-decrement until the queue drains:

indegree = [0, 1, 1, 2] — 1←0, 2←0, 3←1&2 seed queue with indegree-0 nodes → q = [0]; output = [] pop 0 → output [0]; indeg 1: 1→0, indeg 2: 1→0 → enqueue both → q = [1, 2] pop 1 → output [0, 1]; indeg 3: 2→1 (not 0 yet) → q = [2] pop 2 → output [0, 1, 2]; indeg 3: 1→0 → enqueue 3 → q = [3] pop 3 → output [0, 1, 2, 3]; no out-edges → q = [] emitted 4 = numCourses → valid order [0, 1, 2, 3]
Why Kahn's is usually the interview pick It's iterative (no recursion-depth worry on 10⁵-node chains), the cycle check falls out for free (idx < n), and the level structure (process the queue one frontier at a time) directly answers "how many semesters / rounds?" — see Parallel Courses below.

Core B — DFS post-order + reverse (with a 3-color cycle guard)

DFS naturally finishes a node only after all its descendants are done. So a node's post-order finish time is later than everything it points to — reverse the post-order and you get a topological order. To catch cycles, color nodes: white (unvisited), gray (on the current recursion stack), black (fully done). Hitting a gray node means a back-edge → a cycle. 

// 0 = white (unseen), 1 = gray (in progress), 2 = black (done)
int[] color;
List<List<Integer>> adj;
Deque<Integer> stack;        // collects post-order; we pop it to reverse
boolean hasCycle;

int[] topoDFS(int n, int[][] edges) {
    adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
    for (int[] e : edges) adj.get(e[0]).add(e[1]);
    color = new int[n];
    stack = new ArrayDeque<>();
    hasCycle = false;
    for (int i = 0; i < n; i++)
        if (color[i] == 0) dfs(i);   // launch from every component
    if (hasCycle) return new int[0];
    int[] order = new int[n];
    for (int i = 0; i < n; i++) order[i] = stack.pop(); // reverse post-order
    return order;
}
void dfs(int u) {
    color[u] = 1;                // mark gray: now on the stack
    for (int v : adj.get(u)) {
        if (color[v] == 1) { hasCycle = true; return; } // back-edge to a gray node = cycle
        if (color[v] == 0) dfs(v);
    }
    color[u] = 2;                // done → black
    stack.push(u);               // record finish order
}

Time O(V + E). Space O(V + E), plus O(V) recursion stack — the one caveat versus Kahn's on very deep graphs.

A boolean visited is NOT enough for directed cycle detection With two colors you can't tell "already finished (black, fine)" from "currently on my stack (gray, cycle)." A black node reached again is a harmless cross/forward edge; a gray one is a back-edge. Use three colors (or a separate onStack set) — this is the classic bug that flags a valid DAG as cyclic.

Case: Course Schedule — can you finish? (LC 207) ★Google favorite

boolean canFinish(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[numCourses];
    for (int[] p : prerequisites) {      // p = {course, prereq} → prereq -> course
        adj.get(p[1]).add(p[0]);
        indeg[p[0]]++;
    }
    Queue<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++)
        if (indeg[i] == 0) q.offer(i);
    int done = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        done++;
        for (int v : adj.get(u))
            if (--indeg[v] == 0) q.offer(v);
    }
    return done == numCourses;           // all taken ⇒ no cycle ⇒ finishable
}

Case: Course Schedule II — return the order (LC 210)

Identical to Kahn's core: capture the emit sequence, return empty on a cycle.

int[] findOrder(int numCourses, int[][] prerequisites) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < numCourses; i++) adj.add(new ArrayList<>());
    int[] indeg = new int[numCourses];
    for (int[] p : prerequisites) { adj.get(p[1]).add(p[0]); indeg[p[0]]++; }
    Queue<Integer> q = new ArrayDeque<>();
    for (int i = 0; i < numCourses; i++) if (indeg[i] == 0) q.offer(i);
    int[] order = new int[numCourses];
    int idx = 0;
    while (!q.isEmpty()) {
        int u = q.poll();
        order[idx++] = u;
        for (int v : adj.get(u)) if (--indeg[v] == 0) q.offer(v);
    }
    return idx == numCourses ? order : new int[0]; // cycle ⇒ empty
}

Case: Alien Dictionary — BUILD the graph, then topo (LC 269) ★Google favorite

You're given words sorted in an alien language's lexicographic order. The order between two letters is revealed only by the first differing character of each adjacent word pair: in "wrt" then "wrf", the first difference is t vs f, so t → f. Collect those edges, then topo-sort the letters. 

String alienOrder(String[] words) {
    Map<Character, Set<Character>> adj = new HashMap<>();
    Map<Character, Integer> indeg = new HashMap<>();
    for (String w : words)               // every letter is a node, even with no edges
        for (char c : w.toCharArray()) {
            adj.putIfAbsent(c, new HashSet<>());
            indeg.putIfAbsent(c, 0);
        }
    for (int i = 0; i + 1 < words.length; i++) {
        String a = words[i], b = words[i + 1];
        int min = Math.min(a.length(), b.length());
        // TRAP: "abc" before "ab" is impossible — a longer word can't precede its own prefix
        if (a.length() > b.length() && a.startsWith(b)) return "";
        for (int j = 0; j < min; j++) {
            char x = a.charAt(j), y = b.charAt(j);
            if (x != y) {                // FIRST difference is the only signal
                if (adj.get(x).add(y)) indeg.merge(y, 1, Integer::sum); // dedup: bump indegree only on a NEW edge
                break;                   // stop at the first difference
            }
        }
    }
    Queue<Character> q = new ArrayDeque<>();
    for (char c : indeg.keySet()) if (indeg.get(c) == 0) q.offer(c);
    StringBuilder sb = new StringBuilder();
    while (!q.isEmpty()) {
        char u = q.poll();
        sb.append(u);
        for (char v : adj.get(u))
            if (indeg.merge(v, -1, Integer::sum) == 0) q.offer(v);
    }
    return sb.length() == indeg.size() ? sb.toString() : ""; // leftover ⇒ cycle ⇒ no valid order
}
The two Alien-Dictionary traps (1) Invalid prefix: if word a is longer than the next word b and a starts with b (e.g. "abc" before "ab"), no ordering of letters can fix it — return "" immediately. (2) Only the first differing char gives an edge — break after recording it; later characters tell you nothing.

Case: Minimum Height Trees — peel leaves (LC 310)

A topological-style peeling: the roots that minimize tree height are the graph's center(s). Trim all degree-1 leaves simultaneously, then the new leaves, and so on. Whatever survives (1 or 2 nodes) is the answer. This is Kahn's idea on an undirected graph with degree instead of indegree. 

List<Integer> findMinHeightTrees(int n, int[][] edges) {
    if (n == 1) return List.of(0);
    List<Set<Integer>> adj = new ArrayList<>();
    for (int i = 0; i < n; i++) adj.add(new HashSet<>());
    for (int[] e : edges) { adj.get(e[0]).add(e[1]); adj.get(e[1]).add(e[0]); }
    Queue<Integer> leaves = new ArrayDeque<>();
    for (int i = 0; i < n; i++) if (adj.get(i).size() == 1) leaves.offer(i);
    int remaining = n;
    while (remaining > 2) {               // stop at the 1 or 2 central nodes
        int sz = leaves.size();
        remaining -= sz;
        for (int i = 0; i < sz; i++) {   // peel one whole layer
            int leaf = leaves.poll();
            int nei = adj.get(leaf).iterator().next();
            adj.get(nei).remove(leaf);
            if (adj.get(nei).size() == 1) leaves.offer(nei);
        }
    }
    return new ArrayList<>(leaves);       // the surviving center(s)
}

Case: Parallel Courses — count levels = min semesters (LC 1136)

Same Kahn's machinery, but you process the queue one frontier at a time: each frontier is a set of courses with all prereqs met, taken together in one semester. The number of frontiers is the minimum number of semesters; if a cycle blocks some course, return -1. 

int minimumSemesters(int n, int[][] relations) {
    List<List<Integer>> adj = new ArrayList<>();
    for (int i = 0; i <= n; i++) adj.add(new ArrayList<>());  // courses are 1..n → size n+1
    int[] indeg = new int[n + 1];
    for (int[] r : relations) { adj.get(r[0]).add(r[1]); indeg[r[1]]++; }
    Queue<Integer> q = new ArrayDeque<>();
    for (int i = 1; i <= n; i++) if (indeg[i] == 0) q.offer(i);
    int semesters = 0, taken = 0;
    while (!q.isEmpty()) {
        int sz = q.size();               // one full layer = one semester
        semesters++;
        for (int i = 0; i < sz; i++) {
            int u = q.poll();
            taken++;
            for (int v : adj.get(u))
                if (--indeg[v] == 0) q.offer(v);
        }
    }
    return taken == n ? semesters : -1;  // cycle ⇒ -1
}

4 · Edge-case checklist

  • Cycle ⇒ empty/impossible result. Always compare emitted count to n (Kahn's) or check the gray-node guard (DFS). Decide what "impossible" returns: false, new int[0], "", or -1.
  • Build the implicit graph correctly. Most failures here are in graph construction, not the sort. For Alien Dictionary, edges come only from the first differing char of adjacent words — and the longer-prefix case ("abc" before "ab") is an immediate "".
  • Duplicate edges inflate indegree. If the same edge can appear twice, a node's indegree never drops to 0 and you falsely report a cycle. Dedup with a Set per node, and bump indegree only when the edge is genuinely new.
  • Disconnected DAG. Seed every indegree-0 node before the loop, not just node 0 — separate components each need a starting point.
  • Edge direction. Pin down which way the edge points. "prereq → course" vs "course → prereq" flips your whole indegree array. In LC 207/210 the input is {course, prereq}, so the edge is prereq → course.
  • 1-indexed nodes (LC 1136 courses are 1..n) → size arrays n+1 and iterate from 1.
  • Recursion depth (DFS variant). A 10⁵-node chain can StackOverflow — prefer Kahn's, or convert to an explicit stack.
