Union-Find (Disjoint Set Union)

One parent[] array answers "are these two in the same group?" and "merge their groups" in near-constant time — the right tool the moment edges arrive one at a time.

Mission link: graphs are ~25% of Google intern questions. Recognize a dynamic-connectivity problem in < 60s and code a path-compressed, union-by-size DSU in Java from memory. This is Lesson 6 of the 9-lesson graph track. Mission

1 · The one idea

A Disjoint Set Union tracks a partition of n elements into groups. Each element points at a parent; follow parents up to the root, which names the group. find(x) returns x's root; union(a, b) hangs one root under the other. Two optimizations make it fly: path compression (flatten the tree while you find) and union by rank/size (always attach the smaller tree under the larger). Together they drive each operation to near-O(α(n)) ≈ O(1) amortized.

Why a whole graph lesson for it? DFS/BFS (Lessons 02–03) count components beautifully — once the graph is fully built. DSU shines when connectivity is dynamic / online: edges stream in and you must answer "connected?" after each one, or you need to detect the first edge that closes a cycle. That's a different superpower from traversal.

Recognition trigger "Connected / groups / provinces / components", dynamic (online) connectivity (edges added one at a time), detecting a cycle in an undirected graph, "accounts merge / equations", or building a Kruskal MST (Lesson 08). If the question is "do these edges fuse everything into one blob, and when?" — DSU fires.
DSU vs DFS/BFS — pick fast Static graph, "count the islands once" → DFS/BFS is fine (and gives you the actual paths). Edges streaming in, "are u and v connected now?", or "which edge first creates a cycle?" → DSU, because re-running DFS after every edge is O(V+E) per query.

2 · Core template

Memorize this class. We use union by size here (init all 1): it keeps trees flat and hands you each component's element count for free via size[find(x)].

class DSU {
    int[] parent, size;
    int count;                       // number of disjoint sets (components)

    DSU(int n) {
        parent = new int[n];
        size   = new int[n];
        count  = n;
        for (int i = 0; i < n; i++) { parent[i] = i; size[i] = 1; }  // each its own root
    }

    int find(int x) {                // iterative, with path compression
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];  // path halving: point x at its grandparent
            x = parent[x];
        }
        return x;
    }

    boolean union(int a, int b) {    // union by size; false if already same set
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;  // already joined → this edge would close a CYCLE
        if (size[ra] < size[rb]) { int t = ra; ra = rb; rb = t; }  // ra is the bigger tree
        parent[rb] = ra;             // smaller hangs under bigger
        size[ra] += size[rb];
        count--;                     // two sets became one
        return true;
    }
}

Time O(α(n)) amortized per find/union — α is the inverse Ackermann function, ≤ 4 for any n in this universe, so effectively O(1). Building is O(n); processing m operations is O(n + m·α(n)) ≈ O(n + m). Space O(n) for the two arrays.

Worked example — dry run

Input: n = 5, operations union(0,1), union(2,3), union(1,2). Watch the parent[] array evolve, then read off the resulting DSU forest:

start: parent=[0,1,2,3,4] — every element its own root union(0,1): find(0)=0, find(1)=1; hang 1 under 0 → parent=[0,0,2,3,4] union(2,3): find(2)=2, find(3)=3; hang 3 under 2 → parent=[0,0,2,2,4] union(1,2): find(1)=0, find(2)=2; hang 2's root under 0 → parent=[0,0,0,2,4] find(3): 3→2→0, PATH COMPRESSION points 3 straight at 0 → parent=[0,0,0,0,4] roots: find(0)=find(1)=find(2)=find(3)=0, find(4)=4 → components = 2: {0,1,2,3}, {4}
Recursive find (path compression, fully flat) If you prefer recursion, find becomes a two-liner that flattens completely (every node points straight at the root): 
int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]); // compress on the way back up
    return parent[x];
}
Same α(n) bound. Prefer the iterative version for very deep chains (10⁶ nodes) to avoid a recursion-stack overflow — the recursion mirrors a degenerate tree's depth.
The #1 bug Comparing or merging the raw elements instead of their roots. Always union(a,b) through find(a)/find(b), and to test "connected" use find(a) == find(b) — never parent[a] == parent[b] (a deep tree breaks that instantly).

3 · All the cases (this is why the pattern matters)

Case: number of provinces — adjacency matrix (LC 547)

int findCircleNum(int[][] isConnected) {
    int n = isConnected.length;
    DSU dsu = new DSU(n);
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++)        // upper triangle: matrix is symmetric
            if (isConnected[i][j] == 1) dsu.union(i, j);
    return dsu.count;                           // disjoint sets = provinces
}

Case: number of connected components — edge list (LC 323)

int countComponents(int n, int[][] edges) {
    DSU dsu = new DSU(n);
    for (int[] e : edges) dsu.union(e[0], e[1]); // one pass over the edges
    return dsu.count;                            // no adjacency list, no visited array, no DFS
}
Contrast with Lesson 01 The DFS version built an adjacency list, a visited[] array, and looped launches. DSU does the same job in four lines — and unlike DFS it answers connectivity incrementally as each edge arrives.

Case: redundant connection — the first cycle edge (LC 684) ★Google favorite

int[] findRedundantConnection(int[][] edges) {
    DSU dsu = new DSU(edges.length + 1);        // nodes labelled 1..n → size n+1, ignore index 0
    for (int[] e : edges)
        if (!dsu.union(e[0], e[1])) return e;    // both ends already joined → this edge closes the cycle
    return new int[0];
}
Why DSU is the natural fit The graph starts as a tree plus one extra edge. Process edges in order; the first union that returns false is the one that, when removed, leaves a tree. DFS could find a cycle too, but DSU answers it in a single streaming pass — exactly the dynamic-connectivity sweet spot.

Case: graph valid tree (LC 261)

boolean validTree(int n, int[][] edges) {
    if (edges.length != n - 1) return false;     // a tree on n nodes has EXACTLY n-1 edges
    DSU dsu = new DSU(n);
    for (int[] e : edges)
        if (!dsu.union(e[0], e[1])) return false; // a repeated union ⇒ a cycle ⇒ not a tree
    return true;                                  // n-1 edges + acyclic ⇒ connected ⇒ tree
}

Why the edge count alone closes it: with exactly n-1 edges, "no cycle" mathematically forces "connected" (and vice-versa). So once you've checked n-1 edges and no union failed, you're done — no separate count == 1 check needed. (You could instead skip the edge-count check and assert dsu.count == 1 at the end; either works, not both.)

Case: accounts merge — strings need an index map (LC 721) ★Google favorite

List<List<String>> accountsMerge(List<List<String>> accounts) {
    Map<String, Integer> id = new HashMap<>();    // email → dsu index
    Map<String, String> owner = new HashMap<>();  // email → person name
    int n = 0;
    for (List<String> acc : accounts)
        for (int i = 1; i < acc.size(); i++) {    // acc.get(0) is the name; emails follow
            String email = acc.get(i);
            if (!id.containsKey(email)) id.put(email, n++);
            owner.put(email, acc.get(0));
        }
    DSU dsu = new DSU(n);
    for (List<String> acc : accounts)
        for (int i = 2; i < acc.size(); i++)      // union every email to the first email in its account
            dsu.union(id.get(acc.get(1)), id.get(acc.get(i)));

    Map<Integer, TreeSet<String>> groups = new HashMap<>();
    for (String email : id.keySet())              // bucket emails by their root
        groups.computeIfAbsent(dsu.find(id.get(email)), k -> new TreeSet<>()).add(email);

    List<List<String>> res = new ArrayList<>();
    for (TreeSet<String> emails : groups.values()) {
        List<String> row = new ArrayList<>(emails);   // TreeSet ⇒ already sorted
        row.add(0, owner.get(emails.first()));    // prepend the owner's name
        res.add(row);
    }
    return res;
}
The reusable trick — DSU only speaks integers When elements are strings, emails, or grid coordinates, build a Map<Thing,Integer> first, union on the ids, then group the originals by find(id). This map-to-index move recurs in nearly every real-world DSU problem (and is exactly why interviewers love LC 721 — it tests whether you can bridge messy input to a clean integer DSU).

Case: satisfiability of equality equations (LC 990) ★Google favorite

Two passes: union everything the == equations force together, then check that no != equation contradicts a merge.

boolean equationsPossible(String[] equations) {
    DSU dsu = new DSU(26);                        // variables are single lowercase letters a..z
    for (String eq : equations)
        if (eq.charAt(1) == '=')                  // pattern is "a==b" → chars 0 and 3
            dsu.union(eq.charAt(0) - 'a', eq.charAt(3) - 'a');
    for (String eq : equations)
        if (eq.charAt(1) == '!'                    // "a!=b" but they're already in one set → impossible
            && dsu.find(eq.charAt(0) - 'a') == dsu.find(eq.charAt(3) - 'a'))
            return false;
    return true;
}
Order matters: union first, check second All == constraints must be applied before any != is tested — otherwise a later equality could retroactively contradict an inequality you already passed. "Merge all the musts, then verify the must-nots" is a general DSU shape.

Case: number of islands II — online connectivity (LC 305, sketch)

The canonical dynamic problem: land appears one cell at a time, and after each addition you report the island count. Map each cell (r,c) to id r*cols + c, treat a new land cell as a fresh component (count++), then union it with any already-land 4-neighbour. 

List<Integer> numIslands2(int m, int n, int[][] positions) {
    DSU dsu = new DSU(m * n);
    boolean[] land = new boolean[m * n];
    int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};
    int islands = 0;
    List<Integer> res = new ArrayList<>();
    for (int[] p : positions) {
        int id = p[0] * n + p[1];
        if (land[id]) { res.add(islands); continue; }  // repeated add → no change
        land[id] = true; islands++;                    // new cell starts as its own island
        for (int[] d : dirs) {
            int nr = p[0] + d[0], nc = p[1] + d[1];
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            int nid = nr * n + nc;
            if (land[nid] && dsu.union(id, nid)) islands--; // merged two islands into one
        }
        res.add(islands);
    }
    return res;
}

Re-running BFS/DFS after every insertion would be O(k·V); DSU answers each insertion in amortized O(α(n)). This is the one case where DSU is not just convenient but strictly the right complexity — and it's why "online / streaming connectivity" is the loudest DSU signal. Kruskal's MST (Lesson 08) leans on the very same union-returns-true test to add only cycle-free edges.

4 · Edge-case checklist

  • Forgetting path compression → a degenerate chain makes find O(n) and the whole solution O(n·m); you'll TLE on big inputs. Keep the parent[x] = parent[parent[x]] line. ✓
  • Skipping union by size/rank → trees grow tall and find degrades; union by size keeps them flat. Use both optimizations together for the α(n) bound.
  • The "already connected" check IS cycle detection → union returning false (i.e. find(a)==find(b) before merging) means this edge closes a cycle. Don't decrement count in that case. ✓
  • 1-indexed vs 0-indexed sizing → LC 684/261-style problems label nodes 1..n; size arrays at n+1 and ignore index 0, or you'll throw ArrayIndexOutOfBounds. ✓
  • Comparing parent[a]==parent[b] instead of roots → correct only on a flat tree; once trees get deep it silently lies. Always compare find(a)==find(b).
  • Self-loop / duplicate edge → harmlessly handled by the early return false (already same root). ✓
  • DSU is union-only → no efficient split/delete. If edges get removed, process events in reverse time (deletions become additions) or reach for a different structure.
