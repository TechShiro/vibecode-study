Mission link: Largest Rectangle in Histogram is a canonical big-tech hard; Trapping Rain Water is arguably the single most-asked hard on LeetCode. Solving either cleanly in 20 minutes is a strong hire signal. This is Lesson 2 of the 2-lesson monotonic-stack track. Mission

1 · The one idea

Lesson 1 asked "where is my nearest greater/smaller neighbor?" This lesson asks the follow-up that makes problems hard: "how far can I extend before someone stops me?" A bar in a histogram extends left and right until a shorter bar blocks it; an element is the minimum of every subarray that doesn't contain a smaller element. Both boundaries are exactly previous smaller and next smaller — one increasing-stack pass computes them, and the pop moment is when an element learns both of its walls at once.

Recognition trigger "Largest rectangle / maximal area under bars", "water trapped between walls", "sum of minimums/maximums over all subarrays", "remove digits/characters to make the smallest result". General tell: each element's contribution is decided by its nearest smaller (or greater) element on each side — that phrase means one monotonic-stack pass, O(n).

2 · Core: Largest Rectangle in Histogram (LC 84) — fully worked

Naive: for each bar, walk left and right while bars stay ≥ it, area = height × width → O(n²). The stack version: sweep with an increasing stack of indices. While the incoming bar is shorter than the top, the top gets popped — and at that instant it knows everything: the incoming bar i is its first shorter bar on the right, and the element now exposed beneath it on the stack is its first shorter bar on the left. Its rectangle spans strictly between them. 

int largestRectangleArea(int[] h) {
    int n = h.length, best = 0;
    Deque<Integer> st = new ArrayDeque<>();     // indices; heights increasing bottom→top
    for (int i = 0; i <= n; i++) {              // i == n is a virtual 0-height SENTINEL bar…
        int cur = (i == n) ? 0 : h[i];          // …that flushes every bar left on the stack
        while (!st.isEmpty() && cur < h[st.peek()]) {
            int mid = st.pop();                 // bar 'mid' now knows both walls:
            int height = h[mid];                //   right wall = i (first shorter on the right)
            int left = st.isEmpty() ? -1 : st.peek(); //   left wall = new top (first shorter on the left)
            int width = i - left - 1;           // strictly between the walls
            best = Math.max(best, height * width);
        }
        st.push(i);
    }
    return best;
}

Time O(n) — push/pop once each, sentinel included. Space O(n).

h = [2, 1, 5, 6, 2, 3]   (stack shown as heights) i=0 (2): push. st=[2] i=1 (1): 1<2 → pop 2: left wall −1, width 1−(−1)−1=1, area 2. push. st=[1] i=2 (5): push. st=[1,5]   i=3 (6): push. st=[1,5,6] i=4 (2): pop 6: width 4−2−1=1, area 6 · pop 5: width 4−1−1=2, area 10. push. st=[1,2] i=5 (3): push. st=[1,2,3] i=6 (sentinel 0): pop 3 (w=1, a=3), pop 2 (w=4, a=8), pop 1 (w=6, a=6) best = 10 ✓ — every bar was measured exactly once, at its pop
The sentinel and the width formula Appending a virtual height-0 bar means you never write a second "drain the stack" loop — bar n is shorter than everything, so it flushes all survivors. And width = i − st.peek() − 1 (with −1 for an empty stack) is worth memorizing: it says "strictly between my two shorter walls". Deriving it live under pressure is where people burn 10 minutes.

Case: Trapping Rain Water — stack variant (LC 42)

Sweep with a decreasing stack of indices (walls waiting for a taller right wall). When a taller bar arrives, pop the valley floor: the popped bar is the bottom, the new stack top is the left wall, the incoming bar the right wall. Water fills a horizontal slab: width between the walls × (shorter wall − floor). Note the shape difference from LC 84: histogram accumulates vertically per bar at pop; rain water accumulates horizontal layers per pop. 

int trap(int[] h) {
    Deque<Integer> st = new ArrayDeque<>();     // indices; heights decreasing bottom→top
    int water = 0;
    for (int i = 0; i < h.length; i++) {
        while (!st.isEmpty() && h[i] > h[st.peek()]) {
            int floor = st.pop();               // valley bottom between two taller walls
            if (st.isEmpty()) break;            // no left wall → this dip can't hold water
            int left = st.peek();
            int width = i - left - 1;           // strictly between the walls
            int depth = Math.min(h[left], h[i]) - h[floor]; // water rises to the SHORTER wall
            water += width * depth;             // one horizontal slab of water
        }
        st.push(i);
    }
    return water;
}

Time O(n), Space O(n). (LC 42 also has a two-pointer O(1)-space solution — the Two Pointers track covers it; mention both in an interview.)

Case: Sum of Subarray Minimums (LC 907) — contribution counting

Naive: enumerate all O(n²) subarrays. Flip the ledger: instead of "what's each subarray's min", ask "in how many subarrays is element i THE min?" If the nearest smaller element is left[i] steps behind (strictly smaller) and right[i] steps ahead (smaller-or-equal), any subarray starting in those left slots and ending in those right slots has a[i] as its minimum: left[i] · right[i] subarrays, contributing a[i] · left[i] · right[i]. One pass computes both spans — an element's pop moment fixes its right span; the survivor beneath fixes its left span. 

int sumSubarrayMins(int[] a) {
    final int MOD = 1_000_000_007;
    int n = a.length;
    long ans = 0;
    Deque<Integer> st = new ArrayDeque<>();     // indices; values increasing (non-strict) bottom→top
    for (int i = 0; i <= n; i++) {
        int cur = (i == n) ? Integer.MIN_VALUE : a[i];   // sentinel flushes everyone
        while (!st.isEmpty() && cur < a[st.peek()]) {    // strict < here, ≥ stays — see trap below
            int mid = st.pop();
            int left  = st.isEmpty() ? -1 : st.peek();   // nearest STRICTLY smaller on the left
            long L = mid - left;                // choices for the subarray's start
            long R = i - mid;                   // choices for the end (up to first ≤ on the right)
            ans = (ans + a[mid] % MOD * L % MOD * R) % MOD;
        }
        st.push(i);
    }
    return (int) ans;
}

Time O(n), Space O(n). Contribution counting — "sum over all subarrays = sum over all elements of (value × times it's counted)" — is a technique worth naming out loud; LC 2104 (Sum of Subarray Ranges) is the same trick twice (max minus min).

The duplicate double-count trap (LC 907) With equal values like [3, 3], if both sides use strict "smaller", the subarray [3, 3] is credited to both threes. Fix: break the tie asymmetrically — strictly-smaller boundary on one side, smaller-or-equal on the other (above: pop on cur < top, so equal values stay and become left boundaries). Each subarray then credits its min to exactly one occurrence.

Case: Remove K Digits (LC 402) — lexicographic-min stack

Make the smallest number by deleting k digits. Greedy insight: a number is smaller when its leading digits are smaller, so if a digit is bigger than the one after it, deleting it always helps. That's "pop the previous greater while budget remains" — an increasing stack over the digit string. Same greedy skeleton solves LC 316 / 1081 (Remove Duplicate Letters) and LC 321. 

String removeKdigits(String num, int k) {
    Deque<Character> st = new ArrayDeque<>();   // digits, non-decreasing bottom→top
    for (char c : num.toCharArray()) {
        while (!st.isEmpty() && k > 0 && st.peek() > c) {
            st.pop();                           // a bigger digit BEFORE a smaller one — delete it
            k--;
        }
        st.push(c);
    }
    while (k-- > 0) st.pop();                   // digits already non-decreasing → trim the largest, at the END
    StringBuilder sb = new StringBuilder();
    for (Iterator<Character> it = st.descendingIterator(); it.hasNext(); )
        sb.append(it.next());                   // bottom→top order = left→right digits
    int i = 0;
    while (i < sb.length() - 1 && sb.charAt(i) == '0') i++; // strip leading zeros, keep one digit
    String s = sb.substring(i);
    return s.isEmpty() ? "0" : s;
}

Time O(n), Space O(n). Three sub-traps in one problem: leftover k (input already increasing, e.g. "12345"), leading zeros ("10200", k=1 → "200"), and everything removed → return "0".

4 · Edge-case checklist

  • Forgetting the sentinel / final drain (84, 907): an increasing input never pops, and you return 0. Loop to i ≤ n with a virtual smallest bar, or drain explicitly after the loop.
  • Width off-by-one: i − st.peek() − 1 after popping, and left = −1 when the stack empties. Test on a single bar: [5] must give 5.
  • Rain water needs a left wall: after popping, an empty stack means the water spills left — break, don't count.
  • Duplicates in 907: strict on one side, non-strict on the other, or equal minima double-count. Also take % MOD inside the accumulation, in long.
  • 402's three exits: spend leftover k from the end; strip leading zeros; empty result is "0".
  • Deque direction when rebuilding strings: ArrayDeque.push adds to the head, so iterate with descendingIterator() to read bottom→top (or use StringBuilder as the stack and skip the issue).
