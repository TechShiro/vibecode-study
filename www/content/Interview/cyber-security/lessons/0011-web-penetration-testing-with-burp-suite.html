1 · The One Idea

A web browser is designed for friendly human interaction—it automatically obeys HTML form constraints, client-side JavaScript validation, and hidden input fields. A penetration tester uses an Intercepting Proxy (such as Burp Suite or OWASP ZAP) sitting between the browser and the target server. By intercepting raw HTTP/S packets in transit, the pen-tester strips away all client-side restrictions, alters cookies and headers, and analyzes backend responses directly.

2 · Burp Suite Core Architecture & Modules

ModuleFunction & PurposeWorkflow Example
Proxy Captures and freezes HTTP/S requests in real time before they reach the web server. Intercept an e-commerce checkout request and modify price=1000 to price=1 to test price tampering.
Repeater Allows manual editing and re-issuing of single requests with instant response viewing. Fine-tuning SQL injection or XSS payloads by changing one character at a time.
Intruder Automated customized attacks and parameter fuzzing with wordlists. Brute-forcing admin passwords (Sniper attack), enumerating user IDs, fuzzing directory endpoints.
Decoder Transforms raw data using URL, Base64, Hex, HTML, and cryptographic hashes. Quickly decoding base64 tokens or obfuscated webshell strings.

3 · Malicious File Uploads & Webshell Execution

If an application permits users to upload profile pictures or documents without strict verification, an attacker uploads an executable script (e.g. cmd.php, shell.jsp):

Bypassing File Upload Filters

  • MIME-Type Bypass: Intercept request in Burp and change Content-Type: application/x-php to image/jpeg.
  • Double Extensions & Null-Bytes: avatar.php.jpg or shell.php%00.png.
  • Magic Bytes Injection: Prepend valid JPEG magic bytes (ÿØÿ) to a PHP webshell: 
    &xFF&xD8&xFF&xE0 <?php system($_GET['cmd']); ?>

Once uploaded to a public directory, requesting http://target.com/uploads/cmd.php?cmd=whoami grants interactive Remote Code Execution (RCE) on the server!

4 · Server-Side Request Forgery (SSRF) & Cloud Metadata

In an SSRF attack, the attacker tricks a backend web server into making an HTTP request to an unexpected destination (usually internal network devices or cloud metadata services):

Attacker sends URL parameter
Target Web Server fetches internal URL
AWS Metadata Service (169.254.169.254)

The Cloud Metadata Attack: When running inside AWS, Azure, or GCP, applications have access to a local link-local IP service. By injecting:

POST /fetch-url HTTP/1.1
url=http://169.254.169.254/latest/meta-data/iam/security-credentials/admin-role

The backend server queries the AWS metadata API and returns temporary AWS access keys and secret tokens, enabling the attacker to take over the entire cloud infrastructure!
