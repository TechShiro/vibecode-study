1 · The One Idea

Cryptography is the mathematical foundation of modern digital trust. It follows Kerckhoffs's Principle: a cryptographic system should remain secure even if everything about the system (the algorithm, source code, hardware) is public knowledge, so long as the secret key remains confidential. Symmetric cryptography uses the same secret key for both encryption and decryption, offering blazing-fast bulk data throughput.

2 · Block Ciphers & AES (Advanced Encryption Standard)

AES operates on fixed 128-bit (16-byte) blocks using key sizes of 128, 192, or 256 bits through repeated rounds of Substitution-Permutation Networks (SubBytes, ShiftRows, MixColumns, AddRoundKey).

Modes of Operation

ModeMechanismSecurity Assessment
ECB (Electronic Codebook) Each 16-byte block encrypted independently with the same key. FATALLY INSECURE. Identical plaintext blocks produce identical ciphertext blocks! (The famous Linux Tux penguin image remains clearly visible even after ECB encryption).
CBC (Cipher Block Chaining) Each plaintext block is XORed with the previous ciphertext block before encryption; uses a random Initialization Vector (IV) for block 1. Secure confidentiality, but vulnerable to Padding Oracle Attacks if integrity is not verified.
GCM (Galois/Counter Mode) Turns block cipher into stream cipher via incrementing counter; includes a Galois Message Authentication Code (GMAC). THE INDUSTRY GOLD STANDARD (AEAD). Provides both Confidentiality and Authenticated Integrity in one operation.

3 · Cryptographic Hash Functions & Passwords

A hash function takes arbitrary-length input and produces a fixed-size deterministic digest (e.g. SHA-256 = 32 bytes). It must satisfy three mathematical properties:

  1. Pre-image Resistance (One-Way): Given H(x), it is computationally impossible to find x.
  2. Second Pre-image Resistance (Weak Collision): Given x, impossible to find y ≠ x such that H(x) = H(y).
  3. Collision Resistance (Strong Collision): Impossible to find ANY two different inputs with H(x) = H(y). (Broken in MD5 and SHA-1).

Why SHA-256 is Terrible for Passwords!

Fast hashes like SHA-256 are engineered to hash gigabytes of files per second. Modern consumer GPUs (RTX 4090) can calculate over 50 billion SHA-256 hashes per second! An 8-character password hashed with SHA-256 can be brute-forced in minutes.

Correct Defense: Slow Key Derivation Functions (KDFs):

  • bcrypt: Work factor parameter dynamically increases CPU iterations.
  • Argon2id (Winner of Password Hashing Competition): Memory-hard; intentionally demands large chunks of RAM (e.g. 64MB) to defeat ASIC and GPU cluster parallelization.
  • Salt: A unique random string appended to each user's password before hashing. Defeats precomputed Rainbow Tables.

4 · Password Cracking with Hashcat

# 1. Crack NTLM hashes using RockYou wordlist and Rule-based mutations
hashcat -m 1000 -a 0 hashes.txt /usr/share/wordlists/rockyou.txt -r /usr/share/hashcat/rules/best64.rule

# 2. Crack SHA-512 crypt ($6$) Linux hashes
hashcat -m 1800 -a 0 shadow_hashes.txt /usr/share/wordlists/rockyou.txt

# 3. Pure Brute-Force Mask Attack (8 characters lowercase + digits)
hashcat -m 0 -a 3 md5_hashes.txt ?l?l?l?l?d?d?d?d
