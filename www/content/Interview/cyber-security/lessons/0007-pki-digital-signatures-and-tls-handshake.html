1 · The One Idea

Even with RSA and Diffie-Hellman, an attacker can position themselves in the middle (MITM) and replace Alice's public key with their own. How do you know a public key genuinely belongs to google.com and not an imposter? Public Key Infrastructure (PKI) solves this via Digital Certificates (X.509) issued and cryptographically signed by globally trusted Certificate Authorities (CAs).

2 · Digital Signatures: Integrity & Non-Repudiation

Message → SHA-256 Hash
Encrypt Hash with SENDER's Private Key
Digital Signature Attached

To verify: The recipient decrypts the signature using the Sender's Public Key to retrieve the original hash, hashes the received message themselves, and compares the two. If a single byte was altered in transit, the hashes will not match.

3 · Public Key Infrastructure (PKI) & Chain of Trust

  1. Root CA: Embedded directly inside your Operating System and Browser (e.g. DigiCert, Let's Encrypt). Kept offline in an air-gapped vault.
  2. Intermediate CA: Signed by the Root CA; issues everyday end-entity certificates.
  3. Server Certificate: Presented by the web server containing its public key, domain name, validity dates, and signed by the Intermediate CA.
  4. Revocation: CRL (Certificate Revocation Lists) and OCSP Stapling (Online Certificate Status Protocol) check if a stolen certificate was revoked before expiration.

4 · The Modern TLS 1.3 Handshake (1-RTT)

TLS 1.3 overhauled web security: it deprecated obsolete insecure ciphers (RSA key exchange, CBC mode, RC4, MD5), mandated Perfect Forward Secrecy (PFS) via Ephemeral Diffie-Hellman (ECDHE), and reduced handshake latency to a single round-trip (1-RTT):

Step 1

ClientHello

Browser sends supported cipher suites (e.g. TLS_AES_256_GCM_SHA384), supported TLS version (1.3), SNI (domain name), and its Ephemeral Diffie-Hellman key share.

Step 2

ServerHello & Handshake

Server selects cipher suite, sends its Diffie-Hellman key share, server certificate, and digital signature. Both parties compute shared master secret. Handshake is complete!

Step 3

Encrypted Application Data

All subsequent HTTP traffic (GET/POST requests, cookies, payloads) is encrypted using symmetric AES-256-GCM. Fast, secure, and immune to retroactive decryption if server private key is stolen later.
