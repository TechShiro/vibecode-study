Cross-Site Scripting (XSS), CSRF & CORS Misconfigurations

Client-side web exploitation: browser security models, session hijacking, cross-site forgery, and Content Security Policy.

← Back to Course IndexModule D – Web Security (OWASP Top 10)

1 · The One Idea

The foundational security principle of modern web browsers is the Same-Origin Policy (SOP): scripts running on bank.com cannot access cookies, DOM trees, or localStorage belonging to malicious.com (an origin is defined as {protocol, domain, port}). Cross-Site Scripting (XSS) tricks the victim's browser into executing attacker-supplied JavaScript inside the trusted origin of bank.com, completely nullifying the Same-Origin Policy.

2 · The Three Flavors of XSS

1

Stored XSS (Persistent)

Malicious payload is permanently saved inside the application database (e.g. comment section, profile bio). Every user who visits the page has the malicious JavaScript executed in their browser session. Most dangerous!

2

Reflected XSS (Non-Persistent)

Payload is embedded in a malicious phishing link (e.g. search.php?q=<script>...</script>) and immediately reflected back by the server in the HTTP response. Executes only when victim clicks the link.

3

DOM-based XSS

Vulnerability exists entirely on the client-side JavaScript without server involvement. Occurs when untrusted data from a source (location.search) reaches an execution sink (innerHTML, eval(), document.write()).

3 · Cross-Site Request Forgery (CSRF)

CSRF tricks an authenticated user's browser into transmitting an unauthorized command to a trusted web application. Because browsers automatically attach session cookies to cross-origin requests, a malicious website containing:

<img src="https://bank.com/transfer?to=attacker&amount=5000" />

forces the victim's browser to execute the transfer with valid session cookies!

CSRF Defenses

  • SameSite Cookie Attribute: Set SameSite=Strict or SameSite=Lax so cookies are NEVER sent on cross-origin requests.
  • Anti-CSRF Tokens: Cryptographically random tokens generated per session, embedded as hidden form fields, and validated on every state-changing POST/PUT request.

4 · Cross-Origin Resource Sharing (CORS) Misconfigurations

CORS relaxes SOP to allow legitimate cross-domain APIs. Dangerous misconfigurations occur when developers carelessly trust wildcards with credentials:

# VULNERABLE SERVER RESPONSE HEADERS:
Access-Control-Allow-Origin: https://evil-attacker.com  (or dynamic reflection of Origin)
Access-Control-Allow-Credentials: true
# Result: Attacker's JS can read victim's private JSON data!

5 · Comprehensive Defense: CSP & Cookie Flags

  • HttpOnly Flag: Set-Cookie: session_id=abc; HttpOnly; Secure; SameSite=Strict. Prohibits JavaScript from accessing the cookie via document.cookie, completely preventing cookie-theft via XSS!
  • Content Security Policy (CSP): HTTP response header restricting where scripts, styles, and images can load from: 
    Content-Security-Policy: default-src 'self'; script-src 'self' https://trustedscripts.com; object-src 'none';
