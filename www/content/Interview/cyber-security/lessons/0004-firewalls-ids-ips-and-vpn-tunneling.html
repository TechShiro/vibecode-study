1 · The One Idea

To defend private enterprise networks against external hostile traffic, organizations deploy three interlocking technologies: Firewalls (which enforce perimeter access rules based on IP/port/protocol state), Intrusion Detection/Prevention Systems (IDS/IPS) (which inspect packet payloads for known exploit signatures and anomalies), and Virtual Private Networks (VPNs) (which wrap untrusted public internet traffic inside encrypted, authenticated cryptographic tunnels).

2 · Firewall Generations

Gen 1

Stateless Packet Filters

Inspects each packet in isolation against static rules (source/dest IP, port). Vulnerable to spoofed ACK flags; cannot determine if a packet is part of an established legitimate connection.

Gen 2

Stateful Inspection (SPI)

Tracks the state of active TCP connections (State Table: NEW, ESTABLISHED, RELATED). Incoming replies are automatically permitted only if they correspond to an existing outbound session (e.g. Linux iptables / nftables).

Gen 3

Next-Gen Firewalls (NGFW)

Operates at Layer 7 (Application Layer). Decrypts TLS traffic, identifies application protocols (e.g. distinguishing BitTorrent over port 80 from legitimate HTTP), and integrates antivirus and sandboxing.

3 · IDS vs IPS & Writing Snort Rules

  • Intrusion Detection System (IDS): Passive monitoring (out-of-band via SPAN/TAP port). Sniffs traffic, raises alerts, but does not stop attacks.
  • Intrusion Prevention System (IPS): Active inline deployment. Packets physically pass through the IPS; can actively drop malicious packets and reset TCP connections in real time.

Anatomy of a Snort / Suricata Rule

alert tcp any any -> 192.168.1.100 80 (
    msg:"MALWARE-BACKDOOR Webshell Access Attempt";
    content:"cmd.php"; nocase;
    content:"cmd="; http_uri;
    sid:1000005; rev:1;
)
  • Header: alert tcp any any -> 192.168.1.100 80 (action, protocol, src IP/port, direction, dst IP/port).
  • Options: msg (human readable description), content (string pattern to match), sid (unique Snort ID ≥ 1,000,000 for custom rules).

4 · VPN Tunneling: IPsec vs OpenVPN vs WireGuard

ProtocolLayerCryptographyCodebase & Speed
IPsecLayer 3 (Network)AES-CBC / AES-GCM, IKEv2 key exchange.Complex configuration; great for corporate Site-to-Site router links.
OpenVPNLayer 4 (Transport / TLS)OpenSSL (AES, RSA, SHA-256) over TCP or UDP.Mature, flexible, penetrates firewalls easily via port 443; high CPU overhead.
WireGuardLayer 3 (In-Kernel)Modern crypto: Curve25519, ChaCha20, Poly1305, BLAKE2s.~4,000 lines of code (vs 100,000+ for OpenVPN); ultra-fast, minimal attack surface, instant roaming.
