1 · The One Idea

HTTP is fundamentally pull-based: a client asks, the server answers, and the socket closes. For chat apps or live gaming, polling every second floods servers with empty HTTP headers. WebSockets keep an open, persistent TCP connection between client and server. Socket.io wraps raw WebSockets with automatic reconnection, heartbeat pings, fallback to long-polling for corporate firewalls, and Rooms for targeted broadcasting.

2 · Building a Node.js + Socket.io Server in 20 Lines

import { createServer } from 'http';
import { Server } from 'socket.io';

const httpServer = createServer();
const io = new Server(httpServer, {
  cors: { origin: 'http://localhost:3000' }
});

io.on('connection', (socket) => {
  console.log('Client connected:', socket.id);

  // Joining a specific chat room
  socket.on('join_room', (roomId) => {
    socket.join(roomId);
    console.log(`Socket ${socket.id} joined room ${roomId}`);
  });

  // Broadcasting message only to participants in that room
  socket.on('send_message', ({ roomId, message, user }) => {
    io.to(roomId).emit('receive_message', { user, message, time: Date.now() });
  });

  socket.on('disconnect', () => {
    console.log('Client disconnected:', socket.id);
  });
});

httpServer.listen(4000, () => console.log('Socket server live on port 4000'));
