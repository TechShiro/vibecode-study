Strings, Numbers & Built-ins

The standard library tour — why 0.1 + 0.2 misses 0.3, what JSON silently throws away, and the modern operators (?. ??) that make real-world data handling civilized.

Track goal: Full-stack web dev — JS → React/Next → Express/Nest → Postgres/Drizzle. This is Lesson 5 of 24. Index

1 · Strings — immutable, method-rich

Like Java's String, JS strings are immutable: no method ever changes a string — every "modification" returns a brand-new one. Forget this and you'll write no-op lines all day: 

let s = "hello";
s.toUpperCase();      // returns "HELLO"…
console.log(s);       // …but s is still "hello" — the result was thrown away!
s = s.toUpperCase();  // reassign to keep it (same discipline as Java)
s[0] = "J";           // silently ignored — you cannot write into a string

The working vocabulary — grouped the way you'll actually reach for them:

const str = "  JavaScript is everywhere  ";

// CLEAN & CASE
str.trim()                 // "JavaScript is everywhere" — strip edge whitespace
                           // (trimStart / trimEnd for one side)
"NSUT".toLowerCase()       // "nsut"
"nsut".toUpperCase()       // "NSUT"

// EXTRACT
const t = "JavaScript";
t.slice(0, 4)        // "Java" — start, endExclusive; NEGATIVES OK: t.slice(-6) → "Script"
t.substring(0, 4)    // "Java" — older; swaps reversed args, treats negatives as 0.
                     // Just use slice — one rule for arrays AND strings.
t.at(-1)             // "t" — like arrays; t[0] → "J" (bracket read is fine, write is not)
t.charAt(0)          // "J" — the pre-bracket ancient way; know it exists

// SEARCH — the same family you met on arrays (deliberate symmetry)
t.includes("Script")     // true
t.startsWith("Java")     // true
t.endsWith("Script")     // true
t.indexOf("a")           // 1 — first hit; lastIndexOf("a") → 3; -1 if absent

// SPLIT & JOIN — string ⇄ array round trip
"a,b,c".split(",")       // ["a","b","c"]  (Java's split, minus the regex-only rule)
"hello".split("")        // ["h","e","l","l","o"] — chars; then array methods apply!
"hello".split("").reverse().join("")   // "olleh" — the interview classic

// REPLACE
"a-b-c".replace("-", "+")     // "a+b-c" — FIRST occurrence only!
"a-b-c".replaceAll("-", "+")  // "a+b+c" — all (or use a /regex/g — §6)

// PAD & REPEAT
"7".padStart(3, "0")     // "007" — invoice numbers, clock digits
"ab".repeat(3)           // "ababab"

Template literals (Lesson 1 recap): backticks, ${expr} interpolation, real multi-line strings. Default to them for any string with variables inside.

Java parallel Same immutability, same "reassign to keep" habit, same length-ish API — but JS length is a property (s.length), not a method call. No char type: "a" is a 1-char string, and comparing runs === on content for strings (primitives compare by value — no .equals() dance needed). There's no StringBuilder either; for heavy concatenation, push parts into an array and join("").

2 · Numbers — IEEE 754 and the 0.1 + 0.2 scandal

Lesson 1 said it: JS has ONE number type — the 64-bit IEEE 754 double, identical to Java's double. No int/long/float. That single fact explains the most famous line in JavaScript: 

0.1 + 0.2            // 0.30000000000000004
0.1 + 0.2 === 0.3    // false ?!

Why: doubles store numbers in binary. Just as 1/3 has no finite decimal form (0.3333…), 0.1 and 0.2 have no finite binary form — the hardware stores the nearest representable value, and the tiny errors add up. This is not a JS bug; Java's double does exactly the same (0.1 + 0.2 != 0.3 there too — Java just rounds when printing). The professional fixes: 

Math.abs(a - b) < Number.EPSILON      // compare with a tolerance, never ===
(0.1 + 0.2).toFixed(2)                // "0.30" — round for DISPLAY (returns a string!)
// For money: store integer paise/cents (1050, not 10.50) — the industry standard,
// same reason Java uses BigDecimal for currency.

Integer safety has a boundary too — doubles have 53 bits of integer precision:

Number.MAX_SAFE_INTEGER       // 9007199254740991 (2^53 − 1)
9007199254740992 === 9007199254740993   // true?! beyond the limit, integers blur

// BIGINT — arbitrary-precision integers (Java's BigInteger, but with operators)
const big = 9007199254740993n;          // the n suffix — a separate primitive type
big + 1n              // 9007199254740994n — exact
big + 1               // TypeError — no mixing BigInt and number; convert explicitly
// Real use: 64-bit database IDs, crypto. Otherwise regular numbers are fine.

Conversion and checking — know the differences:

Number("42")        // 42    — strict: the WHOLE string must be numeric
Number("42px")      // NaN
Number("")          // 0     — classic surprise
parseInt("42px")    // 42    — lenient: reads digits from the front, stops at junk
parseInt("px42")    // NaN   — but the front must start numeric
parseInt("08", 10)  // 8     — always pass radix 10 out of habit
parseFloat("3.14em")// 3.14
+"42"               // 42    — unary plus, shorthand for Number()

Number.isInteger(42)      // true  (42.0 too — same double!)
Number.isFinite(1 / 0)    // false — Infinity exists: 1/0 is Infinity, not an error
(1234.5678).toFixed(2)    // "1234.57" — string out, remember
(0.000001234).toPrecision(2) // "0.0000012"

And the Math toolbox (all static, like java.lang.Math):

Math.round(4.5)   // 5   — nearest (.5 rounds UP, even for 4.5)
Math.floor(4.9)   // 4   — toward −∞  (Math.floor(-4.1) → -5!)
Math.ceil(4.1)    // 5   — toward +∞
Math.trunc(-4.9)  // -4  — chop the decimals (what Java int-casting does)
Math.min(3, 1, 2) // 1   — varargs; for arrays: Math.min(...arr) (Lesson 4 spread)
Math.abs(-5); Math.pow(2, 10); 2 ** 10; Math.sqrt(144);  // ** is the operator form

Math.random()     // float in [0, 1) — never exactly 1
// THE formula — random integer from min to max inclusive (memorize it):
function randInt(min, max) {
  return Math.floor(Math.random() * (max - min + 1)) + min;
}
randInt(1, 6)     // a die roll 🎲

3 · Date — useful, quirky, and month-is-0-indexed

JS dates are one object type wrapping a single number: milliseconds since Jan 1, 1970 UTC (the Unix epoch — same as Java's System.currentTimeMillis()).

// CREATING
const now = new Date();                    // current moment
const ts  = Date.now();                    // just the number, no object — for timing
new Date(0)                                // epoch: Jan 1 1970 UTC
new Date("2026-07-26T10:30:00")            // ISO string — the reliable parse format
new Date(2026, 6, 26)                      // ⚠ July 26! Month is 0-INDEXED: 6 = July.
                                           // Days are 1-indexed. Yes, really. THE date gotcha.

// GETTING (local-time versions; each has a getUTC* twin)
now.getFullYear()   // 2026    (never getYear() — that's broken legacy)
now.getMonth()      // 6       — 0-indexed again: 6 means July
now.getDate()       // 26      — day of MONTH
now.getDay()        // 0–6     — day of WEEK, 0 = Sunday (Date vs Day trips everyone)
now.getHours(); now.getMinutes(); now.getSeconds();
now.getTime()       // the underlying milliseconds — the escape hatch to math

// SETTING — mutates the object; overflow rolls over intelligently:
const d = new Date(2026, 0, 31);
d.setDate(d.getDate() + 1);       // Jan 31 + 1 day → Feb 1 — the "add days" idiom
d.setMonth(11);                    // December

// MATH — subtracting dates coerces both to milliseconds:
const days = (deadline - now) / (1000 * 60 * 60 * 24);

// FORMATTING
now.toISOString()                  // "2026-07-26T05:00:00.000Z" — for APIs/DBs (UTC)
now.toLocaleDateString("en-IN")    // "26/7/2026" — for humans
now.toLocaleString("en-IN", { dateStyle: "medium", timeStyle: "short" })
                                   // "26 Jul 2026, 10:30 am"
Gotcha The 0-indexed month bites everyone once — new Date(2026, 12, 1) is not December, it's January 2027 (month 12 overflows). Java repeated this mistake in old java.util.Calendar and fixed it in java.time; JS is still waiting on its fix (the upcoming Temporal API). Until then: store and transmit ISO strings or timestamps, format with toLocale*, and reach for a library (date-fns) for heavy date logic.

4 · JSON — what survives the round trip

JSON (JavaScript Object Notation) is the text format of the web — every API in Modules C–E speaks it. It looks like JS object-literal syntax but is stricter: keys must be double-quoted strings, and only strings, numbers, booleans, null, arrays, and objects exist. Two methods do everything: 

const user = { name: "Krish", year: 3, skills: ["java", "js"] };

// STRINGIFY: object → text (to send/store)  — Java parallel: Jackson/Gson serialization
const text = JSON.stringify(user);
// '{"name":"Krish","year":3,"skills":["java","js"]}'

// PARSE: text → object (on receipt)
const back = JSON.parse(text);
back.name           // "Krish" — a fresh object, structurally equal, not === (new references)

JSON.stringify(user, null, 2)   // 3rd arg 'space': pretty-print with 2-space indent
JSON.stringify(user, ["name"])  // 2nd arg 'replacer': keep only listed keys → '{"name":"Krish"}'
JSON.stringify(user, (k, v) => k === "year" ? undefined : v)  // replacer fn: drop fields
JSON.parse('{"bad json"')       // SyntaxError — ALWAYS try/catch parsing of external input

What does NOT survive — the interview meat. JSON is a data format, not a JS snapshot:

Value in your objectAfter stringifyAfter parse (round trip)
string / number / boolean / nullkeptidentical — the survivors
nested objects & arrayskeptrebuilt fresh (new references)
function (method)silently droppedgone — behavior can't be serialized
undefined propertysilently droppedgone (in arrays: becomes null)
Datebecomes an ISO stringstays a string! — you must re-wrap: new Date(str)

The "Date becomes a string" row causes real bugs weekly: an API returns a user with createdAt, you call .getFullYear() on it, and it explodes — because after JSON.parse it's a string. Re-hydrate manually.

5 · Symbol — the third key type, briefly

Lesson 1 listed symbol among the primitives; Lessons 3–4 used Symbol.iterator. Now the two-minute complete story. A Symbol is a guaranteed-unique identifier: 

const id1 = Symbol("id");     // the "id" is just a debug label…
const id2 = Symbol("id");
id1 === id2                    // false — EVERY Symbol() call is unique, forever

// Use: collision-proof object keys (bracket syntax — Lesson 3)
const ID = Symbol("dbId");
user[ID] = 12345;
user[ID]                       // 12345 — but invisible to normal inspection:
Object.keys(user)              // no ID here; JSON.stringify skips it; for..in skips it

Two facts to retain: (1) object keys are only ever strings or symbols — now the Lesson 3 statement is complete; (2) well-known symbols are hooks the language itself looks for on your objects — Symbol.iterator (makes you iterable, Lesson 4) is the star; others like Symbol.asyncIterator exist on the same pattern. You'll rarely mint your own symbols, but you now recognize the mechanism libraries use to hide internals.

6 · RegExp — pattern matching essentials

Java's Pattern/Matcher, but built into the language with literal syntax: /pattern/flags. Same regex dialect underneath — your Java regex knowledge transfers almost fully: 

const re = /\d+/g;             // literal: pattern \d+ , flag g
new RegExp("\\d+", "g")        // constructor form — for building patterns from variables;
                               // note DOUBLE backslash in the string, like Java

// FLAGS: g = all matches (not just first) · i = ignore case · m = multiline anchors

// TEST — "does it match?" (validation)
/^\d{6}$/.test("110078")               // true — a 6-digit PIN code; ^ $ anchor whole string

// MATCH — "what matched?"
"a1b22c333".match(/\d+/)       // ["1", index: 1, …]  — first match + info (no g flag)
"a1b22c333".match(/\d+/g)      // ["1", "22", "333"]  — all matches (g flag)

// REPLACE — with patterns and capture groups
"price: 999".replace(/\d+/, "###")             // "price: ###"
"2026-07-26".replace(/(\d+)-(\d+)-(\d+)/, "$3/$2/$1")  // "26/07/2026" — $n = group n
"a b  c".split(/\s+/)                          // ["a","b","c"] — split on any whitespace

// The patterns you'll actually use:
/^[\w.+-]+@[\w-]+\.[\w.]+$/.test(email)   // pragmatic email shape-check
/^\d{10}$/.test(phone)                    // 10-digit phone
/^[a-z0-9-]+$/.test(slug)                 // url-slug characters only

Building blocks refresher: \d digit, \w word char, \s whitespace, . anything, + one-or-more, * zero-or-more, ? optional, {n,m} counts, [abc] set, (x) capture group, ^ $ anchors, | or. Enough for 95% of app code — validation, extraction, cleanup.

7 · The modern operators: ?. ?? and logical assignment

Real-world data is full of holes — an API user may have no address. Pre-2020 JS guarded with clumsy && chains; these three additions fixed it, and you'll use them in every file from here to the capstone.

Optional chaining ?. — "if what's before me is null/undefined, stop and produce undefined instead of throwing":

const user = { name: "Krish", address: null };

user.address.city        // TypeError: Cannot read properties of null 💥
user.address?.city       // undefined — short-circuits calmly at the hole
user.address?.city?.toUpperCase()  // chain as deep as needed
user.getBio?.()          // call the method ONLY if it exists
scores?.[0]              // works for index/bracket access too
// Java flashback: this is the null-check pyramid — if (u != null && u.getAddress() != null)…
// — collapsed into one character. (Only null/undefined trigger it; 0 and "" pass through.)

Nullish coalescing ?? — "default only for null/undefined." The crucial contrast is with ||, which defaults on any falsy value (Lesson 1's list):

const settings = { volume: 0, theme: "" };

settings.volume || 50    // 50 — WRONG! 0 is falsy, so || stomps a legitimate value
settings.volume ?? 50    // 0  — right: 0 is not null/undefined, keep it
settings.theme ?? "dark" // "" — kept; use || only when "" SHOULD count as missing
settings.missing ?? "x"  // "x" — both operators agree when truly absent

const city = user.address?.city ?? "Unknown";   // the idiomatic pair: probe, then default

Logical assignment — the compound-assignment forms (ES2021):

config.retries ??= 3;     // assign 3 only if retries is null/undefined — "set default"
cache.user ||= fetchUser(); // assign if falsy
flags.debug &&= verify();   // assign only if currently truthy
// You met ??= inside Lesson 4's groupBy: (groups[key] ??= []).push(item)

8 · Shallow vs deep copy — the full story

Threads from three lessons converge here. Lesson 1: variables hold references. Lesson 4: spread copies one level. Now the complete map of "I want a copy" — a topic interviewers adore because every option has a catch. 

const original = {
  name: "Krish",
  skills: ["java", "js"],
  joined: new Date("2026-01-01")
};

// LEVEL 0 — assignment: NOT a copy at all (one object, two labels — Lesson 1)
const alias = original;

// LEVEL 1 — SHALLOW copy: new top level, nested objects SHARED
const shallow = { ...original };            // or Object.assign({}, original)
shallow.name = "K2";                        // safe — top-level primitive slot is own
shallow.skills.push("sql");                 // ⚠ original.skills changed too — shared ref!

// LEVEL 2 — DEEP copy, the modern way: structuredClone (Node 17+, all browsers)
const deep = structuredClone(original);
deep.skills.push("sql");                    // original untouched ✓
deep.joined instanceof Date                 // true ✓ — Dates, Maps, Sets, even circular
                                            // references all survive. Limits: functions,
                                            // class identity, DOM nodes → throws/loses.

// LEVEL 2 (legacy) — the JSON trick: you'll see it in old code and interviews
const jsonCopy = JSON.parse(JSON.stringify(original));
// Deep, but inherits EVERY §4 limitation: functions/undefined dropped,
// joined is now a STRING, Map/Set gutted, circular refs throw. Know it; prefer structuredClone.
TechniqueDepthKeeps Dates/Map/Set?Handles circular?Verdict
b = anone — same object——Not a copy
{...a} / [...a] / Object.assign / slice()1 levelshared, not copiedn/aFine when nesting is shallow or nested parts are treated read-only

For deep copies use structuredClone, which handles Dates, Maps, Sets and circular references. The JSON round-trip trick is the legacy alternative, but it drops functions and undefined, turns Dates into strings, and throws on circular data."

9 · Interview questions this lesson answers

  • Q. "Why is 0.1 + 0.2 !== 0.3? How do you handle it?"
    JS numbers are IEEE 754 doubles; 0.1 and 0.2 have no exact binary representation, so their stored approximations sum to 0.30000000000000004. Handle with epsilon comparison (Math.abs(a-b) < Number.EPSILON), toFixed for display, or integer paise/cents for money. Java's double behaves identically — hence BigDecimal there.
  • Q. "slice vs substring for strings?"
    Nearly identical, but slice supports negative (from-the-end) indexes while substring treats negatives as 0 and silently swaps reversed arguments. Use slice — it also matches array semantics.
  • Q. "Number() vs parseInt()?"
    Number("42px") is NaN — the whole string must be numeric (and Number("") is 0). parseInt("42px") is 42 — it reads leading digits and stops. Pass the radix: parseInt(s, 10).
  • Q. "What are the quirks of the Date object?"
    Months are 0-indexed (6 = July) while days are 1-indexed; getDay() is day-of-week (0 = Sunday) vs getDate() day-of-month; setters mutate; overflow rolls over (useful for date math). Store/transmit ISO strings or timestamps; the Temporal API is the future fix.
  • Q. "What does JSON.stringify do with functions, undefined, and Dates?"
    Functions and undefined-valued properties are silently dropped (undefined in arrays becomes null); Dates are serialized as ISO strings and stay strings after parse; Map/Set become {}; BigInt and circular references throw. Replacer and space arguments allow filtering and pretty-printing.
  • Q. "?? vs || ?"
    || falls back on any falsy value — so it wrongly replaces valid 0, "", and false. ?? falls back only on null/undefined. Rule: use ?? for defaults, and pair it with ?. for safe access into possibly-missing data.
  • Q. "How do you deep-copy an object?"
    structuredClone — deep, preserves Dates/Map/Set, survives circular refs. Spread/assign are shallow (one level). The JSON trick is deep but lossy. For objects with methods/class identity, write a copy method or constructor — cloning can't preserve behavior.
  • Q. "What is a Symbol used for?"
    A guaranteed-unique primitive used as a collision-proof, non-enumerable object key; object keys are only strings or symbols. Well-known symbols like Symbol.iterator are protocol hooks the language checks for — that's how iterability works.
