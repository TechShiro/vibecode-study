GraphQL APIs & Apollo Server

Replacing rigid REST endpoints with declarative, client-driven data querying.

↑ Back to Course Index Module G — Modern APIs & DevOps

1 · The One Idea

In REST, endpoints are rigid and fixed. To render a mobile profile screen, a smartphone app might have to call /users/1, then /users/1/orders, then /users/1/reviews (Under-fetching). Simultaneously, the /users/1 endpoint returns 50 unused fields (Over-fetching). GraphQL replaces multiple REST endpoints with a single POST /graphql endpoint where the client sends a query specifying the exact fields it needs, and the server returns exactly that shape in a single request!

2 · Defining a GraphQL Schema & Resolvers

import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';

// 1. Schema Definition Language (SDL)
const typeDefs = `#graphql
  type Book {
    id: ID!
    title: String!
    author: String!
  }

  type Query {
    books: [Book]
    book(id: ID!): Book
  }
`;

// 2. Resolvers (Functions that fetch the actual data)
const resolvers = {
  Query: {
    books: () => db.books.findAll(),
    book: (_, { id }) => db.books.findById(id),
  },
};

const server = new ApolloServer({ typeDefs, resolvers });
const { url } = await startStandaloneServer(server, { listen: { port: 4000 } });
console.log(`GraphQL API live at ${url}`);
