Arrays, Destructuring & Iteration

Ninety percent of everyday JS is transforming arrays of data — this is the lesson you'll use in literally every file you ever write, from React lists to database rows.

Track goal: Full-stack web dev — JS → React/Next → Express/Nest → Postgres/Drizzle. This is Lesson 4 of 24. Index

1 · Arrays are objects (with quirks)

A Java array is a fixed-length block of one type. A JS array is neither: it's an object whose keys happen to be "0", "1", "2"… plus a self-maintaining length property. Any types, any length, growable at will — closer to Java's ArrayList<Object> than to int[]: 

const mixed = [1, "two", true, { id: 3 }, [4, 5]];  // literal syntax — the normal way
mixed.length          // 5 — a live property, not a method (no parentheses)
typeof mixed          // "object" — Lesson 1's quirk; the real test:
Array.isArray(mixed)  // true

const arr = [10, 20, 30];
arr[5] = 60;          // writing past the end works — creates a SPARSE array
arr                   // [10, 20, 30, <2 empty slots>, 60], length is now 6
arr[3]                // undefined — holes read as undefined, no exception
arr.length = 2;       // assigning length TRUNCATES: arr is now [10, 20]!
arr[-1]               // undefined — negative indexes are just the key "-1", not Python-style
arr.at(-1)            // 20 — .at() is how you ask for "last element" properly

2 · The everyday mutators: push/pop/shift/unshift, splice, sort

These methods mutate — they change the array in place. First the ends:

const q = ["a", "b"];
q.push("c");      // add to END      → ["a","b","c"], returns new length 3
q.pop();          // remove from END → returns "c", q is ["a","b"]  (stack ops!)
q.unshift("z");   // add to FRONT    → ["z","a","b"]
q.shift();        // remove FRONT    → returns "z"   (queue: push + shift)
// Mnemonic: push/pop work the cheap end; SHIFTing everything over is the front pair.

slice vs splice — two similar names, opposite temperaments, and a permanent interview favorite:

const letters = ["a", "b", "c", "d", "e"];

// SLICE(start, endExclusive) — COPY a section, original untouched (non-mutating)
letters.slice(1, 3)   // ["b","c"]  — like Java's substring semantics
letters.slice(-2)     // ["d","e"]  — negatives count from the end
letters.slice()       // full shallow copy — a classic idiom
letters               // still ["a","b","c","d","e"] ✓

// SPLICE(start, deleteCount, ...items) — SURGERY on the original (mutating)
letters.splice(1, 2);           // removes "b","c" → letters is ["a","d","e"]
letters.splice(1, 0, "X", "Y"); // deletes 0, inserts → ["a","X","Y","d","e"]
letters.splice(2, 1, "Z");      // replace: ["a","X","Z","d","e"]

sort — home of the single most famous array gotcha in JS:

[10, 9, 80, 3].sort()             // [10, 3, 80, 9] ?! — default sort converts
                                  // elements to STRINGS and sorts alphabetically
[10, 9, 80, 3].sort((a, b) => a - b)  // [3, 9, 10, 80] — always pass a comparator
[10, 9, 80, 3].sort((a, b) => b - a)  // [80, 10, 9, 3] — descending

// Comparator contract — same as Java's Comparator.compare(a, b):
//   negative → a first · positive → b first · 0 → keep order (sort is stable)
people.sort((a, b) => a.age - b.age);            // by number field
people.sort((a, b) => a.name.localeCompare(b.name)); // by string field

// sort AND reverse both MUTATE. To sort a copy:
const sorted = [...nums].sort((a, b) => a - b);  // spread-copy first (§6)
nums.toSorted((a, b) => a - b);                  // ES2023: non-mutating twin (also toReversed, toSpliced)

3 · The searchers: indexOf, includes, find, some, every

const nums = [5, 12, 8, 12];
nums.indexOf(12)        // 1 — first index, or -1 if absent (uses === )
nums.includes(8)        // true — cleaner than indexOf !== -1; also finds NaN

const users = [{ id: 1, name: "Asha" }, { id: 2, name: "Bo" }];
// indexOf can't find objects (=== compares references — Lesson 3). Use a predicate:
users.find(u => u.id === 2)       // { id: 2, name: "Bo" } — first match, else undefined
users.findIndex(u => u.id === 2)  // 1 — its index, else -1

nums.some(n => n > 10)    // true  — does ANY element pass? (Java: anyMatch)
nums.every(n => n > 0)    // true  — do ALL elements pass?  (Java: allMatch)
// Both short-circuit, like && / || across the array.

4 · The big three: map, filter, reduce

These are the heart of modern JS — Java 8 streams without the .stream()/.collect() ceremony. All three are non-mutating: they read your array and produce something new. 

const prices = [100, 250, 40, 999];

// MAP — transform every element; same length out as in
prices.map(p => p * 1.18)              // [118, 295, 47.2, 1178.82] — add GST
users.map(u => u.name)                 // ["Asha","Bo"] — extract a field (constant use)
prices.map((p, i) => `#${i}: ${p}`)    // callback also receives the index

// FILTER — keep elements that pass the test; 0..n length out
prices.filter(p => p < 200)            // [100, 40]

// Chaining — reads like a sentence (Java: stream().filter().map().toList())
prices.filter(p => p < 500).map(p => p * 1.18)   // [118, 295, 47.2]

reduce deserves a slow walkthrough, because it's the general-purpose "boil an array down to one value" machine, and interviews probe it. Signature: arr.reduce((accumulator, element) => newAccumulator, initialValue). The callback runs once per element; whatever it returns becomes the accumulator for the next round; the final accumulator is the answer. 

// SUM — watch the accumulator flow:
[1, 2, 3, 4].reduce((acc, n) => acc + n, 0)
//  round 1: acc=0,  n=1 → returns 1
//  round 2: acc=1,  n=2 → returns 3
//  round 3: acc=3,  n=3 → returns 6
//  round 4: acc=6,  n=4 → returns 10 ← final result

// MAX — the accumulator can be a "best so far":
[3, 9, 4].reduce((best, n) => n > best ? n : best, -Infinity)   // 9

// COUNTING — the accumulator can be an OBJECT used as a tally:
["js", "java", "js", "sql", "js"].reduce((tally, lang) => {
  tally[lang] = (tally[lang] ?? 0) + 1;
  return tally;
}, {})
// → { js: 3, java: 1, sql: 1 }

// GROUP BY — the interview classic: bucket objects by a key
const students = [
  { name: "Asha", year: 3 }, { name: "Bo", year: 2 }, { name: "Cal", year: 3 }
];
students.reduce((groups, s) => {
  (groups[s.year] ??= []).push(s);   // ??= : create the bucket if missing (Lesson 5)
  return groups;
}, {})
// → { 2: [Bo], 3: [Asha, Cal] }

// Omit initialValue → first element becomes acc (fine for sums; throws on []. Prefer passing it.)
Interview one-liner "map transforms 1-to-1, filter selects 0-to-n, reduce folds n-to-1 — anything, in fact: sum, max, counts, groupBy, even map and filter themselves can be written as reduce. All three are non-mutating higher-order functions on Array.prototype."

Rounding out the toolkit:

[1, [2, [3, [4]]]].flat()      // [1, 2, [3, [4]]] — one level by default
[1, [2, [3, [4]]]].flat(Infinity) // [1, 2, 3, 4]
sentences.flatMap(s => s.split(" ")) // map then flatten one level — words from sentences
["a", "b", "c"].join("-")      // "a-b-c" — array → string (String.join in Java)
[1, 2].concat([3, 4], 5)       // [1,2,3,4,5] — non-mutating merge (spread does this too)
new Array(4).fill(0)           // [0,0,0,0] — initialize; beware fill(obj) shares ONE object
Array.from({ length: 5 }, (_, i) => i * i)  // [0,1,4,9,16] — build from scratch
nums.forEach(n => console.log(n))  // just loop — returns undefined, can't break/chain

5 · Destructuring — unpacking in one line

Destructuring mirrors construction: the literal syntax on the left of = pulls values out instead of putting them in. Java has nothing like it (records get close); JS uses it everywhere — React hooks return [state, setState], Express handlers destructure req, every import list is a destructure. 

// ARRAY destructuring — position-based
const [first, second] = [10, 20, 30];   // first=10, second=20 (30 ignored)
const [, , third] = [10, 20, 30];       // skip with holes: third=30
const [head, ...tail] = [1, 2, 3, 4];   // rest: head=1, tail=[2,3,4]
let a = 1, b = 2;
[a, b] = [b, a];                        // SWAP without a temp variable — interview party trick

// OBJECT destructuring — name-based (order irrelevant)
const user = { id: 7, name: "Asha", address: { city: "Delhi", pin: 110078 } };
const { name, id } = user;              // name="Asha", id=7
const { name: userName } = user;        // RENAME: variable is userName ("name" stays a key)
const { role = "student" } = user;      // DEFAULT: used only if the value is undefined
const { address: { city } } = user;     // NESTED: city="Delhi" (address itself NOT bound)
const { id: uid, ...rest } = user;      // rest = everything else: { name, address }

// IN PARAMETERS — the killer use: named arguments, Java-style builders not needed
function connect({ host, port = 5432, ssl = false }) {
  return `${host}:${port} ssl=${ssl}`;
}
connect({ host: "db.local", ssl: true });   // caller passes one readable object

for (const [key, value] of Object.entries(user)) { }  // destructure per iteration

6 · Spread and rest — three dots, two meanings

Same token ..., opposite directions. Spread (in a call or literal) explodes a collection into individual pieces. Rest (in a parameter list or destructuring pattern) gathers pieces into a collection. Where it appears tells you which one it is. 

// SPREAD in array literals — copy / merge / insert
const base = [2, 3];
const copy   = [...base];              // shallow copy (replaces slice())
const merged = [1, ...base, 4];        // [1, 2, 3, 4]

// SPREAD in calls — array → separate arguments (replaces apply, Lesson 3)
Math.max(...[5, 9, 2])                 // 9

// SPREAD in object literals — copy / merge; later keys WIN
const defaults = { theme: "dark", lang: "en" };
const config = { ...defaults, lang: "hi" };   // { theme: "dark", lang: "hi" }
const updated = { ...user, year: 4 };         // "copy with one change" — THE React
                                              // state-update idiom you'll write daily

// REST — the gatherer (already met in Lessons 2 and §5)
function sum(...nums) { return nums.reduce((a, n) => a + n, 0); }
const [winner, ...losers] = ["A", "B", "C"];

Critical caveat: spread copies are shallow — one level deep. Nested objects are shared references (copy.address === user.address after {...user}). Deep copying is a Lesson 5 topic (structuredClone).

7 · Four ways to loop — and which to use

const scores = [90, 85, 77];
for (let i = 0; i < scores.length; i++) { }  // CLASSIC — full control, verbose

8 · The iterable protocol — how for..of really works

Why does for..of work on arrays, strings, Maps, Sets — and your own objects if you wish? Because it doesn't know about any of them. It follows a contract, exactly like Java's Iterable/Iterator interfaces:

  • An iterable is any object with a method under the special key Symbol.iterator that returns an iterator. (Java: Iterable.iterator().)
  • An iterator is any object with a next() method returning { value, done }. (Java: hasNext()/next() fused into one call.)
// What for..of does under the hood:
const it = [10, 20][Symbol.iterator]();
it.next();   // { value: 10, done: false }
it.next();   // { value: 20, done: false }
it.next();   // { value: undefined, done: true } — loop ends

// Write your own iterable — a number range:
const range = {
  from: 1, to: 4,
  [Symbol.iterator]() {                 // computed key (§ Lesson 3) + method shorthand
    let current = this.from;
    const last = this.to;
    return {
      next: () => current <= last
        ? { value: current++, done: false }
        : { value: undefined, done: true }
    };
  }
};
for (const n of range) console.log(n);  // 1 2 3 4
[...range]                              // [1,2,3,4] — spread uses the SAME protocol!
const [x, y] = range;                   // so does array destructuring: x=1, y=2

9 · Generators — iterators without the boilerplate

Writing next() machinery by hand is tedious. A generator function (function*) writes it for you: call it and you get an iterator; each yield inside is one next() result. The magic: the function pauses at each yield and resumes exactly there on the next call — a function you can freeze mid-flight. Java has no equivalent (the closest is a hand-rolled Iterator or Stream.iterate). 

function* rangeGen(from, to) {
  for (let n = from; n <= to; n++) {
    yield n;                       // pause here, hand out n, wait to be resumed
  }
}

const g = rangeGen(1, 3);
g.next();   // { value: 1, done: false } — ran until the first yield, froze
g.next();   // { value: 2, done: false } — resumed, looped once, froze again
g.next();   // { value: 3, done: false }
g.next();   // { value: undefined, done: true } — function finished

for (const n of rangeGen(1, 4)) console.log(n);  // generators are iterable: 1 2 3 4

// LAZY + INFINITE — impossible with arrays, natural with generators:
function* fibonacci() {
  let [a, b] = [0, 1];
  while (true) {                   // infinite loop, yet safe: values are made ON DEMAND
    yield a;
    [a, b] = [b, a + b];
  }
}
const fib = fibonacci();
fib.next().value; fib.next().value; fib.next().value;  // 0, 1, 1 — take only what you need

// The range object from §8, rewritten — compare the sizes:
const range2 = {
  from: 1, to: 4,
  *[Symbol.iterator]() {           // a generator AS the Symbol.iterator method
    for (let n = this.from; n <= this.to; n++) yield n;
  }
};

Where you'll meet them: Redux-Saga, some async iteration patterns, and interviews. Day-to-day you'll consume iterables constantly and write generators rarely — but explaining lazy evaluation with a fibonacci generator is a strong interview move.

10 · Map, Set, WeakMap, WeakSet

ES6 added real collections — direct cousins of java.util. First, why a Map when objects already hold key–value pairs?

const m = new Map();
m.set("name", "Krish");           // fluent: set returns the map
m.set(42, "the answer");          // number key STAYS a number (objects stringify keys!)
const objKey = { id: 1 };
m.set(objKey, "metadata");        // OBJECT keys — impossible with plain objects

m.get(objKey)    // "metadata"
m.has(42)        // true
m.size           // 3 — a property (objects need Object.keys(o).length)
m.delete(42);
for (const [k, v] of m) { }       // directly iterable, insertion order guaranteed
new Map(Object.entries(obj))      // object → Map;  Object.fromEntries(m) goes back

Set = java.util.HashSet: unique values, fast membership checks:

const s = new Set([1, 2, 2, 3, 2]);
s.size            // 3 — duplicates dropped on entry
s.add(4); s.has(2); s.delete(1);
[...new Set(arr)] // THE dedupe idiom — memorize it

// Set.has is O(1); arr.includes is O(n) — for many lookups, build a Set first:
const allowed = new Set(["admin", "editor"]);
roles.filter(r => allowed.has(r));

WeakMap / WeakSet — the "know what they're for" pair. Keys must be objects, and the collection holds them weakly: if nothing else references a key object, the garbage collector may reclaim it, entry and all (Java parallel: WeakHashMap). Consequence: not iterable, no size — you can't observe what the GC took. Use case: attaching metadata or caches to objects you don't own, without preventing their cleanup — this is how libraries tag DOM nodes without leaking memory. Interview line: "WeakMap = object-keyed map that doesn't block garbage collection; therefore non-iterable; used for metadata and caches."

11 · Interview questions this lesson answers

  • Q. "Difference between map and forEach?"
    map returns a new transformed array and is chainable; forEach returns undefined and exists purely for side effects. Neither mutates; neither can break. If you're building a result, use map.
  • Q. "slice vs splice?"
    slice(start, end) copies a portion, non-mutating, negatives allowed. splice(start, deleteCount, ...items) removes/inserts in place — it mutates and returns the removed elements.
  • Q. "Why does [10, 9, 80].sort() give [10, 80, 9]... wait, [10, 3, 80, 9]?"
    Default sort coerces elements to strings and sorts lexicographically ("10" < "3" < "80" < "9"). Always pass a comparator: (a, b) => a - b. Also note sort mutates; use toSorted or spread-copy to preserve the original.
  • Q. "Explain reduce."
    Folds an array to a single value: the callback receives (accumulator, element) and returns the next accumulator, seeded by initialValue. Demonstrate with sum, then with groupBy — an object accumulator whose buckets you push into — to show it can build anything.
  • Q. "for..of vs for..in?"
    for..of iterates values of anything implementing the iterable protocol (arrays, strings, Map, Set). for..in iterates enumerable keys (as strings) of an object, including inherited ones — wrong tool for arrays.
  • Q. "What makes something iterable? What's a generator?"
    Iterable = has a Symbol.iterator method returning an iterator (next() → {value, done}) — JS's version of Java's Iterable/Iterator. A generator (function*/yield) auto-builds an iterator from a function that pauses at each yield — enabling lazy and even infinite sequences.
  • Q. "Map vs plain object? Set vs array?"
    Map: any key type, .size, ordered direct iteration, no prototype pollution — a true HashMap; objects suit fixed string-keyed records. Set: uniqueness + O(1) has vs array's O(n) includes; [...new Set(arr)] dedupes. Weak variants hold object keys without blocking GC, so they're non-iterable — used for metadata/caches.
  • Q. "Is spread a deep copy?"
    No — shallow, one level. Nested objects/arrays are shared references. Deep options: structuredClone (proper) or the JSON trick (lossy) — Lesson 5.
