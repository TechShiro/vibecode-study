Web Security, XSS, CSRF & Auth.js

Hardening web frontends and backends against exploits while implementing modern OAuth.

1 · The One Idea

The two most infamous vulnerabilities in web engineering are XSS (Cross-Site Scripting) and CSRF (Cross-Site Request Forgery). Storing authentication tokens in browser localStorage is fatal because any XSS injection script can execute localStorage.getItem('token') and send it to an attacker server! Production web security stores session tokens in HttpOnly, Secure, SameSite=Strict Cookies, which JavaScript code is physically forbidden from accessing.

2 · XSS vs CSRF Comparison

Vulnerability How It Works The Defense
XSS (Cross-Site Scripting) An attacker injects malicious <script> tags into user comments or profile fields, which execute in other users' browsers. Sanitize inputs, use Content Security Policy (CSP), never use dangerouslySetInnerHTML.
CSRF (Cross-Site Request Forgery) A malicious website tricks a user's browser into executing an unauthorized HTTP request to a banking site where the user is currently logged in. Use SameSite=Strict cookie flags and anti-CSRF challenge tokens.

3 · Modern Authentication with Auth.js (NextAuth)

import NextAuth from 'next-auth';
import GitHub from 'next-auth/providers/github';
import Google from 'next-auth/providers/google';

export const { handlers, signIn, signOut, auth } = NextAuth({
  providers: [
    GitHub({ clientId: process.env.GITHUB_ID, clientSecret: process.env.GITHUB_SECRET }),
    Google({ clientId: process.env.GOOGLE_ID, clientSecret: process.env.GOOGLE_SECRET }),
  ],
  callbacks: {
    authorized({ auth }) {
      return !!auth?.user; // Require login for protected routes
    },
  },
});
