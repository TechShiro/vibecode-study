Process Concept, Memory Layout & PCB

From static executable file on disk to dynamic living process inside virtual memory.

↑ Back to Course IndexModule A — Process & Architecture

1 · The One Idea

A Program is passive code sitting dormant on your SSD (e.g. chrome.exe). A Process is an active program in execution. The operating system represents each active process in memory using a C struct called the Process Control Block (PCB) (task_struct in Linux), tracking its Program Counter, register states, open file descriptors, and memory maps.

2 · The Process Memory Layout

  • Stack: Grows downward; holds local function variables, parameters, and return addresses.
  • Heap: Grows upward; holds dynamically allocated memory (malloc in C, new in Java/JS).
  • BSS Segment: Uninitialized global and static variables (zero-filled by OS).
  • Data Segment: Explicitly initialized global and static variables.
  • Text (Code) Segment: Compiled machine instructions (marked Read-Only).

3 · The 5-State Process Lifecycle

New
Ready (in queue)
Running (on CPU)
Terminated

If a running process issues an I/O request (disk read), it moves to Waiting / Blocked state and relinquishes the CPU until I/O completes!
