Threads, Multithreading & Context Switching

Lightweight execution units, kernel vs user threads, and the hardware cost of context switching.

↑ Back to Course IndexModule A — Process & Architecture

1 · The One Idea

A Thread is the smallest schedulable unit of CPU execution. While different processes have completely isolated address spaces, threads belonging to the same process share their Code, Data, Heap, and Open Files. Each thread has its own private Program Counter, CPU Registers, and Call Stack.

2 · Process vs Thread Comparison

FeatureProcessThread
Memory IsolationCompletely isolated; cannot touch neighbor memory.Shared heap and memory; bugs can corrupt sibling threads.
Creation CostHeavy (must allocate page tables, file descriptors, address space).Lightweight (allocates only a thread stack ~1MB).
Context Switch OverheadHigh (Must flush CPU TLB caches and swap page directories).Low (Page tables remain identical; only registers swapped).

3 · Threading Models: 1:1 vs N:1 vs M:N

  • 1:1 Model (Linux pthreads, Java threads): Every user thread maps to a native kernel thread. Full multicore parallelism, but OS thread creation overhead caps concurrency at ~10,000 threads.
  • M:N Green Threads / Fibers (Go Goroutines, Java 21 Virtual Threads): Thousands of lightweight user threads scheduled onto a small pool of OS kernel worker threads using cooperative work-stealing schedulers!
