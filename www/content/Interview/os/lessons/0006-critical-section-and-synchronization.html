The Critical Section Problem & Synchronization

The theoretical requirements and hardware instructions that guarantee mutual exclusion.

↑ Back to Course IndexModule B — Synchronization & Deadlocks

1 · The One Idea

A Critical Section is a segment of code where processes access shared resources (shared variables, files, tables). To guarantee correctness under concurrent execution, any synchronization solution must satisfy Three Mandatory Criteria:

  1. Mutual Exclusion: If process $P_i$ is executing in its critical section, no other process can enter.
  2. Progress: If no process is in its critical section and some wish to enter, selection cannot be postponed indefinitely.
  3. Bounded Waiting: There must be a bound on the number of times other processes can enter before a waiting process is granted access (prevents starvation).

2 · Peterson's Algorithm (Software Solution for 2 Processes)

// Process i:
flag[i] = true;
turn = j;
while (flag[j] && turn == j); // Busy wait

/* CRITICAL SECTION */

flag[i] = false; // Exit section

Satisfies all 3 criteria, but fails on modern multicore CPUs due to out-of-order execution and memory reordering unless memory barriers are used.

3 · Hardware Synchronization: Atomic Test-And-Set

Modern CPUs solve this in hardware using atomic instructions like TestAndSet and CompareAndSwap (CAS), executing read-modify-write as an uninterruptible bus cycle.
