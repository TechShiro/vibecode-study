CPU Scheduling Algorithms & MLFQ

How operating system schedulers maximize CPU utilization while keeping interactive desktop apps responsive.

↑ Back to Course IndexModule A — Process & Architecture

1 · The One Idea

When multiple processes are in the Ready queue, the CPU Scheduler (Short-Term Scheduler) decides which process gets the CPU next. The dispatcher performs the actual context switch. Scheduling balances two competing goals: Throughput (finishing batch jobs quickly) vs Response Time (giving interactive keystrokes sub-10ms feedback).

2 · The Core Scheduling Algorithms

AlgorithmPreemptive?Pros & Cons
FCFS (First-Come, First-Served)Non-preemptiveSimple FIFO queue. Convoy Effect: Short processes get stuck waiting behind one massive CPU-bound process.
SJF / SRTF (Shortest Job First)Preemptive (SRTF)Mathematically optimal minimum average waiting time! But impossible to know future burst times in advance; risks starving long processes.
Round Robin (RR)PreemptiveEach process gets a fixed Time Quantum (e.g. 10ms). If quantum is too large, degrades to FCFS. If too small, context switch overhead dominates CPU.
Priority SchedulingBothHigher priority jobs run first. Vulnerable to Starvation. Solved via Aging (gradually boosting priority of waiting jobs).

3 · The Production Gold Standard: Multilevel Feedback Queue (MLFQ)

Devised by Fernando Corbató (Turing Award), MLFQ learns process behavior on the fly:

  • Has multiple priority queues (Queue 0 = highest, Queue 3 = lowest).
  • Interactive I/O jobs (short bursts) stay at the highest priority queue, getting instant responsiveness.
  • CPU-heavy compute jobs (crunching numbers) use up their full time slice and automatically sink to lower priority queues!
