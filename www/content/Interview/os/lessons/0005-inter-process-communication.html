Inter-Process Communication (IPC)

How isolated processes safely exchange data across memory barriers.

↑ Back to Course IndexModule A — Process & Architecture

1 · The One Idea

Because the OS enforces strict memory protection, Process A cannot read bytes from Process B. When processes must collaborate (e.g. a web server talking to a database process), they use IPC mechanisms. IPC splits into two fundamental models: Shared Memory (fastest) and Message Passing (safest).

2 · The 5 Major IPC Mechanisms

  1. Anonymous Pipes (|): Unidirectional byte stream between related parent/child processes (e.g. ls | grep "txt").
  2. Named Pipes (FIFOs): Bidirectional file-system pipes allowing unrelated processes to communicate.
  3. Shared Memory (POSIX shmget / mmap): OS maps the exact same physical RAM pages into the virtual address spaces of both processes! Fastest possible IPC (zero kernel copying), but requires explicit mutex synchronization!
  4. Message Queues: Kernel-managed structured message buffers with priority ordering.
  5. Unix Domain Sockets & Network Sockets: High-performance bidirectional streams using standard socket file descriptors.
