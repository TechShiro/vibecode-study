OS Architecture, Dual Mode & System Calls

How hardware CPU rings protect operating system integrity from runaway user applications.

↑ Back to Course IndexModule A — Process & Architecture

1 · The One Idea

An Operating System is fundamentally a resource allocator and control program. If user programs could write directly to physical hard drives or network chips, a single bug in a video game could wipe your family photos or freeze the CPU. Hardware CPUs solve this via Dual Mode Operation: the CPU switches between User Mode (Ring 3) (restricted instructions) and Kernel Mode (Ring 0) (privileged instructions). Whenever an app needs to read a file or open a socket, it executes a System Call, triggering a software trap to Kernel Mode.

2 · User Mode vs Kernel Mode

ModePrivilege LevelWhat is Allowed
User Mode (Ring 3)RestrictedGeneral computation in user memory. Cannot modify interrupt vectors or execute I/O instructions.
Kernel Mode (Ring 0)UnrestrictedFull access to CPU hardware, memory management unit (MMU), and physical hardware registers.

3 · The Lifecycle of a System Call

  1. App calls C library wrapper (e.g. read(fd, buffer, 1024)).
  2. Library places system call number in CPU register (e.g. RAX = 0 on Linux x86_64).
  3. Executes CPU instruction syscall (or int 0x80), triggering a hardware trap.
  4. CPU switches from Ring 3 to Ring 0 and jumps to the kernel's System Call Table.
  5. Kernel verifies arguments, executes device driver I/O, switches back to Ring 3, and returns control.
