The Producer-Consumer Pattern & Backpressure

Decoupling task generation from task execution using thread-safe bounded buffers.

↑ Back to Course Index Module N — Concurrency & Thread Safety

1 · The One Idea

In a multithreaded application, if producer threads (e.g. network socket readers) generate tasks faster than consumer threads (e.g. database writers) can process them, an unbounded queue will grow indefinitely until the JVM runs out of heap memory and crashes with java.lang.OutOfMemoryError. The Producer-Consumer Pattern coordinates threads through a Bounded Buffer (BlockingQueue), automatically applying Backpressure to slow down producers when the queue is full.

2 · How a Bounded BlockingQueue Coordinates Threads

Producer Thread
Bounded Queue (Capacity: 100)
Consumer Thread
  • put(item): Adds an item to the queue. If the buffer is full (100 items), the calling producer thread blocks and sleeps until a consumer removes an item!
  • take(): Removes and returns an item. If the buffer is empty, the consumer thread blocks and sleeps until a producer inserts an item!
  • Zero CPU wasted in busy-waiting loops! Handled efficiently by OS condition variables (Lock.newCondition()).

3 · Production Implementation with Java BlockingQueue

public class LogProcessor {
    // Fixed bounded buffer prevents OutOfMemoryError
    private final BlockingQueue<LogMessage> queue = new ArrayBlockingQueue<>(1000);

    public void start() {
        // Consumer thread
        Thread consumer = new Thread(() -> {
            try {
                while (!Thread.currentThread().isInterrupted()) {
                    LogMessage msg = queue.take(); // Blocks if queue empty
                    persistToDisk(msg);
                }
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });
        consumer.start();
    }

    public void submitLog(LogMessage msg) throws InterruptedException {
        queue.put(msg); // Blocks if queue full (Backpressure!)
    }
}
