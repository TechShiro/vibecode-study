Encapsulation & Information Hiding

Protecting your object's internal state and enforcing business invariants.

↑ Back to Course Index Module L — OOP Foundations

1 · The One Idea

Encapsulation is the bundling of data (attributes) and the methods that operate on that data into a single unit (class), while restricting direct access to internal implementation details (Data Hiding). At the zero level, encapsulation is NOT just making fields private and generating boilerplate getter and setter methods! Real encapsulation means protecting business invariants: making it physically impossible for external code to corrupt the object into an invalid state.

2 · The Flaw of Blind Getters/Setters

Look at this classic beginner mistake:

public class BankAccount {
    // Blind getter/setter exposes internal field to corruption
    private double balance;
    public double getBalance() { return balance; }
    public void setBalance(double b) { this.balance = b; }
}

// Somewhere in external code:
account.setBalance(-500000.0); // Balance corrupted! Invariant broken!

3 · True Encapsulation: Enforcing Invariants

An encapsulated class guards its own boundaries through intentional domain methods:

public class BankAccount {
    private double balance;

    public BankAccount(double initialDeposit) {
        if (initialDeposit < 0) {
            throw new IllegalArgumentException("Initial deposit cannot be negative");
        }
        this.balance = initialDeposit;
    }

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Deposit must be positive");
        this.balance += amount;
    }

    public void withdraw(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Withdrawal must be positive");
        if (amount > this.balance) throw new IllegalStateException("Insufficient funds");
        this.balance -= amount;
    }

    public double getBalance() { return balance; } // Read-only view
}
