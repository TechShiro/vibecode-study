Push vs Pull Architecture: The Social Feed Dilemma

How Twitter, Instagram, and LinkedIn architect personalized real-time timelines.

↑ Back to Course Index Module K — System Design Trade-offs

1 · The One Idea

When you open Twitter or Instagram, you see a custom feed built from hundreds of accounts you follow. When an author posts a tweet, when should the system do the heavy work of putting that tweet into their followers' timelines? Push Architecture (Fan-out on Write) prepares timelines ahead of time when tweets are posted. Pull Architecture (Fan-out on Read) waits until a user opens their app and queries the database on the fly.

2 · Push vs Pull Comparison

Aspect Push Model (Fan-out on Write) Pull Model (Fan-out on Read)
When work is done At Write Time. When Alice posts, her tweet ID is pushed into the Redis timeline lists of all 200 of her followers immediately. At Read Time. When Bob opens his app, the system runs: SELECT * FROM tweets WHERE author_id IN (follows) ORDER BY created_at DESC LIMIT 20.
Read Latency Blazing fast ($O(1)$ read from in-memory Redis list). Slow and expensive (heavy SQL JOIN across hundreds of authors on disk).
Write Cost High write amplification. 1 tweet requires updating thousands of Redis lists. Minimal. 1 tweet requires exactly 1 database row insert.
The Killer Bug The Celebrity Problem: If an account with 100 million followers tweets, the system must write 100,000,000 Redis entries, choking the queue for minutes! Read Load: If 50 million active users refresh their feeds every minute, database CPU spikes to 100%.

3 · The Real-World Winner: The Hybrid Model

Production systems like Twitter and Instagram use a Hybrid Architecture:

  • For 99% of normal users (< 20,000 followers): Use Push (Fan-out on Write). Timelines are pre-computed in Redis for instant $O(1)$ loading.
  • For Celebrities (> 20,000 followers): Do NOT fan-out on write! Store their tweets in a separate author table.
  • When Bob opens Twitter: Bob's app fetches his pre-computed Redis feed AND fetches the latest tweets of the 2 celebrities he follows, merging them in application memory in < 5ms!
