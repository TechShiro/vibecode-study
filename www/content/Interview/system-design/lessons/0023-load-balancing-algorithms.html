Load Balancing Algorithms & Architecture

Distributing incoming user traffic uniformly across server pools to eliminate bottlenecks.

1 · The One Idea

If 100,000 users connect to a single web server, that server crashes. If you add 10 web servers, you need a smart traffic cop standing at the front door to inspect each incoming request and route it to an available, healthy backend server. That traffic cop is a Load Balancer (LB).

2 · Layer 4 vs Layer 7 Load Balancing

Feature Layer 4 Load Balancer (Transport) Layer 7 Load Balancer (Application)
What it inspects IP addresses and TCP/UDP ports only. Cannot see HTTP headers, cookies, or URLs. Full HTTP payload: URLs, cookies, HTTP headers, request body.
Routing capability Pure packet forwarding. Cannot route by path (e.g. /api vs /images). Smart routing (e.g., /video to Video microservice, /pay to Payment service).
Performance Blazing fast (minimal CPU overhead, line-rate throughput). Slightly more CPU-intensive (must decrypt TLS and parse HTTP text).
Examples AWS NLB (Network Load Balancer), HAProxy (TCP mode), IPVS. AWS ALB (Application Load Balancer), Nginx, Envoy, Traefik.

3 · The Core Balancing Algorithms

  1. Round Robin: Sends Request 1 to Server A, Request 2 to Server B, Request 3 to Server C, then loops back. Great when all servers have identical hardware and requests take equal processing time.
  2. Weighted Round Robin: Assigns weights based on server specs (e.g., Server A has 32 cores = weight 3; Server B has 8 cores = weight 1). Server A receives 3 requests for every 1 request Server B gets.
  3. Least Connections: Directs traffic to the server currently handling the fewest active connections. Ideal for long-lived sessions (e.g., chat apps, file uploads) where round robin would cause uneven pile-ups.
  4. IP Hash: Computes Hash(Client_IP) % N to ensure a given user consistently routes to the same backend server (useful for session affinity, though modern apps prefer stateless JWTs).
  5. Power of Two Random Choices: Picks two random servers and routes to whichever of the two has fewer connections. Surprisingly outperforms Least Connections in large distributed clusters by eliminating herd behavior!

4 · Health Checks: Removing Dead Servers

A load balancer continuously pings each backend server (e.g., GET /healthz every 5 seconds). If a server returns an error or times out 3 times in a row, the LB instantly cuts it from the pool with zero dropped user requests!
