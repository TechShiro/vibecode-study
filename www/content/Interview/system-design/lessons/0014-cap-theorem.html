The CAP Theorem & PACELC

The inescapable trade-off every distributed engineer must make when networks fail.

1 · The One Idea

The CAP Theorem (proven by Eric Brewer and Seth Gilbert) states that a distributed data store can simultaneously provide at most two of the following three guarantees: Consistency (C), Availability (A), and Partition Tolerance (P).

However, in the real physical world, network cables can get cut, routers can crash, and packets get dropped. Therefore, Partition Tolerance (P) is mandatory. The real decision you make as a system designer is: "When a network partition happens, do I choose Consistency (CP) or Availability (AP)?"

2 · Defining the Three Letters

  • Consistency (C): Every read receives the most recent write or an error. All nodes see identical data at the same moment.
  • Availability (A): Every non-failing node returns a successful response for every request, without guaranteeing that it contains the most recent write.
  • Partition Tolerance (P): The system continues to operate despite an arbitrary number of messages being dropped or delayed by the network between nodes.

Imagine a client writes data to Node A. Because the network link between Node A and Node B is severed, Node A cannot replicate the write to Node B.

Now another client asks Node B for that data. What should Node B do?

Choice Behavior Examples
CP (Consistency + Partition Tolerance) Node B refuses to respond or returns an error because it knows it cannot guarantee fresh data. Sacrifices availability to protect correctness. Google Spanner, HBase, ZooKeeper, etcd, MongoDB (default config).
AP (Availability + Partition Tolerance) Node B returns its local, potentially stale data immediately without failing. Sacrifices consistency to stay online. Apache Cassandra, Amazon DynamoDB, CouchDB, DNS.

4 · Beyond CAP: The PACELC Theorem

The CAP theorem only talks about what happens during rare network partitions. But 99.9% of the time, the network is working perfectly! What trade-offs do we make during normal operation? Computer scientist Daniel Abadi created the PACELC Theorem to answer this:

PACELC Formula

If there is a Partition: choose between Availability or Consistency.

Else (normal operation): choose between Latency or Consistency.

  • PC / EC (e.g., BigTable, Spanner): Under partition, pick consistency; normal operation, still pay latency cost to maintain strict consistency.
  • PA / EL (e.g., DynamoDB, Cassandra): Under partition, stay available; normal operation, return data with ultra-low latency, accepting eventual consistency.
