1 · The One Idea

In low-level system design interviews and technical design documents, you do not write 5,000 lines of production code. You draw UML (Unified Modeling Language) Diagrams to communicate relationships between classes, interfaces, and state machines with absolute clarity before writing code.

2 · The 5 Core Relationships in UML Class Diagrams

Relationship Visual Notation Meaning & Code Example
Inheritance (Generalization) Solid line with hollow triangle arrow ──▷ "IS-A" relationship.
class Dog extends Animal
Realization (Implementation) Dashed line with hollow triangle arrow --▷ Class implements an Interface.
class PayPal implements PaymentMethod
Composition (Strong HAS-A) Solid line with filled black diamond ◆── Child cannot exist without Parent (Shared lifecycle).
Car ◆── Engine (If Car is crushed, Engine is destroyed).
Aggregation (Weak HAS-A) Solid line with hollow white diamond ◇── Child exists independently of Parent.
Department ◇── Teacher (If Department closes, Teacher still exists).
Association / Dependency Simple arrow ──> or dashed --> Class A uses Class B as a parameter in a method.
void print(Document doc)

3 · UML Sequence Diagrams: Tracing Interactions Over Time

While class diagrams show static structure, Sequence Diagrams show dynamic time execution from top to bottom:

  • Lifelines (Vertical Dashed Lines): Represent the lifetime of an object instance during the scenario.
  • Synchronous Messages (Solid Arrow): Caller blocks waiting for response.
  • Asynchronous Messages (Open Stick Arrow): Non-blocking message / event fire-and-forget.
  • Return Message (Dashed Arrow): Value returned to caller.
