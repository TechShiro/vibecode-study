Creational Design Patterns

Patterns that abstract and control object instantiation mechanics.

↑ Back to Course Index Module M — Design Patterns

1 · The One Idea

Directly instantiating objects using the new keyword hardcodes dependencies, spreads object creation logic across your entire codebase, and makes unit testing difficult. Creational Design Patterns decouple the client from the instantiation process, giving you complete control over how objects are created, configured, and managed.

2 · The 4 Essential Creational Patterns

1. Singleton Pattern (Thread-Safe Bill Pugh / Enum)

Ensures a class has only one instance and provides a global point of access (e.g., ThreadPool, Configuration Manager).

// Thread-Safe Bill Pugh Singleton (Lazy + Zero Locking Overhead)
public class DatabaseConnectionPool {
    private DatabaseConnectionPool() {} // Private constructor

    private static class Holder {
        private static final DatabaseConnectionPool INSTANCE = new DatabaseConnectionPool();
    }

    public static DatabaseConnectionPool getInstance() {
        return Holder.INSTANCE;
    }
}

2. Factory Method Pattern

Defines an interface for creating an object, but lets subclasses decide which class to instantiate.

public interface Notification { void notifyUser(); }
public class SMSNotification implements Notification { public void notifyUser() { /* ... */ } }
public class EmailNotification implements Notification { public void notifyUser() { /* ... */ } }

public class NotificationFactory {
    public static Notification create(String type) {
        if ("SMS".equalsIgnoreCase(type)) return new SMSNotification();
        if ("EMAIL".equalsIgnoreCase(type)) return new EmailNotification();
        throw new IllegalArgumentException("Unknown type: " + type);
    }
}

3. Builder Pattern (Fluent API)

Solves the Telescoping Constructor Anti-Pattern when an object has 10+ optional parameters.

HttpRequest request = new HttpRequest.Builder()
    .url("https://api.example.com")
    .method("POST")
    .timeout(5000)
    .header("Authorization", "Bearer token")
    .build();

4. Prototype Pattern

Creates new objects by cloning an existing instance rather than building from scratch. Ideal when creating an object is computationally expensive (e.g. requires loading 50MB of 3D mesh data from disk).
