TCP vs UDP

The two transport layer protocols that power every single byte exchanged on the internet.

↑ Back to Course Index Module E — Networking

1 · The One Idea

At Layer 4 of the OSI model, internet traffic must choose between two philosophies: TCP (Transmission Control Protocol) guarantees that every single packet arrives in exact order with zero loss, sacrificing raw speed to ensure 100% reliability. UDP (User Datagram Protocol) fires packets like bullets with zero setup and no guarantee of delivery, achieving maximum speed and ultra-low latency.

2 · TCP: The Reliable Workhorse

The 3-Way Handshake

Before sending any data, TCP establishes a virtual connection:

Client: SYN
Server: SYN-ACK
Client: ACK (Connection Established!)

Key Features of TCP:

  • In-Order Delivery: Packets are assigned sequence numbers. If Packet 3 arrives before Packet 2, TCP buffers Packet 3 until Packet 2 arrives (Head-of-Line Blocking).
  • Retransmission (ACKs): If an acknowledgment is not received within a timeout, the packet is automatically resent.
  • Congestion Control: TCP dynamically throttles speed based on network congestion algorithms (e.g., Cubic, BBR).

3 · UDP: Fast and Fearless

UDP has no connection setup, no handshakes, no acknowledgments, and no retransmissions. It simply wraps data in an 8-byte header and blasts it across the wire.

If a packet drops, UDP does not care. In real-time video games (like Counter-Strike) or live VoIP calls (Zoom), re-sending a dropped packet from 300ms ago is completely useless because that game frame or audio sound has already passed!

4 · Comparison Table

Feature TCP UDP
Connection Type Connection-oriented (3-way handshake) Connectionless
Reliability 100% Guaranteed (Retransmits lost packets) Best-effort (Packets may be dropped)
Ordering Strictly preserved No ordering guarantee
Header Size 20–60 bytes 8 bytes
Speed Slower due to ACK overhead and congestion control Blazing fast, minimal latency
Use Cases Websites (HTTP/1.1 & HTTP/2), Email, File transfers (FTP), Database connections Live video calls, Multiplayer gaming, DNS queries, Video streaming (WebRTC), HTTP/3 (QUIC)

5 · The Future: HTTP/3 and QUIC

Historically, the web ran on TCP. But TCP's Head-of-Line blocking was slowing down modern web pages. Google engineered QUIC, a protocol built on top of UDP that implements reliability, encryption (TLS 1.3), and multiplexing in user space. QUIC is now the standard underlying HTTP/3!
