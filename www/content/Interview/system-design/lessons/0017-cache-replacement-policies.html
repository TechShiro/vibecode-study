Cache Replacement (Eviction) Policies

How cache systems decide which data to throw away when memory is 100% full.

↑ Back to Course Index Module D — Caching

1 · The One Idea

RAM is expensive and strictly bounded (e.g., 32 GB). Eventually, your cache will fill up completely. When a new write arrives, the cache cannot simply say "No room!". It must automatically evict (discard) an old key to make room. Cache Replacement Policies are the algorithms used to select the best victim key to evict so that the remaining keys produce the highest possible future hit ratio.

2 · The Eviction Algorithms

1. LRU (Least Recently Used) — The King of Caching

Evicts the item that has not been accessed for the longest period of time. Grounded in the principle of temporal locality: if you accessed a piece of data recently, you will likely access it again soon.

Implementation: Built using a Doubly Linked List + Hash Map:

  • Hash Map provides $O(1)$ lookup for any key.
  • Doubly Linked List maintains access order: whenever a key is accessed, move its node to the front (Head) in $O(1)$.
  • When full, remove the node at the tail (Tail) in $O(1)$.

2. LFU (Least Frequently Used)

Evicts the item with the lowest total access count. Useful when some items are universally popular over long horizons.

Flaw: An item accessed 10,000 times during a morning flash sale will stay stuck in cache all afternoon even when nobody searches for it anymore (frequency pollution). Solved by decaying counters over time.

3. FIFO (First In, First Out)

Evicts the oldest item based solely on when it was added, regardless of how frequently or recently it was accessed. Simple queue implementation, but performs poorly for real-world workloads.

4. Clock (Second Chance Algorithm)

A memory-efficient approximation of LRU. Operates as a circular buffer with a reference bit (0 or 1). When looking for a victim, the pointer moves clockwise: if bit is 1, set to 0 and skip; if bit is 0, evict that page.

3 · Comparison Table

Algorithm Time Complexity Space Overhead Common Use Case
LRU $O(1)$ get / put 2 pointers per node (Prev/Next) Default in 90% of caches (web apps, Redis, CPU cache).
LFU $O(1)$ via min-heap / freq buckets Access counters + buckets Content streaming, static asset distribution.
FIFO $O(1)$ Lowest (simple queue) Simple pipeline buffers where order strictly mirrors flow.
Random Eviction $O(1)$ Zero overhead Redis allkeys-random when keys have uniform access patterns.
