Distributed Systems Fundamentals: Consensus & Raft

How computers agree on reality across unreliable networks.

↑ Back to Course Index Bonus HLD Fundamentals

1 · The One Idea

In a single machine, there is one CPU and one memory bus — truth is absolute. In a distributed cluster of 5 servers, network cables can disconnect, machines can experience garbage collection pauses for 10 seconds, and messages can arrive out of order. If Server 1 thinks it is the leader, but Server 2 also thinks it is the leader, both will accept conflicting writes, causing fatal data corruption (Split-Brain). Distributed Consensus algorithms (like Raft and Paxos) mathematically guarantee that a cluster of machines agree on a sequence of decisions even when some nodes fail.

2 · How the Raft Consensus Algorithm Works (Zero-Level)

Raft breaks consensus into three simple, understandable subproblems:

1. Leader Election

  • Nodes start in Follower state. Each follower has a randomized election countdown timer (e.g. 150ms to 300ms).
  • If a follower doesn't hear a heartbeat from the leader before its timer expires, it promotes itself to Candidate and votes for itself.
  • It sends RequestVote messages to all peers.
  • If it receives votes from a Strict Majority (Quorum: $\lfloor N/2 floor + 1$) of nodes, it becomes the new official Leader!

2. Log Replication

  • All client writes must go directly to the Leader.
  • The leader writes the command to its local log and sends AppendEntries RPCs to all followers.
  • Once a majority of followers acknowledge writing the log entry to their disks, the leader commits the entry and returns success to the client.

3. Safety (Preventing Split-Brain)

Quorum Math Prevents Split-Brain In a 5-node cluster, a majority is 3. If a network partition splits the cluster into 2 nodes on the East Coast and 3 nodes on the West Coast: The East Coast group (2 nodes) cannot form a majority (2 < 3) and refuses to elect a leader or accept writes. Only the West Coast group (3 nodes) has a quorum and remains active. There can never be two simultaneous majorities!

3 · Real-World Consensus Engines

  • etcd: Powers the brain of every Kubernetes cluster using Raft.
  • ZooKeeper: Historically powered Kafka and Hadoop coordination (Zab protocol).
  • CockroachDB & TiDB: Uses Raft per range partition for distributed SQL consistency.
