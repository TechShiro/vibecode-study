Polymorphism & Dynamic Dispatch

Enabling single lines of code to seamlessly execute hundreds of different behaviors.

↑ Back to Course Index Module L — OOP Foundations

1 · The One Idea

Polymorphism (Greek for "many forms") is the ability of different objects to respond to the same method call in their own unique way. In a payment system, you don't write if (type == CREDIT_CARD) ... else if (type == PAYPAL) ... else if (type == CRYPTO). Instead, you declare paymentProcessor.pay(amount), and the JVM automatically invokes the correct logic at runtime. This completely eliminates messy, bug-ridden conditional chains!

2 · Compile-Time vs Runtime Polymorphism

Type Mechanism How it Works
Compile-Time (Static) Method Overloading Multiple methods with the exact same name but different parameter signatures within the same class. Resolved by the compiler during compilation (Static Binding).
Runtime (Dynamic) Method Overriding A subclass provides a specific implementation of a method already declared in its parent class/interface. Resolved at runtime based on the actual object instance in memory (Dynamic Dispatch).

3 · Under the Hood: Virtual Method Table (vtable)

How does the JVM know which method to run when looking at an interface reference? Shape s = new Circle(); s.draw();

  • Every Java class loaded in memory has a hidden vtable (Virtual Method Table), which is an array of memory pointers pointing to its actual method bytecodes.
  • When s.draw() is called, the JVM looks up the object header in the Heap, reads its class metadata pointer, finds the draw slot in the class's vtable, and jumps to the Circle.draw() bytecode address in a single fast array lookup!
