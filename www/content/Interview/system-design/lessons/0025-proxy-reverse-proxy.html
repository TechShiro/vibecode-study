Forward Proxy, Reverse Proxy & API Gateways

The invisible gatekeepers of client privacy and server architecture.

↑ Back to Course Index Module F — Load Balancers & Traffic Management

1 · The One Idea

A Forward Proxy sits in front of clients and protects/masks the clients from the internet. A Reverse Proxy sits in front of servers and protects/masks the backend infrastructure from the outside world. If you remember one sentence: Forward proxies protect clients; reverse proxies protect servers.

2 · Forward Proxy vs Reverse Proxy

Aspect Forward Proxy (Client Proxy) Reverse Proxy (Server Gateway)
Position Between client and the open internet. Between internet and internal backend servers.
Who knows who? The client knows the proxy. The destination server has no idea who the real client is. The client thinks the reverse proxy IS the server. The client has no idea how many backend servers exist.
Primary Purpose Bypassing geo-restrictions, corporate internet content filtering, caching outbound requests, anonymizing client IP. Load balancing, SSL/TLS termination, DDoS protection, centralized authentication, response caching, compression (Gzip/Brotli).
Examples Squid, Tor, Corporate enterprise proxies. Nginx, Envoy, HAProxy, Cloudflare edge, Traefik.

3 · The API Gateway: The Supercharged Reverse Proxy

In modern microservices architectures, a reverse proxy evolves into an API Gateway (e.g., Kong, AWS API Gateway, Spring Cloud Gateway):

  • Request Routing: Dispatches /auth/* to Auth Service, /orders/* to Orders Service.
  • Authentication & JWT Verification: Validates tokens once at the perimeter so internal services don't have to duplicate auth logic.
  • Rate Limiting & Quotas: Blocks abusive clients before they touch internal microservices.
  • Protocol Translation: Translates external public REST/JSON requests into internal high-performance gRPC messages.
