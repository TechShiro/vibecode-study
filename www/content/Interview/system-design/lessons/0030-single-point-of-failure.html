Single Point of Failure (SPOF)

How to identify, eliminate, and architect around vulnerable bottlenecks that can take your entire system offline.

↑ Back to Course Index Module H — Microservices Architecture

1 · The One Idea

A Single Point of Failure (SPOF) is any single component in your entire technology stack (a server, database, load balancer, DNS provider, power supply, or third-party API) whose failure will cause the entire application to stop functioning. The foundational rule of High Availability (HA) engineering is: "Everything fails, all the time". A resilient system eliminates SPOFs by introducing redundancy and automated failover at every single layer.

2 · Eliminating SPOFs Layer by Layer

Layer The SPOF Vulnerability The Architectural Redundancy Solution
DNS Layer Single DNS provider goes down (e.g., Dyn DNS DDoS attack). Dual DNS setup (e.g., Route53 + Cloudflare) with automated health routing.
Load Balancer A single Nginx or ALB instance crashes. Active-Passive pair with Floating Virtual IP (VRRP / Keepalived) or multi-AZ managed load balancers.
Compute / Web A server running your web backend freezes. Auto-scaling server pool across at least 3 distinct Availability Zones (AZs) behind an LB.
Database Primary database hard disk corrupts. Master-Replica configuration with synchronous replication and automated election/failover (e.g., AWS RDS Multi-AZ).
Data Center Hurricane or power grid blackout takes down an entire AWS region (e.g. us-east-1). Multi-region deployment with geo-DNS failover.

3 · Active-Active vs Active-Passive Failover

  • Active-Passive: Primary instance handles 100% of traffic. Standby replica sits idle, mirroring data. If Primary fails, Heartbeat detects it, and Standby promotes itself to Primary within 30–60 seconds.
  • Active-Active: Both instances actively handle live traffic concurrently. If one dies, the remaining instance absorbs the full traffic load immediately with zero downtime.
