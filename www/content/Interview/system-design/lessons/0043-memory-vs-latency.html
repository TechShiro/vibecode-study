Developing mechanical sympathy for computer hardware speeds to design lightning-fast systems.

1 · The One Idea

To design scalable software, you must have an intuitive grasp of the physical speed differences between computer hardware layers. A CPU L1 cache reference takes 1 nanosecond. Reading from an NVMe SSD takes 100,000 nanoseconds. A network packet crossing the Atlantic Ocean takes 100,000,000 nanoseconds! If you treat disk and network calls as free, your architecture will crawl under load.

2 · Latency Numbers Every Engineer Should Know (Jeff Dean / Peter Norvig)

Operation Actual Time Human Scaled (If 1 CPU Cycle = 1 Second)
L1 CPU Cache Reference 0.5 – 1 ns 1 second (A single heartbeat)
L2 CPU Cache Reference 4 ns 4 seconds
RAM (Main Memory) Read 100 ns 1.5 minutes
Read 1 MB sequentially from RAM 3,000 ns (3 µs) 50 minutes
Read 1 MB sequentially from NVMe SSD 50,000 ns (50 µs) 14 hours
Read 1 MB sequentially from Rotational HDD 1,000,000 ns (1 ms) 11.5 days
Network Round Trip (Same Data Center) 500,000 ns (0.5 ms) 5.8 days
Send packet: California to Netherlands 150,000,000 ns (150 ms) 4.75 YEARS!

3 · Space vs Time: Bloom Filters

A Bloom Filter is a space-efficient probabilistic data structure used to test whether an element is a member of a set in $O(k)$ time using only bits!

  • Possible Responses: "Definitely NOT in the set" (100% guaranteed) OR "PROBABLY in the set" (tiny configurable false positive rate, e.g. 1%).
  • Why this saves massive memory: To track 1 billion usernames, a Hash Set requires 32 GB of RAM. A Bloom Filter checks existence using just 1.2 GB of RAM!
  • Where it is used: Google Chrome checks malicious URLs; Cassandra checks if an SSTable on disk contains a row key before touching the disk!
