1 · The One Idea

When you press the brake pedal in a car, you don't think about hydraulic fluid pressures, ABS electronic sensors, or friction pad calipers clamping steel rotors. The pedal is an Abstraction: a clean interface that lets you control the vehicle without understanding its complex mechanical internals. In software design, Abstraction separates what an operation does from how it is executed under the hood.

2 · Abstract Classes vs Interfaces in Java

Feature Abstract Class Interface
Relationship Strict Identity: "IS-A" Capability / Contract: "CAN-DO"
Multiple Inheritance No (A class can extend only 1 abstract class). Yes (A class can implement unlimited interfaces).
State / Fields Can hold instance variables, mutable state, and constructors. Cannot hold instance variables (only public static final constants).
Method Implementations Can provide full default code and abstract methods. Primarily abstract; can provide default and static methods since Java 8.
When to Use When sharing code and state among closely related family classes (e.g. BaseGameCharacter). When defining polymorphic capabilities across unrelated classes (e.g. Comparable, Serializable, PaymentGateway).

3 · Designing Clean Contracts

Senior Design Rule Always program to an Interface, not an implementation!
List<String> users = new ArrayList<>(); (GOOD — easy to swap for LinkedList)
ArrayList<String> users = new ArrayList<>(); (POOR — tightly coupled to ArrayList)
