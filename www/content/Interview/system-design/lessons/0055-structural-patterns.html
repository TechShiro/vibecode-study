Structural Design Patterns

Assembling classes and objects into flexible, loosely-coupled architectures.

↑ Back to Course Index Module M — Design Patterns

1 · The One Idea

Structural Design Patterns focus on how classes and objects are composed to form larger structures while keeping the relationships flexible and efficient. They ensure that when one part of a system changes, the entire structure doesn't collapse.

2 · The Core Structural Patterns

1. Adapter Pattern (The Translator)

Converts the interface of a class into another interface clients expect. Acts like an international plug adapter.

Example: Your app expects a PaymentProcessor interface with pay(double). You integrate a legacy third-party library with method chargeCard(int cents). The LegacyBankAdapter wraps the legacy class and converts dollars to cents internally!

2. Decorator Pattern (Dynamic Behavior Layering)

Attaches additional responsibilities to an object dynamically without subclassing. Wraps the original object.

Example: Java I/O streams: new BufferedReader(new InputStreamReader(new FileInputStream("data.txt"))). Each decorator adds buffering or character decoding onto the raw byte stream!

3. Facade Pattern (The Simple Mask)

Provides a simplified, high-level interface to a complex subsystem of 10 different classes.

Example: A HomeTheaterFacade exposes a single method: watchMovie(), which internally dims lights, lowers the projector screen, turns on surround sound, and starts Netflix.

4. Proxy Pattern (The Surrogate)

Provides a placeholder for another object to control access to it. Types of proxies:

  • Virtual Proxy: Delays loading heavy objects until actually needed (Lazy Loading).
  • Protection Proxy: Verifies user security permissions before forwarding calls.
  • Remote Proxy: Represents an object running on a completely different network server (RPC/gRPC).
