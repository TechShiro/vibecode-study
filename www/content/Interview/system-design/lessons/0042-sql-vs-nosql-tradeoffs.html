SQL vs NoSQL: Storage Engine Deep Dive

Looking under the hood at disk layouts, B-Trees, and Log-Structured Merge Trees.

↑ Back to Course Index Module K — System Design Trade-offs

1 · The One Idea

The difference between SQL and NoSQL is not just "tables vs JSON documents". At the fundamental engineering level, the difference lies in their Storage Engines: how they organize bits on physical disk platters and NVMe flash drives. Relational SQL databases are optimized for fast reads and complex relational range scans using B-Trees. Write-heavy NoSQL databases (Cassandra, RocksDB, ScyllaDB) are optimized for blazing write throughput using LSM-Trees.

2 · B-Trees (SQL) vs LSM-Trees (NoSQL)

Feature B-Tree / B+Tree (PostgreSQL, MySQL, Oracle) LSM-Tree (Cassandra, RocksDB, BigTable)
Disk Write Mechanism In-Place Updates: Overwrites existing 4KB/8KB disk pages in place. Requires random disk writes. Append-Only Writes: Writes sequentially to an in-memory MemTable and appends to an immutable disk SSTable. Zero random disk I/O!
Write Performance Moderate (slowed down by random disk seeking and updating secondary index pages). Extremely Fast: Sequential writes match the maximum raw throughput of physical NVMe drives.
Read Performance Extremely Fast: Point lookups and range scans take $O(\log N)$ with predictable single disk seeks. Slower: Must check MemTable, Bloom Filters, and potentially multiple SSTable disk levels.
Background Maintenance Vacuuming / defragmentation. Compaction: Background threads constantly merge and deduplicate older SSTables, causing periodic write amplification.

3 · The Decision Framework

When to pick what
  • Pick SQL (PostgreSQL / MySQL): When data has strict relations, requires ACID guarantees, needs multi-table JOINs, or your read-to-write ratio is high (90% reads, 10% writes).
  • Pick NoSQL (Cassandra / DynamoDB / MongoDB): When write volume is astronomical (100k+ writes/sec: IoT telemetry, chat messages, financial audit logs), schema changes daily, or data must be horizontally sharded across multiple continents with zero downtime.
