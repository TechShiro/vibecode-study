Inheritance vs Composition: The Golden Rule

Why senior software engineers favor object composition over inheritance hierarchies.

↑ Back to Course Index Module L — OOP Foundations

1 · The One Idea

Inheritance creates an "IS-A" relationship (a Dog is an Animal), allowing a subclass to inherit fields and methods from a superclass. However, inheritance creates the tightest possible coupling in object-oriented programming: changes to the parent class silently break child classes across the codebase (The Fragile Base Class Problem). The Gang of Four design rule states: "Favor object composition over class inheritance" — build systems using "HAS-A" relationships instead.

2 · The Diamond Problem & Why Java Forbids Multiple Inheritance

In C++, a class D can inherit from both B and C, which both inherit from A. If A defines print(), and both B and C override it, which method should D.print() call? This ambiguity is the Diamond of Death. Java completely eliminated multiple class inheritance to prevent this ambiguity, allowing classes to implement multiple Interfaces instead.

3 · The Fragile Base Class Problem

Suppose you extend Java's HashSet to count total elements added over time by overriding add() and addAll():

public class InstrumentedHashSet<E> extends HashSet<E> {
    private int addCount = 0;

    @Override
    public boolean add(E e) {
        addCount++;
        return super.add(e);
    }

    @Override
    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);
    }
}

If you call addAll(List.of(1, 2, 3)), what is addCount? It is 6, not 3! Because inside JDK's HashSet.addAll(), the implementation loops and calls this.add() for each element, double-counting every item! Inheritance broke because you relied on internal parent implementation details.

4 · The Solution: Composition (Wrapping)

public class InstrumentedSet<E> {
    // HAS-A relationship (Composition)
    private final Set<E> set;
    private int addCount = 0;

    public InstrumentedSet(Set<E> set) { this.set = set; }

    public boolean add(E e) {
        addCount++;
        return set.add(e); // Forwarding
    }

    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return set.addAll(c);
    }
}
