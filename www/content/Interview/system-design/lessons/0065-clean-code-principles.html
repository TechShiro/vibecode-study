Clean Code Principles: DRY, KISS & YAGNI

Crafting software that humans can read, understand, and maintain over decades.

↑ Back to Course Index Module O — UML & API Design

1 · The One Idea

Martin Fowler famously wrote: "Any fool can write code that a computer can understand. Good programmers write code that humans can understand." In enterprise software engineering, code is read 10 times more often than it is written. Clean Code Principles provide the mental discipline to keep systems readable, simple, and free of technical debt.

2 · The Core Principles

1. DRY (Don't Repeat Yourself)

Every piece of knowledge or business logic must have a single, unambiguous, authoritative representation within a system. When logic is duplicated across 4 files, a bug fix applied to one file is forgotten in the other three, creating subtle production bugs.

2. KISS (Keep It Simple, Stupid)

Systems work best if they are kept simple rather than made complicated. Do not build an over-engineered microservice mesh with Kafka event streams when a 20-line SQLite query solves the actual business requirement.

3. YAGNI (You Aren't Gonna Need It)

Never implement functionality based on speculative future needs ("We might need multi-currency support next year!"). Build only what is needed today. Unused speculative code clutters architecture, consumes test bandwidth, and usually turns out to be wrong anyway.

4. The Boy Scout Rule

"Always leave the campground cleaner than you found it." Whenever you touch an existing file to add a feature, clean up one messy variable name, extract one small helper method, or improve one comment. Over time, code quality improves rather than decaying.
