Throughput vs Latency & Tail Latency (P99)

Why average latency is a lie and how batching trades individual speed for massive volume.

↑ Back to Course Index Module K — System Design Trade-offs

1 · The One Idea

Latency is the time it takes to process a single request (measured in milliseconds). Throughput is the total number of requests the system can process in a given timeframe (measured in Queries Per Second / QPS). Engineers often assume improving throughput automatically improves latency, but the opposite is frequently true: techniques like Batching dramatically increase total throughput while making individual request latency slightly higher.

2 · Little's Law: The Mathematical Proof

Formulated by MIT professor John Little, Little's Law governs every queuing system on Earth (from grocery store checkouts to Linux network sockets):

Little's Law Formula

L = λ × W

  • $L$: Average number of concurrent requests inside the system.
  • $\lambda$ (Lambda): Arrival rate (Throughput in requests per second).
  • $W$: Average time each request spends in the system (Latency).

Example: If your service receives 1,000 requests/sec ($\lambda = 1000$) and each request takes 200ms ($W = 0.2 ext{s}$), your server must hold $1000 imes 0.2 = \mathbf{200 ext{ concurrent active connections}}$ at all times! If latency spikes to 2s, concurrency instantly jumps to 2,000, exhausting thread pools!

3 · Why "Average Latency" is a Dangerous Lie

If a product dashboard says: "Average API latency is 15ms", engineers celebrate. But if 99 users experience 10ms and 1 user experiences 5,000ms (5 seconds), the average is still low! That 1 user had a catastrophic experience. In an e-commerce checkout page that makes 50 microservice calls to render, the probability that a user experiences at least one slow request approaches 100%!

Percentiles That Matter:

  • P50 (Median): 50% of requests are faster than this number.
  • P90 / P95: Reflects normal heavy-load performance.
  • P99 / P99.9 (Tail Latency): The slowest 1% (or 0.1%) of requests. Caused by garbage collection (GC) pauses, network retransmissions, or lock contention. Top companies optimize strictly for P99 latency.
