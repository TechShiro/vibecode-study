WebRTC & Video Streaming

Architecting peer-to-peer real-time video calls and planetary-scale video streaming (Netflix, YouTube).

↑ Back to Course Index Module E — Networking

1 · The One Idea

Video architectures split into two totally different engineering paradigms based on latency requirements:

  • Interactive Video (Zoom, Google Meet, WhatsApp Calls): Latency must be < 200ms. Uses WebRTC over UDP, connecting peers directly without intermediate storage.
  • Broadcasting & VOD (YouTube, Netflix, Twitch): Latency can be 2–10 seconds. Uses chunked HTTP streaming (HLS or MPEG-DASH), caching video slices across global CDNs.

2 · WebRTC Architecture: How P2P Traverses Firewalls

In the real world, smartphones and laptops do not have public IP addresses; they sit behind home Wi-Fi routers with NAT (Network Address Translation) and firewalls. Two phones cannot simply talk to each other without help.

Component Role How It Works
Signaling Server Session Discovery A lightweight WebSocket server where peers exchange SDP (Session Description Protocol) offers/answers to agree on codecs and resolutions.
STUN Server Public IP Discovery The client asks STUN: "What is my public IP address and port as seen from the open internet?" (Works for 85% of standard NATs).
TURN Server Fallback Relay When strict corporate firewalls block direct P2P connections, TURN acts as an encrypted relay server in the cloud, passing packets between peers.
ICE Framework Orchestration Collects all candidate network paths (direct LAN, STUN, TURN) and picks the fastest viable connection.

3 · Video on Demand (Netflix / YouTube): HLS & Adaptive Bitrate

Why doesn't Netflix send you one giant 5GB movie.mp4 file?

  1. Chunking: The video is transcoded into small 2 to 6-second fragments (chunks).
  2. Multi-Bitrate Encoding: Every chunk is rendered in multiple resolutions: 360p, 720p, 1080p, and 4K.
  3. Manifest File (playlist.m3u8): A master index file tells the video player which chunks correspond to which resolution.
  4. Adaptive Bitrate (ABR): The client's video player constantly measures network download speed. If your Wi-Fi dips, the player smoothly requests the next 2-second chunk in 720p instead of 4K without pausing playback or showing a buffering wheel!
