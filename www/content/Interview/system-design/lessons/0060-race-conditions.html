Lock-free concurrency, Java Memory Model (JMM), and atomic hardware primitives.

1 · The One Idea

Why is count++ NOT thread-safe in Java? Because at the CPU assembly level, count++ is three separate operations: 1) Read count from RAM into CPU register; 2) Add 1 in register; 3) Write register back to RAM. If two threads execute this simultaneously, both read 5, both increment to 6, and both write 6. Two increments happened, but count only increased by 1! This is a Race Condition.

2 · The Two Concurrency Bugs: Visibility vs Atomicity

Problem What Goes Wrong The Solution
Memory Visibility Bug Modern CPUs have private L1/L2 caches. Thread 1 updates flag = true, but the value sits in Core 1's cache. Thread 2 running on Core 2 continues reading flag = false indefinitely in an infinite loop! volatile keyword: Guarantees that any write to a variable is immediately flushed to main memory, and reads always fetch fresh from RAM.
Atomicity Bug volatile guarantees visibility, but does NOT guarantee atomicity! volatile int count; count++; will STILL corrupt under concurrency! Atomic Classes (AtomicInteger) or Lock-free CAS instructions.

3 · Lock-Free Concurrency: Compare-And-Swap (CAS)

Locks block threads, causing heavy OS kernel context switches. Compare-And-Swap (CAS) is a single atomic instruction supported directly by modern CPU hardware (e.g. CMPXCHG on x86 chips):

  • It takes three arguments: Memory address $V$, Expected old value $A$, and New value $B$.
  • "If value at $V$ is still $A$, atomically swap it to $B$ and return true. If someone else changed it, do nothing and return false."
// Under the hood of Java's AtomicInteger
public class AtomicInteger {
    private volatile int value;

    public final int incrementAndGet() {
        while (true) {
            int current = get();
            int next = current + 1;
            if (compareAndSet(current, next)) { // Hardware CAS
                return next;
            }
            // If CAS failed, someone beat us; loop and retry with fresh value!
        }
    }
}
