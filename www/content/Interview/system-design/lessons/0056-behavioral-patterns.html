Behavioral Design Patterns

Mastering algorithms, communication flow, and responsibility assignment between objects.

↑ Back to Course Index Module M — Design Patterns

1 · The One Idea

Behavioral Design Patterns are concerned with algorithms and the assignment of responsibilities between objects. They don't just describe how classes are structured — they characterize the complex control flow and message passing patterns between interacting components.

2 · The Core Behavioral Patterns

1. Strategy Pattern (Interchangeable Algorithms)

Defines a family of algorithms, encapsulates each one, and makes them interchangeable at runtime.

Example: Navigation app route calculation: Navigator.setRouteStrategy(new DrivingStrategy()) or new WalkingStrategy(). The navigator delegates pathfinding without knowing the algorithm math.

2. Observer Pattern (Event Listener)

Defines a one-to-many dependency: when one object (Subject) changes state, all its registered dependents (Observers) are notified and updated automatically.

Example: YouTube Channel (Subject) uploads a new video. All 500,000 subscribed mobile devices (Observers) receive an alert.

3. Command Pattern (Encapsulating Requests as Objects)

Encapsulates a request as an object, thereby letting you parameterize clients with different requests, queue or log requests, and support Undo/Redo operations!

public interface Command {
    void execute();
    void undo();
}

4. State Pattern (Object State Machines)

Allows an object to alter its behavior when its internal state changes. The object appears to change its class.

Example: Vending machine state machine: NoCoinState, HasCoinState, DispensingState, SoldOutState. Pressing the "Dispense" button behaves completely differently depending on the active State object!
