Functional Dependencies & Armstrong's Axioms

Mathematical constraints that govern relational schemas, determining candidate keys and formal closure sets.

← Back to Course IndexModule B – Normalization

1 · The One Idea

A Functional Dependency (FD) is a mathematical constraint between two sets of attributes in a relation. If attribute set X uniquely determines attribute set Y, we write X → Y. This means: in any legal state of relation R, whenever two tuples have identical values for X, they must have identical values for Y (t1[X] = t2[X] ⇒ t1[Y] = t2[Y]). Understanding FDs is the foundation of schema normalization.

2 · Armstrong's Axioms (Sound & Complete)

In 1974, William W. Armstrong developed a set of inference rules that generate all valid FDs logically implied by a given FD set F:

Rule 1

Reflexivity

If Y ⊆ X, then X → Y.
Example: {emp_id, emp_name} → emp_id. (Trivial dependency).

Rule 2

Augmentation

If X → Y, then XZ → YZ for any attribute set Z.
Adding identical attributes to both sides preserves validity.

Rule 3

Transitivity

If X → Y and Y → Z, then X → Z.
Example: roll_no → dept_id and dept_id → hod_name ⇒ roll_no → hod_name.

Secondary Inferred Rules

  • Union Rule: If X → Y and X → Z, then X → YZ.
  • Decomposition Rule: If X → YZ, then X → Y and X → Z. (Note: You CANNOT decompose the left-hand side!)
  • Pseudotransitivity Rule: If X → Y and WY → Z, then WX → Z.

3 · Attribute Closure Algorithm (X+)

The closure of attribute set X under FD set F (denoted X+) is the set of all attributes functionally determined by X.

Algorithm: Computing X+

  1. Initialize result = X.
  2. Repeat until result does not change:
    • For each FD A → B in F: if A ⊆ result, then result = result ∪ B.
  3. Return result.

4 · Finding All Candidate Keys Algorithmically

A Superkey is any attribute set K such that K+ = R (determines all attributes of the table). A Candidate Key is a minimal superkey (no proper subset of K is a superkey).

Heuristic for Candidate Key Discovery:

  • Essential Attributes: Attributes that appear only on the Left-Hand Side (LHS) of FDs or never appear in any FD MUST be part of every candidate key.
  • Redundant Attributes: Attributes that appear only on the Right-Hand Side (RHS) can NEVER be part of any candidate key.
  • Start by computing the closure of all essential attributes. If their closure equals the entire relation R, it is the unique candidate key!

5 · Canonical Cover (Minimal Cover)

A Canonical Cover Fc of FD set F is a minimal equivalent set of FDs without redundancy:

  1. Decompose all RHS attributes into singletons (X → YZ becomes X → Y and X → Z).
  2. Eliminate extraneous LHS attributes (e.g., if AB → C and A → B, then B is extraneous in LHS).
  3. Eliminate redundant FDs whose removal does not shrink the closure.
