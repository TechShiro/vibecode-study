Relational Algebra & Relational Calculus

The mathematical theory behind SQL: procedural relational algebra and declarative relational calculus.

← Back to Course IndexModule A – Foundations & Modeling

1 · The One Idea

SQL is not an ad-hoc scripting language; it is founded on Relational Algebra (invented by Edgar F. Codd in 1970). Relational algebra is a procedural query language where relations (tables) are treated as mathematical sets of tuples, and operators consume one or more relations to yield a new relation (closure property). Every SQL query you write is compiled by the database parser into a tree of relational algebra expressions.

2 · The 5 Fundamental Primitive Operators

All complex database operations can be expressed using combinations of these 5 fundamental operators:

OperatorNotationSQL EquivalentDefinition & Behavior
Selectionσp(R)WHERE conditionHorizontal filtering: selects tuples that satisfy predicate p.
ProjectionπA1..An(R)SELECT col1, col2Vertical filtering: extracts specified columns and eliminates duplicate rows.
Cartesian ProductR × SFROM R CROSS JOIN SCombines every tuple of R with every tuple of S. Degree = deg(R)+deg(S), Cardinality = |R| × |S|.
Set UnionR ∪ SUNIONCombines tuples from both relations. Relations must be union-compatible (same arity and compatible data types).
Set DifferenceR − SEXCEPT / MINUSReturns tuples that are in R but NOT in S. Requires union compatibility.

3 · Derived & Join Operators

  • Theta Join (R ⋈θ S): Cartesian product followed by a selection condition σθ(R × S).
  • Equi-Join: A Theta Join where the condition contains only equality operators (=).
  • Natural Join (R ⨝ S): An Equi-join on all attributes having the same name in both relations, followed by projection to eliminate duplicate join columns.
  • Division Operator (R ÷ S): "Find all entities in R that are associated with ALL entities in S".

    Example: "Find all students who have enrolled in every single course required for graduation."

4 · Declarative Querying: Relational Calculus

While Relational Algebra is procedural (specifies the sequence of operations to compute the result), Relational Calculus is declarative (specifies WHAT data is desired without stating the algorithmic steps):

  • Tuple Relational Calculus (TRC): Based on finding tuples { t | P(t) } where predicate P holds true. SQL is heavily modeled after TRC (SELECT * FROM t WHERE P(t)).
  • Domain Relational Calculus (DRC): Formulated on variable attributes rather than entire tuples: { ⟨x1, x2⟩ | ⟨x1, x2⟩ ∈ R ∧ x1 > 100 }. QBE (Query By Example) is based on DRC.

Codd's Equivalence Theorem

A query language is formally declared Relationally Complete if it can express any query that can be formulated in basic Relational Algebra or safe Relational Calculus. SQL is relationally complete.
