1. Elliptic curve arithmetic memorise

Curve, addition and doubling on Ep(a, b) y2 = x3 + ax + b (mod p), non-singular iff 4a3 + 27b2 ≠ 0

P ≠ Q:   λ = (y2 − y1)(x2 − x1)−1 mod p
P = Q:   λ = (3x12 + a)(2y1)−1 mod p

x3 = λ2 − x1 − x2  ·  y3 = λ(x1 − x3) − y1  (both mod p)
−P = (x, p − y)  ·  P + (−P) = O  ·  P + O = P
  • No division mod p — multiply by the modular inverse. −k mod p = p − k.
  • Finding points: list the QRs by squaring 1…(p−1)/2; for each x test whether x3+ax+b is a QR; each hit gives two points (x, y) and (x, p−y).
  • Hasse’s bound for the point count: p + 1 ± 2√p.
  • kP by double-and-add; reduce the scalar mod n (the order of the point) first.
  • ECDLP: given P and Q = kP, find k — about √n work, no sub-exponential attack. Hence 256-bit ECC ≈ 3072-bit RSA.

2. ECC cryptosystems

Keys, ECDH and EC ElGamal Private nA, public PA = nAG

ECDH:   K = nAPB = nBPA = nAnBG; session key = x-coordinate. No authentication → MITM.

EC ElGamal encrypt:   C = { kG,   Pm + kPB }
decrypt:   Pm = C2 − nBC1  (since nBC1 = kPB)

Message → point: Koblitz’s method (x = mK + j until x3+ax+b is a QR), or use ECC for the key and AES for the data. Ciphertext is twice the message size.

3. Digital signature basics

The process Sign: h = H(M) → S = Eprivate(h) → send M ‖ S
Verify: h1 = H(M′), h2 = Dpublic(S), accept iff h1 = h2
  • Gives: authentication, integrity, non-repudiation. Not confidentiality — encrypt separately.
  • Sign the digest, not the message: speed, fixed size, RSA block limit, and it kills the multiplicative property.
  • Direct (sender + receiver; sender can falsely claim key theft → use timestamps) vs arbitrated (trusted third party validates and dates every message).
  • RSA approach = one value, deterministic, recovers the digest, also encrypts. DSS approach = pair (r, s), randomised by k, no recovery, signature only.
  • MAC vs signature: symmetric vs asymmetric · key-holder-only vs anyone verifies · no vs yes non-repudiation · fast vs slow.

5. The signature schemes formulas

RSA n = pq · φ(n) = (p−1)(q−1) · ed ≡ 1 mod φ(n)
Sign: S = [H(M)]d mod n  ·  Verify: Se mod n = H(M)
ElGamal — public (p, α, y = αx), private x gcd(k, p−1) = 1  ·  r = αk mod p  ·  s = k−1(M − xr) mod (p−1)
Verify: αM ≡ yrrs (mod p)  —  r is mod p, s is mod p−1
Schnorr — q | p−1, αq ≡ 1, private s, public v = α−s x = αr mod p  ·  e = H(M ‖ x)  ·  y = (r + se) mod q  ·  signature (e, y)
Verify: x′ = αyve mod p, check H(M ‖ x′) = e
DSA — p, q | p−1, g = h(p−1)/q mod p, private x, public y = gx r = (gk mod p) mod q  ·  s = k−1[H(M) + xr] mod q
w = s−1 mod q · u1 = H(M)w mod q · u2 = rw mod q
v = [(gu1yu2) mod p] mod q  →  accept iff v = r
ECDSA — curve, G of order n, private d, public Q = dG R = kG, r = xR mod n  ·  s = k−1[H(M) + dr] mod n
w = s−1, u1 = H(M)w, u2 = rw  (all mod n)
X = u1G + u2Q  →  accept iff xX mod n = r  (X should equal kG)

8. Traps that cost marks

  • EC: using the addition λ when P = Q; forgetting the bracket order (x1 − x3) in y3; not checking the result is on the curve.
  • RSA: computing d as the inverse of e mod n instead of mod φ(n).
  • ElGamal: computing s mod p instead of mod (p−1).
  • DSA: dropping the second reduction — both r and v are mod p then mod q; comparing v with s instead of r.
  • ECDSA: reducing the x-coordinate mod p instead of mod n.
  • All DSS-type schemes: if r = 0 or s = 0, discard k and start again.
  • Every numerical: finish with the verification step — it is your own proof, and it is usually worth marks by itself.
