Integrity procedure: sender computes h1 = H(M), sends M insecurely and h1 safely; receiver computes h2 = H(M′) and compares. An unprotected digest detects accidents, not attackers — the attacker recomputes it.

  • Collision resistance ⇒ second preimage resistance, not the reverse.
  • Requirements list: variable input, fixed output, efficiency, the three resistances, avalanche effect, deterministic.
  • Pigeonhole: collisions must exist — the claim is only that they cannot be found.
  • Simple hashes: bitwise XOR (order-blind), rotated XOR (order-aware, still forgeable). Checksums resist noise, not adversaries.

Merkle–Damgård (iterated hash)

The five steps pad → append length (MD-strengthening) → split into blocks → Hi = f(Hi−1, Mi) from a fixed IV → output Ht
If f is collision resistant, the whole hash is collision resistant.

Two ways to build f: dedicated from scratch (MD4, MD5, SHA) or from a block cipher (Rabin, Davies–Meyer, Matyas–Meyer–Oseas, Miyaguchi–Preneel — Whirlpool).

Random Oracle Model

  • Bellare & Rogaway, 1993. An ideal hash: a table of (message, digest) pairs.
  • Repeated message → same digest. New message → uniformly random n-bit digest, then recorded.
  • No structure to exploit → brute force is the only attack, so security can be counted in queries.
  • Used to prove RSA-OAEP, RSA-PSS, DSS.
  • Limitation: no real hash is an oracle; schemes exist secure in the ROM but insecure with every real hash (Canetti–Goldreich–Halevi, 1998). Evidence, not guarantee.

Design rule: an n-bit digest gives only n/2 bits of collision security. 128 → 64 (MD4/MD5, broken) · 160 → 80 (SHA-1, deprecated) · 512 → 256 (SHA-512, Whirlpool).

MAC, HMAC, CMAC highest yield

MAC MAC = C(K, M); send M ‖ MAC; receiver recomputes and compares.
Gives integrity + source authentication. No confidentiality. No non-repudiation — the key is shared.

Three arrangements: M ‖ C(K,M) · EK2[M ‖ C(K1,M)] · EK2[M] ‖ C(K1, EK2[M]).

Security requirements: knowing (M, MAC) must not yield a MAC for another message; MACs uniformly distributed (collision probability 2−n); the MAC depends on all message bits; key space large.

HMAC — RFC 2104 / FIPS 198 HMAC(K, M) = H[ (K+ ⊕ opad) ‖ H[ (K+ ⊕ ipad) ‖ M ] ]
ipad = 0x36 repeated · opad = 0x5C repeated · K+ = key zero-padded to block size b
b = 512 for MD5/SHA-1/SHA-256, 1024 for SHA-512
  • Eight steps: pad K (hash it first if longer than b) → K+⊕ipad = Si → prepend to M → hash → pad the inner digest → K+⊕opad = So → prepend → hash again.
  • Why two constants: they differ in half their bits, so one key becomes two independent pseudorandom keys.
  • Why nested: H(K ‖ M) alone falls to the length-extension attack.
  • Cost: only two extra block computations, both precomputable.
CMAC — NIST SP 800-38B AES/3DES in CBC mode, zero IV, tag = leftmost s bits of the last ciphertext block.
L = E(K, 0b) → K1, K2 = 2K1 (multiply by x in GF(2b): shift left, XOR 0x87 if a 1 shifts out)
Complete final block → XOR K1. Padded final block (1 then 0s) → XOR K2.
Fixes CBC-MAC/DAA, which is forgeable for variable-length messages.

MD4 detail

  • Five steps: pad to 448 mod 512 → append 64-bit length → init A,B,C,D = 67452301, EFCDAB89, 98BADCFE, 10325476 → 3 rounds × 16 steps → add to the incoming buffer, output A‖B‖C‖D.
  • Round functions: F = (X∧Y)∨(¬X∧Z) selection · G = (X∧Y)∨(X∧Z)∨(Y∧Z) majority · H = X⊕Y⊕Z parity.
  • Constants: 0, 5A827999 (230√2), 6ED9EBA1 (230√3) — nothing-up-my-sleeve numbers.
  • Step: a ← (a + F(b,c,d) + X[k] + K) <<< s, addition mod 232.
  • MD5 = MD4 + fourth round I(X,Y,Z)=Y⊕(X∨¬Z) + a unique T[i] per step from |sin i| + an extra addition of b.

SHA-512 detail

  • Five steps: pad to 896 mod 1024 → append 128-bit length → init eight 64-bit registers (fractional parts of √ of the first 8 primes) → 80 rounds per 1024-bit block → add to the incoming values, output the eight registers.
  • K0…K79: fractional parts of the cube roots of the first 80 primes.
  • Expansion: Wt = σ1(Wt−2) + Wt−7 + σ0(Wt−15) + Wt−16, with σ0 = ROTR1⊕ROTR8⊕SHR7, σ1 = ROTR19⊕ROTR61⊕SHR6.
  • Round: T1 = h + Ch(e,f,g) + Σ1(e) + Wt + Kt; T2 = Σ0(a) + Maj(a,b,c); e ← d + T1, a ← T1 + T2, the rest shift.
  • Ch = (e∧f)⊕(¬e∧g) · Maj = (a∧b)⊕(a∧c)⊕(b∧c) · Σ0 = ROTR28,34,39 · Σ1 = ROTR14,18,41.
  • SHA-384 = SHA-512 with a different IV, truncated to 384 bits.

Whirlpool detail

  • Hi = E(Hi−1, Mi) ⊕ Mi ⊕ Hi−1 — Miyaguchi–Preneel; H0 = 0.
  • Cipher W: AES with an 8×8 byte state, 512-bit block and key, 10 rounds of SubBytes (S-box, confusion) → ShiftColumns (column j down by j) → MixRows (8×8 MDS over GF(28)) → AddRoundKey.
  • Key schedule: the same round function applied to the key, with round constants RC[r] from the S-box in place of round keys.
  • Weakness: slow in software (key schedule per block), lightly deployed, rebound attacks on reduced rounds.

Answer openers worth memorising verbatim

  • “Confidentiality hides the message; it does not preserve it. Integrity therefore needs its own mechanism.”
  • “Message = document, digest = fingerprint.”
  • “Collisions must exist by the pigeonhole principle; security means they cannot be found.”
  • “A MAC gives integrity and authentication but not non-repudiation, because the key is shared.”
  • “An n-bit digest gives only n/2 bits of collision security, which is why digest lengths grew.”
  • “MD5 is MD4 with a fourth round, per-step constants and an extra addition.”
  • “Whirlpool builds its compression function from a block cipher; SHA-512 builds one from scratch.”
