What is system security?

System security is the collection of mechanisms, policies, hardware, and software controls designed to protect an organization's computing systems, stored data, and communication channels from unauthorized access, modification, disruption, or destruction.

Core Security Relationship $$\text{Threat} + \text{Vulnerability} = \text{Risk}$$
  • Asset: Anything of value requiring protection (hardware, proprietary data, credentials, computation cycles).
  • Vulnerability: A weakness, design flaw, or software bug that can be exploited by an adversary (e.g., unchecked buffer length).
  • Threat: A potential event or agent that may cause harm by violating confidentiality, integrity, or availability.
  • Attack: An intentional action taken to exploit a specific vulnerability.
  • Security Control / Countermeasure: Any safeguard implemented to eliminate vulnerabilities or mitigate threat impacts.

Security Policy vs Security Mechanism

The Fundamental Distinction
  • Security Policy: A formal specification of what is permitted and what is prohibited within a system (e.g., “Only accounting managers may approve invoices exceeding $10,000”).
  • Security Mechanism: The technical algorithm, software control, or hardware feature that enforces the policy (e.g., Kerberos authentication, cryptographic digital signatures, and ACL matrices).

STRIDE Threat Modeling

Developed by Microsoft, STRIDE is the standard taxonomy for identifying threats during system architecture and design:

Threat (STRIDE)Security Property ViolatedDefinition & Example
S — SpoofingAuthenticationPretending to be someone else (e.g., forging an IP address or email sender).
T — TamperingIntegrityUnauthorized modification of data at rest or in transit (e.g., altering packet payloads).
R — RepudiationNon-repudiationDenying having performed an action (e.g., claiming an order was never submitted).
I — Information DisclosureConfidentialityExposing sensitive information to unauthorized entities (e.g., packet sniffing).
D — Denial of ServiceAvailabilityExhausting system resources so legitimate requests are dropped (e.g., SYN flooding).
E — Elevation of PrivilegeAuthorizationGaining higher access rights than authorized (e.g., exploiting a buffer overflow to get root shell).

Principles of Secure System Design (Saltzer & Schroeder)

  1. Least Privilege: Every program and user must operate using the minimum set of privileges necessary to perform its task.
  2. Fail-Safe Defaults: Access decisions should be based on explicit permission rather than exclusion (default deny).
  3. Complete Mediation: Every access request to every object must be checked for authorization without caching bypasses.
  4. Open Design: The security of the system must not depend on keeping the design secret (Kerckhoffs's principle).
  5. Separation of Privilege: Requiring two independent conditions/keys to grant high-value access (dual control).
  6. Defense in Depth: Layering multiple independent defensive controls so failure of one does not compromise the entire system.

Check yourself

Retrieval practice

1. What is the fundamental difference between a security policy and a security mechanism?

Policy specifies authorization rules (what); mechanisms (like ACLs, cryptosystems) enforce them (how).

2. In the STRIDE threat model, an attacker altering payment records violates:

Tampering is unauthorized alteration or manipulation of data, which violates the security goal of integrity.

3. The principle that access decisions should default to 'deny' unless explicitly permitted is called:

Fail-safe defaults ensure that if a check fails or a rule is omitted, the request is rejected by default.

Recall without looking

Define asset, threat, vulnerability, and risk.

Asset: valuable resource needing protection. Threat: potential harm/violator. Vulnerability: flaw or weakness. Risk: the probability and consequence of a threat exploiting a vulnerability.

What does STRIDE stand for?

Spoofing (auth), Tampering (integrity), Repudiation (non-repudiation), Information disclosure (confidentiality), Denial of service (availability), Elevation of privilege (authorization).
