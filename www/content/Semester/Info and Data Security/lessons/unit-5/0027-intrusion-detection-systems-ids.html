What is an Intrusion Detection System?

An Intrusion Detection System (IDS) is a hardware device or software application that monitors system or network activities for malicious actions or policy violations, and produces reports or alerts to a management station.

IDS vs Firewall
  • Firewall: Acts as a perimeter security gatekeeper. It inspects packet headers (IPs, ports) and enforces access control rules to block unauthorized traffic. It rarely analyzes deep payload content.
  • IDS: Acts as an intelligent security alarm / detective. It performs deep packet inspection and behavioural analysis on traffic that has already passed through the firewall, identifying sophisticated multi-step attacks.
  • Intrusion Prevention System (IPS): An inline active device that not only detects intrusions but immediately drops malicious packets or terminates TCP connections.

Detection Techniques

FeatureSignature-Based (Misuse Detection)Anomaly-Based (Behavioral Detection)
PrincipleCompares current activity against a database of known attack signatures (patterns, byte sequences, regex).Establishes a baseline profile of “normal” activity and flags statistically significant deviations.
Detection of Known AttacksExtremely accurate with very low false alarm rates.Can detect known attacks, but may miss stealthy attacks that mimic normal baseline traffic.
Zero-Day DetectionIneffective — blind to novel attacks until a signature is authored and distributed.Effective — can detect previously unseen zero-day attacks and insider anomalies.
False Positive RateVery Low (fires only on precise signature match).High (legitimate changes in user behaviour trigger false alarms).
MaintenanceRequires constant downloading of updated signature feeds.Requires periodic retraining to prevent baseline drift.
Classification Errors
  • False Positive (Type I error): Normal legitimate traffic is erroneously flagged as malicious (crying wolf).
  • False Negative (Type II error): An actual malicious intrusion slips past undetected (dangerous security breach).

Deployment Architecture: HIDS vs NIDS

CriterionHost-Based IDS (HIDS)Network-Based IDS (NIDS)
PlacementInstalled directly on individual critical servers/endpoints.Placed at network chokepoints, switch SPAN/mirror ports, or taps.
Monitoring ScopeAnalyzes host-specific audit logs, system calls, file integrity (checksums), and registry changes.Analyzes raw network packets, protocol headers, and payload streams across all hosts.
Encrypted TrafficCan inspect decrypted payloads in host memory before/after encryption.Blinded by end-to-end encrypted payloads (HTTPS, TLS, SSH).
Resource OverheadConsumes CPU and memory on the protected host.Zero resource overhead on protected host machines.
ResilienceVulnerable to being disabled if an attacker gains root on the host.Invisible and tamper-resistant; has no IP address on monitored link.
Attack VerificationCan determine whether an attack actually succeeded on the host OS.Cannot easily confirm if an attack exploit succeeded on the target.

Honeypots and Deception Technology

A honeypot is an isolated decoy system intentionally configured with vulnerabilities and placed on a network to attract adversaries. Because a honeypot has no legitimate production purpose, any activity directed at it is presumed malicious.

  • Low-Interaction Honeypot: Simulates only specific network daemons (e.g., emulates an open FTP or SSH banner). Safe and lightweight; used for gathering automated worm scans.
  • High-Interaction Honeypot: Runs a real, full operating system with real services. Provides deep forensic insight into zero-day attacker techniques and command history, but carries risk if used as a pivot point.
  • Honeytoken: Fake sensitive data (e.g., bogus database credit card numbers or dummy API keys) used to detect unauthorized exfiltration.

Snort: Architecture and Rule Anatomy

Snort is the world's most widely deployed open-source network intrusion detection and prevention system.

Snort Rule Structure 
alert tcp any any -> 192.168.1.0/24 80 (msg:"WEB-ATTACK /etc/passwd access attempt"; content:"/etc/passwd"; nocase; sid:1000001; rev:1;)

1. Rule Header: Defines the action and network addressing:

  • alert: Action to take (alert, log, drop, reject).
  • tcp: Protocol to match (TCP, UDP, ICMP, IP).
  • any any: Source IP address and source port.
  • ->: Direction of traffic flow.
  • 192.168.1.0/24 80: Destination subnet and destination port (HTTP).

2. Rule Options (enclosed in parentheses):

  • msg:"...": Human-readable alert description.
  • content:"...": Byte sequence or ASCII string to search for inside packet payload.
  • nocase: Case-insensitive payload matching.
  • sid: Snort Rule Unique Identifier (IDs ≥ 1,000,000 are custom local rules).
  • rev: Revision number of the rule.

Check yourself

Retrieval practice

1. Why can an anomaly-based IDS detect zero-day attacks while a signature-based IDS cannot?

Novel exploits do not have existing signatures, but their unusual activity deviates from the baseline profile.

2. What is a key limitation of a Network-based IDS (NIDS) compared to a Host-based IDS (HIDS)?

End-to-end encryption conceals payload contents from network taps; only the endpoint HIDS can inspect unencrypted data.

3. In a Snort rule, the string to search for inside packet payloads is specified using:

The `content` option searches for specific ASCII or hex patterns within the payload stream.

Recall without looking

Signature vs anomaly detection: trade-off in false positives/negatives.

Signature: low false positives, high false negatives for zero-days. Anomaly: high false positives (benign anomalies flagged), low false negatives for zero-days.

Name two advantages and two disadvantages of NIDS over HIDS.

Advantages: 1. Single sensor covers entire subnet. 2. Zero CPU overhead on endpoints. Disadvantages: 1. Blinded by TLS/HTTPS encrypted traffic. 2. Cannot verify if exploit succeeded on target OS.

What is a honeypot and why are its false positives virtually zero?

A honeypot has no valid production users or services; any connection attempt to it is inherently unauthorized or malicious.
