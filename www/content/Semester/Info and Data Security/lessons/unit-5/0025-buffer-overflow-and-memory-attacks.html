The Anatomy of a Stack Frame

Each function call pushes an activation frame onto the stack. In x86 architecture, the stack grows downwards towards lower addresses, but buffers inside arrays fill upwards towards higher addresses.

Stack EntryDirectionPurpose
Function ArgumentsHigher MemoryParameters pushed by the caller in reverse order (right-to-left)
Saved Return Address (EIP/RIP)↑Instruction pointer where execution resumes after function returns
Saved Frame Pointer (EBP/RBP)↑Base pointer of the caller's stack frame
Local Buffers & VariablesLower MemoryMemory allocated for function's local variables (e.g. char buf[64];)

How a Stack Buffer Overflow Works (“Smashing the Stack”)

In languages like C and C++, there is no built-in runtime bounds-checking on arrays or pointers. Unsafe functions like strcpy(), strcat(), gets(), and scanf("%s") copy characters into memory until encountering a null terminator (\0), regardless of buffer size.

Worked vulnerability example 
void vulnerable_function(char *user_input) {
    char buffer[64];
    strcpy(buffer, user_input);  /* UNSAFE: No bounds check! */
}

If user_input contains 100 bytes:

Memory Layout:
[ buffer (64 bytes) ] → fills toward → [ Saved EBP (4 bytes) ] → [ Saved RET (4 bytes) ]

Attack Payload (100 bytes):
[ NOP Sled (0x90...) ] [ Shellcode (execve /bin/sh) ] [ Overwrite EBP ] [ Target Address ]
   (low address)  ──────────────────────────────────────────────>   (overwrites RET)

The Execution Hijack:

  1. The input fills the 64-byte buffer, spills past the boundary, and overwrites the saved EBP register.
  2. It then overwrites the Saved Return Address with an address pointing back into the buffer.
  3. When vulnerable_function finishes and executes the ret instruction, the CPU pops the attacker's forged address into the Instruction Pointer (EIP).
  4. Control jumps straight to the attacker's shellcode with the privileges of the running process (often root / SYSTEM).

Exploit Components: Shellcode and NOP Sled

  • Shellcode: A small machine-code payload written in assembly that executes system calls (e.g., spawning a Unix shell /bin/sh or binding a remote network socket). It must avoid null bytes (\x00) to prevent terminating strcpy() prematurely.
  • NOP Sled (0x90): A sequence of “No Operation” instructions placed immediately before the shellcode. The attacker does not need an exact return address; pointing anywhere inside the NOP sled causes the CPU to “slide” down until executing the shellcode.

Other Memory Vulnerabilities

  • Format String Attacks: Occurs when user input is passed directly as the format argument (e.g., printf(user_input)). Attackers use %x to leak stack secrets or %n to write arbitrary values to memory.
  • Integer Overflow: When an integer arithmetic wrap-around causes a small buffer to be allocated (e.g. malloc(len + 1) wrapping to 0), followed by a massive copy that overflows the heap.
  • Heap Overflow: Overflows heap-allocated memory, corrupting chunk headers (forward/backward pointers in malloc metadata) to overwrite function pointers.

Modern Defensive Countermeasures

Defense MechanismLevelHow it works
1. Stack Canaries (StackGuard)CompilerPlaces a random 32/64-bit secret integer (canary) between local buffers and the saved return address. Before returning, the function verifies the canary value. If altered by an overflow, the program halts immediately (SIGABRT) without jumping to the return address.
2. ASLR (Address Space Layout Randomization)Operating System / KernelRandomizes the memory offsets of the stack, heap, and shared libraries each time the program runs. The attacker cannot predict the exact address of their shellcode or library functions.
3. DEP / NX Bit (Data Execution Prevention / W^X)CPU Hardware / OSMarks memory pages as either Writable or Executable, never both ($W \oplus X$). Memory pages in the stack and heap are non-executable; jumping to shellcode on the stack triggers a hardware CPU fault.
4. Safe Functions & Modern LanguagesDeveloper / ApplicationReplacing unsafe C routines with bounded alternatives (strncpy, snprintf, fgets), or using memory-safe programming languages (Rust, Go, Java, Python).

Check yourself

Retrieval practice

1. In a classic stack smashing attack, what critical value on the stack is overwritten to redirect control flow?

Overwriting the saved return address causes the CPU to jump to the attacker's chosen payload upon function return.

2. What is the purpose of a NOP sled (sequence of 0x90 bytes)?

Jumping anywhere within the NOP sled slides the instruction pointer straight into the payload.

3. How does Data Execution Prevention (DEP / NX bit) protect against buffer overflow exploits?

With DEP/NX, the CPU refuses to execute code residing in stack or heap pages, causing an immediate segmentation fault.

Recall without looking

List the memory segments of a running process from low to high address.

Text (code) → Data (initialized globals) → BSS (uninitialized) → Heap (grows up) → Stack (grows down) → Kernel space.

How do stack canaries prevent control-flow hijacking?

A canary is placed between local variables and the saved return address. A linear buffer overflow must overwrite the canary to reach the return address; the function checks the canary before returning and aborts if corrupted.

Name the three hardware/OS/compiler mitigations against buffer overflows.

1. Stack Canaries (compiler). 2. ASLR (randomizes stack/heap/library memory addresses). 3. DEP/NX bit (prevents execution of data pages).
