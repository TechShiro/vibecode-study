PGP services

ServiceHow
AuthenticationHash message (SHA), encrypt hash with sender’s private key (RSA/DSS) = digital signature
ConfidentialityEncrypt message with one-time session key (AES/3DES), encrypt session key with receiver’s public key (RSA/ElGamal)
CompressionZIP after signing, before encryption (signature on uncompressed, encryption on compressed)
CompatibilityRadix-64 (Base64) conversion for email transport
SegmentationSplit large messages to fit email size limits
PGP message creation order 1. Hash → sign with sender’s private key (authentication).
2. Compress the signed message.
3. Encrypt with session key, encrypt session key with receiver’s public key.
4. Base64 encode for email transport.

PGP trust model — Web of Trust

No central CA. Users sign each other’s public keys. Trust is decentralised — you trust a key if enough people you trust have signed it.

S/MIME

Secure/Multipurpose Internet Mail Extensions. Uses X.509 certificates from a CA hierarchy (not web of trust). Provides the same services as PGP but integrated into email clients (Outlook, Thunderbird).

Check yourself

Retrieval practice

1. PGP achieves confidentiality by:

Hybrid encryption: fast symmetric for the message, slow asymmetric only for the small session key.

2. In PGP, compression is done:

Sign on original (so verifier doesn't need same compressor). Compress before encryption (encrypted data is random, uncompressible).

3. S/MIME uses:

S/MIME relies on the PKI with CAs, suitable for corporate environments.

Recall without looking

PGP five services.

Authentication (sign with private key), confidentiality (session key + public key), compression (ZIP), compatibility (Base64), segmentation.

PGP vs S/MIME — two key differences.

PGP: web of trust, standalone. S/MIME: CA hierarchy (X.509), built into email clients.
