IPSec overview

IPSec operates at the network layer (IP). It secures all traffic between two points transparently — applications don’t need modification. Used in VPNs.

Two modes

Transport modeTunnel mode
ProtectsOnly the IP payload (data)The entire original IP packet (header + data)
New headerOriginal IP header staysNew outer IP header added
Used betweenHost-to-host (end-to-end)Gateway-to-gateway (or host-to-gateway)

Two security protocols

AH (Authentication Header)

Provides authentication and integrity for the entire IP packet (including parts of the header). No encryption.

AH fields Next Header | Payload Length | SPI | Sequence Number | ICV (Integrity Check Value = HMAC)

ESP (Encapsulating Security Payload)

Provides confidentiality (encryption) + authentication + integrity. Encrypts the payload; authenticates the ESP header + payload.

ESP fields SPI | Sequence Number | [Encrypted payload] | Padding | Pad Length | Next Header | ICV

Check yourself

Retrieval practice

1. Tunnel mode protects:

Tunnel mode encapsulates the whole packet, hiding the original addresses. Used for VPNs.

2. AH provides:

AH authenticates the entire packet (including IP header) but does not encrypt. ESP does both.

3. ESP encrypts:

ESP encrypts the payload and authenticates ESP header + encrypted payload. IP header is outside.

Recall without looking

Transport vs tunnel mode.

Transport: protects payload only, original header stays, host-to-host. Tunnel: protects entire original packet, new outer header, gateway-to-gateway (VPN).

AH vs ESP in one line each.

AH: authentication + integrity for entire packet, no encryption. ESP: encryption + authentication for payload, NAT-compatible.
