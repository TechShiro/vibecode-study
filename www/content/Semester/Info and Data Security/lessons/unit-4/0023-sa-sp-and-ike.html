Security Association (SA)

Definition An SA is a one-way relationship between sender and receiver defining security parameters.
Identified by the triple: (SPI, Destination IP, Protocol [AH or ESP]).
For two-way communication, two SAs are needed (one in each direction).

SA parameters include: sequence number counter, anti-replay window, AH/ESP info (algorithm, keys, IV, lifetime), mode (transport/tunnel), MTU.

Security databases

DatabasePurpose
SAD (Security Association Database)Stores all active SAs and their parameters (keys, algorithms, SPI)
SPD (Security Policy Database)Determines what to do with each packet: DISCARD, BYPASS, or PROTECT (apply IPSec)

Internet Key Exchange (IKE)

IKE automates SA establishment — negotiates algorithms and keys. Uses UDP port 500.

IKE two phases Phase 1: Establish an IKE SA (secure channel between peers). Uses DH for key agreement. Two modes: Main mode (6 messages, identity protected) or Aggressive mode (3 messages, faster but identity exposed).

Phase 2: Use the IKE SA to negotiate IPSec SAs (for AH/ESP). Uses Quick mode (3 messages). Can create multiple IPSec SAs over one IKE SA.

Retrieval practice

1. An SA is identified by:

The SPI (Security Parameter Index) in the AH/ESP header tells the receiver which SA to use.

2. SPD decides:

SPD = policy: what should happen. SAD = parameters: how it happens.

3. IKE Phase 1 establishes:

Phase 1 creates a secure management channel. Phase 2 uses that channel to negotiate the actual IPSec SAs for data protection.

Recall without looking

What is an SA?

A one-way security relationship: (SPI, dest IP, protocol). Stores keys, algorithms, mode. Two-way needs two SAs.

IKE two phases.

Phase 1: establish IKE SA (main or aggressive mode, DH). Phase 2: negotiate IPSec SAs (quick mode). Phase 1 protects Phase 2.

SPD vs SAD.

SPD: policy (discard/bypass/protect). SAD: stores active SAs with all parameters.
