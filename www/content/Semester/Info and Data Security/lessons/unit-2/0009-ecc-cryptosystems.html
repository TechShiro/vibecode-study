ECC Cryptosystems — ECDH and EC ElGamal

Turning the point arithmetic into cryptography: key generation, Diffie–Hellman key exchange on a curve, elliptic curve ElGamal encryption and decryption — both worked end to end — plus the ECC-versus-RSA argument.

The domain parameters and the key pair

Every ECC scheme starts from a set of public domain parameters that all parties agree on, and each party then holds one private integer and one public point.

The security statement in one line

Everyone sees G and PA = nAG. Recovering nA from them is exactly the ECDLP, which has no known sub-exponential attack. That single fact secures every scheme in this lesson and the ECDSA of Lesson 14.

ECDH — Elliptic Curve Diffie–Hellman

The protocol Alice picks private nA, publishes PA = nAG.
Bob picks private nB, publishes PB = nBG.

Alice computes K = nAPB    Bob computes K = nBPA
Both equal nAnBG — the shared secret point. Its x-coordinate is normally taken as the session key.
Numerical 1 — ECDH worked in full

Q. On the curve E17(2, 2): y2 = x3 + 2x + 2 mod 17 with base point G = (5, 1) of order n = 19, Alice’s private key is nA = 3 and Bob’s is nB = 10. Find both public keys and the shared secret.

Step 0 — check G is on the curve. y2 = 1; x3 + 2x + 2 = 125 + 10 + 2 = 137 ≡ 137 − 136 = 1. ✓

Step 1 — build the multiples of G we need.

2G = 2(5,1): λ = (3·25 + 2)(2·1)−1 = 77 · 2−1 ≡ 9 · 9 = 81 ≡ 13  (77 ≡ 9; 2−1 = 9 since 2×9 = 18 ≡ 1).
x3 = 169 − 10 = 159 ≡ 6;   y3 = 13(5 − 6) − 1 = −14 ≡ 3.   2G = (6, 3)

3G = 2G + G = (6,3) + (5,1): λ = (1 − 3)(5 − 6)−1 = (−2)(−1)−1 = 2.
x3 = 4 − 6 − 5 = −7 ≡ 10;   y3 = 2(6 − 10) − 3 = −11 ≡ 6.   3G = (10, 6)

Step 2 — the public keys.   PA = 3G = (10, 6)    PB = 10G = (7, 11)  (continuing the doubling chain: 4G = (3,1), 8G = (13,7), 10G = 8G + 2G = (7,11))

Step 3 — the shared secret, computed by each side.

Alice: K = nAPB = 3 × (7,11) = 3 × 10G = 30G. Since 30 mod 19 = 11, this is 11G = (13, 10).

Bob: K = nBPA = 10 × (10,6) = 10 × 3G = 30G = 11G = (13, 10).

Shared secret point K = (13, 10); the session key is its x-coordinate, 13.

Sanity checks: both sides reached the same point — if they had not, the arithmetic is wrong. And reduce the scalar mod n before multiplying: 30G = 11G because 19G = O. That shortcut saves half the work in the exam.

The man-in-the-middle warning

Exactly as with ordinary Diffie–Hellman: ECDH gives no authentication. Darth can substitute his own public point for each side and hold two separate shared secrets. The fix is to sign the exchanged points — which is ECDSA, Lesson 14 — or to certify them. State this whenever a question asks about ECDH security.

EC ElGamal — elliptic curve encryption

First, a problem to name: the plaintext must be a point on the curve, and not every integer is one. Two standard answers, and mentioning either earns a mark:

  • Koblitz’s method: embed the message m as the x-coordinate by trying x = mK + j for j = 0, 1, 2, … until x3 + ax + b is a quadratic residue; the receiver recovers m as ⌊x/K⌋.
  • Use ECC only for the key, and encrypt the data with AES under it — what real systems (ECIES, TLS) actually do.
EC ElGamal encryption and decryption Bob’s private key nB, public key PB = nBG.

Encrypt a message point Pm: Alice picks a random secret k and sends the pair
C = { C1, C2 } = { kG,   Pm + kPB }

Decrypt: Bob computes Pm = C2 − nBC1
because nBC1 = nB(kG) = k(nBG) = kPB, the same mask Alice added.
Why the ciphertext is two points

C2 hides the message under the mask kPB, and C1 = kG is the clue that lets only Bob rebuild that mask — an eavesdropper would need k from kG, which is the ECDLP. Note the message expands to twice the size, the standard drawback of ElGamal-type encryption.

Numerical 2 — EC ElGamal worked in full

Q. On E17(2,2) with G = (5,1), Bob’s private key is nB = 10 so PB = (7, 11). Alice encrypts the message point Pm = (9, 16) using random k = 7. Find the ciphertext and verify the decryption.

Step 1 — C1 = kG = 7G. From the doubling chain, 4G = (3,1) and 2G = (6,3), so 7G = 4G + 2G + G = (0, 6).

Step 2 — the mask kPB = 7 × (7,11). Since PB = 10G, this is 70G; and 70 mod 19 = 70 − 57 = 13, so kPB = 13G = (16, 4).

Step 3 — C2 = Pm + kPB = (9,16) + (16,4).
λ = (4 − 16)(16 − 9)−1 = (−12)(7)−1 ≡ 5 · 5 = 25 ≡ 8  (−12 ≡ 5; 7−1 = 5 since 7×5 = 35 ≡ 1).
x3 = 64 − 9 − 16 = 39 ≡ 5;   y3 = 8(9 − 5) − 16 = 32 − 16 = 16.   C2 = (5, 16)

Ciphertext: C = { (0, 6), (5, 16) }

Step 4 — Bob decrypts. First nBC1 = 10 × (0,6). C1 = 7G, so this is 70G = 13G = (16, 4) — the same mask, as required.

Step 5 — subtract: Pm = C2 − (16,4) = (5,16) + (16, −4) = (5,16) + (16, 13).
λ = (13 − 16)(16 − 5)−1 = (−3)(11)−1 ≡ 14 · 14 = 196 ≡ 9  (11−1 = 14 since 11×14 = 154 = 153 + 1).
x3 = 81 − 5 − 16 = 60 ≡ 9;   y3 = 9(5 − 9) − 16 = −36 − 16 = −52 ≡ 16.

Recovered Pm = (9, 16) — identical to the original. ✓

The trick that halves the work: express every point as a multiple of G and add the scalars mod n, doing full point arithmetic only for the final subtraction. Examiners accept it, and it removes most chances of error.

Applications

ECDH for key agreement in TLS 1.3, SSH, Signal and WhatsApp; ECDSA for certificates, code signing and Bitcoin/Ethereum transactions; ECIES for hybrid encryption; and ECC throughout smart cards, SIMs, passports and IoT, where an RSA key would be too large to store or too slow to use.

Check yourself

1. In ECDH, the shared secret computed by both parties is:

Scalar multiplication commutes: n_A(n_B G) = n_B(n_A G). Adding the public points would give a value an eavesdropper could compute too.

2. In EC ElGamal, the ciphertext component C₁ = kG exists in order to:

n_B C₁ = n_B kG = kP_B. An attacker would have to get k from kG — the ECDLP. And note the receiver never needs k itself.

3. On a curve where G has order 19, computing 30G is best handled by:

19G = O, so scalars work modulo the order n. The last option is right but pointless — 19G is the identity, so it contributes nothing.

4. Plaintext must be encoded as a curve point before EC ElGamal because:

Koblitz's method embeds m in the x-coordinate by trying successive candidates; real systems avoid the problem by using ECC for the key and a symmetric cipher for the data.

5. ECDH on its own is vulnerable to a man-in-the-middle attack because:

Exactly the weakness of plain Diffie–Hellman. The remedy is to sign or certify the points — ECDSA plus a certificate, which is what TLS does.

Recall without looking

List the ECC domain parameters and the key pair.

Public: the prime p, the curve coefficients a and b, the base point G, and n, the order of G. Each user picks a random private integer n_A with 1 < n_A < n and publishes the public key point P_A = n_A G. Recovering n_A from P_A is the ECDLP.

State the ECDH protocol.

Alice publishes P_A = n_A G and Bob publishes P_B = n_B G. Alice computes K = n_A P_B, Bob computes K = n_B P_A, and both equal n_A n_B G. The x-coordinate of that point is used as the session key. Without authentication of the exchanged points it is open to a man-in-the-middle attack.

Give the EC ElGamal encryption and decryption formulas.

With Bob’s public key P_B = n_B G, Alice picks a random k and sends C = {kG, P_m + kP_B}. Bob recovers the plaintext as P_m = C₂ − n_B C₁, because n_B C₁ = n_B kG = kP_B, the mask that was added. The ciphertext is twice the size of the message.

How is a message turned into a curve point?

By Koblitz’s method: take x = mK + j for j = 0, 1, 2, … until x³ + ax + b is a quadratic residue, giving a valid point; the receiver recovers m as ⌊x/K⌋. Practical systems avoid the issue by using ECC only to establish a key and encrypting the data with a symmetric cipher.

Compare ECC and RSA on six points.

ECDLP versus factoring; 256-bit versus 3072-bit keys at the same security; fast versus slow key generation; slower encryption and verification but faster signing and decryption; much smaller signatures; and best suited to constrained devices where RSA suits established server PKI.

Give the advantages and disadvantages of ECC.

Advantages: far smaller keys for equal security, lower bandwidth, storage and power, fast key generation and signing, short signatures, and better scaling as security rises. Disadvantages: complex mathematics and implementation, fatal failures if the nonce k repeats, dependence on trustworthy curve choice, side-channel risk in scalar multiplication, and vulnerability to quantum attack.
