The gap a MAC leaves

Unit I ended with a MAC: integrity plus source authentication, from a key both parties hold. That shared key is the problem. Since the receiver can produce any tag the sender can, the receiver cannot prove to a judge that the sender wrote the message — and the sender can deny it. A dispute between the two parties is unresolvable.

The definition to write

A digital signature is a value computed from a message using the signer’s private key, which anyone can verify with the corresponding public key. Because only the signer holds the private key, a valid signature proves the message came from them and has not changed — and proves it to a third party, which is what makes it a signature rather than a checksum.

The process

Signing and verification SIGNING (sender):   h = H(M)  →  S = EKprivate(h)  →  send M ‖ S

VERIFICATION (receiver):   h1 = H(M′)  and  h2 = DKpublic(S)
h1 = h2 → signature valid. Otherwise reject.
The rule that decides every public-key question

Encrypt with the key of the person who must be the only one able to do it. For confidentiality use the receiver’s public key — only they can decrypt. For a signature use the sender’s private key — only they can sign, and everyone can check. Getting these the wrong way round is the single commonest error in this topic.

Why the digest is signed, not the message

ReasonDetail
SpeedAsymmetric encryption is roughly a thousand times slower than hashing. Signing a 100 MB file means encrypting a 512-bit digest, not 100 MB.
SizeThe signature stays short and fixed-length whatever the message size.
Block limitsRSA can only encrypt a value smaller than the modulus; a long message would have to be split and each block signed separately.
SecuritySigning raw message blocks exposes RSA’s multiplicative property, which allows forgery (Lesson 11). Hashing first destroys that structure.

The four steps as a diagram

Draw it exactly like this

Sender side: M → [Hash] → h → [Encrypt with sender’s private key] → S. Transmit M and S together.

Receiver side: the received M′ → [Hash] → h1; in parallel, S → [Decrypt with sender’s public key] → h2. Both feed a comparator.

Label the comparator’s two outputs — equal means accept (authentic, unaltered, undeniable); unequal means reject. Examiners look for that comparator.

What a signature provides — and what it does not

ServiceProvided?Why
Message authenticationYesOnly the private key holder could have produced a signature that verifies
Message integrityYesAny change to M changes the recomputed digest
Non-repudiationYesThe receiver cannot forge it, so the sender cannot credibly deny it — usually with a trusted third party holding the certificate
ConfidentialityNOThe message travels in the clear. For secrecy, encrypt separately with the receiver’s public key

Signature then encryption is the usual order: sign the message, then encrypt {M, S} with the receiver’s public key — so that the signature is not exposed and the receiver knows who signed the plaintext they actually read.

Requirements of a digital signature scheme

  • The signature must be a bit pattern that depends on the message being signed — it cannot be a fixed token.
  • It must use information unique to the sender, to prevent forgery and denial.
  • It must be relatively easy to produce, easy to verify and easy to recognise.
  • It must be computationally infeasible to forge — either by constructing a new message for an existing signature, or a fraudulent signature for a given message.
  • It must be practical to retain a copy of the signature in storage, for later dispute resolution.

Check yourself

1. A digital signature is created by encrypting the message digest with:

Only the sender holds the private key, which is what makes the signature unforgeable and undeniable. Encrypting with the receiver's public key would give confidentiality instead.

2. Digital signatures sign the digest rather than the message chiefly because:

Speed and size are the main reasons, with RSA's block limit and its multiplicative property behind them. Signing gives no confidentiality at all.

3. A digital signature provides all of the following except:

The message travels in the clear beside its signature. For secrecy, encrypt {M, S} with the receiver's public key after signing.

4. The main weakness of a direct digital signature scheme is that:

Its whole validity rests on the private key staying secret, and there is no third party to fix the time of signing. Timestamps and prompt reporting of compromise are the usual remedies.

5. Compared with the RSA approach, the DSS approach to signing:

DSS-style schemes use a fresh random k per signature, output two values, and verify by recomputing v and testing v = r. They cannot be used for encryption.

6. A MAC cannot replace a digital signature because:

Symmetry destroys non-repudiation: a judge cannot tell sender from receiver. Only the asymmetry of a private key resolves a dispute.

Recall without looking

Define a digital signature.

A value computed from a message using the signer’s private key, verifiable by anyone holding the matching public key. Because only the signer has the private key, a valid signature proves the message came from them and has not been altered, and proves it to a third party.

Give the signing and verification procedures.

Signing: hash the message to get h, encrypt h with the sender’s private key to get S, and transmit M with S. Verification: hash the received message to get h₁, decrypt S with the sender’s public key to get h₂, and compare. Equal digests mean the signature is valid.

Why is the digest signed rather than the message?

Asymmetric encryption is about a thousand times slower than hashing, so signing a fixed 512-bit digest is far cheaper; the signature stays short; RSA can only encrypt values below the modulus; and hashing destroys the algebraic structure that would otherwise permit forgery through RSA’s multiplicative property.

What services does a digital signature provide, and which does it not?

It provides message authentication, message integrity and non-repudiation. It does not provide confidentiality — the message travels in the clear, so it must be separately encrypted with the receiver’s public key if secrecy is needed.

List the requirements of a digital signature scheme.

The signature must depend on the message being signed; it must use information unique to the sender; it must be relatively easy to produce, verify and recognise; it must be computationally infeasible to forge either by making a new message for an old signature or a new signature for a given message; and it must be practical to store a copy for later disputes.

Distinguish direct from arbitrated digital signatures.

A direct signature involves only sender and receiver and depends entirely on the sender’s private key staying secret — the sender can falsely claim theft and repudiate, and a stolen key allows backdated forgery, which timestamps partly address. An arbitrated signature routes every message through a trusted arbiter who validates, dates and forwards it, at the cost of requiring complete trust in that arbiter.

Give five differences between a MAC and a digital signature.

Symmetric versus asymmetric cryptography; verifiable only by the key holder versus by anyone; no non-repudiation versus non-repudiation; fast versus slow; and a key needing a secure channel versus a public key needing a certificate. MACs protect packets inside TLS and IPsec; signatures secure certificates, contracts and code.
