SHA-512

The SHA family table, the five steps, the 1024-bit block and 80 rounds, the word-expansion schedule, the six logical functions — and the padding numerical, the one calculation this unit sets.

Exam strategy

The single most likely long question in Unit I: “Explain the SHA-512 algorithm with a block diagram.” Structure the answer as parameters table → five steps → round function → word expansion, and draw two diagrams: the overall Merkle–Damgård chain and one round with the eight registers. The padding numerical is a near-certain 2–5 mark sub-question — it takes thirty seconds once the rule is memorised, so never leave it.

The SHA family

Developed by NIST with the NSA, standardised as FIPS 180. SHA-1 was the workhorse of the 1990s; the SHA-2 family (SHA-224, 256, 384, 512) replaced it after the birthday bound made 160 bits uncomfortable. This table is worth full marks by itself.

SHA-384 is SHA-512 with a different IV, truncated to its leftmost 384 bits. One sentence, one mark, frequently asked.

The five steps

Step 1 — Append padding bits

The SHA-512 padding rule Pad so that the length is congruent to 896 modulo 1024
— that is, 128 bits short of a whole 1024-bit block.
Padding is a single 1 followed by 0s, and is always present: between 1 and 1024 bits.

Step 2 — Append length

A 128-bit unsigned big-endian field holding the length of the original message in bits. The result is an exact multiple of 1024 bits.

Step 3 — Initialise the 512-bit buffer

Eight 64-bit registers a, b, c, d, e, f, g, h, initialised from the fractional parts of the square roots of the first eight prime numbers (2, 3, 5, 7, 11, 13, 17, 19) — nothing-up-my-sleeve numbers again.

The IV (first two shown; you are not expected to memorise all eight) a = 6A09E667F3BCC908    b = BB67AE8584CAA73B    …    h = 5BE0CD19137E2179

Step 4 — Process the message in 1024-bit blocks

Each block enters the compression function F, which runs 80 rounds. Each round uses one 64-bit word Wt from the expanded message schedule and one 64-bit constant Kt.

The 80 round constants

K0 … K79 are the first 64 bits of the fractional parts of the cube roots of the first 80 prime numbers. Their purpose is to destroy any regularity in the message data, so that no pattern in the input survives into the digest.

The message schedule — expanding 16 words into 80

The 1024-bit block gives only sixteen 64-bit words W0…W15, but 80 rounds need 80 words. The remaining 64 are generated:

Word expansion, for t = 16 to 79 Wt = σ1(Wt−2) + Wt−7 + σ0(Wt−15) + Wt−16   (addition mod 264)

σ0(x) = ROTR1(x) ⊕ ROTR8(x) ⊕ SHR7(x)
σ1(x) = ROTR19(x) ⊕ ROTR61(x) ⊕ SHR6(x)

The point to state: every one of the 80 rounds depends on the entire block, which is what gives SHA-512 its avalanche.

The round function

One of the 80 rounds T1 = h + Ch(e, f, g) + Σ1(e) + Wt + Kt
T2 = Σ0(a) + Maj(a, b, c)

then h←g, g←f, f←e, e←d + T1, d←c, c←b, b←a, a←T1 + T2

Note the shape of the round: only two of the eight registers are genuinely recomputed (a and e); the other six merely shift along. That observation is often worth a mark and always helps in drawing the diagram.

Step 5 — Final addition and output

After the 80 rounds, the eight output words are added modulo 264 to the eight words that entered the block (the feed-forward). The result chains into the next block. After the last block, the concatenation of the eight registers is the 512-bit digest.

The padding numerical

The method — four lines, always the same 1. r = L mod 1024, where L is the message length in bits
2. Padding P = 896 − r  (if this is ≤ 0, add 1024)
3. Total length = L + P + 128
4. Number of blocks = Total ÷ 1024
Worked example 1 — the standard case

Q. A message of 2590 bits is hashed with SHA-512. Find the padding, the total length and the number of blocks.

r = 2590 mod 1024. Since 2 × 1024 = 2048,   r = 2590 − 2048 = 542.

P = 896 − 542 = 354 bits — that is a single 1 followed by 353 zeros.

Total = 2590 + 354 + 128 = 3072 bits.

Blocks = 3072 ÷ 1024 = 3 blocks.

Sanity check: 3072 is a whole multiple of 1024, and 2590 + 354 = 2944 ≡ 896 (mod 1024). Both conditions hold.

Worked example 2 — when the remainder overshoots 896

Q. A message is 5000 bits long. Find the padding and the number of blocks.

r = 5000 mod 1024. Since 4 × 1024 = 4096,   r = 5000 − 4096 = 904.

896 − 904 = −8, which is negative, so add 1024: P = −8 + 1024 = 1016 bits.

Total = 5000 + 1016 + 128 = 6144 bits = 6 blocks.

Why: only 120 bits remained in the current block, not enough for the 128-bit length field, so the padding runs into a further block. This is the case examiners set to catch students who apply the formula blindly.

Worked example 3 — the edge case

Q. A message is exactly 896 bits. How much padding is added?

r = 896, so 896 − 896 = 0. But padding can never be zero, so P = 0 + 1024 = 1024 bits — one 1 followed by 1023 zeros.

Total = 896 + 1024 + 128 = 2048 bits = 2 blocks.

Worked example 4 — given in bytes

Q. A file of 300 bytes is hashed with SHA-512. Find the number of blocks and the number of 64-bit words processed.

L = 300 × 8 = 2400 bits.   r = 2400 − 2048 = 352.

P = 896 − 352 = 544 bits.   Total = 2400 + 544 + 128 = 3072 bits = 3 blocks.

Each block is 16 words of 64 bits, expanded to 80 in the schedule, so the compression function runs 3 × 80 = 240 rounds in total.

The three ways this numerical is disguised

(i) “in bytes” — multiply by 8 first. (ii) “how many zeros in the padding” — the answer is P − 1, because one bit is the leading 1. (iii) “with MD5/SHA-1 instead” — the same method with 448 mod 512 and a 64-bit length field. Getting the constants the right way round is the whole exercise.

Security

No collision or preimage attack is known against full SHA-512. Its 512-bit digest gives 2256 collision resistance, and its 64-bit words make it faster than SHA-256 on 64-bit processors despite the larger state. It is also naturally resistant to the length-extension weakness in its truncated form SHA-384, since 128 bits of the final state are discarded.

Check yourself

1. A 2590-bit message hashed with SHA-512 requires padding of:

2590 mod 1024 = 542; 896 − 542 = 354; 2590 + 354 + 128 = 3072 = 3 × 1024.

2. A message whose length leaves a remainder of 904 modulo 1024 receives:

Only 120 bits are left in the block, too few for the 128-bit length field, so the padding spills into another block: −8 + 1024 = 1016.

3. SHA-512 expands each block's sixteen words into eighty because:

W_t = σ₁(W_{t−2}) + W_{t−7} + σ₀(W_{t−15}) + W_{t−16}. Every later word mixes several earlier ones, which is what spreads the avalanche.

4. The 80 round constants K_t of SHA-512 are taken from:

Cube roots for the 80 round constants, square roots of the first eight primes for the IV. The sine values are MD5's per-step constants.

5. In one round of SHA-512, the registers that are genuinely recomputed are:

a ← T₁ + T₂ and e ← d + T₁; the rest are a shift register. Seeing that makes the round diagram easy to reproduce.

6. SHA-384 is best described as:

Same block size, same word size, same 80 rounds — only the initial values and the truncation differ.

Recall without looking

Give the parameters of SHA-512.

512-bit digest, 1024-bit blocks, 64-bit words, eight registers, 80 rounds, a 128-bit length field, maximum message length 2¹²⁸ − 1 bits, big-endian byte order, and 2²⁵⁶ collision resistance.

State the five steps of SHA-512.

Append padding so the length is 896 mod 1024; append the 128-bit original length; initialise the eight 64-bit registers from the fractional parts of the square roots of the first eight primes; process each 1024-bit block through 80 rounds using the expanded message schedule and the 80 constants; add the block output to the incoming values and output the concatenated registers as the 512-bit digest.

State the padding rule and the four-line method for the numerical.

Pad with a single 1 followed by zeros until the length is congruent to 896 mod 1024; padding is always between 1 and 1024 bits. Method: r = L mod 1024; P = 896 − r, adding 1024 if that is zero or negative; total = L + P + 128; blocks = total ÷ 1024.

Write the word-expansion formula and the two sigma functions.

For t = 16 to 79, W_t = σ₁(W_{t−2}) + W_{t−7} + σ₀(W_{t−15}) + W_{t−16} modulo 2⁶⁴, where σ₀(x) = ROTR¹(x) ⊕ ROTR⁸(x) ⊕ SHR⁷(x) and σ₁(x) = ROTR¹⁹(x) ⊕ ROTR⁶¹(x) ⊕ SHR⁶(x).

Write the SHA-512 round function.

T₁ = h + Ch(e,f,g) + Σ₁(e) + W_t + K_t and T₂ = Σ₀(a) + Maj(a,b,c). Then the registers shift — h←g, g←f, f←e, e←d+T₁, d←c, c←b, b←a, a←T₁+T₂ — so only a and e are genuinely recomputed.

Define Ch, Maj, Σ₀ and Σ₁.

Ch(e,f,g) = (e∧f) ⊕ (¬e∧g), the choose or selection function. Maj(a,b,c) = (a∧b) ⊕ (a∧c) ⊕ (b∧c), the majority function. Σ₀(a) = ROTR²⁸ ⊕ ROTR³⁴ ⊕ ROTR³⁹ and Σ₁(e) = ROTR¹⁴ ⊕ ROTR¹⁸ ⊕ ROTR⁴¹, both rotations only.

Where do the IV and the round constants come from?

The eight initial register values are the first 64 bits of the fractional parts of the square roots of the first eight primes; the 80 round constants K_t are the same for the cube roots of the first 80 primes. Both are nothing-up-my-sleeve numbers, and the constants exist to destroy any regularity in the message data.

Give six differences between MD5 and SHA-512.

128- versus 512-bit digest; 512- versus 1024-bit blocks; 32-bit words in four registers versus 64-bit words in eight; 64 steps versus 80 rounds; a 64-bit versus a 128-bit length field; little-endian versus big-endian. MD5 is broken for collisions at 2⁶⁴; SHA-512 offers 2²⁵⁶.
