Hash Functions and Their Properties

The three resistance properties, the requirements list, the Merkle–Damgård iterated structure that MD4, SHA-512 and Whirlpool all share, and the applications. The most reliably asked topic in Unit I.

Exam strategy

Three questions, and one of them is close to certain: “What is a cryptographic hash function? Explain its properties.” Answer it with the three resistance properties named and defined — preimage, second preimage, collision — not with a vague list of adjectives. The other two: “Explain the iterated (Merkle–Damgård) hash function structure” with the diagram, and “Differentiate hashing from encryption.”

Visual Taxonomy: The Three Pillars of Hash Function Security
1. Pre-image Resistance (One-Way) Given digest $y$, it is computationally infeasible to find any $x$ such that $H(x) = y$. Search complexity: $\mathcal{O}(2^n)$.
2. Second Pre-image Resistance Given input $x$, it is infeasible to find $x' \ne x$ such that $H(x') = H(x)$. Prevents replacing message with forged duplicate. Complexity: $\mathcal{O}(2^n)$.
3. Collision Resistance (Strong) Infeasible to find *any* distinct pair $(x, x')$ with $H(x) = H(x')$. Bounded by Birthday Attack: $\mathcal{O}(2^{n/2})$.

Definition

Cryptographic hash function A function H that takes a variable-length message M
and produces a fixed-length output h = H(M), called the hash value or message digest,
such that finding anything useful about M from h, or finding two messages with the same h,
is computationally infeasible.

Two words carry the whole meaning. Fixed-length makes the digest a practical fingerprint. Computationally infeasible means an attack exists in principle but would take longer than the age of the universe on any realistic hardware — cryptography almost never claims impossibility, only infeasibility.

The three resistance properties

These three are the answer to “properties of a hash function”. Learn the given/find shape of each — that is what distinguishes them, and mixing up the first two is the commonest error in the paper.

PropertyGivenAttacker must findAlso calledEffort for an n-bit digest
1. Preimage resistanceA digest hAny message M with H(M) = hOne-way property2n
2. Second preimage resistanceA message MA different M′ with H(M′) = H(M)Weak collision resistance2n
3. Collision resistanceNothing — free choiceAny pair M, M′ with H(M) = H(M′)Strong collision resistance2n/2
How to tell 2 from 3 in one line

Second preimage: the message is handed to you and you must match it. Collision: you may pick both messages yourself. The freedom to pick both is what makes collisions far cheaper — 2n/2 instead of 2n, by the birthday paradox of Lesson 3. That is why a 128-bit digest like MD5’s gives only 64 bits of collision security and is now considered broken.

The properties are ordered in strength: collision resistance implies second preimage resistance, but not the other way round. A hash used for digital signatures needs all three; a hash used only to store passwords needs mainly preimage resistance.

Why collisions must exist at all — the pigeonhole principle

The input space is infinite (messages of any length); the output space has only 2n values. So infinitely many messages map to each digest — collisions certainly exist. Cryptography does not deny this; it only requires that finding one is infeasible. Write that sentence in any question that asks whether a hash function is collision-free; the answer “no, but they cannot be found” earns the mark that “yes” loses.

The full requirements list

If a question asks for “requirements” or “characteristics” rather than “properties”, give this list — the three resistances plus the practical ones.

RequirementMeaning
Variable input sizeH accepts a message of any length
Fixed output sizeThe digest is always n bits (128, 160, 512…)
EfficiencyH(M) is easy and fast to compute for any M — hashing must be cheaper than encrypting

Iterated hash functions: the Merkle–Damgård scheme

Nobody designs a hash function that swallows a gigabyte in one gulp. Instead a compression function that maps a fixed, larger input to a fixed, smaller output is applied repeatedly. That construction is the Merkle–Damgård scheme, and MD4, MD5, SHA-1, SHA-512 all follow it (Whirlpool uses the related Miyaguchi–Preneel scheme of Lesson 7).

The scheme, in the five steps to write in an answer

1. Pad the message so its length is an exact multiple of the block size, and append the original message length in the last block (this length field is called MD-strengthening, and it is what stops a class of extension attacks).

2. Split the padded message into blocks M1, M2, …, Mt of equal size.

3. Initialise a chaining variable H0 to a fixed initial value (IV) defined by the standard.

4. Iterate: Hi = f(Hi−1, Mi) for i = 1…t, where f is the compression function. Each step takes the previous chaining value and the next block.

5. Output: the final chaining value Ht is the message digest.

The theorem worth quoting

If the compression function f is collision resistant, then the whole iterated hash function is collision resistant. This is the Merkle–Damgård result, and it is why designers only have to get one small function right instead of a function on arbitrary-length inputs.

Draw it as a horizontal chain of boxes labelled f, each fed from above by Mi and from the left by Hi−1, with IV entering the first box and the digest leaving the last. Every algorithm diagram in Lessons 5, 6 and 7 is a zoom-in on one of those f boxes.

Simple (non-cryptographic) hash functions — and why they fail

Sometimes asked as a short note. Two classic constructions, both far too weak for security:

TechniqueOperationWeakness
Bitwise XOR of blocksDivide the message into n-bit blocks and XOR them all together: Ci = bi1 ⊕ bi2 ⊕ … ⊕ bimReordering blocks does not change the result; forging a message with a chosen digest is trivial
Rotated XOR (RXOR)Rotate the running digest left by one bit before each XOR, so block position mattersBetter on random data, still easily forged — no avalanche, no one-wayness

The lesson these teach: a checksum detects noise, a cryptographic hash resists an adversary. CRC is in the same category — excellent against transmission errors, useless against deliberate modification.

Check yourself

1. Second preimage resistance means that given:

Option two is preimage resistance and option three is collision resistance. The distinguishing feature here is that M is fixed for you.

2. Collision resistance is harder to achieve than second preimage resistance because:

The freedom to pick both messages is exactly the birthday-paradox setting, and it square-roots the effort.

3. In the Merkle–Damgård scheme, the message length is appended to the last block in order to:

This is MD-strengthening. Without it, two messages that pad to the same bit string could be made to collide.

4. A cryptographic hash function is collision-free:

Infinite input space, finite output space. The security claim is about finding a collision, never about their existence.

5. A simple XOR of all message blocks fails as a cryptographic hash mainly because:

XOR is commutative, so order is invisible, and an attacker can adjust one block to force any digest wanted. RXOR fixes order but not forgeability.

6. Which is the correct relationship between the resistance properties?

Strong collision resistance is the strongest of the three, which is why MD5 fell to collision attacks long before any preimage attack existed.

Recall without looking

Define a cryptographic hash function.

A function H that maps a variable-length message to a fixed-length digest h = H(M), such that it is computationally infeasible to invert it, to find a second message with a given message’s digest, or to find any two messages with the same digest.

Name and define the three resistance properties, with their attack effort.

Preimage resistance (one-way): given h, cannot find M with H(M) = h — effort 2ⁿ. Second preimage resistance (weak collision resistance): given M, cannot find M′ ≠ M with the same digest — effort 2ⁿ. Collision resistance (strong): cannot find any pair M, M′ with the same digest — effort only 2^(n/2) by the birthday paradox.

List the requirements of a hash function.

Variable input size, fixed output size, efficiency of computation, preimage resistance, second preimage resistance, collision resistance, avalanche effect (pseudorandomness) and deterministic output.

Describe the Merkle–Damgård iterated hash structure.

Pad the message to a multiple of the block size and append its length (MD-strengthening); split it into blocks M₁…M_t; set H₀ to a fixed IV; iterate H_i = f(H_{i−1}, M_i) using the compression function f; output H_t as the digest. If f is collision resistant then so is the whole hash function.

Give two ways of building a compression function, with an example of each.

Made from scratch as a dedicated design — MD4, MD5, SHA-1, SHA-512. Or built from an existing block cipher using a scheme such as Rabin, Davies–Meyer, Matyas–Meyer–Oseas or Miyaguchi–Preneel — Whirlpool, which uses the AES-like cipher W.

Give four differences between hashing and encryption.

Hashing is one-way, encryption is reversible; hashing is keyless (as an MDC), encryption is always keyed; a hash output is fixed-length, ciphertext grows with the plaintext; hashing targets integrity, encryption targets confidentiality.

List five applications of hash functions.

Message integrity checking, message authentication through MACs, digital signatures (the digest is signed rather than the message), password storage, file deduplication and integrity verification, and pseudorandom number or key generation.
