The gap encryption leaves

Encryption protects confidentiality — it stops an eavesdropper reading the message. It does not stop the eavesdropper changing it. A ciphertext that has been altered in transit still decrypts; it decrypts to garbage, or in some modes to a usefully altered plaintext. The receiver has no way to tell.

The one-line justification for this whole unit

Confidentiality hides the message; it does not preserve it. Some documents — a public tender notice, a software download, a bank instruction — may not need hiding at all, yet must arrive unaltered. Integrity is therefore a separate goal, needing separate machinery.

The four security goals, and which one this unit is about

GoalQuestion it answersMechanism
ConfidentialityCan an outsider read it?Encryption (DES, AES, RSA)
IntegrityHas it been changed on the way?Hash function → message digest (MDC)
AuthenticationDid it really come from that sender?MAC, HMAC, CMAC (Lesson 4)
Non-repudiationCan the sender later deny sending it?Digital signature (Unit II)

Note the ladder: integrity alone is the weakest of the three, authentication adds the sender’s identity, and non-repudiation adds proof to a third party. A hash gives you the first, a MAC the first two, a signature all three. Stating that ladder in an answer is worth a mark on its own.

The document and fingerprint analogy

This is Forouzan’s framing and the one your examiner expects.

The analogy, stated exactly A person’s fingerprint is taken and filed alongside a document.
If the document is later disputed, the fingerprint is checked again.
A different fingerprint means the document is not the original.

In cryptography: message = document,   message digest = fingerprint.
Physical worldElectronic world
DocumentMessage M (any length)
Fingerprint of the document’s ownerMessage digest h = H(M), fixed length
Fingerprint is small, the document is largeDigest is 128–512 bits however large M is
Fingerprint must be kept where nobody can swap itThe digest must travel over a safe channel, or be protected by a key
The point students miss — and examiners test

The digest itself must be protected. If Eve can change the message she can simply recompute the digest and change that too. A plain hash sent alongside the message over the same channel gives no security against an active attacker — it only detects accidental corruption. This is precisely why Lesson 4 exists: a MAC solves it by mixing a secret key into the digest.

Message digest — the definition to write down

Message digest h = H(M)
H is a cryptographic hash function; M is a message of arbitrary length;
h is a fixed-length digest, also called a hash value, fingerprint,
or MDC (Modification Detection Code).
Property of the digestWhy it matters here
Fixed length regardless of message sizeA 1 GB file and a 3-letter message both give (say) 512 bits — cheap to store, send and sign
One-way — M cannot be recovered from hPublishing the digest reveals nothing about the message
Deterministic — same M always gives the same hWithout this, checking would be impossible
Avalanche effect — one changed input bit changes about half the output bitsMakes the comparison at the receiver a reliable yes/no test
Collision resistant — two messages with the same digest cannot feasibly be foundOtherwise Eve substitutes a different message with the same fingerprint

Checking integrity: the procedure

The three-step procedure, worth drawing as a diagram

At the sender: compute h1 = H(M). Send M over the ordinary (insecure) channel and h1 over a safe channel — or store h1 safely.

In transit: M may be altered by an attacker or by noise, becoming M′.

At the receiver: compute h2 = H(M′) from the message actually received, and compare with the h1 that arrived safely.

h1 = h2 → integrity preserved. h1 ≠ h2 → the message was modified; reject it.

Draw this as two boxes joined by two arrows — a thick arrow for the message down the insecure channel, a thin one for the digest down the safe channel — with a comparator at the receiver. That diagram, correctly labelled, is usually half the marks in an “explain message integrity” question.

SituationHow the digest is protected

Password fileOnly the digest is stored; the password itself is never kept

Check yourself

1. Encryption alone does not provide integrity because:

Confidentiality hides the message; it does not preserve it. Detecting change needs a digest, not a cipher.

2. In the document-and-fingerprint analogy, the message digest corresponds to:

Message = document, digest = fingerprint. The fingerprint is far smaller than the document and changes if the document does.

3. A message and its plain hash are sent over the same insecure channel. This provides:

The hash function is public. Eve changes M, recomputes H(M), and sends both. The digest needs a safe channel or a secret key.

4. Integrity, authentication and non-repudiation differ in that:

Hash gives integrity. MAC gives integrity plus authentication. Digital signature gives all three.

5. The avalanche effect matters for integrity checking because:

Roughly half the output bits flip for one input bit. Note that no fixed-length hash can guarantee zero collisions — that is the pigeonhole principle of Lesson 3.

Recall without looking

Define message integrity and say why encryption does not provide it.

Message integrity means the message must arrive exactly as it was sent, with any change detectable. Encryption provides confidentiality — it hides the content — but an encrypted message can still be altered in transit and the receiver cannot tell. Integrity therefore needs its own mechanism: a cryptographic hash producing a message digest.

State the document-and-fingerprint analogy.

A fingerprint is taken alongside a document and filed; if the document is later disputed the fingerprint is checked again, and a mismatch proves the document is not the original. In cryptography the message is the document and the message digest is the fingerprint — small, fixed in length, and different if the message changes.

Give the procedure for checking integrity at sender and receiver.

Sender computes h₁ = H(M), sends M over the insecure channel and h₁ over a safe channel. Receiver computes h₂ = H(M′) on the message received and compares. Equal digests mean the message is intact; unequal means it was modified and must be rejected.

Why must the digest be sent over a safe channel?

Because the hash function is public and keyless. An attacker who can alter the message can recompute the digest of the altered message and replace it, so an unprotected digest detects only accidental errors. Protecting it needs either a safe channel, a secret key (MAC) or the sender’s private key (digital signature).

Distinguish MDC from MAC.

An MDC is a keyless digest giving integrity only, and must travel over a safe channel. A MAC mixes a shared secret key into the digest, giving integrity plus source authentication, and can travel over the same insecure channel as the message. Neither gives non-repudiation; that needs a digital signature.

List five properties of a message digest.

Fixed length whatever the input size; one-way, so the message cannot be recovered; deterministic, so the same message always gives the same digest; avalanche effect, where one input bit changes about half the output bits; and collision resistance, so two messages with the same digest cannot feasibly be found.
