MD4 — Message Digest 4

The 128-bit digest, the 512-bit block, the four-word buffer, three rounds of sixteen steps, and the three boolean functions. The ancestor of MD5, SHA-1 and RIPEMD, and the reason all of them look alike.

Exam strategy

Asked as “Explain the MD4 algorithm” or, very often, “Explain MD5 / the MD family” — the two are close enough that one answer with a comparison table covers both. Marks sit in the parameter table (128 / 512 / 3 rounds / 48 steps), the padding rule, the three round functions and the diagram of one step. Do not try to memorise the shift amounts or the message-word order; no examiner asks for them.

Where it sits

MD4 was designed by Ronald Rivest at MIT in 1990 (RFC 1320). It was built to be fast on 32-bit machines and simple enough to code without lookup tables. Its importance today is historical and structural: MD5, SHA-0, SHA-1, SHA-256 and RIPEMD are all direct descendants, so learning MD4 is learning the shape of the entire family.

Step 1 — Append padding bits

The padding rule Pad the message so that its length is congruent to 448 modulo 512,
i.e. 64 bits short of a whole block.
The padding is a single 1 bit followed by as many 0 bits as needed.
Padding is always applied — between 1 and 512 bits, never zero.

The last clause matters: if the message is already 448 mod 512, a whole extra 512 bits of padding is added. Never answer “no padding needed”.

Step 2 — Append length

A 64-bit field holding the length of the original message in bits (modulo 264) is appended, filling the block out. The padded message is now an exact multiple of 512 bits. This length field is the MD-strengthening of Lesson 2.

Step 3 — Initialise the buffer

A 128-bit buffer of four 32-bit registers A, B, C, D holds the chaining value. It starts at a fixed IV, written in little-endian order:

The initial values A = 67 45 23 01    B = EF CD AB 89
C = 98 BA DC FE    D = 10 32 54 76
(the first two are ascending nibbles, the second two their complements — that is the memory hook)

Step 4 — Process the message in 512-bit blocks

Each block passes through the compression function HMD4: three rounds of sixteen steps, all four registers updated once per step, with the block’s sixteen words used once per round in a different order each time.

The three round functions

RoundFunctionDefinitionMeaning
1F(X, Y, Z)(X ∧ Y) ∨ (¬X ∧ Z)Selection — if X then Y else Z, bit by bit
2G(X, Y, Z)(X ∧ Y) ∨ (X ∧ Z) ∨ (Y ∧ Z)Majority — the bit held by at least two of the three
3H(X, Y, Z)X ⊕ Y ⊕ ZParity — XOR of the three

These are nothing-up-my-sleeve numbers — taken from the square roots of small integers so that nobody can suspect the designer of hiding a trapdoor in them. That phrase is worth writing; it is a standard one-mark point.

The operation of a single step

One step of round 1 (rounds 2 and 3 replace F with G or H and add the constant) a ← (a + F(b, c, d) + X[k]) <<< s

where X[k] is one of the sixteen message words of this block,
<<< s is a circular left shift by s bits, and
addition is modulo 232. The registers then rotate: (a,b,c,d) → (d,a,b,c).

Two features to name in an answer: addition modulo 232 is the only non-linear arithmetic, and the circular shift is what spreads a change across word boundaries — together they give the avalanche effect.

Step 5 — Output

After the three rounds, the four output words are added modulo 232 to the buffer values that entered the block (the feed-forward that makes the compression function one-way). The buffer then chains into the next block. After the last block, A ‖ B ‖ C ‖ D, in little-endian order, is the 128-bit digest.

The one-sentence summary examiners reward

MD5 is MD4 with a fourth round, a distinct additive constant at every step, and an extra addition per step — all three changes bought diffusion at the cost of speed.

Security of MD4

YearResult
1991Den Boer and Bosselaers break MD4 reduced to two rounds
1995–96Dobbertin finds full collisions in MD4 in minutes on a PC
2004–05Wang’s techniques reduce MD4 collisions to a handful of hash operations by hand, and break MD5 as well
NowMD4 must never be used for security. It survives only inside legacy protocols such as NTLM password hashes and the rsync checksum

The underlying cause is the one from Lesson 3: a 128-bit digest gives only 64 bits of collision resistance, and MD4’s three rounds provide too little diffusion even to reach that bound.

Check yourself

1. MD4 pads a message so that its length is congruent to:

448 + 64 = 512. The 896/1024 answer is SHA-512, which is the trap in this question.

2. If a message is already 448 bits long, MD4 adds:

Padding is between 1 and 512 bits and is never skipped. A message already at 448 mod 512 gets an entire extra block of padding.

3. The round-2 function G(X, Y, Z) = (X∧Y) ∨ (X∧Z) ∨ (Y∧Z) implements:

Selection is F, parity is H. Majority is G, and the same function reappears in SHA-512 as Maj(a,b,c).

4. MD5 differs from MD4 principally in that it:

Both produce 128 bits from 512-bit blocks. The differences are the extra round, the 64 per-step constants derived from |sin i|, and the extra addition of b per step.

5. The constants 5A827999 and 6ED9EBA1 are used because they:

These are nothing-up-my-sleeve numbers: 2³⁰√2 and 2³⁰√3. SHA-512 uses the same idea with cube roots of the first eighty primes.

Recall without looking

Give the parameters of MD4.

128-bit digest, 512-bit blocks, 32-bit words, four registers A B C D, three rounds of sixteen steps giving 48 steps, little-endian byte order, maximum message length 2⁶⁴ − 1 bits, Merkle–Damgård structure.

State the five steps of MD4.

Append padding bits so the length is 448 mod 512; append the 64-bit original length; initialise the four-register buffer to the fixed IV; process the message in 512-bit blocks through three rounds of sixteen steps; add the block output to the incoming buffer values and, after the last block, output A‖B‖C‖D as the 128-bit digest.

State the MD4 padding rule precisely.

A single 1 bit followed by enough 0 bits to bring the length to 448 modulo 512. Padding is always present, between 1 and 512 bits, so a message already at 448 mod 512 receives a whole extra 512-bit block of padding. A 64-bit length field then completes the block.

Name the three round functions with their definitions.

F(X,Y,Z) = (X∧Y) ∨ (¬X∧Z), a selection; G(X,Y,Z) = (X∧Y) ∨ (X∧Z) ∨ (Y∧Z), a majority; H(X,Y,Z) = X ⊕ Y ⊕ Z, a parity. Rounds 1, 2 and 3 use them in that order, with additive constants 0, 5A827999 and 6ED9EBA1.

Write the form of a single MD4 step.

a ← (a + F(b,c,d) + X[k] + K) <<< s, where X[k] is a message word of the current block, K the round constant, <<< a circular left shift and addition is modulo 2³². The registers then rotate so that a different one is updated at the next step.

Give six differences between MD4 and MD5.

Three rounds and 48 steps versus four rounds and 64 steps; three round functions versus four, MD5 adding I(X,Y,Z) = Y ⊕ (X ∨ ¬Z); one constant per round versus a unique constant per step taken from |sin i|; MD5 adds the rotated result to b for extra diffusion; MD4 is faster, MD5 more diffusive; both are broken for collisions, MD4 far more thoroughly.

Summarise the security history of MD4.

Two of its three rounds were broken in 1991; Dobbertin found full collisions in 1995–96; by 2005 Wang’s methods reduced collision finding to a trivial cost. Its 128-bit digest gives only 64 bits of collision resistance in any case, so MD4 must never be used for security and survives only in legacy uses such as NTLM and rsync.
