Challenge-response authentication

The verifier sends a challenge (a fresh random number, called a nonce). The claimant computes a response using their secret and the nonce. Since the nonce is different every time, a recorded response cannot be replayed.

Symmetric-key challenge-response

Unilateral authentication (A proves identity to B) 1. B → A:   RB   (random nonce)
2. A → B:   EK(RB)   (encrypt nonce with shared key K)
3. B decrypts, checks RB matches. If yes, A is authenticated.
Mutual authentication (both prove identity) 1. A → B:   RA
2. B → A:   EK(RA ‖ RB)
3. A → B:   EK(RB)
A decrypts step 2, checks RA, extracts RB, encrypts RB in step 3. B decrypts step 3, checks RB.

Asymmetric-key challenge-response

Using digital signatures 1. B → A:   RB
2. A → B:   SigA(RB)   (sign nonce with A’s private key)
3. B verifies with A’s public key. If valid, A is authenticated.
Why nonces defeat replay

A replay attacker has EK(Rold) from a previous session. But next time B sends a new Rnew and expects EK(Rnew). The attacker cannot compute this without K.

Timestamps as an alternative to nonces

Instead of a nonce, use the current time T. A sends EK(T) and B checks that T is recent. This reduces the protocol to one message but requires synchronised clocks — a practical difficulty.

The reflection attack

In a naïve mutual protocol where both sides use the same key, an attacker can open a second session to the verifier, forward the challenge, and get the response computed for free. Defence: use different keys for each direction, or include identifiers in the encrypted response.

Zero-Knowledge Proofs (ZKP)

A zero-knowledge proof lets Alice prove to Bob that she knows a secret without revealing any information about the secret itself.

Three properties of a ZKP 1. Completeness: if Alice knows the secret, Bob will always be convinced.
2. Soundness: if Alice does NOT know the secret, she cannot convince Bob (except with negligible probability).
3. Zero-knowledge: Bob learns NOTHING about the secret beyond the fact that Alice knows it.

The cave analogy (Ali Baba’s cave)

A circular cave with a locked door at the back. Alice enters from one side (chosen randomly). Bob calls out “come out from the left” (or right). If Alice knows the secret word to open the door, she can always comply. If she doesn’t, she succeeds only if she guessed correctly — probability ½. After n rounds, the probability of faking drops to 2−n.

The Fiat–Shamir protocol

Fiat–Shamir identification Setup: n = pq (RSA modulus). Alice picks secret s, publishes v = s² mod n.

Round:
1. Alice picks random r, sends x = r² mod n (commitment)
2. Bob sends challenge bit e ∈ {0, 1}
3. Alice sends y = r · se mod n (response)
4. Bob checks: y² ≡ x · ve (mod n)

Repeat t rounds. Probability of cheating = 2−t.
Why it is zero-knowledge

Bob sees (x, e, y) but x is random (r² mod n) and y reveals nothing about s because r is random. A simulator can produce transcripts identical to real ones without knowing s — this is the formal definition of zero-knowledge.

Interactive vs non-interactive ZKP

  • Interactive: requires back-and-forth between prover and verifier (Fiat–Shamir protocol above).
  • Non-interactive: the challenge is derived from the commitment using a hash function (Fiat–Shamir heuristic). Used in digital signatures and blockchain.

Retrieval practice

1. Challenge-response authentication defeats replay attacks because:

A fresh nonce means each response is unique to that session. An attacker who records E_K(R_old) cannot produce E_K(R_new) without K.

2. In a symmetric challenge-response, the claimant proves identity by:

The claimant encrypts the nonce with K, proving they possess K without sending K itself.

3. The three properties of a zero-knowledge proof are:

Completeness (honest prover convinces), soundness (dishonest prover fails), zero-knowledge (verifier learns nothing beyond the claim).

4. In Fiat–Shamir, after t rounds the probability of cheating is:

Each round the cheater has a ½ chance of guessing the challenge bit correctly. After t rounds, the probability is (½)t = 2−t.

5. A reflection attack exploits:

The attacker forwards the challenge to the same verifier in a second session, getting the response computed without knowing the key.

6. Using timestamps instead of nonces requires:

Timestamps replace the nonce but need both parties’ clocks to agree within a tolerance. Clock drift opens a replay window.

7. The Fiat–Shamir heuristic converts an interactive ZKP to non-interactive by:

Instead of the verifier choosing the challenge, the prover computes e = H(x) from their own commitment. No interaction needed.

Recall without looking

Draw the symmetric challenge-response protocol.

B → A: R_B (nonce). A → B: E_K(R_B). B decrypts, checks match. For mutual: add A → B: R_A first, and B responds with E_K(R_A | R_B).

State the three properties of a ZKP.

Completeness: honest prover always convinces. Soundness: dishonest prover fails except with negligible probability. Zero-knowledge: verifier learns nothing about the secret.

Explain the Fiat–Shamir protocol.

Setup: v = s² mod n. Round: Alice sends x = r² mod n, Bob sends bit e, Alice sends y = r·s^e mod n, Bob checks y² = x·v^e mod n. Cheating probability = 2^{-t} after t rounds.

How does a reflection attack work?

Attacker opens a second session with the verifier, forwards the challenge, and gets the encrypted response computed for free. Defence: use directional keys or include identifiers.
