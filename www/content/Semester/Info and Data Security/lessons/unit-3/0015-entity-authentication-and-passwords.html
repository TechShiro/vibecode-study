Entity Authentication and Passwords

The difference between message authentication and entity authentication, the three factor categories, password-based schemes — fixed passwords, one-time passwords (OTP), S/Key and the dictionary attack — and why passwords alone are never enough.

Exam strategy

Entity authentication vs message authentication is a guaranteed 2–4 marker. Password attacks (dictionary, brute-force, replay) and countermeasures (salting, hashing, OTP) are a separate 5-marker. This lesson covers both.

Visual Taxonomy: The Three Fundamental Authentication Factors
1. Knowledge Factor ("What you know") Passwords, PINs, secret answers. Cheap and ubiquitous, but vulnerable to shoulder surfing, phishing, dictionary and brute force attacks.
2. Possession Factor ("What you have") Hardware tokens, smart cards, authenticator apps (TOTP), SMS OTP. Cannot be easily guessed; requires physical theft to compromise.
3. Inherence Factor ("What you are") Fingerprint, iris, facial recognition, voiceprint, keystroke dynamics. Cannot be lost or forgotten, but cannot be reissued if revoked.

Entity authentication (also called identification) answers: “Is the party I am talking to really who they claim to be, right now?” The “right now” is what makes it different from a MAC or signature, which can be verified offline.

The three authentication factors

Something you KNOW · something you HAVE · something you ARE Knowledge: password, PIN, passphrase
Possession: smart card, hardware token, phone (OTP app)
Inherence: fingerprint, iris, voice, face (biometrics — Lesson 17)

Multi-factor authentication (MFA) combines two or more factors. ATM = card (have) + PIN (know). Modern logins = password (know) + OTP on phone (have).

The line examiners want

Using two factors from the same category (two passwords) is not multi-factor. MFA requires factors from different categories.

Password-based authentication

Fixed passwords

The simplest scheme: the claimant sends (ID, password) and the verifier checks against a stored copy.

Threats:

  • Eavesdropping / sniffing: password sent in cleartext can be intercepted.
  • Replay attack: an attacker records the login and replays it later.
  • Dictionary attack: try every word in a dictionary (and common substitutions).
  • Brute-force attack: try every possible combination systematically.
  • Password file theft: if the server stores plaintext passwords, stealing the file compromises everyone.
  • Social engineering / phishing: trick the user into revealing the password.

Countermeasures

DefenceHow it helps
HashingStore h(password), not the password. Even if the file is stolen, the attacker must invert the hash.
SaltingStore (salt, h(salt ‖ password)). A random salt per user defeats precomputed rainbow tables and ensures two users with the same password have different hashes.
Key stretchingIterate the hash thousands of times (PBKDF2, bcrypt, scrypt) to make brute-force slow.
Account lockoutLock after n failed attempts.
Encryption in transitTLS/SSL prevents eavesdropping.

One-Time Passwords (OTP)

Each password is valid for exactly one login. Even if intercepted, it is useless for the next session. This defeats replay attacks completely.

S/Key (Lamport’s scheme) Setup: user picks a secret s. Compute a hash chain:
p1 = h(s),   p2 = h(p1) = h2(s),   …   pn = hn(s)

Server stores pn (the last value).

Login k: user sends pn−k. Server checks h(pn−k) = pn−k+1 (its stored value).
If correct, server replaces its stored value with pn−k.
Why S/Key works

The hash chain is used backwards. An attacker who intercepts pn−k would need to compute h−1 to find pn−k−1, which is inverting the hash — infeasible. Forward computation (hashing) is easy; backward computation is the one-way property.

TOTP and HOTP

  • HOTP (HMAC-based OTP): OTP = Truncate(HMAC(K, counter)). Counter increments on each use.
  • TOTP (Time-based OTP): OTP = Truncate(HMAC(K, ⌊time/30⌋)). Changes every 30 seconds. Used by Google Authenticator, Microsoft Authenticator.

Check yourself

Retrieval practice

1. The key difference between entity authentication and message authentication is:

Entity authentication requires timeliness — proving identity NOW. A MAC or signature on a message can be verified at any time.

2. The three factors of authentication are:

Know = password/PIN, Have = token/card, Are = biometric. MFA uses at least two from different categories.

3. Salting a password hash defends against:

A random salt per user means an attacker cannot use a single precomputed table. Even two users with password “123456” get different hashes.

4. In S/Key, the hash chain is used:

The chain is used backwards because going forward (hashing) is easy but going backward (inverting) is infeasible. An intercepted OTP cannot produce the next one.

5. TOTP generates a new code every:

TOTP uses ⌊time/30⌋ as input to HMAC. HOTP uses a counter instead.

6. A replay attack is defeated by:

OTPs are valid once only. Challenge-response uses a fresh random nonce each time, so a recorded response is useless next time.

7. Two passwords from the same category constitute:

MFA requires factors from different categories. Two passwords are both “knowledge” — still single-factor.

Recall without looking

Entity authentication vs message authentication.

Entity: proves identity in real-time (who are you NOW?). Message: proves origin and integrity of a message (who sent this, and is it unchanged?). Entity requires timeliness; message does not.

Name the three authentication factors.

Something you know (password, PIN), something you have (token, smart card), something you are (biometric). MFA = two or more from different categories.

How does S/Key work?

Hash chain used backwards: p_n = h^n(s). Server stores last value. Login k: user sends p_{n-k}, server checks h(p_{n-k}) = stored value, then replaces stored value. Intercepted OTP is useless because inverting the hash is infeasible.

Three password countermeasures.

Hashing (store h(pw) not pw), salting (random salt defeats rainbow tables), key stretching (PBKDF2/bcrypt makes brute-force slow). Also: account lockout, TLS in transit.
