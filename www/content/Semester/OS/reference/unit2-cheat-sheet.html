Scheduling basics

Four situations for a scheduling decision: (1) running → waiting, (2) running → ready, (3) waiting → ready, (4) terminates. Only 1 and 4 → non-preemptive; otherwise preemptive.

Dispatcher's three steps: switch context · switch to user mode · jump to the proper location in the user program. Time taken = dispatch latency.

Five criteria: CPU utilisation (max, 40–90 %) · throughput (max) · turnaround time (min) · waiting time (min) · response time (min). Scheduling affects only waiting time directly.

Burst distribution: exponential — very many short bursts, few long ones. That is why SJF works.

Convoy effect: in FCFS one CPU-bound process holds the CPU while short I/O-bound processes queue behind it — both CPU and devices end up under-utilised.

Exponential averaging — predicting the next burst τn+1 = α tn + (1 − α) τn
α = 0 → recent history ignored  ·  α = 1 → only the last burst counts  ·  α = ½ is usual.
Round Robin rules Queue rule: on preemption, processes that arrived during the quantum join the queue first, then the preempted process.
Waiting bound: no process waits more than (n − 1) × q for its next turn.
q too large → FCFS. q too small → processor sharing drowned in context-switch overhead. Rule of thumb: 80 % of bursts shorter than q.

Ageing: gradually raise the priority of long-waiting processes. Priorities 127 (low) to 0 (high), +1 every 15 min → a priority-127 process reaches 0 within 32 hours.

Multilevel and multiprocessor

Multilevel queue: permanent assignment to one queue; between queues either fixed-priority preemptive (risks starvation) or a fixed time slice each (80 % foreground / 20 % background).

Multilevel feedback queue — the distinction: a process CAN move between queues. Demotion punishes CPU hogs; promotion is ageing and prevents starvation. Five parameters: number of queues · algorithm per queue · when to upgrade · when to demote · which queue a process enters. It is the most general and most complex algorithm.

 Asymmetric (AMP)Symmetric (SMP)
SchedulingOne master does everythingEach processor is self-scheduling
RacesNone — one processor touches the dataMust be carefully programmed

Processor affinity: keep a process on the same CPU so its cache stays warm. Soft = attempted, not guaranteed; hard = the process names its allowed CPUs (sched_setaffinity()). Affinity works against load balancing.

Load balancing: needed only with private per-CPU queues. Push migration = a periodic task moves work off a busy CPU; pull migration = an idle CPU takes work from a busy one.

Memory stall: a core can spend up to half its time waiting on memory → multithreaded multicore (hyper-threading / chip multithreading). Two scheduling levels: the OS picks the software thread for each hardware thread; the hardware picks which hardware thread runs on the core. Coarse-grained switching costs a pipeline flush; fine-grained switches at instruction-cycle boundaries.

Real time: rate-monotonic = static priority, inversely proportional to period. EDF = dynamic priority by nearest deadline. Minimise interrupt latency and dispatch latency.

Synchronisation high yield

Race condition: with count = 5, a concurrent count++ and count-- can leave 4, 5 or 6, because each compiles to load–modify–store and whichever store is last wins.

The three conditions — M P B Mutual exclusion — if Pi is in its critical section, no other process is. Prevents corruption.
Progress — if no process is in its critical section, only processes not in their remainder section decide who enters next, and the choice is not postponed indefinitely. Prevents deadlock.
Bounded waiting — a bound exists on how many times others may enter after a process requests and before it is granted. Prevents starvation.

flag[i] = false;

Mutual exclusion: if both were inside, both flags are true, so both need turn equal to their own index — impossible.
Progress: if Pj is in its remainder, flag[j] is false and Pi enters at once.
Bounded waiting: Pi waits at most one turn.

Hardware: test_and_set(&t) saves the old value, sets t = true, returns the old — atomically. Loop: while (test_and_set(&lock)) ; … lock = false;. Satisfies mutual exclusion but not bounded waiting without a waiting[] array. compare_and_swap swaps only if the value matches the expected one.

Disabling interrupts fails because it does not work on a multiprocessor, a looping user process would hang the machine, and the clock is missed.

Mutex lock: acquire() spins until available then clears it; release() sets it. Busy-waiting version = spinlock, justified on a multiprocessor with short critical sections.

Semaphores

wait and signal — both atomic wait(S)  (P, down):   while (S <= 0) ; S--;
signal(S) (V, up):   S++;

Block–wakeup version: wait decrements, and if S < 0 adds the process to the list and calls block(). signal increments, and if S ≤ 0 removes a process and calls wakeup().
A negative value's magnitude = the number of blocked processes.
QuestionWorkingAnswer
Init 10, 6 P, 4 V10 − 6 + 48, nobody blocked

Binary vs counting: 0/1 vs any integer · mutex lock vs general · init 1 vs init N · mutual exclusion vs resource counting · one process vs up to N.

Ordering: to make S2 follow S1, use synch = 0; P1 does S1 then signal(synch), P2 does wait(synch) then S2. Precedence graph: one semaphore per edge, all 0, signal at the tail and wait at the head.

Priority inversion: a high-priority process waits because a low-priority one holds a lock, and a medium-priority process preempts the holder. Fix: priority inheritance — the holder temporarily inherits the waiter's priority. Mars Pathfinder, 1997.

Four misuses: swapping wait and signal → several processes inside; wait instead of signal → deadlock; omitting wait → no mutual exclusion; omitting signal → deadlock.

Monitors

Definition: an abstract data type encapsulating shared data with the procedures that operate on it, guaranteeing only one active process inside at a time — the compiler inserts the mutual exclusion.

Condition variables: x.wait() suspends and releases the monitor; x.signal() resumes exactly one process, and has no effect at all if nobody is waiting.

Signal and wait (Hoare) — the signalled process runs, the signaller waits; the condition is known to hold. Signal and continue (Java, C#, Pthreads) — the signaller runs on, so the waiter must re-test in a while loop.

Dining philosophers monitor: state[5] of THINKING/HUNGRY/EATING plus condition self[5]. pickup(i): set HUNGRY, test(i), wait if not EATING. putdown(i): set THINKING, test((i+4)%5) and test((i+1)%5). test(i): set EATING and signal only if i is HUNGRY and neither neighbour is EATING. Deadlock-free (no hold-and-wait) but not starvation-free.

Conditional wait x.wait(c): the process with the smallest priority number c is resumed first; without it the default is FCFS.
