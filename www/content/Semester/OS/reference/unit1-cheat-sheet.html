Definitions to write verbatim memorise

TermDefinition
Operating system(1) A program that manages the computer's hardware resources and allocates them fairly and efficiently. (2) A program acting as an interface between user and hardware, controlling execution and preventing improper use. The kernel is the one program running at all times.
ProcessA program in execution — an active entity with a program counter, resources and a memory image.
ThreadA basic unit of CPU utilisation, comprising a thread ID, program counter, register set and stack.
PCBThe data structure representing a process, holding everything the OS knows about it.
System callThe programmatic way a program requests a service from the kernel — the only legal entry point.
Context switchSaving the state of the running process into its PCB and loading the next process's state from its PCB.
Race conditionSeveral processes access shared data concurrently and the outcome depends on the order of access.

Functions, goals and structure

Four-layer view: users → application programs → operating system → hardware.

Goals: convenience (primary), efficiency (secondary), ability to evolve.

Eight functions: process, memory, file, I/O device, secondary storage management; protection and security; networking; command interpretation.

Dual-mode operation mode bit = 0 → kernel mode (all instructions)    mode bit = 1 → user mode (privileged instructions trap)
Privileged: all I/O instructions · set the timer · interrupt management · switch to kernel mode · clear memory · modify MMU registers · halt.
Dual mode protects the OS from user programs; the timer protects it from programs that never stop.
CPU utilisation under multiprogramming Utilisation = 1 − pn   (p = fraction of time a process waits for I/O, n = processes in memory)
p = 0.8:   n=1 → 20 %  ·  n=2 → 36 %  ·  n=4 → 59 %  ·  n=10 → 89.3 %

Monolithic vs microkernel: everything vs only IPC in the kernel · large vs small · function calls vs messages · faster vs slower · lower vs higher reliability · recompile vs add a user server.

Why modular wins: interfaces like layers, separability like a microkernel, speed like monolithic — modules run in kernel mode and call directly.

Embedded / networkEmbedded: special-purpose, limited. Network: the user knows the machines and logs in explicitly

System boot six steps

  1. Power on; the PC is set to a fixed ROM address.
  2. The bootstrap program (BIOS / UEFI firmware) runs.
  3. POST — power-on self-test of CPU, memory, devices.
  4. Locate the boot block — the first sector of the boot disk (MBR).
  5. The boot loader (GRUB, Windows Boot Manager) loads the kernel into memory.
  6. The kernel initialises, creates the first process (init / systemd), starts daemons, waits for events.

SYSGEN = configuring the OS for the specific machine: CPU, memory size, devices, options.

Services, interfaces and system programs

Group A — helpful to the user: user interface · program execution · I/O operations · file system manipulation · communication · error detection.
Group B — efficient system operation: resource allocation · accounting · protection and security.

CLI vs GUI: steep vs gentle learning · faster vs slower for an expert · very low vs high resource use · excellent vs poor automation · risky vs protected against typos.

Six categories of system program: file management · status information · file modification · programming-language support · program loading and execution · communications. (Plus background services / daemons.)

Debugging: log files · core dump = failed user process · crash dump = failed kernel · trace listings and counters for performance tuning · Heisenbug = a bug that changes when observed.

Three parameter-passing methods: registers (fastest, but limited in number) · block in memory, address in a register (no limit; Linux, Solaris) · stack (no limit).

System call vs API vs function call: kernel mode + mode switch vs user mode, no switch. printf() is API; write() is the system call. APIs give portability and simplicity.

The cp trace: get both file names → open input (abort with message on failure) → create output (abort or ask to overwrite) → loop read/write with error checks → detect EOF → close both → message and exit.

Job mix: the long-term scheduler must pick a mix of I/O-bound and CPU-bound processes — all of one kind idles either the CPU or the devices.

fork() — the numerical rule fork() returns 0 in the child, the child's PID in the parent, −1 on failure.
n successive unconditional forks → 2n processes = 2n − 1 children; a later printf runs 2n times.
Conditional forks: draw the tree — the doubling rule no longer applies.

Zombie = terminated, parent has not called wait(). Orphan = parent died first; re-parented to init. Cascading termination = killing a process kills all descendants.

Bounded buffer: empty when in == out; full when (in+1) % BUFFER_SIZE == out; usable capacity BUFFER_SIZE − 1.

Three message-passing design questions: naming — direct (name the process; poor modularity) or indirect (name a mailbox); synchronisation — blocking or non-blocking, with blocking–blocking called a rendezvous; buffering — zero capacity (sender must block), bounded (blocks when full), unbounded (never blocks).

Ordinary pipe: unidirectional, needs a parent–child relationship, no file-system name, dies with the processes. Named pipe (FIFO): bidirectional, no relationship needed, named via mkfifo(), persists.

Threads

Own: thread ID, program counter, register set, stack. Share: code, data, heap, open files, signals, address space.

Four benefits: responsiveness · resource sharing · economy · scalability.

ModelAdvantageDisadvantageExample
Many-to-oneFast — all in user spaceOne blocking call blocks the process; no parallelismGreen Threads
One-to-oneReal concurrency and parallelismKernel-thread creation cost → a cap on thread countLinux, Windows
Many-to-manyBoth benefits; no artificial limitDifficult to implementOlder Solaris; two-level in IRIX, HP-UX
Amdahl's law speed-up ≤ 1 / ( S + (1 − S)/N ),   S = serial fraction, N = cores.   Ceiling = 1/S.
S = 0.25: N=2 → 1.6, N=4 → 2.286, max 4×.   S = 0.05: N=8 → 5.93, max 20×.
Check: the answer must be less than N and less than 1/S.

Concurrency = several tasks make progress (one core suffices). Parallelism = several execute at the same instant (needs several cores).

Five multicore challenges: identifying tasks · balance · data splitting · data dependency · testing and debugging.

Six threading issues: fork/exec semantics · signal handling · cancellation (asynchronous vs deferred, which stops at cancellation points) · thread-local storage · thread pools · scheduler activations with LWPs and upcalls.
