1. I/O Hardware & Transfer Mechanisms guaranteed

  • Registers in Device Controller: Data-in (read by CPU), Data-out (written by CPU), Status (busy/ready flags), Control (commands).
  • Memory-Mapped vs Port-Mapped I/O: Memory-mapped shares CPU RAM address space, uses regular MOV instructions. Port-mapped has separate I/O space and special IN/OUT instructions.
MechanismOperationCPU OverheadBest For

Interrupt-DrivenDevice raises INTR; CPU executes ISR via vector tablePer-byte / word context switchSlow/sporadic devices (keyboard)

DMA Modes: Burst mode (DMAC locks bus for entire block). Cycle stealing (DMAC steals single bus cycles during CPU internal ALU work).

2. Kernel I/O Subsystem: Buffering & Spooling arithmetic

  • Why Buffer? 1. Speed mismatch. 2. Transfer size mismatch. 3. Copy semantics.
  • Buffering Arithmetic ($T$ = transfer time, $C$ = compute time, $M$ = memory copy):
    • No buffering: Time per block = $T + C$.
    • Single buffering: Time per block = $\max(C, T) + M$.
    • Double buffering (ping-pong): Time per block = $\max(C, T)$ (complete concurrency).
  • Buffering vs Caching vs Spooling:
    • Buffering: Transient storage for in-transit speed/size smoothing.
    • Caching: Holds fast duplicate copy of disk blocks to accelerate repeated reads.
    • Spooling: Queues entire output files on disk for dedicated serial devices (printers).
  • STREAMS: Modular full-duplex character I/O: Stream head ↔ STREAMS modules (read/write queues) ↔ Driver.

3. Protection & Access Matrix guaranteed 10-marker

Access Matrix: Rows = Domains ($D_i$). Columns = Objects ($O_j$). Entry $A[i,j]$ = Access Rights.
Dynamic Rights: switch (transition to another domain), copy (*) (propagate rights), owner (add/delete rights in column), control (modify row rights).
PropertyAccess Control List (ACL)Capability List (C-List)
Matrix PartitionDecomposition by Columns (stored with object)Decomposition by Rows (stored with domain/process)
EnforcementKernel checks list on object access (e.g. open)Process presents unforgeable ticket/token to kernel
RevocationTrivial and immediate: delete domain entry from objectDifficult: capabilities are widely distributed
Real-World UseUnix permissions, Windows NTFS ACLsFile descriptors, microkernel capabilities (Mach)

Revocation Trade-offs: Immediate vs delayed, selective vs general, partial vs total, temporary vs permanent.

4. OS Threats & Security Case Studies taxonomy

  • Program Threats:
    • Trojan Horse: Masquerades as legitimate software while performing hidden malicious actions.
    • Trapdoor / Backdoor: Developer secret bypass skipping standard authentication.
    • Logic Bomb: Dormant malicious code triggered by a specific event or condition.
    • Buffer Overflow: Overwriting stack frame return address to execute shellcode.
  • System & Network Threats: Port scanning (reconnaissance via nmap), Denial of Service (TCP SYN flood exhausting backlog, defended by SYN Cookies).
  • Linux Case Study — SELinux (MAC): Discretionary Access Control (DAC) fails when root is hijacked. SELinux enforces Mandatory Access Control (MAC) via Type Enforcement: kernel labels all processes and objects; access blocked unless explicit policy rule exists, even for root.
  • Windows Case Study: Security Identifiers (SIDs), Access Tokens inherited by processes, Security Descriptors containing DACLs, and User Account Control (UAC) least-privilege token stripping.

Ten-Minute Exam Final Scan

  1. DMA cycle stealing: DMAC transfers a byte over the bus when the CPU is busy with internal ALU operations.
  2. Double buffering time: Effective time per block = $\max(C, T)$. Complete overlap of I/O and CPU computation.
  3. Least privilege: Operating processes with minimal necessary rights limits vulnerability impact.
  4. ACL vs C-List: ACL = column (with object, easy revocation). C-List = row (with domain, difficult revocation).
  5. Spooling: Queues files on disk because physical printers cannot interleave output from concurrent processes.
  6. SELinux: Uses Type Enforcement (MAC) to confine processes regardless of whether they have UID 0 (root).
  7. SYN flood: Exhausts half-open connection backlog table; mitigated using SYN Cookies.
