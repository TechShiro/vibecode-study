When is page replacement needed?

When a page fault occurs and no free frame is available, the OS must choose a victim page to evict. If the victim is dirty (modified), it must be written to disk first.

Optimal (OPT / MIN)

Replace the page that will not be used for the longest time in the future. Gives the minimum possible faults. Not implementable (requires future knowledge) but used as a benchmark.

Belady’s anomaly

With FIFO, increasing the number of frames can increase page faults. Example: reference string 1,2,3,4,1,2,5,1,2,3,4,5 with 3 frames gives 9 faults; with 4 frames gives 10 faults. LRU and OPT are stack algorithms and never exhibit this anomaly.

Frame allocation

  • Equal allocation: divide frames equally among processes.
  • Proportional allocation: allocate frames proportional to process size.
  • Global replacement: a process can take a frame from any other process.
  • Local replacement: a process can only replace its own frames.

Thrashing

Thrashing: a process spends more time paging (swapping in/out) than executing. CPU utilisation drops sharply.

Cause and solution Cause: too many processes, each with too few frames to hold its working set.
Working set: the set of pages a process actively uses in a time window Δ.
Solution: if total working set demand > available frames, suspend a process (reduce multiprogramming degree).

Check yourself

Retrieval practice

1. FIFO replaces the page that:

FIFO = queue order. The first page loaded is the first evicted, regardless of whether it is still being used.

2. Belady’s anomaly can occur with:

Only FIFO. LRU and OPT are stack algorithms — more frames always means ≤ faults.

3. LRU replaces the page that:

LRU looks at the past (last use time). OPT looks at the future. They are mirror images.

4. Thrashing is caused by:

Each process gets fewer frames than its working set needs, causing constant page faults. CPU utilisation drops.

5. The working set model solves thrashing by:

If Σworking_set_sizes > total frames, the OS suspends a process to free frames for the others.

6. Optimal page replacement gives:

OPT replaces the page used farthest in the future. Impossible to implement (requires oracle), but used to measure other algorithms.

Recall without looking

FIFO vs LRU vs Optimal — one sentence each.

FIFO: evict oldest page (queue). LRU: evict least recently used (past). OPT: evict farthest future use (benchmark, not implementable). LRU and OPT are stack algorithms (no Belady's anomaly).

What is Belady’s anomaly?

With FIFO, more frames can cause MORE page faults. Does not happen with LRU or OPT (stack algorithms).

What is thrashing and how is it solved?

Thrashing = process spends more time paging than executing (too few frames). Solution: working set model — ensure each process has enough frames, suspend one if demand > supply.

Global vs local replacement.

Global: process can take frames from others (higher throughput, risk thrashing). Local: process replaces only its own frames (isolated, predictable).
