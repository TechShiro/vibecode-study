Deadlock Detection and Recovery

The detection algorithm (wait-for graph for single-instance, Banker’s-style for multi-instance), when to run it, and the four recovery strategies.

Exam strategy

“Explain deadlock detection algorithm” or “differentiate prevention, avoidance, and detection”. Recovery is a short-note — know process termination and resource preemption.

Detection

Single-instance resources

Maintain a wait-for graph (collapse the RAG: Pi→Pj if Pi waits for a resource held by Pj). Deadlock ⇔ cycle in wait-for graph.

Multi-instance resources

Same algorithm as Banker’s safety check, but using Request instead of Need (what each process is currently requesting, not its maximum). If some processes remain unfinished, they are deadlocked.

Check yourself

Retrieval practice

1. For single-instance resources, deadlock detection uses:

Wait-for graph collapses the RAG. A cycle directly indicates deadlock when each resource has one instance.

2. The difference between avoidance and detection is:

Avoidance checks safety before granting. Detection lets deadlock happen, then finds and recovers.

3. Starvation during recovery is prevented by:

If the same process is always chosen as victim, it starves. A cost factor including rollback count prevents this.

Recall without looking

Single-instance vs multi-instance detection.

Single: wait-for graph, cycle = deadlock. Multi: Banker's-style with Request (not Max), unfinished processes are deadlocked.

Four recovery methods.

Terminate all, terminate one-at-a-time, resource preemption, rollback to checkpoint.
