Deadlock Prevention and Avoidance

Prevention by breaking one of the four conditions, avoidance using the safe-state concept, and the Banker’s Algorithm — the single most important numerical in this unit.

Exam strategy

Banker’s Algorithm is a guaranteed 10–15 mark numerical. You must compute Need = Max − Allocation, then find a safe sequence. Show the Work vector at every step. Prevention is a 5-mark theory question.

Banker's Algorithm Safety State Evaluation Engine
1. Compute Need Matrix: Need[i][j] = Max[i][j] - Allocation[i][j] Work = Available vector • Finish[i] = false for all processes
↓ Find process i with Finish[i]==false and Need[i] ≤ Work
2. Process i Can Safely Execute to Completion! Work = Work + Allocation[i] • Finish[i] = true • Add Pi to Safe Sequence
↓ Repeat until all finished
If all Finish[i] == true: System is in SAFE STATE (Deadlock Free!)

Deadlock prevention

Ensure at least one of the four necessary conditions can never hold:

ConditionPrevention strategyDrawback
Mutual exclusionMake resources sharable (impossible for printers, etc.)Not practical for most resources
Hold and waitRequest ALL resources before starting, or release all before new requestLow utilisation, possible starvation
No preemptionIf a process cannot get a resource, preempt all its held resourcesOnly works for resources whose state can be saved (CPU, memory)
Circular waitImpose a total ordering on resources; request in order onlyMust know ordering in advance; inconvenient

Deadlock avoidance — safe states

Safe state A state is safe if there exists a sequence ⟨P1,…,Pn⟩ such that for every Pi, the resources Pi still needs can be satisfied by currently available resources plus resources held by all Pj with j < i.

Safe ⇒ no deadlock. Unsafe ≠ deadlock (but deadlock is possible).

Banker’s Algorithm

Data structures n = processes, m = resource types.
Available[m]: currently available instances of each type.
Max[n][m]: maximum demand of each process.
Allocation[n][m]: currently allocated to each process.
Need[n][m] = Max − Allocation
Safety algorithm 1. Let Work = Available, Finish[i] = false for all i.
2. Find a process i such that Finish[i] = false AND Need[i] ≤ Work.
3. If found: Work = Work + Allocation[i], Finish[i] = true. Go to step 2.
4. If no such i exists: if all Finish[i] = true ⇒ SAFE. Otherwise ⇒ UNSAFE.

The exam shortcut

Start by scanning for the process whose Need is smallest — it is most likely to fit into the current Work vector. After each allocation, Work grows, making subsequent processes easier to satisfy.

Check yourself

Retrieval practice

1. Need[i] in Banker’s Algorithm is computed as:

Need = maximum demand minus what the process already has. This is how much more it might request.

2. A safe state means:

Safe = at least one completion order exists. The system avoids deadlock by only granting requests that keep it safe.

3. To prevent the circular-wait condition:

If all processes request resources in a fixed order, no circular chain can form.

4. The Banker’s Algorithm is an example of:

Avoidance = check before granting. Prevention = design constraints. Detection = find after occurrence. Recovery = fix after detection.

5. An unsafe state:

Unsafe ≠ deadlocked. It means no safe sequence exists, so processes MIGHT deadlock depending on future requests.

Recall without looking

State the four prevention strategies and their drawbacks.

Break ME: share resources (impractical). Break H&W: request all upfront (low util). Break NP: preempt (only for saveable state). Break CW: total ordering (inconvenient).

State the Banker's safety algorithm.

Work = Available. Find process i with Need[i] ≤ Work and Finish[i]=false. Set Work += Alloc[i], Finish[i]=true. Repeat. If all finish, safe.

Safe vs unsafe vs deadlocked.

Safe: at least one completion sequence exists. Unsafe: no safe sequence, deadlock possible. Deadlocked: processes actually stuck in circular wait.
