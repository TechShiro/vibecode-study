Virtual memory concept

Virtual memory allows a process to use more memory than physically available. Only needed pages are in RAM; the rest stay on disk. The OS maintains the illusion of a large contiguous address space.

Benefits:

  • Programs larger than physical memory can run.
  • More processes can be in memory simultaneously (higher multiprogramming).
  • Less I/O needed (only load pages when needed).

Demand paging

Demand paging = bring a page into memory only when it is referenced. A lazy swapper (or pager) never swaps in a page unless needed.

Valid-invalid bit Each page table entry has a valid-invalid bit:
Valid (v): page is in memory.
Invalid (i): page is on disk (or not part of the address space).
Accessing an invalid page triggers a page fault.

Page fault handling

  1. Process references a page marked invalid → trap to OS (page fault).
  2. OS checks: is the reference legal? If not, terminate process.
  3. Find a free frame (or use page replacement to free one).
  4. Read the page from disk into the free frame.
  5. Update the page table: set valid bit, record frame number.
  6. Restart the instruction that caused the fault.
Pure demand paging

Start a process with no pages in memory. Every page is brought in by a page fault. After a while, the working set is in memory and faults become rare — locality of reference.

Effective Access Time (EAT)

EAT formula Let p = page fault rate (0 ≤ p ≤ 1), m = memory access time, f = page fault service time.

EAT = (1 − p) × m + p × f
Worked example — EAT

Memory access time = 200 ns. Page fault service time = 8 ms = 8,000,000 ns. Page fault rate = 1/1000 = 0.001.

EAT = (1 − 0.001) × 200 + 0.001 × 8,000,000

= 0.999 × 200 + 0.001 × 8,000,000

= 199.8 + 8,000 = 8,199.8 ns

Even a 0.1% page fault rate slows memory access by 40×!

Copy-on-Write (COW)

When a process forks, both parent and child share the same pages (marked read-only). A page is copied only when one process tries to write to it. Saves memory and avoids unnecessary copying.

Check yourself

Retrieval practice

1. A page fault occurs when:

Invalid bit means the page is on disk. The OS must bring it into a frame before the process can continue.

2. The correct page fault handling order is:

The trap comes first (hardware), then the OS validates, finds a frame, reads from disk, updates the table, and restarts.

3. EAT with p = 0.01, memory time = 100 ns, fault time = 10 ms is:

EAT = (1-p)×m + p×f. A 1% fault rate with 10 ms service time makes average access ~100 μs, 1000× slower than pure RAM.

4. Copy-on-write defers page copying until:

Both processes share the same physical pages after fork. Only when one writes does the OS copy that page.

5. Locality of reference means:

Temporal locality (same page accessed again soon) and spatial locality (nearby pages accessed) make demand paging effective.

Recall without looking

Six steps of page fault handling.

1. Trap to OS. 2. Check legality. 3. Find free frame. 4. Read page from disk. 5. Update page table (valid bit). 6. Restart instruction.

EAT formula.

EAT = (1-p) × memory_access_time + p × page_fault_service_time. Even small p causes huge slowdown because disk is ~105× slower than RAM.

What is copy-on-write?

After fork, parent and child share same pages (read-only). Page is copied only when one writes. Saves memory and fork time.
