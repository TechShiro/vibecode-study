Objectives of memory management

  • Relocation: move processes in memory without breaking references.
  • Protection: prevent one process from accessing another’s memory.
  • Sharing: allow processes to share code/data when appropriate.
  • Logical organisation: manage memory as modules (segments).
  • Physical organisation: manage the physical memory hierarchy efficiently.

Swapping and overlays

Swapping: temporarily move an entire process from main memory to disk (swap out) and bring it back later (swap in). Allows more processes than can fit in RAM.

Overlays: programmer manually divides a program into pieces; only the needed overlay is in memory at a time. Superseded by virtual memory.

Contiguous allocation

Fixed partitions

Memory divided into fixed-size partitions. Each process gets one partition.

  • Internal fragmentation: process smaller than partition ⇒ wasted space inside the partition.
  • Simple but inflexible.

Variable partitions

Partitions created dynamically to fit each process exactly.

  • External fragmentation: free memory exists but is scattered in non-contiguous holes.
  • Compaction: shuffle processes to combine holes (expensive).

Placement algorithms

AlgorithmStrategySpeedFragmentation
First FitAllocate the first hole that is big enoughFastModerate
Best FitAllocate the smallest hole that fitsSlow (search all)Leaves tiny unusable holes
Worst FitAllocate the largest holeSlow (search all)Largest remaining hole, but poor in practice
The exam line

First fit is generally fastest and as good as best fit. Internal fragmentation = wasted space inside a partition. External fragmentation = wasted space between partitions.

Paging

Divide logical memory into pages and physical memory into frames, both of equal size. A page table maps page numbers to frame numbers. No external fragmentation; small internal fragmentation (last page only).

Address translation Logical address = (page number, page offset)
page number p = ⌊address / page_size⌋
page offset d = address mod page_size
Physical address = frame_number × page_size + d
Worked example — paging address translation

Page size = 4 KB = 4096 bytes. Logical address = 13500.

Page number p = ⌊13500 / 4096⌋ = ⌊3.295⌋ = 3

Offset d = 13500 mod 4096 = 13500 − (3 × 4096) = 13500 − 12288 = 1212

If page table says page 3 → frame 6:

Physical address = 6 × 4096 + 1212 = 24576 + 1212 = 25788

Page table structure

  • Single-level: one array indexed by page number. Simple but large for big address spaces.
  • Multi-level: page the page table itself. Reduces memory for sparse address spaces.
  • Inverted page table: one entry per physical frame, not per page. Small table but slow lookup (hash to fix).
  • TLB (Translation Lookaside Buffer): hardware cache of recent page-to-frame mappings. Hit ⇒ no memory access for translation.

Segmentation

Divide logical address space into variable-length segments (code, data, stack, heap). Each segment has a base and limit.

Segment address translation Logical address = (segment number s, offset d)
Check: d < limit[s] (else trap).
Physical address = base[s] + d

Segmentation with paging: each segment is paged. Combines benefits of both — logical structure from segmentation, no external fragmentation from paging. Used in Intel x86.

Check yourself

Retrieval practice

1. Internal fragmentation occurs in:

Internal = space wasted inside the allocated unit. Fixed partitions waste the most; paging wastes only in the last page.

2. Paging eliminates:

Any free frame can be used for any page, so holes between processes are impossible. Small internal fragmentation remains in the last page.

3. Given page size 1 KB and logical address 3500, the page number is:

p = ⌊3500/1024⌋ = 3. d = 3500 − 3×1024 = 3500 − 3072 = 428.

4. First fit allocates:

First fit is fast and performs about as well as best fit in practice.

5. A TLB is:

TLB hit = translate without accessing the page table in memory. Critical for paging performance.

6. Segmentation with paging combines:

Each segment is paged, so we get logical modules AND no external fragmentation. Intel x86 used this approach.

Recall without looking

Internal vs external fragmentation.

Internal: wasted space inside allocated block (fixed partitions, paging last page). External: free space scattered in holes (variable partitions, segmentation). Paging eliminates external; segmentation eliminates internal.

Paging address translation formula.

Page p = ⌊address / page_size⌋. Offset d = address mod page_size. Physical = frame[p] × page_size + d.

Three placement algorithms.

First fit: first hole that fits (fastest). Best fit: smallest sufficient hole (tiny leftovers). Worst fit: largest hole (poor in practice).

Paging vs segmentation — three differences.

Paging: fixed-size, transparent, no external frag. Segmentation: variable-size, visible to programmer, no internal frag. Combined: segmentation with paging.
