System model

A system has a set of resource types R1,…,Rm, each with Wi instances. A process uses a resource by: Request → Use → Release.

The four necessary conditions

Deadlock can occur if and only if all four hold simultaneously:

ConditionMeaning
1. Mutual ExclusionAt least one resource is held in non-sharable mode — only one process can use it at a time.
2. Hold and WaitA process holding at least one resource is waiting to acquire additional resources held by other processes.
3. No PreemptionResources cannot be forcibly taken from a process — they must be released voluntarily.
4. Circular WaitThere exists a set {P0,…,Pn} such that P0 waits for a resource held by P1, P1 waits for P2,…, Pn waits for P0.

Resource-Allocation Graph (RAG)

  • Process node: circle (Pi).
  • Resource node: rectangle (Rj) with dots inside showing instances.
  • Request edge: Pi → Rj (process wants resource).
  • Assignment edge: Rj → Pi (resource is held by process).
Deadlock detection from RAG Single-instance resources: deadlock ⇔ cycle in the RAG.
Multi-instance resources: cycle is necessary but not sufficient. Need the full detection algorithm (Lesson 17).

Check yourself

Retrieval practice

1. The four necessary conditions for deadlock are:

All four must hold simultaneously for deadlock to occur. Breaking any one prevents deadlock.

2. In a RAG with single-instance resources, deadlock exists if and only if:

For single-instance resources, a cycle is both necessary and sufficient. For multi-instance, a cycle is necessary but not sufficient.

3. “Hold and wait” means:

The process refuses to release what it has while waiting for additional resources, potentially blocking others.

4. In a RAG, a request edge goes from:

P → R = request. R → P = assignment. The arrow points in the direction of “wants” or “held by.”

5. Deadlock requires all four conditions to hold:

All four are necessary. Prevention strategies work by ensuring at least one can never hold.

Recall without looking

Name the four necessary conditions for deadlock.

1. Mutual exclusion. 2. Hold and wait. 3. No preemption. 4. Circular wait. All must hold simultaneously.

How do you detect deadlock from a RAG?

Single-instance: cycle = deadlock. Multi-instance: cycle is necessary but not sufficient — run the detection algorithm.
