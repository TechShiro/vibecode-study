Operating system structures

“Structure” means how the code of the OS is organised internally. The story is a progression: each structure fixes a defect of the one before it.

1. Simple structure — MS-DOS

Written to give the most functionality in the least space, with no careful division into modules. Interfaces and levels of functionality are not well separated: application programs can call the BIOS routines directly and write straight to the display and disk.

MS-DOS layer sketch application program → resident system program → MS-DOS device drivers → ROM BIOS device drivers → hardware
… but the arrows can also skip levels, which is exactly the problem.

Why it survived: the Intel 8088 for which it was written had no dual mode and no hardware protection, so the designers had no way to enforce separation. Consequence: a crashing program takes the whole system down.

2. Monolithic structure — traditional UNIX

The entire operating system runs as a single program in kernel mode, in one address space. Everything — file system, scheduler, memory manager, device drivers, networking — is inside the kernel and any part may call any other part directly.

AdvantagesDisadvantages
Very fast — a call between subsystems is an ordinary function call, with no message passing and no mode switchHard to understand, modify and debug — a single huge program
Little overhead in system callsNo isolation — a bug in any driver can crash the entire system
Simple design; direct access to all data structuresAdding a feature means recompiling the whole kernel

3. Layered structure

The OS is broken into N layers, layer 0 being the hardware and layer N−1 the user interface. A layer may use only the services of the layer directly below it.

Layered approach layer N−1 — user interface
…
layer 2 — device drivers
layer 1 — CPU scheduling
layer 0 — hardware
AdvantagesDisadvantages
Simplicity of construction and debugging. Debug layer 0 first; when layer k fails, the error must be in layer k, because k−1 is already provenDeciding the layers is hard — the backing-store driver needs the scheduler, and the scheduler may need the backing store, so the ordering is not obvious
Each layer hides its data structures from the layers above — true modularityPoor performance — a system call must pass through every layer, each adding overhead

4. Microkernel structure — Mach, QNX, MINIX

Strip the kernel down: move everything non-essential out of the kernel into user-space server processes. What remains in the kernel is minimal — typically only process (thread) management, minimal memory management, and inter-process communication. File systems, device drivers, protocol stacks and the rest run as ordinary user processes.

Communication between a client program and a server is indirect, by message passing through the microkernel.

AdvantagesDisadvantages
Easy to extend — a new service is a new user program, no kernel changePerformance overhead of message passing and the extra mode switches
Easy to port to a new hardware architecture — little code is machine dependentTwo mode switches per request instead of one function call
More reliable and more secure — a crashing file-system server does not bring down the kernel; less code runs in kernel modeComplex to get right; some services genuinely need kernel privileges

5. Modular structure — the modern answer (Linux, Solaris)

The best current design uses loadable kernel modules. There is a small core kernel with a set of well-defined interfaces, and additional services — a file system, a device driver, a scheduling class — are linked in dynamically, at boot time or at run time.

It is the sweet spot: like layers, because each module has a defined interface; like microkernels, because modules are separate and loadable; but as fast as monolithic, because modules run in kernel mode and call one another directly rather than by message passing. That sentence answers “why is the modular approach preferred?” on its own.

6. Hybrid structure

Real systems mix approaches for performance and practicality.

SystemWhat it actually is
LinuxMonolithic (all in one address space, for speed) plus loadable modules

macOS / iOSDarwin: the Mach microkernel for IPC and memory, with a BSD monolithic layer above it
AndroidA modified Linux kernel, plus the ART runtime and libraries in user space

Virtual machines

A virtual machine takes the layered approach to its conclusion: it treats hardware and the kernel as though they were all hardware, and gives each process the illusion of its own private processor and its own memory. The host runs a virtual machine manager (hypervisor); each guest runs its own complete OS.

  • Benefit — complete isolation: each VM is protected from every other, so a guest crash affects nobody else.
  • Benefit — development and research: you can test a new OS or a risky change without disturbing normal operation.
  • Cost: hard to implement (the virtual machine must be an exact duplicate of the underlying machine) and slower, since privileged instructions must be trapped and simulated.

The distinction examiners test

Distributed vs network OS: in a distributed system the user does not know, and does not need to know, which machine runs the job — it looks like a single computer (transparency). In a network OS the user knows there are many machines and must explicitly log in or copy files across.

Multiprogramming vs multiprocessing: multiprogramming is one CPU switching among many jobs; multiprocessing is many CPUs genuinely running jobs at the same instant.

System boot

“How does the OS get into memory when there is no OS in memory to load it?” That circularity is the whole point of the boot question.

The boot sequence — write these six steps 1. Power on. The CPU's program counter is set by hardware to a fixed address in ROM / EEPROM.
2. The bootstrap program (firmware, BIOS or UEFI) runs. It is in ROM, so it needs no loading and cannot be modified by a virus easily.
3. It runs POST — the power-on self-test — checking CPU registers, memory and devices.
4. It initialises the hardware, then locates the boot block — the first sector of the boot disk, the Master Boot Record.
5. The boot block holds the boot loader (GRUB, Windows Boot Manager), which is larger and smarter; it finds the kernel on disk and loads it into main memory.
6. The kernel starts executing, initialises its data structures, creates the first process (init or systemd), starts the system daemons, and waits for events.

Two supporting terms:

  • Bootstrapping — the general name for a small simple program pulling in a large complex one, “lifting itself by its own bootstraps.”
  • System generation (SYSGEN) — configuring the OS for the particular machine it will run on: which CPU, how much memory, which devices, which options. The OS is then either recompiled or, more commonly today, configured by a table read at boot time.

Recall without looking

Name the six OS structures in order of development.

Simple (MS-DOS), monolithic (traditional UNIX), layered, microkernel (Mach, QNX), modular with loadable kernel modules (Linux, Solaris), and hybrid (macOS Darwin, Windows). Virtual machines are a further extension of layering.

Give the advantage and the disadvantage of the layered approach.

Advantage: simplicity of construction and debugging, because each layer uses only the proven layer below it. Disadvantages: deciding the layer ordering is genuinely difficult, and every system call must traverse all the layers, which costs performance.

Compare monolithic and microkernel on five points.

Kernel content: everything vs only IPC and minimal process/memory management. Size: large vs small. Communication: direct function calls vs message passing. Speed: monolithic faster. Reliability and extensibility: microkernel better, since a failed server is restartable and new services are just user programs.

Why is the modular approach preferred today?

It has defined interfaces like a layered system, separable loadable parts like a microkernel, but its modules run in kernel mode and call one another directly, so it keeps monolithic speed without message-passing overhead.

List the eight types of operating system.

Batch, multiprogramming, multitasking/time-sharing, multiprocessing, real-time (hard and soft), distributed, clustered, and embedded/network.

Distinguish distributed from network operating systems, and multiprogramming from multiprocessing.

Distributed systems are transparent — the user does not know which machine runs the job; in a network OS the user knows and logs in explicitly. Multiprogramming is one CPU switching among many jobs; multiprocessing is many CPUs executing simultaneously.

Give the six steps of the boot sequence.

Power on and the PC is set to a fixed ROM address; the bootstrap program (BIOS/UEFI) runs; POST tests the hardware; the boot block on the boot disk is located; the boot loader in it loads the kernel into memory; the kernel initialises, creates the first process and waits for events.

What is SYSGEN?

System generation — configuring the operating system for the specific machine it will run on: CPU type, memory size, devices present and options wanted. The result is either a recompiled kernel or, more commonly, a configuration table read at boot.
