Operating System Services, User Interfaces and System Programs

The eight services split into two groups, the three kinds of user interface, the six categories of system program, and the debugging facilities the OS provides.

Exam strategy

A reliable 5-mark question: “List and explain the services provided by an operating system.” The mark is won by splitting them into two groups — services that help the user, and services that ensure efficient system operation — before listing. Most students just list eight things; the split is what looks like an answer rather than a recall. CLI vs GUI is a short-note favourite, and system program vs application program is a one-liner that appears in objective sections.

The services — and the split that earns the mark

An operating system provides an environment for the execution of programs. It offers services in two groups.

Group A — services helpful to the user

ServiceWhat it does
1. User interfaceProvides a way to interact with the system — a command-line interpreter, a graphical interface, or a touch-screen interface
2. Program executionLoads a program into memory, runs it, and ends it — either normally or with an error indication
3. I/O operationsA running program may need I/O on a file or a device. The user cannot control devices directly, so the OS must do it — this is also a protection requirement
4. File system manipulationRead, write, create, delete, search files and directories; list file information; manage permissions
5. CommunicationLets processes exchange information, either on the same computer or across a network — by shared memory or by message passing
6. Error detectionDetects errors in the CPU and memory (power failure, memory error), in I/O devices (parity error, out of paper), and in user programs (divide by zero, illegal instruction, illegal memory access), and takes the appropriate action

Group B — services that ensure efficient operation of the system itself

ServiceWhat it does
7. Resource allocationWhen multiple users or jobs run at once, each needs resources allocated — CPU cycles, main memory, file storage, I/O devices. The OS holds the allocation code, including the CPU scheduler
8. AccountingKeeps track of which user uses how much and what kind of resource — for billing, or for accumulating usage statistics that guide reconfiguration
9. Protection and securityEnsures that all access to system resources is controlled, that concurrent processes do not interfere with each other, and that outsiders cannot get in
The framing sentence to open the answer with

“Operating system services fall into two groups: those helpful to the user — user interface, program execution, I/O, file manipulation, communication and error detection — and those that ensure the efficient operation of the system itself — resource allocation, accounting, and protection and security.”

The user – operating system interface

Three kinds. The syllabus asks for “user interfaces”, so name all three even though the comparison is really between the first two.

1. Command-line interface (CLI) — the shell

Takes typed commands and executes them. On UNIX and Linux the user may choose among several shells — Bourne shell (sh), C shell (csh), Bourne-Again shell (bash), Korn shell (ksh); on Windows, cmd and PowerShell.

The command interpreter has two possible implementations, and knowing which is which is a favourite objective question:

ApproachHow it worksConsequence
Commands built into the interpreterThe interpreter itself contains the code for every command; it jumps to the right section of its own codeThe interpreter is large; adding a command means rewriting the interpreter
Commands implemented as system programs (UNIX)The interpreter only finds and loads a separate program file of that name, then passes it the parametersThe interpreter is small; new commands are added by simply adding a new file, with no change to the interpreter

2. Graphical user interface (GUI)

A desktop metaphor: the mouse moves a pointer over icons representing files, programs and folders; clicking invokes an action; windows, menus and dialogue boxes carry the interaction. First developed at Xerox PARC in the 1970s. Examples: Windows Explorer, macOS Aqua, and on Linux the choice of KDE or GNOME.

3. Touch-screen interface

Mobile devices have no mouse and often no keyboard, so the interface is built on gestures — tap, swipe, pinch — with an on-screen virtual keyboard for text. Android and iOS are the examples.

Note this, it wins a mark

The user interface is not part of the kernel. The shell and the GUI are system programs that run in user mode and reach the kernel only through system calls. That is why one machine can run several different shells and several different desktop environments over the same kernel.

System programs

System programs — also called system utilities — provide a convenient environment for program development and execution. They sit above the system-call layer and below the application programs. Six categories:

CategoryExamples
1. File managementCreate, delete, copy, rename, print, list files and directories — cp, rm, mkdir, ls
2. Status informationDate, time, available memory, disk space, number of users, performance and logging — date, df, top, registry on Windows
3. File modificationText editors to create and modify files; commands to search and transform their contents — vi, nano, grep, sed
4. Programming-language supportCompilers, assemblers, debuggers and interpreters — gcc, python, gdb
5. Program loading and executionAbsolute loaders, relocatable loaders, linkage editors, overlay loaders
6. CommunicationsCreate virtual connections among processes, users and machines — e-mail, remote login, file transfer, web browsing

A seventh group is usually added: background services — daemons or services launched at boot that run for the life of the machine, such as the network daemon, the print spooler and schedulers.

System program vs application program

A system program ships with the operating system and exists to manage or extend the system itself (compiler, shell, file utilities). An application program is written to solve the user's own problem and is independent of the OS (a browser, a game, a spreadsheet). Both run in user mode — the difference is purpose and origin, not privilege.

Operating system debugging

The syllabus lecture plan names this explicitly, and it is a short note worth 3–5 marks.

Debugging is finding and fixing errors, or bugs. The OS helps in three ways:

FacilityWhat it capturesUsed for
Log filesError information written as failures occurRoutine diagnosis after the fact
Core dumpA capture of the memory of a failed user processDebugging application failures
Crash dumpA capture of kernel memory after a kernel crash — a “crash” is a kernel failure, as opposed to a process “core dump”Debugging the OS itself

Beyond failure analysis, the OS supports performance tuning — removing bottlenecks by measuring the system. Two approaches:

  • Trace listings: record system-call and event activity, and analyse it afterwards. Tools: strace, DTrace.
  • Counters and profiling: the OS keeps counters of activity that tools such as top, vmstat and Windows Task Manager display live.

Heisenbug is the term worth dropping: a bug that changes behaviour or disappears when you try to observe it — common in operating systems, because adding instrumentation alters timing, and most OS bugs are timing bugs.

Check yourself

1. Accounting, resource allocation, and protection belong to which group of OS services?

Opening your answer with this two-group split is what separates a full-mark answer from a bare list.

2. In UNIX, adding a new shell command requires:

UNIX implements commands as separate system programs; the interpreter only locates and loads the file. The alternative — commands built into the interpreter — makes the interpreter large and closed.

3. Which is a genuine advantage of a CLI over a GUI?

CLI wins on automation, resource use, expert speed and remote administration. GUI wins on discoverability, learning curve and error tolerance.

4. Compilers, assemblers and debuggers are:

They ship with the OS and exist to manage or extend the system, so they are system programs — but they still run in user mode, above the system-call layer.

5. A capture of kernel memory taken after the kernel itself fails is a:

Core dump = failed user process; crash dump = failed kernel. Keeping those two words apart is the whole of this question.

6. Error detection as an OS service covers:

Power failure and memory errors, parity errors and out-of-paper, divide by zero and illegal memory access — all three levels, with an appropriate action for each.

Recall without looking

List the OS services in their two groups.

Helpful to the user: user interface, program execution, I/O operations, file system manipulation, communication, error detection. Ensuring efficient system operation: resource allocation, accounting, protection and security.

Name the three kinds of user interface.

Command-line interface (the shell — sh, bash, csh, ksh, cmd, PowerShell), graphical user interface (desktop metaphor with icons, windows and a pointer; KDE and GNOME on Linux), and touch-screen interface (gestures plus a virtual keyboard, on Android and iOS).

Give the two ways a command interpreter can be implemented, and the consequence of each.

Commands built into the interpreter: the interpreter is large and must be rewritten to add a command. Commands as separate system programs, the UNIX way: the interpreter is small, and a new command is added by adding a new file.

Compare CLI and GUI on five points.

Learning curve: CLI steep, GUI gentle. Expert speed: CLI faster. Resource use: CLI very low. Automation: CLI excellent through scripts and pipes, GUI poor. Error tolerance: GUI better, through confirmation dialogues.

Name the six categories of system program.

File management, status information, file modification, programming-language support, program loading and execution, and communications — with background services or daemons usually added as a seventh.

Distinguish a system program from an application program.

A system program ships with the OS and exists to manage or extend the system; an application program is written to solve the user's own problem. Both run in user mode — the difference is purpose, not privilege.

Distinguish a core dump from a crash dump, and define a Heisenbug.

A core dump captures the memory of a failed user process; a crash dump captures kernel memory after a kernel failure. A Heisenbug is a bug that changes or vanishes when observed, common in operating systems because instrumentation alters timing and most OS bugs are timing bugs.
