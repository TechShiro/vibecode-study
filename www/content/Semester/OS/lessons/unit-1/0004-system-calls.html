What a system call is

Definition to write A system call is the programmatic way in which a computer program requests a service from the kernel of the operating system. It is the only legal entry point into the kernel, and it provides the interface between a running process and the operating system.

The mechanism is the trap from Lesson 1: the system call is a software interrupt. It switches the mode bit from user (1) to kernel (0), transfers control to a fixed location in the kernel, and switches the bit back on return. Every system call is therefore a mode switch — but note carefully, not a context switch: the same process continues running, only in a different mode.

System call vs API vs library function

Programmers almost never write system calls directly; they call an Application Programming Interface, and the API's library function issues the system call for them.

The three most common APIs are Win32 API for Windows, POSIX API for UNIX, Linux and macOS, and the Java API for the JVM.

Why call the API rather than the system call?

Portability — a program written to the API compiles and runs on any system supporting that API. And simplicity — the API hides the messy detail of the trap. printf() in the C library ultimately invokes the write() system call, but your source code never says so.

How the call is identified

Each system call has a number. The kernel maintains a table indexed by these numbers — the system call table — whose entries point to the routine implementing each call. The system call interface intercepts the call, looks up the number, invokes the routine, and returns the status and any return values. The caller need know nothing about how the call is implemented.

Passing parameters to the operating system

There are exactly three methods. This is a standing 3–5 mark question, so learn all three with their trade-offs.

MethodHowLimitation / advantage
1. RegistersPass the parameters in CPU registersSimplest and fastest, but there may be more parameters than registers — then it fails
2. Block or table in memoryStore the parameters in a block of memory and pass the address of that block in a registerNo limit on the number or length of parameters. Used by Linux and Solaris
3. StackThe program pushes the parameters onto the stack; the OS pops them offAlso imposes no limit; the natural fit for languages that already use a stack for calls

Methods 2 and 3 are preferred exactly because they do not cap the number of parameters.

The standard trace — copying one file to another

“List the sequence of system calls needed to copy the contents of one file to another.” Answer it as a numbered list; the marks come from including the error handling at every step, which most students omit.

Q. Sequence of system calls for cp source.txt dest.txt
  1. Acquire the input file name. Either the OS writes a prompt (write to screen) and reads the name from the keyboard (read), or the name comes on the command line.
  2. Acquire the output file name the same way.
  3. Open the input file — open(). If it does not exist, or access is denied, print a message (write to screen) and abort.
  4. Create the output file — create(). If a file of that name already exists, either abort or ask the user whether to delete the existing file and continue.
  5. Loop: read() from the input file, then write() to the output file. Each iteration must check for read errors (hardware failure, bad block) and write errors (disk full, physical write error), and act accordingly.
  6. Detect end of file on the read and exit the loop.
  7. Close both files — close().
  8. Write a completion message to the console, and terminate normally — exit().

Categories used: file management (open, create, read, write, close), device management (read from keyboard, write to screen), and process control (abort, exit). Say that sentence at the end — it ties the answer back to the six types and reads as understanding.

Numerical — the cost of a system call

Q. A program writes 4 KB of data one byte at a time. A write() system call costs 1 µs of mode-switch and kernel overhead plus 0.01 µs per byte transferred. Compare the total cost of 4096 one-byte calls with one 4096-byte call.

Case A — one byte per call. Number of calls = 4096.

Cost per call = 1 µs overhead + 0.01 µs × 1 byte = 1.01 µs

Total = 4096 × 1.01 = 4136.96 µs ≈ 4.14 ms

Case B — one call for the whole buffer. Number of calls = 1.

Cost = 1 µs overhead + 0.01 µs × 4096 bytes = 1 + 40.96 = 41.96 µs ≈ 0.042 ms

Speed-up = 4136.96 / 41.96 ≈ 98.6×

Reading: in Case A the machine spends 4096 µs on overhead and only 41 µs on real work — 99 % of the time is mode switching. This is precisely why the C library buffers: printf() accumulates output and issues one write(), instead of one per character.

Sanity check: the transfer component (0.01 × 4096 = 40.96 µs) is identical in both cases, as it must be — the same bytes move either way. Only the overhead term changes, from 4096 µs to 1 µs.

Check yourself

1. A system call causes:

Mode switch, not context switch — the same process keeps the CPU, only its privilege level changes. Mixing these two up is the single most common error on this topic.

2. Which parameter-passing method has a hard limit on the number of parameters?

Registers are the fastest but there are only so many of them. Block and stack methods are preferred precisely because they impose no limit.

3. chmod() belongs to which category of system call?

It sets file permissions, which is access control. Some books fold protection into information maintenance and list five categories — say six and note the alternative.

4. printf() is:

The API layer exists for portability and simplicity. Your source calls printf(); the library buffers and eventually issues write().

5. The kernel identifies which service was requested by:

Each system call has a number; the table's entries point at the implementing routines. The system call interface hides all of this from the programmer.

6. In MS-DOS, running a program:

MS-DOS is single-tasking, so there is only ever one program in memory. UNIX forks a child and can run both concurrently — that contrast is the exam point.

Recall without looking

Define a system call and say what mechanism implements it.

A system call is the programmatic way a program requests a service from the kernel, and it is the only legal entry point into the kernel. It is implemented as a trap — a software interrupt — that switches the mode bit to kernel mode, transfers control to a fixed kernel location, and switches back on return. It is a mode switch, not a context switch.

Distinguish system call, API and ordinary function call.

A function call runs entirely in user mode with no mode switch. An API library function also runs in user mode but issues system calls on the programmer's behalf; it is used for portability and simplicity. A system call executes in kernel mode and is the expensive one. printf() is API, write() is a system call.

Give the three methods of passing parameters to the OS.

In registers — simplest and fastest, but limited by the number of registers. In a block or table in memory, passing its address in a register — no limit, used by Linux and Solaris. On the stack, pushed by the program and popped by the OS — also no limit. The latter two are preferred.

Name the six categories of system call with two examples each.

Process control (fork, exit, wait, exec), file management (open, read, write, close), device management (ioctl, read, write), information maintenance (getpid, time, sleep), communication (pipe, socket, shm_open, mmap), and protection (chmod, umask, chown).

Give the sequence of system calls to copy one file to another.

Acquire input and output file names; open the input file, aborting with a message on failure; create the output file, aborting or asking to overwrite if it exists; loop reading from input and writing to output, checking read and write errors each time; detect end of file; close both files; print a completion message and exit. It uses file management, device management and process control calls.

Why does the C library buffer output rather than issuing one system call per character?

Because the per-call overhead dwarfs the per-byte cost. Writing 4 KB one byte at a time with 1 µs overhead per call costs about 4137 µs, of which 4096 µs is pure overhead; one 4096-byte call costs about 42 µs — roughly 99 times faster.
