What an operating system is

There is no universally accepted definition, so the exam accepts either of two — and the safest answer gives both:

The two definitions to write 1. As a resource allocator: an operating system is a program that manages the computer's hardware resources — CPU, memory, I/O devices, files — and allocates them fairly and efficiently among competing programs and users.

2. As a control program / extended machine: an operating system is a program that acts as an interface between the user and the hardware, controls the execution of user programs and prevents errors and improper use of the computer.

One-line version: “The operating system is the one program running at all times on the computer — the kernel. Everything else is either a system program or an application program.”

The four-layer view — draw this

Every question that begins “What is an operating system” should carry this diagram. A computer system has four components:

Structure of a computer system

The OS sits in the middle. Hardware provides the basic computing resources; application programs define how those resources are used to solve a user's problem; the OS controls and coordinates the use of hardware among the applications. That sentence is a mark on its own.

Goals of an operating system

GoalMeaningWhose interest
Convenience (primary)Make the computer easy to use — hide the ugly hardware detail behind clean abstractions such as files, processes and virtual memoryThe user
Efficiency (secondary)Use the hardware — especially the CPU — with maximum utilisation and minimum idle timeThe system owner
Ability to evolvePermit new functions, devices and services to be added without disturbing the existing serviceThe designer
The tension worth naming

Convenience and efficiency pull against each other. A mainframe OS sacrifices convenience for efficiency, because the hardware was the costly thing; a personal-computer OS sacrifices efficiency for convenience, because the user's time is the costly thing. Naming this trade-off in a 10-mark answer reads as understanding rather than memorisation.

Operating system operations

Three ideas here, and all three get asked.

1. The OS is interrupt-driven

A modern OS does nothing until something asks it to. It sits idle and is woken by an event, and there are exactly two kinds of event:

EventSourceAlso calledExamples
InterruptHardware — arrives asynchronously on the interrupt lineHardware interruptDisk finished a read, keystroke arrived, timer expired
Trap (or exception)Software — generated synchronously by the executing instructionSoftware interruptDivide by zero, invalid memory access, a system call

On any event the hardware transfers control to a fixed location, which holds the address of the interrupt service routine; the table of these addresses is the interrupt vector. The state of the interrupted process is saved first and restored afterwards.

2. Dual-mode operation — the exam favourite

The OS must protect itself, and each user program, from every other user program. It cannot do that if a user program may execute any instruction it likes. So the hardware provides two modes of execution, distinguished by one bit — the mode bit.

Dual-mode operation mode bit = 0 → kernel mode (also supervisor, system or privileged mode) — every instruction allowed
mode bit = 1 → user mode — privileged instructions are forbidden

A user program that attempts a privileged instruction causes a trap; the OS then kills or signals the offender.

Privileged instructions — executable only in kernel mode — include: switching to kernel mode, all I/O instructions, timer management, interrupt management, clearing memory, modifying memory-management registers, and the halt instruction.

The sequence for a system call is worth writing out, because it is a standard 4-mark answer:

  1. The user program, in user mode, executes a system call.
  2. The system call is a trap — the hardware sets mode bit = 0 and jumps into the kernel.
  3. The kernel validates the parameters and performs the service in kernel mode.
  4. On return, the kernel sets mode bit = 1 and returns control to the user program.

3. The timer

Dual mode stops a program corrupting the OS, but not a program that simply refuses to give the CPU back — an infinite loop would hang the machine. The fix is a timer: a counter decremented by the hardware clock that raises an interrupt when it reaches zero. The OS sets the timer before handing the CPU to a user process; when it fires, control returns to the OS. Loading the timer is itself a privileged instruction, so a process cannot disable its own preemption.

The one-line answer

Dual-mode operation protects the OS from user programs; the timer protects the OS from user programs that never stop. Together they are the entire hardware basis of protection.

Multiprogramming and multitasking

These two are constantly confused and constantly examined. The difference is what triggers the switch.

 MultiprogrammingMultitasking (time sharing)
IdeaKeep several jobs in memory so the CPU always has something to runSwitch the CPU between jobs so rapidly that each user can interact with the machine
Switch happens whenThe running job waits for I/OA fixed time quantum expires, or on I/O
NatureNot preempted by timePreemptive — needs a timer
GoalMaximise CPU utilisation and throughputMinimise response time
InteractionNone — jobs run to completionInteractive — the user types and sees a response
NeedsJob scheduling and memory managementAll of the above plus CPU scheduling, swapping and virtual memory

Degree of multiprogramming = the number of processes held in main memory at one time. Raising it raises CPU utilisation — up to the point where memory is over-committed and the system begins thrashing.

The guiding rule is the principle of least privilege: every user and every program gets exactly the privileges it needs to do its job, and no more.

Open-source operating systems

An open-source OS is distributed with its source code, which anyone may read, modify and redistribute — Linux, FreeBSD, Android's AOSP. Closed-source systems ship only the binary — Windows, macOS.

Numerical — CPU utilisation under multiprogramming

Q. A process spends a fraction p of its time waiting for I/O. With n processes in memory, what is the CPU utilisation? Compute it for p = 0.8 with n = 1, 2, 4 and 10.

Model. Treat the n processes as independent. The CPU is idle only when all n are simultaneously waiting for I/O, which happens with probability pn. Therefore

CPU utilisation = 1 − pn

npn = 0.8nUtilisation = 1 − 0.8n
10.80020.0 %
20.64036.0 %
40.409659.0 %
100.107489.3 %

Reading: one process leaves the CPU idle 80 % of the time; ten processes cut idleness to about 11 %. That is the entire argument for multiprogramming — and the returns diminish sharply, since going from 1 to 4 buys 39 points while going from 4 to 10 buys only 30 more.

Sanity check: utilisation must lie in [0, 1] and must increase with n. Both hold. If p = 0 — no I/O at all — utilisation is 1 for every n, as it should be.

Check yourself

1. The one program running at all times on the computer is called:

Everything else is either a system program, which ships with the OS but is not always running, or an application program. This is the standard working definition.

2. A trap differs from an interrupt in that a trap is:

A trap is a software interrupt: divide by zero, invalid access, or a deliberate system call. An interrupt comes from a device and can arrive at any moment.

3. Which of these is NOT a privileged instruction?

Reading the clock is harmless and is allowed in user mode. Setting it is privileged, because otherwise a process could disable its own preemption.

4. Multiprogramming switches the CPU to another job when:

Time-quantum switching is time sharing, and it requires a timer. Multiprogramming switches on I/O waits, which is why it needs no preemption hardware.

5. Protection differs from security in that protection deals with:

Protection asks “is this access authorised?” and uses the access matrix and dual mode. Security asks “is this user genuine, and is the system defended from outside?”

6. With a per-process I/O wait fraction of 0.5, CPU utilisation with 3 processes in memory is:

1 − pⁿ = 1 − 0.5³ = 1 − 0.125 = 0.875. The CPU is idle only when all three happen to be waiting at once.

Recall without looking

Give both definitions of an operating system.

As a resource allocator: a program that manages the computer's hardware resources and allocates them fairly and efficiently among competing programs and users. As a control program: a program that acts as an interface between the user and the hardware, controls the execution of user programs and prevents errors and improper use. The kernel is the one program running at all times.

Draw the four-layer structure of a computer system.

Users on top, then application programs, then the operating system, then hardware at the bottom. Hardware provides the resources, applications define how they are used, and the OS coordinates the two.

List the eight functions of an operating system.

Process management, memory management, file management, I/O device management, secondary storage management, protection and security, networking, and command interpretation.

Name the three goals of an operating system.

Convenience (primary), efficiency (secondary) and the ability to evolve. Convenience and efficiency pull against each other — mainframe systems favoured efficiency, personal systems favour convenience.

Explain dual-mode operation and name four privileged instructions.

A hardware mode bit distinguishes kernel mode (0, everything allowed) from user mode (1, privileged instructions trap). Privileged instructions include all I/O instructions, setting the timer, interrupt management, switching to kernel mode, clearing memory, changing memory-management registers, and halt.

Why is a timer necessary, and what makes it safe?

Dual mode stops a user program corrupting the OS but not one that loops forever and never returns the CPU. A timer counts down and interrupts when it reaches zero, returning control to the OS. Loading the timer is itself a privileged instruction, so a user process cannot disable its own preemption.

Distinguish multiprogramming from multitasking.

Multiprogramming keeps several jobs in memory and switches when the running job waits for I/O; its goal is CPU utilisation. Multitasking, or time sharing, switches on a time quantum using a timer, is preemptive, is interactive, and its goal is response time.

Give the CPU utilisation formula under multiprogramming.

With n processes each spending a fraction p of its time waiting for I/O, CPU utilisation = 1 − pⁿ. With p = 0.8 this gives 20 % at n = 1, 59 % at n = 4 and 89 % at n = 10.
