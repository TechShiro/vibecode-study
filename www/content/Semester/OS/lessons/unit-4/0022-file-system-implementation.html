File System Implementation and Allocation Methods

On-disk structures (boot block, super block, directory implementation), three allocation methods (contiguous, linked, indexed), and free-space management (bit vector, linked list).

Exam strategy

“Compare contiguous, linked, and indexed allocation” is a guaranteed 10-marker. Draw diagrams for each. Free-space management with bit vectors is a common short-note.

On-disk structures

  • Boot control block: info to boot OS from that partition (boot sector / boot block).
  • Volume control block: partition details — number of blocks, block size, free-block count (superblock in UNIX).
  • Directory structure: file names, inode numbers (UNIX) or full attributes (FAT).
  • FCB (File Control Block): per-file metadata — permissions, timestamps, data block pointers (= inode in UNIX).

Allocation methods

Contiguous allocation

Each file occupies contiguous blocks. Directory stores (start block, length).

Pro: fast sequential and direct access. Con: external fragmentation, file cannot grow easily.

Linked allocation

Each block has a pointer to the next. Directory stores (first block, last block).

Pro: no external fragmentation, file can grow. Con: no direct access (must traverse), pointer space overhead, reliability (lost pointer = lost file).

FAT (File Allocation Table): linked allocation where pointers are stored in a separate table — improves random access.

Indexed allocation

An index block contains all pointers to the file’s data blocks.

Pro: supports direct access, no external fragmentation. Con: index block overhead, may need multi-level index for large files.

UNIX inode: 12 direct + 1 single-indirect + 1 double-indirect + 1 triple-indirect pointers.

Free-space management

  • Bit vector (bitmap): one bit per block (1=free, 0=allocated). Fast to find free blocks. Space: 1 bit/block.
  • Linked list: link all free blocks. Space-efficient but slow to find contiguous free blocks.
  • Grouping: first free block stores n free-block addresses. Last points to next group.
  • Counting: store (start, count) for each contiguous run of free blocks.

Recall without looking

Three allocation methods — one line each.

Contiguous: consecutive blocks, fast but fragments. Linked: pointer chain, no fragmentation but no direct access. Indexed: index block with all pointers, best of both.

UNIX inode structure.

12 direct + 1 single-indirect + 1 double-indirect + 1 triple-indirect pointers. Handles small to very large files.
