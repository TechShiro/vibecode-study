Classic Problems of Synchronisation

The bounded buffer, readers–writers in both variants, dining philosophers with the deadlock and its four fixes, and the sleeping barber — every solution written in full with the semaphores named and initialised.

Exam strategy

These three problems are the highest-value theory in Unit II — one of them appears in every paper, usually for 10 marks. The answer format is fixed and you should follow it exactly: (1) state the problem, (2) list the shared variables with their initial values, (3) write the producer/consumer or reader/writer code, (4) explain why it works, (5) name the remaining flaw. For dining philosophers, the marks are in the deadlock scenario and its four remedies, not in the code. Always state the initial value of every semaphore — that line alone is often worth a mark.

1. The bounded-buffer (producer–consumer) problem

The problem. A pool of n buffers is shared by a producer process and a consumer process. The producer must not add to a full buffer; the consumer must not remove from an empty one; and no two processes may manipulate the buffer at the same instant.

Shared data — three semaphores, and their initial values semaphore mutex = 1;   — binary; provides mutual exclusion on the buffer
semaphore full = 0;    — counting; counts filled slots
semaphore empty = n;  — counting; counts free slots

Initially there are n free slots and no filled ones, which is exactly what those two values say.
ProducerConsumer
do {
  /* produce an item in next_p */
  wait(empty);  /* claim a free slot */
  wait(mutex);  /* enter CS */
     /* add next_p to the buffer */
  signal(mutex); /* leave CS */
  signal(full);  /* one more filled */
} while (true); 		do {
  wait(full);   /* claim a filled slot */
  wait(mutex);  /* enter CS */
     /* remove an item into next_c */
  signal(mutex); /* leave CS */
  signal(empty); /* one more free */
     /* consume the item */
} while (true);
The symmetry to point out — it reads as understanding

The producer waits on empty and signals full; the consumer waits on full and signals empty. Each consumes one kind of slot and produces the other. Note also that empty and full always sum to n when nobody is inside the critical section — a useful check.

The ordering trap — this is the question examiners actually ask

“What happens if the producer executes wait(mutex) before wait(empty)?”

Answer: deadlock. Suppose the buffer is full. The producer acquires mutex, then blocks on wait(empty) — while still holding the mutex. The consumer then blocks on wait(mutex), so it can never remove an item, so empty is never signalled, so the producer waits for ever. Rule: always acquire the counting semaphore before the mutex, and release in the reverse order.

2. The readers–writers problem

The problem. A data set is shared among several concurrent processes. Readers only read it; writers both read and write. The rule: any number of readers may read simultaneously, but a writer must have exclusive access — no other writer and no reader.

SituationAllowed?
Reader – ReaderYes — reading does not change the data
Reader – WriterNo
Writer – WriterNo
VariantRuleWho starves
First readers–writers problem (readers' preference)No reader is kept waiting unless a writer has already obtained permission to use the objectWriters may starve — a continuous stream of readers keeps the writer out for ever
Second readers–writers problem (writers' preference)Once a writer is ready, it performs its write as soon as possible — new readers must wait behind itReaders may starve

Neither variant is starvation-free. Say that explicitly; it is the concluding sentence the answer wants. A fair solution requires a third, queue-ordering semaphore.

First readers–writers solution — shared data semaphore rw_mutex = 1;  — mutual exclusion for writers, and for the first and last reader
semaphore mutex = 1;    — protects the read_count variable itself
int read_count = 0;   — how many readers are currently reading
WriterReader
do {
  wait(rw_mutex);
     /* writing is performed */
  signal(rw_mutex);
} while (true); 		do {
  wait(mutex);
  read_count++;
  if (read_count == 1) wait(rw_mutex);
  signal(mutex);
     /* reading is performed */
  wait(mutex);
  read_count--;
  if (read_count == 0) signal(rw_mutex);
  signal(mutex);
} while (true);
The two lines that carry the whole solution

if (read_count == 1) wait(rw_mutex); — only the first reader locks the writers out. Readers 2, 3, 4 … walk straight in, which is exactly what “many readers at once” means.

if (read_count == 0) signal(rw_mutex); — only the last reader to leave lets the writers back in.

The second semaphore, mutex, exists purely because read_count++ is itself a shared-variable update, and would otherwise be a race condition — exactly the one traced in Lesson 11.

Where it appears in practice: reader–writer locks in real kernels, and database systems, where a shared lock is granted for reading and an exclusive lock for writing. They pay off when there are many more readers than writers and when readers hold the lock for a long time.

3. The dining-philosophers problem

The problem. Five philosophers sit around a circular table. In the centre is a bowl of rice; between each pair of philosophers is a single chopstick — five chopsticks for five philosophers. A philosopher alternately thinks and eats, and to eat she must pick up both the chopstick on her left and the one on her right, one at a time, and may take only a chopstick that is not already held.

It is the standard abstraction of allocating several resources among several processes without deadlock and without starvation — open your answer with that sentence.

The naive solution — one semaphore per chopstick semaphore chopstick[5];  — all initialised to 1

/* philosopher i */
do {
  wait(chopstick[i]);        /* left */
  wait(chopstick[(i+1) % 5]); /* right */
     /* eat */
  signal(chopstick[i]);
  signal(chopstick[(i+1) % 5]);
     /* think */
} while (true);
Why it deadlocks — this is the marked part of the answer

Suppose all five philosophers become hungry at the same instant and each picks up her left chopstick. All five chopsticks are now held. Every philosopher then waits for her right chopstick, which is her neighbour's left one. No philosopher can proceed and none will release. The system is deadlocked, and all five starve.

All four Coffman conditions hold: mutual exclusion (a chopstick is held by one philosopher), hold and wait (each holds one and waits for another), no preemption (a chopstick cannot be snatched), and circular wait (P0 waits for P1's, … P4 waits for P0's).

The four remedies — learn all four

#RemedyHow it breaks the deadlockCost
1Allow at most four philosophers to sit at the table simultaneouslyWith 4 philosophers and 5 chopsticks, at least one philosopher can always get both — breaks hold-and-wait / circular waitReduced concurrency. Implemented with a counting semaphore initialised to 4
2Pick up both chopsticks only if both are available, in a critical sectionNo philosopher can ever hold exactly one — breaks hold and waitNeeds an extra mutex around the pick-up; slightly less parallel
3Asymmetric solution: an odd-numbered philosopher picks up her left chopstick first, an even-numbered one her right firstBreaks the circular wait — two neighbours contend for the same chopstick first, so one of them always loses and releasesNone — the elegant answer, and the one to give if only one is asked for
4Monitor solution with three states — thinking, hungry, eating — and a condition variable per philosopherA philosopher may only move to eating if neither neighbour is eating; otherwise she waits on her condition variableDeadlock-free, but still not starvation-free — see Lesson 14
The sentence to close with

Any satisfactory solution must guard against deadlock and starvation — a deadlock-free solution does not automatically eliminate the possibility of starvation. Remedies 1 to 4 all remove deadlock; only careful additional ordering removes starvation.

4. The sleeping-barber problem

Worth knowing because it is the fourth classic, and it appears when a paper wants something less predictable.

The problem. A barber shop has one barber, one barber chair and n chairs for waiting customers. If there is no customer, the barber sleeps. When a customer arrives: if the barber is asleep, the customer wakes him; if the barber is busy and a waiting chair is free, the customer sits and waits; if all chairs are full, the customer leaves.

Shared data semaphore customers = 0;  — counts waiting customers; the barber waits on it
semaphore barbers = 0;    — counts free barbers; the customer waits on it
semaphore mutex = 1;      — protects the waiting counter
int waiting = 0;         — number of customers currently seated, waiting
BarberCustomer
do {
  wait(customers); /* sleep if none */
  wait(mutex);
  waiting--;
  signal(barbers); /* I am ready */
  signal(mutex);
     /* cut hair */
} while (true); 		wait(mutex);
if (waiting < n) {
  waiting++;
  signal(customers); /* wake barber */
  signal(mutex);
  wait(barbers);   /* wait my turn */
    /* get haircut */
} else {
  signal(mutex);     /* shop full — leave */
}

Check yourself

1. In the bounded-buffer solution, the semaphore empty is initialised to:

All n slots start free and none is filled, so empty = n and full = 0. When nobody is inside the critical section, empty + full = n always.

2. If the producer executes wait(mutex) before wait(empty), the result is:

The producer blocks on empty while still holding the mutex, so the consumer can never enter to free a slot. Acquire the counting semaphore first, always.

3. In the readers–writers solution, wait(rw_mutex) is executed by a reader:

If every reader locked, readers could not read concurrently, which is the whole point. Only the first locks out writers, and only the last lets them back in.

4. In the first readers–writers problem, who can starve?

The second variant reverses it: writers get preference, so readers may starve. Neither classic variant is starvation-free, and saying so is the concluding mark.

5. The dining-philosophers deadlock occurs when:

All five chopsticks are then held and every philosopher waits on her neighbour's — a circular wait, with all four Coffman conditions satisfied.

6. The asymmetric solution to dining philosophers has:

It breaks the circular wait: two neighbours now contend for the same chopstick first, so one loses and releases. It costs no concurrency, unlike the four-at-a-table rule.

7. A deadlock-free solution to dining philosophers:

Deadlock and starvation are separate requirements. Even the monitor solution, which is deadlock-free, can starve a philosopher whose neighbours alternate.

Recall without looking

Give the bounded-buffer solution with initial values.

mutex = 1, full = 0, empty = n. The producer does wait(empty), wait(mutex), add, signal(mutex), signal(full). The consumer does wait(full), wait(mutex), remove, signal(mutex), signal(empty). Each waits on one counting semaphore and signals the other.

What happens if the mutex is acquired before the counting semaphore?

Deadlock. A producer facing a full buffer blocks on wait(empty) while still holding the mutex, so the consumer can never enter to free a slot and signal empty. Always acquire the counting semaphore first and release in reverse order.

State the readers–writers rule and its two variants.

Many readers may read simultaneously, but a writer needs exclusive access. Reader–reader is allowed; reader–writer and writer–writer are not. The first variant gives readers preference and may starve writers; the second gives writers preference and may starve readers. Neither is starvation-free.

Write the reader's code and explain the two conditional lines.

wait(mutex); read_count++; if (read_count == 1) wait(rw_mutex); signal(mutex); read; wait(mutex); read_count--; if (read_count == 0) signal(rw_mutex); signal(mutex). Only the first reader locks writers out and only the last unlocks, which is what permits concurrent reading. The inner mutex protects read_count, which is itself shared.

State the dining-philosophers problem and why the naive solution deadlocks.

Five philosophers, five chopsticks, one between each pair; a philosopher needs both neighbouring chopsticks to eat and picks them up one at a time. It abstracts allocating several resources among several processes. If all five pick up their left chopstick at once, all five are held and each waits on her neighbour's — mutual exclusion, hold and wait, no preemption and circular wait all hold.

Give the four remedies for dining philosophers.

Allow at most four at the table; pick up both chopsticks only when both are available, inside a critical section; the asymmetric rule where odd philosophers take the left first and even ones the right first; and a monitor solution with thinking, hungry and eating states plus one condition variable per philosopher. All remove deadlock; none automatically removes starvation.

Describe the sleeping-barber problem and its semaphores.

One barber, one barber chair, n waiting chairs. The barber sleeps when no customer waits; an arriving customer wakes him, sits if a chair is free, or leaves if all are full. Semaphores: customers = 0, which the barber waits on; barbers = 0, which the customer waits on; mutex = 1 protecting the waiting counter.
