1. Multilevel queue scheduling

The idea: processes are easily classified into different groups with different response-time requirements, so give each group its own queue with its own scheduling algorithm.

A typical five-level arrangement, highest priority first 1. System processes — scheduled by priority or FCFS
2. Interactive processes (foreground) — Round Robin
3. Interactive editing processes — Round Robin
4. Batch processes (background) — FCFS
5. Student processes — FCFS

A process is permanently assigned to one queue, based on some property fixed at entry — memory size, process priority or process type. It never moves between queues. That inflexibility is the algorithm's defining property, and it is what the exam tests.

2. Multilevel feedback queue scheduling

The one distinction that carries the mark

In a multilevel queue, a process is permanently assigned to one queue. In a multilevel feedback queue, a process can move between queues. That movement is the “feedback”.

The idea: separate processes by the characteristics of their CPU bursts, which are not known in advance and can be learnt by observation.

  • A process that uses too much CPU time is demoted to a lower-priority queue. This automatically pushes I/O-bound and interactive processes — which give up the CPU quickly — into the high-priority queues, exactly where they belong.
  • A process that waits too long in a low-priority queue is promoted to a higher one. This is ageing, and it is what prevents starvation.
The five parameters that define a multilevel feedback queue 1. The number of queues.
2. The scheduling algorithm for each queue.
3. The method used to determine when to upgrade a process to a higher-priority queue.
4. The method used to determine when to demote a process to a lower-priority queue.
5. The method used to determine which queue a process enters when it needs service.

The multilevel feedback queue is the most general CPU-scheduling algorithm — it can be configured to behave like any of the others — and correspondingly the most complex, since those five parameters must all be tuned.

3. Multiple-processor scheduling

With more than one CPU, load sharing becomes possible — and scheduling becomes correspondingly more complex. The discussion below assumes homogeneous processors: identical in functionality, so any process can run on any of them.

The two approaches

 Asymmetric multiprocessing (AMP)Symmetric multiprocessing (SMP)
StructureOne processor — the master server — handles all scheduling decisions, I/O processing and other system activity. The others execute only user codeEach processor is self-scheduling. Each examines the ready queue and selects a process to run
Data sharingOnly one processor accesses the system data structures, so no sharing problemAll processors share the queues, so the OS must be carefully programmed against races
QueuesOne, owned by the masterEither one common ready queue, or a private queue per processor
BottleneckYes — the master is a single point of contention and of failureNo single bottleneck
ComplexitySimpleComplex
Used byOlder and simpler systemsVirtually all modern systems — Windows, Linux, macOS

Processor affinity

When a process runs on a processor, that processor's cache fills with the process's data. If the process migrates to another processor, the first cache must be invalidated and the second re-populated — expensive. So systems try to keep a process running on the same processor: this is processor affinity.

KindMeaning
Soft affinityThe OS attempts to keep a process on the same processor, but makes no guarantee — migration is still possible
Hard affinityThe process specifies a subset of processors on which it may run, and the OS honours it absolutely. Linux provides both, through the sched_setaffinity() system call

NUMA and affinity interact: in a non-uniform memory access architecture, a CPU has faster access to some parts of main memory than to others. The scheduler and the memory-placement algorithm must cooperate — a process assigned to a CPU should have its memory allocated near that CPU.

Load balancing

Load balancing keeps the workload evenly distributed across all processors. It is necessary only where each processor has its own private ready queue — with a single common queue, a processor that becomes idle simply takes the next process, so balancing is automatic.

ApproachWho actsHow
Push migrationA specific task periodically checks the load on each processorIf it finds an imbalance, it pushes processes from an overloaded processor to an idle or less-busy one
Pull migrationAn idle processor acts for itselfIt pulls a waiting task from a busy processor
The tension to name

Load balancing and processor affinity work against each other. Balancing wants to migrate processes; affinity wants to keep them put. Every real scheduler is a compromise between the two — saying so is worth a mark.

Multicore processors

Placing multiple cores on one physical chip. Faster and lower-power than separate chips, but scheduling must account for a phenomenon called the memory stall: when a core accesses memory, it may spend up to half its time waiting for the data, because memory is far slower than the processor.

The remedy is multithreaded multicore design — two or more hardware threads per core. When one thread stalls on memory, the core switches to the other. Intel calls this hyper-threading; the general term is chip multithreading (CMT).

LevelWho schedulesWhat
Level 1The operating systemWhich software thread runs on each hardware thread (logical processor) — using any algorithm from Lesson 9
Level 2The hardware / coreWhich hardware thread actually executes on the physical core — typically a round-robin or a dynamic urgency-based policy

Two hardware multithreading approaches: coarse-grained, where a thread runs until a long-latency event such as a memory stall and the switch costs a full pipeline flush; and fine-grained (interleaved), where switching happens at a much finer granularity, at instruction-cycle boundaries, with hardware designed to make the switch nearly free.

Real-time scheduling — the two algorithms to name

AlgorithmRulePriority is
Rate-monotonic (RMS)Assign each periodic task a priority inversely proportional to its period — the shorter the period, the higher the priorityStatic — fixed once
Earliest deadline first (EDF)Assign priority according to the deadline — the earlier the deadline, the higher the priorityDynamic — recomputed as deadlines approach

Two latencies must also be minimised in a real-time system: interrupt latency, the time from an interrupt arriving to the start of its service routine; and dispatch latency, the time to stop one process and start another.

Check yourself

1. The essential difference between a multilevel queue and a multilevel feedback queue is that in the latter:

That movement is the “feedback”. Demotion punishes CPU hogs; promotion is ageing, which prevents starvation.

2. In a multilevel feedback queue, a process that uses its entire time quantum is:

Using the whole quantum marks it as CPU-bound. I/O-bound and interactive processes release the CPU early and so stay in the fast queues, which is exactly the intent.

3. How many parameters define a multilevel feedback queue scheduler?

Number of queues; algorithm for each; when to upgrade; when to demote; and which queue a process enters. It is the most general algorithm, and the most complex to tune.

4. In asymmetric multiprocessing:

Its advantage is simplicity — only one processor touches the system data structures, so there are no races. Its cost is that the master is a bottleneck.

5. Processor affinity exists because:

Soft affinity attempts to keep a process put but allows migration; hard affinity lets a process name the processors it may run on. Affinity pulls against load balancing.

6. Load balancing is generally unnecessary when:

With a common queue, an idle processor just takes the next process, so balance is automatic. Private queues need push migration, pull migration, or both.

7. In rate-monotonic scheduling, priority is:

The dynamic, deadline-driven alternative is earliest-deadline-first (EDF). RMS is static; EDF recomputes priorities as deadlines approach.

Recall without looking

Describe multilevel queue scheduling and its two inter-queue methods.

Processes are classified into groups, each with its own queue and its own algorithm — for instance system, interactive, editing, batch and student queues. A process is permanently assigned to one queue and never moves. Between queues, either fixed-priority preemptive scheduling is used, which risks starving the lower queues, or each queue is given a time slice, such as 80 % foreground and 20 % background.

State the difference between multilevel queue and multilevel feedback queue, and how each direction of movement helps.

In a multilevel queue a process never changes queue; in a feedback queue it can. A process that uses too much CPU is demoted, which automatically separates CPU-bound from interactive work. A process that waits too long is promoted, which is ageing and prevents starvation.

Name the five parameters of a multilevel feedback queue.

The number of queues; the scheduling algorithm for each queue; the method for deciding when to upgrade a process; the method for deciding when to demote it; and the method for deciding which queue a process enters when it needs service.

Compare asymmetric and symmetric multiprocessing.

Asymmetric: one master processor makes all scheduling decisions and handles I/O and system activity while the others run user code — simple, no data-sharing races, but the master is a bottleneck. Symmetric: every processor is self-scheduling from a common or private ready queue — no bottleneck, but the OS must be written carefully against races. Almost all modern systems use SMP.

Define processor affinity, its two kinds, and the tension it creates.

Affinity is keeping a process on the same processor so its cache stays warm. Soft affinity attempts this without guarantee; hard affinity lets a process specify the processors it may use. It works against load balancing, which wants to migrate processes to even out the load — every real scheduler compromises between the two.

Distinguish push and pull migration.

Push migration: a periodic task checks the load and moves processes from an overloaded processor to a less busy one. Pull migration: an idle processor pulls a waiting task from a busy one. Both are needed only where each processor has a private ready queue.

Explain the memory stall and how multithreaded multicore design answers it.

A core accessing memory can spend up to half its time waiting, because memory is far slower than the processor. Giving each core two or more hardware threads lets the core switch to the other thread while one stalls. Intel calls this hyper-threading; the general term is chip multithreading. Scheduling then has two levels: the OS chooses which software thread runs on each hardware thread, and the hardware chooses which hardware thread executes on the core.

Name the two real-time scheduling algorithms and the two latencies.

Rate-monotonic scheduling assigns static priorities inversely proportional to task period. Earliest-deadline-first assigns dynamic priorities by nearest deadline. The two latencies to minimise are interrupt latency, from interrupt arrival to the start of its service routine, and dispatch latency, the time to stop one process and start another.
