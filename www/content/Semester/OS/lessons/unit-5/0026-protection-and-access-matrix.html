Protection and the Access Matrix

Goals and principles of OS protection, domains of protection, the Access Matrix model, implementing access matrices (ACLs vs Capability Lists), and revocation of access rights.

Exam strategy

“Explain the Access Matrix model and compare Access Control Lists (ACL) with Capability Lists (C-Lists)” is a guaranteed 10-mark question. Provide an explicit tabular matrix diagram and contrast revocation difficulty in both implementations.

What is Protection?

Protection refers to a mechanism for controlling the access of programs, processes, or users to the resources defined by a computer system. While security measures defend the system from external adversaries, protection ensures internal processes do not improperly manipulate internal OS objects.

The Principle of Least Privilege

Programs, users, and even systems should be operated using the minimum set of privileges necessary to complete their required job. This limits the damage (“blast radius”) caused by buggy code, malicious intrusions, or compromised credentials.

Domain of Protection

A computer system contains objects (hardware devices like disks and printers, software objects like files, semaphores, and memory segments). An access right is the permission to perform a specific operation on an object (e.g., read, write, execute).

Definition of a Domain A Domain is a collection of access rights, where each right is an ordered pair:
$$\langle \text{Object-ID}, \text{Rights-Set} \rangle$$ A process executes within the context of a protection domain.

Domain Association:

  • Static: The process stays in a fixed domain for its entire lifetime (simplistic, but violates least privilege).
  • Dynamic (Domain Switching): A process can transition from one domain to another when invoking specialized procedures (e.g., the Unix setuid bit temporarily elevates a normal user process to the root domain while running passwd).

The Access Matrix Model

The Access Matrix is a general conceptual model for representing protection policies:

  • Rows: Represent Domains ($D_1, D_2, \dots, D_n$).
  • Columns: Represent Objects ($F_1, F_2, \dots, \text{Printer}, D_j$).
  • Cell Entry $A[i, j]$: The set of access rights that a process in domain $D_i$ may exercise on object $O_j$.

Special Dynamic Rights:

  • switch: Allows a process in domain $D_1$ to switch its execution context into domain $D_2$.
  • copy right (*): A process holding read* can copy the read permission to other domains.
  • owner: Allows a domain to add or delete access rights in that object's column.
  • control: If $D_1$ has control over domain $D_2$, $D_1$ can modify the permissions in row $D_2$.

Implementation of the Access Matrix

In practice, the Access Matrix is immense and extremely sparse (thousands of files, but each domain accesses only a handful). Storing it as a dense 2D array is impossible. Operating systems implement it using one of three architectures:

ArchitectureHow it Stores the MatrixReal-World Analogy
1. Global Table A single table of ordered triples: $\langle \text{Domain}, \text{Object}, \text{Rights} \rangle$. Stored in kernel RAM. A master national registry database.
2. Access Control Lists (ACL) Column-wise: Each object has an attached list of pairs $\langle \text{Domain}, \text{Rights} \rangle$. Evaluated on object access. A guest list held at the door of a VIP room.
3. Capability Lists (C-Lists) Row-wise: Each domain has an attached list of capabilities $\langle \text{Object}, \text{Rights} \rangle$. A personal key ring or unforgeable concert tickets.
4. Lock-and-Key Hybrid: Each object has a bit pattern (Lock); each domain holds unique bit patterns (Keys). Access granted if key matches lock. Physical padlock and matching brass keys.

Revocation of Access Rights

When an access right is rescinded, several design trade-offs emerge:

  • Immediate vs Delayed: Immediate revocation affects active running processes instantly. Delayed revocation occurs the next time the process attempts to re-open the object.
  • Selective vs General: Revoking access for a single specific user versus revoking it for all users of the object.
  • Partial vs Total: Revoking only write access while preserving read access versus revoking all rights.
  • Temporary vs Permanent: Whether the right can be restored or is permanently expunged.
Why Revocation is Hard in Capability Systems (and Solutions)

In a capability system, once a process holds a capability ticket, finding and revoking all copies is difficult. Systems solve this using:

  1. Indirection / Back-pointers: Capabilities point to an entry in a global table, which then points to the object. Revoking the pointer in the table immediately invalidates all capabilities.
  2. Generation Keys: The object and capability both contain a generation number (e.g. 5). When revoked, the object increments its generation to 6. Old capabilities mismatch and fail.

Check yourself

Retrieval practice

1. What is the key distinction between an Access Control List (ACL) and a Capability List?

ACLs decompose the access matrix by columns (attached to objects); Capability lists decompose it by rows (attached to domains).

2. Why is revoking access rights trivial in an ACL-based system?

To revoke access to an object, the administrator simply modifies or deletes that domain's entry in the object's local ACL.

3. The Principle of Least Privilege states that:

Least privilege restricts access to prevent bugs or compromised components from damaging unrelated resources.

Recall without looking

What do rows and columns represent in an Access Matrix?

Rows = Domains (protection contexts). Columns = Objects (files, devices, printers, other domains). Cells = Access rights.

Contrast ACL vs Capability List on column/row and revocation.

ACL: column-wise (stored with object), revocation is immediate and easy. Capability List: row-wise (stored with domain/process), revocation is difficult because copies are widely distributed.

What are the four dynamic rights in an access matrix?

Switch (domain transition), Copy (*) (duplicate right to another domain), Owner (modify column rights), Control (modify row rights).
