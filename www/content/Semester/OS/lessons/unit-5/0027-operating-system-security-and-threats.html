Operating System Security and Threats

The security problem, program threats (Trojans, trapdoors, logic bombs, buffer overflows), system and network threats (DoS, port scanning), and Linux/Windows modern security case studies (SELinux and Windows UAC).

Exam strategy

“Explain program threats and system threats with examples” and “Compare Linux (SELinux) and Windows OS security architectures” are recurrent 7-to-10 mark questions. Define the standard threat taxonomy and detail Mandatory Access Control (MAC) vs Discretionary Access Control (DAC).

The Security Problem

An operating system is secure if its resources are used and accessed as intended under all circumstances. System security encompasses four core dimensions:

  1. Confidentiality: Preventing unauthorized disclosure of user files, credentials, and memory contents.
  2. Integrity: Preventing unauthorized modification or corruption of system binaries, configurations, and user data.
  3. Availability: Ensuring system hardware, CPU time, and network bandwidth remain accessible to authorized users.
  4. Authenticity & Accountability: Ensuring every request is tied to a verified identity, recorded in tamper-resistant audit logs.

Program Threats

Program threats exploit software bugs, design flaws, or social engineering to execute unauthorized instructions within a process context.

Program ThreatMechanismReal-World Scenario / Impact
Trojan Horse Disguises itself as a useful, benign application (e.g., a system game, screensaver, or driver update) while secretly executing unauthorized actions. A user installs a fake calculator app; the program runs normally on screen while secretly dumping browser passwords.
Trapdoor / Backdoor A secret entry point or bypass intentionally or inadvertently left in the code by a developer that skips standard authentication. A hardcoded master password (admin/admin123) left in production firmware that grants instant root access.
Logic Bomb Dormant embedded code that remains completely silent until a specific logical condition is satisfied (e.g., a date, a database query, or absence of an employee ID). A disgruntled engineer programs code to erase accounting databases if their name disappears from the company payroll roster.
Buffer Overflow Writing past array boundaries in memory to corrupt adjacent control structures (saved EBP and return address), redirecting execution to shellcode. Overwriting stack frames in network daemons to spawn a root shell without credentials.
Viruses & Worms Code that infects host executables (virus) or autonomous self-replicating programs that propagate over network sockets (worm). Morris worm, CIH virus, Slammer.

System and Network Threats

1. Port Scanning

Automated reconnaissance using tools like nmap to probe a target IP for open TCP/UDP ports. Attackers identify running services (e.g., Apache 2.4.49, OpenSSH 7.2) and map them to published vulnerabilities (CVEs).

2. Denial of Service (DoS and DDoS)

Attacks aimed at destroying availability rather than stealing data:

  • TCP SYN Flood: Attacker sends thousands of spoofed TCP SYN packets. The OS allocates a transmission control block (TCB) in the “half-open” queue and waits for the final ACK. The queue exhausts, causing the server to reject legitimate users. Defended using SYN Cookies.
  • DDoS: A botnet of hundreds of thousands of compromised devices floods a target with hundreds of gigabits of traffic simultaneously, choking upstream network bandwidth.

Modern OS Security Case Studies

Case Study 1: Linux Security Model & SELinux

Traditional Linux utilizes Discretionary Access Control (DAC) based on owner, group, and others (chmod 755). A major flaw in DAC is that if an attacker compromises a daemon running as root, they gain total control over the entire system.

Mandatory Access Control (MAC) via SELinux

Security-Enhanced Linux (SELinux) enforces Mandatory Access Control (MAC) using Flask security architecture:

  • Every process (subject) and system file/socket (object) is assigned a security context label: user:role:type:sensitivity.
  • Access is governed strictly by the Type Enforcement (TE) model: even if a process runs as root, if the policy rule does not explicitly grant the type permission to write to /etc/shadow, the Linux kernel blocks the access and logs an audit failure.
  • Root's omnipotent power is effectively curtailed.

Case Study 2: Windows Security Architecture

Windows NT/10/11 implements an object-based security model managed by the Security Reference Monitor (SRM):

Windows Security Components
  • Security Identifiers (SIDs): Every user, group, and computer account has a globally unique, immutable string identifier (e.g., S-1-5-21-...-1001).
  • Access Token: Created when a user logs in (LSASS). Contains the user's SID, group SIDs, and active privileges. Every child process spawned inherits this access token.
  • Security Descriptor (SD): Attached to every securable OS object (files, registry keys, threads). Contains the Owner SID and a DACL (Discretionary Access Control List) composed of Access Control Entries (ACEs) specifying Allow or Deny permissions.
  • User Account Control (UAC): Even when an administrator logs in, their primary login session receives a stripped standard-user access token. High-privilege tasks prompt the user with a secure desktop consent dialog before elevating to administrator privilege.

Check yourself

Retrieval practice

1. Why does Mandatory Access Control (MAC / SELinux) provide stronger security than traditional Linux DAC permissions?

In SELinux MAC, policy rules dictate what types can interact; even root processes are strictly confined to their declared domains.

2. In a TCP SYN flood Denial of Service attack, what operating system resource is exhausted?

The server allocates state for incomplete 3-way handshakes until its connection backlog is exhausted.

3. In Windows security, what object is created upon logon and inherited by all spawned child processes?

The Access Token carries the user's SIDs, group memberships, and privileges throughout their process tree.

Recall without looking

Contrast a Trojan Horse and a Trapdoor.

Trojan: masquerades as useful software while secretly performing unauthorized actions. Trapdoor: a hidden developer backdoor that bypasses standard authentication.

How does SELinux enforce security differently from traditional Linux DAC?

Traditional DAC allows the root user to bypass all checks. SELinux (MAC) labels all processes and objects with types; the kernel blocks actions unless an explicit policy rule permits them, even for root.

Name the key components of the Windows security model.

SIDs (unique identity identifiers), Access Tokens (process credentials), Security Descriptors with DACLs (attached to objects), and UAC (least-privilege elevation).
