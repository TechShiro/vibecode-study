I/O Hardware Structure

The computer interacts with peripheral hardware via three components: physical devices, electronic device controllers, and system buses (PCIe, USB, SATA).

Device Controller Registers

The CPU communicates with a device controller through four hardware registers:

  1. Data-in register: Read by the CPU to receive input data from the device.
  2. Data-out register: Written by the CPU to transmit output data to the device.
  3. Status register: Read by the CPU; contains bit flags (e.g. busy, data-ready, error).
  4. Control register: Written by the CPU to command the controller (e.g. start read, enable interrupts).

The Three I/O Transfer Techniques

1. Polling (Programmed I/O / Busy-Waiting)

The CPU repeatedly loops reading the controller's status register until the busy bit clears and the data-ready bit is set:

while (controller->status & BUSY) {
    /* Busy-wait / spin loop */
}
*buffer++ = controller->data_in;
  • Advantage: Very simple; minimal latency if the hardware device is extremely fast (e.g. sub-microsecond cache controller).
  • Disadvantage: Completely wastes CPU clock cycles in a spin-wait if the device is slow (e.g., waiting for human typing or mechanical disk rotation).
2. Interrupt-Driven I/O

The CPU commands the controller to initiate an operation, then immediately switches context to execute other user processes. When the controller finishes, it asserts an electrical Interrupt Request (INTR) line on the bus.

  • The CPU finishes its current clock cycle instruction, saves process registers, and queries the Interrupt Vector Table (IVT) to find the address of the corresponding Interrupt Service Routine (ISR).
  • The ISR transfers the data, clears the interrupt flag, and returns via IRET.
  • Maskable vs Non-Maskable: Maskable interrupts can be temporarily deferred by the CPU during critical code sections; Non-Maskable Interrupts (NMI) handle unrecoverable hardware faults (memory parity failure).
  • Disadvantage: Inefficient for high-speed devices; interrupting the CPU for every single byte/word of a 100MB file transfer causes crippling context-switch overhead.
3. Direct Memory Access (DMA)

For high-speed block devices (disks, Gigabit NICs), the CPU delegates the entire data movement to a specialized hardware co-processor: the DMA Controller (DMAC).

Step 1: CPU writes to DMAC registers:
        - Source address (Device port)
        - Destination address (Memory buffer)
        - Byte count (e.g. 4096 bytes)
        - Control command (Read/Write)
Step 2: CPU resumes running user processes.
Step 3: DMAC manages bus requests and transfers the entire block 
        directly between device and RAM without CPU intervention.
Step 4: Once all bytes are moved, DMAC raises a SINGLE interrupt to the CPU.

DMA Bus Arbitration Modes:

  • Burst Mode (Block Transfer): The DMAC seizes total control of the system bus and transfers the entire data block in one contiguous burst. Fast for I/O, but CPU is locked out of RAM during the burst.
  • Cycle Stealing: The DMAC “steals” single bus clock cycles from the CPU when the CPU is executing internal arithmetic (ALU) operations not requiring the system bus. Minimizes CPU interference.

Check yourself

Retrieval practice

1. Why is interrupt-driven I/O inefficient for moving large files from an SSD to RAM?

Handling millions of interrupts per second causes unacceptable ISR context-switching penalties, making DMA essential.

2. In Direct Memory Access (DMA), what is 'cycle stealing'?

Cycle stealing interleaves bus access between the CPU and DMAC without blocking the CPU for long contiguous periods.

3. In Memory-Mapped I/O, how does the CPU communicate with device registers?

Device registers appear as normal memory addresses, accessible with standard load/store CPU instructions.

Recall without looking

Name the four registers of an I/O device controller.

Data-in (receive), Data-out (transmit), Status (busy/ready flags), Control (command execution).

Memory-mapped vs Port-mapped I/O.

Memory-mapped: device registers share RAM address space, use standard MOV instructions. Port-mapped: separate I/O space, requires special IN/OUT instructions.

Contrast DMA burst mode and cycle stealing.

Burst mode: DMAC locks the bus for the entire block transfer. Cycle stealing: DMAC takes individual bus cycles when the CPU is busy with internal ALU operations.
