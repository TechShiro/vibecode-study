Definitions memorise

Algorithm: a finite sequence of unambiguous instructions that, for a given set of inputs, produces the required output in finite time.

Five characteristics: Input (zero or more) · Output (at least one) · Definiteness · Finiteness · Effectiveness. An OS is a program but not an algorithm — it violates finiteness.

RAM model — four assumptions: a single processor executing sequentially; each simple operation costs one time step; unlimited memory with every access costing one step and no memory hierarchy; each word holds one number. Used for machine independence, simplicity, and because it ranks algorithms correctly.

A priori = theoretical, before implementation, machine-independent, asymptotic. A posteriori = profiled after implementation, exact, machine-dependent.

Asymptotic notation high yield

The definitions — write these before any proof f = O(g): ∃ c, n0 > 0 with 0 ≤ f(n) ≤ c·g(n) for all n ≥ n0.  Upper bound — worst case.
f = Ω(g): ∃ c, n0 with 0 ≤ c·g(n) ≤ f(n).  Lower bound — best case.
f = Θ(g): ∃ c1, c2, n0 with c1g(n) ≤ f(n) ≤ c2g(n).  Tight bound.
f = o(g): for EVERY c, f(n) < c·g(n) eventually.   f = ω(g): for every c, c·g(n) < f(n).

Θ ⇔ O and Ω together. Limit test: O → finite · o → 0 · Θ → finite non-zero · ω → ∞.

Disproof template (show n² ≠ O(n)): assume n² ≤ cn; divide by n to get n ≤ c; but c is fixed and n unbounded — contradiction.

Growth-rate chain 1 < log log n < log n < √n < n < n log n < n² < n³ < 2n < 3n < n! < nn
Two traps: log n is SLOWER than √n, and n! is FASTER than 2n. The log base is irrelevant.

Properties: reflexive (O, Ω, Θ only) · transitive (all five) · symmetric — Θ only · transpose symmetric (O↔Ω, o↔ω) · sum rule: f1+f2 = O(max(g1, g2)) · product rule · constant rule. n = O(n²) is true; n² = O(n) is false — big oh is not symmetric.

Recursion tree: for level i give the node count ai, the size n/bi and the level cost; find the height; sum. Top-heavy → Θ(f(n)). Balanced → f(n) × levels. Bottom-heavy → Θ(nlogba).

The identity: alogbn = nlogba.

Induction proof of T(n) = 2T(n/2) + n = O(n log n): guess T(n) ≤ cn log n; substituting gives cn log n − cn + n ≤ cn log n whenever c ≥ 1. The base case must be n = 2, not n = 1, since c·1·log 1 = 0 < T(1).

ExamplesMerge sort, quick sort, Strassen, binary searchFractional knapsack, Huffman, Prim, Kruskal, DijkstraN-queens, graph colouring, Hamiltonian cycle, subset sum0/1 knapsack, TSP, job assignment, 15-puzzle

Greedy fails on 0/1 knapsack, TSP and negative-weight shortest paths. Fractional knapsack works because items can be split.

Fractional knapsack, W = 15, p = (10,5,15,7,6,18,3), w = (2,3,5,7,1,4,1): ratios 5, 1.67, 3, 1, 6, 4.5, 3 → order 5, 1, 6, 3, 7, 2, 4 → x = (1, 2/3, 1, 0, 1, 1, 1), profit = 55.33, weight exactly 15.

4-queens: clash if xi = xj or |xi − xj| = |i − j|. Solutions (2,4,1,3) and (3,1,4,2).

Branch-and-bound 0/1 knapsack: the upper bound at a node = profit so far + the fractional-knapsack value of the remaining capacity. Prune any node whose bound is worse than the best complete solution found.

Dynamic programming differs from divide and conquer in having overlapping subproblems (solved once and stored), and from greedy in considering all choices.
