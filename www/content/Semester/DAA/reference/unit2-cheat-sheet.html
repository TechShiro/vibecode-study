Binary search trees

Property: at every node, all left keys < key < all right keys, recursively. Inorder traversal gives sorted order — the free check on every answer.

Traversals: Inorder = L-Root-R (sorted) · Preorder = Root-L-R (starts with the root) · Postorder = L-R-Root (ends with the root) · Level order uses a queue. All Θ(n).

Deletion — three cases: leaf → remove; one child → replace by the child; two children → replace the key by the inorder successor (minimum of the right subtree), then delete that successor. The inorder predecessor is equally correct — state which you use.

Reconstruction: inorder + preorder → unique; inorder + postorder → unique; preorder + postorder → NOT unique. Inorder is always needed, because only it separates the left subtree from the right.

Worked example — insert 45, 15, 79, 90, 10, 55, 12, 20, 50: root 45; inorder 10, 12, 15, 20, 45, 50, 55, 79, 90; preorder 45, 15, 10, 12, 20, 79, 55, 50, 90; postorder 12, 10, 20, 15, 50, 55, 90, 79, 45.

AVL trees

Balance factor and the four rotations BF = height(left) − height(right) ∈ {−1, 0, +1}. ±2 → rotate at the lowest such node A.

LL (+2, child +1) → single right rotation  ·  RR (−2, child −1) → single left
LR (+2, child −1) → left at the child, then right at A  ·  RL (−2, child +1) → right at the child, then left at A

Same direction twice → single. Direction changes → double.
Shortcut: of the three keys involved, the middle one becomes the subtree root.

Insertion needs at most 1 rotation; deletion may need O(log n) — because a rotation restores the subtree's height on insertion but reduces it on deletion. Deletion also uses the L0 / L1 / L−1 and R0 / R1 / R−1 notation, chosen from the sibling's balance factor; L0 and R0 can only arise from a deletion.

Minimum nodes in an AVL tree of height h N(h) = N(h−1) + N(h−2) + 1,   N(0) = 1, N(1) = 2  →  1, 2, 4, 7, 12, 20, 33, 54, 88, 143, 232
N(h) = Fibonacci(h+3) − 1 — the sparsest are called Fibonacci trees. Maximum nodes = 2h+1 − 1.
h < 1.44 log2(n + 2) − 0.328

Worked: minimum nodes at height 5 = 20. Maximum height with 20 nodes = 5 (since N(6) = 33 > 20). Inserting 10, 20, 30, 40, 50, 25 gives root 30 after two RR rotations and one RL.

Red–black trees

The five properties — verbatim 1. Every node is RED or BLACK.   2. The root is BLACK.   3. Every leaf (NIL) is BLACK.
4. If a node is RED, both its children are BLACK — no two adjacent reds.
5. All simple paths from a node to its descendant leaves contain the same number of BLACK nodes.

h ≤ 2 log2(n + 1) — because property 5 equalises the blacks and property 4 caps the reds, so no path exceeds twice any other.

Insertion: insert as a BST, colour the new node RED (black would break property 5, the hardest to repair), fix up, then colour the root black.

Fix-up — RED UNCLE → RECOLOUR, BLACK UNCLE → ROTATE. Case 1 (red uncle): parent and uncle black, grandparent red, move up. Case 2 (black uncle, triangle): rotate at the parent → Case 3. Case 3 (black uncle, line): rotate at the grandparent, parent black, grandparent red — done.

Deletion: a removed red node breaks nothing; a removed black one makes its replacement double black, pushed up through four sibling cases — only the “black sibling with two black children” case loops. At most 3 rotations.

B-trees

Order m — write these two numbers first Max keys = m − 1    Min keys = ⌈m/2⌉ − 1 (except the root, which needs only 1)
Max children = m   Min children = ⌈m/2⌉   A node with k keys has k + 1 children. All leaves at the same level.

Order 3 = 2–3 tree · order 4 = 2–3–4 tree ≡ a red–black tree · order 5 → max 4 keys, min 2.

Insertion: only at a leaf; on overflow split and push the MEDIAN up, repeating upward. If the root splits, the height grows by one — a B-tree grows upward.

Deletion: replace an internal key by its predecessor or successor from a leaf; on underflow borrow from an immediate sibling that has more than the minimum, otherwise merge the node, the separator and a sibling. “Borrow if you can, merge if you must.”

Bounds Max keys = mh+1 − 1  ·  Min keys = 2⌈m/2⌉h − 1  ·  h ≤ log⌈m/2⌉((n+1)/2)
Order 101 with 106 keys → h ≤ 3, so 4 disk accesses against 20 for a binary tree.

Worked: order 5, inserting 10…90 gives root [30 | 60] with leaves [10|20], [40|50], [70|80|90]. Deleting 40 borrows from the right (60 down, 70 up); deleting 50 then merges into [10|20|30|60] under root [70].

B+ tree: data only in the leaves, which are linked; keys duplicated in internal nodes; uniform search cost; excellent range queries; higher branching factor and so a shallower tree; easier deletion. Used by nearly every database index.

Hashing

Collisions are unavoidable by the pigeonhole principle, since |U| > m. Load factor α = n/m.

Hash functions: division h(k) = k mod m with m prime, not near a power of 2 · multiplication h(k) = ⌊m(kA mod 1)⌋ with A = (√5−1)/2 ≈ 0.618 (m may be a power of 2) · mid-square · folding · universal hashing.

Naming trap: open hashing = separate chaining; closed hashing = open addressing.

Deletion in open addressing needs a DELETED tombstone, or every probe sequence through that slot breaks. Rehashing doubles the table (next prime above 2m) and reinserts everything — O(n), amortised O(1).

Heaps

Formulas 1-based: parent ⌊i/2⌋, left 2i, right 2i+1.   0-based: parent ⌊(i−1)/2⌋, left 2i+1, right 2i+2.
Height ⌊log2n⌋ · leaves ⌈n/2⌉ at indices ⌊n/2⌋+1 to n · internal ⌊n/2⌋ · nodes at height h ≤ ⌈n/2h+1⌉

BUILD-MAX-HEAP heapifies from ⌊n/2⌋ down to 1 — everything above ⌊n/2⌋ is a leaf.

The O(n) proof — five lines Nodes at height h ≤ ⌈n/2h+1⌉  ·  heapify at height h costs O(h)
T(n) = Σ ⌈n/2h+1⌉·O(h) = O(n · Σ h/2h)
Σh=0∞ h/2h = 2  (from Σkxk = x/(1−x)² at x = ½)
⇒ T(n) = O(2n) = O(n)

A heap is NOT a BST — siblings are unordered and inorder is not sorted. The second largest is always a child of the root; the smallest can be any leaf, so finding it costs Θ(n).

Worked: build from [4, 10, 3, 5, 1] → [10, 5, 3, 4, 1]. Insert 15 → [15, 5, 10, 4, 1, 3]. Extract-max → 15, heap back to [10, 5, 3, 4, 1].

Priority queue applications: heap sort · Dijkstra (O(V²) → O((V+E) log V)) · Prim · Huffman · CPU priority scheduling · least-cost branch and bound.

Quick sort — the three derivations Best: T(n) = 2T(n/2) + Θ(n) → Θ(n log n)
Worst: T(n) = T(n−1) + Θ(n) = n(n+1)/2 → Θ(n²), on already sorted input
Average: T(n) = (1/n)Σ[T(i) + T(n−1−i)] + Θ(n) ≈ 1.39 n log2n = Θ(n log n)

Even a fixed 9:1 split gives n log n — only a split unbalanced by a constant number of elements gives n².
Fixes: randomised pivot · median-of-three · introsort (switch to heap sort past depth 2 log n) — what std::sort does.
The Ω(n log n) lower bound — six steps Model a comparison sort as a binary decision tree: internal nodes are comparisons, leaves are output permutations.
It must produce all n! permutations ⇒ at least n! leaves.
A binary tree of height h has ≤ 2h leaves ⇒ 2h ≥ n! ⇒ h ≥ log2(n!).
By Stirling, log2(n!) = Θ(n log n). The height is the worst-case comparison count. ∎

Merge and heap sort are therefore asymptotically optimal. Counting, radix and bucket sort escape the bound by not comparing elements to each other.

Worked traces. Merge sort [38,27,43,3,9,82,10] → [3,9,10,27,38,43,82]. Quick sort [10,80,30,90,40,50,70] with pivot 70 → after the first partition [10,30,40,50,70,90,80], final [10,30,40,50,70,80,90]. Heap sort [4,10,3,5,1] → heap [10,5,3,4,1] → sorted [1,3,4,5,10].

Counting sort of [4,2,2,8,3,3,1]: counts [0,1,2,2,1,0,0,0,1] → cumulative [0,1,3,5,6,6,6,6,7] → place right to left (which is what makes it stable) → [1,2,2,3,3,4,8]. The last cumulative entry must equal n.

Radix sort of [170,45,75,90,802,24,2,66]: units → [170,90,802,2,24,45,75,66]; tens → [802,2,24,45,66,170,75,90]; hundreds → [2,24,45,66,75,90,170,802]. Radix sort is only truly linear when d is fixed and small — in general d ≥ logkn.

Bucket sort of ten values in [0,1) with bucket ⌊10x⌋: scatter, insertion-sort each bucket, concatenate. Linear time is an assumption about the distribution, not a guarantee.

KMP — the LPS array LPS[i] = length of the longest PROPER prefix of P[0..i] that is also a suffix.
Build: len = 0, LPS[0] = 0; if P[i] = P[len] then len++, LPS[i] = len, i++; else if len ≠ 0 then len = LPS[len−1] (i unchanged); else LPS[i] = 0, i++.

P = “ABABCABAB” → LPS = [0, 0, 1, 2, 0, 1, 2, 3, 4]

Search: on a mismatch after j matches, set j = LPS[j−1] and do not move the text pointer; if j = 0, advance the text pointer. Match found when j = m, at shift i − j.
Boyer–Moore — the two rules, take the LARGER shift Bad character: mismatch at pattern position j against text character c → shift = max(1, j − last[c]); if c is not in the pattern at all, shift = j + 1 (skip past it).
Good suffix: align the part that matched with another occurrence of it in P, or with a prefix of P, or shift past it by m.

Worked: P = “ABC” in T = “ABAAABCD” with last[A]=0, last[B]=1, last[C]=2: shift 0 mismatches (shift 2), shift 2 mismatches (shift 2), match at shift 4 — only 5 comparisons.
