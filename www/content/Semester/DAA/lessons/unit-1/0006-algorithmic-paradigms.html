1. Divide and conquer

The three steps DIVIDE — break the problem into a number of subproblems that are smaller instances of the same problem.
CONQUER — solve the subproblems recursively. If a subproblem is small enough, solve it directly — the base case.
COMBINE — combine the subproblem solutions into the solution for the original problem.
Control abstraction
DandC(P) {
   if (Small(P)) return S(P);     /* base case, solved directly */
   else {
     divide P into smaller instances P1, P2, …, Pk;
     return Combine( DandC(P1), DandC(P2), …, DandC(Pk) );
   }
}

The running time is always a recurrence of the shape T(n) = a T(n/b) + f(n) — which is precisely why Lesson 5's Master theorem exists.

2. Greedy

The strategy Build the solution one piece at a time, always choosing the piece that looks best at this moment — the locally optimal choice — and never reconsidering it.
Property requiredMeaning
Greedy-choice propertyA globally optimal solution can be reached by making a locally optimal choice at each step. The choice may depend on choices already made, but not on choices still to come.
Optimal substructureAn optimal solution to the problem contains within it optimal solutions to the subproblems
Control abstraction
Greedy(a, n) {  /* a[1..n] is the input set */
   solution = ∅;
   for (i = 1; i <= n; i++) {
     x = Select(a);          /* pick the locally best item */
     if (Feasible(solution, x))  /* does it keep the solution legal? */
       solution = Union(solution, x);
   }
   return solution;
}
Three functions define any greedy algorithm: Select, Feasible and Union.
The crucial warning — include it in every greedy answer

Greedy does not always give the optimal solution. It is optimal for fractional knapsack, activity selection, Huffman coding, Prim's, Kruskal's and Dijkstra's. It fails for the 0/1 knapsack problem — which needs dynamic programming — and for the travelling salesman problem, and for shortest paths with negative edges.

The contrast to quote: fractional knapsack is solved greedily because an item can be cut; 0/1 knapsack cannot, because taking a high-ratio item may block a better combination.

3. Backtracking

The strategy A systematic, refined brute force: build the solution one component at a time, and as soon as a partial solution cannot possibly be completed into a valid one, abandon it and back up to the previous component — backtrack.
TermMeaning
State-space treeThe tree of all partial solutions. Backtracking performs a depth-first traversal of it
Bounding functionThe test that decides whether a partial solution can lead to a complete one
Promising nodeA partial solution that may still lead to a complete solution — explore its children
Non-promising nodeOne that cannot — prune the whole subtree and backtrack
Live node / E-node / dead nodeGenerated but not fully explored / currently being expanded / cannot be expanded further

Classic problems: N-queens, graph colouring, Hamiltonian cycle, subset sum, sum of subsets, the knight's tour, and Sudoku.

Worked example — the 4-queens problem.

The problem: place 4 queens on a 4×4 board so that no two share a row, a column or a diagonal.

The formulation: since no two queens may share a row, put queen i in row i and let xi be its column. The solution is a vector (x1, x2, x3, x4).

The bounding function — two conditions Queens at (i, xi) and (j, xj) conflict if
xi = xj  (same column)   or   |xi − xj| = |i − j|  (same diagonal)

The trace:

Answer: x = (2, 4, 1, 3), meaning queens at (1,2), (2,4), (3,1), (4,3). The second solution is its mirror, (3, 1, 4, 2), and there are exactly two for n = 4.

Verify the diagonals of (2,4,1,3): |2−4| = 2 ≠ |1−2| = 1 ✓; |2−1| = 1 ≠ |1−3| = 2 ✓; |2−3| = 1 ≠ |1−4| = 3 ✓; |4−1| = 3 ≠ |2−3| = 1 ✓; |4−3| = 1 ≠ |2−4| = 2 ✓; |1−3| = 2 ≠ |3−4| = 1 ✓. All six pairs clear.

The saving: brute force would test 44 = 256 placements (or 4! = 24 with the one-per-row rule). Backtracking examined about a dozen nodes. That pruning is the entire point.

4. Branch and bound

The strategy Like backtracking, it searches a state-space tree — but it is used for optimisation problems, not just feasibility. At each node it computes a bound on the best value obtainable in that subtree, and prunes any subtree whose bound is worse than the best complete solution found so far.
Search strategyHow the next live node is chosen
FIFO branch and boundA queue — a breadth-first search of the state-space tree
LIFO branch and boundA stack — a depth-first search, closest to backtracking
Least-cost (LC) branch and boundA priority queue on the bound — expand the most promising node first. Usually the fastest

Classic problems: 0/1 knapsack, travelling salesman, job assignment, and 15-puzzle.

Two more paradigms the syllabus meets later

Dynamic programming (Unit IV) differs from divide and conquer in that its subproblems overlap, so each is solved once and its answer stored — memoisation or a table. It also differs from greedy in that it considers all choices rather than committing to one. That is why 0/1 knapsack needs DP and fractional knapsack does not.

Brute force tries every possibility with no pruning at all. Backtracking is brute force plus a bounding function; branch and bound is brute force plus a bound and an ordering.

Recall without looking

Give the three steps and the control abstraction of divide and conquer.

Divide the problem into smaller instances of the same problem; conquer by solving them recursively, with a base case solved directly; combine the results. The abstraction is: if Small(P) return S(P), else divide into P₁…Pₖ and return Combine(DandC(P₁), …). The cost is always T(n) = aT(n/b) + f(n).

Give the greedy control abstraction and the two properties required.

Repeatedly Select the locally best item, test whether it is Feasible, and if so take its Union with the solution. It requires the greedy-choice property — a global optimum is reachable by locally optimal choices — and optimal substructure.

Where does greedy work and where does it fail?

It is optimal for fractional knapsack, activity selection, Huffman coding, Prim's, Kruskal's and Dijkstra's. It fails for 0/1 knapsack, the travelling salesman problem, and shortest paths with negative edges. The contrast: fractional knapsack allows splitting an item, 0/1 does not.

Work the fractional knapsack for W = 15 with profits 10,5,15,7,6,18,3 and weights 2,3,5,7,1,4,1.

Ratios 5, 1.67, 3, 1, 6, 4.5, 3 give the order 5, 1, 6, 3, 7, 2, 4. Take items 5, 1, 6, 3, 7 whole (13 units, profit 52), then 2/3 of item 2 for 3.33. Total 55.33, with x = (1, 2/3, 1, 0, 1, 1, 1) and weight exactly 15.

Define backtracking and its vocabulary.

A refined brute force that builds a solution one component at a time and abandons a partial solution as soon as it cannot be completed. It performs a depth-first traversal of the state-space tree, using a bounding function to decide whether a node is promising; a non-promising node has its whole subtree pruned. Live node, E-node and dead node describe a node generated, being expanded, and unable to be expanded.

Solve 4-queens and state the clash conditions.

With queen i in row i and column xᵢ, two queens clash if xᵢ = xⱼ or |xᵢ − xⱼ| = |i − j|. The two solutions are (2, 4, 1, 3) and (3, 1, 4, 2).

Compare backtracking with branch and bound on six points.

Feasibility vs optimisation; depth-first only vs FIFO, LIFO or least-cost; a feasibility bounding function vs a bound compared against the best solution so far; returning to a node on failure vs choosing the next live node; better when solutions are dense vs guaranteeing optimality; N-queens and graph colouring vs 0/1 knapsack and TSP.

How does dynamic programming differ from divide and conquer and from greedy?

From divide and conquer: its subproblems overlap, so each is solved once and stored. From greedy: it considers all choices instead of committing to one. That is why 0/1 knapsack needs dynamic programming while fractional knapsack does not.
