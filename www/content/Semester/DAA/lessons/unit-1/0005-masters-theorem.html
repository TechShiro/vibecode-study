Master's Theorem

The three cases for dividing functions with the extended fourth case, twenty drilled recurrences, the master theorem for decreasing functions, and the five situations where it does not apply.

Exam strategy

These are the cheapest marks in the whole subject. A Master-theorem question is two lines of work: identify a, b and k, compare a with bk, write the answer. Expect two or three of them per paper, sometimes as objective questions. Drill the twenty below until identification is instant — and learn the decreasing-function version too, because syllabi that name “Master's theorem” separately, as this one does, usually examine both.

The Master theorem for dividing functions

The form it applies to T(n) = a · T(n/b) + f(n)    where a ≥ 1, b > 1, and f(n) is positive

a = number of subproblems  ·  b = factor by which the size shrinks  ·  f(n) = work outside the recursion

Write f(n) = Θ(nk logp n) with k ≥ 0. Then compare a with bk.
The three cases — write this box out before every answer CASE 1 — a > bk  (the leaves dominate)
    T(n) = Θ(nlogba)

CASE 2 — a = bk  (every level costs the same)
    if p > −1:   T(n) = Θ(nk logp+1 n)
    if p = −1:   T(n) = Θ(nk log log n)
    if p < −1:   T(n) = Θ(nk)

CASE 3 — a < bk  (the root dominates)
    if p ≥ 0:   T(n) = Θ(nk logp n)
    if p < 0:   T(n) = Θ(nk)
Where the three cases come from — say this and the answer stops being memorisation

They are the three recursion-tree shapes from Lesson 4. Case 1 is the bottom-heavy tree — the leaves dominate, and there are nlogba of them. Case 2 is the balanced tree — every level costs f(n), and there are log n levels, so one extra log appears. Case 3 is the top-heavy tree — the root's f(n) swamps everything below it.

The three-step method

Step 1. Read off a and b, then write f(n) as nklogpn and read off k and p.
Step 2. Compute bk and compare it with a. That names the case.
Step 3. Write the answer from the box, showing the comparison. Always write “a = 8, b = 2, k = 2, so bk = 4 < 8 = a, hence Case 1” — the marks are in that line, not in the final symbol.

Twenty drilled examples

Case 1 — a > bk, the leaves dominate

M1. T(n) = 8T(n/2) + n²

a = 8, b = 2, f(n) = n² so k = 2, p = 0.   bk = 2² = 4 < 8 = a → Case 1.

T(n) = Θ(nlog28) = Θ(n³)

This is naive divide-and-conquer matrix multiplication — no better than the school method.

M2. T(n) = 7T(n/2) + n²  (Strassen's algorithm)

a = 7, b = 2, k = 2, p = 0.   bk = 4 < 7 → Case 1.

T(n) = Θ(nlog27) = Θ(n2.807)

Compare M1: reducing eight multiplications to seven drops the exponent from 3 to 2.807 — the entire point of Strassen's algorithm.

M3. T(n) = 3T(n/2) + n

a = 3, b = 2, k = 1.   bk = 2 < 3 → Case 1.

T(n) = Θ(nlog23) = Θ(n1.585)

M4. T(n) = 4T(n/2) + n

a = 4, b = 2, k = 1.   bk = 2 < 4 → Case 1.

T(n) = Θ(nlog24) = Θ(n²)

M5. T(n) = 16T(n/4) + n

a = 16, b = 4, k = 1.   bk = 4 < 16 → Case 1.

T(n) = Θ(nlog416) = Θ(n²)

M6. T(n) = 3T(n/3) + √n

a = 3, b = 3, f(n) = n1/2 so k = 0.5.   bk = 30.5 = 1.732 < 3 → Case 1.

T(n) = Θ(nlog33) = Θ(n)

M7. T(n) = √2 · T(n/2) + log n

a = √2 ≈ 1.414, b = 2, f(n) = log n = n0log1n so k = 0, p = 1.   bk = 20 = 1 < 1.414 → Case 1.

T(n) = Θ(nlog2√2) = Θ(n0.5) = Θ(√n)

Note that a need not be an integer — only a ≥ 1. And note that in Case 1, p is irrelevant.

Case 2 — a = bk, every level costs the same

M8. T(n) = 2T(n/2) + n  (Merge sort)

a = 2, b = 2, k = 1, p = 0.   bk = 2 = a → Case 2, and p = 0 > −1.

T(n) = Θ(n1 log0+1 n) = Θ(n log n)

M9. T(n) = T(n/2) + 1  (Binary search)

a = 1, b = 2, f(n) = 1 = n0 so k = 0, p = 0.   bk = 20 = 1 = a → Case 2, p > −1.

T(n) = Θ(n0 log1 n) = Θ(log n)

M10. T(n) = 4T(n/2) + n²

a = 4, b = 2, k = 2, p = 0.   bk = 4 = a → Case 2.

T(n) = Θ(n² log n)

M11. T(n) = 2T(n/2) + n log n

a = 2, b = 2, f(n) = n log n = n1log1n so k = 1, p = 1.   bk = 2 = a → Case 2, p = 1 > −1.

T(n) = Θ(n log1+1 n) = Θ(n log² n)

This is the example that breaks the three-case version in CLRS — there is no polynomial gap between n log n and nlog22 = n. The extended version above handles it directly, which is why Indian syllabi teach the extended version.

M12. T(n) = 2T(n/2) + n / log n

f(n) = n · (log n)−1, so k = 1, p = −1.   bk = 2 = a → Case 2, and p = −1 exactly.

T(n) = Θ(n log log n)

The p = −1 sub-case exists solely for this shape. It is a classic objective question precisely because most students skip it.

M13. T(n) = 2T(n/2) + n / log² n

k = 1, p = −2.   bk = 2 = a → Case 2, and p = −2 < −1.

T(n) = Θ(n)

M14. T(n) = 4T(n/2) + n² log n

a = 4, b = 2, k = 2, p = 1.   bk = 4 = a → Case 2, p > −1.

T(n) = Θ(n² log² n)

Case 3 — a < bk, the root dominates

M15. T(n) = 2T(n/2) + n²

a = 2, b = 2, k = 2, p = 0.   bk = 4 > 2 = a → Case 3, p ≥ 0.

T(n) = Θ(n²)

M16. T(n) = 4T(n/2) + n³

a = 4, b = 2, k = 3.   bk = 8 > 4 → Case 3.

T(n) = Θ(n³)

M17. T(n) = T(n/2) + n

a = 1, b = 2, k = 1.   bk = 2 > 1 → Case 3.

T(n) = Θ(n) — matching R7 from Lesson 4, solved there by geometric series.

M18. T(n) = 2T(n/4) + n0.51

a = 2, b = 4, k = 0.51.   bk = 40.51 = 2.028 > 2 = a → Case 3 — but only just.

T(n) = Θ(n0.51)

Compare: with the exponent 0.5 instead, bk = 40.5 = 2 = a, which is Case 2, giving Θ(√n log n). A hundredth in the exponent changes the case. Always compute bk numerically rather than guessing.

M19. T(n) = 3T(n/4) + n log n

a = 3, b = 4, k = 1, p = 1.   bk = 4 > 3 → Case 3, p = 1 ≥ 0.

T(n) = Θ(n log n)

M20. T(n) = 2T(n/2) + n / log n — against M12, to show the comparison discipline

Already done in M12 as Case 2. Now change one thing: T(n) = T(n/2) + n / log n.

a = 1, b = 2, k = 1, p = −1.   bk = 2 > 1 = a → Case 3, and p = −1 < 0.

T(n) = Θ(nk) = Θ(n)

Note that in Case 3, a negative p is simply discarded.

The Master theorem for decreasing functions

The syllabus names “Master's theorem” without qualification, and the decreasing version is the half most students never learn — so it is disproportionately worth knowing.

For T(n) = a · T(n − b) + f(n), with f(n) = O(nk) If a < 1:   T(n) = O(nk)
If a = 1:   T(n) = O(nk+1)
If a > 1:   T(n) = O(nk · an/b)
#RecurrenceabkCaseAnswer
D1T(n) = T(n−1) + 1110a = 1O(n)
D2T(n) = T(n−1) + n111a = 1O(n²)
D3T(n) = T(n−1) + n²112a = 1O(n³)
D4T(n) = T(n−1) + log n110*a = 1O(n log n)
D5T(n) = 2T(n−1) + 1210a > 1O(2n)
D6T(n) = 3T(n−1) + 1310a > 1O(3n)
D7T(n) = 2T(n−1) + n211a > 1O(n · 2n)
D8T(n) = 2T(n−2) + 1220a > 1O(2n/2)
D9T(n) = ½T(n−1) + n½11a < 1O(n)

*D4 is a boundary case: log n is not exactly nk, but it behaves like k = 0 with an extra log, and the standard answer is O(n log n) — the sum of log 1 + log 2 + … + log n = log(n!) = Θ(n log n).

The pattern to hold in your head

a = 1 means “add one to the exponent” — the same work done n times. a > 1 means exponential — the branching factor raised to the number of levels, n/b. That is the whole theorem.

When the Master theorem does NOT apply

A standing 3–5 mark question: “state the limitations of the Master theorem.” Five situations:

#SituationExampleWhy it fails
1a is not a constantT(n) = 2nT(n/2) + nThe theorem requires a fixed a ≥ 1
2a < 1T(n) = 0.5 T(n/2) + nFewer than one subproblem is meaningless
3f(n) is not positiveT(n) = 2T(n/2) − n log nf must be positive for large n
4The subproblems are of unequal sizeT(n) = T(n/3) + T(2n/3) + nThe form aT(n/b) assumes all a subproblems are the same size — use a recursion tree instead
5b ≤ 1, or the recurrence is a decreasing oneT(n) = T(n−1) + nUse the decreasing-function version above, or back-substitution

A sixth, for CLRS's three-case version only: the regularity condition. Case 3 there additionally requires a·f(n/b) ≤ c·f(n) for some c < 1. The classic counter-example is T(n) = T(n/2) + n(2 − cos n), where f oscillates and the condition fails.

Check yourself

1. T(n) = 8T(n/2) + n² solves to:

a = 8, b = 2, k = 2, so bᵏ = 4 < 8 — Case 1, giving n^log₂8 = n³. Changing a to 7 gives Strassen's n^2.807; changing it to 4 gives Case 2 and n² log n.

2. T(n) = 2T(n/2) + n log n solves to:

k = 1 and p = 1, with bᵏ = 2 = a — Case 2 with p > −1, so the log exponent rises to p + 1 = 2. This is the case CLRS's three-case version cannot handle.

3. T(n) = 2T(n/2) + n / log n solves to:

k = 1, p = −1 and a = bᵏ — the special p = −1 sub-case of Case 2. With p = −2 instead the answer would be Θ(n).

4. T(n) = 2T(n/4) + n^0.51 falls in:

bᵏ = 4^0.51 = 2.028 > 2 = a, but only just. With the exponent 0.5 instead, bᵏ = 2 = a and it becomes Case 2 with answer Θ(√n log n) — compute bᵏ numerically, never by eye.

5. T(n) = 2T(n − 1) + 1 solves to:

Decreasing form with a = 2 > 1, b = 1, k = 0, so O(n⁰ · 2^(n/1)) = O(2ⁿ). It is the Tower of Hanoi recurrence.

6. Which recurrence does the Master theorem NOT apply to?

The subproblems are of unequal size, so the form aT(n/b) does not fit — use a recursion tree, which gives Θ(n log n). Note that a = √2 is perfectly legal, since only a ≥ 1 is required.

7. In Case 1 of the Master theorem, the value of p:

The leaves dominate so completely that any polylogarithmic factor in f(n) is swamped. p only matters in Cases 2 and 3.

Recall without looking

State the Master theorem for dividing functions, all cases.

For T(n) = aT(n/b) + f(n) with a ≥ 1, b > 1 and f(n) = Θ(n^k log^p n): if a > b^k then Θ(n^log_b a); if a = b^k then Θ(n^k log^(p+1) n) when p > −1, Θ(n^k log log n) when p = −1, and Θ(n^k) when p < −1; if a < b^k then Θ(n^k log^p n) when p ≥ 0 and Θ(n^k) when p < 0.

Explain where the three cases come from.

They are the three recursion-tree shapes. Case 1 is bottom-heavy: the leaves dominate, and there are n^log_b a of them. Case 2 is balanced: every level costs f(n) and there are log n levels, so one extra log appears. Case 3 is top-heavy: the root's f(n) swamps everything below.

Give the answers for merge sort, Strassen, naive matrix multiplication and binary search.

2T(n/2) + n = Θ(n log n). 7T(n/2) + n² = Θ(n^2.807). 8T(n/2) + n² = Θ(n³). T(n/2) + 1 = Θ(log n).

State the Master theorem for decreasing functions.

For T(n) = aT(n − b) + f(n) with f(n) = O(n^k): a < 1 gives O(n^k); a = 1 gives O(n^(k+1)); a > 1 gives O(n^k · a^(n/b)). So a = 1 adds one to the exponent, and a > 1 is exponential.

Name the five situations where the Master theorem does not apply.

a is not a constant; a < 1; f(n) is not positive; the subproblems have unequal sizes, as in T(n/3) + T(2n/3) + n; and the recurrence is a decreasing one. CLRS's three-case version additionally needs the regularity condition af(n/b) ≤ cf(n) in Case 3, which fails for oscillating f such as n(2 − cos n).

Why does T(n) = 2T(n/4) + n^0.51 differ from T(n) = 2T(n/4) + n^0.5?

b^k is 4^0.51 = 2.028 in the first, which exceeds a = 2, giving Case 3 and Θ(n^0.51). In the second b^k = 4^0.5 = 2 = a, giving Case 2 and Θ(√n log n). A hundredth in the exponent changes the case, so compute b^k numerically.
