Recurrence Relations

The three methods — back-substitution (iteration), the recursion tree, and substitution with induction — worked through twelve recurrences, plus the change-of-variable trick.

Exam strategy

“Solve the recurrence T(n) = … using the substitution method / recursion tree method” is a 5–10 mark question, and it appears every year. Read the wording carefully: if it names a method, you must use that method — quoting the Master theorem earns nothing. Learn the back-substitution discipline below: expand exactly three times, spot the pattern, write the general k-th term, then set k so the recursion bottoms out. That is the whole technique, and it never fails.

What a recurrence is, and how to write one

Definition A recurrence relation is an equation that describes a function in terms of its own value on smaller inputs, together with one or more base cases.

For a recursive algorithm it has the shape
T(n) = (cost of the recursive calls) + (cost of the work done outside them)
AlgorithmRecurrenceReading
Binary searchT(n) = T(n/2) + 1One call on half the array, plus a constant comparison
Merge sortT(n) = 2T(n/2) + nTwo calls on halves, plus a linear merge
Quick sort, best caseT(n) = 2T(n/2) + nBalanced partition, linear partitioning cost
Quick sort, worst caseT(n) = T(n−1) + nMaximally unbalanced partition
Strassen's multiplicationT(n) = 7T(n/2) + n²Seven half-size multiplications, quadratic additions
Naive matrix multiplicationT(n) = 8T(n/2) + n²Eight half-size multiplications
Tower of HanoiT(n) = 2T(n−1) + 1Two calls on n−1 discs, plus one move
FactorialT(n) = T(n−1) + 1One call, constant work
The two families — recognise which you are in

Decreasing (subtract): T(n) = aT(n − b) + f(n). The size drops by a fixed amount, so there are about n/b levels — and the answers tend to be polynomial or exponential.

Dividing (divide): T(n) = aT(n/b) + f(n). The size drops by a fixed factor, so there are only about logbn levels — and the answers involve logarithms.

Method 1 — back-substitution (iteration)

The discipline — follow it exactly and this method never fails

Step 1. Expand the recurrence three times. Three is enough to see the pattern and few enough to stay tidy.
Step 2. Write the general k-th expansion.
Step 3. Choose k so the recursion hits the base case — usually T(1) or T(0).
Step 4. Substitute that k and simplify.

R1. T(n) = T(n − 1) + 1, with T(1) = 1.

Expand:

T(n) = T(n−1) + 1
       = [T(n−2) + 1] + 1 = T(n−2) + 2
       = [T(n−3) + 1] + 2 = T(n−3) + 3

General k-th term:   T(n) = T(n − k) + k

Hit the base: set n − k = 1, so k = n − 1.

T(n) = T(1) + (n − 1) = 1 + n − 1 = n

T(n) = Θ(n)

R2. T(n) = T(n − 1) + n, with T(0) = 0.  (Quick sort's worst case)

T(n) = T(n−1) + n
       = T(n−2) + (n−1) + n
       = T(n−3) + (n−2) + (n−1) + n

General: T(n) = T(n−k) + [(n−k+1) + … + n]

Set k = n: T(n) = T(0) + (1 + 2 + … + n) = 0 + n(n+1)/2

T(n) = Θ(n²)

This is exactly why quick sort degrades to n² on a sorted array.

R3. T(n) = 2T(n − 1) + 1, with T(0) = 0.  (Tower of Hanoi)

T(n) = 2T(n−1) + 1
       = 2[2T(n−2) + 1] + 1 = 4T(n−2) + 2 + 1 = 4T(n−2) + 3
       = 4[2T(n−3) + 1] + 3 = 8T(n−3) + 4 + 3 = 8T(n−3) + 7

General: T(n) = 2kT(n−k) + (2k − 1)

Set k = n: T(n) = 2nT(0) + 2n − 1 = 2n − 1

T(n) = Θ(2n)

Sanity check: n = 3 gives 7 moves, which matches the puzzle by hand.

R4. T(n) = T(n/2) + 1, with T(1) = 1.  (Binary search)

T(n) = T(n/2) + 1 = T(n/4) + 2 = T(n/8) + 3

General: T(n) = T(n/2k) + k

Hit the base: set n/2k = 1, so 2k = n, so k = log2n.

T(n) = T(1) + log2n = 1 + log2n

T(n) = Θ(log n)

R5. T(n) = 2T(n/2) + n, with T(1) = 1.  (Merge sort — the most important recurrence in the course)

T(n) = 2T(n/2) + n
       = 2[2T(n/4) + n/2] + n = 4T(n/4) + n + n = 4T(n/4) + 2n
       = 4[2T(n/8) + n/4] + 2n = 8T(n/8) + n + 2n = 8T(n/8) + 3n

General: T(n) = 2kT(n/2k) + k·n

Set n/2k = 1, so k = log2n and 2k = n:

T(n) = n·T(1) + n log2n = n + n log2n

T(n) = Θ(n log n)

Notice the structure: every level costs exactly n, and there are log n levels. That observation is the recursion-tree method, which the next section makes formal.

R6. T(n) = 2T(n/2) + 1, with T(1) = 1.

T(n) = 2T(n/2) + 1 = 4T(n/4) + 2 + 1 = 8T(n/8) + 4 + 2 + 1

General: T(n) = 2kT(n/2k) + (2k − 1)

k = log2n, 2k = n:   T(n) = n + n − 1 = 2n − 1

T(n) = Θ(n)

Compare R5 and R6: the recursive part is identical, and only the additive term changed from n to 1 — yet the answer changed from n log n to n. The work done outside the recursion decides the answer.

R7. T(n) = T(n/2) + n, with T(1) = 1.

T(n) = T(n/2) + n = T(n/4) + n/2 + n = T(n/8) + n/4 + n/2 + n

General: T(n) = T(n/2k) + n(1 + ½ + ¼ + … + 1/2k−1)

The bracket is a geometric series with ratio ½, whose sum is less than 2 however many terms there are.

T(n) < T(1) + 2n

T(n) = Θ(n)

The lesson: a decreasing geometric series sums to a constant multiple of its first term. When the top level dominates, the answer is just the top level.

R8. T(n) = n · T(n − 1), with T(1) = 1.

T(n) = n·T(n−1) = n(n−1)T(n−2) = n(n−1)(n−2)T(n−3)

General: T(n) = n(n−1)(n−2)…(n−k+1) · T(n−k)

Set k = n − 1: T(n) = n(n−1)…2 · T(1) = n!

T(n) = Θ(n!)

Method 2 — the recursion tree

The discipline

Step 1. Draw the tree. The root is the non-recursive cost f(n); its children are the subproblems.
Step 2. Find, for level i: the number of nodes (ai), the size at each node (n/bi), and hence the cost of the level.
Step 3. Find the height — the level at which the size reaches 1.
Step 4. Sum the level costs.
Always draw at least three levels plus the leaf level, and label a “cost per level” column down the right-hand side. That column is where the marks are.

Height: the size is 1 when n/2i = 1, so i = log2n, giving log2n + 1 levels.

Total = (cost per level) × (number of levels) = n × (log2n + 1)

T(n) = Θ(n log n)

This is the picture to draw when a question says “analyse merge sort” — every level does exactly n work, and there are log n of them.

R9. T(n) = 3T(n/2) + n — a tree where the levels are NOT equal.

The level costs form an increasing geometric series with ratio 3/2, so the bottom level dominates — the opposite of R7.

Height = log2n. Number of leaves = 3log2n = nlog23, using the identity alogbn = nlogba.

Total = n · Σi=0..log₂n (3/2)i. An increasing geometric series is dominated by its last term, so

T(n) = Θ(nlog23) = Θ(n1.585)

The identity to memorise: alogbn = nlogba. It converts a leaf count into a polynomial, and it is the whole reason the Master theorem's first case reads nlogba.

R10. T(n) = T(n/3) + T(2n/3) + n — an unbalanced tree.

The two subproblems are of different sizes, so the tree is lopsided and the Master theorem does not apply. The recursion tree still works.

Cost per level: at every level the sizes still add up to n — n/3 + 2n/3 = n, then n/9 + 2n/9 + 2n/9 + 4n/9 = n, and so on. So each full level costs n.

Height: the tree is unbalanced, so it has two different depths.

  • Shortest path follows the n/3 branch: depth log3n.
  • Longest path follows the 2n/3 branch: n(2/3)d = 1 gives d = log3/2n.

Below depth log3n some branches have terminated, so levels cost at most n. Hence

n · log3n  ≤  T(n)  ≤  n · log3/2n

Both bounds are Θ(n log n), since the logarithm base is only a constant factor.

T(n) = Θ(n log n)

Why this recurrence matters: it is quick sort with a guaranteed 1:2 split. Even a badly unbalanced but constant-ratio split still gives n log n — which is why quick sort is fast in practice.

Method 3 — substitution (guess and verify by induction)

The discipline

Step 1. Guess the form of the answer — usually from a recursion tree or from a similar recurrence you know.
Step 2. Assume the guess holds for all values smaller than n (strong induction).
Step 3. Substitute into the recurrence and prove it holds for n, finding the constant.
Step 4. Verify the base case.

Some books call back-substitution “the substitution method” too. If a question says “substitution method” and the recurrence is simple, do back-substitution; if it says “prove that T(n) = O(…)”, do the induction.

R11. Prove by substitution that T(n) = 2T(⌊n/2⌋) + n is O(n log n).

Guess: T(n) ≤ c · n log n for some constant c > 0 and all n ≥ n0.

Inductive hypothesis: assume it holds for ⌊n/2⌋, that is

T(⌊n/2⌋) ≤ c · ⌊n/2⌋ log(⌊n/2⌋)

Inductive step: substitute into the recurrence.

T(n) ≤ 2 · [ c · (n/2) log(n/2) ] + n
        = c n log(n/2) + n
        = c n (log n − log 2) + n
        = c n log n − c n + n

This is ≤ c n log n provided −cn + n ≤ 0, that is provided c ≥ 1.

Base case: for n = 2, T(2) = 2T(1) + 2. With T(1) = 1 this is 4, and c·2·log 2 = 2c, so c ≥ 2 suffices. (Note that n = 1 cannot be used as the base, since c·1·log 1 = 0 while T(1) > 0 — start the induction at n = 2, which is legal because asymptotic claims only concern large n.)

With c = 2 and n0 = 2, T(n) ≤ 2n log n, so T(n) = O(n log n). ∎

The base-case subtlety is exactly what examiners probe — mention it.

R12 — change of variable. Solve T(n) = 2T(√n) + log n.

Neither method applies directly, because the size shrinks by a square root. Substitute n = 2m, so m = log n.

Then √n = 2m/2, and the recurrence becomes

T(2m) = 2 T(2m/2) + m

Define S(m) = T(2m). Then

S(m) = 2 S(m/2) + m

which is exactly R5. So S(m) = Θ(m log m). Substituting m = log n back:

T(n) = Θ(log n · log log n)

Whenever you see √n inside a recurrence, substitute n = 2m. It is a small trick with a large payoff, and it turns an unfamiliar recurrence into a familiar one.

The three shapes of a recursion tree — and the one-line answer for each

Top-heavy (level costs decrease geometrically, as in R7): the root dominates → T(n) = Θ(f(n)).

Balanced (all level costs equal, as in R5): T(n) = Θ(f(n) × number of levels).

Bottom-heavy (level costs increase geometrically, as in R9): the leaves dominate → T(n) = Θ(nlogba).

Those three cases are precisely the three cases of the Master theorem, which the next lesson turns into a formula.

Check yourself

1. The recurrence for merge sort is:

Two recursive calls on halves, plus a linear merge. Option two is binary search with linear work — Θ(n); option three is Θ(n); option four is quick sort's worst case — Θ(n²).

2. Solving T(n) = T(n−1) + n with T(0) = 0 gives:

Expanding gives T(0) + (1 + 2 + … + n). This is exactly quick sort on an already sorted array.

3. In the recursion tree for T(n) = 2T(n/2) + n, the cost of each level is:

Level i has 2ⁱ nodes each costing n/2ⁱ, so the product is always n. With log n + 1 levels the total is Θ(n log n).

4. The number of leaves in the tree for T(n) = 3T(n/2) + n is:

3^(log₂n) = n^(log₂3), using a^(log_b n) = n^(log_b a). The level costs grow geometrically, so the leaves dominate and T(n) = Θ(n^log₂3).

5. T(n) = T(n/3) + T(2n/3) + n solves to:

Every level still costs n, and the height is between log₃n and log_{3/2}n — both Θ(log n). It shows that even a fixed-ratio unbalanced split keeps quick sort at n log n.

6. In the induction proof for T(n) = 2T(n/2) + n = O(n log n), the base case cannot be n = 1 because:

Start the induction at n = 2 instead. This is legitimate because asymptotic statements only concern sufficiently large n — and it is exactly the subtlety examiners probe.

7. To solve T(n) = 2T(√n) + log n, the right first move is:

With S(m) = T(2^m) it becomes S(m) = 2S(m/2) + m, which is merge sort's recurrence — so S(m) = Θ(m log m) and T(n) = Θ(log n · log log n).

Recall without looking

Give the recurrences for binary search, merge sort, quick sort in both cases, Strassen's and Tower of Hanoi.

Binary search T(n) = T(n/2) + 1. Merge sort and quick sort best case T(n) = 2T(n/2) + n. Quick sort worst case T(n) = T(n−1) + n. Strassen T(n) = 7T(n/2) + n². Naive matrix multiplication T(n) = 8T(n/2) + n². Tower of Hanoi T(n) = 2T(n−1) + 1.

State the back-substitution discipline.

Expand three times; write the general k-th expansion; choose k so the recursion reaches the base case — n − k = 1 for decreasing recurrences, n/2^k = 1 giving k = log n for dividing ones; substitute and simplify.

Solve T(n) = 2T(n/2) + n and T(n) = 2T(n/2) + 1 by back-substitution.

The first gives T(n) = 2^k T(n/2^k) + kn; at k = log n this is n + n log n = Θ(n log n). The second gives 2^k T(n/2^k) + (2^k − 1) = 2n − 1 = Θ(n). Only the non-recursive term differs, and it changes the whole answer.

Describe the recursion-tree method and the three shapes a tree can have.

For each level find the number of nodes aⁱ, the size n/bⁱ, and hence the level cost; find the height where the size reaches 1; sum the level costs. Top-heavy (costs decrease geometrically): the root dominates, T = Θ(f(n)). Balanced (equal costs): T = f(n) × number of levels. Bottom-heavy (costs increase): the leaves dominate, T = Θ(n^log_b a).

Give the identity that converts a leaf count to a polynomial.

a^(log_b n) = n^(log_b a). It is why the Master theorem's first case reads n^(log_b a), and why T(n) = 3T(n/2) + n has n^(log₂3) leaves.

Prove T(n) = 2T(n/2) + n = O(n log n) by induction.

Guess T(n) ≤ cn log n. Assuming it for n/2, T(n) ≤ 2c(n/2)log(n/2) + n = cn log n − cn + n, which is ≤ cn log n whenever c ≥ 1. The base case must be n = 2 rather than n = 1, since c·1·log 1 = 0 while T(1) > 0; c = 2 works there.

How do you handle a √n inside a recurrence?

Change the variable: put n = 2^m, so √n = 2^(m/2), and define S(m) = T(2^m). T(n) = 2T(√n) + log n becomes S(m) = 2S(m/2) + m = Θ(m log m), so T(n) = Θ(log n · log log n).
