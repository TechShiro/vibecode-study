Asymptotic Notations and Their Significance

The formal definitions of O, Ω, Θ, little-o and little-ω, ten worked proofs finding c and n0, the growth-rate ordering, the properties, and the comparison table.

Exam strategy

This is the most reliably examined topic in Unit I. Three shapes: “Define big oh, omega and theta with graphs” (draw all three graphs — they are worth a mark each); “Show that 3n + 2 = O(n)” (you must produce actual values of c and n0, not wave at the definition); and “Arrange these functions in increasing order of growth”. Why asymptotic notation exists

Lesson 1 gave exact counts such as T(n) = 2n + 3 and 2n² + 2n + 1. Those exact counts are useless for comparison: the constants depend on the machine, and for large n only the fastest-growing term matters. So we throw away constant factors and lower-order terms, and keep only the rate of growth.

The significance — if the question says “and their significance”, say this

1. It makes analysis machine independent — constants absorb hardware differences.
2. It describes behaviour for large input, which is where efficiency actually matters — every algorithm is fast on ten elements.
3. It allows algorithms to be compared and classified without implementing either of them.
4. It gives bounds and guarantees, so we can promise an algorithm will never be slower than some function.

The three main notations

Big Oh — the upper bound f(n) = O(g(n)) if there exist positive constants c and n0 such that

0 ≤ f(n) ≤ c · g(n)   for all n ≥ n0

Meaning: g is an upper bound — f grows no faster than g. Used for the worst case.
Graph: c·g(n) sits above f(n) to the right of n0.
Big Omega — the lower bound f(n) = Ω(g(n)) if there exist positive constants c and n0 such that

0 ≤ c · g(n) ≤ f(n)   for all n ≥ n0

Meaning: g is a lower bound — f grows at least as fast as g. Used for the best case.
Graph: c·g(n) sits below f(n) to the right of n0.
Theta — the tight bound f(n) = Θ(g(n)) if there exist positive constants c1, c2 and n0 such that

0 ≤ c1 · g(n) ≤ f(n) ≤ c2 · g(n)   for all n ≥ n0

Meaning: f grows at exactly the rate of g — sandwiched between two multiples of it.
Graph: f(n) lies between c1g(n) and c2g(n) to the right of n0.
The theorem that ties them together

f(n) = Θ(g(n)) if and only if f(n) = O(g(n)) and f(n) = Ω(g(n)). Theta is exactly the conjunction of the other two, which is why a theta proof always has two halves.

The key difference between O and o: the bound 0 ≤ f(n) ≤ c·g(n) in big oh holds for some constant c, but in little oh it must hold for every c. So 2n² = O(n²) is true but 2n² = o(n²) is false; 2n = o(n²) is true.

Ten worked proofs

The method — use it every time

Step 1. Write the definition with the actual functions substituted.
Step 2. Bound each lower-order term by the dominant term, which is legal only for n large enough — and that requirement gives you n0.
Step 3. Add up the coefficients — that gives you c.
Step 4. State “hence, with c = … and n0 = …, the definition is satisfied.” Never end without both values.

Proof 1. Show 3n + 2 = O(n).

We need c and n0 with 3n + 2 ≤ c·n for all n ≥ n0.

For n ≥ 2 we have 2 ≤ n, so   3n + 2 ≤ 3n + n = 4n.

Hence with c = 4 and n0 = 2, 3n + 2 = O(n). ✓

Check at n = 2: 3(2) + 2 = 8 and 4(2) = 8. Equality holds, so n0 = 2 is exactly right; n0 = 1 would fail, since 5 > 4.

Proof 2. Show 3n + 3 = O(n).

For n ≥ 3 we have 3 ≤ n, so 3n + 3 ≤ 3n + n = 4n.

c = 4, n0 = 3. ✓   Check at n = 3: 12 ≤ 12.

Proof 3. Show 100n + 6 = O(n).

For n ≥ 6 we have 6 ≤ n, so 100n + 6 ≤ 100n + n = 101n.

c = 101, n0 = 6. ✓

The point of this one: the constant 100 is enormous, and the answer is still O(n). Big oh discards constant factors entirely.

Proof 4. Show 10n² + 4n + 2 = O(n²).

For n ≥ 2,   4n ≤ 2n²   and   2 ≤ n². Hence 10n² + 4n + 2 ≤ 10n² + 2n² + n² = 13n².

c = 13, n0 = 2. ✓

A tighter pair also works: for n ≥ 5, 4n + 2 ≤ n², giving c = 11, n0 = 5. Any valid pair earns full marks — there is no unique answer, and saying so is worth a line.

Proof 5. Show 3n + 2 = Ω(n).

We need c·n ≤ 3n + 2. Since 2 > 0, we have 3n ≤ 3n + 2 for every n ≥ 1.

c = 3, n0 = 1. ✓

Omega proofs are usually easier than big-oh proofs, because dropping a positive term is always legal.

Proof 6. Show 3n + 2 = Θ(n).

Combine Proofs 1 and 5. We need c1n ≤ 3n + 2 ≤ c2n.

Lower: 3n ≤ 3n + 2 for n ≥ 1, so c1 = 3.
Upper: 3n + 2 ≤ 4n for n ≥ 2, so c2 = 4.

Take n0 = max(1, 2) = 2. With c1 = 3, c2 = 4, n0 = 2, 3n + 2 = Θ(n). ✓

Note the max: the theta proof needs a single n0 that works for both halves, so always take the larger.

Proof 7 — the hard one. Show ½n² − 3n = Θ(n²).

We need c1n² ≤ ½n² − 3n ≤ c2n². Divide all three parts by n²:

c1 ≤ ½ − 3/n ≤ c2

Right-hand inequality: ½ − 3/n ≤ ½ always, so c2 = ½, valid for every n ≥ 1.

Left-hand inequality: we need ½ − 3/n ≥ c1 > 0, which requires n > 6. Choose n0 = 7: then ½ − 3/7 = 7/14 − 6/14 = 1/14. And since ½ − 3/n increases with n, the bound holds for every n ≥ 7.

With c1 = 1/14, c2 = 1/2 and n0 = 7, ½n² − 3n = Θ(n²). ✓

Why n0 cannot be smaller: at n = 6, ½ − 3/6 = 0, and c1 must be strictly positive. At n = 5 the function is negative. Dividing through by n² is the trick that makes this manageable — use it whenever the constants are fractional.

Proof 8. Show 6·2n + n² = O(2n).

We use the fact that n² ≤ 2n for all n ≥ 4 (check: n = 4 gives 16 ≤ 16; n = 5 gives 25 ≤ 32; and 2n outgrows n² from there on).

So for n ≥ 4:   6·2n + n² ≤ 6·2n + 2n = 7·2n.

c = 7, n0 = 4. ✓

Proof 9 — a disproof. Show that n² is NOT O(n).

Proof by contradiction. Suppose n² = O(n). Then there are constants c and n0 with

n² ≤ c·n   for all n ≥ n0

Dividing both sides by n (which is positive) gives n ≤ c for all n ≥ n0.

But c is a fixed constant and n is unbounded — take n = c + 1, which is ≥ n0 for large enough choice, and the inequality fails. Contradiction. Hence n² ≠ O(n). ∎

This is the template for every “show that f is not O(g)” question: assume it, divide out, and derive that an unbounded quantity is bounded by a constant.

Proof 10 — using the limit test. Classify n² against n³.

limn→∞ n²/n³ = lim 1/n = 0  ⇒  n² = o(n³), and therefore also n² = O(n³).

Conversely lim n³/n² = lim n = ∞  ⇒  n³ = ω(n²), and therefore also n³ = Ω(n²).

And lim (3n² + 5n)/n² = 3, a finite non-zero constant  ⇒  3n² + 5n = Θ(n²).

The limit test is the fastest route when the functions are not polynomials — but a question that says “prove using the definition” wants c and n0, so read the wording.

The line worth remembering

Polynomial time (nk for constant k) is “tractable”; exponential and factorial time is “intractable”. That distinction is the whole basis of Unit V's P vs NP discussion — and this table shows why: at n = 100, an n³ algorithm does a million steps while a 2n algorithm does more steps than there are atoms in the observable universe.

Two comparisons students get wrong

  • nk versus an (a > 1): the exponential always wins, for any fixed k, however large. n1000 = o(2n).
  • log n versus √n: the logarithm always wins (grows slower). Any polynomial of n, however small the exponent, eventually beats any power of log n.
  • 2n versus n!: the factorial wins. And n! < nn, since n! is a product of n terms each at most n.
  • The base of a logarithm is irrelevant. log2n and log10n differ only by the constant factor log210, so both are Θ(log n) — which is why the base is never written.

Properties of asymptotic notation

PropertyStatementHolds for
Reflexivef(n) = O(f(n)), and likewise for Ω and ΘO, Ω, Θ — not o or ω
TransitiveIf f = O(g) and g = O(h) then f = O(h)All five
Symmetricf = Θ(g) ⇔ g = Θ(f)Θ only
Transpose symmetricf = O(g) ⇔ g = Ω(f);   f = o(g) ⇔ g = ω(f)O with Ω, o with ω
Sum ruleIf f1 = O(g1) and f2 = O(g2), then f1 + f2 = O(max(g1, g2))—
Product ruleIf f1 = O(g1) and f2 = O(g2), then f1 · f2 = O(g1 · g2)—
Constant ruleIf f = O(g) then k·f = O(g) for any constant k > 0—

The sum rule is the one you use constantly: the complexity of two sequential blocks is the maximum of the two, not the sum. A loop of Θ(n) followed by a loop of Θ(n²) is Θ(n²).

Why big oh is not symmetric — a favourite objective question

n = O(n²) is true, but n² = O(n) is false. Big oh is a “≤” relation, and ≤ is not symmetric. Only Θ, which behaves like “=”, is symmetric.

Check yourself

1. The definition of f(n) = O(g(n)) requires that:

The third option is the definition of little oh — “for every c” rather than “there exists a c”. That quantifier is the entire difference between O and o.

2. For 3n + 2 = O(n), a valid pair is:

At n = 2, 3n + 2 = 8 and 4n = 8, so the inequality just holds. With c = 3 it fails for every n, since 3n + 2 > 3n always.

3. In proving ½n² − 3n = Θ(n²), the constants are:

Divide through by n² to get c₁ ≤ ½ − 3/n ≤ c₂. The upper bound is ½ always; the lower needs n > 6, and at n = 7 the value is 1/14.

4. Which ordering is correct?

Two traps: log n grows slower than √n, and n! grows faster than 2ⁿ. The full chain is 1, log log n, log n, √n, n, n log n, n², n³, 2ⁿ, 3ⁿ, n!, nⁿ.

5. Which property does big oh NOT satisfy?

n = O(n²) but n² ≠ O(n). Big oh is a ≤ relation; only Θ, which behaves like =, is symmetric.

6. A Θ(n) block followed by a Θ(n²) block has total complexity:

Sequential blocks take the maximum; nested blocks take the product. That single rule handles most of Lesson 3.

7. If lim f(n)/g(n) = 0, then:

Limit 0 → little oh; limit ∞ → little omega; a finite non-zero limit → theta. Little oh always implies big oh, since a strict bound is also a bound.

Recall without looking

Give the formal definitions of O, Ω and Θ.

f = O(g) if there exist positive c, n₀ with 0 ≤ f(n) ≤ c·g(n) for all n ≥ n₀ — an upper bound, used for the worst case. f = Ω(g) if 0 ≤ c·g(n) ≤ f(n) — a lower bound, used for the best case. f = Θ(g) if there exist c₁, c₂, n₀ with c₁g(n) ≤ f(n) ≤ c₂g(n) — a tight bound. And f = Θ(g) iff f = O(g) and f = Ω(g).

Distinguish O from o, and Ω from ω.

Big oh requires the bound for some constant c; little oh requires it for every c, making it a strictly loose bound. So 2n² = O(n²) but not o(n²), while 2n = o(n²). By the limit test: O gives a finite limit, o gives 0, Ω gives a limit above 0, ω gives ∞, and Θ gives a finite non-zero constant.

Prove 3n + 2 = O(n) and 3n + 2 = Θ(n).

For n ≥ 2, 2 ≤ n so 3n + 2 ≤ 4n: c = 4, n₀ = 2. For theta, also 3n ≤ 3n + 2 for n ≥ 1, so c₁ = 3, c₂ = 4, n₀ = max(1,2) = 2.

Prove that n² is not O(n).

Suppose it were: then n² ≤ cn for all n ≥ n₀, so dividing by n gives n ≤ c. But c is a fixed constant and n is unbounded, so choosing n = c + 1 breaks the inequality. Contradiction.

Write the growth-rate chain.

1 < log log n < log n < √n < n < n log n < n² < n³ < … < 2ⁿ < 3ⁿ < n! < nⁿ. Watch the two traps: log n is slower than √n, and n! is faster than 2ⁿ.

State the seven properties of asymptotic notation.

Reflexive (for O, Ω, Θ but not o or ω); transitive (all five); symmetric (Θ only); transpose symmetric (O with Ω, o with ω); sum rule — f₁ + f₂ = O(max(g₁, g₂)); product rule — f₁·f₂ = O(g₁·g₂); constant rule — k·f = O(g).

Why is asymptotic notation used at all?

It makes analysis machine independent by absorbing constants; it describes behaviour for large input, where efficiency matters; it allows algorithms to be compared and classified without implementing them; and it gives bounds and guarantees. It also separates tractable polynomial time from intractable exponential time, which is the basis of P vs NP.
