Complexity Analysis of Algorithms

The four rules for reading complexity off code, then twenty worked fragments — simple loops, dependent loops, multiplying and dividing counters, the harmonic-series case, the √n cases, and recursion.

Exam strategy

“Find the time complexity of the following code” is worth 2–5 marks and appears in every paper, often three times over. It is pure pattern recognition — there are only about eight distinct patterns, and they are all below. Learn to spot the counter's update rule first: i++ gives n, i = i*2 gives log n, i = i+i also gives log n, i*i ≤ n gives √n, and j = j+i inside an i-loop gives n log n. Everything else is those five combined.

The four rules

Everything reduces to these 1. Sequential statements → ADD, then take the MAXIMUM. A Θ(n) block followed by a Θ(n²) block is Θ(n²).
2. Nested loops → MULTIPLY. An n-loop containing an m-loop is Θ(nm).
3. If–else → take the MAXIMUM of the two branches (for worst-case analysis).
4. A loop's cost = (number of iterations) × (cost of the body).

So the entire task is: for each loop, how many times does it run? That question has a small number of standard answers.

Group A — single loops

1. The basic loop

for (i = 0; i < n; i++)
   statement;

The statement executes n times.   T(n) = Θ(n)

2. Constant step

for (i = 0; i < n; i = i + 5)
   statement;

Runs n/5 times. Constants are discarded.   T(n) = Θ(n)

The trap: students often answer Θ(n/5). Θ(n/5) = Θ(n) — write the simplified form.

3. Multiplying counter — the logarithm

for (i = 1; i <= n; i = i * 2)
   statement;

i takes the values 1, 2, 4, 8, …, 2k. The loop stops when 2k > n, that is when k > log2n.

T(n) = Θ(log2 n) = Θ(log n)

With i = i * 3 it is log3n — still Θ(log n), since the base is only a constant factor.

4. Dividing counter

for (i = n; i >= 1; i = i / 2)
   statement;

i takes n, n/2, n/4, …, 1 — the same sequence read backwards.   T(n) = Θ(log n)

5. The √n condition

for (i = 1; i * i <= n; i++)
   statement;

The loop continues while i² ≤ n, i.e. while i ≤ √n.   T(n) = Θ(√n)

This is the primality-test-by-trial-division pattern.

6. The accumulating counter — also √n

p = 0;
for (i = 1; p <= n; i++)
   p = p + i;

After k iterations, p = 1 + 2 + … + k = k(k+1)/2. The loop stops when p > n, so

k(k+1)/2 > n  ⇒  k² ≈ 2n  ⇒  k ≈ √(2n)

T(n) = Θ(√n)

Sanity check with n = 50: k(k+1)/2 > 50 first at k = 10, since 10·11/2 = 55. And √(2·50) = 10. Exact.

7. Squaring counter — log log n

for (i = 2; i <= n; i = i * i)
   statement;

i takes 2, 4, 16, 256, … that is 21, 22, 24, 28, …, 22k. It stops when 22k > n, so 2k > log n, so k > log log n.

T(n) = Θ(log log n)

Sanity check with n = 65536: i = 2, 4, 16, 256, 65536 — five iterations. log log 65536 = log 16 = 4. Correct to within the constant.

Group B — nested loops

8. Independent nesting

for (i = 0; i < n; i++)
   for (j = 0; j < n; j++)
     statement;

n × n.   T(n) = Θ(n²) — the matrix-addition pattern.

9. Dependent nesting — the triangle

for (i = 0; i < n; i++)
   for (j = 0; j < i; j++)
     statement;

The inner loop runs 0, 1, 2, …, n−1 times, so the total is

0 + 1 + 2 + … + (n−1) = n(n−1)/2 = (n² − n)/2

T(n) = Θ(n²) — half of the previous one, but the same order. This is the bubble-sort and selection-sort pattern.

10. Nested log — n log n

for (i = 0; i < n; i++)
   for (j = 1; j < n; j = j * 2)
     statement;

Outer n, inner log n, independent.   T(n) = Θ(n log n)

11. Two logs nested — log² n

for (i = 1; i < n; i = i * 2)
   for (j = 1; j < n; j = j * 2)
     statement;

T(n) = Θ(log n × log n) = Θ(log² n)

12. The harmonic case — the one that catches people

for (i = 1; i <= n; i++)
   for (j = 1; j <= n; j = j + i)
     statement;

The inner loop steps by i, so for a given i it runs about n/i times. The total is

n/1 + n/2 + n/3 + … + n/n = n · (1 + ½ + ⅓ + … + 1/n) = n · Hn

and the harmonic number Hn ≈ ln n = Θ(log n). Therefore

T(n) = Θ(n log n)

The trap: it looks like a double loop over n, so the instinctive answer is Θ(n²) — and that is wrong. Whenever the inner step size depends on the outer counter, expect a harmonic series and an answer of n log n.

13. Triple nesting

for (i = 0; i < n; i++)
   for (j = 0; j < n; j++)
     for (k = 0; k < n; k++)
       statement;

T(n) = Θ(n³) — the matrix-multiplication and Floyd–Warshall pattern.

14. Dependent triple nesting

for (i = 1; i <= n; i++)
   for (j = 1; j <= i; j++)
     for (k = 1; k <= j; k++)
       statement;

The statement runs once for each triple with 1 ≤ k ≤ j ≤ i ≤ n. The number of such triples is

C(n + 2, 3) = n(n+1)(n+2)/6

T(n) = Θ(n³) — one sixth of the independent version, same order.

Sanity check with n = 3: 3·4·5/6 = 10. Enumerating: i=1 gives 1 triple, i=2 gives 3, i=3 gives 6 — total 10. ✓

Group C — while loops, sequential blocks and conditionals

15. Halving while loop

while (n > 1)
   n = n / 2;

T(n) = Θ(log n) — the binary-search pattern.

16. Sequential blocks — take the maximum

for (i = 0; i < n; i++)        /* block A */
   statement;

for (i = 0; i < n; i++)        /* block B */
   for (j = 0; j < n; j++)
     statement;

T(n) = Θ(n) + Θ(n²) = Θ(max(n, n²)) = Θ(n²)

17. If–else — take the worse branch

if (condition)
   for (i = 0; i < n; i++) statement;     /* Θ(n) */
else
   for (i = 0; i < n; i++)
     for (j = 0; j < n; j++) statement; /* Θ(n²) */

Worst case T(n) = Θ(n²); best case Θ(n). If the question just says “find the complexity”, give the worst case and say so.

18. Inner loop independent of the outer counter — a common trick question

for (i = 0; i < n; i++)
   for (j = 0; j < 100; j++)
     statement;

The inner loop runs a constant 100 times, whatever n is. Total = 100n.   T(n) = Θ(n), not Θ(n²).

Always check whether the inner bound actually involves n.

Group D — recursive fragments

19. Linear recursion

int fact(int n) {
   if (n <= 1) return 1;
   return n * fact(n - 1);
}

Recurrence: T(n) = T(n−1) + 1, with T(1) = 1.

Expanding: T(n) = T(n−2) + 2 = T(n−3) + 3 = … = T(1) + (n−1) = n.

T(n) = Θ(n) time, and Θ(n) space for the recursion stack.

20. Binary recursion — Tower of Hanoi

void hanoi(int n, char a, char b, char c) {
   if (n == 0) return;
   hanoi(n-1, a, c, b);
   move(a, c);
   hanoi(n-1, b, a, c);
}

Recurrence: T(n) = 2T(n−1) + 1, with T(0) = 0.

Expanding: T(n) = 2(2T(n−2) + 1) + 1 = 4T(n−2) + 3 = 8T(n−3) + 7 = … = 2nT(0) + (2n − 1)

T(n) = 2n − 1 = Θ(2n) — the exact number of moves, which is why the question is a favourite.

Sanity check: n = 3 gives 7 moves, which anyone can verify by hand. Space is only Θ(n), the depth of the recursion.

21. Divide and conquer — binary search

bsearch(a, low, high, x) {
   if (low > high) return -1;
   mid = (low + high) / 2;
   if (a[mid] == x) return mid;
   if (a[mid] > x) return bsearch(a, low, mid-1, x);
   return bsearch(a, mid+1, high, x);
}

Recurrence: T(n) = T(n/2) + 1.   Only one of the two halves is searched.

T(n) = Θ(log n) &mdash ; solved in full in Lessons 4 and 5.

Check yourself

1. for (i = 1; i <= n; i = i * 3) statement; has complexity:

It is log₃n, and the base is only a constant factor, so it is Θ(log n). Multiplying the counter always gives a logarithm.

2. for (i = 1; i <= n; i++) for (j = 1; j <= n; j = j + i) statement; is:

The inner loop runs n/i times, so the total is n(1 + ½ + ⅓ + … + 1/n) = n·Hₙ ≈ n ln n. Whenever the inner step depends on the outer counter, look for the harmonic series.

3. p = 0; for (i = 1; p <= n; i++) p = p + i; runs how many times?

After k iterations p = k(k+1)/2, which exceeds n when k ≈ √(2n). At n = 50 the loop stops at k = 10, and √100 = 10.

4. for (i = 0; i < n; i++) for (j = 0; j < 100; j++) statement; is:

The inner bound does not involve n, so it contributes a constant factor of 100. Always check whether the inner limit actually depends on n.

5. for (i = 2; i <= n; i = i * i) statement; is:

i takes 2, 4, 16, 256, … = 2^(2^k), so the loop ends when 2^k > log n, that is when k > log log n. At n = 65536 there are five iterations.

6. The Tower of Hanoi recurrence T(n) = 2T(n−1) + 1 gives exactly:

Expanding gives 2ⁿT(0) + (2ⁿ − 1), and T(0) = 0. Check: n = 3 needs 7 moves, which you can verify by hand.

7. for (i = 1; i <= n; i++) for (j = 1; j <= i; j++) for (k = 1; k <= j; k++) is:

It counts triples with 1 ≤ k ≤ j ≤ i ≤ n, which is C(n+2, 3). At n = 3 that is 10, matching a hand count of 1 + 3 + 6.

Recall without looking

State the four rules for reading complexity off code.

Sequential statements: add, then take the maximum. Nested loops: multiply. If–else: take the maximum branch for the worst case. A loop costs the number of iterations times the cost of the body.

Give the complexity for each counter update rule.

i = i + 1 or i + k gives Θ(n); i = i*2 or i/2 gives Θ(log n); i = i*i gives Θ(log log n); condition i*i ≤ n gives Θ(√n); p = p + i with condition p ≤ n gives Θ(√n).

Why is for i≤n { for j≤n step i } n log n and not n²?

The inner loop steps by i, so it runs about n/i times. Summing n/i for i = 1 to n gives n times the harmonic number Hₙ, and Hₙ ≈ ln n. So the total is Θ(n log n). Whenever the inner step size depends on the outer counter, expect a harmonic series.

How many iterations does p = 0; for (i = 1; p ≤ n; i++) p += i; perform?

After k iterations p = k(k+1)/2, so the loop ends when k(k+1)/2 > n, giving k ≈ √(2n) and complexity Θ(√n).

Give the eight standard patterns with their complexities.

Single loop Θ(n); multiplying or dividing counter Θ(log n); i*i ≤ n gives Θ(√n); i = i*i gives Θ(log log n); independent double nesting Θ(n²); dependent nesting j < i also Θ(n²) but n(n−1)/2; outer n with inner log n gives Θ(n log n); inner step depending on the outer counter gives Θ(n log n).

Solve T(n) = T(n−1) + 1 and T(n) = 2T(n−1) + 1 by expansion.

The first gives T(1) + (n−1) = Θ(n) — the factorial pattern. The second gives 2ⁿT(0) + (2ⁿ − 1) = 2ⁿ − 1 = Θ(2ⁿ) — Tower of Hanoi, whose space is only Θ(n).
