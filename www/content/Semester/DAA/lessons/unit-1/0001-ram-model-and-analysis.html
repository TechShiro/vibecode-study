What an algorithm is

Definition An algorithm is a finite sequence of unambiguous instructions that, for a given set of inputs, produces the required output in a finite amount of time.

Equivalently: a well-defined computational procedure that takes some value or set of values as input and produces some value or set of values as output.

The five characteristics — a guaranteed 5-mark list

#PropertyMeaning
1InputZero or more quantities are externally supplied. Zero is allowed — an algorithm that prints the first hundred primes needs no input
2OutputAt least one quantity is produced. An algorithm producing nothing is useless by definition
3DefinitenessEach instruction is clear and unambiguous — exactly one interpretation
4FinitenessThe algorithm terminates after a finite number of steps for every input
5EffectivenessEvery instruction must be basic enough to be carried out, in principle, by a person with pencil and paper in finite time
The distinction examiners like

A program is not an algorithm. A program is an algorithm expressed in a programming language, and it need not satisfy finiteness — an operating system is a program designed to run for ever, which is why it is not an algorithm.

The RAM model of computation

Before you can say “this algorithm takes n log n time”, you must say what a unit of time is. Machines differ enormously, so analysis is done against an idealised machine — the Random Access Machine.

The four assumptions of the RAM model 1. A single processor executing instructions sequentially, one at a time. No concurrency, no parallelism.
2. Each simple operation — arithmetic (+, −, ×, ÷), comparison, assignment, a logical operation, a function call and return — takes exactly one time step.
3. Memory is unlimited, and any memory access takes one time step, regardless of address. There is no memory hierarchy — no cache, no disk, no paging.
4. Each word of memory holds one integer or one real number, and its size is enough for the data in use.

Why use such an unrealistic model?

AdvantageExplanation
Machine independenceThe running time becomes a property of the algorithm, not of a particular CPU, compiler or operating system
SimplicityAnalysis reduces to counting steps, which is arithmetic and not engineering
It predicts well in practiceDespite ignoring caches and pipelines, the model's predictions match real behaviour closely enough to rank algorithms correctly — which is all we need

The honest limitation, worth one line: the model assumes every memory access costs the same. On a real machine a cache hit is roughly a hundred times faster than a main-memory access, so two algorithms with identical RAM-model complexity can differ substantially in practice. The model ranks algorithms correctly; it does not predict wall-clock time.

Counting primitive operations

The frequency count method: for each statement, write down its cost per execution and how many times it executes; the total is the sum of the products. This is the technique behind every complexity question in Lesson 3.

Worked example 1 — sum of an array.
StatementCostTimesTotal
sum = 0;111
for (i = 0; i < n; i++)1n + 1n + 1
  sum = sum + a[i];1nn
return sum;111
Total2n + 3

T(n) = 2n + 3 = Θ(n).

Note the n + 1: a loop condition is tested one extra time — the test that fails and ends the loop. Forgetting that single extra test is the most common slip in frequency counting, and although it does not change the asymptotic answer, examiners look for it.

Worked example 2 — matrix addition.
StatementTimes
for (i = 0; i < n; i++)n + 1
  for (j = 0; j < n; j++)n(n + 1)
    c[i][j] = a[i][j] + b[i][j];n²
Total2n² + 2n + 1

T(n) = 2n² + 2n + 1 = Θ(n²).

Why the inner loop runs n(n+1) times: for each of the n values of i, the inner condition is tested n + 1 times.

The shortcut you will actually use

Once the method is understood, stop counting exactly and count only the dominant statement — the one inside the innermost loop. Matrix addition: one statement, run n² times, so Θ(n²). Matrix multiplication: one statement, run n³ times, so Θ(n³). Show the full table only when the question says “count the number of primitive operations” or “find the frequency count.”

Best, worst and average case

CaseMeaningNotation usually usedIs it useful?
Best caseThe minimum number of steps over all inputs of size nΩ (big omega)Rarely — it is a guarantee about the luckiest input, which tells you almost nothing
Worst caseThe maximum number of steps over all inputs of size nO (big oh)The most useful. It is a guarantee: the algorithm never takes longer. It also occurs often in practice
Average caseThe expected number of steps, over some assumed probability distribution of inputsΘ (theta)Most realistic, but hardest to compute, and it depends on an assumption about the input distribution that may be wrong
The standard example — linear search for a key x in an array of n elements.
CaseWhenComparisonsComplexity
Bestx is the first element1Ω(1)
Worstx is the last element, or is absentnO(n)
Averagex is equally likely to be at any of the n positions(n + 1) / 2Θ(n)

The average-case derivation — write this out, it is worth marks:

If x is present and equally likely at each position, the probability of each position is 1/n and finding it at position i costs i comparisons. So

E = Σi=1..n (1/n) · i = (1/n) · n(n+1)/2 = (n + 1) / 2

Sanity check: the average must lie between the best (1) and the worst (n). For n = 10 it is 5.5, which does. And note that the average case is still Θ(n) — halving the constant does not change the order.

The counter-intuitive fact worth quoting

Quick sort's worst case is on an already sorted array. With the first or last element as pivot, every partition splits n elements into 0 and n−1, giving T(n) = T(n−1) + n = Θ(n²). It is the standard “explain quick sort's worst case” answer, and Lesson 13 works the recurrence in full.

Space complexity

Space complexity = fixed part + variable part Fixed part — independent of the input size: the instruction space (the compiled code), simple variables, constants, and fixed-size component variables.

Variable part — depends on the input size: dynamically allocated space, the space for the data itself, and the recursion stack.

S(P) = c + SP(n), where c is the fixed part.

Auxiliary space is the extra space an algorithm needs beyond the input. It is the number usually quoted, and the one that matters:

AlgorithmAuxiliary spaceIn place?
Merge sortO(n) — the temporary merge arrayNo
Quick sortO(log n) average, O(n) worst — the recursion stackYes (by the usual convention)
Heap sortO(1)Yes
Counting sortO(k), for a key range of kNo
Insertion / bubble / selection sortO(1)Yes

A priori and a posteriori analysis

 A priori analysisA posteriori analysis

Depends onNothing but the algorithmThe machine, compiler, language and OS
UsesAsymptotic notationA clock and a profiler

This course is about a priori analysis. That is precisely why the RAM model exists — it lets you say something true about an algorithm without ever running it.

Check yourself

1. Which characteristic does an operating system violate, so that it is a program but not an algorithm?

An OS is designed never to terminate. The five characteristics are input (zero or more), output (at least one), definiteness, finiteness and effectiveness.

2. In the RAM model, accessing a[1000000] compared with a[0] takes:

There is no memory hierarchy in the model. That is its main departure from reality — but it still ranks algorithms correctly, which is what the model is for.

3. The frequency count for for (i = 0; i < n; i++) is:

The condition is tested once more than the body executes — the final test is the one that fails and ends the loop. It does not change the order, but examiners look for it.

4. The average number of comparisons in a successful linear search is:

Σ(1/n)·i for i = 1 to n = (1/n)·n(n+1)/2. It must lie between 1 and n, and it does — but it is still Θ(n).

5. Quick sort's worst case occurs when the input array is:

With the first or last element as pivot, sorted input splits n into 0 and n−1, giving T(n) = T(n−1) + n = Θ(n²). Randomised pivot selection is the standard remedy.

6. The auxiliary space of merge sort and heap sort respectively is:

Merge sort needs a temporary array to merge into, which is why it is not in place. Heap sort sorts within the array itself.

7. A priori analysis differs from a posteriori analysis in that it:

A priori analysis yields a function of the input size, expressed asymptotically. A posteriori analysis profiles a real program on a real machine.

Recall without looking

Define an algorithm and list its five characteristics.

A finite sequence of unambiguous instructions that, for a given set of inputs, produces the required output in finite time. Characteristics: input (zero or more externally supplied quantities), output (at least one), definiteness (each instruction clear and unambiguous), finiteness (terminates in a finite number of steps), effectiveness (each instruction basic enough to be done with pencil and paper).

State the four assumptions of the RAM model and why it is used.

A single processor executing instructions sequentially; each simple operation takes exactly one time step; memory is unlimited and every access costs one step, with no memory hierarchy; each word holds one number. It is used for machine independence, for simplicity — analysis becomes step counting — and because it predicts relative performance well enough to rank algorithms correctly.

Give the frequency count for array summation and for matrix addition.

Array sum: 1 + (n+1) + n + 1 = 2n + 3 = Θ(n). Matrix addition: (n+1) + n(n+1) + n² = 2n² + 2n + 1 = Θ(n²). The loop condition always executes one more time than the body.

Define best, worst and average case, and say which is most useful.

Best is the minimum steps over inputs of size n, worst the maximum, average the expected number over an assumed input distribution. Worst case is the most useful, because it is a guarantee the algorithm never exceeds and it often occurs in practice; average case is the most realistic but the hardest to compute and depends on a distributional assumption.

Give the three cases for linear search, with the average-case derivation.

Best 1 comparison (first element), worst n (last or absent), average (n+1)/2. Derivation: with probability 1/n the key is at position i costing i comparisons, so E = (1/n)·n(n+1)/2 = (n+1)/2. The average is still Θ(n).

Why is quick sort's worst case an already sorted array?

With the first or last element as pivot, every partition of sorted input splits n elements into 0 and n−1, so T(n) = T(n−1) + n = Θ(n²). Merge sort and heap sort have no such case, because their splits are always balanced.

Define space complexity and give the auxiliary space of the main sorts.

Space complexity is a fixed part — code, constants, simple variables — plus a variable part depending on input size, including the recursion stack. Auxiliary space: merge sort O(n), quick sort O(log n) average and O(n) worst for the stack, heap sort O(1), counting sort O(k), insertion and bubble and selection sort O(1).

Contrast a priori with a posteriori analysis.

A priori is theoretical, done before implementation, machine-independent, and yields an approximate function of the input size expressed asymptotically. A posteriori is done after implementation, gives exact times and memory, and depends on the machine, compiler, language and OS. This course is about a priori analysis, which is why the RAM model exists.
