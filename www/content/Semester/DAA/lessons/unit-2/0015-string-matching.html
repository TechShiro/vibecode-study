The problem

Statement Given a text T of length n and a pattern P of length m, both over an alphabet Σ, find all shifts s (0 ≤ s ≤ n − m) at which P occurs in T, that is, at which T[s+1 … s+m] = P[1 … m].

1. The naive (brute-force) algorithm

The algorithm
NAIVE-STRING-MATCHER(T, P)
   for s = 0 to n − m
     if P[1 … m] == T[s+1 … s+m]
       print "pattern occurs with shift" s
Slide the pattern one position at a time and compare all m characters at each of the n − m + 1 positions.

Why it is wasteful — the observation both better algorithms are built on

The naive algorithm throws away everything it learnt. If P = “ABABC” and the first four characters matched before the fifth failed, we know the text contains “ABAB” there — so we know sliding by one must fail, and by two might work. KMP exploits what matched; Boyer–Moore exploits what mismatched. That single sentence frames the whole lesson.

2. The Knuth–Morris–Pratt algorithm

The idea Preprocess the pattern to build the LPS array — Longest Proper Prefix which is also a Suffix, also called the failure function π.

LPS[i] = the length of the longest proper prefix of P[0 … i] that is also a suffix of P[0 … i].

“Proper” means it cannot be the whole string.

On a mismatch after j characters have matched, do not move the text pointer at all — instead set j = LPS[j − 1] and try again.

Building the LPS array

The rule
len = 0;   LPS[0] = 0;   i = 1;
while (i < m) {
   if (P[i] == P[len]) { len++; LPS[i] = len; i++; }
   else if (len != 0) { len = LPS[len − 1]; }  /* do NOT increment i */
   else { LPS[i] = 0; i++; }
}

Two sanity rules: LPS[0] is always 0, and LPS[i] can never exceed i (the prefix must be proper). LPS values can also only increase by at most 1 at a time, though they may drop by more.

The property to state: the text pointer i never moves backwards. Every character of T is examined at most once for advancing, so the search is Θ(n), and with Θ(m) preprocessing the total is Θ(n + m) — in every case, best and worst alike.

3. The Boyer–Moore algorithm

The two ideas 1. Compare from RIGHT to LEFT within the pattern, though the pattern still slides left to right along the text.
2. On a mismatch, shift by the MAXIMUM of two rules: the bad-character rule and the good-suffix rule.

The bad-character rule

The rule Let the mismatch occur at pattern position j against text character c.

If c occurs in the pattern: shift so that the rightmost occurrence of c in P[0 … j−1] aligns with that text position.
    shift = max(1, j − last[c])

If c does not occur in the pattern at all: the pattern can be moved entirely past c.
    shift = j + 1

Count the work: Boyer–Moore made 5 comparisons in total. The naive algorithm would have made far more, and would have tested every shift from 0 to 5. Shifting by 2 each time means some text characters were never examined at all — which is how the algorithm becomes sublinear.

The good-suffix rule

The rule — three cases Suppose the characters P[j+1 … m−1] matched (call this the good suffix) before P[j] mismatched.

Case 1. The good suffix occurs elsewhere in P, preceded by a different character → shift so that that other occurrence aligns with the text.
Case 2. The good suffix does not occur again, but a suffix of the good suffix is a prefix of P → shift so that that prefix aligns.
Case 3. Neither → shift the pattern past the good suffix entirely, by m.
How to describe the two rules in one line each

Bad character: “align the mismatched text character with its rightmost occurrence in the pattern, or skip past it entirely if it does not occur.”

Good suffix: “align the part that did match with another occurrence of it in the pattern, or with a prefix of the pattern.”

Boyer–Moore takes the LARGER of the two shifts — both are safe, so taking the bigger can never miss a match.

The two facts worth stating at the end of a comparison answer

1. Boyer–Moore is sublinear in the best and average case — it can skip up to m characters at a time, so it may never even look at most of the text. It is the algorithm used in real text editors and in grep.

2. But its worst case is O(nm), no better than naive — for example T = “AAAA…A” with P = “AAAA”. KMP is the one with the guarantee. The Boyer–Moore–Galil variant repairs the worst case to O(n).

Recall without looking

State the string-matching problem and the naive algorithm's complexity.

Given a text of length n and a pattern of length m, find all shifts at which the pattern occurs. The naive algorithm slides the pattern one position at a time and compares all m characters, costing Θ(n) at best and Θ((n − m + 1)m) = Θ(nm) at worst — for example T = “AAA…A” with P = “AAAB”.

What do KMP and Boyer–Moore each exploit?

The naive algorithm discards everything it learnt from a partial match. KMP exploits what matched — the prefix-suffix structure of the pattern. Boyer–Moore exploits what mismatched, through the bad-character rule, as well as what matched, through the good-suffix rule.

Define the LPS array and give the rule for building it.

LPS[i] is the length of the longest proper prefix of P[0…i] that is also a suffix of it. Build it with len = 0 and LPS[0] = 0; if P[i] equals P[len], increment len, set LPS[i] = len and advance i; otherwise if len is non-zero set len = LPS[len−1] without advancing i; otherwise set LPS[i] = 0 and advance i.

Give the LPS array for “ABABCABAB” and verify the last entry.

[0, 0, 1, 2, 0, 1, 2, 3, 4]. The last entry is 4 because the longest proper prefix of the whole pattern that is also a suffix is “ABAB”.

Describe the KMP search and its complexity.

Compare left to right; on a mismatch after j matches, set j = LPS[j−1] without moving the text pointer, and if j is already 0 advance the text pointer instead. The text pointer never backtracks, so the search is Θ(n) and the total, including Θ(m) preprocessing, is Θ(n + m) in every case.

State Boyer–Moore's two rules.

Bad character: on a mismatch at pattern position j against text character c, shift by max(1, j − last[c]) so the rightmost occurrence of c in the pattern aligns; if c does not occur in the pattern at all, shift by j + 1 and skip past it. Good suffix: align the part that already matched with another occurrence of it in the pattern, or with a prefix of the pattern, or shift past it entirely. Take the larger of the two shifts.

Compare naive, KMP and Boyer–Moore.

Naive: no preprocessing, O(nm) worst, O(1) space. KMP: Θ(m) preprocessing, Θ(n + m) in every case, O(m) space, never backtracks — use it when a worst-case guarantee is needed. Boyer–Moore: Θ(m + |Σ|) preprocessing, sublinear Ω(n/m) in the best case and fastest in practice, but O(nm) worst — used by text editors and grep, and repaired to O(n) by the Boyer–Moore–Galil variant.
