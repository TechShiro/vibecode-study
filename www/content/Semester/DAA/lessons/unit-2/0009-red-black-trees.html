Red–Black Trees

The five properties, the height bound and why it holds, the three insertion cases with a seven-key worked trace, the double-black deletion cases, and the AVL comparison.

Exam strategy

Two questions. “State the properties of a red–black tree and insert the following keys” — write the five properties verbatim first (they are worth marks on their own), then trace the insertion, naming the case at every fix-up. “Compare AVL and red–black trees” — the table at the end. Learn the height bound h ≤ 2 log2(n+1) and the one-line reason for it. Deletion is examined far less often than insertion; know the vocabulary and the four cases, but drill insertion.

The five properties — learn these verbatim

A red–black tree is a BST in which every node carries one extra bit of colour, and 1. Every node is either RED or BLACK.
2. The root is BLACK.
3. Every leaf (the NIL sentinel) is BLACK.
4. If a node is RED, then both its children are BLACK — equivalently, no two red nodes may be adjacent.
5. For every node, all simple paths from that node to its descendant leaves contain the same number of BLACK nodes.
TermMeaning
Black-height, bh(x)The number of black nodes on any path from x down to a leaf, not counting x itself but counting the NIL leaf. Property 5 says this is well defined
NIL / sentinelA single shared black “external node” standing in for every null pointer. It simplifies the code and makes property 3 easy to state
Internal nodeA node carrying an actual key — as opposed to a NIL leaf
The one-line reason it works — say this before any proof

Property 5 forces every root-to-leaf path to contain the same number of black nodes; property 4 forbids two reds in a row, so no path can be more than twice as long as any other. A tree in which no path exceeds twice the shortest is approximately balanced, which is all we need for O(log n).

The height bound A red–black tree with n internal nodes has height

h ≤ 2 log2(n + 1)

Sketch: a subtree rooted at x contains at least 2bh(x) − 1 internal nodes. Since at least half the nodes on any root-to-leaf path are black, bh(root) ≥ h/2. Hence n ≥ 2h/2 − 1, and rearranging gives the bound.

Therefore search, insert and delete are all O(log n) in the worst case — the same guarantee as AVL, with a looser constant.

Insertion — the algorithm

The procedure Step 1. Insert the key exactly as in an ordinary BST.
Step 2. Colour the new node RED.
Step 3. If a violation has occurred, fix it up and colour the root black.
Why the new node is coloured red

Colouring it black would add a black node to one path only, breaking property 5 — the hardest property to repair. Colouring it red can only break property 4, the no-two-reds rule, and only if its parent happens to be red. Red is the cheaper mistake. That sentence earns a mark.

The fix-up — three cases, decided by the UNCLE's colour Let z = the new red node, p = its parent, g = its grandparent, u = its uncle (g's other child).
A violation exists only when p is RED.

CASE 1 — the uncle u is RED.
  → RECOLOUR: make p and u black, make g red. Then move z up to g and repeat.
  No rotation. The violation may move up the tree.

CASE 2 — the uncle u is BLACK, and z is an “inner” child (z is a right child of a left parent, or a left child of a right parent — a triangle).
  → Rotate at p in the direction that turns the triangle into a line, then continue into Case 3.

CASE 3 — the uncle u is BLACK, and z is an “outer” child (a line).
  → Rotate at g in the opposite direction, then recolour: p becomes black, g becomes red. Done — no further propagation.

Finally: always colour the root BLACK.
The two-word summary

Red uncle → recolour. Black uncle → rotate. That is the entire decision, and it is the first thing to write in the answer.

Deletion — the shape of it

Deletion is harder, and is examined less often. Know the structure and the vocabulary.

The procedure Step 1. Delete as in an ordinary BST (Lesson 7's three cases). Let y be the node actually removed and x the node that takes its place.
Step 2. If y was RED, nothing is broken — removing a red node changes no black-height and creates no adjacent reds. Stop.
Step 3. If y was BLACK, its path has lost a black node, breaking property 5. Give x an extra unit of “blackness” — it becomes double black — and push that extra blackness up the tree until it can be discharged.
CaseSibling w of the double-black node xAction
1w is REDRecolour w black and the parent red, then rotate at the parent. This converts the situation into Case 2, 3 or 4
2w is black and both of w's children are blackRecolour w red and move the double-black problem up to the parent. Repeat
3w is black, w's near child is red and its far child is blackRecolour and rotate at w, converting it into Case 4
4w is black and w's far child is redRecolour and rotate at the parent. The extra black is discharged — done.

Only Case 2 loops, and it moves the problem strictly upward, so deletion performs at most three rotations and O(log n) recolourings.

The line to close a comparison answer with

Both guarantee O(log n) in the worst case. Red–black trees win in practice because a bounded number of rotations matters more than a slightly shorter tree — which is why every standard library uses them rather than AVL.

Check yourself

1. Which is NOT a red–black tree property?

There is no constraint on the children of a black node — a black node may have black children, red children, or none. The constraint runs the other way.

2. A newly inserted node is coloured red because:

Red can only break the no-two-adjacent-reds rule, and only when the parent is red. Black would add a black node to one path only, breaking property 5 immediately.

3. During insertion fix-up, when the uncle is RED you:

Red uncle means recolour; black uncle means rotate. Case 1 is the only case that propagates the problem upward.

4. The height of a red–black tree with n internal nodes is at most:

1.44 log₂(n+2) is the AVL bound. The factor 2 here comes from properties 4 and 5 together: no path can exceed twice the length of any other.

5. Inserting 10, 20, 30, 15, 25, 5, 1 leaves the root as:

Inserting 30 triggers Case 3, which left-rotates at 10 and makes 20 the root. Nothing afterwards displaces it, and the root is always coloured black at the end.

6. A red–black deletion performs at most how many rotations?

Only Case 2 loops, and it recolours rather than rotates. AVL deletion, by contrast, may need O(log n) rotations — which is the main practical reason libraries prefer red–black trees.

7. Java's TreeMap and the C++ STL map are implemented as:

A bounded number of rotations per update matters more in practice than a slightly shorter tree. The Linux kernel's CFS scheduler uses them too.

Recall without looking

State the five properties of a red–black tree.

Every node is red or black; the root is black; every leaf (NIL) is black; if a node is red both its children are black, so no two reds are adjacent; and for every node, all simple paths from it to descendant leaves contain the same number of black nodes.

Define black-height and give the height bound with its reason.

The black-height of x is the number of black nodes on any path from x down to a leaf, excluding x but including the NIL leaf. The height satisfies h ≤ 2 log₂(n + 1), because property 5 makes all paths contain the same number of blacks and property 4 stops any path having more than that many reds — so no path exceeds twice the length of any other.

Give the insertion procedure and say why the new node is red.

Insert as in a BST, colour the new node red, fix up any violation, and finally colour the root black. Red is chosen because colouring the node black would add a black node to a single path and break property 5, which is the hardest property to repair; red can only break the no-two-reds rule.

Give the three insertion fix-up cases.

Case 1, uncle red: recolour parent and uncle black and grandparent red, then move up to the grandparent and repeat — no rotation. Case 2, uncle black and the node is an inner child forming a triangle: rotate at the parent to turn it into a line, then continue into Case 3. Case 3, uncle black and the node is an outer child forming a line: rotate at the grandparent and recolour parent black and grandparent red — done. Red uncle means recolour, black uncle means rotate.

Describe red–black deletion.

Delete as in a BST. If the removed node was red nothing breaks. If it was black, its path has lost a black node, so the replacing node becomes double black and that extra blackness is pushed up. Four cases turn on the sibling: red sibling, rotate to convert; black sibling with two black children, recolour it red and move up — the only looping case; black sibling with a red near child, rotate at the sibling; black sibling with a red far child, rotate at the parent and finish. At most three rotations.

Compare AVL with red–black on six points.

Balance: strict, 1.44 log n, versus loose, 2 log(n+1). Storage: a height or balance factor versus a single colour bit. Search: AVL faster. Update: red–black faster. Rotations per insert: 1 versus 2; per delete: O(log n) versus at most 3. Use AVL when lookups dominate; red–black is what Java's TreeMap, the C++ STL map and the Linux kernel actually use.
