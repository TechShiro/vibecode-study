Binary Search Trees

Exam strategy

Three question shapes, all mechanical. “Construct a BST from the following keys and give its traversals” — draw the tree neatly, then read off all three traversals; the inorder must come out sorted, which is your free self-check. “Delete key X and redraw” — the three cases, and the two-child case is the one that gets marked. “Construct the tree from the given inorder and preorder” — a standard 5-marker. The BST property

Definition A binary search tree is a binary tree in which, for every node x:

every key in the left subtree of x is < key(x), and
every key in the right subtree of x is > key(x).

The property is recursive — it must hold at every node, not merely at the root.
The consequence that everything follows from

An inorder traversal of a BST visits the keys in sorted order. That single fact is the definition of “search tree”, it is the check you run on every answer, and it is why an inorder traversal costs Θ(n) and gives you a sorted array for free.

Construction — the worked example

Q. Construct a BST by inserting, in this order: 45, 15, 79, 90, 10, 55, 12, 20, 50.

Rule: start at the root; go left if the new key is smaller, right if larger; insert as a leaf where you fall off the tree. The first key becomes the root.

The three traversals

The definitions — the position of the ROOT names the traversal Inorder   = Left, Root, Right   → gives sorted order in a BST
Preorder  = Root, Left, Right   → the root comes first; used to copy a tree
Postorder = Left, Right, Root   → the root comes last; used to delete a tree
The three traversals of the tree above

Inorder:   10, 12, 15, 20, 45, 50, 55, 79, 90

Preorder:   45, 15, 10, 12, 20, 79, 55, 50, 90

Postorder:   12, 10, 20, 15, 50, 55, 90, 79, 45

Three checks, all free: the inorder is sorted; the preorder begins with the root; the postorder ends with the root. Run all three before writing your final answer.

A fourth traversal is worth naming: level order (breadth-first), which visits nodes level by level using a queue. Here it is 45, 15, 79, 10, 20, 55, 90, 12, 50. All four traversals cost Θ(n).

Every BST operation costs O(h), where h is the height — so the whole game is keeping h small. That is what Lessons 8, 9 and 10 are about.

Deletion — the three cases

The three cases, in order of difficulty Case 1 — the node is a leaf (no children). Simply delete it and set the parent's pointer to NULL.

Case 2 — the node has exactly one child. Replace the node by its child — the child, and its whole subtree, moves up.

Case 3 — the node has two children. Replace the node's key by its inorder successor (the minimum of its right subtree), then recursively delete that successor from the right subtree. The successor has at most one child, so this reduces to Case 1 or Case 2.
The alternative that is equally correct

Case 3 may instead use the inorder predecessor — the maximum of the left subtree. Both are accepted. State which one you are using in the first line, and be consistent; examiners mark a mixed answer as wrong.

Three deletions from the tree above, done in sequence.

(a) Delete 12 — Case 1 (leaf).

12 is a leaf, so remove it and set 10's right pointer to NULL. Node 10 is now a leaf.

(b) Delete 55 — Case 2 (one child).

55 has only a left child, 50. Replace 55 by 50, so 50 becomes the left child of 79.

(c) Delete 15 — Case 3 (two children).

15 has children 10 and 20. Its inorder successor is the minimum of its right subtree, which is 20.

  • Copy 20's key into the node holding 15.
  • Recursively delete 20 from the right subtree — and 20 is a leaf, so this is Case 1.

Reconstructing a tree from two traversals

The rule that answers the whole question type

Inorder + preorder → unique tree. Inorder + postorder → unique tree. Preorder + postorder → NOT unique.

Inorder is always required, because it is inorder that tells you which keys lie left of the root and which lie right. Preorder or postorder only tells you which key is the root.

Q. Construct the binary tree with inorder D B E A F C G and preorder A B D E C F G.

Method: the first key of the preorder is the root. Find it in the inorder; everything to its left is the left subtree, everything to its right is the right subtree. Recurse.

The degenerate case — the example to quote.

Insert 10, 20, 30, 40, 50 in that order:

10 → 20 → 30 → 40 → 50   (each new key is larger, so it goes right every time)

The result is a right-skewed tree — effectively a linked list of height 4. A search for 50 costs 5 comparisons, not log25 ≈ 2.3.

So a BST built from sorted input has O(n) operations — no better than an array, and worse than a sorted array with binary search. This is the entire motivation for AVL trees (Lesson 8), red–black trees (Lesson 9) and B-trees (Lesson 10), all of which force h = O(log n) whatever the insertion order.

The BST's selling point: it is the only structure in that table with logarithmic search, insert and delete at once. A sorted array searches quickly but inserts slowly; a linked list inserts quickly but searches slowly.

Inorder is essential, because only it separates the left subtree from the right. Preorder or postorder alone tells you the root but not the split.

5. For the tree built from 45, 15, 79, 90, 10, 55, 12, 20, 50, the preorder is:

Option two is the inorder, option three the postorder, option four the level order. Preorder starts with the root and takes the whole left subtree before the right.

6. All BST operations cost:

h is log n only when the tree is balanced, and n − 1 when it is skewed. Everything that follows in this unit is about forcing h to stay O(log n).

7. The inorder successor of a node that has a right subtree is:

It is the right child only when that child has no left subtree. When a node has no right subtree at all, the successor is the lowest ancestor whose left child is also an ancestor of the node.

Recall without looking

State the BST property and its key consequence.

For every node x, all keys in the left subtree are less than key(x) and all keys in the right subtree are greater — and the property must hold recursively at every node. The consequence is that an inorder traversal visits the keys in sorted order.

Give the three traversals and how to remember them.

Inorder is Left–Root–Right and gives sorted order; preorder is Root–Left–Right and starts with the root; postorder is Left–Right–Root and ends with the root. The position of the root in the name gives the order. Level order uses a queue. All are Θ(n).

Give the three deletion cases.

Leaf: delete it and null the parent's pointer. One child: replace the node by that child. Two children: replace the key by the inorder successor — the minimum of the right subtree — then recursively delete that successor, which has at most one child. The inorder predecessor may be used instead, consistently.

Which pairs of traversals determine a tree uniquely, and why?

Inorder with preorder, and inorder with postorder. Preorder with postorder does not. Inorder is essential because only it says which keys lie left of the root and which lie right; preorder and postorder only identify the root.

Describe the reconstruction method from inorder and preorder.

The first key of the preorder is the root. Locate it in the inorder: everything to its left forms the left subtree and everything to its right the right subtree. Recurse on each part, taking the next unused preorder keys as the roots. Verify by reading both traversals back off the finished tree.

State the height in the best, average and worst case, and what causes the worst case.

Balanced: ⌊log₂n⌋. Random insertion order: about 1.39 log₂n. Skewed: n − 1, caused by inserting keys in sorted or reverse-sorted order, which makes the tree a linked list with O(n) operations.

Why use a BST rather than a sorted array or a linked list?

A BST is the only one of the three with logarithmic search, insert and delete together. A sorted array searches in O(log n) but inserts and deletes in O(n); a linked list inserts in O(1) but searches in O(n).
