Heaps and Priority Queues

The heap property, the array representation and its index formulas, heapify, the O(n) build-heap proof, insertion and extraction, the counting formulas, and what a priority queue is used for.

Exam strategy

Two questions, both certain. “Build a max-heap from the given array” — work bottom-up from index ⌊n/2⌋, and show the array after every heapify call. “Prove that build-heap runs in O(n) time” — a 5-mark derivation that most students cannot do, so it is worth learning outright; the whole proof is the sum Σ h/2h = 2. Also learn the index formulas and the counting formulas (leaves, internal nodes, height), which appear as objective questions.

The definition

A binary heap A binary heap is a complete binary tree — every level is completely filled except possibly the last, which is filled from left to right — that satisfies the heap property:

MAX-HEAP:   A[parent(i)] ≥ A[i]   for every node i ≠ root
MIN-HEAP:   A[parent(i)] ≤ A[i]   for every node i ≠ root
The two things a heap is NOT — both are exam traps

1. A heap is not a binary search tree. There is no ordering between siblings, and no left/right rule. Only the parent–child relation is constrained. An inorder traversal of a heap is not sorted.

2. The largest element is at the root, but the second largest is NOT necessarily at depth 1. It is, however, always one of the root's two children — a fact worth knowing, since “where can the second largest be?” is a common objective question. The smallest element of a max-heap can be any leaf, so finding it costs Θ(n).

The array representation

A heap needs no pointers — the tree structure is implied by the array indices. That is its great practical advantage.

The index formulas — know both conventions 1-based indexing (the textbook convention):
    parent(i) = ⌊i / 2⌋    left(i) = 2i    right(i) = 2i + 1

0-based indexing (the programming convention):
    parent(i) = ⌊(i − 1) / 2⌋    left(i) = 2i + 1    right(i) = 2i + 2

State which you are using at the top of the answer. This page uses 1-based.
The counting formulas — for a heap of n nodes Height of the heap = ⌊log2 n⌋
Number of leaves = ⌈n / 2⌉ — and they occupy indices ⌊n/2⌋ + 1 through n
Number of internal (non-leaf) nodes = ⌊n / 2⌋
Number of nodes at height h ≤ ⌈n / 2h+1⌉
Quick numerical. A max-heap holds 100 elements. Give its height, its number of leaves, and the index range of its leaves.

Height = ⌊log2100⌋ = ⌊6.64⌋ = 6

Leaves = ⌈100/2⌉ = 50, at indices 51 to 100

Internal nodes = ⌊100/2⌋ = 50, at indices 1 to 50

Sanity check: 50 + 50 = 100 ✓. And a complete tree of height 6 holds between 26 = 64 and 27 − 1 = 127 nodes; 100 lies in that range ✓.

Heapify — the core operation

MAX-HEAPIFY(A, i) — assumes the subtrees of i are already heaps
MAX-HEAPIFY(A, i)
   l = 2i;   r = 2i + 1;
   largest = i;
   if (l ≤ heap-size and A[l] > A[largest]) largest = l;
   if (r ≤ heap-size and A[r] > A[largest]) largest = r;
   if (largest ≠ i) {
     swap A[i] and A[largest];
     MAX-HEAPIFY(A, largest);  /* the violation may have moved down */
   }
Cost: O(log n) — it can travel at most the height of the tree. Also called sift-down, percolate-down or trickle-down.
BUILD-MAX-HEAP(A) — turn an arbitrary array into a heap
BUILD-MAX-HEAP(A, n)
   for i = ⌊n/2⌋ down to 1
     MAX-HEAPIFY(A, i);
Start at ⌊n/2⌋ because every index above that is already a leaf, and a leaf is trivially a heap. Work downward in index, which means bottom-up in the tree, so that both subtrees of i are heaps by the time i is processed.
Q. Build a max-heap from A = [4, 10, 3, 5, 1].

n = 5, so start at i = ⌊5/2⌋ = 2 and count down to 1.

i = 2 — node A[2] = 10, children A[4] = 5 and A[5] = 1.

The largest of 10, 5, 1 is 10 itself, so nothing changes. Array: [4, 10, 3, 5, 1]

i = 1 — node A[1] = 4, children A[2] = 10 and A[3] = 3.

The largest is 10 at index 2 → swap A[1] and A[2]. Array: [10, 4, 3, 5, 1]

Recurse at index 2: node A[2] = 4, children A[4] = 5 and A[5] = 1. Largest is 5 at index 4 → swap. Array: [10, 5, 3, 4, 1]

Recurse at index 4: it is a leaf, so stop.

The max-heap: A = [10, 5, 3, 4, 1]
        10  (index 1)
      /    \
    5      3  (2, 3)
   /  \
  4    1      (4, 5)

Check: 10 ≥ 5 and 10 ≥ 3 ✓; 5 ≥ 4 and 5 ≥ 1 ✓. Note that 3 < 4 — and that is perfectly legal, because they are not in a parent–child relation. This is the point where students wrongly “fix” the heap.

The O(n) build-heap proof

Why the naive bound is wrong, and what the right one is

The naive argument: n/2 calls to heapify, each O(log n), gives O(n log n). That bound is correct but not tight.

Why it is loose: heapify costs O(h) for a node at height h — and most nodes are near the bottom, where h is small. Half the nodes are leaves with h = 0; a quarter have h = 1; and so on. The expensive calls are rare.

The derivation — write it exactly like this.

Step 1. The number of nodes at height h is at most ⌈n / 2h+1⌉.

Step 2. MAX-HEAPIFY on a node at height h costs O(h).

Step 3. Total cost:

T(n) = Σh=0⌊log n⌋ ⌈n / 2h+1⌉ · O(h) = O( n · Σh=0⌊log n⌋ h / 2h )

Step 4 — the key sum. Extend the sum to infinity, which only makes it larger:

Σh=0∞ h / 2h = 2

Why: the standard identity Σk=0∞ k xk = x / (1 − x)² for |x| < 1. At x = ½ this is (½) / (¼) = 2.

Step 5. Therefore

T(n) = O(n · 2) = O(n)  ∎

Sanity check on the sum: 0/1 + 1/2 + 2/4 + 3/8 + 4/16 + 5/32 = 0 + 0.5 + 0.5 + 0.375 + 0.25 + 0.156 = 1.78, and the remaining terms carry it to 2. ✓

The one-sentence version, if you are short of time

“Heapify costs O(h), and there are at most n/2h+1 nodes at height h, so the total is n · Σ h/2h = 2n = O(n).” Even that single line earns most of the marks.

Insertion and extraction

OperationMethodCost
MAXIMUM(A)Return A[1]Θ(1)
INSERT(A, key)Place the key at the end of the array, then sift UP: while it is larger than its parent, swapO(log n)
EXTRACT-MAX(A)Save A[1]; move the LAST element to the root; decrease the heap size by 1; MAX-HEAPIFY(A, 1)O(log n)
INCREASE-KEY(A, i, key)Raise A[i], then sift upO(log n)
BUILD-MAX-HEAP(A)Heapify from ⌊n/2⌋ down to 1O(n)
DELETE(A, i)Replace A[i] by the last element, then sift up or down as neededO(log n)
SEARCH(A, key)Linear scan — a heap gives no helpΘ(n)
Q. Insert 15 into the max-heap [10, 5, 3, 4, 1], then extract the maximum.

Insert 15.

  • Append at index 6: [10, 5, 3, 4, 1, 15]
  • Parent of index 6 is ⌊6/2⌋ = 3, holding 3. Since 15 > 3, swap: [10, 5, 15, 4, 1, 3]
  • Parent of index 3 is ⌊3/2⌋ = 1, holding 10. Since 15 > 10, swap: [15, 5, 10, 4, 1, 3]
  • Index 1 is the root — stop.

Result: [15, 5, 10, 4, 1, 3] — 2 swaps, which is O(log n).

Extract the maximum.

  • The maximum is 15. Save it.
  • Move the last element, 3, to the root and shrink the heap to 5: [3, 5, 10, 4, 1]
  • MAX-HEAPIFY at index 1: children are A[2] = 5 and A[3] = 10; the largest is 10 at index 3 → swap: [10, 5, 3, 4, 1]
  • Recurse at index 3: its children would be indices 6 and 7, both beyond the heap — it is a leaf. Stop.

Result: maximum = 15, heap = [10, 5, 3, 4, 1] — back to where we started, as it must be. ✓

Priority queues

Definition A priority queue is an abstract data type maintaining a set S of elements, each with an associated value called a key (its priority), supporting INSERT, MAXIMUM (or MINIMUM), EXTRACT-MAX and INCREASE-KEY.

Unlike an ordinary queue, elements leave in order of priority, not in order of arrival.
ImplementationInsertExtract-maxFind-max
Unsorted array or listO(1)O(n)O(n)
Sorted array or listO(n)O(1)O(1)
Binary heapO(log n)O(log n)O(1)
Binary search tree (balanced)O(log n)O(log n)O(log n)

The binary heap is the standard implementation, because it is the only one with logarithmic cost for both operations, and it needs no pointers.

Recall without looking

Define a binary heap and state the two things it is not.

A complete binary tree — every level filled except possibly the last, which fills left to right — satisfying A[parent(i)] ≥ A[i] for a max-heap or ≤ for a min-heap. It is not a binary search tree: siblings have no ordering and an inorder traversal is not sorted. And the second-largest element is not at a fixed position, though it is always a child of the root; the smallest can be any leaf, so finding it costs Θ(n).

Give the index formulas in both conventions and the counting formulas.

1-based: parent ⌊i/2⌋, left 2i, right 2i+1. 0-based: parent ⌊(i−1)/2⌋, left 2i+1, right 2i+2. Height = ⌊log₂n⌋; leaves = ⌈n/2⌉ at indices ⌊n/2⌋+1 to n; internal nodes = ⌊n/2⌋; nodes at height h ≤ ⌈n/2^(h+1)⌉.

Describe MAX-HEAPIFY and BUILD-MAX-HEAP.

MAX-HEAPIFY(A, i) assumes both subtrees of i are heaps; it finds the largest of A[i] and its two children, and if that is not A[i] it swaps and recurses on the affected child. It costs O(log n). BUILD-MAX-HEAP calls it for i from ⌊n/2⌋ down to 1, because every index above ⌊n/2⌋ is already a leaf.

Prove that BUILD-MAX-HEAP runs in O(n).

There are at most ⌈n/2^(h+1)⌉ nodes at height h and heapify costs O(h) there, so the total is Σ ⌈n/2^(h+1)⌉·O(h) = O(n · Σ h/2^h). Extending the sum to infinity, Σ h/2^h = 2 by the identity Σ k x^k = x/(1−x)² at x = ½. So the total is O(2n) = O(n). The naive n/2 × O(log n) bound is correct but not tight, because most nodes are near the bottom where h is small.

Give the cost of every heap operation.

MAXIMUM Θ(1); INSERT O(log n) by appending and sifting up; EXTRACT-MAX O(log n) by moving the last element to the root, shrinking, and heapifying; INCREASE-KEY O(log n); BUILD-MAX-HEAP O(n); DELETE O(log n); SEARCH Θ(n), since a heap gives no help in finding an arbitrary key.

Define a priority queue and compare its implementations.

An ADT maintaining elements with priorities, supporting insert, maximum, extract-max and increase-key; elements leave by priority rather than by arrival. Unsorted array: O(1) insert but O(n) extract. Sorted array: O(n) insert but O(1) extract. Binary heap: O(log n) for both plus O(1) find-max, and no pointers — which is why it is the standard choice.

Name five applications of priority queues.

Heap sort; Dijkstra's shortest path, where a heap improves O(V²) to O((V+E) log V); Prim's minimum spanning tree; Huffman coding, repeatedly extracting the two smallest frequencies; CPU priority scheduling; and least-cost branch and bound.
