NP-Completeness and Polynomial Reductions

Formal definitions of NP-Hard and NP-Complete, Euler/Venn complexity diagrams, polynomial-time reductions ($L_1 \le_P L_2$), transitivity, the 2-step NP-completeness proof recipe, and the Cook–Levin Theorem.

Exam strategy

“Define NP-Hard and NP-Complete” and “State the Cook-Levin Theorem and explain the steps to prove a problem is NP-Complete” are 10-mark examination essentials. Always draw the P vs NP Venn diagrams (both under $P \ne NP$ and $P = NP$).

Definitions: NP-Hard vs NP-Complete

1. NP-Hard A problem $X$ is NP-Hard if every problem $Y \in \text{NP}$ is polynomial-time reducible to $X$: $$\forall Y \in \text{NP}, \quad Y \le_P X$$ Note: An NP-Hard problem does not need to belong to class NP. It does not even need to be a decision problem (e.g., the Halting Problem is NP-Hard and undecidable).
2. NP-Complete (NPC) A problem $X$ is NP-Complete if and only if it satisfies both conditions:
  1. $X \in \mathbf{NP}$ (its proposed solutions can be verified in polynomial time).
  2. $X$ is $\mathbf{NP}\text{\bf-Hard}$ ($\forall Y \in \text{NP}, Y \le_P X$).
NP-Complete problems are the hardest problems in class NP. If any single NP-Complete problem can be solved in polynomial time, then every problem in NP can be solved in polynomial time ($P = NP$).

Polynomial-Time Reductions ($L_1 \le_P L_2$)

A reduction is an algorithm that converts instances of one problem into instances of another problem. It allows us to solve the first problem using a subroutine that solves the second.

Formal Definition of $\le_P$ (Karp Reduction) A language $L_1$ is polynomial-time reducible to language $L_2$ (written $L_1 \le_P L_2$) if there exists a function $f: \Sigma^* \to \Sigma^*$ such that:
  1. $f(x)$ is computable by a deterministic algorithm in polynomial time.
  2. For all inputs $x$: $$x \in L_1 \iff f(x) \in L_2$$ (i.e., $x$ is a YES-instance of $L_1$ if and only if $f(x)$ is a YES-instance of $L_2$).
Direction of Hardness — Avoid the Common Trap!

Think of $L_1 \le_P L_2$ as: “$L_1$ is no harder than $L_2$” (or $L_2$ is at least as hard as $L_1$).

  • If $L_1 \le_P L_2$ and $L_2 \in P$: Then $L_1 \in P$ (solvability flows backward).
  • If $L_1 \le_P L_2$ and $L_1 \notin P$: Then $L_2 \notin P$ (hardness flows forward).
  • Transitivity: If $A \le_P B$ and $B \le_P C$, then $A \le_P C$.

The 2-Step Recipe to Prove Problem $X$ is NP-Complete

To prove a new problem $X$ is NP-Complete, you do not need to reduce all infinitely many NP problems to $X$. Thanks to transitivity, you follow this exact template:

The Standard Proof Recipe
  1. Step 1: Prove $X \in \text{NP}$
    • Describe a certificate (candidate solution) $S$.
    • Show that $S$ has polynomial size ($|S| = O(n^k)$).
    • Present a deterministic algorithm that verifies whether $S$ is valid in polynomial time.
  2. Step 2: Choose a known NP-Complete problem $Y$ (e.g. 3-SAT, Clique, Vertex Cover).
  3. Step 3: Construct a reduction mapping $f$ from $Y$ to $X$ ($Y \le_P X$)
    • Show how any arbitrary instance $y$ of $Y$ is transformed into an instance $x = f(y)$ of $X$ in polynomial time.
  4. Step 4: Prove correctness in both directions (if and only if)
    • Forward (⇒): If $y$ is a YES-instance of $Y$, prove that $f(y)$ must be a YES-instance of $X$.
    • Backward (⇐): If $f(y)$ is a YES-instance of $X$, prove that $y$ must be a YES-instance of $Y$.

The Cook–Levin Theorem (1971)

Before any reduction can work, there had to be a first NP-Complete problem established without reducing from another problem.

Cook–Levin Theorem Statement $$\mathbf{SAT} \text{ (Boolean Satisfiability)} \text{ is } \mathbf{NP}\text{\bf-Complete.}$$

How Stephen Cook proved it:

  • Any problem $Y \in \text{NP}$ is decided by some non-deterministic Turing Machine $M$ in polynomial time $p(n)$.
  • Cook constructed a giant boolean formula $\Phi$ whose variables encode the state, tape symbols, and head position of $M$ across all $p(n)$ execution steps.
  • He proved that $\Phi$ is satisfiable if and only if $M$ reaches an accepting state on input $w$.
  • Because $\Phi$ has size $O(p(n)^2)$ and is constructed in polynomial time, every problem in NP reduces to SAT. This anchored the foundation of NP-Completeness.

Check yourself

Retrieval practice

1. To prove that a new problem X is NP-Complete by reduction from known problem Y, what is the required direction?

We must show X is at least as hard as known problem Y, which means reducing Y to X (Y ≤_P X).

2. What makes the Cook-Levin Theorem historically unique?

Cook proved SAT is NP-Complete by encoding non-deterministic Turing Machine executions directly into boolean formulas.

3. If problem A ≤_P B, and an O(n³) deterministic algorithm is found for problem B, what does this imply for A?

Polynomial reduction ensures that if the target problem B is in P, the source problem A is also in P.

Recall without looking

Define NP-Hard vs NP-Complete.

NP-Hard: All problems in NP reduce to it in polynomial time (need not be in NP). NP-Complete: NP-Hard AND belongs to class NP.

What are the two conditions of a polynomial reduction L1 ≤_P L2?

1. Mapping f is computable in deterministic polynomial time. 2. x ∈ L1 ⟺ f(x) ∈ L2 (YES maps to YES, NO maps to NO).

What is the Cook-Levin theorem?

Boolean Satisfiability (SAT) is NP-Complete. It proved from first principles that any NP machine computation can be encoded into a polynomial-sized boolean formula.
