P, NP Classes and Non-Determinism

Decision vs optimization problems, deterministic vs non-deterministic algorithms, formal definitions of complexity classes P and NP, certificates and polynomial verifiers, and the P versus NP question.

Exam strategy

“Define Class P, Class NP, and Non-Deterministic algorithms with examples” is a standard 5-to-8 mark question. Distinguish clearly between solving an instance from scratch and verifying a proposed certificate.

Decision vs Optimization Problems

Computational problems fall broadly into two categories:

  • Optimization Problem: Seeks the best solution (e.g., “Find a tour visiting all cities with minimum total edge weight” or “Find the maximum profit subset of knapsack items”).
  • Decision Problem: Asks a question with a binary YES / NO answer (e.g., “Given graph $G$ and integer $k$, does there exist a tour with total weight $\le k$?”).
Why Complexity Theory Studies Decision Problems

Decision problems are formally represented as formal languages ($L \subseteq \{0, 1\}^*$). If a decision version of a problem is intractable, its corresponding optimization problem is at least as hard. Moreover, by binary searching over threshold parameter $k$, an optimization problem can be solved with only $O(\log(\text{Range}))$ calls to the decision solver.

The Two Phases of a Non-Deterministic Algorithm

  1. Guessing Phase: Generates an arbitrary candidate solution $S$ (called a certificate or witness) of polynomial length using non-deterministic choice primitives (choice()).
  2. Verification Phase: A standard deterministic algorithm inspects the candidate certificate $S$ and input $x$, verifying in polynomial time whether $S$ satisfies the problem conditions.
Non-Deterministic Algorithm for Hamiltonian Cycle 
Algorithm NonDeterministic_HC(Graph G(V, E)):
    // Step 1: Guessing Phase
    Guess a sequence of vertices S = <v1, v2, ..., vn> of length |V|
    
    // Step 2: Deterministic Verification Phase (Polynomial Time O(V + E))
    If S does not contain all vertices of V exactly once:
        return FALSE
    For i = 1 to n - 1:
        If edge (v_i, v_{i+1}) is not in E:
            return FALSE
    If edge (v_n, v_1) is not in E:
        return FALSE
    return TRUE  // Found a valid Hamiltonian Cycle!

Because verification takes $O(V)$ time, Hamiltonian Cycle belongs to class NP.

Complexity Class P (Polynomial Time)

Class P Definition $$\mathbf{P} = \{ L \subseteq \{0,1\}^* \mid L \text{ can be decided by a deterministic algorithm in } O(n^k) \text{ time for some constant } k \}$$ Problems in P are considered tractable or efficiently solvable on classical computers.

Examples of problems in P:

  • Searching (Binary search $O(\log n)$) and Sorting (Merge sort $O(n \log n)$).
  • Shortest Paths (Dijkstra $O(E + V \log V)$, Bellman-Ford $O(VE)$).
  • Minimum Spanning Tree (Kruskal, Prim $O(E \log V)$).
  • Linear Programming (Interior-point methods).

Complexity Class NP (Nondeterministic Polynomial Time)

Class NP Definition (Verification View) $$\mathbf{NP} = \{ L \subseteq \{0,1\}^* \mid \exists \text{ a polynomial-time verifier } V(x, y) \text{ and constant } c \text{ such that }$$ $$x \in L \iff \exists \text{ certificate } y \text{ with } |y| = O(|x|^c) \text{ such that } V(x, y) = \text{ACCEPT} \}$$

In simple terms: NP is the set of decision problems whose proposed solutions can be checked for correctness in polynomial time.

The P versus NP Question

Does $P = NP$? Or is $P \ne NP$?

  • It is trivially true that $P \subseteq NP$: Any problem that can be solved in polynomial time can certainly be verified in polynomial time (the verifier simply ignores the certificate and solves the problem directly).
  • The unresolved question: If a solution can be verified efficiently, can it always be found efficiently from scratch?
  • Most computer scientists strongly conjecture that $P \ne NP$, meaning verification is fundamentally easier than discovery. Proving or disproving this is one of the seven Millennium Prize Problems, carrying a $1,000,000 reward from the Clay Mathematics Institute.
Class co-NP Overview

co-NP is the class of languages whose complements are in NP. For problems in co-NP, a “NO” instance has a short, polynomial-time verifiable counterexample. For example, testing whether a boolean formula is a Tautology (true under all assignments) is in co-NP (a single falsifying assignment proves NO).

Retrieval practice

1. What does the abbreviation 'NP' actually stand for in computational complexity?

NP stands for Nondeterministic Polynomial time, meaning solvable in polynomial time on a non-deterministic machine.

2. Which statement correctly describes the relationship between P and NP?

Any problem solvable deterministically in polynomial time can trivially be verified in polynomial time.

3. A candidate solution provided to a polynomial-time verifier to prove an instance is in NP is called:

A certificate (witness) is the polynomial-sized evidence checked by the deterministic verifier.

Recall without looking

Contrast Class P and Class NP in one sentence each.

Class P is the set of decision problems solvable in deterministic polynomial time. Class NP is the set of decision problems verifiable in deterministic polynomial time given a certificate.

What are the two phases of a non-deterministic algorithm?

1. Guessing phase: generates a candidate certificate non-deterministically. 2. Verification phase: checks deterministically in polynomial time whether the guess is valid.

Why is P ⊆ NP?

Because if a problem can be solved in polynomial time without help, its verifier can simply solve the instance from scratch in polynomial time, ignoring the certificate.
