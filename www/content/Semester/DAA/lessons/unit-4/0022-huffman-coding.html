Huffman Coding

Prefix-free codes, building the Huffman tree using a priority queue, encoding and decoding, optimality of Huffman codes, and a complete worked example.

Exam strategy

“Construct Huffman tree and codes for the given frequencies” is a guaranteed 10-marker. Show the priority queue at each merge step, draw the final tree, and list the codes.

Problem

Given characters with frequencies, assign variable-length binary codes such that total encoding length is minimised. The code must be prefix-free — no code is a prefix of another — so decoding is unambiguous.

Algorithm

Huffman’s algorithm 1. Create a leaf node for each character, insert into a min-priority queue by frequency.
2. While queue has more than one node:
   Extract two nodes with minimum frequency.
   Create a new internal node with these as children, frequency = sum.
   Insert the new node back.
3. The remaining node is the root of the Huffman tree.
4. Assign 0 to left edges, 1 to right edges. Path from root to leaf = code.

Time: O(n log n) (n insertions and extractions from priority queue)
Worked example

Characters and frequencies: a=5, b=9, c=12, d=13, e=16, f=45

Step 1: Merge a(5) + b(9) = 14. Queue: {c:12, d:13, 14, e:16, f:45}

Step 2: Merge c(12) + d(13) = 25. Queue: {14, e:16, 25, f:45}

Step 3: Merge 14 + e(16) = 30. Queue: {25, 30, f:45}

Step 4: Merge 25 + 30 = 55. Queue: {f:45, 55}

Step 5: Merge f(45) + 55 = 100. Root.

Codes:

Total bits = 45(1) + 12(3) + 13(3) + 5(4) + 9(4) + 16(3) = 45 + 36 + 39 + 20 + 36 + 48 = 224.

Fixed-length (3 bits each) would need 100 × 3 = 300 bits. Huffman saves 25%.

Retrieval practice

1. Huffman coding is a greedy algorithm because:

Local choice: merge two smallest. This greedy choice leads to an optimal prefix-free code.

2. A prefix-free code means:

Prefix-free = uniquely decodable. In the tree, characters are only at leaves, so no code is a prefix of another.

3. The time complexity of Huffman coding is:

n-1 merges, each involving extract-min and insert on a heap = O(log n) each.

4. In Huffman coding, the most frequent character gets:

High-frequency characters are merged last, ending up near the root with short paths.

Recall without looking

Huffman algorithm in four lines.

Min-heap of leaf nodes by frequency. Repeat: extract two min, merge, insert sum. Until one node (root). Assign 0/1 to left/right. O(n log n).

Why Huffman is optimal.

Greedy choice: merging two smallest frequencies always leads to minimum total weighted path length. Produces an optimal prefix-free code.
