MST definition

A spanning tree of a connected undirected graph is a subgraph that is a tree connecting all vertices. A minimum spanning tree has the least total edge weight.

Kruskal’s algorithm

Kruskal’s 1. Sort all edges by weight (ascending).
2. For each edge (in order): if it does not form a cycle (check with Union-Find), add it to the MST.
3. Stop when MST has V−1 edges.

Time: O(E log E) = O(E log V). Uses Union-Find for cycle detection.
Worked example — Kruskal’s

Graph: A–B(4), A–C(3), B–C(1), B–D(2), C–D(4), C–E(6), D–E(5). V=5, need 4 edges.

Prim’s algorithm

Prim’s 1. Start with any vertex. MST set = {start}.
2. Find the minimum-weight edge connecting a vertex in MST to a vertex outside MST.
3. Add that edge and vertex to MST.
4. Repeat until all vertices are in MST.

Time: O(V²) with adjacency matrix | O(E log V) with binary heap

Check yourself

Retrieval practice

1. An MST of a graph with V vertices has exactly:

A tree with V vertices always has V-1 edges. Adding one more would create a cycle.

2. Kruskal’s checks for cycles using:

Union-Find: if two endpoints are in the same set, adding the edge creates a cycle. Nearly O(1) per operation with path compression.

3. Prim’s algorithm with an adjacency matrix runs in:

V iterations, each scanning V entries to find the minimum. With a binary heap it improves to O(E log V).

4. Kruskal’s is better for:

Kruskal's sorts edges O(E log E). For sparse graphs E is small. Prim's O(V²) is better when E ≈ V².

Recall without looking

Kruskal's algorithm in three lines.

Sort edges by weight. Add each edge if it doesn't form a cycle (Union-Find). Stop at V-1 edges. O(E log V).

Prim's algorithm in three lines.

Start from any vertex. Always add the minimum-weight crossing edge. Grow until all vertices included. O(V²) or O(E log V).
