Why reduce attributes?

  • Real datasets contain redundant attributes that do not help classification.
  • Removing them simplifies the model without losing information.
  • This is the rough-set approach to dimensionality reduction / feature selection.
  • Unlike statistical methods, rough sets need no domain knowledge, no distance metric, and no parameters.

Dispensable vs indispensable

Dispensable attribute Attribute a ∈ P is dispensable in P if:
IND(P) = IND(P − {a})

Removing it does not change the equivalence classes.
Indispensable attribute Attribute a ∈ P is indispensable in P if:
IND(P) ≠ IND(P − {a})

Removing it merges some equivalence classes that were separate.

A set P is independent if every attribute in it is indispensable — no attribute can be removed without coarsening the partition.

Reduct

Reduct A reduct of P (relative to a decision d) is a minimal subset R ⊆ P such that:
• R preserves the same positive region as P  (POSR(d) = POSP(d))
• No proper subset of R has this property (minimality)
  • A decision system may have multiple reducts.
  • Every reduct gives a sufficient set of attributes for correct classification.
  • Finding all reducts is NP-hard in general, but exam tables are small enough for hand computation.

Core

Core CORE(P) = intersection of ALL reducts

These are the absolutely essential attributes — present in every reduct.
The containment to remember

CORE ⊆ every REDUCT ⊆ P

The core is always a subset of every reduct, and every reduct is always a subset of the full attribute set. The core may be empty (if no single attribute appears in every reduct).

The discernibility matrix

A systematic way to find reducts and core from a decision table.

  • Build an n×n matrix where entry (i, j) lists the attributes that have different values for objects i and j.
  • Only fill entries for pairs with different decisions.
  • Core = attributes that appear as singleton entries — they are the only attribute distinguishing that pair, so they cannot be removed.
  • A reduct must contain at least one attribute from every entry in the matrix.

Worked example — finding reduct and core

Full worked example

Decision table:

ObjectColourSizeShapeDecision
x1RedSmallCircleYes
x2RedLargeCircleYes
x3BlueSmallSquareNo
x4GreenLargeCircleNo
x5BlueSmallCircleNo
x6RedSmallSquareNo

X = {x1, x2} (Decision = Yes). Condition attributes P = {Colour, Size, Shape}.

Step 1: Equivalence classes with all attributes.

All six rows are unique ⇒ IND(P) = {{x1}, {x2}, {x3}, {x4}, {x5}, {x6}}

Step 2: Check each attribute for dispensability.

Remove Colour ⇒ IND({Size, Shape})

x1=(Small,Circle), x2=(Large,Circle), x3=(Small,Square), x4=(Large,Circle), x5=(Small,Circle), x6=(Small,Square)

• {x1, x5} merge — x1=Yes, x5=No ⇒ MIXED!
• POS changes ⇒ Colour is INDISPENSABLE

Remove Size ⇒ IND({Colour, Shape})

x1=(Red,Circle), x2=(Red,Circle), x3=(Blue,Square), x4=(Green,Circle), x5=(Blue,Circle), x6=(Red,Square)

• {x1, x2} merge — both Yes ✓
• All others are singletons with consistent decisions ✓
• Classification preserved ⇒ Size is DISPENSABLE

Remove Shape ⇒ IND({Colour, Size})

x1=(Red,Small), x2=(Red,Large), x3=(Blue,Small), x4=(Green,Large), x5=(Blue,Small), x6=(Red,Small)

• {x1, x6} merge — x1=Yes, x6=No ⇒ MIXED!
• POS changes ⇒ Shape is INDISPENSABLE

Step 3: Find the reduct.

Indispensable: {Colour, Shape}. Check if this is sufficient:

IND({Colour, Shape}): {x1,x2}=(Red,Circle) both Yes ✓, {x3}=(Blue,Square) No ✓, {x4}=(Green,Circle) No ✓, {x5}=(Blue,Circle) No ✓, {x6}=(Red,Square) No ✓

{Colour, Shape} preserves classification ⇒ it is a REDUCT (and the only one).

Step 4: Core.

Only one reduct = {Colour, Shape}, so CORE = {Colour, Shape}.

Dispensable = {Size} — it can be removed without affecting classification.

Size never appears as a singleton — it is always accompanied by another attribute, so it is never the sole distinguisher for any pair.

The practical shortcut

For exam problems: (1) Build the discernibility matrix for pairs with different decisions. (2) Core = all singleton entries. (3) Check if core alone is a reduct; if not, add attributes from remaining entries. This is faster than testing every subset.

Retrieval practice

1. An attribute a is dispensable in P if:

Dispensable means the attribute can be removed without affecting the equivalence classes. The second option describes an indispensable attribute.

2. A reduct is:

A reduct preserves classification power and is minimal — removing any attribute from it would change the positive region. The set of all indispensable attributes is the core, not necessarily a reduct.

3. The core of a set of attributes is:

CORE = ∩ (all reducts). These are the absolutely essential attributes.

4. In the discernibility matrix, core attributes are identified as:

A singleton entry means that attribute is the ONLY one distinguishing that pair, so removing it would make them indiscernible — it must be in every reduct.

5. Removing an indispensable attribute causes:

Indispensable means removing it changes IND(P) — classes merge. If objects with different decisions merge, classification is lost.

6. Can a decision system have multiple reducts?

Multiple reducts are common. Each represents a different minimal feature set that works. The core is the intersection of all of them.

7. The correct containment relationship is:

Core is the smallest (intersection of reducts), each reduct is larger, and P is the full set. CORE ⊆ REDUCT ⊆ P.

Recall without looking

Define reduct and core.

Reduct: minimal subset of attributes preserving the positive region (same classification as the full set). Core: intersection of all reducts — the absolutely essential attributes. CORE ⊆ REDUCT ⊆ P.

Dispensable vs indispensable.

Dispensable: removing it doesn’t change IND(P). Indispensable: removing it merges classes, potentially losing classification. Core attributes are always indispensable.

How to find core from the discernibility matrix.

Build the matrix for pairs with different decisions. Core = set of attributes that appear as singleton entries — they are the sole distinguisher for some pair.

Why does attribute reduction matter?

Removes redundant features without losing classification power. No parameters, no domain knowledge needed. The reduct IS the selected feature set.
