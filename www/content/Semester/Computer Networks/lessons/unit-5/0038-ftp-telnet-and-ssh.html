FTP, TELNET and SSH

FTP's two connections and the active/passive distinction, TELNET's network virtual terminal, and why SSH replaced it. Two protocols named in the syllabus, and the third because no answer about TELNET is complete without it.

Exam strategy

"Explain FTP with a diagram" is a 5-mark question, and the diagram must show two connections, not one — that is the whole point of FTP and the single fact examiners check. For TELNET, the marks are in the Network Virtual Terminal concept and in why TELNET is insecure. Keep two lines for SSH as the answer to that.

FTP — File Transfer Protocol

FTP transfers files between two hosts. Its distinguishing design decision, and the source of most exam questions about it:

FTP uses TWO TCP connections Control connection — port 21. Opened first, stays open for the entire session. Carries only commands and replies.
Data connection — port 20. Opened and closed again for every single file transferred. Carries only the file data.

Why separate the two? — the reasoning that earns the mark

Because commands and data have completely different requirements. Commands are tiny, textual and must be deliverable during a transfer — a user needs to be able to send ABORT while a large file is still moving. Data is bulk, may be binary, and needs its type and structure negotiated. Trying to interleave both on one connection would mean escaping data that looked like commands, and would make aborting a transfer impossible. Two connections keep control responsive while data flows.

The three attributes to negotiate

AttributeOptions
File typeASCII (default, for text — converted to and from NVT ASCII), EBCDIC, or image/binary (a stream of bits, for programs and images)
Data structureFile (a continuous stream of bytes, the default), record (divided into records), or page (divided into numbered pages)

Anonymous FTP, and FTP's security problem

Anonymous FTP lets a user access public files without an account: log in as anonymous with an e-mail address as the password. Access is normally read-only and confined to a public directory.

FTP sends the username and password in plain text over the control connection, and the file data unencrypted. Anyone tapping the link sees both. The replacements are FTPS (FTP over TLS) and SFTP (file transfer over SSH — a different protocol entirely, despite the similar name).

TFTP, in one line

TFTP (Trivial File Transfer Protocol, port 69, UDP) is a deliberately minimal alternative: no authentication, no directory listing, one connection, and it builds its own stop-and-wait reliability on top of UDP. Used for booting diskless workstations and loading router configurations — cases where the client is too simple to implement FTP.

TELNET — Terminal Network

TELNET (port 23) is the standard TCP/IP protocol for remote login: it lets a user at one machine log in to a remote machine and run commands there as though sitting at its terminal.

TermMeaning
Local loginKeystrokes go to the local terminal driver, which passes them to the local operating system.
Remote loginKeystrokes are accepted by the terminal driver but not interpreted locally. They are passed to the TELNET client, translated to NVT form, sent across the network, and delivered to a pseudoterminal driver on the remote machine, which makes the remote OS believe a local terminal is attached.

The Network Virtual Terminal — the key concept

The problem NVT solves, and the answer to "what is NVT?"

Every kind of computer has its own character set and its own control sequences. If TELNET had to know about all of them, every client would need code for every possible server. The NVT is a universal intermediate representation. The client translates from its local form into NVT form; the server translates from NVT form into its own. Each system needs to know only its own encoding and the NVT standard — so n systems need n translators rather than n².

NVT uses two character sets: data characters (7-bit US ASCII in an 8-bit byte, with the top bit 0) and control characters (the same byte with the top bit set to 1). Control characters are preceded by the IAC (Interpret As Command) byte, value 255.

Options and negotiation

TELNET can be enriched with options — echo mode, terminal type, line width, binary transmission. Both ends negotiate which to use, with four commands worth naming: WILL ("I will do this"), WONT, DO ("please do this"), DONT. There is also sub-option negotiation for options that need a parameter, such as the terminal type.

SSH — Secure Shell

TELNET sends everything, including the password, in plain text. Anyone able to observe the traffic can read the login credentials and every keystroke. That is why TELNET is effectively obsolete on public networks.

BasisTELNETSSH
Port2322

SSH has three components worth naming: SSH-TRANS (the transport layer protocol, providing the encrypted channel and server authentication), SSH-AUTH (authenticating the client to the server), and SSH-CONN (multiplexing several logical channels — a login session, a file transfer, a forwarded port — over the one encrypted connection).

The comparison examiners want in one line

SSH is TELNET with encryption, server authentication and integrity checking — and it can tunnel other protocols through the same secure connection. If a question asks why TELNET is no longer used, that sentence is the answer.

Check yourself

Retrieval practice

1. FTP's control connection:

Control (port 21) persists for the session; the data connection (port 20) is opened and closed per file. Keeping them separate is what lets a user send ABORT while a large transfer is still running.

2. In active mode FTP, the data connection is opened by:

Active mode has the client issue PORT and the server call back — an unsolicited inbound connection that client firewalls reject. Passive mode has the client connect outbound both times, which is why it is now the default.

3. The Network Virtual Terminal exists so that:

Without a universal intermediate form, every client would need a translator for every possible server — n² translators for n systems. NVT reduces that to n. TELNET does nothing at all about password secrecy, which is why SSH replaced it.

4. TELNET character mode is inefficient because:

One byte of data travelling in a 41-byte packet, twice over. This is precisely the traffic pattern Nagle's algorithm was designed to control — the two topics connect directly.

5. TFTP differs from FTP in that TFTP:

TFTP (port 69, UDP) is deliberately minimal — no authentication, no directory listing, one connection, and its own stop-and-wait reliability layered on UDP. It exists for clients too simple to implement FTP, such as booting diskless machines.

6. The principal reason SSH replaced TELNET is that SSH:

TELNET sends credentials and every keystroke in the clear. SSH encrypts everything, authenticates both parties, checks integrity, and can additionally tunnel other protocols through the same secure connection.

Recall without looking

Describe FTP's two connections and why they are separate.

Control on port 21, open for the whole session, carrying only commands and replies; data on port 20, opened and closed for each file, carrying only file data. They are separate because commands are tiny, textual and must be deliverable during a transfer (so ABORT works), while data is bulk, possibly binary, and needs its type and structure negotiated.

Compare active and passive FTP.

Active: the client sends PORT and the server opens the data connection back to the client from port 20 — client firewalls block this unsolicited inbound connection. Passive: the client sends PASV, the server nominates an ephemeral port, and the client connects to it — both connections are outbound, so it works through firewalls and is the modern default.

Name the three attributes FTP negotiates.

File type (ASCII, EBCDIC, image/binary); data structure (file, record, page); transmission mode (stream, block, compressed).

What is anonymous FTP, and what is FTP's security weakness?

Logging in as "anonymous" with an e-mail address as password to reach public files, normally read-only in a restricted directory. The weakness: FTP sends the username, password and data in plain text. Replaced by FTPS (FTP over TLS) and SFTP (file transfer over SSH).

Explain the Network Virtual Terminal.

A universal intermediate character representation. The client translates from its local form into NVT form and the server translates NVT into its own, so each system needs to know only its own encoding plus the standard — n translators rather than n². Data characters are 7-bit ASCII with the top bit 0; control characters have the top bit 1 and are preceded by IAC (255).

Name TELNET's three modes of operation.

Default mode — local echo, a whole line sent on Enter. Character mode — each character sent separately and echoed remotely, which is very inefficient. Line mode — editing done locally, completed line sent; the usual compromise.

Give five differences between TELNET and SSH.

Port 23 vs 22; no encryption vs everything encrypted; password in the clear vs password or public-key authentication with the server also authenticated; no integrity checking vs message authentication codes; remote login only vs port forwarding, SFTP/SCP and remote command execution. SSH's components are SSH-TRANS, SSH-AUTH and SSH-CONN.
