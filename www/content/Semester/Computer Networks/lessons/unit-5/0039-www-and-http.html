WWW and HTTP

URLs, the three kinds of web document, the HTTP request and response formats, the methods and status codes, persistent versus non-persistent connections with a worked timing comparison, and cookies and caching.

Exam strategy

Two questions. (1) "Explain HTTP with its message format" — draw the request and response formats as labelled blocks, then the methods and status-code classes. (2) "Differentiate persistent and non-persistent HTTP" — a short comparison, and the marks are in the RTT count, so learn the two formulas. Cookies are a standard 3-mark add-on: HTTP is stateless, cookies are how state is added on top.

The World Wide Web

The WWW is a repository of linked information spread over the Internet. It is a distributed client-server service: the client (browser) requests, the server supplies, and documents are linked to one another by hyperlinks. The web is not the Internet — it is one application running on it, a distinction worth a sentence.

The distinction that gets tested

Dynamic documents run on the server; active documents run on the client. Both change, but the location of the computation differs, and that is the whole point of the classification. Dynamic content is created fresh for each request; active content is a program shipped to the browser to execute.

HTTP

HTTP is the protocol used to access data on the World Wide Web. It runs over TCP port 80, and it borrows deliberately from two ancestors: it is like FTP in transferring files, and like SMTP in its message format — but unlike FTP it uses only one connection, with the commands travelling on the same connection as the data.

HTTP is stateless — state this early in any HTTP answer

The server retains no information about previous requests. Every request is treated as entirely independent. This makes servers simple and enormously scalable — but it means the protocol cannot by itself remember a logged-in user or a shopping basket. Cookies exist precisely to add state on top of a stateless protocol.

Worked numerical — loading a page

Q. A web page consists of a base HTML file plus 10 images. The round-trip time is 100 ms. Ignoring transmission time, compare the load time using non-persistent and persistent HTTP.

Non-persistent. Each of the 11 objects needs its own connection: 1 RTT to set it up, 1 RTT to request and receive.

Total = 11 objects × 2 RTT = 22 × 100 ms = 2200 ms = 2.2 s

Persistent. One connection set up once, then each object costs 1 RTT.

Total = 1 RTT (setup) + 11 × 1 RTT = 12 × 100 ms = 1200 ms = 1.2 s

Saving = 1000 ms, or about 45%.

The follow-up examiners add: with non-persistent HTTP over 5 parallel connections, the 10 images are fetched in 2 batches of 5. Time = 2 RTT (base file) + 2 batches × 2 RTT = 6 RTT = 600 ms. Parallelism helps more than persistence here — which is exactly why HTTP/1.0 browsers opened multiple connections, and why the comparison is worth making.

Sanity check: persistent must always beat non-persistent for the same number of parallel connections. If your persistent figure is larger, you have double-counted the setup.

Pipelining

A refinement of persistent connections: the client sends the next request before the previous response has arrived, rather than waiting. This removes most of the per-object round trips. Worth one line as the natural extension of persistence.

Cookies

HTTP is stateless, but many applications need to remember a user. Cookies supply that memory.

How a cookie works — four steps 1. The server creates a cookie: an identifier, a domain, a path and an expiry.
2. It sends it to the client in a Set-Cookie header of the response.
3. The client stores it, filed under that server's domain.
4. On every later request to that domain, the client returns it in a Cookie header, and the server recognises the user.
Used forConcern
Session management — keeping a user logged inPrivacy — third-party cookies let advertisers track a user across many sites
Shopping basketsSecurity — a stolen session cookie can impersonate the user
Personalisation and preferencesCookies are stored in plain text on the client, so nothing sensitive should be put in them

Proxy servers and caching

A proxy server sits between clients and the origin server and keeps copies of recent responses. If a requested document is in its cache and still fresh, it answers directly.

BenefitHow
Reduces latencyThe proxy is nearer than the origin server
Reduces external trafficRepeated requests never leave the organisation
Reduces load on the origin serverIt sees only cache misses
Enables filtering and loggingAll web traffic passes one controllable point

Keeping the cache fresh uses conditional GET: the proxy sends a request with an If-Modified-Since header. If the document has not changed, the server replies 304 Not Modified with no body — confirming the cached copy is still good at almost no bandwidth cost. That is what status code 304 is for, and it is a neat 2-mark answer.

Check yourself

Retrieval practice

1. A document created by a program running on the client machine is called:

Active runs on the client (JavaScript, applets); dynamic runs on the server (PHP, CGI, JSP). Both change per request — what distinguishes them is where the computation happens.

2. HTTP is described as stateless, meaning:

Statelessness is about server memory, not connection lifetime — a persistent connection is still stateless. It makes servers simple and scalable, and it is exactly why cookies had to be invented to remember a logged-in user.

3. A page with a base file plus 4 images, RTT 50 ms, loaded over persistent HTTP takes about:

Persistent = 1 RTT to establish + 1 RTT per object = 6 × 50 = 300 ms. The 500 ms figure is the non-persistent case, where every object pays for its own handshake.

4. Which method requests only the header of a document?

HEAD returns the headers with no body — useful for testing whether a document exists or has changed without downloading it. OPTIONS asks which methods are supported; TRACE echoes the request back for diagnostics.

5. A status code of 503 indicates:

5xx is the server's fault, 4xx the client's. Learning the five classes rather than a long list of codes answers most questions of this shape.

6. A proxy sends If-Modified-Since and receives 304 Not Modified. This means:

Conditional GET is how a cache checks freshness cheaply: 304 confirms the copy is current and carries no body at all, so the check costs almost no bandwidth. That is precisely what the 304 code exists for.

Recall without looking

Give the four parts of a URL.

Protocol (http, https, ftp), host (domain name or IP address), port (optional; 80 for HTTP, 443 for HTTPS), and path (the file's location within the server).

Distinguish static, dynamic and active documents.

Static — fixed content stored on the server and simply retrieved. Dynamic — created by the server when the request arrives (CGI, PHP, JSP). Active — a program sent to the client and run there (JavaScript, applets). The classification is by where the computation happens.

Draw the HTTP request and response message formats.

Request: request line (method, URL, version), header lines, blank line, optional body. Response: status line (version, status code, status phrase), header lines, blank line, body. The only structural difference is the first line.

Name six HTTP methods.

GET (retrieve), POST (send data), HEAD (header only), PUT (store), DELETE (remove), TRACE (echo for diagnostics), OPTIONS (which methods are supported), CONNECT (tunnelling proxy).

Give the five status code classes with an example of each.

1xx informational (100 Continue); 2xx success (200 OK); 3xx redirection (301 Moved Permanently, 304 Not Modified); 4xx client error (404 Not Found); 5xx server error (500 Internal Server Error).

Compare persistent and non-persistent HTTP, with the timing formulas.

Non-persistent (HTTP/1.0): one TCP connection per object, closed after each; about 2 RTT per object. Persistent (HTTP/1.1 default): one connection for many objects; about 1 RTT for setup plus 1 RTT per object. Persistence also makes the Content-Length header necessary, since the connection closing no longer marks the end.

Explain how cookies work and why they exist.

HTTP is stateless, so cookies add state. The server creates a cookie with an identifier, domain, path and expiry, sends it in a Set-Cookie header, the client stores it under that domain, and returns it in a Cookie header on every later request. Used for sessions, baskets and personalisation; the concerns are privacy (third-party tracking) and security (a stolen session cookie impersonates the user).

What is a proxy server, and how does it check freshness?

A server between clients and the origin server that caches recent responses, reducing latency, external traffic and origin load, and providing a point for filtering and logging. It checks freshness with a conditional GET carrying If-Modified-Since; an unchanged document returns 304 Not Modified with no body.
