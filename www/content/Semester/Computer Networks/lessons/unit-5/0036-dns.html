DNS — Domain Name System

The namespace, zones and servers, the two resolution methods, caching, and the resource record types. The recursive-versus-iterative diagram is the single most-drawn figure in Unit V.

Exam strategy

"Explain DNS with the resolution process" is a 10-mark near-certainty. Structure it as: what DNS is → the namespace diagram (an inverted tree) → the server hierarchy → recursive and iterative resolution, drawn as two separate diagrams → caching. The two diagrams are where the marks are; the difference between them is the sub-question that separates answers.

What DNS is and why it exists

People use names; the network uses IP addresses. DNS is the distributed directory that maps a domain name to an IP address.

Why not one central file? — the "why distributed" answer

The original Internet did use one file, hosts.txt, copied to every machine. That fails on four counts, and naming all four is the full-mark answer:

  1. A single point of failure — if that server dies, the entire Internet stops resolving names.
  2. Traffic volume — one machine could not answer every query on the Internet.
  3. Distance — a single server is far away from most of the world, so lookups are slow.
  4. Maintenance — the file would have to be updated constantly and redistributed everywhere.

DNS solves all four by being hierarchical and distributed: no server holds everything, and each organisation maintains its own part.

The domain namespace

The namespace is an inverted tree with the root at the top. It has a maximum of 128 levels, from level 0 (root) downward.

TermMeaning
LabelEach node has a label of up to 63 characters. The root's label is null (empty).
Domain nameThe sequence of labels from a node up to the root, separated by dots. Maximum 255 characters.
FQDNFully Qualified Domain Name — ends with a null label, i.e. a trailing dot: www.example.com.
PQDNPartially Qualified Domain Name — does not reach the root; a suffix is added by the resolver.
DomainA subtree of the namespace — a node and everything below it.

Zones and servers

Domain vs zone — the distinction that is tested A domain is a subtree of the namespace.
A zone is what a server is actually responsible for.
If a server has not delegated any part of its domain, zone = domain. If it has delegated subdomains to other servers, the zone is the domain minus the delegated parts.
Server typeRole
Root serverIts zone is the whole tree. It usually does not store information itself; it delegates to TLD servers. There are 13 logical root server addresses worldwide.
Primary serverStores a file about its zone, and creates, maintains and updates it. The authoritative source.
Secondary serverTransfers the complete zone file from a primary and serves it, but cannot update it. It exists for redundancy and load sharing. The transfer is called a zone transfer — and this is the one DNS operation that uses TCP rather than UDP, because the file may be large and must arrive complete.
Local / resolver serverThe server a host is configured to ask. It performs the resolution on the host's behalf and caches the answers.

Resolution: recursive and iterative

The resolver is the client-side component that asks the questions. There are two ways for the query to proceed, and the distinction is the exam's favourite.

Recursive resolutionIterative resolution
Who does the workThe server the client askedThe client (resolver) itself
The reply isThe final answer, or an errorEither the answer or a referral — "I do not know, ask this server"
Number of queries the client sendsOneSeveral — one per level of the hierarchy
LoadFalls on the serverFalls on the client
Used betweenA host and its local DNS serverThe local DNS server and the root, TLD and authoritative servers
Worked walkthrough — resolving www.example.com

The two methods are almost always used together in one lookup. Trace it:

Step 1 — recursive. The host sends one query to its local DNS server: "what is the address of www.example.com?" It then waits. It will receive either the answer or an error, and nothing in between. This part is recursive.

Steps 2 to 7 — iterative. The local server now does the work itself:

  1. Local server → root server: "www.example.com?"
    Root replies: "I do not know, but here is the .com TLD server."
  2. Local server → .com TLD server: "www.example.com?"
    TLD replies: "I do not know, but here is the authoritative server for example.com."
  3. Local server → authoritative server for example.com: "www.example.com?"
    It replies with the actual IP address.

Step 8. The local server caches the answer and returns it to the host.

The sentence that ties it together, and is worth a mark: the host-to-local-server half is recursive; the local-server-to-hierarchy half is iterative. That is why a diagram of a real lookup shows one arrow out and back at the top, and a fan of arrows below it.

Why the split makes sense: the host is a simple device and should not have to walk a hierarchy, so it delegates. The root and TLD servers answer an enormous volume of queries and cannot afford to chase referrals on anyone's behalf, so they refer instead.

Caching

When a server receives an answer for a name outside its own zone, it stores it in cache before passing it on. The next request for that name is answered immediately.

PointDetail
BenefitDrastically reduces search time and traffic, especially for the root and TLD servers.
The riskA cached mapping can become out of date if the real address changes.
Fix 1 — TTLThe authoritative server attaches a time to live to every record, saying how long it may be cached. When the TTL expires the entry is discarded.
Fix 2 — markingA cached reply is marked unauthoritative so the asker knows it did not come from the authoritative source, and can ask again if it needs certainty.

Resource records and messages

SOAStart of Authority — the zone's parameters: primary server, admin contact, serial number, refresh and TTL values

DNS messages come in two kinds, query and response, and both use the same format: a header plus four sections — question, answer, authoritative, and additional. A query carries only the header and question sections; a response fills in the rest.

Three one-mark facts

DNS uses UDP port 53 for queries, because a query and reply are one small packet each and a handshake would cost more than the exchange.
It uses TCP for zone transfers, because the whole zone file must arrive complete and it may be large.
It also falls back to TCP when a response exceeds 512 bytes — the traditional UDP message limit.

Check yourself

Retrieval practice

1. In recursive resolution, the client receives:

Recursive means the server carries the burden and returns a definitive result. Referrals are the iterative pattern, used between the local server and the root, TLD and authoritative servers.

2. A zone differs from a domain in that a zone is:

A domain is a subtree of the namespace; a zone is the part of it a given server actually serves. If nothing has been delegated the two coincide, but once subdomains are handed to other servers the zone is the domain minus those parts.

3. DNS uses TCP rather than UDP for:

A zone file must arrive complete and may be large, so it needs TCP's reliability. Ordinary queries use UDP port 53 because a handshake would cost more than the two-packet exchange — though TCP is also used when a response exceeds 512 bytes.

4. A cached DNS entry is discarded when:

TTL is attached by the authoritative server to bound how stale a cached answer can become. Cached replies are also marked unauthoritative, so the asker knows it did not come from the source and can re-ask if it needs certainty.

5. Which record type maps a domain to its mail server?

MX is the mail exchange record, carrying a preference value so several servers can be ranked. NS names the authoritative name server, CNAME defines an alias, and PTR does reverse lookups from address to name.

6. A single central hosts file was abandoned mainly because:

Four reasons: single point of failure, unmanageable traffic volume, distance from most of the world, and constant maintenance and redistribution. A hierarchical distributed system fixes all four at once.

Recall without looking

What is DNS, and why is it distributed rather than centralised?

A distributed directory mapping domain names to IP addresses. A single central file fails on four counts: single point of failure, query volume beyond one machine, distance from most of the world, and constant maintenance and redistribution. A hierarchical distributed design fixes all four.

Define label, domain name, FQDN and PQDN.

Label — the name of a node, up to 63 characters; the root's label is null. Domain name — the sequence of labels from a node to the root, dot-separated, up to 255 characters. FQDN — ends at the root, with a trailing dot. PQDN — does not reach the root; the resolver adds a suffix.

Name the three kinds of top-level domain.

Generic (com, org, net, edu, gov, mil, int); country codes (in, uk, us, jp, often subdivided as ac.in or co.in); and inverse (in-addr.arpa) for reverse address-to-name lookups.

Distinguish domain from zone, and name the server types.

A domain is a subtree of the namespace; a zone is what a server is actually responsible for — the domain minus any delegated subdomains. Servers: root (zone is the whole tree, delegates to TLDs), primary (creates and maintains the zone file), secondary (receives it by zone transfer, cannot update it), and local/resolver (queried by hosts, and caches).

Compare recursive and iterative resolution.

Recursive — the queried server does the work and returns the final answer or an error; the client sends one query; the load falls on the server; used between a host and its local DNS server. Iterative — the server returns a referral naming the next server to ask; the client sends several queries, one per level; the load falls on the client; used between the local server and the root, TLD and authoritative servers.

Walk through resolving www.example.com.

The host sends one recursive query to its local server. The local server then queries iteratively: the root refers it to the .com TLD server, which refers it to the authoritative server for example.com, which returns the address. The local server caches the answer and returns it to the host.

Why is caching used, what is the risk, and how is it managed?

Caching cuts search time and traffic, especially at the root and TLD servers. The risk is stale mappings. Managed by a time-to-live attached by the authoritative server, after which the entry is discarded, and by marking cached replies unauthoritative.

Name seven DNS record types.

A (IPv4), AAAA (IPv6), NS (authoritative name server), CNAME (alias to canonical name), MX (mail exchange, with preference), SOA (start of authority — zone parameters), PTR (reverse lookup).
