The Application Layer and Client-Server Model

The paradigms applications are built on, the socket interface, and the map of which protocol sits on which transport and port. Short, but it organises the seven lessons that follow.

Exam strategy

Rarely a question on its own — more often the opening paragraph of a longer application-layer answer, and the source of one-mark questions about ports and paradigms. The two things genuinely worth memorising: the client-server vs P2P table (which also appeared in Unit I, so it is free marks twice), and the protocol/transport/port table at the end of this lesson.

Where the application layer sits

The application layer is the top layer, and it is where the user — human or software — actually meets the network. Two properties distinguish it from every layer below:

  • It runs on hosts only, never in the network. Routers implement layers 1–3 and have no application layer at all. This is why new applications can be deployed without changing a single router — the reason the Internet has been able to evolve so fast.
  • It is the only layer that provides services directly to the user, rather than to the layer above it.

In the TCP/IP model, the application layer absorbs OSI's session and presentation layers. Their functions still exist — dialog control, encryption, compression, format translation — but they are the application protocol's own responsibility rather than a separate layer's.

The one-line contrast

In client-server, capacity is fixed and the server is the bottleneck. In P2P, capacity grows with demand, because every new user is also a new supplier. That single sentence explains why file distribution moved to P2P while everything transactional stayed client-server.

Hybrid systems

Most real systems are neither pure form. A hybrid uses a central server for coordination — finding peers, authenticating, indexing — and direct peer-to-peer transfer for the data. BitTorrent's tracker works this way. One line on hybrids is a good addition to any paradigm answer.

The socket interface

A socket is the interface between an application process and the transport layer — the door through which a process pushes data into, and pulls it out of, the network. It is a software abstraction, not hardware.

Socket address, again Socket address = IP address + port number
A connection is identified by the pair of socket addresses, one at each end.

Because a connection is identified by the pair, a web server can hold thousands of simultaneous connections on the same port 80 — each is distinguished by the client's address and ephemeral port. This is worth stating whenever a question asks how one server serves many clients at once.

The order of the calls

A TCP client-server exchange Server: socket() → bind() → listen() → accept() → read()/write() → close()
Client: socket() → connect() → write()/read() → close()

Two observations that get asked: only the server calls bind, listen and accept (it must claim a known port and wait), and only the client calls connect (it initiates). The asymmetry of the calls mirrors the asymmetry of the roles.

The pattern behind the table — state it rather than just listing

Everything that moves substantial data or must not lose any of it uses TCP — HTTP, FTP, SMTP, TELNET. Everything that is a short request-and-reply, or must work before a connection is possible, uses UDP — DNS, DHCP, SNMP, TFTP. If you are asked which transport a protocol uses and cannot recall it, that rule will usually get you there.

What an application-layer protocol has to define

A short list that makes a good opening paragraph for any "explain protocol X" answer:

  • The types of message exchanged — requests, responses, commands.
  • The syntax of each type — what fields it has and how they are delimited.
  • The semantics of each field — what the values mean.
  • The rules for when a process sends a message and how it responds.

These are the same three elements — syntax, semantics, timing — from the definition of a protocol in Lesson 1, applied at this layer.

Check yourself

Retrieval practice

1. Routers do not implement the application layer. The consequence is that:

Routers implement layers 1–3 only, so the application layer runs on hosts alone. That is precisely why the Internet has been able to absorb the web, streaming and everything since without touching the core.

2. In the client-server paradigm, a conversation is always started by:

The server runs continuously and passively, holding a well-known port. It never initiates. That asymmetry is exactly why only the server calls bind, listen and accept, and only the client calls connect.

3. A web server can hold thousands of connections on port 80 because:

The identifying tuple is server IP and port plus client IP and port. Since every client contributes a different ephemeral port, all those connections stay distinct while sharing the server's single port 80.

4. Which protocol runs over UDP rather than TCP?

DHCP must work before the client has an IP address, so no connection could be established and it must broadcast — neither of which TCP can do. The general rule: short request-reply or pre-connection protocols use UDP, bulk or lossless ones use TCP.

5. The main scalability advantage of P2P over client-server is that:

In client-server, capacity is fixed and every new client only adds load. In P2P every new user is also a new supplier, so the system is self-scaling. Central security is the client-server advantage, not the P2P one.

Recall without looking

Give two properties that distinguish the application layer from lower layers.

It runs on hosts only and never in the network — routers implement layers 1–3 and have no application layer, which is why new applications need no change to any router. And it is the only layer providing services directly to the user rather than to the layer above.

Give six differences between client-server and P2P.

Fixed roles vs every peer both; server runs continuously vs no always-on server; the client always initiates vs either peer; server needs a permanent well-known address vs changing addresses; server is a bottleneck and single point of failure vs self-scaling with none; strong central security vs weak per-peer security.

What is a hybrid system?

One that uses a central server for coordination — finding peers, authenticating, indexing — and direct peer-to-peer transfer for the data itself. BitTorrent's tracker is the standard example.

Define a socket and name the three types.

A software interface between an application process and the transport layer. Stream socket (TCP, connection-oriented, reliable byte stream); datagram socket (UDP, connectionless, message oriented); raw socket (directly on IP, bypassing transport, used by tools such as ping).

Give the socket call sequence for a TCP client and server.

Server: socket, bind, listen, accept, read/write, close. Client: socket, connect, write/read, close. Only the server binds, listens and accepts; only the client connects.

Give the port and transport for DNS, DHCP, FTP, HTTP, SMTP, POP3 and IMAP4.

DNS 53/UDP; DHCP 67 and 68/UDP; FTP 21 control and 20 data/TCP; HTTP 80/TCP; SMTP 25/TCP; POP3 110/TCP; IMAP4 143/TCP. Also SSH 22, TELNET 23, TFTP 69/UDP, SNMP 161/UDP, HTTPS 443.

What must an application-layer protocol define?

The types of message exchanged, the syntax of each type, the semantics of each field, and the rules for when messages are sent and how they are responded to — syntax, semantics and timing applied at this layer.
