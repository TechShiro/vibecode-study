SSL, IPsec, Firewalls and Intrusion Detection

Security applied at three different layers, and the two defensive devices. Where each mechanism sits in the stack is the organising idea of the whole lesson — and the last lesson of the syllabus.

Exam strategy

Usually two or three short questions rather than one long one. "Compare SSL and IPsec" — and the answer starts with which layer each operates at, because everything else follows from that. "Explain types of firewall" — packet filter versus proxy, with the layer each works at. "Explain IDS and its types" — two classifications, by placement and by detection method; giving both is what distinguishes a full answer.

The organising idea — write this first Security can be applied at any layer, and where it sits decides what it protects:
Application layer → PGP (mail) — protects one application
Transport layer → SSL / TLS — protects any TCP application that asks for it
Network layer → IPsec — protects all traffic, transparently, without the application knowing

SSL and TLS

SSL (Secure Sockets Layer) and its standardised successor TLS (Transport Layer Security) sit between the application layer and TCP. HTTP running over SSL/TLS is HTTPS, on port 443.

ServiceHow
ConfidentialityData encrypted with a symmetric session key
IntegrityA message authentication code (MAC) on every record
Server authenticationThe server presents a digital certificate signed by a certificate authority
Client authenticationOptional — requested by the server only when needed

The four SSL protocols

ProtocolJob
Handshake ProtocolThe important one. Negotiates the cipher suite, authenticates the server (and optionally the client), and establishes the shared session keys.
Record ProtocolCarries the actual data: it fragments, compresses, adds a MAC, encrypts and adds a header. Every other SSL protocol travels inside it.
Change Cipher Spec ProtocolA single byte, signalling "everything after this point uses the newly negotiated keys".
Alert ProtocolReports errors and warnings — bad certificate, handshake failure, close notify.

The handshake, in four phases

SSL handshake Phase 1 — establish security capabilities. ClientHello (version, random number, cipher suites offered, session id) → ServerHello (the chosen version, its own random, the chosen cipher suite).
Phase 2 — server authentication and key exchange. The server sends its certificate, optionally a key exchange message, optionally a certificate request, then ServerHelloDone.
Phase 3 — client authentication and key exchange. The client verifies the certificate, sends its own if asked, and sends the pre-master secret encrypted with the server's public key.
Phase 4 — finish. Both sides derive the same master secret and session keys from the pre-master secret and the two randoms, exchange ChangeCipherSpec, and send Finished messages that are already encrypted.
The one sentence that explains the whole handshake

SSL uses asymmetric cryptography exactly once — to get a symmetric session key safely across — and then uses that fast symmetric key for all the actual data. This is the hybrid scheme from Lesson 41, deployed. It is why the handshake is comparatively slow and the subsequent transfer is not, and it is the single most valuable sentence you can write about SSL.

Why the two random numbers? Because the master secret is derived from the pre-master secret and both randoms, an attacker who replays an old handshake produces different keys. The randoms are what make each session unique — a good 2-mark point.

IPsec

IPsec secures traffic at the network layer, which gives it a property SSL does not have: it protects every application transparently, without any of them being modified or even aware. It is built into IPv6 and available as an add-on for IPv4.

The AH/ESP fact examiners test

AH provides authentication and integrity but NOT confidentiality. ESP provides all three. If a question asks which to use when the data must be kept secret, the answer is ESP. This one row is the most commonly asked fact about IPsec.

Security Association (SA) is IPsec's other named concept: a one-way (simplex) logical connection defining the algorithms, keys and parameters in use. Because it is one-way, two SAs are needed for bidirectional communication. An SA is identified by three things: the Security Parameter Index (SPI), the destination IP address, and the protocol (AH or ESP).

Firewalls

A firewall is a device installed between an organisation's internal network and the rest of the Internet. It inspects traffic and forwards or blocks it according to a policy — it is a filter, not an encryptor, and that distinction is worth stating.

Packet-filter firewallProxy (application gateway) firewall
LayerNetwork and transport (3 and 4)Application (7)
Decides usingSource and destination IP address, source and destination port, and protocolThe content of the message itself
Can it inspect data?No — it sees headers onlyYes — it understands the application protocol
SpeedFastSlow — it must parse the whole message
Example rule"Block all inbound traffic to port 23 (TELNET)""Block any HTTP request whose URL contains a banned word"
WeaknessCannot distinguish two messages on the same port, so it cannot block some web traffic and allow the restHigher overhead; a separate proxy is needed for each application protocol

A third kind is worth a line: a stateful inspection firewall tracks the state of each connection, so it can allow an inbound packet only if it belongs to a connection that an internal host started. This is what modern firewalls do, and it fixes the packet filter's inability to tell a reply from an unsolicited approach.

The one-line contrast

A packet filter reads the envelope; a proxy reads the letter. The packet filter is fast but blind to content; the proxy sees everything but is slow and needs one implementation per protocol.

Intrusion Detection Systems

An IDS monitors network or system activity for malicious activity or policy violations and raises an alert. It is a monitor, not a barrier.

IDS vs IPS vs firewall — the distinction to state

A firewall blocks traffic according to a policy, at the perimeter. An IDS detects and alerts but does not stop anything. An IPS (Intrusion Prevention System) detects and actively blocks. The neat summary: a firewall is a locked door, an IDS is a burglar alarm, an IPS is an alarm that also bolts the door.

The trade-off in one line

Signature-based detection is accurate about attacks it already knows; anomaly-based detection can catch new attacks but cries wolf. That trade-off is the substance of any IDS comparison question, and real systems use both together.

Types of intruder

One line each, sometimes asked: masquerader (an outsider using a legitimate user's account), misfeasor (a legitimate user exceeding their privileges), and clandestine user (someone who has seized supervisory control and is suppressing the audit trail).

Check yourself

Retrieval practice

1. The essential difference between SSL and IPsec is that:

The layer decides everything else. SSL protects only applications written to call it; IPsec sits below the transport layer and protects all traffic without applications knowing. The typical uses are also the other way round — IPsec for VPNs, SSL for HTTPS.

2. Which IPsec protocol provides confidentiality?

AH gives authentication and integrity but no encryption; ESP gives all three, which is why ESP is what is actually deployed. This single row is the most commonly asked IPsec fact.

3. IPsec tunnel mode differs from transport mode in that tunnel mode:

Tunnel mode wraps the whole datagram inside a new one, hiding the original addresses — which is exactly what a VPN needs. Transport mode protects the payload only, leaves the header visible, and is used host to host.

4. During the SSL handshake, asymmetric cryptography is used to:

Asymmetric cryptography is used once, to get a symmetric key across safely; all the bulk data is then encrypted symmetrically because that is roughly a thousand times faster. That hybrid design is the point of the handshake.

5. A packet-filter firewall cannot:

It reads headers only — addresses, ports and protocol — so two messages on the same port look identical to it. Distinguishing them needs a proxy firewall, which parses the application content.

6. Anomaly-based intrusion detection, compared with signature-based:

Anomaly detection compares against a baseline of normal behaviour, so a novel attack can stand out — but so can unusual legitimate activity, hence the false positives. Signature databases and their updates belong to the other method, and host-versus-network is a separate classification entirely.

Recall without looking

Which layer does each security mechanism operate at, and what follows from that?

Application layer — PGP, protecting one application. Transport layer — SSL/TLS, protecting any TCP application written to call it. Network layer — IPsec, protecting all traffic transparently without applications knowing. The layer determines the scope of protection and whether applications must be modified.

Name the four SSL protocols and what each does.

Handshake — negotiates the cipher suite, authenticates the server, establishes session keys. Record — fragments, compresses, adds a MAC, encrypts, and carries everything else. Change Cipher Spec — one byte signalling that the new keys are now in use. Alert — reports errors and warnings.

Describe the four phases of the SSL handshake.

1. Establish security capabilities — ClientHello and ServerHello exchange version, randoms and cipher suite. 2. Server authentication and key exchange — certificate, optional key exchange, optional certificate request, ServerHelloDone. 3. Client authentication and key exchange — the client verifies the certificate and sends the pre-master secret encrypted with the server's public key. 4. Finish — both derive the master secret and session keys, exchange ChangeCipherSpec and encrypted Finished messages.

Why does SSL use both asymmetric and symmetric cryptography?

Asymmetric is used once to get a symmetric session key across safely, because public keys can be distributed openly. All bulk data is then encrypted symmetrically because that is roughly a thousand times faster. This is the hybrid scheme in practice.

Compare AH and ESP.

AH provides authentication and integrity and also authenticates the outer IP header, but provides no confidentiality; protocol number 51. ESP provides authentication, integrity and encryption, covering the payload only; protocol number 50. ESP is what is actually deployed.

Compare IPsec transport and tunnel modes.

Transport mode protects the IP payload only, adds no new header, is used host to host, and leaves the original addresses visible. Tunnel mode protects the entire original datagram, adds a new outer IP header, is used router to router or host to router, hides the original addresses, and is what VPNs use.

What is a Security Association?

A one-way (simplex) logical connection defining the algorithms, keys and parameters in use — so two are needed for bidirectional communication. It is identified by the Security Parameter Index (SPI), the destination IP address, and the protocol (AH or ESP).

Compare packet-filter and proxy firewalls.

Packet filter works at layers 3 and 4 using IP addresses, ports and protocol; it is fast but sees headers only, so it cannot distinguish two messages on the same port. Proxy works at layer 7 and inspects message content, so it can filter precisely, but it is slow and needs a separate implementation per protocol. Stateful inspection firewalls track connection state so a reply can be told from an unsolicited approach.

Distinguish firewall, IDS and IPS.

A firewall blocks traffic by policy at the perimeter — a locked door. An IDS detects and alerts but stops nothing — a burglar alarm. An IPS detects and actively blocks — an alarm that also bolts the door.

Give both IDS classifications.

By placement: NIDS at a strategic network point, seeing packets for many hosts but blind to encrypted traffic; HIDS on one host, seeing system calls, file changes and logs in detail. By detection method: signature-based, matching known attack patterns — accurate but blind to new attacks; anomaly-based, flagging deviations from a learned baseline — can catch new attacks but produces many false positives.
