DHCP — Dynamic Host Configuration Protocol

The DORA sequence, the four items a host receives, leases and renewal, and the relay agent that lets one server cover many networks. A short lesson with one diagram that must be drawn correctly.

Exam strategy

A 5-mark question, and the marks are concentrated in one place: the DORA sequence, drawn as a four-arrow timeline with the message names labelled. Learn the acronym, learn which two messages are broadcast and why, and add the relay agent in one line — that last point is what separates a 5 from a 3.

The problem DHCP solves

Every host needs an IP address before it can communicate. Assigning them by hand does not scale, and it fails completely for laptops and phones that move between networks. DHCP assigns addresses automatically and temporarily.

The four items a host receivesWhy it needs it
IP addressIts own identity on the network
Subnet maskTo tell which destinations are local and which need a router
Default gateway (router address)Where to send anything not on the local network
DNS server addressTo resolve names into addresses

Naming all four is worth a mark on its own. A common weak answer says only "an IP address" — DHCP supplies a complete configuration, which is exactly what makes it more useful than its predecessors.

DHCP's ancestors

ProtocolProvidesLimitation
RARPAn IP address, from a MAC addressBroadcast at the data link layer, so it cannot cross a router — every network segment needs its own server. Supplies nothing but the address.
BOOTPA full configuration, over UDP, so it can be relayed across routersStatic — the administrator must pre-configure a table binding each MAC address to an IP address. No good for a visitor's laptop.
DHCPThe same as BOOTP, plus dynamic allocation from a pool— It is backward compatible with BOOTP.
The one-line progression

RARP gives an address but cannot cross a router. BOOTP crosses routers but needs every client pre-registered. DHCP does both and allocates dynamically. That sentence answers "how does DHCP differ from BOOTP and RARP?" completely.

The three allocation methods

MethodHow it worksUsed for
Static (manual) allocationThe administrator binds a specific IP address to a specific MAC address. The client always gets the same address.Servers, printers — anything that must be findable at a fixed address
Automatic allocationThe server assigns a permanent address from the pool the first time the client appears, and keeps it for that client.Stable, long-lived clients
Dynamic allocationThe server leases an address from the pool for a limited time; it returns to the pool when the lease ends.The normal case — laptops, phones, guests

DORA — the four-message exchange

DORA Discover → Offer → Request → Acknowledge
#MessageFrom → ToCastWhat happens
1DHCPDISCOVERClient → ServerBroadcastThe client has no address, so it uses source 0.0.0.0 and destination 255.255.255.255. It does not know where any server is, so it must broadcast.
2DHCPOFFERServer → ClientBroadcastThe server offers an address plus the mask, gateway and DNS server, and a lease time. It must broadcast because the client still has no address to be unicast to.
3DHCPREQUESTClient → ServerBroadcastThe client formally requests the offered address. It broadcasts so that any other servers that made offers learn they were not chosen and can return their offered addresses to their pools.
4DHCPACKServer → ClientBroadcast or unicastThe server confirms the lease. The client may now use the address.
Two "why" questions attached to DORA

Why is DISCOVER broadcast? The client has no address and does not know where any DHCP server is. It can only shout.
Why is REQUEST broadcast rather than unicast to the chosen server? Because several servers may have offered. Broadcasting the request tells the unchosen servers to release the addresses they had reserved. Without this, offered-but-unused addresses would leak out of the pool.

The other DHCP messages

MessageMeaning
DHCPNAKThe server refuses the request — for example the address is no longer available, or the client has moved to a different network.
DHCPDECLINEThe client rejects the offered address, typically because an ARP probe showed it is already in use.
DHCPRELEASEThe client gives the address back before the lease expires — sent on a clean shutdown.
DHCPINFORMThe client already has an address but wants the other configuration parameters.

Leases and renewal

Addresses are leased, not given. The lease is what makes reuse possible: a laptop that leaves the network stops renewing, and its address returns to the pool automatically.

The two renewal timers T1 = 50% of the lease time — the client tries to renew with the original server (unicast).
T2 = 87.5% of the lease time — if renewal failed, the client tries to rebind with any DHCP server (broadcast).
100% — if both failed, the client must stop using the address and start again from DHCPDISCOVER.

The two-stage design is deliberate: at T1 the original server is preferred so the client keeps the same address, and only if that server is unreachable does the client widen its search.

Worked example — lease timers

Q. A client receives a lease of 8 hours at 09:00. At what times will it attempt renewal, rebinding, and give up the address?

T1 = 50% of 8 hours = 4 hours → 13:00, unicast renewal to the original server.

T2 = 87.5% of 8 hours = 7 hours → 16:00, broadcast rebinding to any server.

Expiry = 8 hours → 17:00, the address must be abandoned and DORA restarted.

Sanity check: T1 < T2 < expiry always, and 87.5% is 7/8 — the fraction is chosen so the client gets a second chance while still leaving an eighth of the lease as margin.

The DHCP relay agent

The problem: DHCPDISCOVER is a broadcast, and routers do not forward broadcasts. So a naive design needs a DHCP server on every single network segment.

The solution: a relay agent — usually the router itself — is configured with the DHCP server's address. It receives the broadcast, converts it to a unicast addressed to the server, and forwards it. Replies come back to the relay agent, which broadcasts them onto the client's network.

This is the reason one central DHCP server can serve an entire campus. Mention it in any DHCP answer; it is a distinct mark and most answers omit it.

Where the ports come from

DHCP uses UDP, server port 67 and client port 68. UDP rather than TCP because the client has no IP address, so no connection could be established, and because the exchange must be broadcast — which TCP cannot do at all. The two fixed ports exist so that broadcast replies can be distinguished from other broadcast traffic.

DHCP 4-Phase DORA Lease Allocation Handshake

Check yourself

Retrieval practice

1. The DORA sequence stands for:

Four messages: the client discovers, the server offers, the client requests, the server acknowledges. Drawing this as a labelled four-arrow timeline is most of the marks on a DHCP question.

2. The DHCPREQUEST message is broadcast rather than unicast because:

Several servers may have offered addresses and reserved them. The broadcast request tells the unchosen ones to release what they held — otherwise offered-but-unused addresses would leak out of the pool.

3. A DHCP relay agent exists because:

DISCOVER is a broadcast and stops at the router. The relay agent — usually the router itself — converts it to a unicast aimed at the configured server and forwards it, which is what lets one server cover a whole campus.

4. At T1, which is 50% of the lease, the client:

T1 tries the original server by unicast, so the client keeps the same address. Only at T2 — 87.5% — does it widen the search by broadcasting to any server, and only at 100% must it abandon the address.

5. DHCP improves on BOOTP mainly by:

BOOTP already crossed routers and supplied a full configuration — those are its improvements over RARP. Its limitation was being static: every client had to be pre-registered by MAC address. Dynamic pool allocation is DHCP's addition.

6. DHCP uses UDP rather than TCP because:

No address means no connection can be established, and TCP cannot broadcast at all. UDP guarantees nothing — the client simply retries if a message is lost.

Recall without looking

What four items does DHCP supply a host?

IP address, subnet mask, default gateway (router address), and DNS server address — a complete configuration, not just an address.

Compare RARP, BOOTP and DHCP.

RARP gives only an address and broadcasts at the data link layer, so it cannot cross a router — every segment needs a server. BOOTP gives a full configuration over UDP and can be relayed across routers, but is static: every client must be pre-registered by MAC address. DHCP does everything BOOTP does and adds dynamic allocation from a pool.

Name the three allocation methods.

Static (manual) — a specific address bound to a specific MAC, for servers and printers. Automatic — a permanent address assigned from the pool on first appearance. Dynamic — a leased address returned to the pool when the lease ends; the normal case.

Describe the DORA sequence, saying which messages are broadcast and why.

DHCPDISCOVER — broadcast, because the client has no address (source 0.0.0.0) and does not know where a server is. DHCPOFFER — broadcast, because the client still has no address to unicast to. DHCPREQUEST — broadcast, so unchosen servers release the addresses they reserved. DHCPACK — confirms the lease.

Name four DHCP messages besides the DORA four.

DHCPNAK (server refuses the request), DHCPDECLINE (client rejects the address, usually because an ARP probe found it in use), DHCPRELEASE (client returns the address early), DHCPINFORM (client has an address but wants the other parameters).

State the two lease timers and what happens at each.

T1 at 50% of the lease — unicast renewal to the original server, so the client keeps the same address. T2 at 87.5% — broadcast rebinding to any server. At 100% the client must stop using the address and restart from DHCPDISCOVER.

What is a relay agent and why is one needed?

DHCPDISCOVER is a broadcast and routers do not forward broadcasts, so without help every segment would need its own server. A relay agent — usually the router — is configured with the server's address, converts the broadcast to a unicast, forwards it, and broadcasts the reply back onto the client's network.
