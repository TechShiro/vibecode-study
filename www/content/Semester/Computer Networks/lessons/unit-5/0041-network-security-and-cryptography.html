Network Security Fundamentals and Cryptography

The security goals, the attacks against each, symmetric versus asymmetric cryptography, and RSA worked end to end with real numbers. The one numerical in the security half of this syllabus.

Exam strategy

Three questions. (1) "Explain the goals of security and the attacks that threaten them" — organise the attacks under the goals rather than as a flat list; that structure is worth marks by itself. (2) "Compare symmetric and asymmetric cryptography" — a table. (3) An RSA numerical — the only calculation in this half, and entirely mechanical once you can do modular exponentiation.

The three security goals

GoalMeansThreatened by
ConfidentialityInformation is accessible only to authorised parties — hidden from everyone else, both in storage and in transit.Snooping, traffic analysis
IntegrityInformation can be changed only by authorised parties, and only in authorised ways.Modification, masquerading, replaying, repudiation
AvailabilityInformation is available to authorised parties when needed. Information nobody can reach is useless.Denial of service

These three are usually called the CIA triad. Every attack below maps onto exactly one of them, which is why organising the answer this way is stronger than listing attacks at random.

The attacks

Passive attacks — threaten confidentiality

The attacker's goal is to obtain information, not to alter it. Nothing on the system changes, so passive attacks are very hard to detect — the emphasis must be on prevention (encryption) rather than detection. Stating that asymmetry is worth a mark.

AttackWhat happens
SnoopingUnauthorised access to or interception of data. Reading a message in transit. Prevented by encryption, which makes the intercepted data unintelligible.
Traffic analysisEven when the content is encrypted, the attacker learns from the pattern — who is talking to whom, how often, how much, and when. Prevented by traffic padding and by hiding the endpoints.

Active attacks — threaten integrity and availability

The attacker alters data or affects the system. Active attacks can be detected but are hard to prevent absolutely, so the emphasis is the reverse of passive attacks: detect and recover.

AttackWhat happensGoal threatened
ModificationThe attacker intercepts and changes the message before forwarding it.Integrity
Masquerading (spoofing)The attacker impersonates somebody else to gain access they do not have.Integrity
ReplayingThe attacker captures a valid message and re-sends it later — for example replaying a bank transfer. Note that the message is genuine, which is why replay defeats simple authentication and needs timestamps or nonces.Integrity
RepudiationOne of the two legitimate parties denies having sent or received a message. Unusual in that the attacker is a participant, not an outsider. Countered by digital signatures.Integrity
Denial of serviceThe attacker slows or stops the service for legitimate users — by flooding requests, or by deleting responses so that the sender retries and worsens the load. SYN flooding from Lesson 31 is the classic example.Availability

Security services and mechanisms

Security services (ITU-T X.800)Security mechanisms

The relationship worth one sentence: services are what we want; mechanisms are how we get it — and encipherment (cryptography) is the mechanism that underpins nearly all of them.

Cryptography basics

The vocabulary Plaintext — the original readable message
Ciphertext — the transformed, unreadable message
Cipher — the encryption/decryption algorithm
Key — the value the cipher operates with
Encryption: C = Ek(P)  ·  Decryption: P = Dk(C)

Kerckhoffs's principle, worth stating: the security must rest entirely on the secrecy of the key, never on the secrecy of the algorithm. Algorithms are published and analysed publicly; only keys are secret. An algorithm that must stay hidden to be safe has never been reviewed and is not trustworthy.

Symmetric key cryptography

PropertyDetail
KeysOne shared secret key for both encryption and decryption
SpeedFast — suitable for bulk data
Main problemKey distribution — how do the two parties agree a secret key over an insecure channel in the first place?
Number of keysFor n people to communicate pairwise: n(n − 1)/2 keys — the same formula as mesh topology links, and it scales just as badly.
AlgorithmsDES (56-bit key, 64-bit blocks, 16 rounds, Feistel structure — now insecure, the key is too short), 3DES, AES (128/192/256-bit keys, 128-bit blocks — the current standard), RC4, Blowfish

Two structural divisions worth naming: substitution vs transposition (replacing symbols vs reordering them), and stream cipher vs block cipher (encrypting one symbol at a time vs a fixed-size block at a time).

Asymmetric (public key) cryptography

The two keys and their two uses Each party has a public key (published) and a private key (kept secret).

For confidentiality: encrypt with the receiver's PUBLIC key; only the receiver's private key can decrypt.
For authentication (digital signature): encrypt with the sender's PRIVATE key; anyone can verify with the sender's public key, and only the sender could have produced it.
The rule that decides every public-key question

Encrypt with the key of the person you want to be the ONLY one able to read it. Sending a secret to Bob? Use Bob's public key — only Bob holds the matching private key. Proving you wrote something? Use your own private key — only you hold it, so a successful check with your public key proves authorship. Getting these the wrong way round is the single commonest error in this topic.

The comparison table

BasisSymmetricAsymmetric
KeysOne shared keyA key pair — public and private

Key distributionDifficult — the shared secret must travel securelyEasy — the public key can be published openly
Keys for n usersn(n − 1)/22n (a pair each)

AlgorithmsDES, 3DES, AES, RC4RSA, Diffie-Hellman, ECC, DSA
The hybrid answer — add this and the answer is complete

Real systems use both. Asymmetric cryptography is used once, to exchange a symmetric session key; the bulk data is then encrypted symmetrically because that is fast. You get public key's easy distribution and symmetric key's speed. This is exactly what SSL/TLS does — see the next lesson.

RSA

The RSA procedure 1. Choose two large primes p and q.
2. Compute n = p × q.
3. Compute φ(n) = (p − 1)(q − 1).
4. Choose e with 1 < e < φ(n) and gcd(e, φ(n)) = 1.
5. Compute d such that e × d ≡ 1 (mod φ(n)).
6. Public key = (e, n)  ·  Private key = (d, n)

Encrypt: C = Pe mod n   ·   Decrypt: P = Cd mod n
Worked numerical — RSA end to end

Q. Take p = 7 and q = 11, with e = 13. Find the public and private keys, then encrypt the plaintext P = 5 and decrypt the result to verify.

Step 1 — n: n = 7 × 11 = 77

Step 2 — φ(n): φ(77) = (7 − 1)(11 − 1) = 6 × 10 = 60

Step 3 — check e: gcd(13, 60) = 1 ✓ so e = 13 is valid.

Step 4 — find d such that 13d ≡ 1 (mod 60).
Try multiples: 13 × 37 = 481, and 481 = 8 × 60 + 1 = 480 + 1. ✓
So d = 37.

Keys: public = (13, 77), private = (37, 77)

Step 5 — encrypt P = 5: C = 513 mod 77

Use square and multiply rather than computing 513 directly:
52 = 25
54 = 252 = 625; 625 − (8 × 77 = 616) = 9
58 = 92 = 81; 81 − 77 = 4
13 = 8 + 4 + 1, so 513 = 58 × 54 × 51 = 4 × 9 × 5 = 180
180 − (2 × 77 = 154) = 26

Ciphertext C = 26

Step 6 — decrypt: P = 2637 mod 77

262 = 676; 676 − 616 = 60
264 = 602 = 3600; 3600 − (46 × 77 = 3542) = 58
268 = 582 = 3364; 3364 − (43 × 77 = 3311) = 53
2616 = 532 = 2809; 2809 − (36 × 77 = 2772) = 37
2632 = 372 = 1369; 1369 − (17 × 77 = 1309) = 60

37 = 32 + 4 + 1, so 2637 = 2632 × 264 × 261 = 60 × 58 × 26
60 × 58 = 3480; 3480 − (45 × 77 = 3465) = 15
15 × 26 = 390; 390 − (5 × 77 = 385) = 5 ✓

The original plaintext P = 5 is recovered.

Three things that decide the marks here:

  • Reduce mod n at every step. Never compute 513 or 2637 in full — the numbers become unmanageable and the arithmetic goes wrong.
  • Write the exponent as a sum of powers of two (13 = 8+4+1, 37 = 32+4+1) and multiply the corresponding squares. This is square-and-multiply, and it is the method examiners expect.
  • Always decrypt to check. If you do not get the original plaintext back, something is wrong — and the verification itself usually earns a mark.

Why RSA is secure: the public key gives away n and e. To find d an attacker needs φ(n), which needs p and q — that is, they must factor n. For a 2048-bit n that is computationally infeasible. RSA's security rests on the difficulty of factoring large numbers.

Hash functions and digital signatures

Property of a cryptographic hashMeaning
Fixed-length outputAny input length produces a fixed-size digest — SHA-1 gives 160 bits, SHA-256 gives 256 bits, MD5 gives 128 bits.
One-wayComputing the digest from the message is easy; recovering the message from the digest is infeasible.
Collision resistantIt is infeasible to find two different messages with the same digest.
Avalanche effectChanging one bit of the input changes about half the output bits.
Digital signature — how it actually works Signing: hash the message → encrypt the digest with the sender's private key → send message + signature.
Verifying: hash the received message → decrypt the signature with the sender's public key → compare the two digests. If they match, the message is authentic and unaltered.

Why sign the digest and not the whole message? Because asymmetric encryption is slow, and the digest is a small fixed size however large the message. Signing a 100 MB file means encrypting 256 bits, not 100 MB. This is a standard 2-mark sub-question.

A digital signature provides three services, and naming all three is the full answer: authentication (only the holder of the private key could have produced it), integrity (any change breaks the digest match), and non-repudiation (the sender cannot later deny it). It does not provide confidentiality — the message itself is still in the clear unless separately encrypted.

Check yourself

Retrieval practice

1. Traffic analysis threatens which security goal, and why is it hard to stop?

Encryption hides content but not who talks to whom, how often and how much. Countering it needs traffic padding and endpoint hiding, not stronger encryption.

2. To send a confidential message to Bob, Alice encrypts it with:

Encrypt with the key of the person who should be the only one able to read it — only Bob holds the matching private key. Using Alice's private key would be a signature, proving authorship rather than providing secrecy.

3. With p = 5, q = 11 and e = 3, the value of φ(n) is:

φ(n) = (p−1)(q−1) = 4 × 10 = 40. The value 55 is n itself, which is a different quantity — confusing the two is the standard slip and it breaks the rest of the calculation.

4. RSA is secure because an attacker who knows n and e would have to:

Finding d requires φ(n), which requires p and q, which requires factoring n. For a 2048-bit n that is infeasible. Note also that the private key is never distributed at all, which is what makes public-key distribution easy.

5. Digital signatures sign the message digest rather than the message because:

Signing a 100 MB file means encrypting a 256-bit digest, not 100 MB. Note too that signing gives authentication, integrity and non-repudiation, but not confidentiality — the message travels in the clear unless separately encrypted.

6. Replay attacks succeed against simple authentication because:

Nothing about the message is wrong — it was valid when first sent. That is why replay needs timestamps or nonces to defeat it, rather than stronger signatures or encryption.

Recall without looking

Name the three security goals and the attacks against each.

Confidentiality — threatened by snooping and traffic analysis. Integrity — threatened by modification, masquerading, replaying and repudiation. Availability — threatened by denial of service. Together, the CIA triad.

Distinguish passive from active attacks, including how each is countered.

Passive attacks obtain information without altering anything, so they are very hard to detect and the emphasis is on prevention through encryption. Active attacks alter data or affect the system; they can be detected but are hard to prevent absolutely, so the emphasis is detection and recovery.

Define snooping, modification, masquerading, replaying, repudiation and denial of service.

Snooping — unauthorised interception of data. Modification — intercepting and altering a message. Masquerading — impersonating another party. Replaying — capturing a valid message and re-sending it later. Repudiation — a legitimate party denying they sent or received a message. Denial of service — slowing or stopping the service for legitimate users.

State Kerckhoffs's principle.

Security must rest entirely on the secrecy of the key, never on the secrecy of the algorithm. Algorithms are published and publicly analysed; only keys are secret.

Give six differences between symmetric and asymmetric cryptography.

One shared key vs a public/private pair; fast vs about a thousand times slower; difficult vs easy key distribution; n(n−1)/2 vs 2n keys for n users; suited to bulk data vs key exchange and signatures; no non-repudiation vs non-repudiation through digital signatures. Algorithms: DES, 3DES, AES vs RSA, Diffie-Hellman, ECC.

How do real systems combine the two?

Asymmetric cryptography is used once to exchange a symmetric session key; the bulk data is then encrypted symmetrically for speed. This gives public key's easy distribution with symmetric key's performance — exactly what SSL/TLS does.

State the RSA procedure and both formulas.

Choose primes p and q; n = pq; φ(n) = (p−1)(q−1); choose e with gcd(e, φ(n)) = 1; find d with e·d ≡ 1 mod φ(n). Public key (e, n), private key (d, n). Encrypt C = Pᵉ mod n; decrypt P = C^d mod n. Security rests on the difficulty of factoring n.

Describe how a digital signature is created and verified, and what it provides.

Signing: hash the message, encrypt the digest with the sender's private key, send message plus signature. Verifying: hash the received message, decrypt the signature with the sender's public key, compare the digests. It provides authentication, integrity and non-repudiation — but not confidentiality.

Name four properties of a cryptographic hash function.

Fixed-length output regardless of input size; one-way, so the message cannot be recovered from the digest; collision resistant, so two messages with the same digest cannot feasibly be found; and the avalanche effect, where one changed input bit alters about half the output bits.
