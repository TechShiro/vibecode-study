HDLC and Point-to-Point Protocol

Two named data link protocols. HDLC gives you configurations, transfer modes and three frame types; PPP gives you a frame format, four transition phases and two authentication protocols. Both are descriptive — diagram-and-list questions, no numericals.

Exam strategy

Asked as "Explain HDLC with its frame format" and "Explain PPP and its frame format" — 5 marks each, sometimes combined into 10. Draw the frame format as a labelled box diagram with byte counts; that diagram is most of the mark. Then list the field meanings in one line each. For HDLC, the three frame types (I, S, U) are the part most often asked on its own.

HDLC — High-level Data Link Control

HDLC is a bit-oriented protocol for communication over point-to-point and multipoint links. It implements the ARQ mechanisms of the previous lesson. It was developed by ISO, and is the basis from which PPP, LAPB, LAPD and Frame Relay were derived.

Station types and configurations

StationRole
Primary stationControls the link. The frames it sends are called commands.
Secondary stationOperates under the primary's control. The frames it sends are called responses.
Combined stationActs as both primary and secondary; may send both commands and responses.
ConfigurationDescription
UnbalancedOne primary station and one or more secondary stations. Point-to-point or multipoint.
BalancedTwo combined stations, of equal status. Point-to-point only.

The two transfer modes — a standard 3-mark question

NRM — Normal Response ModeABM — Asynchronous Balanced Mode
ConfigurationUnbalanced — one primary, one or more secondariesBalanced — two combined stations
Who may initiateOnly the primary. A secondary may transmit only when the primary permits it.Either station may initiate transmission at any time.
Link typePoint-to-point or multipointPoint-to-point only
UsageOlder, master–slave arrangementsThe common mode today

(An older third mode, ARM — Asynchronous Response Mode, lets a secondary start transmission without permission but keeps the primary responsible for the link. Mention it in one line if you have room.)

The HDLC frame format

HDLC frame | Flag | Address | Control | Information | FCS | Flag |
   8 bits     8 or more    8 or 16    variable    16 or 32    8 bits
FieldSizePurpose
Flag8 bitsThe pattern 01111110, marking the start and end of the frame. Bit stuffing keeps this pattern out of the data.
Address1 or more bytesThe address of the secondary station. If the primary created the frame it holds the to address; if a secondary created it, the from address.
Control1 or 2 bytesUsed for flow and error control. Its first bits determine the frame type — see below.
InformationVariableThe user data, or network management information in a U-frame.
FCS2 or 4 bytesFrame Check Sequence — the error-detection field, a CRC-16 or CRC-32.

The three frame types

TypeControl field starts withCarriesPurpose
I-frame (Information)0User data, plus control information piggybacked on itTransporting user data from the network layer, and acknowledging received frames at the same time
S-frame (Supervisory)10No user dataFlow and error control only — acknowledgements (RR), negative acknowledgements (REJ, SREJ), and stopping the sender (RNR)
U-frame (Unnumbered)11System management informationLink setup and disconnection, mode setting (SNRM, SABM, DISC), and reporting

Inside the control field, three sub-fields recur and are worth naming: N(S) the send sequence number, N(R) the receive sequence number (the acknowledgement), and the P/F bit (Poll/Final) — called Poll when the primary sends it and Final when a secondary does.

Piggybacking — a 2-mark definition worth having ready

Piggybacking is attaching an acknowledgement for received frames onto an outgoing data frame, instead of sending a separate acknowledgement frame. It saves bandwidth and reduces the number of frames on the link. In HDLC it is the N(R) field carried inside an I-frame.

PPP — Point-to-Point Protocol

PPP is the most common protocol for point-to-point access — the one used when a user dials in to an ISP, and on serial and DSL links. It is byte-oriented, unlike HDLC.

What PPP provides — and what it deliberately does not

PPP providesPPP does not provide
A frame format for encapsulating dataFlow control — a sender may send as many frames as it wishes
A link control protocol (LCP) for establishing, maintaining and terminating the linkError control — errors are detected by the FCS but corrupted frames are simply discarded, not retransmitted
Authentication protocols (PAP and CHAP)Addressing for a multipoint configuration — it is point-to-point only
Network control protocols (NCPs), one per network-layer protocol carriedSupport for multipoint links or sophisticated flow control
A way to carry multiple network-layer protocols over one link

The lack of flow and error control is a genuine design decision, not an oversight: PPP is used over links where higher layers (TCP) already provide these services, and duplicating them would only add overhead.

The PPP frame format

PPP frame | Flag | Address | Control | Protocol | Payload | FCS | Flag |
  1 byte     1 byte     1 byte    1 or 2 bytes   variable   2 or 4    1 byte
FieldValue / sizePurpose
Flag01111110 (0x7E)Frame delimiter. Because PPP is byte-oriented, it uses byte stuffing, not bit stuffing — the escape byte is 0x7D.
AddressConstant 11111111 (0xFF)The broadcast address. It is fixed because there is only one possible recipient on a point-to-point link.
ControlConstant 00000011 (0x03)Fixed, indicating an unnumbered frame — PPP does not use sequence numbers.
Protocol1 or 2 bytesStates what the payload contains — user data, or LCP, or an NCP, or an authentication packet. This is the field that lets PPP multiplex several protocols.
PayloadVariable, default max 1500 bytesThe data being carried.
FCS2 or 4 bytesCRC for error detection.
The point examiners test on the PPP frame

The address and control fields are constants (0xFF and 0x03) and carry no information. Why? On a point-to-point link there is exactly one other station, so there is nothing to address and no sequence to manage. Say this explicitly — it shows you understand the frame rather than having memorised the byte values.

The transition phases

PPP link lifecycle Dead → Establish → (Authenticate) → Network → Open → Terminate → Dead
PhaseWhat happens
DeadThe link is not in use; no carrier is present.
EstablishA carrier is detected. LCP packets negotiate options and set up the link.
AuthenticateOptional. If required during establishment, PAP or CHAP packets are exchanged. Failure returns the link to Dead.
NetworkNCP packets configure the network-layer protocol(s) to be carried — for example IPCP for IP.
OpenData transfer takes place.
TerminateThe connection is closed down and the link returns to Dead.

The three protocol groups inside PPP

ProtocolFull nameJob
LCPLink Control ProtocolEstablishing, maintaining, configuring and terminating the link; negotiating options such as maximum payload size and authentication method.
APAuthentication ProtocolsPAP and CHAP — verifying the identity of the party at the other end.
NCPNetwork Control ProtocolsOne per network-layer protocol carried — IPCP for IP, and others for IPX, AppleTalk, and so on. This is how PPP carries several protocols over one link.

PAP vs CHAP — a reliable 3-mark comparison

BasisPAP — Password Authentication ProtocolCHAP — Challenge Handshake Authentication Protocol
StepsTwo-step: the user sends name and password; the system replies with an authenticate-ack or authenticate-nak.Three-step: the system sends a challenge (a random value); the user replies with a hash of the challenge and its password; the system computes the same hash and compares.
Password on the linkSent in plain textNever sent — only a hash of it travels
SecurityWeak — anyone tapping the link learns the passwordStrong — the challenge changes every time, so a captured response is useless later
When it runsOnce, at connection setupAt setup and repeatedly during the session

Check yourself

Retrieval practice

1. In HDLC Normal Response Mode (NRM), a secondary station may transmit:

NRM is the unbalanced, master–slave mode: one primary controls the link and secondaries speak only when permitted. Either station transmitting freely describes ABM, the balanced mode used today.

2. An HDLC frame whose control field begins with the bits 10 is:

The pattern is: 0 → I-frame, 10 → S-frame, 11 → U-frame. S-frames carry acknowledgements and rejects but never user data; that is exactly why they exist.

3. The address field of a PPP frame is always 0xFF because:

With exactly one station at the other end, addressing is meaningless, so the field is fixed at the broadcast value and carries no information. The same reasoning fixes the control field at 0x03.

4. Which service does PPP deliberately not provide?

PPP has an FCS (detection), PAP/CHAP (authentication) and LCP (establishment). What it omits is flow control, and it also omits error correction — bad frames are detected and discarded, never retransmitted.

5. CHAP is more secure than PAP mainly because:

PAP sends the password in plain text. CHAP sends only a hash of a random challenge, so an intercepted response cannot be reused — and CHAP repeats the check periodically during the session rather than only at setup.

6. In the PPP transition phases, NCP packets are exchanged during the:

LCP runs in Establish, PAP/CHAP in Authenticate, NCP in Network, and only then does Open carry data. Keep the three protocol groups paired with their phases — that pairing is the question.

Recall without looking

What is HDLC, and what are its station types and configurations?

A bit-oriented ISO protocol for point-to-point and multipoint links, implementing ARQ. Stations: primary (sends commands), secondary (sends responses), combined (both). Configurations: unbalanced (one primary with secondaries) and balanced (two combined stations, point-to-point only).

Compare NRM and ABM.

NRM is unbalanced: one primary, and a secondary may transmit only with the primary's permission; point-to-point or multipoint. ABM is balanced: two combined stations, either may initiate transmission at any time; point-to-point only, and the common mode today.

Draw and label the HDLC frame format.

Flag (8 bits, 01111110) | Address (1+ bytes, the secondary's address) | Control (1–2 bytes, sets the frame type) | Information (variable) | FCS (2 or 4 bytes, CRC-16/32) | Flag (8 bits). Bit stuffing prevents the flag pattern appearing in the data.

Name the three HDLC frame types and their purposes.

I-frame (control starts 0) — carries user data with piggybacked acknowledgement. S-frame (starts 10) — flow and error control only, no user data; RR, RNR, REJ, SREJ. U-frame (starts 11) — link management: setup, disconnection, mode setting.

Define piggybacking.

Attaching an acknowledgement for received frames onto an outgoing data frame instead of sending a separate acknowledgement frame, saving bandwidth and reducing the frame count. In HDLC it is the N(R) field inside an I-frame.

Draw and label the PPP frame format.

Flag (0x7E) | Address (constant 0xFF) | Control (constant 0x03) | Protocol (1–2 bytes, says what the payload is) | Payload (variable, default max 1500 bytes) | FCS (2 or 4 bytes) | Flag. Byte stuffing with escape byte 0x7D.

List the PPP transition phases.

Dead → Establish (LCP) → Authenticate (optional, PAP/CHAP) → Network (NCP) → Open (data transfer) → Terminate → Dead.

What are LCP, AP and NCP?

LCP — Link Control Protocol, establishes, maintains, configures and terminates the link. AP — Authentication Protocols, PAP and CHAP. NCP — Network Control Protocols, one per network-layer protocol carried (IPCP for IP), which is how PPP carries several protocols on one link.

PAP vs CHAP — three differences.

PAP is two-step and sends the password in plain text, once at setup, and is weak. CHAP is three-step (challenge, hashed response, verification), never sends the password, repeats during the session, and is strong because the challenge changes each time.
