Framing, Flow and Error Control

Byte stuffing and bit stuffing, then the three sliding-window protocols — Stop-and-Wait ARQ, Go-Back-N and Selective Repeat — with the efficiency formulas and the window-size rules that the numericals are built from.

Exam strategy

Three questions come from here. (1) Bit stuffing — a 3-mark "apply bit stuffing to this bit stream", pure mechanics. (2) Compare the three ARQ protocols — a table, 5–10 marks; keep a row for window sizes, it is the most-asked single fact. (3) An efficiency numerical — compute a, then apply the formula. Learn a = Tp/Tt first; every efficiency formula in this lesson is built on it.

Framing

The data link layer packs bits into frames, so that each frame is distinguishable from the next. Framing adds a sender address and a destination address, and separates one message from another.

ApproachHow it worksProblem
Fixed-size framingEvery frame is the same size, so the size itself acts as the delimiter. No boundary marking is needed.Inflexible; wasteful when messages are short. Used in ATM (53-byte cells).
Variable-size framingNeeds an explicit way to mark where a frame ends and the next begins — by character-oriented or bit-oriented framing.The delimiter pattern may appear inside the data, which is exactly what stuffing solves.

Character-oriented (byte) framing and byte stuffing

Data is carried as 8-bit characters. A flag byte is added at the start and end of the frame to mark its boundaries.

The problem: if the data is not text but an image or a program, a byte identical to the flag may occur inside the data, and the receiver will think the frame ended early.

Byte stuffing (character stuffing) Sender: whenever a byte equal to the flag or to the escape (ESC) character appears in the data, insert an extra ESC byte immediately before it.
Receiver: on seeing an ESC, discard it and treat the next byte as data, not as a delimiter.

Note the second half of the rule: ESC itself must also be stuffed, otherwise a genuine ESC in the data would be swallowed. Students routinely forget this case, and it is often the point of the question.

Bit-oriented framing and bit stuffing

The frame is treated as a sequence of bits, delimited by the flag 01111110 (a 0, six 1s, a 0). The data must never contain six consecutive 1s, or the receiver would read a false flag.

Bit stuffing — the rule Sender: after five consecutive 1s in the data, insert a 0.
Receiver: after five consecutive 1s, remove the following 0.
Worked example — bit stuffing

Q. Apply bit stuffing to the data 0111111111100011.

Scan left to right, counting consecutive 1s and inserting a 0 after every run of five:

Original:  0 11111 11111 00011

After the first five 1s → insert 0. After the next five 1s → insert 0.

Stuffed: 0 11111 0 11111 0 00011 = 011111011111000011

Two rules that decide the marks:

  • The stuffed 0 is inserted after exactly five 1s, not after six. Counting to six is the standard error.
  • The count restarts from zero after each inserted 0 — the stuffed 0 breaks the run.

Sanity check: read your answer back and confirm that nowhere does it contain six consecutive 1s. If it does, you missed an insertion.

Flow control and error control

TermDefinition
Flow controlA set of procedures that restricts the amount of data a sender may send before waiting for acknowledgement, so that a fast sender does not overwhelm a slow receiver.
Error controlDetection and retransmission of damaged or lost frames. In the data link layer it is based on Automatic Repeat Request (ARQ) — retransmission of a frame whenever an error is detected.

Protocols split into two families: those for noiseless channels (idealised, taught as a stepping stone) and those for noisy channels (the real ones).

ChannelProtocols
NoiselessSimplest Protocol (no flow or error control at all); Stop-and-Wait Protocol (flow control only)
NoisyStop-and-Wait ARQ; Go-Back-N ARQ; Selective Repeat ARQ

The efficiency framework — learn this first

The three quantities everything is built on Tt = transmission time = frame size ÷ bandwidth
Tp = propagation time = distance ÷ propagation speed
a = Tp / Tt
Efficiency of the three protocols Stop-and-Wait:   η = 1 / (1 + 2a)
Go-Back-N:   η = N / (1 + 2a)  (capped at 1)
Selective Repeat:   η = N / (1 + 2a)  (capped at 1)
Throughput = η × bandwidth
Optimal window size N = 1 + 2a  (the N that makes efficiency 100%)

Why 1 + 2a? The sender spends 1 unit of time transmitting the frame, then waits a units for it to propagate, plus a units for the acknowledgement to come back. Total cycle = 1 + 2a units, of which only 1 was useful. (Strictly there is also the acknowledgement's own transmission time, but it is normally neglected unless the question gives it.)

1. Stop-and-Wait ARQ

  • The sender sends one frame, then stops and waits for its acknowledgement before sending the next.
  • Frames and acknowledgements are numbered alternately 0 and 1 — a 1-bit sequence number is enough.
  • The sender keeps a copy of the last frame sent and starts a timer. If the timer expires before the ACK arrives, the frame is resent.
  • Sender window = 1, receiver window = 1.
  • Handles: lost frames (timer expires, resend), damaged frames (receiver discards, timer expires), and lost acknowledgements (timer expires, resend; the receiver detects the duplicate by its sequence number and discards it).
  • Weakness: the link sits idle for the whole round trip. On a long or fast link this is catastrophic — see the numerical below.

Piggybacking

Piggybacking is a technique used in bidirectional data communication to improve link efficiency by attaching an outgoing acknowledgement (ACK) to an outgoing data frame, rather than sending a separate, dedicated ACK frame.

Why Piggybacking Saves Massive Bandwidth

In two-way communication (Node A ↔ Node B), if Node B needs to send an ACK to Node A, sending a separate control frame wastes an entire frame header, preamble, and channel time. With piggybacking, Node B waits briefly: when its upper layer produces a data packet for Node A, it writes Node A's ACK number directly into the data frame's header. To avoid indefinite delays if Node B has no outgoing data, an acknowledgement timer is used — if the timer expires before outgoing data is ready, a standalone ACK is dispatched immediately.

Sliding Window Control Variables · $S_f$, $S_n$, $R_n$

To implement sliding window flow control reliably, the sender and receiver maintain precise pointer variables tracking outstanding, unacknowledged frames:

VariableFull NameMaintained byFunction in the Protocol
$S_f$Send window, firstSenderHolds the sequence number of the oldest outstanding (unacknowledged) frame. Points to the left edge of the sender window.
$S_n$Send window, nextSenderHolds the sequence number of the next frame to be sent. As each frame is transmitted, $S_n$ advances by 1.
$S_{ ext{size}}$Send window sizeSenderThe maximum number of unacknowledged frames allowed: $S_{ ext{size}} = 2^m - 1$ (Go-Back-N) or $2^{m-1}$ (Selective Repeat). Window constraint: $S_n - S_f < S_{ ext{size}}$.

Window Dynamics Formula $$ ext{Frames in flight (sent but unacknowledged)} = (S_n - S_f) \pmod{2^m}$$ $$ ext{Window is completely full when: } S_n - S_f = S_{ ext{size}}$$ $$ ext{When a valid ACK arrives for frame } k: S_f \leftarrow (k + 1) \pmod{2^m} ext{ (window slides forward!)}$$

2. Go-Back-N ARQ

  • The sender may transmit several frames before receiving acknowledgements — it keeps a window of outstanding frames.
  • The receiver window is 1: it accepts frames only in order and silently discards any out-of-order frame.
  • Acknowledgements are cumulative — an ACK for frame n means "all frames up to and including n received".
  • If a frame is lost or damaged, that frame and every frame sent after it are retransmitted. Hence the name.
  • Sender window = 2m − 1 (m = number of sequence-number bits); receiver window = 1.
Why the Go-Back-N window is 2m − 1, not 2m

If the window were the full 2m, then after all acknowledgements were lost the receiver could not tell a retransmitted frame 0 from a brand-new frame 0 — the sequence numbers would have wrapped exactly. Leaving one number unused makes the two cases distinguishable. This "why" is asked directly and is worth two marks.

3. Selective Repeat ARQ

  • The receiver keeps a window too, and accepts and buffers out-of-order frames.
  • Only the specific damaged or lost frame is retransmitted, not everything after it.
  • Uses NAK (negative acknowledgement) to request a particular frame, alongside ACKs.
  • Sender window = receiver window = 2m−1 — both are half the sequence-number space.
  • Cost: the receiver needs buffering and must sort frames back into order, so it is more complex than Go-Back-N. That complexity is why Go-Back-N remained common despite being less efficient.

Worked numerical 1 — Stop-and-Wait efficiency

Q. A 1 Mbps link carries frames of 1000 bits. The one-way propagation delay is 20 ms. Find the efficiency and the throughput of Stop-and-Wait ARQ.

Tt = 1000 bits ÷ 106 bps = 1 ms

Tp = 20 ms (given)

a = Tp/Tt = 20/1 = 20

Efficiency η = 1/(1 + 2a) = 1/(1 + 40) = 1/41 = 0.0244 = 2.44%

Throughput = 0.0244 × 1 Mbps = 24.4 kbps

Comment worth writing: a 1 Mbps link is delivering 24.4 kbps — 97.5% of the capacity is wasted waiting. This is precisely why sliding-window protocols exist. Always add this sentence; it converts a calculation into an answer.

Worked numerical 2 — the window size needed for 100% efficiency

Q. For the same link, what sender window size would give full utilisation, and how many bits are needed for the sequence number under Go-Back-N?

Optimal N = 1 + 2a = 1 + 40 = 41 frames

Sequence-number bits under Go-Back-N: the window is 2m − 1, so we need
2m − 1 ≥ 41  →  2m ≥ 42  →  m = 6 (since 26 = 64, giving a window of 63)

Under Selective Repeat the window is 2m−1, so
2m−1 ≥ 41  →  2m−1 ≥ 41  →  m − 1 = 6  →  m = 7 (giving a window of 64)

The comparison to state: Selective Repeat needs one more sequence-number bit than Go-Back-N for the same window, because it spends half its sequence space on the receiver window. That is part of the price of its higher efficiency.

Worked numerical 3 — Go-Back-N efficiency with a given window

Q. On the same link (a = 20), Go-Back-N is used with a sender window of 15. Find the efficiency and throughput.

η = N/(1 + 2a) = 15/41 = 0.366 = 36.6%

Throughput = 0.366 × 1 Mbps = 366 kbps

Sanity check: N = 15 is less than the optimal 41, so efficiency must be below 100% — 36.6% is consistent. If a formula ever gives you an efficiency above 1, cap it at 100%: the window is larger than needed and the link is simply saturated.

Worked Problem 1 · Stop-and-Wait Minimum Frame Size for 50% Efficiency (Mam's Material)

Question: A link operates at a bit rate of $4 ext{ kbps}$ with a one-way propagation delay of $20 ext{ ms}$. Calculate the minimum frame size required to achieve at least 50% channel efficiency using the Stop-and-Wait protocol.

Given: Bit rate $B = 4 ext{ kbps} = 4000 ext{ bps}$, Propagation delay $T_p = 20 ext{ ms} = 20 imes 10^{-3} ext{ s}$
Target Efficiency $\eta = 0.50$ (50%)

Formula: $\eta = rac{T_t}{T_t + 2 T_p}$
$0.50 = rac{T_t}{T_t + 2(20 imes 10^{-3})} = rac{T_t}{T_t + 40 imes 10^{-3}}$
$0.50 imes (T_t + 0.040) = T_t \implies 0.020 = 0.50 T_t \implies T_t = 0.040 ext{ s} = 40 ext{ ms}$

Since $T_t = rac{ ext{Frame Size } L}{ ext{Bit Rate } B}$:
$ ext{Minimum Frame Size } L = T_t imes B = (40 imes 10^{-3} ext{ s}) imes (4000 ext{ bps}) = \mathbf{160 ext{ bits (or 20 bytes)}}.$
Worked Problem 2 · Network Throughput Calculation (Mam's Material)

Question: A network with a transmission bandwidth of $10 ext{ Mbps}$ passes an average of 12,000 frames per minute, with each frame carrying an average of 10,000 bits. Calculate the throughput of this network and the channel utilization.

Data transferred per minute = $12,000 ext{ frames} imes 10,000 ext{ bits/frame} = 1.2 imes 10^8 ext{ bits}$
Data transferred per second (Throughput) = $ rac{1.2 imes 10^8 ext{ bits}}{60 ext{ s}} = 2 imes 10^6 ext{ bps} = \mathbf{2 ext{ Mbps}}$

Channel Utilization = $ rac{ ext{Throughput}}{ ext{Bandwidth}} = rac{2 ext{ Mbps}}{10 ext{ Mbps}} = 0.20 = \mathbf{20\%}.$
Worked Problem 3 · Selective Repeat Frame Loss Action (Mam's Material)

Question: In a Selective Repeat ARQ system with 3-bit sequence numbers, the sender transmits frames 0, 1, 2, 3, and 4. Frame 2 is lost due to channel noise, while frames 0, 1, 3, and 4 arrive uncorrupted. Detail the exact actions taken by the receiver and sender.

1. Receiver Action:
• Frames 0 and 1 arrive in order: Receiver accepts them, delivers them to the network layer, sends ACK 1 and ACK 2, and advances its receive window.
• Frame 2 is missing. Next, Frame 3 arrives: The receiver recognizes Frame 2 was skipped. It immediately transmits a negative acknowledgement NAK 2. It does not discard Frame 3; it stores Frame 3 in its buffer.
• Frame 4 arrives: Stored in the receiver buffer alongside Frame 3.

2. Sender Action:
• Upon receiving NAK 2 (or upon expiration of Frame 2's dedicated timer), the sender retransmits only Frame 2.
• Unlike Go-Back-N, the sender does not retransmit frames 3 or 4.

3. Recovery: When the retransmitted Frame 2 arrives safely, the receiver takes Frame 2, pulls buffered frames 3 and 4 out of memory, delivers frames 2, 3, and 4 in correct order to the network layer, and advances its window past frame 4!

Check yourself

Retrieval practice

1. In bit stuffing, the sender inserts a 0 after:

The flag is 01111110 — six 1s. Stuffing after five 1s guarantees six can never occur in the data. Waiting for six would already have created the false flag. The escape-character rule belongs to byte stuffing, not bit stuffing.

2. In Go-Back-N ARQ, an out-of-order frame arriving at the receiver is:

Receiver window = 1 means frames are accepted only in strict order; anything else is dropped. Buffering out-of-order frames and using NAKs is Selective Repeat — that is the whole difference between the two.

3. With m = 4 sequence-number bits, the sender window sizes for Go-Back-N and Selective Repeat are:

Go-Back-N: 2^m − 1 = 15. Selective Repeat: 2^(m−1) = 8. Selective Repeat's sender window is smaller for the same m, because half the sequence space is reserved for the receiver window.

4. A link has Tt = 2 ms and Tp = 8 ms. The efficiency of Stop-and-Wait is:

a = Tp/Tt = 8/2 = 4. η = 1/(1 + 2a) = 1/(1 + 8) = 1/9 ≈ 11.8%. Forgetting to double a — the acknowledgement has to travel back too — is the usual slip.

5. Why is the Go-Back-N sender window limited to 2m − 1 rather than 2m?

With a full 2^m window, losing all acknowledgements would leave the receiver unable to distinguish a resent frame 0 from a new frame 0 — the numbering wraps exactly. Leaving one number unused breaks that ambiguity.

6. Byte stuffing must also escape the ESC character itself because:

The receiver's rule is "on seeing ESC, drop it and take the next byte literally". An unescaped data ESC would therefore be silently deleted and the byte after it misread. Forgetting this case is the standard mistake on byte-stuffing questions.

Recall without looking

Define framing, and name the two approaches to variable-size framing.

Framing packs bits into frames so each is distinguishable from the next, adding sender and destination addresses. Variable-size framing is done either character-oriented (byte stuffing with flag and ESC bytes) or bit-oriented (bit stuffing with the flag 01111110).

State the byte stuffing and bit stuffing rules.

Byte stuffing: the sender inserts an extra ESC before any data byte equal to the flag or to ESC; the receiver discards an ESC and treats the next byte as data. Bit stuffing: the sender inserts a 0 after five consecutive 1s; the receiver removes the 0 that follows five 1s.

Define flow control and error control.

Flow control restricts how much data a sender may transmit before waiting for acknowledgement, so a fast sender does not overwhelm a slow receiver. Error control detects and retransmits damaged or lost frames; in the data link layer it is based on Automatic Repeat Request (ARQ).

Write the efficiency formulas and the definition of a.

a = Tp/Tt, where Tt = frame size/bandwidth and Tp = distance/propagation speed. Stop-and-Wait: η = 1/(1 + 2a). Go-Back-N and Selective Repeat: η = N/(1 + 2a), capped at 1. Throughput = η × bandwidth. Optimal window N = 1 + 2a.

Give the sender and receiver window sizes for all three protocols.

Stop-and-Wait: sender 1, receiver 1. Go-Back-N: sender 2^m − 1, receiver 1. Selective Repeat: sender 2^(m−1), receiver 2^(m−1).

Go-Back-N vs Selective Repeat — four differences.

Receiver window 1 vs 2^(m−1); out-of-order frames discarded vs buffered; on error, retransmits the frame and all after it vs only that frame; cumulative ACKs vs individual ACKs plus NAKs. Selective Repeat also needs sorting and buffering at the receiver, so it is more complex but uses bandwidth better.

Why is the Go-Back-N window 2^m − 1?

With a full 2^m window, if every acknowledgement were lost the receiver could not distinguish a retransmitted frame 0 from a new frame 0, since the sequence numbers wrap exactly. Leaving one number unused removes the ambiguity.
