Error Detection and Correction

The most numerical lesson in the subject. Parity, LRC, checksum, CRC and Hamming code — each worked end to end with the arithmetic shown. CRC and Hamming between them appear in almost every paper.

Exam strategy

Expect a CRC numerical and a Hamming code numerical. Together they are often 15–20 marks, and they are objectively markable — you either get them right or you do not. Do the division and the parity checks slowly; almost every lost mark here is arithmetic, not understanding. Always verify your own answer at the receiver end: divide the codeword again and show the remainder is zero. That verification is usually worth a mark and it catches your own mistakes.

Types of error

TypeDefinitionWhere it happens
Single-bit errorOnly one bit of a given data unit is changed — from 1 to 0 or 0 to 1.Rare in serial transmission; more likely in parallel transmission
Burst errorTwo or more bits in the data unit have changed. The length of the burst is measured from the first corrupted bit to the last, and bits in between need not all be corrupted.The common case — noise usually lasts longer than one bit interval

Why burst errors dominate: noise typically lasts longer than the duration of one bit, so the higher the data rate, the more bits are affected by the same burst of noise. A 1 ms noise burst corrupts 10 bits at 10 kbps but 1000 bits at 1 Mbps.

Redundancy, block coding and Hamming distance

The central idea of every scheme in this lesson: redundancy — extra bits are added by the sender and used by the receiver to detect or correct errors, then discarded.

In block coding, the message is divided into datawords of k bits, and r redundant bits are added to make codewords of n = k + r bits. Of the 2n possible codewords, only 2k are valid. If the receiver gets an invalid codeword, an error has occurred.

Hamming distance d(x, y) = the number of bit positions in which x and y differ
Computed as: XOR the two words and count the 1s.

Minimum Hamming distance dmin is the smallest Hamming distance between any pair of valid codewords in the code. It determines everything the code can do:

The two capability rules To detect up to s errors:   dmin ≥ s + 1
To correct up to t errors:   dmin ≥ 2t + 1
Worked example — Hamming distance

Q. Find d(10101, 11110). If a code has dmin = 4, how many errors can it detect, and how many can it correct?

10101 ⊕ 11110 = 01011  →  three 1s  →  d = 3

Detection: dmin ≥ s + 1 → 4 ≥ s + 1 → s = 3 errors detectable

Correction: dmin ≥ 2t + 1 → 4 ≥ 2t + 1 → t ≤ 1.5 → t = 1 error correctable

The point to state: detection is always cheaper than correction. The same dmin = 4 detects three errors but corrects only one, because correcting requires knowing which valid codeword was intended, not merely that the received one is invalid.

1. Parity check (VRC)

Vertical Redundancy Check. A single parity bit is appended so that the total number of 1s in the unit becomes even (even parity) or odd (odd parity).

  • Detects: all odd numbers of bit errors (1, 3, 5 …).
  • Fails on: any even number of errors — two flipped bits leave the parity unchanged. Since burst errors commonly affect an even number of bits, simple parity is weak in practice.
  • dmin = 2, so it detects one error and corrects none.
  • Cheapest scheme; used where errors are rare and cost matters.

2. Two-dimensional parity (LRC)

Longitudinal Redundancy Check. Data is organised into a table of rows and columns. A parity bit is computed for each row (as in VRC) and for each column, giving an extra parity row at the bottom.

  • Improvement: detects all burst errors up to a length equal to the number of columns, and can locate a single-bit error at the intersection of the failing row and the failing column — so a single error can even be corrected.
  • Still fails: if two bits in one data unit are damaged and two bits in exactly the same positions in another data unit are also damaged, the checker will not detect it. Four errors arranged in a rectangle are invisible.

3. Checksum

Used mainly at the network and transport layers (IP, TCP and UDP headers), not at the data link layer.

Checksum procedure Sender: divide the data into equal-size words → add all words using one's complement addition → complement the sum → that is the checksum → send it with the data.
Receiver: add all words including the checksum → complement the result → if it is all zeros, accept; otherwise reject.

One's complement addition means: if the addition produces a carry out of the leftmost bit, that carry is added back into the rightmost bit (wrapped around).

4. Cyclic Redundancy Check (CRC)

The standard scheme at the data link layer, and the one most likely to be asked. Based on binary division, where subtraction is replaced by XOR — there are no borrows and no carries.

CRC procedure Sender: append (n − 1) zeros to the dataword, where n is the number of bits in the divisor (generator) → divide by the generator using XOR → the remainder is the CRC → replace the appended zeros with the remainder to form the codeword.
Receiver: divide the received codeword by the same generator → if the remainder is all zeros, accept; otherwise the data is corrupted.
Worked numerical — CRC, sender side

Q. Dataword = 1001, generator (divisor) = 1011. Find the codeword to be transmitted.

The divisor has 4 bits, so append 3 zeros: dividend = 1001000

Divide 1001000 by 1011 using XOR at every step:

Step 1: leading 4 bits 1001, leading bit is 1 → XOR with 1011
1001 ⊕ 1011 = 0010  → drop the leading 0, bring down the next bit (0) → 0100

Step 2: 0100, leading bit is 0 → XOR with 0000
0100 ⊕ 0000 = 0100  → drop the leading 0, bring down the next bit (0) → 1000

Step 3: 1000, leading bit is 1 → XOR with 1011
1000 ⊕ 1011 = 0011  → drop the leading 0, bring down the last bit (0) → 0110

Step 4: 0110, leading bit is 0 → XOR with 0000
0110 ⊕ 0000 = 0110  → drop the leading 0 → remainder = 110

CRC = 110

Codeword transmitted = dataword + CRC = 1001 110 = 1001110

Sanity check: the remainder must have exactly one fewer bit than the divisor. Divisor is 4 bits, remainder is 3 bits. ✓

Worked numerical — CRC, receiver side

Q. The receiver gets 1001110. Verify it using the same generator 1011.

Step 1: 1001 ⊕ 1011 = 0010 → bring down 1 → 0101

Step 2: leading 0 → 0101 ⊕ 0000 = 0101 → bring down 1 → 1011

Step 3: leading 1 → 1011 ⊕ 1011 = 0000 → bring down 0 → 0000

Step 4: leading 0 → 0000 ⊕ 0000 = 0000 → remainder = 000

Remainder is zero → the data is accepted as error-free. ✓

Always show this step in the exam. It proves your sender-side arithmetic and is frequently worth a mark of its own.

CRC generator polynomials

The divisor is usually written as a polynomial. 1011 is x3 + x + 1 (bits read as coefficients of x3, x2, x1, x0). Standard generators worth naming:

NamePolynomialUsed in
CRC-8x8 + x2 + x + 1ATM header
CRC-10x10 + x9 + x5 + x4 + x2 + 1ATM AAL
CRC-16x16 + x12 + x5 + 1HDLC
CRC-32x32 + x26 + x23 + … + x + 1Ethernet (IEEE 802.3), ZIP, PNG

Properties of a good generator polynomial (a common 3-mark theory sub-question):

  • It should have at least two terms.
  • The coefficient of x0 must be 1 (the last bit must be 1).
  • It should not divide xt + 1 for any t up to the frame length — this ensures burst errors are caught.
  • If it has the factor (x + 1), all odd numbers of errors are detected.

CRC detects: all single-bit errors; all double-bit errors (with a suitable generator); all odd numbers of errors (if the generator has the factor x + 1); and all burst errors shorter than the degree of the generator — which is why CRC-32 is so effective for Ethernet frames.

5. Hamming code — error correction

Everything so far only detects. Hamming code corrects a single-bit error by locating exactly which bit is wrong.

Number of redundant bits needed 2r ≥ m + r + 1
m = number of data bits  ·  r = number of redundancy (parity) bits

Placement rule: the r parity bits go in the positions that are powers of two — positions 1, 2, 4, 8, 16 … Data bits fill the remaining positions. Positions are numbered from 1, starting at the left.

Parity bitChecks positionsRule of thumb
p1 (position 1)1, 3, 5, 7, 9, 11 …Check 1, skip 1
p2 (position 2)2, 3, 6, 7, 10, 11 …Check 2, skip 2
p4 (position 4)4, 5, 6, 7, 12, 13, 14, 15 …Check 4, skip 4
p8 (position 8)8–15, 24–31 …Check 8, skip 8
Worked numerical — Hamming code, encoding

Q. Encode the dataword 1011 using even-parity Hamming code.

Step 1 — how many parity bits? m = 4. Try r = 3: 23 = 8 ≥ 4 + 3 + 1 = 8. ✓ So r = 3, and the codeword is 7 bits.

Step 2 — lay out the positions. Parity at 1, 2, 4; data at 3, 5, 6, 7. The data bits 1, 0, 1, 1 fill positions 3, 5, 6, 7 in order:

Position1234567
Bitp1p21p4011

Step 3 — compute each parity bit for even parity.

p1 checks positions 1, 3, 5, 7 → data there is 1, 0, 1 → sum = 2, already even → p1 = 0

p2 checks positions 2, 3, 6, 7 → data there is 1, 1, 1 → sum = 3, odd → p2 = 1

p4 checks positions 4, 5, 6, 7 → data there is 0, 1, 1 → sum = 2, already even → p4 = 0

Codeword = 0 1 1 0 0 1 1 = 0110011

Worked numerical — Hamming code, detecting and correcting

Q. The receiver gets 0110111. Find and correct the error.

Position1234567
Received bit0110111

Recompute each check. For even parity, a check gives 0 if the count of 1s is even and 1 if it is odd.

c1 = positions 1, 3, 5, 7 = 0, 1, 1, 1 → three 1s, odd → c1 = 1

c2 = positions 2, 3, 6, 7 = 1, 1, 1, 1 → four 1s, even → c2 = 0

c4 = positions 4, 5, 6, 7 = 0, 1, 1, 1 → three 1s, odd → c4 = 1

Syndrome, written c4 c2 c1 = 1 0 1 = 5 in decimal

Therefore bit 5 is in error. Flip it: position 5 goes from 1 back to 0.

Corrected codeword = 0110011, and removing the parity positions 1, 2, 4 leaves the data at positions 3, 5, 6, 7 = 1011. ✓

Two things that cost marks here: the syndrome is read c4c2c1, with the highest-numbered check as the most significant bit — reversing it gives the wrong position. And a syndrome of 000 means no error, not "error at position 0".

Hamming code's limit — state it

Standard Hamming code has dmin = 3, so it corrects one error and detects two. It cannot correct a burst error. The usual fix, worth a closing line, is to send the block column by column rather than row by row, so that a burst in transmission is spread across many codewords and appears as one single-bit error in each — each of which Hamming can then correct.

Check yourself

Retrieval practice

1. A code has dmin = 5. How many errors can it detect and correct?

dmin ≥ s + 1 gives s = 4. dmin ≥ 2t + 1 gives 5 ≥ 2t + 1, so t = 2. Detection is always the larger number — knowing something is wrong is cheaper than knowing what was intended.

2. Simple parity checking fails to detect:

Two flipped bits restore the original parity, so the receiver sees nothing wrong. Since burst errors often flip an even number of bits, this is a serious weakness in practice — and the reason CRC replaced parity on real links.

3. In CRC, the number of zeros appended to the dataword equals:

A divisor of n bits means n − 1 appended zeros, and the remainder is n − 1 bits. Checking that the remainder has one fewer bit than the divisor is the quickest way to catch a slip in the division.

4. A receiver computes a Hamming syndrome of c₄c₂c₁ = 011. This means:

The syndrome read as a binary number gives the position directly: 011 = 3. Reading it in the reverse order (110 = 6) is the standard error — c₄ is the most significant bit. A syndrome of 000 would mean no error.

5. At the receiver, a correct checksum verification produces a sum of:

The checksum is the complement of the sender's sum, so adding it back gives all 1s; complementing that gives all 0s, which is the accept condition. A remainder relates to CRC, not checksum — the two mechanisms are different.

6. How many redundancy bits are needed to Hamming-encode 7 data bits?

Test 2^r ≥ m + r + 1 upward. r = 3 gives 8 ≥ 11, which is false; r = 4 gives 16 ≥ 12, which holds. So r = 4 and the codeword is 11 bits.

Recall without looking

Define single-bit error and burst error.

Single-bit error: only one bit of the data unit is changed. Burst error: two or more bits changed; its length is measured from the first to the last corrupted bit, and bits in between need not all be corrupted. Burst errors dominate because noise usually lasts longer than one bit interval.

Define Hamming distance and state the two capability rules.

The number of bit positions in which two words differ — XOR them and count the 1s. To detect up to s errors, d_min ≥ s + 1. To correct up to t errors, d_min ≥ 2t + 1.

State the CRC procedure at sender and receiver.

Sender: append (n − 1) zeros to the dataword where n is the divisor length; divide by the generator using XOR; the remainder is the CRC; replace the appended zeros with it. Receiver: divide the received codeword by the same generator; a zero remainder means accept.

What does CRC detect?

All single-bit errors; all double-bit errors with a suitable generator; all odd numbers of errors if the generator has the factor (x + 1); and all burst errors shorter than the degree of the generator polynomial.

State the checksum procedure.

Sender: divide data into equal-size words, add them using one's complement addition (carry out of the leftmost bit is added back at the right), complement the sum, send it. Receiver: add all words including the checksum, complement; all zeros means accept.

Give the Hamming redundancy formula and the parity placement rule.

2^r ≥ m + r + 1. Parity bits go in positions that are powers of two — 1, 2, 4, 8 — numbering positions from 1 at the left. p1 checks 1,3,5,7…; p2 checks 2,3,6,7…; p4 checks 4,5,6,7….

How does the receiver locate the erroneous bit in Hamming code?

It recomputes each parity check, writing 1 where the parity fails. Reading the results as a binary number with the highest-numbered check as the most significant bit (c₄c₂c₁) gives the position of the erroneous bit directly. A syndrome of all zeros means no error.

How can Hamming code be made to handle burst errors?

Arrange the codewords in a table and send them column by column instead of row by row. A burst in transmission is then spread across many codewords, appearing as a single-bit error in each — which Hamming can correct.
