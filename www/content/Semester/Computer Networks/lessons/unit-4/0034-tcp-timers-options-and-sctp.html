TCP Timers, Options and SCTP

The four timers with the RTO calculation worked out, the seven TCP options, and SCTP — its two headline features, its cookie handshake, and the three-way comparison that closes Unit IV.

Exam strategy

Three short questions rather than one long one. "Explain TCP timers" — name all four with one line each, 4 marks. "What is Karn's algorithm?" — 3 marks, and it needs the problem stated before the fix. "Explain SCTP / compare TCP, UDP and SCTP" — 5 marks, and multi-homing and multi-streaming are the two words that must appear.

The four TCP timers

TimerPurposeWhat happens on expiry
Retransmission (RTO)Waits for an acknowledgement of a sent segmentThe segment is retransmitted, and congestion control treats it as severe congestion — cwnd drops to 1 MSS.
PersistenceHandles the zero-window deadlock — a lost window update would otherwise leave both sides waiting foreverA one-byte probe segment is sent, forcing the receiver to report its current window size.
KeepaliveDetects a connection whose other end has crashed or gone away, so idle connections do not persist for everTypically after 2 hours of idleness, probes are sent. After ten unanswered probes, 10 minutes apart, the connection is terminated.
TIME-WAIT (2MSL)Runs after the connection is closed by the active closerWaits 2 × MSL so that a lost final ACK can be re-answered and all old segments die out, then releases the connection.

Calculating the retransmission timeout

The RTO cannot be a fixed constant. Too short and TCP retransmits segments that were merely slow; too long and it takes forever to notice a real loss. So TCP measures the round-trip time continuously and adapts.

The three quantities and the formula RTTM — the measured round-trip time for one segment
RTTS — the smoothed round-trip time (a weighted running average)
RTTD — the deviation

After the first measurement:   RTTS = RTTM  ·  RTTD = RTTM / 2
After each later measurement:
  RTTS = (1 − α) × previous RTTS + α × RTTM   (α = 1/8)
  RTTD = (1 − β) × previous RTTD + β × | RTTS − RTTM |   (β = 1/4)
  RTO = RTTS + 4 × RTTD
Worked numerical — RTO calculation

Q. The first measured round-trip time is 1.5 s. A second segment measures 2.5 s. Find RTTS, RTTD and RTO after each measurement, taking α = 1/8 and β = 1/4.

After the first measurement (RTTM = 1.5):

RTTS = 1.5 s  (the first measurement is taken as-is)
RTTD = 1.5 / 2 = 0.75 s
RTO = 1.5 + 4(0.75) = 1.5 + 3.0 = 4.5 s

After the second measurement (RTTM = 2.5):

RTTS = (7/8)(1.5) + (1/8)(2.5) = 1.3125 + 0.3125 = 1.625 s

| RTTS − RTTM | = | 1.625 − 2.5 | = 0.875

RTTD = (3/4)(0.75) + (1/4)(0.875) = 0.5625 + 0.21875 = 0.78125 s

RTO = 1.625 + 4(0.78125) = 1.625 + 3.125 = 4.75 s

Two checks worth stating:

  • Use the NEW RTTS when computing RTTD, not the old one. Using the previous value is the standard error in this calculation.
  • The RTO rose from 4.5 s to 4.75 s because the second sample was slower and more variable. RTO should always be comfortably larger than RTTS — the whole point of the 4 × RTTD term is to leave headroom for variation, so that normal jitter never triggers a retransmission.

Karn's algorithm

The problem it solves must be stated first. Suppose a segment is sent, times out, and is retransmitted. An acknowledgement then arrives. Which transmission is it acknowledging? There is no way to tell — both carried the same sequence number. If we assume it answered the retransmission, we compute a round-trip time that is far too short; if the original, far too long. Either way the RTT estimate is corrupted.

Karn's algorithm Do not update the RTT estimate using any segment that was retransmitted.
Take RTT measurements only from segments acknowledged on their first transmission.

Karn's algorithm alone would leave a gap: if the RTO is too short and every segment gets retransmitted, no measurement is ever usable and the RTO never adapts. So Karn's algorithm is paired with exponential backoff: each time a segment is retransmitted, the RTO is doubled. Once a segment finally gets through on its first attempt, normal measurement resumes. Give both halves — the algorithm and the backoff — because the pairing is the point.

TCP options

Up to 40 bytes may follow the fixed 20-byte header. Seven options are defined:

OptionSizePurpose
End of Option (EOP)1 byteMarks the end of the options list; padding follows.
No Operation (NOP)1 byteA filler used to align the next option on a 4-byte boundary.
Maximum Segment Size (MSS)4 bytesAnnounces the largest segment this end is willing to receive. Exchanged only during connection establishment (in the SYN), and it is not negotiated — each side simply states its own limit. Default 536 bytes if absent.
Window Scale Factor3 bytesThe window field is only 16 bits, capping the window at 65,535 bytes — far too small for a fast, long link. This option supplies a left-shift count, multiplying the window by up to 214. Set only in the SYN segment.
Timestamp10 bytesTwo uses: more accurate RTT measurement, and PAWS (Protection Against Wrapped Sequence numbers) on very fast links where the 32-bit sequence number could wrap during one connection.
SACK-Permitted2 bytesSent in the SYN to say this end supports selective acknowledgement.
SACKvariableSelective Acknowledgement — reports blocks of data that arrived out of order, so the sender retransmits only what is genuinely missing rather than everything after the gap.
Why the window scale option exists — a good 2-mark answer

The window field is 16 bits, so the maximum window is 65,535 bytes. On a link with a large bandwidth-delay product — say 1 Gbps with a 100 ms round trip, which can hold about 12.5 MB in flight — a 64 KB window leaves the link almost entirely idle while the sender waits for acknowledgements. The scale factor lifts the ceiling to about 1 GB. This is the same bandwidth-delay-product idea from Lesson 1, applied at the transport layer.

SCTP — Stream Control Transmission Protocol

The third transport protocol named in the syllabus. It was designed for telephony signalling over IP, and it combines the good properties of TCP and UDP while adding two features neither has.

The two headline features

FeatureWhat it meansWhy it matters
Multi-homingEach endpoint may have several IP addresses, and the association uses one as primary with the others as backups.Fault tolerance. If the primary path fails, traffic moves to an alternative address without dropping the connection. A TCP connection is bound to one address pair and dies with it.
Multi-streamingOne association carries several independent streams of messages, each with its own sequence numbering.Eliminates head-of-line blocking: a lost message in stream 1 stalls only stream 1, while streams 2 and 3 keep delivering. In TCP, one lost segment blocks everything behind it.

Other SCTP properties worth naming

  • Message-oriented — like UDP, it preserves message boundaries. TCP's byte stream does not.
  • Reliable and connection-oriented — like TCP: acknowledged, ordered within a stream, with flow and congestion control.
  • Association, not connection — SCTP's term, because it links sets of addresses rather than a single pair.
  • Packets made of chunks — a general header plus one or more chunks, which may be control chunks or data chunks; several can be bundled into one packet.
  • Three numbering levels: TSN (Transmission Sequence Number, per association, for reliability), SI (Stream Identifier), and SSN (Stream Sequence Number, for ordering within a stream).
  • No half-close — SCTP does not support it; shutdown closes both directions.

The four-way handshake with a cookie

SCTP establishes an association in four steps rather than three, and the reason is a security improvement worth stating:

SCTP association establishment 1. Client → Server: INIT
2. Server → Client: INIT ACK, carrying a cookie — and the server allocates no resources yet
3. Client → Server: COOKIE ECHO, returning the cookie
4. Server → Client: COOKIE ACK — only now does the server allocate resources

This makes SCTP immune to SYN flooding by design. Because the server commits nothing until the cookie comes back, an attacker sending thousands of INIT chunks from spoofed addresses consumes no server state at all. TCP had to retrofit the same idea as SYN cookies; SCTP built it in.

Check yourself

Retrieval practice

1. Which timer resolves the zero-window deadlock?

A lost window update would leave both sides waiting forever, because pure acknowledgements are not themselves acknowledged. The persistence timer's one-byte probe forces the receiver to report its current window.

2. RTTS = 2.0 s and RTTD = 0.5 s. The RTO is:

RTO = RTTS + 4 × RTTD = 2.0 + 2.0 = 4.0 s. The 4 × deviation term leaves headroom so that ordinary jitter never triggers a needless retransmission.

3. Karn's algorithm says that TCP should:

After a retransmission there is no way to tell which transmission an arriving ACK refers to, so the measurement would be meaningless. Karn's fix is paired with exponential backoff — doubling the RTO on each retransmission — so the timer still adapts when nothing gets through first time.

4. The window scale option exists because:

On a 1 Gbps link with a 100 ms round trip, about 12.5 MB can be in flight — a 64 KB window would leave it nearly idle. Sequence-number wrapping is a real problem too, but it is solved by the timestamp option's PAWS mechanism, not by window scaling.

5. SCTP's multi-streaming eliminates:

Independent streams with their own sequence numbering mean a lost message stalls only its own stream. Surviving a path failure is the other feature — multi-homing — and the two are frequently swapped in answers.

6. SCTP is immune to SYN flooding because:

The four-way handshake — INIT, INIT ACK with cookie, COOKIE ECHO, COOKIE ACK — means thousands of forged INITs cost the server no state at all. TCP retrofitted the same idea as SYN cookies; SCTP had it by design.

Recall without looking

Name the four TCP timers and what each does.

Retransmission (RTO) — waits for an acknowledgement; on expiry the segment is resent and cwnd drops to 1. Persistence — resolves the zero-window deadlock by sending a one-byte probe. Keepalive — detects a crashed peer, typically after 2 hours idle, then ten probes 10 minutes apart. TIME-WAIT — the active closer waits 2 × MSL before releasing the connection.

Write the RTO formulas.

First measurement: RTTS = RTTM, RTTD = RTTM/2. Afterwards: RTTS = (1−α)·previous RTTS + α·RTTM with α = 1/8; RTTD = (1−β)·previous RTTD + β·|RTTS − RTTM| with β = 1/4; RTO = RTTS + 4·RTTD. Use the new RTTS when computing RTTD.

State the problem Karn's algorithm solves, and the fix.

After a retransmission, an arriving acknowledgement could refer to either transmission, so the measured RTT is meaningless. Karn's algorithm excludes retransmitted segments from RTT measurement, and is paired with exponential backoff — doubling the RTO on each retransmission — so the timer still adapts when no segment gets through first time.

Name the seven TCP options.

End of Option, No Operation, Maximum Segment Size, Window Scale Factor, Timestamp, SACK-Permitted, SACK.

What is MSS, and is it negotiated?

The largest segment an endpoint is willing to receive, announced in the SYN during connection establishment. It is not negotiated — each side simply states its own limit. The default is 536 bytes if the option is absent.

Explain SCTP's two headline features.

Multi-homing — each endpoint may have several IP addresses, so if the primary path fails traffic moves to a backup without dropping the association, giving fault tolerance TCP cannot. Multi-streaming — one association carries several independent streams, each separately numbered, so a loss in one stream does not stall the others; this eliminates head-of-line blocking.

Describe SCTP's four-way handshake and its security benefit.

INIT, then INIT ACK carrying a cookie with no resources allocated, then COOKIE ECHO returning it, then COOKIE ACK when the server finally allocates. Because nothing is committed until the cookie returns, forged INITs from spoofed addresses cost no server state — SCTP is immune to SYN flooding by design.

Give six differences between TCP and SCTP.

Byte stream vs message oriented; no multi-homing vs multi-homing; no multi-streaming (head-of-line blocking) vs multi-streaming; three-way vs four-way cookie handshake; vulnerable to SYN flooding vs immune; half-close supported vs not supported. SCTP also numbers at three levels — TSN, SI and SSN — and builds packets from chunks.
