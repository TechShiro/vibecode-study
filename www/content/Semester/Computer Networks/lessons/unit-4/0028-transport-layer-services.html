Transport Layer: Introduction and Services

Process-to-process delivery, port numbers and socket addresses, multiplexing and demultiplexing, and the connectionless/connection-oriented split. The framing lesson for Unit IV.

Exam strategy

Asked as "Explain the services of the transport layer" — 5 marks. Lead with the three deliveries line (hop-to-hop, host-to-host, process-to-process); it frames everything and takes one sentence. Then port addressing, multiplexing/demultiplexing, segmentation and reassembly, connection control, flow control, error control. The well-known port numbers are a separate one-mark question — learn the eight that matter.

What the transport layer is for

The three deliveries — write this first Data link layer → hop to hop  (node to adjacent node, using MAC addresses)
Network layer → host to host  (source to destination, using IP addresses)
Transport layer → process to process  (using port numbers)

The network layer gets a packet to the right computer. But a computer runs many processes at once — a browser, a mail client, a game. The transport layer's defining job is getting the data to the right process on that computer, and getting the whole message there, in order and intact.

The analogy examiners recognise

The IP address is the street address of a building; the port number is the flat number inside it. The postal service (IP) gets the letter to the building; the port number decides which door it goes under.

The asymmetry worth stating: the server's port must be well known, because the client has to know where to send its first packet. The client's port is ephemeral — chosen at random for that one connection and released afterwards — because the server learns it from the arriving packet.

Flow control vs congestion control — the distinction that separates answers

Flow control protects the receiver. Congestion control protects the network. Flow control is driven by the receiver's advertised window (rwnd); congestion control is driven by the sender's own estimate of network load (cwnd). Both limit how much the sender may transmit, and TCP obeys whichever is smaller. Say both sentences — most answers conflate the two.

Check yourself

Retrieval practice

1. A socket address consists of:

IP address + port number identifies one process on one host. A connection is then identified by the pair of socket addresses — which is how a server can hold thousands of connections on the same port 80.

2. A client's source port number is typically:

The server needs a well-known port because the client must know where to send the first packet. The client does not, because the server learns its port from the arriving segment — so it takes a random ephemeral one and releases it afterwards.

3. Demultiplexing at the receiver uses which field to decide the destination process?

The IP address already got the segment to the right machine; the port number is what picks the process. That is exactly why one host can run a browser, a download and a call over one IP connection at the same time.

4. Flow control and congestion control differ in that:

Flow control is driven by the receiver's advertised window (rwnd), congestion control by the sender's estimate of network load (cwnd), and TCP obeys whichever is smaller. Neither applies to UDP at all.

5. Which port pair belongs to DHCP?

DHCP uses 67 (server) and 68 (client) over UDP. 20/21 is FTP data and control, 110/143 are POP3 and IMAP4, and 80/443 are HTTP and HTTPS.

Recall without looking

State the three deliveries and which layer provides each.

Data link — hop to hop, using MAC addresses. Network — host to host (source to destination), using IP addresses. Transport — process to process, using port numbers.

Define port number and socket address.

A port number is a 16-bit address (0–65,535) identifying a process on a host. A socket address is the IP address combined with the port number; a connection is identified by the pair of socket addresses, one at each end.

Name the three port ranges and who uses each.

Well-known 0–1023, assigned by IANA to standard server processes. Registered 1024–49151, registered but not assigned. Dynamic/ephemeral 49152–65535, chosen at random by the client for one connection.

Give eight well-known port numbers.

FTP 20/21, SSH 22, TELNET 23, SMTP 25, DNS 53, DHCP 67/68, TFTP 69, HTTP 80, POP3 110, IMAP4 143, SNMP 161, HTTPS 443.

Define multiplexing and demultiplexing.

Multiplexing (sender): the transport layer accepts messages from several processes, adds a header with the source port to each, and passes them down to the one network layer — many to one. Demultiplexing (receiver): it reads each segment's destination port and delivers it to the correct process — one to many.

List the seven transport layer services.

Process-to-process delivery via port addressing; multiplexing and demultiplexing; segmentation and reassembly with sequence numbers; connection control; end-to-end flow control; end-to-end error control; congestion control.

Give six differences between connectionless and connection-oriented transport.

No setup vs three-way handshake; independent packets vs one tracked stream; order not guaranteed vs guaranteed; no reliability vs acknowledged and retransmitted; no flow or congestion control vs both; 8-byte header vs 20–60 bytes; fast vs slower.
