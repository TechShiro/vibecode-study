TCP Congestion Control

Slow start, congestion avoidance, congestion detection, and the difference between Tahoe and Reno — with a full window-by-window trace of the congestion window through a timeout and a fast retransmit.

Exam strategy

"Explain TCP congestion control with a diagram" is a 10-mark question and among the three most likely in Unit IV. Draw the cwnd-versus-time graph — exponential rise, the ssthresh line, linear rise, the drop — and label every phase on it. Then trace the numbers in a table. The Tahoe vs Reno distinction is the sub-question that separates good answers, so keep two rows for it.

What congestion is

Congestion occurs when the load on the network is greater than the capacity of the network. Routers have finite queues; when packets arrive faster than they can be forwarded, queues grow, delay rises, and eventually packets are dropped.

ApproachWhen it actsExamples
Open-loop (prevention)Before congestion happens — design the system so it does not occurRetransmission policy, window policy, acknowledgement policy, discarding policy, admission policy
Closed-loop (removal)After congestion is detected — react to itBackpressure, choke packet, implicit signalling, explicit signalling

TCP uses closed-loop, implicit signalling. No router tells TCP that it is congested. TCP infers congestion from packet loss — a timeout or duplicate acknowledgements. The reasoning: on a modern wired network, corruption is rare, so a lost packet almost certainly means a full router queue.

The assumption worth naming

TCP treats loss as evidence of congestion. That is a sound inference on wired links, where errors are rare. It is wrong on wireless links, where packets are often lost to interference rather than queue overflow — and TCP responds by needlessly halving its rate. Stating this limitation shows understanding beyond the mechanism.

The congestion window

The two windows, again Send window = min ( rwnd , cwnd )
rwnd is set by the receiver  |  cwnd is maintained by the sender itself

Congestion control is entirely about how the sender adjusts cwnd. Two other quantities matter:

  • MSS — Maximum Segment Size. cwnd is normally counted in multiples of MSS.
  • ssthresh — the slow start threshold. It is the boundary between the two growth phases.

Phase 1 — Slow start (exponential increase)

Slow start Start with cwnd = 1 MSS.
Increase cwnd by 1 MSS for every acknowledgement received.
Effect: cwnd doubles every round-trip time — 1, 2, 4, 8, 16 …
Continue until cwnd reaches ssthresh, then switch to congestion avoidance.
Why "slow" start is a misnomer — a favourite question

The growth is exponential, which is not slow at all. The name refers to the starting point: TCP begins at one segment rather than immediately blasting a full window into a network whose capacity it does not yet know. It is a slow start, not slow growth. Examiners ask this precisely because the name is misleading.

Phase 2 — Congestion avoidance (additive increase)

Congestion avoidance Begins when cwnd ≥ ssthresh.
Increase cwnd by 1 MSS per round-trip time (i.e. by MSS/cwnd per acknowledgement).
Effect: cwnd grows linearly — 8, 9, 10, 11 …

The rationale: exponential growth got us near the network's capacity quickly; from here on we probe cautiously, because overshooting causes loss.

Phase 3 — Congestion detection (multiplicative decrease)

Congestion is detected two ways, and TCP reacts differently to each — this asymmetry is the heart of the topic.

EventWhat it impliesssthresh becomescwnd becomesThen
Timeout (RTO expiry)Severe congestion — nothing is getting through at allcwnd / 21 MSSSlow start
Three duplicate ACKsMild congestion — later segments are still arriving, so the network workscwnd / 2cwnd / 2 (TCP Reno)Congestion avoidance
AIMD — the principle in one line Additive Increase, Multiplicative Decrease
Grow cautiously by adding; retreat sharply by halving.

Why the asymmetry? Because the cost of the two errors is not equal. Growing too slowly wastes some bandwidth; growing too fast collapses the network for everyone. AIMD is deliberately conservative in the direction where the consequences are worse — and it is also what makes TCP fair, since competing flows converge on an equal share.

Tahoe and Reno

PerformanceLower — over-reacts to a single lost segmentHigher — avoids collapsing to 1 when the network is clearly still working

The one-line distinction: Tahoe treats every loss as severe; Reno distinguishes mild loss (duplicate ACKs) from severe loss (timeout) and only restarts from 1 for the severe case.

  • At RTT 12, slow start would double 4 to 8 — but that would overshoot ssthresh = 6. cwnd stops at ssthresh and the phase switches. Doubling past the threshold is the most common error in this trace.

Under Reno: ssthresh = 12/2 = 6, and cwnd = 6, continuing in congestion avoidance — so RTT 9 would be 7, RTT 10 would be 8. Under Tahoe: cwnd = 1 and slow start, exactly as for a timeout. That divergence is the whole difference between the two.

Congestion Control Taxonomy · Open-Loop vs Closed-Loop

Congestion control mechanisms are divided broadly into two fundamental philosophies: open-loop (preventive — designs protocols so congestion never occurs) and closed-loop (reactive — detects congestion dynamically and throttles transmission).

Mechanism CategoryApproachPolicies / TechniquesHow it operates
Open-Loop (Preventive)Acts before congestion happens; no dynamic feedback from the congested router.• Retransmission Policy: Timers set conservatively so good packets are not resent.
• Window Policy: Selective Repeat used instead of Go-Back-N to avoid retransmitting bursts.
• Acknowledgement Policy: Piggybacking or delayed ACKs to cut control packet traffic.
• Discarding Policy: Discard less sensitive packets first (e.g. video audio over headers).
• Admission Policy: Deny virtual circuit creation if network lacks capacity.		Prevention baked into protocol rules; static and conservative.
Closed-Loop (Reactive)Acts after congestion is detected in real time by intermediate nodes.• Backpressure: Congested node informs upstream neighbor node directly to stop transmitting; ripples backward hop-by-hop.
• Choke Packet: Congested router generates a special control packet sent directly to the original source to slow down.
• Implicit Signaling: Source deduces congestion without direct router warnings (e.g., packet delay or packet loss in TCP).
• Explicit Signaling: Router sets header warning bits: BECN (Backward Explicit Congestion Notification — warns sender) or FECN (Forward Explicit Congestion Notification — warns receiver to throttle ACKs).		Dynamic closed-loop feedback; adapts instantaneously to network state.

Traffic Shaping · Leaky Bucket vs Token Bucket

Traffic shaping is an open-loop mechanism used at the network edge to control the volume and the rate of the traffic sent into the network. It smooths out bursty traffic (where a host sits idle, then fires a massive burst of packets) into a steady, predictable stream.

Visual Architecture: Leaky Bucket vs Token Bucket Algorithms
1. Leaky Bucket (Rigid Constant Rate)
• Analogy: A bucket with a small hole in the bottom. No matter how fast water is poured in, water leaks out at a strictly constant speed.
• Operation: Bursty packets enter a FIFO buffer queue. If the buffer is full, newly arriving packets overflow and are dropped (discarded).
• Output: Generates a completely uniform, continuous stream at rate $\rho$.
• Weakness: Incapable of supporting bursts even when the network has idle spare capacity!
2. Token Bucket (Controlled Bursts Allowed)
• Analogy: Tokens are dropped into a bucket at a constant rate $r$ tokens/sec up to capacity $C$.
• Operation: For a packet to transmit, it must capture and consume 1 token (or $k$ tokens for $k$ bytes). If the bucket is empty, packets must wait for new tokens.
• Output: Allows an idle host that accumulated tokens to transmit a controlled burst at full link speed $M$.
• Maximum Burst Duration: $T = \frac{C}{M - r}$ seconds.

Master Comparison: Leaky Bucket versus Token Bucket

Quality of Service (QoS) · Flow Characteristics and Scheduling

Quality of Service (QoS) is an end-to-end performance guarantee provided by the network. A traffic flow is characterized by four primary metrics: Reliability (percentage of dropped packets), Delay (transit time across the network), Jitter (variation in delay between consecutive packets — critical in VoIP and real-time audio), and Bandwidth (sustained data rate).

Packet Scheduling Disciplines

Scheduling PolicyMechanismPros & Cons in Exams
FIFO (First-In, First-Out)Packets are queued in a single queue and dispatched strictly in the order they arrived.Simplest to implement; provides zero QoS isolation — one aggressive bursty flow starves all other flows.
Priority Queuing (PQ)Packets are classified into high, medium, and low priority queues. Higher-priority queues are served until completely empty before lower queues are touched.Guarantees low latency for real-time voice; risks starvation of low-priority traffic during prolonged high loads.
Weighted Fair Queuing (WFQ)Packets enter separate queues for each flow; a round-robin scheduler services them in proportion to assigned weights: $W_i$.Best overall fairness; guarantees minimum bandwidth to every flow while eliminating starvation.

A timeout means severe congestion: ssthresh halves to 8 and cwnd collapses to 1, restarting slow start. ssthresh = 8 with cwnd = 8 would be Reno's response to three duplicate ACKs instead.

Both behave identically on a timeout. Reno's addition is fast recovery: three duplicate ACKs show later segments are arriving, so it halves cwnd and stays in congestion avoidance instead of collapsing to 1.

Doubling would overshoot to 8, so cwnd stops at ssthresh = 6 and the phase switches to congestion avoidance. Doubling straight past the threshold is the commonest error in a cwnd trace.

5. TCP infers that the network is congested from:

TCP uses closed-loop, implicit signalling — no router tells it anything. A shrinking rwnd is flow control, a different concern. Note the assumption's weakness: on wireless links loss often means interference, not congestion, and TCP still halves its rate.

Recall without looking

Define congestion and name the two general approaches to controlling it.

Congestion occurs when the load on the network exceeds its capacity. Open-loop (prevention) acts before congestion — retransmission, window, acknowledgement, discarding and admission policies. Closed-loop (removal) acts after detection — backpressure, choke packet, implicit and explicit signalling. TCP uses closed-loop with implicit signalling.

Describe slow start.

Start at cwnd = 1 MSS and increase cwnd by 1 MSS for every acknowledgement received, which doubles cwnd each round-trip time — 1, 2, 4, 8. Continue until cwnd reaches ssthresh, then switch to congestion avoidance. The name refers to the starting point, not the growth rate, which is exponential.

Describe congestion avoidance.

Begins when cwnd ≥ ssthresh. cwnd increases by 1 MSS per round-trip time (MSS/cwnd per acknowledgement), so growth is linear rather than exponential — probing cautiously now that the network's capacity is near.

What happens on a timeout, and on three duplicate ACKs?

Timeout — severe congestion: ssthresh = cwnd/2, cwnd = 1 MSS, return to slow start. Three duplicate ACKs — mild congestion, since later segments are arriving: ssthresh = cwnd/2 and, in TCP Reno, cwnd = ssthresh with congestion avoidance continuing (fast recovery).

State AIMD and why the asymmetry exists.

Additive Increase, Multiplicative Decrease — grow by adding, retreat by halving. The two errors differ in cost: growing too slowly wastes some bandwidth, while growing too fast collapses the network for everyone. AIMD also makes competing flows converge on an equal share.

Compare Tahoe and Reno.

Both set ssthresh = cwnd/2 and cwnd = 1 on a timeout. On three duplicate ACKs, Tahoe does the same — cwnd = 1 and slow start — while Reno enters fast recovery, setting cwnd = ssthresh and staying in congestion avoidance. Reno therefore performs better, because it does not over-react to a single lost segment.

What six features must the cwnd-versus-time graph show?

The exponential slow-start curve from 1; a dashed ssthresh line where it bends; the gentle linear congestion-avoidance slope; the vertical drop at the loss event (to 1 for a timeout, to cwnd/2 for duplicate ACKs); the new ssthresh line at half the old cwnd; and the repeating sawtooth.
