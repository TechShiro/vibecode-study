TCP: Services and Header

Stream delivery, the numbering system that everything else depends on, the eleven header fields, the six control flags, and the options. The sequence-number rules in particular return in every remaining lesson of this unit.

Exam strategy

"Draw and explain the TCP header" is a 10-mark near-certainty. Draw it four bytes (32 bits) per row with the bit-width under each field. The two places marks are actually lost: the six control flags (name all six, one line each) and the sequence vs acknowledgement number rule. Get those right and the rest is description.

TCP's services

ServiceWhat it means
Process-to-process communicationDelivery to the correct process using port numbers, as with UDP.
Stream delivery serviceTCP is a stream-oriented protocol. It lets the two processes behave as though connected by an imaginary tube carrying a continuous flow of bytes. Message boundaries are not preserved.
Sending and receiving buffersBecause the two processes may write and read at different speeds, TCP keeps a buffer at each end for storage in both directions.
SegmentsTCP groups bytes from the buffer into packets called segments, adds a header, and hands them to IP. Segments need not be the same size.
Full-duplexData flows in both directions at the same time over one connection. Each direction has its own sequence numbers and its own window.
Connection-orientedA connection is established, used, then torn down. Note: it is a virtual connection, not a physical circuit — the segments themselves travel as independent IP datagrams.
ReliableAcknowledgement, checksum and retransmission guarantee safe, in-order arrival.
The point about "connection-oriented" that earns a mark

TCP's connection is virtual, not physical. IP is connectionless and treats every datagram independently — segments of one TCP connection may take different routes and arrive out of order. TCP creates the appearance of an ordered, reliable pipe on top of that, using sequence numbers and buffering at the endpoints. Saying this shows you understand the layering rather than just the label.

The numbering system — learn this before the header

TCP numbers bytes, not segments. Every byte of data transferred in a connection is numbered, and the segment header reports positions within that byte numbering.

The two rules Sequence number = the number of the FIRST byte of data carried in this segment
Acknowledgement number = the number of the NEXT byte the receiver expects
    — and it is cumulative: acknowledging byte n means every byte up to n−1 arrived safely.

The Initial Sequence Number (ISN) is chosen randomly, not started at 0. Two reasons, both examinable: it prevents a delayed segment from an old connection being mistaken for part of a new one, and it makes connection hijacking harder for an attacker who would otherwise be able to guess sequence numbers.

Worked example — sequence and acknowledgement numbers

Q. A TCP connection transfers 5000 bytes in five segments of 1000 bytes each. The ISN is 10,001. Give the sequence number of each segment, and the acknowledgement number the receiver returns after each.

Byte numbering runs from 10,001 to 15,000. The first data byte is 10,001.

SegmentBytes carriedSequence numberReceiver's ACK number
110,001 – 11,00010,00111,001
211,001 – 12,00011,00112,001
312,001 – 13,00012,00113,001
413,001 – 14,00013,00114,001
514,001 – 15,00014,00115,001

Sanity check: each ACK number = the previous sequence number + the bytes in that segment. And the ACK always names a byte not yet received — it is a request, not a receipt. Answering "11,000" instead of "11,001" is the standard error, and it comes from thinking of the ACK as "the last byte I got" rather than "the next byte I want".

FieldSizePurpose
Source port16 bitsPort of the sending process
Destination port16 bitsPort of the receiving process
Sequence number32 bitsThe number of the first data byte in this segment. During connection setup, when SYN is set, it carries the ISN and consumes one sequence number even though no data is sent.
Acknowledgement number32 bitsThe number of the next byte expected. Cumulative. Valid only when the ACK flag is set.
HLEN4 bitsHeader length in 4-byte words. Value 5 = 20 bytes (no options); value 15 = 60 bytes.
Reserved6 bitsSet to zero, kept for future use
Control flags6 bitsURG, ACK, PSH, RST, SYN, FIN — see below
Window size16 bitsThe receiver's advertised window (rwnd) — how many bytes the receiver is currently willing to accept. Maximum 65,535, which is why the window scale option exists. This field is how flow control is implemented.
Checksum16 bitsCovers header, data and a pseudoheader with protocol number 6. Mandatory in TCP, unlike UDP where it is optional.
Urgent pointer16 bitsValid only when URG is set. Added to the sequence number, it gives the number of the last byte of urgent data.
Options and padding0–40 bytesMSS, window scale, SACK, timestamp — see Lesson 34

The six control flags

FlagNameMeaning when set
URGUrgentThe urgent pointer field is valid — this segment contains data the receiver should process ahead of the queue.
ACKAcknowledgementThe acknowledgement number field is valid. Set on every segment after the first.
PSHPushDeliver the data to the application immediately, without waiting for the buffer to fill. Used by interactive applications such as TELNET.
RSTResetAbort the connection — sent on an error, or when a segment arrives for a connection that does not exist.
SYNSynchroniseSynchronise sequence numbers during connection establishment.
FINFinishTerminate the connection — the sender has no more data to send.
A mnemonic, and the two facts attached to it

In header order the flags are URG, ACK, PSH, RST, SYN, FIN — "Unskilled Attackers Pester Real Security Folks."
Two facts that get asked directly: SYN and FIN each consume one sequence number even though they carry no data (which is why the handshake's numbers advance by 1). Pure ACK segments consume none.

What "urgent" actually means — a common misconception

Urgent data is not sent on a separate faster channel and does not overtake anything in the network. The URG flag simply tells the receiving TCP that the bytes up to the urgent pointer should be passed to the application out of band, ahead of the normal read queue. It is a signal about handling at the destination, not about priority in transit. Ctrl-C in a TELNET session is the classic use.

Check yourself

Retrieval practice

1. A segment carries bytes 4001 to 5000. Its sequence number and the receiver's acknowledgement number are:

Sequence = first byte carried = 4001. Acknowledgement = next byte expected = 5001, not the last byte received. Answering 5000 is the standard slip, and it comes from reading the ACK as a receipt rather than a request.

2. The TCP window size field implements:

rwnd is set by the receiver to say how much it can currently absorb, which protects the receiver — that is flow control. Congestion control uses cwnd, which the sender computes itself and which appears nowhere in the header.

3. Which flags consume a sequence number despite carrying no data?

SYN and FIN each consume one sequence number, which is why the handshake's numbers advance by 1 with no data sent. Pure ACK segments consume none — a fact that matters when tracing a connection trace in an exam question.

4. The PSH flag asks the receiver to:

PSH is about buffering at the endpoints, not priority in transit. Interactive applications such as TELNET use it so a keystroke is not held back waiting for more bytes to accumulate.

5. TCP's initial sequence number is chosen randomly in order to:

A delayed segment from an old connection could otherwise be accepted as part of a new one, and a predictable ISN would let an attacker forge segments into an existing connection. Both reasons are examinable.

6. An HLEN value of 8 means the TCP header is:

HLEN counts 4-byte words: 8 × 4 = 32 bytes. Since the base header is 20 bytes, the extra 12 must be options. Value 5 gives the 20-byte minimum, value 15 the 60-byte maximum.

Recall without looking

List TCP's seven services.

Process-to-process communication via ports; stream delivery service (an imaginary tube of bytes, boundaries not preserved); sending and receiving buffers; segments; full-duplex; connection-oriented; reliable.

Why is TCP's connection called virtual?

IP is connectionless and treats each datagram independently, so segments may take different routes and arrive out of order. TCP creates the appearance of an ordered reliable pipe on top of that, using sequence numbers and endpoint buffering — there is no physical circuit.

State the sequence number and acknowledgement number rules.

Sequence number = the number of the first data byte in this segment. Acknowledgement number = the number of the next byte expected, and it is cumulative, so acknowledging n means everything up to n−1 arrived. TCP numbers bytes, not segments.

Why is the ISN random?

So a delayed segment from an old connection cannot be mistaken for part of a new one, and so an attacker cannot guess sequence numbers to hijack a connection.

Draw the TCP header with field sizes.

Source Port (16) | Destination Port (16); Sequence Number (32); Acknowledgement Number (32); HLEN (4) | Reserved (6) | Flags (6) | Window Size (16); Checksum (16) | Urgent Pointer (16); Options and Padding (0–40 bytes). Total 20–60 bytes.

Name the six control flags and what each means.

URG — urgent pointer valid. ACK — acknowledgement number valid. PSH — deliver to the application immediately. RST — abort the connection. SYN — synchronise sequence numbers during setup. FIN — sender has no more data, terminate.

What is the window size field, and what limits it?

The receiver's advertised window (rwnd), the number of bytes it is currently willing to accept — this is how flow control is implemented. It is 16 bits, so the maximum is 65,535, which is why the window scale option exists.

How does TCP's checksum differ from UDP's?

Both cover header, data and a pseudoheader, but TCP's pseudoheader carries protocol number 6 rather than 17, and the TCP checksum is mandatory whereas UDP's is optional in IPv4.
