The TCP/IP Model, and OSI vs TCP/IP

The model the Internet actually runs on, the protocols that sit in each of its layers, the mapping onto OSI, and the comparison table — which is the highest-probability question in the whole unit.

Exam strategy

"Compare the OSI and TCP/IP reference models" is the single most likely question in Unit I. Answer it as a table of 8–10 rows, preceded by the side-by-side layer diagram, and followed by one short paragraph on why TCP/IP won. That structure — diagram, table, closing paragraph — is a full-mark answer and takes eight minutes.

What TCP/IP is

The TCP/IP protocol suite is the set of protocols on which the Internet runs. It was developed before the OSI model, out of the US Department of Defense's ARPANET project, and it is named after its two most important protocols — TCP (Transmission Control Protocol) and IP (Internet Protocol).

Two facts that matter and are often asked:

  • TCP/IP is a working protocol suite that also happens to define a model. OSI is a model with no protocols of its own. That ordering — protocols first for TCP/IP, model first for OSI — explains almost every difference between them.
  • The original TCP/IP model has four layers. Most modern textbooks, including Forouzan, present a five-layer version that splits the bottom layer into data link and physical. Either is acceptable — state which one you are using.

The mapping in one sentence

TCP/IP merges OSI's top three layers into Application and its bottom two into Network Access. Transport and Network map one-to-one. If you write nothing else about the mapping, write that.

The similarities row — do not omit it

Many students write only differences and lose a mark. Add two lines: both are layered models, both use the concept of protocol stacks, both have comparable transport and network layers, and both pass data by encapsulation from one layer to the next.

Why TCP/IP won

A short paragraph question — "Why is the OSI model not used in practice?" Tanenbaum's four reasons, one line each:

  • Bad timing. By the time the OSI standards were finished, TCP/IP was already widely deployed and researchers had committed to it. There was no reason to switch.
  • Bad technology. Seven layers were partly a political compromise. The session and presentation layers are nearly empty in practice, while the data link and network layers are so full they had to be sub-divided anyway.
  • Bad implementations. The first OSI implementations were large, slow and unwieldy, which gave the model a lasting reputation for poor performance. Early TCP/IP implementations were free with Berkeley UNIX and were good.
  • Bad politics. OSI was seen as the creature of European telecom ministries and bureaucrats, while TCP/IP was associated with universities and open research.

Closing line worth writing: OSI survives as the reference model everyone teaches and reasons with; TCP/IP survives as the suite everyone actually runs.

Check yourself

Retrieval practice

1. The OSI session and presentation layers correspond to which part of the TCP/IP model?

TCP/IP folds OSI layers 5, 6 and 7 into one application layer. The functions still exist — encryption, dialog control — they are simply the application protocol's own responsibility rather than a separate layer's.

2. ARP belongs to which TCP/IP layer, and what does it do?

ARP goes IP → MAC. RARP goes MAC → IP (the reverse, hence the name). Resolving a domain name to an IP is DNS, at the application layer. Mixing up ARP and RARP is the classic slip.

3. Which statement about the OSI and TCP/IP transport layers is correct?

TCP/IP's transport layer has TCP (connection-oriented) and UDP (connectionless). The network layers are the mirror image: OSI's supports both, while TCP/IP's internet layer is connectionless only. That inversion is exactly what the question tests.

4. Which is the strongest structural difference between the two models?

The ordering is the root cause. OSI is general and protocol-independent because the model came first; TCP/IP fits its own protocols closely because they came first. Almost every other difference follows from this one.

5. A 16-bit address such as 80 or 443 identifies:

Port addresses are 16 bits and belong to the transport layer. MAC addresses are 48 bits (data link), IPv4 addresses 32 bits (network). Learn the three bit-lengths — they are asked directly.

Recall without looking

Name the four layers of the TCP/IP model, bottom to top.

Network Access (link), Internet, Transport, Application. The five-layer version splits Network Access into Physical and Data Link.

How do the seven OSI layers map onto the four TCP/IP layers?

OSI 5, 6, 7 → TCP/IP Application. OSI 4 → Transport. OSI 3 → Internet. OSI 1 and 2 → Network Access.

Name two protocols in each TCP/IP layer.

Application: HTTP, FTP, SMTP, DNS, DHCP, TELNET. Transport: TCP, UDP, SCTP. Internet: IP, ICMP, IGMP, ARP, RARP. Network Access: Ethernet, PPP, HDLC, Wi-Fi.

Give six differences between the OSI and TCP/IP models.

Layers (7 vs 4/5); developed by ISO 1984 vs DoD/ARPANET 1970s; model-first vs protocols-first; theoretical reference vs implemented working suite; OSI keeps session and presentation separate, TCP/IP merges them; OSI network layer supports both connection modes and its transport layer only connection-oriented, TCP/IP the exact reverse; OSI is a teaching reference, TCP/IP is what the Internet runs.

Name three similarities between OSI and TCP/IP.

Both are layered; both use protocol stacks with a defined function per layer; both pass data down through encapsulation and up through decapsulation; their transport and network layers have comparable responsibilities.

Name the four types of address and the layer of each.

Physical/MAC (48 bits) — data link. Logical/IP (32 bits in IPv4) — network/internet. Port (16 bits) — transport. Specific/application (e-mail address, URL) — application.

Give the four reasons the OSI model was not adopted in practice.

Bad timing (TCP/IP was already deployed); bad technology (seven layers were a political compromise — session and presentation nearly empty, data link and network overloaded); bad implementations (early ones were large and slow); bad politics (seen as the product of telecom bureaucracies rather than researchers).
