The IPv4 Header and Fragmentation

Thirteen header fields with their sizes and purposes, then the fragmentation numerical — identification, flags and offset worked out fragment by fragment. A diagram question and a calculation question in one lesson.

Exam strategy

"Draw and explain the IPv4 header" is a 10-mark near-certainty. Draw it as a grid four bytes (32 bits) wide, with the bit-width written under every field — that layout is itself worth marks because it shows why the header is a multiple of 4 bytes. Then one line per field. The fragmentation numerical is a separate 5-mark question; the three fields it turns on are identification, flags and fragmentation offset, so give those three extra attention.

FieldSizePurpose
Version4 bitsThe IP version — 4 for IPv4. Tells the receiving software how to interpret the rest.
HLEN (IHL)4 bitsHeader length counted in 4-byte words. Value 5 means 5 × 4 = 20 bytes (no options); maximum value 15 means 60 bytes. This field exists because the header is variable-length.
Type of Service / DSCP8 bitsHow the datagram should be handled — priority, and whether to optimise for delay, throughput or reliability. Reinterpreted as DiffServ for QoS.
Total Length16 bitsThe length of the whole datagram — header plus data — in bytes. Maximum 216 − 1 = 65,535 bytes. Data length = total length − header length.
Identification16 bitsIdentifies which original datagram a fragment belongs to. All fragments of one datagram carry the same value, so the destination can group them.
Flags3 bitsBit 0 reserved (always 0). Bit 1 = DF (Don't Fragment) — if set and the datagram is too big, it is discarded and an ICMP error returned. Bit 2 = MF (More Fragments) — 1 means more fragments follow, 0 means this is the last fragment.
Fragmentation Offset13 bitsThe position of this fragment's data within the original datagram, measured in units of 8 bytes. The 8-byte unit is what lets 13 bits address a 65,535-byte datagram.
Time to Live (TTL)8 bitsA hop counter, decremented by 1 at every router. When it reaches 0 the datagram is discarded and an ICMP time-exceeded message is sent back. Maximum 255. It prevents packets circulating forever in a routing loop.
Protocol8 bitsWhich upper-layer protocol the payload belongs to, so the destination can hand it to the right place: 1 = ICMP, 2 = IGMP, 6 = TCP, 17 = UDP, 89 = OSPF.
Header Checksum16 bitsError detection over the header only, not the data. It must be recomputed at every router, because TTL changes at each hop.
Source address32 bitsThe sender's IP address. Unchanged by routers.
Destination address32 bitsThe final destination's IP address. Unchanged by routers.
Options + Padding0–40 bytesOptional: record route, strict/loose source route, timestamp. Padding brings the header up to a multiple of 4 bytes. Rarely used in practice.
Four one-mark facts from this header

Minimum header 20 bytes, maximum 60 bytes. Maximum total datagram 65,535 bytes. The checksum covers the header only. TTL is a hop count, not a time. Each of these is asked directly, and TTL is the one most often answered wrongly — despite the name, it counts hops, not seconds.

Fragmentation

Every physical network has a Maximum Transmission Unit (MTU) — the largest frame its data link layer can carry. Ethernet's is 1500 bytes. A datagram larger than the next network's MTU must be fragmented.

QuestionAnswer
Who fragments?The source host, or any router along the path whose outgoing network has a smaller MTU.
Who reassembles?Only the destination host. Never an intermediate router.
Why not reassemble at routers?Because fragments may take different routes, so no single router is guaranteed to see them all. Reassembling at the destination is the only place that always works.
Can a fragment be fragmented again?Yes — if it meets a network with an even smaller MTU.
What is copied to every fragment?The whole header, including the identification, source and destination addresses. Only the flags, offset, total length and checksum change.
The fragmentation rules Data per fragment = MTU − header size, rounded down to a multiple of 8
Offset = (bytes of data before this fragment) ÷ 8
MF = 1 for every fragment except the last, which has MF = 0
Identification is the same in every fragment of one datagram

Why the data must be a multiple of 8: the offset field counts in 8-byte units, so every fragment except the last must begin at a byte position divisible by 8. This is the constraint students forget, and it changes the answer whenever MTU − 20 is not itself a multiple of 8.

Worked numerical — the standard fragmentation question

Q. A datagram of 4000 bytes (20-byte header + 3980 bytes of data) must cross a network with an MTU of 1500 bytes. Show the fragments with their total length, identification, MF flag and offset. Assume the identification is 777.

Step 1 — data bytes per fragment.
Each fragment needs its own 20-byte header, so data per fragment = 1500 − 20 = 1480 bytes.
Check it is a multiple of 8: 1480 ÷ 8 = 185 exactly. ✓

Step 2 — how many fragments?
3980 ÷ 1480 = 2.69 → 3 fragments (two full, one partial).

The offset arithmetic:
Fragment 1 starts at byte 0 → offset = 0 ÷ 8 = 0
Fragment 2 starts at byte 1480 → offset = 1480 ÷ 8 = 185
Fragment 3 starts at byte 2960 → offset = 2960 ÷ 8 = 370

Fragment 3's size: 3980 − (1480 + 1480) = 1020 bytes of data, so total length = 1020 + 20 = 1040 bytes.

Four sanity checks — run all of them:

  • The data bytes must sum to the original: 1480 + 1480 + 1020 = 3980. ✓
  • Only the last fragment has MF = 0. ✓
  • Every fragment carries the same identification. ✓
  • The total bytes transmitted grew: 3 headers × 20 = 60 bytes instead of 20, so 4040 bytes now travel where 4000 did. Fragmentation always adds overhead — worth stating as the closing line.
The follow-up question they often attach

"What if a fragment is lost?" The destination cannot reassemble the datagram, so it discards all the fragments it did hold and the entire original datagram is lost. One lost fragment costs the whole datagram — which is why fragmentation is avoided in practice, using Path MTU Discovery (setting the DF bit and shrinking until it fits) instead. IPv6 removes router fragmentation altogether for this reason.

Check yourself

Retrieval practice

1. The HLEN field contains the value 5. The header size is:

HLEN is in 4-byte words, so 5 × 4 = 20 bytes — the minimum, meaning no options are present. The maximum value 15 gives 15 × 4 = 60 bytes.

2. The fragmentation offset field is measured in units of:

Counting in 8-byte units lets a 13-bit field address a 65,535-byte datagram. The consequence is the constraint students forget: every fragment except the last must carry a multiple of 8 data bytes.

3. A datagram of 2500 bytes with a 20-byte header crosses a network with MTU 1000. The first fragment carries how many data bytes?

1000 − 20 = 980, but 980 ÷ 8 = 122.5, not an integer. Round down to 976 (976 ÷ 8 = 122). Taking 980 without checking the multiple-of-8 rule is the standard error in this question.

4. Which field prevents a datagram from circulating forever in a routing loop?

TTL is a hop counter — at zero the datagram is discarded and an ICMP time-exceeded message is returned. Despite the name it counts hops, not seconds, and that is the detail most often got wrong.

5. A fragment arrives with MF = 0 and offset = 0. This means:

Offset 0 means it starts at the beginning; MF = 0 means nothing follows. Together they describe a whole, unfragmented datagram. A last fragment would have offset > 0, and a first fragment of a set would have MF = 1.

6. If one fragment of a datagram is lost in transit:

Reassembly is all-or-nothing at the destination, and IP has no retransmission. Losing one fragment costs the entire datagram, which is why Path MTU Discovery is used to avoid fragmentation and why IPv6 removed router fragmentation entirely.

What are HLEN and Total Length, and what are their limits?

HLEN is the header length in 4-byte words: value 5 = 20 bytes minimum, value 15 = 60 bytes maximum. Total Length is the whole datagram — header plus data — in bytes, maximum 65,535. Data length = total length − header length.

Explain the three flag bits.

Bit 0 is reserved and always 0. DF (Don't Fragment): if set and the datagram is too large, it is discarded and an ICMP error returned. MF (More Fragments): 1 means more fragments follow, 0 marks the last fragment.

What is TTL and why does the checksum change at every router?

TTL is a hop counter decremented at each router; at zero the datagram is discarded and ICMP reports time exceeded, which prevents endless looping. Because TTL changes at every hop, the header checksum — which covers the header only — must be recomputed at every router.

Give the protocol field values for ICMP, IGMP, TCP and UDP.

ICMP = 1, IGMP = 2, TCP = 6, UDP = 17 (and OSPF = 89). The field tells the destination which upper-layer protocol should receive the payload.

Who fragments, who reassembles, and why?

The source host or any router whose outgoing network has a smaller MTU may fragment. Only the destination host reassembles, because fragments may take different routes and no intermediate router is guaranteed to see them all. A fragment can itself be fragmented again.

State the fragmentation rules.

Data per fragment = MTU − header size, rounded down to a multiple of 8. Offset = bytes of data preceding this fragment ÷ 8. MF = 1 on all fragments but the last. The identification value is the same across all fragments of one datagram.

What happens if one fragment is lost?

The destination cannot reassemble, so it discards every fragment it holds and the entire original datagram is lost. This is why Path MTU Discovery is used to avoid fragmentation, and why IPv6 removed router fragmentation.
