IPv6

128-bit addresses, the abbreviation rules, the simplified 40-byte header, extension headers, the IPv4 versus IPv6 table, and the three transition strategies. The last lesson of Unit III.

Exam strategy

Three questions live here, and all three are short. (1) "Compare IPv4 and IPv6" — a table of 8–10 rows, the most likely of the three. (2) "Draw and explain the IPv6 header" — only eight fields, so it is quicker than the IPv4 header question; make sure you can say which four fields were removed and why. (3) An abbreviation exercise — compress or expand an address; purely mechanical, and the ":: only once" rule is what is being tested.

Why IPv6

Problem with IPv4How IPv6 answers it
Address exhaustion — 232 is about 4.3 billion, and even that was used inefficiently2128 addresses — about 3.4 × 1038, effectively inexhaustible
No built-in support for real-time traffic (audio, video)Flow label and traffic class fields for quality of service
No encryption or authentication in the designIPsec is built in rather than bolted on
Complex, variable-length header slows routersFixed 40-byte header, with options moved to separate extension headers
Routers must fragment, and recompute the checksum at every hopRouters never fragment, and there is no header checksum at all

The address

IPv6 addressing 128 bits = 16 bytes, written as 8 groups of 4 hexadecimal digits separated by colons
Address space = 2128 ≈ 3.4 × 1038 addresses

Example: FDEC:0074:0000:0000:0000:B0FF:0000:FFF0

The two abbreviation rules

Rule 1 — drop leading zeros Within each group, leading zeros may be omitted. Trailing zeros may not.
0074 → 74  ·  0000 → 0  ·  FFF0 stays FFF0
Rule 2 — collapse consecutive zero groups A run of consecutive all-zero groups may be replaced by ::
This may be done only ONCE in an address.
Worked example — abbreviation

Q. Abbreviate FDEC:0074:0000:0000:0000:B0FF:0000:FFF0 as far as possible.

Step 1 — drop leading zeros in each group:
FDEC:74:0:0:0:B0FF:0:FFF0

Step 2 — collapse the longest run of zero groups. There are two runs: three zeros in positions 3–5, and a single zero at position 7. Collapse the longer run:
FDEC:74::B0FF:0:FFF0

Why not both? Because :: may appear only once. FDEC:74::B0FF::FFF0 is invalid — with two occurrences the reader cannot tell how many zero groups belong to each, and the address becomes ambiguous. That is the entire point of the rule, and it is what the question tests.

Expanding back: count the groups present (6), subtract from 8, and that is how many zero groups the :: stands for — here 2... but note we collapsed 3 groups and left one 0 written out, giving 6 groups shown plus 2 hidden. Always count to 8 groups when expanding; that check catches every mistake.

The three address types

TypeDelivers toNote

AnycastA group of interfaces — but delivered to only the nearest oneUsed for DNS root servers and CDNs
The fact examiners ask for directly

IPv6 has no broadcast address. Broadcast was removed entirely, because it forces every host to process a packet whether or not it is interested. Its functions are handled by multicast to a well-known group instead — for example, "all nodes on this link" is the multicast address FF02::1. Anycast is the genuinely new type, and its one-line definition is "delivered to the nearest member of the group".

The IPv6 header

IPv6 base header — fixed at 40 bytes, only eight fields Row 1: | Version (4) | Traffic Class (8) | Flow Label (20) |
Row 2: | Payload Length (16) | Next Header (8) | Hop Limit (8) |
Rows 3–6: | Source Address (128 bits = 16 bytes) |
Rows 7–10: | Destination Address (128 bits = 16 bytes) |
FieldSizePurpose
Version4 bitsAlways 6
Traffic Class8 bitsPriority and class of the packet — the equivalent of IPv4's Type of Service
Flow Label20 bitsNew in IPv6. Labels a sequence of packets belonging to one flow, so routers can give them identical special handling without inspecting the higher layers. This is what supports real-time audio and video.
Payload Length16 bitsThe length of the data excluding the 40-byte base header. (In IPv4, Total Length included the header — a difference worth naming.)
Next Header8 bitsIdentifies what follows the base header — either an extension header or the upper-layer protocol (TCP, UDP). It replaces IPv4's Protocol field and also chains the extension headers together.
Hop Limit8 bitsExactly IPv4's TTL, honestly renamed — it always counted hops rather than time.
Source address128 bitsThe sender
Destination address128 bitsThe destination — or, if a routing extension header is present, the next router on the specified path

The four fields removed from IPv4 — and why

RemovedReason
Header checksumIt had to be recomputed at every router because TTL changed, which was pure overhead. The data link layer already checks with a CRC, and the transport layer checksums end to end, so the middle check was redundant.
Identification, Flags, Fragment OffsetRouters no longer fragment in IPv6. If a packet is too large, the router discards it and returns an ICMPv6 "packet too big"; the source must then use Path MTU Discovery and send smaller packets. Source fragmentation, when needed, uses an extension header.
HLEN (header length)Unnecessary — the base header is always exactly 40 bytes.
Options and PaddingMoved out into extension headers, so the base header stays fixed and routers can process it at a predictable speed.

Extension headers

Optional headers placed between the base header and the payload, chained together by each one's Next Header field. Six are defined:

Extension headerPurpose
Hop-by-hop optionInformation that every router along the path must examine — for example jumbogram support
RoutingLists routers that must be visited — the equivalent of IPv4's source-route option
FragmentationFragmentation information, and only the source may use it
Authentication (AH)Validates the sender and protects the data from alteration — part of IPsec
Encrypted Security Payload (ESP)Provides confidentiality — part of IPsec
Destination optionInformation for the destination host only; routers ignore it

The design point worth stating: only the hop-by-hop extension header is examined by intermediate routers. All the others are read only at the destination, so routers stay fast even when many extension headers are present.

The three transition strategies

IPv4 and IPv6 cannot simply be swapped over on a fixed date, so three coexistence mechanisms are defined. This is a reliable 5-mark question — name all three and describe each in two lines.

StrategyHow it worksUsed when
1. Dual stackA host or router runs both IPv4 and IPv6 simultaneously, with an address of each kind. It queries DNS: if the reply is an IPv4 address it uses IPv4, if IPv6 it uses IPv6.The recommended first step, applied everywhere before any switchover
2. TunnellingTwo IPv6 nodes are separated by an IPv4-only region. The IPv6 packet is encapsulated inside an IPv4 packet for the crossing, and decapsulated at the far side.IPv6 islands within an IPv4 sea
3. Header translationThe header is rewritten completely from one version to the other by a translator at the boundary.Only when the receiver understands IPv4 but the sender is IPv6-only — i.e. once most of the Internet has moved and legacy hosts remain
The distinction between tunnelling and translation

Tunnelling wraps the packet and leaves it intact; translation rewrites the packet and destroys the original header. Tunnelling is used when both endpoints speak IPv6 and only the middle does not. Translation is used when the endpoints themselves speak different versions. Getting these the wrong way round is the usual mistake.

Check yourself

Retrieval practice

1. Which abbreviation of 2001:0DB8:0000:0000:0000:0000:1428:57AB is valid?

Leading zeros drop (0DB8 → DB8) and the one run of zero groups collapses to ::. Two :: is invalid because the split becomes ambiguous; and 0DB8 → DB is wrong because only leading zeros may go, not trailing ones.

2. Which address type does IPv6 NOT have?

Broadcast was removed because it forces every host to process a packet regardless of interest; its jobs are done by multicast to well-known groups such as FF02::1. Anycast — delivery to the nearest member of a group — is the type IPv6 adds.

3. The IPv6 header has no checksum because:

IPv4's checksum had to be recomputed at every hop because TTL changed — pure per-router cost. The data link layer's CRC and the transport layer's end-to-end checksum already cover it, so IPv6 drops the middle check and routers get faster.

4. If an IPv6 packet is too large for the next link, the router:

Routers never fragment in IPv6. The source is told and must use Path MTU Discovery to send smaller packets — which is why the identification, flags and offset fields disappeared from the header entirely.

5. Encapsulating an IPv6 packet inside an IPv4 packet to cross an IPv4-only region is:

Tunnelling wraps the packet and leaves the original intact, for use when both endpoints speak IPv6 but the middle does not. Translation rewrites the header outright and is for endpoints speaking different versions.

6. Which extension header is examined by every router along the path?

Only the hop-by-hop header is processed at every router; everything else is read at the destination. That is deliberate — it keeps routers fast no matter how many extension headers a packet carries.

Recall without looking

Give four reasons IPv6 was created.

IPv4 address exhaustion; no built-in support for real-time audio and video; no encryption or authentication in the original design; and a complex variable-length header requiring per-hop checksum recomputation and router fragmentation.

State the IPv6 address size, notation and the two abbreviation rules.

128 bits, written as eight groups of four hexadecimal digits separated by colons. Rule 1: leading zeros in a group may be dropped (trailing ones may not). Rule 2: one run of consecutive all-zero groups may be replaced by ::, and this may be done only once per address.

Name the three IPv6 address types and the one that was removed.

Unicast (one interface), multicast (all members of a group), anycast (the nearest member of a group). Broadcast was removed; its functions are served by multicast to well-known groups such as FF02::1.

Draw the IPv6 header with field sizes.

Version (4) | Traffic Class (8) | Flow Label (20); Payload Length (16) | Next Header (8) | Hop Limit (8); Source Address (128); Destination Address (128). Eight fields, fixed 40 bytes.

Which four things were removed from the IPv4 header, and why?

The header checksum (redundant, and costly to recompute each hop). Identification, flags and fragment offset (routers no longer fragment). HLEN (the base header is always 40 bytes). Options and padding (moved to extension headers so the base header stays fixed).

What is the flow label for?

It labels a sequence of packets belonging to one flow so routers can give them identical special handling without inspecting the higher layers — the mechanism that supports real-time audio and video.

Name the six extension headers.

Hop-by-hop option, routing, fragmentation, authentication (AH), encrypted security payload (ESP), and destination option. Only the hop-by-hop header is examined by intermediate routers.

Give eight differences between IPv4 and IPv6.

32 vs 128-bit addresses; dotted decimal vs colon hexadecimal; variable 20–60 byte vs fixed 40-byte header; 13 vs 8 fields; checksum present vs removed; router fragmentation allowed vs forbidden; options in-header vs extension headers; broadcast vs anycast; IPsec optional vs built in; ToS only vs traffic class and flow label; DHCP vs also stateless autoconfiguration; ARP vs Neighbour Discovery.

Name and describe the three transition strategies.

Dual stack — a node runs both protocols and chooses by what DNS returns. Tunnelling — an IPv6 packet is encapsulated inside an IPv4 packet to cross an IPv4-only region, then decapsulated. Header translation — the header is rewritten from one version to the other, used when the sender is IPv6-only and the receiver understands only IPv4.
