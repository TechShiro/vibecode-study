Exam strategy

Two big questions. (1) "Compare distance vector and link state routing" — a table, plus a worked distance-vector iteration if the question gives a network. Show the table at each step; marks are awarded per iteration. (2) "Explain the count-to-infinity problem and its solutions" — the mechanism plus the four fixes. Multicast is usually a shorter 5-mark question: source-based versus group-shared tree and the three protocols.

Distance Vector Routing

Based on the Bellman-Ford algorithm. Each router keeps a vector of distances to every destination, and knows only the cost to its immediate neighbours.

The Bellman-Ford update Dx(y) = min over all neighbours v of  [ c(x, v) + Dv(y) ]
"My cost to y = the cheapest of (cost to a neighbour + that neighbour's cost to y)"

The count-to-infinity problem

The central weakness of distance vector routing. Suppose A–B fails, but B has already told C that it can reach A at cost 1. C tells B "I can reach A at cost 2" — without knowing that C's own route goes through B. B believes it, sets its cost to 3, tells C, which sets 4, and so on. The cost creeps upward one step at a time, and until it reaches "infinity", packets for A loop between B and C.

FixHow it works
Define infinity as a small numberRIP treats 16 as infinity, so the count terminates in at most 16 rounds. The cost is that RIP cannot be used on networks with paths longer than 15 hops.
Split horizonA router does not advertise a route back on the interface it learned that route from. C stops telling B about a route to A that C learned from B in the first place.
Poison reverseStronger than split horizon: instead of staying silent, the router advertises that route back with a cost of infinity — an explicit "do not use me for this".
Hold-down timersAfter hearing that a route is unreachable, a router ignores updates about it for a set period, giving the bad news time to propagate everywhere before any new route is accepted.

The honest closing line: split horizon and poison reverse fix the two-router loop, but not loops involving three or more routers. That limitation is what motivated link state routing.

Link State Routing

Based on Dijkstra's shortest path algorithm. Every router builds a complete map of the whole network and then computes shortest paths itself.

The four steps 1. Each router discovers its neighbours and the cost to each.
2. It builds a Link State Packet (LSP) listing those neighbours and costs.
3. It floods the LSP to every router in the domain — so all routers end up with identical link state databases.
4. Each router runs Dijkstra's algorithm on that database to build its own shortest-path tree, and from it, its routing table.

Flooding means each router forwards a received LSP out of every interface except the one it arrived on. Because every router receives every LSP, all routers share the same view of the topology — and that shared, complete view is exactly what prevents the loops that plague distance vector.

Path vector routing deserves its own line: like distance vector, but each advertisement carries the entire list of autonomous systems the route passes through. A router seeing its own AS in the path knows the route is a loop and rejects it. It also allows policy-based decisions — an AS can refuse routes through a competitor regardless of cost, which is why BGP is what the Internet actually runs on.

Multicast routing

Why multicast is not just repeated unicast

Sending the same video to 1000 subscribers by unicast means 1000 copies leaving the source and traversing the same backbone links a thousand times. Multicast sends one copy, which routers duplicate only where the paths diverge. The saving in bandwidth and source load is the entire point — state it in any multicast answer.

RPF, RPB and RPM — the three refinements

The progression, each fixing the previous one's flaw RPF — Reverse Path Forwarding. A router forwards a multicast packet only if it arrived on the interface that lies on the router's own shortest path back to the source; otherwise it is discarded. Fixes: looping. Remaining flaw: a network with several routers still receives duplicate copies.

RPB — Reverse Path Broadcasting. For each network, one router is chosen as the parent, and only the parent forwards onto that network. Fixes: duplicates — the result is a genuine broadcast tree. Remaining flaw: it still delivers to networks with no group members.

RPM — Reverse Path Multicasting. Adds pruning — a network with no members sends a prune message and is cut from the tree — and grafting, which reattaches it when a member appears. Fixes: delivery to uninterested networks. This is true multicast.

The examiner's point is the progression: RPF stops loops, RPB stops duplicates, RPM stops waste. Present them in that order with the flaw each one addresses.

Dense mode vs sparse mode — the distinction to state

Dense mode assumes everyone wants the traffic: it floods first and prunes back. Efficient when most networks have members. Sparse mode assumes nobody wants it: nothing is sent until a router explicitly joins. Efficient when members are few and scattered — which is the normal case on the Internet, and why PIM-SM is what is actually deployed.

Check yourself

Retrieval practice

1. In distance vector routing, a router shares:

Distance vector: whole table, neighbours only. Link state is the mirror image — only its own link information, but flooded to everyone. Mixing the two halves is the standard error here.

2. Given A–B = 2, B–C = 1 and a direct A–C link of cost 5, A's best route to C is:

2 + 1 = 3 beats the direct link's 5. A direct link is not automatically the best route, and examiners choose costs precisely to test whether you check the alternatives.

3. Split horizon prevents count-to-infinity by:

Split horizon stops C telling B about a route C learned from B in the first place. The hop limit of 16 and hold-down timers are separate fixes, and flooding belongs to link state routing entirely.

4. Which protocol uses path vector routing, and why?

BGP advertises the full list of autonomous systems a route traverses. A router seeing its own AS knows immediately that the route loops, and the path also lets an AS refuse routes on policy grounds regardless of cost.

5. RPB improves on RPF by:

RPF stops loops but a network with several routers still receives duplicates; RPB designates a single parent per network to eliminate them. Pruning is the further step, RPM. Keep the progression in order: loops, duplicates, waste.

6. PIM sparse mode is preferred over dense mode when:

Dense mode floods then prunes, which only pays off when most networks want the traffic. Sparse mode sends nothing until a router explicitly joins — right for scattered members, which is the normal Internet case. PIM is protocol independent, so the unicast protocol is irrelevant.

Recall without looking

State the Bellman-Ford update rule.

Dx(y) = min over all neighbours v of [ c(x,v) + Dv(y) ] — my cost to y is the cheapest of (cost to a neighbour plus that neighbour's cost to y).

Give six differences between distance vector and link state routing.

Bellman-Ford vs Dijkstra; shares the whole routing table vs only its own link information; with neighbours only vs flooded to every router; no topology knowledge vs a complete map; periodic updates vs on-change only; slow vs fast convergence; suffers count-to-infinity vs immune; low vs high CPU and memory. Protocols: RIP vs OSPF.

Explain the count-to-infinity problem and its four fixes.

When a link fails, a neighbour may advertise back a route that actually ran through the failed link. The cost creeps up one step at a time while packets loop. Fixes: define infinity as a small number (16 in RIP); split horizon (do not advertise a route back on the interface it was learned from); poison reverse (advertise it back with infinite cost); hold-down timers (ignore updates about the route for a period). Split horizon and poison reverse do not fix loops involving three or more routers.

State the four steps of link state routing.

Discover neighbours and link costs; build a Link State Packet listing them; flood the LSP to every router so all share an identical link state database; run Dijkstra's algorithm on that database to build the shortest-path tree and the routing table.

Compare RIP, OSPF and BGP.

RIP — interior, distance vector, hop count metric with maximum 15, full table every 30 s, small networks. OSPF — interior, link state, cost based on bandwidth, LSPs on change, large networks with areas. BGP — exterior, path vector, policy-based, between autonomous systems, and the protocol the Internet backbone runs on.

Compare source-based and group-shared multicast trees.

Source-based: one tree per (source, group) pair, rooted at the source, optimal paths, high router state, suits dense groups — DVMRP, MOSPF, PIM-DM. Group-shared: one tree per group rooted at a core or rendezvous point, sub-optimal paths, low router state, suits sparse groups with many sources — CBT, PIM-SM.

Explain RPF, RPB and RPM and what each fixes.

RPF forwards a packet only if it arrived on the interface on the shortest path back to the source — this stops loops, but a network with several routers still gets duplicates. RPB designates one parent router per network so only it forwards there — this stops duplicates, but networks with no members still receive traffic. RPM adds pruning (and grafting to rejoin) so uninterested networks are cut from the tree — this is true multicast.

Distinguish PIM dense mode from sparse mode.

Dense mode assumes most networks want the traffic: it floods first and prunes back, using a source-based tree. Sparse mode assumes almost none do: nothing is sent until a router explicitly joins, using a group-shared tree rooted at a rendezvous point. Sparse mode is what is actually deployed, because Internet multicast groups are scattered.
