Classless Addressing (CIDR)

Slash notation, the three rules every block must obey, the mask table you should be able to write from memory, and the arithmetic for first address, last address and block size. This is the language subnetting is written in.

Exam strategy

The question is almost always "Given the address a.b.c.d/n, find the first address, the last address and the number of addresses in the block" — 5 marks, entirely mechanical. Learn one formula and one table: block size = 2(32−n), and the /24 to /30 mask values. With those you never need to write binary at all.

Why classless addressing exists

Classful addressing offered only three block sizes — 16.7 million, 65,534 or 254 addresses. An organisation needing 1000 addresses had to take a whole Class B and waste 98% of it. Classless addressing (CIDR — Classless Inter-Domain Routing) removes the classes entirely and allows a block of any power-of-two size.

Prefix and suffix A classless address is split into a prefix (the network part) and a suffix (the host part).
The prefix length n can be any value from 0 to 32 — it is no longer fixed at 8, 16 or 24.
Written as a.b.c.d/n — slash notation, or CIDR notation.
The three formulas Number of addresses N = 2(32 − n)
First address (network address) = address AND mask  (set the last 32−n bits to 0)
Last address (broadcast) = first address + N − 1  (set the last 32−n bits to 1)
Usable hosts = N − 2

How to rebuild the table if you forget it

The mask byte values run 128, 192, 224, 240, 248, 252, 254, 255 — each is the previous one plus the next power of two halved. The address counts run 128, 64, 32, 16, 8, 4, 2, 1. And the two are linked: mask byte + address count = 256. So /27 has 32 addresses and its mask byte is 256 − 32 = 224. That one relationship regenerates the whole table.

/30 is worth noting specially: four addresses, two usable. It is the standard mask for a point-to-point link between two routers, where exactly two addresses are needed and anything larger would waste them.

The three rules every block must obey

RuleMeaning
1. ContiguousThe addresses in the block must be consecutive, with no gaps.
2. Power of twoThe number of addresses must be a power of 2 — 2, 4, 8, 16, 32 …
3. DivisibilityThe first address must be evenly divisible by the number of addresses in the block.

Rule 3 is the one tested, because it is the one that can be checked with arithmetic. It is equivalent to saying the last 32−n bits of the first address are all zero. So 205.16.37.32/28 is valid (32 ÷ 16 = 2, exact) but 205.16.37.33/28 is not (33 ÷ 16 is not an integer).

Worked numerical 1 — the standard question

Q. A block is given as 167.199.170.82/27. Find the number of addresses, the first address, the last address, and the range of usable host addresses.

Number of addresses N = 2(32−27) = 25 = 32

First address. The prefix is 27 bits, so the first three bytes are untouched and only the last byte matters. The /27 mask's last byte is 224.

82 in binary = 01010010
224 in binary = 11100000
AND         = 01000000 = 64

First address = 167.199.170.64

Last address = first + N − 1 = 64 + 32 − 1 = 95
Last address = 167.199.170.95

Usable hosts = 32 − 2 = 30, ranging from 167.199.170.65 to 167.199.170.94

The shortcut that avoids binary entirely: with a block size of 32, the blocks in the last byte begin at 0, 32, 64, 96, 128, 160, 192, 224. The address 82 falls between 64 and 96, so its block starts at 64 and ends at 95. Counting up in steps of the block size is faster and less error-prone than ANDing — use it in the exam, and show the AND once to prove you know why it works.

Worked numerical 2 — using the shortcut

Q. Find the first and last addresses of the block containing 205.16.37.39/28.

N = 2(32−28) = 16

Blocks of 16 in the last byte start at: 0, 16, 32, 48, 64, 80, …

39 lies between 32 and 47, so:

First address = 205.16.37.32  ·  Last address = 205.16.37.47

Usable hosts = 14, from 205.16.37.33 to 205.16.37.46

Check against rule 3: 32 ÷ 16 = 2 exactly, so 205.16.37.32/28 is a valid block start. ✓

Worked numerical 3 — when the prefix is shorter than /24

Q. Find the first and last address of 140.120.84.24/20.

N = 2(32−20) = 212 = 4096 addresses

A /20 prefix means the mask is 255.255.240.0 — the split falls inside the third byte, so that is the byte to work on.

84 in binary = 01010100
240 in binary = 11110000
AND         = 01010000 = 80

First address = 140.120.80.0

The block spans 4096 addresses = 16 whole /24 blocks, so the third byte runs from 80 to 95 and the fourth byte from 0 to 255:

Last address = 140.120.95.255

Sanity check: 16 values of the third byte × 256 values of the fourth = 4096. ✓

The general rule: find which byte the prefix falls inside, and do the arithmetic only in that byte. Bytes before it are copied unchanged; bytes after it become 0 for the first address and 255 for the last.

Supernetting and route aggregation

The mirror image of subnetting: combining several small contiguous blocks into one larger block, so that backbone routers can advertise a single route instead of many. Also called route aggregation or route summarisation.

Worked example — aggregation

Q. An ISP has four adjacent /24 blocks: 200.11.4.0, 200.11.5.0, 200.11.6.0 and 200.11.7.0. Can they be aggregated, and into what?

Write the varying byte in binary:
4 = 00000100
5 = 00000101
6 = 00000110
7 = 00000111

The first six bits are identical (000001); only the last two vary. So the common prefix is 8 + 8 + 6 = 22 bits.

Aggregate block = 200.11.4.0/22, containing 210 = 1024 addresses — exactly the four /24 blocks combined. ✓

The conditions for aggregation, worth stating: the blocks must be contiguous, the count must be a power of two, and the first block's address must be divisible by the total number of addresses — the same three rules as any CIDR block. Here 200.11.4.0 is divisible by 1024 when read as a 32-bit number, so it qualifies.

The one-line answer to "why CIDR?"

CIDR lets an organisation be given a block that matches its actual size, and lets routers advertise many small blocks as one entry. The first fixes address depletion; the second fixes routing table growth. Name both — most answers name only the first.

Check yourself

Retrieval practice

1. How many addresses are in the block 192.168.10.0/26?

The block contains 64 addresses; 62 is the number of usable host addresses after removing the network and broadcast addresses. Read the question carefully — "addresses in the block" and "assignable hosts" differ by exactly 2.

2. The first address of the block containing 205.16.37.39/28 is:

Block size 16, so blocks begin at 0, 16, 32, 48… and 39 falls in the block starting at 32. The given address itself is rarely the first address — that would only happen if it were already divisible by the block size.

3. Which of these is NOT a valid CIDR block?

Rule 3: the first address must be divisible by the block size. A /28 block holds 16 addresses, and 20 ÷ 16 is not an integer, so 20 cannot start a block. 16, 32 and 0 all divide exactly.

4. The mask 255.255.255.248 corresponds to which prefix, and how many usable hosts?

256 − 248 = 8 addresses, so 32 − 3 = /29, and 8 − 2 = 6 usable. The mask-byte-plus-block-size-equals-256 relationship gets you there without memorising the whole table.

5. Four contiguous /24 blocks starting at 200.11.4.0 aggregate into:

Four /24s combine into one block four times as large, so the prefix shortens by log₂4 = 2 bits: /24 → /22. Aggregation always shortens the prefix; a longer prefix such as /26 would mean a smaller block, which is subnetting instead.

6. A /30 mask is typically used for:

/30 gives 4 addresses, 2 usable — precisely one for each end of a router-to-router link. Anything larger would waste addresses on a link that can never hold more than two devices.

Recall without looking

Write the three CIDR formulas.

Number of addresses N = 2^(32 − n). First address = address AND mask (last 32−n bits set to 0). Last address = first + N − 1 (last 32−n bits set to 1). Usable hosts = N − 2.

State the three rules a CIDR block must satisfy.

The addresses must be contiguous; the number of addresses must be a power of two; and the first address must be evenly divisible by the number of addresses in the block.

Write the mask table from /24 to /30.

/24 = 255.255.255.0, 256 addresses. /25 = .128, 128. /26 = .192, 64. /27 = .224, 32. /28 = .240, 16. /29 = .248, 8. /30 = .252, 4. Rebuild it with: mask byte + block size = 256.

What is the fastest way to find the first address without binary?

Compute the block size 2^(32−n), then count up in steps of that size in the byte where the prefix falls: 0, N, 2N, 3N… The given address lies in one of those blocks, and that block's start is the first address. Bytes before the split are copied; bytes after become 0.

Define supernetting and state its conditions.

Combining several small contiguous blocks into one larger block so routers can advertise a single route — also called route aggregation or summarisation. The blocks must be contiguous, their number a power of two, and the first block's address divisible by the total number of addresses.

Give four differences between classful and classless addressing.

Three fixed block sizes versus any power of two; prefix fixed at 8/16/24 by class versus variable 0–32; mask implied by the class versus carried explicitly with the address; wasteful with large routing tables versus efficient with route aggregation.
