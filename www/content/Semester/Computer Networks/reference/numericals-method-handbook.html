Numericals — How to Solve Them

Every numerical type in the CO CSC 501 syllabus, with the method rather than just the answer: how to recognise the question, the formula, the steps in order, the specific trap, and the check that catches your own mistake. The lessons have the worked examples; this has the procedure.

How to attack ANY numerical — the four steps that apply to all of them
  1. Write the formula down before substituting anything. Most lost marks are not conceptual — they are substituting into a half-remembered formula. Writing it first also earns partial credit if the arithmetic then fails.
  2. Convert every unit before you start. ms to s, kbps to bps, KB to bits, dB to a plain ratio. Do all conversions in one visible line, so a marker can see the working.
  3. Show the substitution, then the result. Two lines per step. Never jump from formula to answer.
  4. Run the sanity check named in the relevant section below, and write that you ran it. It catches your own errors and it frequently carries a mark of its own.

Unit I

1. Latency, propagation, transmission, BDP Lesson 1

Recognise it
The question gives a distance and a propagation speed, and/or a message size and a bandwidth.
Formulas
Propagation time = distance ÷ propagation speed Transmission time = message size ÷ bandwidth Latency = propagation + transmission + queuing + processing BDP = bandwidth × propagation delay RTT = 2 × propagation time
Method
  1. Convert everything to base units: km → m, ms → s, Mbps → bps, bytes → bits (×8).
  2. Compute propagation time from the distance pair only.
  3. Compute transmission time from the size pair only.
  4. Add. Ignore queuing and processing unless the question gives them.
Trap
Propagation time never uses message size; transmission time never uses distance. Writing both formulas before substituting makes it impossible to cross them. If no speed is given, state your assumption — usually 2 × 108 m/s in cable.
Check
Compare the message size with the BDP. If the message is larger than the BDP, transmission time must be the bigger of the two; if smaller, propagation dominates.

2. Topology link and port counts Lesson 4

Recognise it
"n devices connected in a mesh/star/ring — how many links / ports?" Or the reverse: given the links, find n.
Formulas
Mesh: duplex links = n(n−1)/2   simplex links = n(n−1) Mesh ports per device = n−1   total ports = n(n−1) Star: n links, 1 port each, n on the hub Ring: n links, 2 ports each
Method (forwards)
Substitute n and evaluate. Read the question for "duplex" or "simplex"; if it says neither, assume duplex and write that you assumed it.
Method (backwards)
  1. Set n(n−1)/2 = given links, so n(n−1) = 2 × links.
  2. Find two consecutive integers with that product — faster than the quadratic. For 132: 11×12, so n = 12.
  3. Only set up n² − n − 2L = 0 if the numbers are awkward. Discard the negative root.
Trap
Halving twice, or not at all. Simplex count is exactly double the duplex count, and it also equals the total port count.
Check
Total ports = 2 × duplex links, because every duplex link has two ends. For n = 8: 28 links, 56 ports. ✓

Unit II

3. Signal basics — period, frequency, wavelength, bandwidth Lesson 7

Formulas
f = 1/T   T = 1/f λ = propagation speed ÷ f Bandwidth of a composite signal = f(highest) − f(lowest) Bit interval = 1 ÷ bit rate Bit length = propagation speed × bit interval A signal with L levels carries log₂L bits per level
Method
Convert to base units first (ms → s, kHz → Hz), substitute, then convert the answer to whatever unit the question asked for. State the unit on every line.
Trap
Bandwidth is a width. Sliding the whole band up or down does not change it — so "the lowest frequency is shifted to X, bandwidth unchanged" means the new highest is simply X + bandwidth.
Check
A long period must give a low frequency, and vice versa. If both came out large, you inverted the wrong one.

4. Decibels and SNR Lesson 7

Formulas
dB = 10 log₁₀(P₂ / P₁) SNR = average signal power ÷ average noise power SNR(dB) = 10 log₁₀(SNR) To convert back: SNR = 10^(SNR(dB) / 10)
Method
  1. Form the ratio P₂/P₁ — after over before.
  2. Take log₁₀ and multiply by 10.
  3. For a chain of links, add the dB values; do not multiply the ratios.
Trap
A negative dB means attenuation, positive means amplification. Getting the sign wrong usually means you inverted the ratio.
Check
Memorise halving the power = −3 dB, doubling = +3 dB, one tenth = −10 dB. Nearly every dB question in this syllabus is built from those.

5. Nyquist bit rate — noiseless channel Lesson 8

Recognise it
The question gives bandwidth and the number of signal levels L, and says the channel is noiseless. Or it gives a bit rate and asks for L.
Formula
BitRate = 2 × B × log₂L
Method (forwards)
Evaluate log₂L first as a plain number (L = 2→1, 4→2, 8→3, 16→4), then multiply.
Method (backwards — find L)
  1. Rearrange: log₂L = BitRate ÷ (2B).
  2. L = 2 raised to that value.
  3. If L is not a power of 2, say so explicitly — the answer to that question is "this bit rate is not achievable on this channel; increase the bandwidth or lower the rate." The impossibility is the answer.
Trap
Forgetting the factor of 2. Nyquist has it; Shannon does not. Also: doubling L does not double the rate — going 4→8 multiplies it by 3/2, because log₂ goes 2→3.
Check
The bit rate must be a whole multiple of 2B. If it is not, either L is wrong or the arithmetic is.

6. Shannon capacity — noisy channel Lesson 8

Recognise it
The question gives SNR, or mentions noise, or asks for the "maximum/highest possible" data rate. No signal levels are given, and none are needed.
Formula
Capacity = B × log₂(1 + SNR)
Method
  1. If SNR is given in dB, convert first: SNR = 10^(dB/10). This is the step most often skipped.
  2. Add 1 to the SNR.
  3. Take log₂ of that. Examiners choose SNR = 1, 3, 7, 15, 31, 63, 127 so that 1+SNR is a clean power of 2.
  4. Multiply by B.
Trap
No factor of 2, and no L. If you wrote 2 × B × log₂(1+SNR) you have merged the two formulas. And substituting a dB value directly is the single commonest error in Unit II.
Check
If 1+SNR came out as a clean power of 2, you are on the intended path. If SNR = 0 the capacity is 0 no matter how wide the channel — a useful edge case to recognise. Shortcut for large SNR: Capacity ≈ B × SNR(dB) / 3.

7. Nyquist and Shannon together Lesson 8

Recognise it
The question gives bandwidth and SNR, then asks for "the appropriate bit rate and signal level". Two answers are wanted.
Method — three steps, in this order
  1. Shannon gives the ceiling. C = B log₂(1+SNR).
  2. Choose a working rate below it — Shannon's limit is theoretical and unreachable in practice. Two thirds of C is a sensible choice; state that you chose it.
  3. Nyquist gives the levels for that chosen rate: rate = 2B log₂L, solve for L.
Trap
Stopping after step 1. The question asked for two things, and most answers give only the capacity.
Check
L must come out a power of 2. Close with the sentence "Shannon gives the limit; Nyquist gives the signal design."

8. Throughput Lesson 8

Recognise it
"A network passes X frames per minute, each of Y bits — find the throughput."
Method
  1. Total bits = frames × bits per frame.
  2. Divide by the time period in seconds (per minute → ÷60).
  3. Compare with the stated bandwidth and say what fraction it is.
Trap
Leaving the answer in bits per minute. And omitting step 3 — the comparison is usually worth a mark, because it turns a calculation into a conclusion.
Check
Throughput can never exceed bandwidth. If it did, re-read the units.

9. FDM bandwidth with guard bands Lesson 10

Formula
Link bandwidth = (n × channel bandwidth) + ((n−1) × guard band)
Method
Multiply channels by their bandwidth, then add n−1 guard bands.
Trap
n channels need n−1 guard bands, not n. Guard bands sit between channels, so there is none before the first or after the last.
Check
Draw five boxes on your page and count the gaps between them: four. That settles it in two seconds.

10. Synchronous TDM Lesson 10

Formulas
Frame rate = input data rate ÷ bits per slot Frame duration = 1 ÷ frame rate Frame size = (n × bits per slot) + framing bits Output data rate = frame rate × frame size Output bit duration = input bit duration ÷ n
Method
  1. Find the input bit duration = 1 ÷ input rate.
  2. Find the frame rate — for bit interleaving it equals the input rate; for character interleaving it equals characters per second.
  3. Build the frame size: n slots plus any framing bits.
  4. Output rate = frame rate × frame size. Slot duration = frame duration ÷ n.
Trap
Forgetting the framing bits in the frame size, which makes the output rate slightly too low.
Check
Frame duration must equal the input bit duration. In the time one source produces a single bit, the multiplexer completes exactly one full round. If those two numbers differ, something is wrong. Also cross-check: data-only output rate = n × input rate, and the framing overhead is the difference.

11. Packet-switching delay Lesson 12

Formulas
Per-packet, per-link time t = packet size ÷ bandwidth Packet switching total = (L + p − 1) × t Circuit switching total = setup time + (whole message ÷ bandwidth) where L = number of links (hops), p = number of packets.
Method
  1. Count the links, not the switches. Two intermediate switches means three links.
  2. Compute t for one packet on one link.
  3. Apply (L + p − 1) × t. Add propagation delay per link if the question gives it.
  4. For circuit switching, the bits stream through continuously — there is no store-and-forward at the switches, so it is setup plus one whole-message transmission.
Trap
Computing L × p × t. That ignores pipelining — later packets move along earlier links while the first packet is still travelling. The −1 is where the pipelining lives.
Check
With p = 1 the formula must reduce to L × t, which is just one packet crossing every link. If it does not, you have mis-set L or p.

12. Hamming distance and error capability Lesson 13

Formulas
d(x,y) = number of differing bit positions = count of 1s in (x XOR y) To DETECT up to s errors: d(min) ≥ s + 1 To CORRECT up to t errors: d(min) ≥ 2t + 1
Method
XOR the two words, count the 1s. For capability, rearrange: s = dmin − 1, and t = the largest integer with 2t + 1 ≤ dmin, i.e. t = floor((dmin − 1)/2).
Trap
Giving the same number for both. Detection is always the larger — dmin = 4 detects 3 but corrects only 1.
Check
Detection count must exceed correction count. If they are equal, you applied one rule twice.

13. CRC Lesson 13

Method — sender
  1. Count the divisor's bits, n. Append n−1 zeros to the dataword.
  2. Take the leading n bits as the current value.
  3. If the leading bit is 1, XOR with the divisor. If it is 0, XOR with all zeros — do not skip the step.
  4. Drop the (now zero) leading bit and bring down the next dividend bit.
  5. Repeat until every dividend bit has been brought down. What remains is the remainder = CRC.
  6. Codeword = dataword with the appended zeros replaced by the CRC.
Method — receiver
Divide the received codeword by the same divisor. Zero remainder → accept. Always show this; it is usually a mark and it verifies your own division.
Trap
Skipping the leading-zero steps, which loses a bring-down and silently shifts everything. And using subtraction with borrows — CRC is mod 2: XOR only, no carries, no borrows.
Check
The remainder must have exactly one fewer bit than the divisor. A 5-bit divisor gives a 4-bit remainder. Also: the number of division steps equals the number of appended-zero positions plus the dataword length minus the divisor length plus 1.

14. Checksum Lesson 13

Method — sender
  1. Split the data into equal-size words.
  2. Add them using one's complement addition: if the sum carries out of the leftmost bit, add that carry back into the rightmost bit.
  3. Complement the final sum — that is the checksum. Send it with the data.
Method — receiver
Add all the words including the checksum, then complement. All zeros → accept.
Trap
Forgetting the wraparound carry, and forgetting to complement at the end.
Check
At the receiver, the sum before complementing must be all 1s. If it is not, either an error occurred or your arithmetic did.

15. Hamming code Lesson 13

Method — encoding
  1. Find r from 2r ≥ m + r + 1, testing r = 1, 2, 3… upward until it holds.
  2. Draw positions 1 to m+r, numbered from 1 at the left. Put parity bits at the powers of two (1, 2, 4, 8) and the data bits, in order, everywhere else.
  3. For each parity bit p, list the positions it covers: check p, skip p — p₁ covers 1,3,5,7…; p₂ covers 2,3,6,7,10,11…; p₄ covers 4,5,6,7,12…; p₈ covers 8–15.
  4. Sum the data bits in each group and set p to make the total even (for even parity).
Method — detecting and correcting
  1. Recompute each check, now including the parity bit itself. Write 1 if the count of 1s is odd, 0 if even.
  2. Read the results as a binary number with the highest-numbered check as the most significant bit: c₈c₄c₂c₁.
  3. That number is the position of the wrong bit. Flip it.
  4. Strip positions 1, 2, 4, 8 to recover the data.
Trap
Reading the syndrome backwards. c₁c₂c₄c₈ produces a plausible-looking but wrong position every single time, with nothing to signal the error. Also: a syndrome of all zeros means no error, not "error at position 0".
Check
Recompute the checks on your corrected word — the syndrome must come out all zeros. And confirm the recovered data matches the original.

16. Bit stuffing Lesson 14

Method
Scan left to right. After every run of five consecutive 1s, insert a 0. The count then restarts from zero — the stuffed 0 breaks the run.
Trap
Counting to six before inserting. By then the false flag already exists. Also forgetting that the counter resets after each insertion, which matters for a run of ten or more 1s.
Check
Read your answer back and confirm it contains nowhere six consecutive 1s. If it does, you missed an insertion.

17. Sliding window efficiency Lesson 14

Formulas
T(t) = frame size ÷ bandwidth T(p) = distance ÷ propagation speed a = T(p) / T(t) Stop-and-Wait: efficiency = 1 / (1 + 2a) Go-Back-N and Selective Repeat: efficiency = N / (1 + 2a), capped at 1 Throughput = efficiency × bandwidth Optimal window N = 1 + 2a GBN sender window = 2^m − 1   SR sender window = 2^(m−1)
Method
  1. Compute Tt and Tp separately.
  2. Compute a — everything else depends on it, so get it right first.
  3. Apply the efficiency formula for the named protocol.
  4. Throughput = efficiency × bandwidth. Add the comparison sentence: "the link delivers X of its Y capacity."
  5. If asked for sequence-number bits: set the window formula ≥ the required N and solve for the smallest m.
Trap
Forgetting to double a. The acknowledgement has to travel back, so the cycle is 1 + 2a, not 1 + a. And if efficiency comes out above 1, cap it at 100% — the window is simply larger than needed.
Check
If N is less than the optimal 1+2a, efficiency must be below 100%. Selective Repeat always needs one more sequence-number bit than Go-Back-N for the same window — if yours came out equal, re-check which formula you used.

18. ALOHA throughput Lesson 16

Formulas
T(fr) = frame size ÷ bandwidth G = stations × frames per second per station × T(fr) Pure ALOHA: S = G × e^(−2G)   max 0.184 at G = 0.5 Slotted ALOHA: S = G × e^(−G)   max 0.368 at G = 1 Successful frames per second = S ÷ T(fr)
Method
  1. Compute the frame time Tfr first.
  2. Compute G = the average number of frames generated per frame-time across all stations.
  3. Substitute into the right formula — pure has the 2 in the exponent, slotted does not.
  4. If asked for frames per second, divide S by Tfr.
Trap
Using frames per second as G. G is measured per frame-time, so it must be multiplied by Tfr.
Check
Slotted must always beat pure at the same G. Neither can exceed its maximum (0.184 / 0.368). If yours does, G was computed wrongly.

19. CSMA/CD minimum frame size Lesson 16

Formulas
Slot time = 2 × T(p)   (the round trip) L(min) = 2 × T(p) × bandwidth Backoff after k collisions: a random wait from 0 to (2^k − 1) slots
Method
  1. Get the one-way propagation time Tp — from distance and speed if not given directly.
  2. Double it for the round trip.
  3. Multiply by the bandwidth. Convert bits to bytes if asked.
Trap
Forgetting the factor of 2. The station must still be transmitting when the collision signal gets back to it, so the round trip is what matters.
Check
For 10 Mbps Ethernet with Tp = 25.6 µs the answer is 512 bits = 64 bytes, which is Ethernet's real minimum frame size. If a question's numbers give something near that, you are on track — and saying so earns a mark.

20. CDMA encode and decode Lesson 17

Formulas
Composite = Σ (d(i) × c(i)) over all stations Decode station i: d(i) = (Composite · c(i)) ÷ N where the dot is element-wise multiply then sum, and N = code length
Method
  1. Convert the data to ±1 first: bit 1 → +1, bit 0 → −1, silent → 0.
  2. Multiply each station's code by its data value, giving one vector each.
  3. Add the vectors element by element to get the composite.
  4. To decode, multiply the composite by that station's code element by element, sum the results, and divide by N.
Trap
Treating a silent station as sending 0, i.e. as −1. Silent contributes nothing; sending a 0 bit contributes the negated code. Confusing the two corrupts the whole composite.
Check
Every decoded value must come out as exactly +1, −1 or 0. Orthogonal codes guarantee clean integers — a fraction means an arithmetic slip. Decode all stations, not just the one asked for; it takes seconds and proves the composite.

Unit III

21. Classful addressing Lesson 20

Recognise it
An IP address is given with no /prefix. The default mask comes from its class.
Method
  1. Read only the first byte to get the class: 1–126 = A, 128–191 = B, 192–223 = C, 224–239 = D, 240–255 = E.
  2. Write the default mask: A = /8, B = /16, C = /24.
  3. Network address = replace all host bytes with 0.
  4. Broadcast address = replace all host bytes with 255.
  5. Host range = network+1 to broadcast−1. Usable hosts = 2(host bits) − 2.
Trap
Forgetting the −2, and setting only the last byte for a Class B (both last two bytes are host bytes).
Check
First host = network + 1 and last host = broadcast − 1, always. Show the AND operation in binary once to demonstrate the mechanism, then use the shortcut.

22. CIDR block — first and last address Lesson 21

Formulas
Number of addresses N = 2^(32 − n) Usable hosts = N − 2 Mask byte + block size = 256 (use this to rebuild the mask table)
Method — without binary
  1. Compute the block size N = 2(32−n).
  2. Find which byte the prefix falls in: /1–8 first byte, /9–16 second, /17–24 third, /25–32 fourth.
  3. In that byte, count up in steps of the block size: 0, N, 2N, 3N… The given address falls inside one of those intervals; its start is the first address.
  4. Bytes before the split are copied unchanged. Bytes after become 0 for the first address and 255 for the last.
  5. Last address = first + N − 1.
Trap
Assuming the given address is the first address. It only is if it happens to be divisible by the block size. Also: for a prefix shorter than /24, the block spans several values of an earlier byte.
Check
The first address must be divisible by the block size (rule 3 of CIDR). And "number of addresses in the block" and "usable hosts" differ by exactly 2 — read which one was asked.

23. Subnetting Lesson 22

Formulas
Number of subnets = 2^s (s = bits borrowed) Addresses per subnet = 2^h (h = 32 − new prefix) Usable hosts per subnet = 2^h − 2 New prefix = old prefix + s
Method — five steps
  1. Decide s. Given a subnet count: smallest s with 2s ≥ subnets needed. Given a host count: smallest h with 2h − 2 ≥ hosts needed, then s = 32 − old prefix − h.
  2. New prefix = old + s. Write its mask.
  3. Block size = 2h = 256 − (last non-255 byte of the mask).
  4. List the subnets by counting up in block-size steps in the relevant byte.
  5. For each, write network address, first host, last host, broadcast — four columns.
Trap
Stopping at the first s you try instead of testing upward. And with a non-power-of-two requirement (6 subnets → s = 3 → 8 subnets), say explicitly how many subnets go unused — that comment is often a mark.
Check
Three checks, all quick: each subnet's broadcast is one less than the next subnet's network address; the last broadcast equals the last address of the original block; and subnets × addresses per subnet = the original block size.

24. VLSM Lesson 22

Recognise it
Several departments with different host requirements out of one block. Fixed-size subnetting will not fit them.
Method
  1. Sort the requirements into descending order. This is the whole trick — do it before anything else.
  2. For each, find the smallest power of two with 2h − 2 ≥ hosts needed, and the prefix that gives it.
  3. Allocate consecutively from the start of the block, largest first, each new block starting where the previous one ended.
  4. For each, write network/prefix, host range, broadcast.
  5. State what remains unallocated.
Trap
Allocating in the order the question lists the departments. This puts a large block at a boundary that cannot hold it, breaking the divisibility rule, and the whole plan then fails. The error is unrecoverable — you have to start again.
Check
Two checks: the allocated sizes plus the leftover must sum to the block size; and every block's start offset must be divisible by that block's own size. Write both out.

25. IPv4 fragmentation Lesson 23

Formulas
Data per fragment = MTU − header, ROUNDED DOWN to a multiple of 8 Number of fragments = ceiling(total data ÷ data per fragment) Offset = (bytes of data before this fragment) ÷ 8 Total length = this fragment's data + header MF = 1 on every fragment except the last
Method
  1. Total data = datagram size − header (usually 20).
  2. Data per fragment = MTU − header, then round down to a multiple of 8.
  3. Number of fragments = total data ÷ data per fragment, rounded UP.
  4. Build a table: fragment number, data bytes, total length, MF, offset. The last fragment carries the remainder.
  5. Offsets rise by (data per fragment ÷ 8) each time.
Trap
Two opposite roundings in one question: the fragment size rounds DOWN, the fragment count rounds UP. Conflating them is the commonest failure. Second trap: reporting offsets as byte positions instead of dividing by 8.
Check
The fragment data bytes must sum to the original data; only the last has MF = 0; all share the same identification; and the total transmitted exceeds the original by (fragments − 1) × header bytes.

26. Distance vector routing Lesson 26

Formula
D(x→y) = minimum over all neighbours v of [ cost(x,v) + D(v→y) ]
Method
  1. Write each router's initial table: 0 to itself, the direct cost to each neighbour, ∞ to everything else.
  2. For the router asked about, take each destination in turn and evaluate the Bellman-Ford expression through every neighbour, including the direct link if one exists.
  3. Take the minimum and record the next hop, not just the cost.
  4. Run another exchange. If nothing changes, the algorithm has converged — say so.
Trap
Assuming the direct link is the best route. Examiners choose costs specifically so it is not — always compare it against the via-neighbour options. Also: omitting the next-hop column, which is half the answer.
Check
Costs can only ever decrease or stay the same across iterations. And state explicitly that you ran one more round to confirm convergence — that step is usually a mark and most answers skip it.

Unit IV

27. TCP sequence and acknowledgement numbers Lessons 30, 31

Rules
Sequence number = number of the FIRST data byte in this segment Acknowledgement number = number of the NEXT byte expected (cumulative) SYN consumes 1 sequence number FIN consumes 1 sequence number A pure ACK consumes 0
Method
  1. Draw a table with columns: direction, flags, seq, ack, data bytes. One row per segment.
  2. Fill the handshake: SYN seq = x; SYN+ACK seq = y, ack = x+1; ACK seq = x+1, ack = y+1.
  3. For each data segment, seq = the previous seq from that side plus the bytes that side has already sent.
  4. Each ack = the other side's last seq + its data bytes (+1 for a SYN or FIN).
Trap
Acknowledging the last byte received rather than the next byte expected — off by one every time. And forgetting that a pure ACK consumes no sequence number, so the following data segment reuses the same seq.
Check
Every acknowledgement number should equal the other side's sequence number plus what it sent. Trace one side's seq down the table — it must rise only by data bytes and by the 1s for SYN and FIN.

28. Effective (usable) window Lesson 32

Formulas
Send window = minimum(rwnd, cwnd) Usable window = send window − bytes outstanding
Method
Take the smaller of rwnd and cwnd, then subtract the bytes already sent but not yet acknowledged.
Trap
Using rwnd alone. If cwnd is the smaller, opening the receiver's window changes nothing — congestion is the binding constraint. Saying which limit is actually operating is worth a mark.
Check
The usable window can never be negative. If it is, either the outstanding count is wrong or the receiver shrank its window — the situation TCP discourages.

29. Congestion window trace Lesson 33

Rules
Slow start: cwnd DOUBLES each RTT, until cwnd reaches ssthresh Congestion avoidance: cwnd increases by 1 each RTT TIMEOUT: ssthresh = cwnd/2, cwnd = 1, go to slow start 3 DUPLICATE ACKs (Reno): ssthresh = cwnd/2, cwnd = ssthresh, STAY in congestion avoidance 3 DUPLICATE ACKs (Tahoe): same as a timeout — cwnd = 1
Method
  1. Draw a table: RTT, cwnd, ssthresh, phase. One row per round — do not try to do it in your head.
  2. Double each round while in slow start, stopping at ssthresh and switching phase there.
  3. Add 1 each round in congestion avoidance.
  4. At a loss event, halve ssthresh from the cwnd value at the moment of loss, then set cwnd per the rule above.
  5. The reduced window applies from the next round. State that convention.
Trap
Doubling past ssthresh. If cwnd is 4 and ssthresh is 6, the next value is 6 — not 8. Second trap: treating duplicate ACKs like a timeout, which is Tahoe, not Reno.
Check
cwnd must never exceed ssthresh while in slow start. ssthresh should be halved from the loss-moment cwnd, not from the old ssthresh. If your Reno and Tahoe traces are identical, you applied one rule to both events.

30. Retransmission timeout (RTO) Lesson 34

Formulas
First measurement: RTT(S) = RTT(M), RTT(D) = RTT(M)/2 Afterwards: RTT(S) = (1−α)×old RTT(S) + α×RTT(M) α = 1/8 RTT(D) = (1−β)×old RTT(D) + β×|RTT(S) − RTT(M)| β = 1/4 RTO = RTT(S) + 4 × RTT(D)
Method
  1. Handle the first measurement specially — it is taken as-is, with deviation half of it.
  2. For each later measurement, compute the new RTTS first.
  3. Then compute RTTD using that new RTTS, not the old one.
  4. Then RTO. Repeat per measurement, showing all three values each time.
Trap
Using the old RTTS in the deviation line. The order matters: smoothed first, deviation second, RTO third.
Check
RTO must be comfortably larger than RTTS — that is the whole purpose of the 4×deviation term. If RTO ever came out close to or below RTTS, something is wrong.

31. HTTP page load time Lesson 39

Formulas
Non-persistent: total = (number of objects) × 2 × RTT Persistent: total = 1 RTT (setup) + (number of objects) × 1 RTT With P parallel connections: batches = ceiling(images ÷ P)
Method
  1. Count the objects, including the base HTML file. "A page with 10 images" means 11 objects.
  2. Non-persistent: each object pays 1 RTT for its own handshake plus 1 RTT for request-and-response.
  3. Persistent: one handshake for the whole session, then 1 RTT per object.
  4. If parallel connections are mentioned, the base file goes first alone, then the images in batches.
  5. Ignore transmission time unless the question gives object sizes and a bandwidth.
Trap
Forgetting the base HTML file in the object count. And charging a setup RTT per object in the persistent case — that is exactly what persistence removes.
Check
Persistent must beat non-persistent for the same number of parallel connections. If it does not, you double-counted the setup.

32. RSA Lesson 41

Formulas
n = p × q φ(n) = (p−1)(q−1) choose e with 1 < e < φ(n) and gcd(e, φ(n)) = 1 find d with e × d ≡ 1 (mod φ(n)) Public key (e, n) Private key (d, n) Encrypt: C = P^e mod n Decrypt: P = C^d mod n
Method
  1. Compute n and φ(n) — keep them clearly labelled; they are used for different things.
  2. Find d by trial: multiply e by 1, 2, 3… until the product is exactly 1 more than a multiple of φ(n). (Extended Euclid is faster but trial is fine at exam sizes.)
  3. Encrypt by square and multiply: write the exponent as a sum of powers of two, compute P², P⁴, P⁸… each time reducing mod n, then multiply the needed ones together, reducing at every multiplication.
  4. Decrypt the same way and confirm you get the original plaintext back.
Trap
Confusing n with φ(n) — φ is used only to find d, n is used in all the modular arithmetic. Second trap: computing the power in full. 48103 has 173 digits; reduce at every single step.
Check
Every intermediate value must be less than n. If one is not, you did not reduce. And always decrypt to verify — if you do not recover the plaintext, something upstream is wrong, and the verification usually carries a mark.
The five sanity checks worth memorising above all others
  1. CRC: the remainder has one fewer bit than the divisor.
  2. Subnetting: subnets × addresses per subnet = the original block size.
  3. TDM: frame duration = input bit duration.
  4. Fragmentation: the fragment data bytes sum to the original data.
  5. RSA: decrypt to recover the plaintext.

Each takes under ten seconds and each catches a whole class of error. Write that you ran the check — markers award for it, and it is the difference between a wrong answer and a right one you can trust.
