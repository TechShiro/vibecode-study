The rule if you forget: bulk or lossless → TCP. Short request-reply, or needed before a connection is possible → UDP.

Client-server: fixed roles, server always-on with a well-known address, client always initiates, server is the bottleneck and single point of failure. P2P: every peer is both, self-scaling, no single point of failure, weak security.

DNS 10 marks

Why distributed: a single file would be a single point of failure, could not carry the query volume, would be far from most users, and would need constant redistribution.

Namespace: inverted tree, max 128 levels. Label ≤ 63 chars, name ≤ 255. FQDN ends at the root (trailing dot); PQDN does not.

TLDs: generic (com, org, edu) · country (in, uk) · inverse (in-addr.arpa) for reverse lookup.

Domain vs zone A domain is a subtree of the namespace. A zone is what a server is actually responsible for — the domain minus any delegated subdomains.

A real lookup uses both: the host-to-local-server half is recursive, the local-server-to-hierarchy half is iterative.

Servers: root (delegates) · primary (creates and maintains the zone file) · secondary (gets it by zone transfer, cannot update) · local/resolver.

Caching: cuts time and traffic; staleness managed by TTL and by marking replies unauthoritative.

Records: A (IPv4) · AAAA (IPv6) · NS (name server) · CNAME (alias) · MX (mail server) · SOA (zone parameters) · PTR (reverse).

UDP 53 for queries; TCP for zone transfers and for responses over 512 bytes.

DHCP 5 marks

DORA DISCOVER (broadcast, src 0.0.0.0) → OFFER (broadcast — client has no address yet) → REQUEST (broadcast — so unchosen servers release their offers) → ACK

Supplies four things: IP address, subnet mask, default gateway, DNS server.

Allocation: static (MAC-bound) · automatic (permanent from pool) · dynamic (leased).

Timers: T1 = 50% unicast renewal to the original server · T2 = 87.5% broadcast rebinding to any server · 100% = abandon and restart DORA.

Relay agent: routers do not forward broadcasts, so the router converts DISCOVER into a unicast to the configured server. This is what lets one server serve a whole campus.

RARP → BOOTP → DHCP: RARP gives only an address and cannot cross a router; BOOTP crosses routers but needs every client pre-registered; DHCP does both and allocates dynamically.

FTP, TELNET, SSH

FTP uses TWO connections Control — port 21, open for the whole session, commands and replies only
Data — port 20, opened and closed per file, data only

Why two: commands must be deliverable during a transfer (so ABORT works), and data needs its type and structure negotiated separately.

Active = server connects back (PORT) — firewalls block it. Passive = client connects out (PASV) — the modern default.

Attributes: file type (ASCII / EBCDIC / image) · structure (file / record / page) · mode (stream / block / compressed).

TFTP: port 69, UDP, no authentication, one connection, its own stop-and-wait.

NVT: a universal intermediate character form, so each system needs only its own translator plus the standard — n translators rather than n². Data chars have the top bit 0; control chars top bit 1, preceded by IAC (255).

TELNET modes: default (line on Enter) · character (very inefficient — this is what Nagle exists for) · line mode.

SSH (22) vs TELNET (23): everything encrypted, server authenticated, integrity checked, plus port forwarding and SFTP/SCP.

WWW and HTTP two questions

URL: protocol :// host : port / path. Documents: static (stored) · dynamic (runs on the SERVER — PHP, CGI) · active (runs on the CLIENT — JavaScript).

HTTP messages Request: request line (method, URL, version) | headers | blank line | optional body
Response: status line (version, code, phrase) | headers | blank line | body
The only structural difference is the first line.

Methods: GET, POST, HEAD (headers only), PUT, DELETE, TRACE, OPTIONS, CONNECT.

Status classes: 1xx informational · 2xx success (200 OK) · 3xx redirection (301, 304 Not Modified) · 4xx client error (404) · 5xx server error (500).

Persistent vs non-persistent Non-persistent (1.0): one connection per object → 2 RTT per object
Persistent (1.1 default): one connection for many → 1 RTT setup + 1 RTT per object

Sample: base file + 10 images, RTT 100 ms. Non-persistent = 11×2×100 = 2200 ms. Persistent = 12×100 = 1200 ms.

HTTP is stateless — which is exactly why cookies exist: Set-Cookie in the response, Cookie in every later request.

Proxy caching checks freshness with a conditional GET (If-Modified-Since); an unchanged document returns 304 with no body.

Electronic mail

The path, and push vs pull UA —SMTP→ sender's server —SMTP→ receiver's server ←POP3/IMAP4— receiver's UA
SMTP pushes (twice). The last hop must PULL, because the recipient's machine may be off or firewalled.

Components: UA (user agent) · MTA (transfer, SMTP) · MAA (access, POP3/IMAP4).

SMTP phases: connection (220, HELO, 250) → transfer (MAIL FROM, one RCPT TO per recipient, DATA, message, a line with only a dot) → QUIT (221).

MIME is not a replacement for SMTP — it converts non-ASCII to ASCII and back, because SMTP carries 7-bit ASCII only. Headers: MIME-Version, Content-Type, Content-Transfer-Encoding (base64 for mostly-binary, quoted-printable for mostly-ASCII), Content-Id, Content-Description.

Webmail's last hop uses HTTP, not POP3 or IMAP4. SMTP still does the first two hops. Sending mail across domains needs the destination's MX record from DNS.

Security fundamentals

CIA and the attacks against each Confidentiality ← snooping, traffic analysis  (passive — hard to detect, so prevent)
Integrity ← modification, masquerading, replaying, repudiation  (active)
Availability ← denial of service

Passive = observe without altering, hard to detect, countered by encryption. Active = alter or disrupt, detectable but hard to prevent.

Replay works because the captured message is genuine — countered by timestamps or nonces, not by stronger encryption. Repudiation is unusual: the attacker is a legitimate party; countered by digital signatures.

Kerckhoffs's principle: security rests on the secrecy of the key, never of the algorithm.

The public-key rule, and the hybrid answer

Encrypt with the key of the person who should be the ONLY one able to read it. Secret for Bob → Bob's public key. Proving you wrote it → your private key.
Real systems use both: asymmetric once to exchange a symmetric session key, then symmetric for the bulk data. That is exactly what SSL does.

RSA the one numerical

The procedure n = p×q  ·  φ(n) = (p−1)(q−1)  ·  choose e with gcd(e, φ) = 1  ·  find d with e·d ≡ 1 (mod φ)
Public (e, n)  ·  Private (d, n)
C = Pe mod n  ·  P = Cd mod n

Worked reference: p = 7, q = 11 → n = 77, φ = 60. e = 13 → d = 37 (13×37 = 481 = 8×60 + 1).
Encrypt P = 5: 5²=25, 5⁴=9, 5⁸=4; 13 = 8+4+1 → 4×9×5 = 180 mod 77 = C = 26.
Decrypt: 26²=60, 26⁴=58, 26⁸=53, 26¹⁶=37, 26³²=60; 37 = 32+4+1 → 60×58×26 mod 77 = 5 ✓

Method: square-and-multiply, reducing mod n at every step. Write the exponent as a sum of powers of two. Always decrypt to verify.

Security: finding d needs φ(n), which needs p and q — i.e. factoring n.

Digital signature: hash the message → encrypt the digest with the sender's private key. Verify by hashing and decrypting with the public key, then comparing. Gives authentication, integrity, non-repudiation — but NOT confidentiality. Sign the digest because asymmetric encryption is slow and the digest is small.

Hash properties: fixed-length output, one-way, collision resistant, avalanche effect.

SSL, IPsec, firewalls, IDS

Security by layer — the organising idea Application → PGP  |  Transport → SSL/TLS  |  Network → IPsec

SSL protocols: Handshake (negotiate, authenticate, establish keys) · Record (fragment, compress, MAC, encrypt) · Change Cipher Spec · Alert.
Handshake phases: 1 capabilities (ClientHello/ServerHello) → 2 server certificate → 3 client sends the pre-master secret encrypted with the server's public key → 4 both derive the master secret, ChangeCipherSpec, Finished.
HTTPS = HTTP over SSL/TLS, port 443.

AHESP

IPsec modes: transport = payload only, no new header, host to host. Tunnel = whole datagram, new outer header, router to router, hides the original addresses — this is what VPNs use.
Security Association = a one-way logical connection (so two are needed), identified by SPI + destination IP + protocol.

SSL vs IPsec: transport vs network layer; only applications that call it vs all traffic transparently; application changes needed vs none; HTTPS vs VPNs.

A packet filter reads the envelope; a proxy reads the letter. A stateful firewall tracks connection state, so it can tell a reply from an unsolicited approach.

Firewall = locked door. IDS = burglar alarm (detects and alerts only). IPS = alarm that also bolts the door.

IDS by placement: NIDS (network point, many hosts, blind to encrypted traffic) vs HIDS (one host, far more detail).
IDS by method: signature-based (known patterns; few false positives, misses new attacks) vs anomaly-based (baseline deviation; catches new attacks, many false positives).
Intruders: masquerader (outsider using an account) · misfeasor (legitimate user exceeding privileges) · clandestine user (has supervisory control, suppressing the audit trail).

Final scan — ten minutes before you go in

  1. Ports: FTP 20/21, SSH 22, TELNET 23, SMTP 25, DNS 53, DHCP 67/68, HTTP 80, POP3 110, IMAP 143, HTTPS 443.
  2. DNS: host→local is recursive, local→hierarchy is iterative. Zone = domain minus delegations.
  3. DORA, all broadcast. REQUEST is broadcast so unchosen servers release their offers. Relay agent crosses routers.
  4. FTP has two connections: control 21 (whole session), data 20 (per file). Passive mode is the modern default.
  5. HTTP is stateless → cookies. Persistent = 1 RTT setup + 1 per object; non-persistent = 2 per object.
  6. Mail: SMTP pushes twice, POP3/IMAP pulls once. MIME converts non-ASCII to ASCII; it does not replace SMTP.
  7. POP3 downloads and deletes; IMAP keeps mail on the server and syncs.
  8. Encrypt with the key of whoever should be the only reader. Sign with your own private key, on the digest.
  9. RSA: n = pq, φ = (p−1)(q−1), e·d ≡ 1 mod φ. C = Pᵉ mod n. Square-and-multiply, reduce every step, verify.
  10. AH has no confidentiality; ESP does. Tunnel mode = VPN. SSL is transport layer, IPsec is network layer.
