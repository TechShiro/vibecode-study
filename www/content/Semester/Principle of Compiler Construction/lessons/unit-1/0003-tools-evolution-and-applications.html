1. Compiler Construction Tools

Writing an entire compiler from scratch in assembly or raw C is an enormous undertaking. Modern compilers are constructed using software packages called compiler-compilers, compiler generators, or translator-writing systems. These tools take a declarative mathematical specification of a language phase and automatically synthesize the executable code for that phase.

The Golden Principle Behind Compiler Tools

Notice the universal pattern across the table: Each tool's input is the exact formal mathematical notation that defines that phase.

  • Regular expressions specify tokens → generates Scanners.
  • Context-free grammars specify language syntax → generates Parsers.
  • Attribute grammars specify semantics → generates Translation Engines.
  • Instruction templates specify machine code → generates Code Generators.
  • Data-flow equations specify variable usage → generates Optimisers.

Writing this sentence directly links theory to tooling and guarantees full credit in university marking.

2. Evolution of Programming Languages

The progression of computer programming languages spans five distinct generations, shifting abstraction away from the underlying electronic hardware toward human problem-solving notation.

Chronological Roadmap: The Five Generations of Programming Languages
1GL
Machine Language (1940s) — Raw binary bit streams (01001100). Executed directly by CPU hardware; completely machine-dependent and severely error-prone.
2GL
Assembly Language (Early 1950s) — Symbolic mnemonics (MOV, ADD, JMP). Introduced symbolic addresses and macro facilities. Still hardware-specific; requires an Assembler.
3GL
High-Level Procedural Languages (Late 1950s – Present) — Human-readable notation. Machine-independent mathematical and English constructs. Requires a Compiler or Interpreter. Examples: Fortran (scientific), COBOL (business), C, C++, Java, Python.
4GL
Application-Specific / Domain-Specific Languages (1970s – Present) Designed for specialised domains; typically declarative and concise. Examples: SQL (relational databases), PostScript (typesetting), MATLAB, R.
5GL
Constraint & Logic-Based Languages (1980s – Present) Programmer states what problem to solve through facts and rules; the execution inference engine deduces how. Examples: Prolog, Mercury, OPS5.

The Two Foundational Classifications

Classification BasisCategoryCore CharacteristicProminent Examples
1. By What the Program Specifies Imperative Specifies HOW the computation is executed via ordered sequences of mutable state-changing statements. C, C++, Java, Go, Rust, Python
Declarative Specifies WHAT result is required; the system determines execution strategy without explicit control flow. SQL, Prolog, Haskell, HTML/CSS
2. By Ancestry & Computation Model von Neumann Languages Computation is modeled directly on the von Neumann hardware model: program counter, sequential memory, and destructive assignment. Fortran, C, Pascal
Object-Oriented Languages Encapsulates state and operations into discrete objects that communicate via message passing and inheritance. Simula 67 (first OO language), Smalltalk, C++, Java

Static versus Dynamic Concepts — Core Terminology

Critical Exam Concept · Static Scoping vs Dynamic Scoping

Static Scoping (Lexical Scoping): The declaration associated with an identifier is determined purely at compile time by reading the physical program text layout. (Standard in C, C++, Java).

Dynamic Scoping: The declaration associated with an identifier is determined at run time based on the active dynamic function call stack. (Common in early Lisp, Perl, Bash).

Consider this classic university exam puzzle:

int x = 10;
void f() { printf("%d", x); }
void g() { int x = 20; f(); }
int main() { g(); return 0; }
  • Under Static Scoping: Output is 10. Looking at the code text, the global declaration int x = 10 encloses function f(). The local declaration in g() is invisible.
  • Under Dynamic Scoping: Output is 20. At run time, f() is invoked by g(), so the runtime engine looks up the call stack and resolves x to g's local variable.
Term PairFirst TermSecond TermPractical Distinction
Static vs Dynamic Static (Compile-Time) Dynamic (Run-Time) A decision the compiler resolves by examining source code is static (e.g. type checking in C). A decision that can only be made while the program executes is dynamic (e.g. dynamic memory allocation with malloc, polymorphism in Java).
Environment vs State Environment
(Name → Location)		 State
(Location → Value)		 The environment maps variable names to memory storage addresses (l-values). The state maps memory storage addresses to values stored there (r-values). Variable declarations alter the environment; assignment operations alter the state.

3. Applications of Compiler Technology

Compiler technology is not limited to producing machine code for computer programs. The deep analysis techniques developed for compilers are deployed across computing systems wherever structured languages and complex architectures interact. Five major applications must be named:

System Architecture: Five Core Applications of Compiler Technology
1. Implementation of High-Level Languages

High-level abstractions (classes, inheritance, lambdas, garbage collection) are computationally expensive unless optimised. A programming language can only afford the abstractions its compiler can efficiently compile away. C's register keyword was rendered obsolete once compilers solved graph-coloring register allocation.

2. Optimisation for Computer Architectures

Modern CPUs depend on compilers to exploit hidden micro-architectural hardware:
• Instruction Pipelining: Reordering instructions to eliminate data hazards and branch stalls.
• Memory Hierarchy: Loop interchange and blocking to maximise CPU L1/L2 cache locality.

3. Co-Design of New Computer Architectures

Modern microprocessors are designed alongside their compilers. RISC succeeded because compilers could schedule simple instructions faster than humans could program complex CISC instructions. Architectures like VLIW, SIMD vector units, and GPUs are entirely unusable without specialized optimizing compiler back ends.

4. Program Translations

Applying parsing and synthesis techniques across diverse domains:
• Hardware Synthesis: Compiling Verilog/VHDL into silicon gate netlists.
• Binary Translation: Translating x86 binaries to run on ARM (e.g. Apple Rosetta 2).
• Database Query Optimisation: Compiling declarative SQL queries into native relational algebra execution plans.

5. Software Productivity & Security Tools

Using compiler analysis to find software vulnerabilities rather than emitting code:
• Static Analysis & Linters: Detecting null pointer dereferences, memory leaks, and buffer overflows (e.g. Coverity, SonarQube).
• Memory Sanitizers: AddressSanitizer and Valgrind injecting memory boundary checks.

The Mandatory Exam Opening Sentence

“Compiler technology is not merely about producing machine code — the analysis techniques a compiler uses to understand and transform a program are applied wherever one formal language must be understood, verified, or translated into another.” Open your answer with this thesis, followed by the five headings above.

Check Yourself

1. Lex takes as input:

Lex compiles regular expressions into a deterministic finite automaton (DFA) scanner. Yacc is the tool that consumes context-free grammars.

2. A Data-Flow Analysis Engine is used to generate which phase?

Data-flow engines calculate how values propagate through variables across program paths, which forms the mathematical foundation for dead code elimination and constant propagation.

3. Under Static Scoping (Lexical Scoping), an identifier reference is resolved by:

Static scoping relies strictly on textual nesting; dynamic scoping relies on runtime call history.

4. Compiling a Verilog or VHDL specification into a hardware gate circuit is an example of which compiler application?

Hardware synthesis uses compiler parsing, intermediate code representation, and optimization passes to generate physical electronic netlists from hardware description languages.

Recall Without Looking

List the six compiler construction tools and the phase each generates.

1. Scanner generators (Lex/Flex) → Lexical Analyser from regular expressions. 2. Parser generators (Yacc/Bison) → Syntax Analyser from Context-Free Grammars. 3. Syntax-directed translation engines → Intermediate Code Generator from attributed parse trees. 4. Code generator generators (burg) → Code Generator from instruction rewriting rules. 5. Data-flow analysis engines → Code Optimiser from data-flow equations. 6. Compiler toolkits (LLVM) → Integrated framework for all phases.

Give the five generations of programming language with examples.

1GL: Machine code (raw binary). 2GL: Assembly language (mnemonics, NASM). 3GL: High-level procedural (Fortran, C, Java, Python). 4GL: Application-specific / declarative (SQL, MATLAB, PostScript). 5GL: Logic and constraint-based (Prolog, Mercury).

Distinguish static scoping from dynamic scoping with an example.

Static scoping resolves identifiers based on textual source structure at compile time; dynamic scoping resolves identifiers based on the active runtime call stack. In a program where global x=10, f() prints x, and g() declares local x=20 and calls f(), static scoping prints 10 while dynamic scoping prints 20.

Contrast Environment and State in programming languages.

Environment is a mapping from variable names to memory storage locations (l-values); altered by declarations. State is a mapping from memory storage locations to their stored values (r-values); altered by assignment statements.

Name all five major applications of compiler technology outside of compilers.

1. Implementation of high-level programming languages (abstract features like OOP and GC). 2. Optimisation for computer architectures (instruction pipelining, cache locality). 3. Co-design of new CPU architectures (RISC, VLIW, GPUs). 4. Program translations (binary translation, hardware synthesis from Verilog, SQL query compilation). 5. Software productivity and security tools (static analysis, memory leak detection, Valgrind).
