1. Translators

Definitions to write verbatim A translator is a system software program that takes a program written in one language — the source language — and converts it into an equivalent program in another language — the target language.

A compiler is a translator that reads a program written in a high-level language and translates it, as a whole, into an equivalent program in a low-level (machine or assembly) language, reporting any errors detected during translation.

An interpreter is a translator that directly executes the operations specified in the source program on inputs supplied by the user, statement by statement, without producing a permanent target program.

The one-line summary, and the trade-off

“A compiler trades slower translation for faster execution; an interpreter trades slower execution for better diagnostics and faster start-up.”

And the sentence examiners look for: the machine-language target program produced by a compiler is usually much faster at mapping inputs to outputs, but an interpreter can give better error diagnostics, because it executes the source program statement by statement.

2. The Language Processing System

A compiler is not an isolated utility; it operates as the centerpiece of a complete five-stage language processing pipeline. Draw this vertical flowchart with every intermediate representation labelled.

Flowchart: The Complete Language Processing Pipeline
Source Program with Preprocessor Directives Human-written C/C++ source code · prog.c
↓ Raw text with #include, #define
1. PREPROCESSOR Macro expansion, file inclusion, conditional compilation · cpp
↓ Modified Source Program (Pure HLL · prog.i)
2. COMPILER Phases 1–6: Lexical, Syntax, Semantic, IR, Optimiser, Code Gen
↓ Target Assembly Program (Mnemonics · prog.s)
3. ASSEMBLER Translates assembly mnemonics to relocatable binary · as
↓ Relocatable Object Code (Addresses from 0 · prog.o)
4. LINKER / LOADER Resolves external symbols with libraries (libc.a, libm.so) · ld
↓ Absolute Machine Code in Memory · a.out / prog.exe
Target Machine Code (Executable Process) Loaded into RAM, Program Counter points to entry point
StageInput → OutputKey Functionality
1. Preprocessor Source with directives (prog.c) → Modified Source (prog.i)
  • Macro expansion: replaces #define PI 3.14 occurrences with literal tokens.
  • File inclusion: inlines header files referenced by #include <stdio.h>.
  • Conditional compilation: evaluates #ifdef, #ifndef, #endif blocks.
  • Comment stripping: removes line and block comments. The output is still in the high-level language.
2. Compiler Modified Source (prog.i) → Target Assembly (prog.s) Translates high-level statements into symbolic assembly instructions (e.g. MOV, ADD, LDF). Performs type validation and code optimisation while reporting structural errors.
3. Assembler Assembly Code (prog.s) → Relocatable Machine Code (prog.o) Translates symbolic opcodes and register names into binary machine words. Relocatable means addresses are relative to a base offset (typically offset 0) because final memory placement is unknown.
4. Linker Relocatable Object Files + Library Files → Single Executable
  • Symbol resolution: matches undefined external references (e.g. printf) with their definitions in library files (libc.a, libm.so).
  • Section merging: merges all .text (code) and .data segments into unified executable sections.
5. Loader Executable file on disk → Active Process in RAM
  • Allocates address space in physical RAM (code, data, stack, heap).
  • Relocation / Address fixing: adjusts relocatable relative offsets to absolute physical memory addresses.
  • Initialises registers, sets the stack pointer (SP), and jumps the Program Counter (PC) to main().
Why compilers produce assembly code instead of direct binary

Assembly language is easier to produce, isolate, and debug. Emitting symbolic assembly allows compiler developers to inspect intermediate compiler outputs easily. It also decouples the compiler from the hardware-specific binary encoding, leaving the straightforward conversion of mnemonics to machine bits to the assembler. Some specialized compilers do generate machine code directly to improve build speed; noting this nuance shows mastery.

3. The Hybrid Model — Java and the JVM

Pure compilation achieves maximum execution speed but binds the binary to a specific CPU architecture. Pure interpretation is completely portable but incurs a heavy runtime penalty. Java merges both into a hybrid architecture.

↓ Portable Bytecode (Prog.class)

Interpreter

JIT Compiler (HotSpot)

↓ Direct CPU Execution
Target Native Machine Instructions & Output Executes at near C/C++ native speed

The mechanism: The Java compiler (javac) does not emit x86 or ARM machine code. Instead, it translates the source into bytecode — a compact, instruction-set architecture designed for a virtual processor. Any device equipped with a Java Virtual Machine (JVM) can execute this bytecode, realising the promise of “Write Once, Run Anywhere” (WORA).

To eliminate the execution slowdown of basic interpretation, modern JVMs incorporate a Just-In-Time (JIT) compiler (HotSpot). The JVM profiles execution in real-time; when a method or loop executes repeatedly (“hot spot”), the JIT compiles that bytecode into native machine instructions and caches it in RAM.

Related terminology: A source-to-source compiler (or transpiler) translates between two high-level languages of similar abstraction (e.g., Babel translating ES6 JavaScript to ES5, or TypeScript compiling to JavaScript).

5. The Analysis–Synthesis Model

Any compiler can be partitioned into two distinct conceptual phases: Analysis (Front End) and Synthesis (Back End).

The Two Halves Defined ANALYSIS (Front End): Breaks down the source program into grammatical constituents, imposes syntax structure, creates a symbol table, reports structural/type errors, and produces an intermediate representation (IR). Source-language dependent, machine independent.

SYNTHESIS (Back End): Takes the intermediate representation and symbol table to construct the target machine code, performing register allocation and instruction scheduling. Machine dependent, source-language independent.
The Engineering Payoff — m + n vs m × n

If you need to support m source languages on n target processor architectures:

  • Without Front/Back separation: You must construct m × n distinct monolithic compilers.
  • With Analysis-Synthesis separation: You build m front ends and n back ends connected via one shared Intermediate Representation — requiring only m + n components!

This modular architecture is the architectural foundation of modern production compiler frameworks such as GCC and LLVM.

Check Yourself

1. The essential difference in error reporting between a compiler and an interpreter is that a compiler:

A compiler scans the complete code and aggregates all compile-time errors in one pass. An interpreter evaluates sequentially and halts upon encountering the very first error.

2. The output produced by the Preprocessor stage is:

The preprocessor expands macros (#define), includes headers (#include), and removes comments. Its output remains valid high-level source code.

3. “Relocatable machine code” means that:

The assembler emits object code assuming a starting offset of 0. The loader subsequently binds these relative offsets to real physical addresses when loading into RAM.

4. Separating a compiler into front-end analysis and back-end synthesis allows m languages and n target architectures to be supported using:

By interfacing through a unified Intermediate Representation (IR), each language requires one front end and each target architecture requires one back end, avoiding the combinatorial explosion.

5. A cross-compiler is defined as a compiler that:

A cross-compiler runs on Machine A and generates executable binary designed to run on Machine B (common in embedded systems and microcontrollers).

Recall Without Looking

Define translator, compiler, and interpreter verbatim.

A translator converts a program written in a source language into an equivalent program in a target language. A compiler translates a high-level program as a whole into low-level machine or assembly language, reporting errors in a batch. An interpreter executes the operations of a high-level program directly, statement by statement on user inputs, without generating an intermediate target file.

Compare compiler and interpreter on the 8 key exam points.

1. Unit: Whole program vs statement by statement. 2. Output: Target object file vs no target file. 3. Speed: Much faster execution vs slower execution. 4. Start time: Slower build vs immediate execution. 5. Error reporting: Batch error report after full scan vs stops at first error. 6. Debugging: Harder to trace runtime state vs superior line-by-line diagnosis. 7. Memory: Requires extra storage for binary vs minimal storage. 8. Lifecycle: Compile once run many times vs source must be re-translated on every run.

Draw the Language Processing System pipeline and label what flows between stages.

Source Program with directives → [Preprocessor] → Modified Source → [Compiler] → Target Assembly → [Assembler] → Relocatable Object Code → [Linker / Loader] (takes libraries) → Target Machine Code in RAM.

Explain what the preprocessor, assembler, linker, and loader do.

Preprocessor expands macros, resolves #include headers, strips comments, and evaluates conditionals. Assembler converts assembly mnemonics into relocatable machine binary. Linker resolves external library symbols and merges sections. Loader places the binary into RAM, binds relocatable offsets to physical memory, initialises CPU registers, and triggers execution.

Explain the Java hybrid model and the role of bytecode and JVM.

Java compiles source code into machine-independent bytecode using javac. The bytecode is interpreted by the JVM on any platform (Write Once Run Anywhere). Hot methods and loops are dynamically compiled into native machine code at runtime by the JIT compiler to achieve native execution speeds.

Explain the Analysis-Synthesis model and the m + n advantage.

Analysis (front end) is source-dependent and machine-independent; it validates syntax/semantics and generates intermediate code. Synthesis (back end) is machine-dependent and source-independent; it generates and optimises target code. Using an intermediate representation allows m languages on n platforms with m + n modules instead of m × n monolithic compilers.
