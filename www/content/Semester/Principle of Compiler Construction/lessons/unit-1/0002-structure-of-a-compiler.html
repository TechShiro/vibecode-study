2. The Six Phases in Detail

#Phase NameInput → OutputCore ResponsibilityErrors Caught
1 Lexical Analysis
(Scanning)		 Source characters → Token stream Scans source text from left to right, groups characters into meaningful character sequences called lexemes, produces a token for each, strips spaces/comments, and inserts identifier names into the Symbol Table. Lexical errors: Illegal characters (e.g. @, $ in C), unterminated string literals or block comments, ill-formed numeric constants (e.g. 123a4).
2 Syntax Analysis
(Parsing)		 Token stream → Syntax tree Imposes a hierarchical grammatical structure on the token stream according to the Context-Free Grammar (CFG) of the language. Constructs an abstract syntax tree where interior nodes represent operators and leaves represent operands. Syntax errors: Missing semicolons, unmatched parentheses or brackets, misplaced keywords (e.g. int x written as x int), syntax rule violations.
3 Semantic Analysis Syntax tree → Annotated syntax tree Checks semantic consistency with language rules. Verifies that variable types match their operations (type checking), ensures variables are declared before use, checks function call arity, and inserts type conversions (coercions) when allowable. Semantic errors: Type mismatch (e.g. assigning string to integer), undeclared variable access, multiple declarations of the same identifier in the same scope, passing wrong number/type of arguments.
4 Intermediate Code Generation (ICG) Annotated tree → Three-Address Code (TAC) Translates the parse tree into an explicit, low-level, machine-independent intermediate representation — typically Three-Address Code. Each instruction contains at most one operator on the right-hand side. None — program is structurally and semantically valid; transformations are purely mechanical.
5 Code Optimisation
(Optional Phase)		 Intermediate code → Optimised Intermediate code Transforms intermediate code to make the target program execute faster, occupy less memory, or consume less power. Involves constant folding, dead code elimination, loop unrolling, and common subexpression elimination. None
6 Code Generation Optimised IR → Target Machine Code Maps intermediate instructions into target assembly/machine code. Resolves memory layout, performs instruction selection, and executes register allocation and assignment (mapping variables to high-speed CPU registers). None
The Two Fundamental Insights Every Examiner Looks For

1. Error Detection Stops After Phase 3: Compile-time errors are detected exclusively in phases 1, 2, and 3. By the time intermediate code generation begins, the source program is verified to be grammatically and semantically sound. Phases 4, 5, and 6 only translate and optimise.

2. The Code Optimiser is the Only Optional Phase: If the optimiser is removed entirely, the compiler still produces a completely correct and functional executable — it simply runs slightly slower. This is why compiler flags like gcc -O0 exist (disabling optimisation to maximize compilation speed during debugging).

3. The Guaranteed 10-Mark Trace: position = initial + rate * 60

University Problem · Trace the statement through all six phases of the compiler

Phase 1 — Lexical Analysis

The scanner isolates lexemes, discards blanks, and emits a stream of tokens. Identifiers are assigned indices pointing to their Symbol Table records:

Lexemeposition=initial+rate*60
Token Emitted⟨id, 1⟩⟨=⟩⟨id, 2⟩⟨+⟩⟨id, 3⟩⟨*⟩⟨number, 60⟩

Output: ⟨id, 1⟩ ⟨=⟩ ⟨id, 2⟩ ⟨+⟩ ⟨id, 3⟩ ⟨*⟩ ⟨60⟩

Symbol Table Entries Created:

IndexVariable NameData TypeMemory Offset / Attributes
1positionfloatoffset 0
2initialfloatoffset 4
3ratefloatoffset 8

Phase 2 — Syntax Analysis

The parser builds a syntax tree respecting operator precedence: multiplication (*) has higher precedence than addition (+), so the multiplication sub-tree is located deeper in the hierarchy.

Syntax Tree (Operator Precedence Tree)
            =
          /    \
    ⟨id, 1⟩    +
              /   \
        ⟨id, 2⟩   *
                 /   \
           ⟨id, 3⟩  ⟨60⟩

Phase 3 — Semantic Analysis

The semantic analyser consults the symbol table and notes that position, initial, and rate are of type float, but 60 is an integer constant. A floating-point multiplication operator requires both operands to be float. The compiler inserts an implicit type coercion node: inttofloat.

Annotated Syntax Tree with Type Coercion
            =
          /    \
    ⟨id, 1⟩    +
              /   \
        ⟨id, 2⟩   *
                 /        \
           ⟨id, 3⟩   inttofloat
                             |
                          ⟨60⟩

Exam Note: The inttofloat node is mandatory on your exam sheet. It proves that the semantic analysis phase verified types and modified the tree.

Phase 4 — Intermediate Code Generation

The compiler evaluates the annotated tree from the bottom up, emitting linear Three-Address Code (TAC) with compiler-generated temporaries (t1, t2, t3):

Three-Address Code (4 instructions) t1 = inttofloat(60)
t2 = id3 * t1
t3 = id2 + t2
id1 = t3

Phase 5 — Code Optimisation

The code optimiser performs two standard optimisations:

  • Constant Folding: The compiler evaluates inttofloat(60) at compile time, replacing the operation with the immediate constant 60.0.
  • Dead Code & Copy Propagation: Eliminates temporary t3, storing the result of addition directly into id1.
Optimised Three-Address Code (Reduced to 2 instructions) t1 = id3 * 60.0
id1 = id2 + t1

Result: 4 intermediate instructions are reduced to 2, eliminating CPU execution overhead.

Phase 6 — Code Generation

The code generator assigns CPU registers (R1, R2) and selects assembly instructions. Floating-point operations are designated by an F suffix (LDF, MULF, ADDF, STF); literal constants are preceded by #:

Target Machine Code (Assembly for a Register Architecture) LDF   R2, id3         ; Load rate into float register R2
MULF  R2, R2, #60.0   ; Multiply R2 by constant 60.0
LDF   R1, id2         ; Load initial into register R1
ADDF  R1, R1, R2      ; Add R2 to R1
STF   id1, R1         ; Store R1 into position

Notice that two CPU registers suffice for the entire expression. Resolving register allocation without spilling variables into memory is the central challenge of code generation.

4. The Two Cross-Cutting Components

The Symbol Table Manager

Formal Definition The Symbol Table is a high-speed data structure maintained by the compiler containing a record for each identifier encountered in the source code, storing attributes such as data type, storage size, scope level, line number of declaration, and memory location.
Attribute TrackedPrimary Consuming PhasePractical Use
Lexeme nameLexical & Syntax AnalysisIdentifier identification and uniqueness validation
Data Type (int, float, struct)Semantic AnalysisType checking, determining operand coercion, struct member access
Scope level & Nesting depthSemantic AnalysisDistinguishing local variables from global variables
Memory offset / Base addressCode GenerationAllocating relative displacement in activation records (stack frames)
Function SignatureSemantic AnalysisChecking argument count, parameter types, and return values

Implementation: Typically implemented using a Hash Table with chaining or bucket trees to guarantee average $O(1)$ search and insertion time.

The Error Handler

Error CategoryDetection PhaseClassic Examples
1. Lexical ErrorPhase 1 (Scanner)Invalid character (@, `), ill-formed numbers (3.14.15), unterminated quotes. Note: Misspelling whille is not a lexical error — the scanner treats it as a valid identifier!
2. Syntactic ErrorPhase 2 (Parser)Missing semicolon, unbalanced parentheses (a + b, unexpected tokens, misplaced control keywords.
3. Semantic ErrorPhase 3 (Semantic)Type mismatch (e.g. float * ptr = "string";), undeclared variable access, multiple conflicting declarations.
4. Logical ErrorNone (Undetectable by compiler)Infinite loop while(1), writing if (x = 5) instead of ==, incorrect algorithmic logic. The compiler cannot deduce program intent!
Error Recovery Goals

A production compiler error handler must fulfill three primary goals:

  1. Clear & accurate reporting: Specify exact file, line number, column, and diagnostic reason.
  2. Rapid recovery: Recover from the current error state quickly to detect remaining errors in the same compilation run without cascading false errors.
  3. Zero overhead: Incur negligible performance cost on syntactically and semantically correct programs.

5. Phase versus Pass

CriterionPhasePass
DefinitionA logically cohesive operation that transforms one representation of the source code into another.A physical traversal over the entire source text or intermediate file on disk/RAM.
Total CountClassical count is strictly six.Depends on compiler architecture (can be 1-pass, 2-pass, 3-pass, or multi-pass).
GroupingPhases are logical abstractions.Multiple phases are routinely grouped into a single physical pass.
Memory RequirementIndependent of hardware constraints.Fewer passes require keeping entire abstract trees in RAM; multi-pass uses disk streams.
Architecture Comparison: Single-Pass vs Multi-Pass Compilers
Single-Pass Compiler

Reads source code once from beginning to end and generates machine code on the fly without intermediate files.

  • Advantage: Very fast compilation, minimal memory footprint.
  • Limitation: Cannot perform global optimisations; cannot handle forward references without backpatching.
  • Example: Original Pascal compilers, Turbo Pascal.
Modern 3-Pass Compiler

Groups the six logical phases into three dedicated physical passes:

Pass 1: Lexical + Syntax + Semantic + ICG (Front End → IR)
Pass 2: Data-flow analysis & Code Optimiser (IR → Optimised IR)
Pass 3: Code Generator & Register Allocator (Target Code)

Example: GCC, LLVM, Clang.

1. In the statement position = initial + rate * 60, the output of the lexical analyser is:

The scanner produces a linear stream of tokens where numbers 1, 2, and 3 are Symbol Table indices, not numerical literals.

2. Which phase of the compiler is responsible for inserting the inttofloat conversion node?

Semantic analysis performs type checking and inserts coercion nodes when mixed-type expressions occur.

3. A missing semicolon in a C program is detected by:

The token stream itself contains valid tokens; it is the structural grammar rule of the language that is violated.

4. Which of the following compiler phases is strictly optional?

Omitting the optimiser yields a completely correct executable that simply runs less efficiently (as seen in debug builds like gcc -O0).

5. An infinite loop caused by writing while (1) or if (x = 5) instead of == is:

The program is lexically, syntactically, and semantically valid C code. Compilers cannot deduce the intended algorithmic objective of the programmer.

Recall Without Looking

Name all six phases with their exact input and output representations.

1. Lexical Analysis: Characters → Token stream. 2. Syntax Analysis: Token stream → Syntax tree. 3. Semantic Analysis: Syntax tree → Annotated syntax tree. 4. Intermediate Code Generation: Annotated tree → Three-Address Code. 5. Code Optimisation (Optional): IR → Optimised IR. 6. Code Generation: Optimised IR → Target Machine Code.

Trace position = initial + rate * 60 through all six phases from memory.

Phase 1: ⟨id,1⟩ ⟨=⟩ ⟨id,2⟩ ⟨+⟩ ⟨id,3⟩ ⟨*⟩ ⟨60⟩. Phase 2: Syntax tree with = at root, id1 left, + right over id2 and (* over id3 and 60). Phase 3: Annotated tree with inttofloat inserted above 60. Phase 4: TAC (t1 = inttofloat(60); t2 = id3 * t1; t3 = id2 + t2; id1 = t3). Phase 5: Optimised TAC (t1 = id3 * 60.0; id1 = id2 + t1). Phase 6: Assembly (LDF R2, id3; MULF R2, R2, #60.0; LDF R1, id2; ADDF R1, R1, R2; STF id1, R1).

What is the Symbol Table, what fields does it store, and who interacts with it?

A hash table data structure storing variable names, data types, scope depth, memory offsets, and procedure signatures. It is populated by the lexical analyser, populated and read heavily by the semantic analyser, and read by the code generator for register and memory allocation.

Contrast a compiler Phase with a compiler Pass.

A phase is a logical operation transforming one intermediate representation into another (always 6 phases). A pass is one physical traversal over the source code or intermediate representation file. Real compilers commonly group 6 phases into 3 passes (Pass 1: Front End, Pass 2: Optimiser, Pass 3: Back End).
