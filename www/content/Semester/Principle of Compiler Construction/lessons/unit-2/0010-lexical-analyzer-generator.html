What Lex is

Definition and Primary Role Lex (or GNU Flex) is a lexical analyser generator: it accepts a user-written specification consisting of regular expressions paired with action fragments in C, and automatically produces the complete C source code (lex.yy.c) for a deterministic finite automaton scanner.

↓ Generates C source code

2. Translation rulesLines of the form   Pattern    { Action }The pattern is a regular expression; the action is C code executed when the pattern matches. This is the heart of the file

A complete worked specification

A Lex program recognising the tokens of a small language.
%{
  /* definitions of the manifest constants LT, LE, EQ, NE, GT, GE,
     IF, THEN, ELSE, ID, NUMBER, RELOP */
  #include "tokens.h"
%}

/* ---------- regular definitions ---------- */
delim    [ \t\n]
ws       {delim}+
letter   [A-Za-z]
digit    [0-9]
id       {letter}({letter}|{digit})*
number   {digit}+(\.{digit}+)?(E[+-]?{digit}+)?

%%

{ws}            { /* no action, no token — just skip it */ }
if              { return(IF); }
then           { return(THEN); }
else           { return(ELSE); }
{id}           { yylval = (int) installID(); return(ID); }
{number}      { yylval = (int) installNum(); return(NUMBER); }
"<"            { yylval = LT; return(RELOP); }
"<="          { yylval = LE; return(RELOP); }
"="            { yylval = EQ; return(RELOP); }
"<>"          { yylval = NE; return(RELOP); }
">"            { yylval = GT; return(RELOP); }
">="          { yylval = GE; return(RELOP); }

%%

int installID() {
  /* look yytext (length yyleng) up in the symbol table;
     insert it if absent; return a pointer to its entry */
}

int installNum() {
  /* similar, but for a table of numeric constants */
}

Four things to point out when you write this out:

  • The {ws} rule returns nothing. Its action is empty, so the scanner simply loops and looks for the next token — which is exactly how whitespace is stripped.
  • Keywords are listed BEFORE {id}. That ordering is what makes if a keyword rather than an identifier, by the second conflict rule below.
  • All six relational operators return the same token, RELOP, distinguished by the attribute placed in yylval — exactly the design from Lesson 5.
  • Curly braces around a name mean “the regular definition” — {id} refers to the definition above; braces around code mean “the action”. The same symbol, two meanings.

Conflict resolution — the two rules

The two rules, in this order

RULE 1 — LONGEST MATCH. Always prefer a longer prefix of the input to a shorter one.

RULE 2 — FIRST RULE LISTED. If the longest possible prefix matches two or more patterns equally, prefer the pattern listed FIRST in the Lex program.

Rule 1 is applied first. Rule 2 only breaks a tie that rule 1 could not. Getting that order right is the whole question.

The pair to quote in the exam is if versus ifx — the same two patterns, resolved by different rules, and it proves you know both.

The practical consequence: keyword rules must be listed before the identifier rule. Reverse them and every keyword would be scanned as an identifier, because {id} would win the tie.

How Lex works internally

The construction — this ties Lessons 8, 9 and 10 together 1. Lex builds an NFA for each pattern pi in the translation rules, by Thompson's construction.
2. It combines them into one NFA: a new start state s0 with an ε-transition to the start state of every individual NFA. Each accepting state is labelled with the pattern it belongs to.
3. It converts that combined NFA to a DFA by the subset construction, or equivalently builds the DFA directly by the followpos method — which is what real Lex implementations do.
4. A DFA state may contain several accepting NFA states. In that case the state is labelled with the pattern listed FIRST in the Lex program — this is exactly how Rule 2 is implemented.
5. To implement Rule 1, the simulator does not stop at the first accepting state. It keeps running, remembering the LAST accepting state it passed and the input position there. When no further transition is possible, it retracts the input pointer to that remembered position and executes that pattern's action.
The one-sentence version

“Lex merges the pattern automata into a single DFA; the longest-match rule is implemented by remembering the last accepting state passed and retracting to it, and the first-rule-listed rule by labelling each DFA state with the earliest pattern among the accepting NFA states it contains.”

Lookahead

Lex provides a lookahead operator /: the pattern r1 / r2 matches r1, but only when it is followed by r2 — and r2 is not part of the lexeme. The classic use is Fortran's DO statement, where DO 5 I = 1,25 is a loop but DO5I = 1.25 is an assignment; the two can be told apart only by looking ahead to the comma.

Recall without looking

What is Lex, and what is the pipeline from specification to running scanner?

A lexical analyser generator that takes regular expressions paired with actions and produces the C source of a scanner; its GNU version is Flex. The pipeline is lex.l → Lex compiler → lex.yy.c → C compiler → a.out, and then input stream → a.out → sequence of tokens.

Give the three sections of a Lex program and what each holds.

Declarations — regular definitions, manifest constants, and C code between %{ and %} copied verbatim. Translation rules — lines of Pattern { Action }, where the action is C code. Auxiliary functions — ordinary C functions used by the actions, often including main(). The sections are separated by %%, the first of which is compulsory.

Name the Lex variables and functions.

yytext is the lexeme just matched; yyleng its length; yylval the attribute passed to the parser; yylex() is the generated scanner, called repeatedly by the parser; yywrap() is called at end of input, returning 1 to stop and 0 to continue with another file; yyin and yyout are the streams; ECHO writes yytext to yyout and is the default action for unmatched input; yymore() and yyless(n) extend or push back a match.

Give the two conflict-resolution rules, in order, with the proving example.

First, longest match — always prefer a longer prefix of the input. Second, if two patterns match the same longest prefix, prefer the one listed first in the program. For input if both the keyword rule and {id} match two characters, so rule 2 gives IF; for ifx, {id} matches three characters against two, so rule 1 gives ID. Hence keyword rules must precede the identifier rule.

Explain how Lex works internally.

It builds an NFA per pattern by Thompson's construction, combines them under a new start state with ε-transitions to each, keeping every accepting state labelled with its pattern, and converts the result to a DFA by the subset construction — or builds the DFA directly by the followpos method. A DFA state containing several accepting NFA states is labelled with the earliest pattern, implementing rule 2. Rule 1 is implemented by continuing past accepting states, remembering the last one and the input position there, then retracting to it.

What does the lookahead operator do?

The pattern r1 / r2 matches r1 only when it is followed by r2, and r2 is not part of the lexeme. The classic use is Fortran's DO statement, where DO 5 I = 1,25 is a loop and DO5I = 1.25 an assignment, distinguishable only by looking ahead to the comma.

Compare a Lex-generated scanner with a hand-written one.

Lex wins on development time, correctness and maintainability, since the automaton is generated mechanically and a change means editing one regular expression. A hand-written scanner can be faster and smaller because it is tuned to one language — which is why GCC and Clang use hand-written scanners while most teaching and prototype compilers use Lex.
