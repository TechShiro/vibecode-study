Alphabets, strings and languages

The three definitions An ALPHABET, written Σ, is any finite set of symbols. Examples: {0, 1} the binary alphabet; the set of letters; ASCII; Unicode.

A STRING over an alphabet is a finite sequence of symbols drawn from that alphabet. Also called a sentence or word. Its length |s| is the number of occurrences of symbols in it. The empty string ε has length 0.

A LANGUAGE is any countable set of strings over some fixed alphabet. This is a very broad definition: ∅ (the empty set) and {ε} (the set containing only the empty string) are both languages — and they are different.
The distinction that appears in objective questions

∅ ≠ {ε}. The empty set contains no strings at all, so |∅| = 0. The set containing the empty string contains exactly one string, so |{ε}| = 1. Similarly ε is a string, not a symbol, and it is never a member of the alphabet.

Operations on languages

The four operations For languages L and M:

UNION         L ∪ M = { s | s is in L or s is in M }
CONCATENATION   LM = { st | s is in L and t is in M }
KLEENE CLOSURE    L* = ∪i=0∞ Li — zero or more concatenations of L. Always contains ε, since L0 = {ε}
POSITIVE CLOSURE   L+ = ∪i=1∞ Li — one or more. Excludes ε unless ε is already in L

Relationships:   L* = L+ ∪ {ε}    and    L+ = L L* = L* L

Regular expressions

The inductive definition — write both parts BASIS.
    ε is a regular expression, and L(ε) = {ε}.
    If a is a symbol in Σ, then a is a regular expression, and L(a) = {a}.

INDUCTION. If r and s are regular expressions denoting L(r) and L(s), then:
    (r) | (s) is a regular expression denoting L(r) ∪ L(s)
    (r)(s) is a regular expression denoting L(r) L(s)
    (r)* is a regular expression denoting (L(r))*
    (r) is a regular expression denoting L(r) — parentheses do not change the language

A language denoted by a regular expression is called a regular set or a regular language.
Precedence — highest first, all left-associative 1. *  (closure)  — highest
2.    (concatenation)
3. |  (union / alternation) — lowest

So (a)|((b)*(c)) may be written a | b*c, and it means “a, or else zero-or-more b's followed by c” — not (a|b)*c.

Regular definitions

Definition A regular definition is a sequence of definitions of the form

d1 → r1,   d2 → r2,   …   dn → rn

where each di is a NEW symbol, not in Σ and not previously defined, and each ri is a regular expression over Σ ∪ {d1, …, di−1}.

The restriction to earlier definitions is what matters: it makes the definitions non-recursive, so each di can be textually substituted away, and the result is still a plain regular expression. Recursion would take us beyond regular languages.
Identifiers in C — write it exactly like this
letter_ → A | B | … | Z | a | b | … | z | _
digit    → 0 | 1 | … | 9
id       → letter_ ( letter_ | digit )*
Unsigned numbers such as 5280, 0.01234, 6.336E4, 1.89E−4
digit       → 0 | 1 | … | 9
digits     → digit digit*      /* one or more */
optFraction → . digits | ε
optExponent → E ( + | − | ε ) digits | ε
number     → digits optFraction optExponent
The two ε alternatives are what make the fraction and the exponent optional — which is exactly what the names say, and exactly what students forget to include.

Ten worked regular expressions

The four templates that solve almost every one

“Contains at least one x” → Σ* x Σ*   — anything, the thing, anything.

“Starts with x” → x Σ*    “Ends with x” → Σ* x

“Exactly k occurrences of a” → put a b* in every gap: b* a b* a b* … with k a's and k+1 gaps.

“Length divisible by k” → (ΣΣ…Σ)* with k copies inside the brackets.

The two that need justifying:

#8, “no ab” → b*a*. If ab never occurs, then once an a appears, no b can ever follow it. So every string is a run of b's followed by a run of a's. Check: bbaa ✓, ε ✓, ba ✓, ab ✗ — correctly excluded.

#5, “exactly two a's” → b*ab*ab*. Two a's create three gaps — before, between and after — and each may hold any number of b's. Check: aa ✓ (all gaps empty), bbabab ✓, aaa ✗.

What regular expressions cannot do — worth one line

Regular expressions cannot count without bound. The language of balanced parentheses, or of strings anbn, is not regular — a finite automaton has no stack, so it cannot remember how many opening brackets it has seen. That is precisely why tokens are described by regular expressions but syntax needs a context-free grammar, and it is the theoretical justification for splitting Phase 1 from Phase 2.

Check yourself

1. Which statement is true?

The empty set contains no strings; the set containing the empty string contains exactly one. And ε is a string of length zero, never a member of Σ.

2. For a string of length n, the number of non-empty substrings counted by position is:

Choose a start and an end with start ≤ end. n + 1 counts prefixes or suffixes; 2ⁿ counts subsequences. Watch for the word “distinct” — banana has 21 substrings by position but only 15 distinct ones.

3. L* differs from L⁺ in that:

L* = ∪ Lⁱ from i = 0, and L⁰ = {ε}. L⁺ starts from i = 1. So L* = L⁺ ∪ {ε} and L⁺ = LL* = L*L.

4. In a | b*c, the precedence means it denotes:

Closure binds tightest, then concatenation, then alternation. Writing (a|b)*c would need the parentheses explicitly.

5. Which algebraic law does NOT hold for regular expressions?

ab ≠ ba. Alternation is commutative, associative and idempotent; concatenation is associative and distributes over alternation, but never commutes.

6. A regular definition requires each rᵢ to use only symbols of Σ and d₁ … dᵢ₋₁ because:

Recursion would take the notation beyond regular languages and into context-free ones — which is precisely what grammars, not regular expressions, are for.

7. A regular expression for strings over {a,b} containing exactly two a's is:

Two a's create three gaps — before, between and after — and each may hold any number of b's. Option two allows more than two a's and forces them adjacent.

8. The language of balanced parentheses is:

Neither is aⁿbⁿ. This is the theoretical reason tokens are described by regular expressions while syntax needs a context-free grammar — the split between phases 1 and 2.

Recall without looking

Define alphabet, string and language, and give the counting formulas.

An alphabet Σ is a finite set of symbols; a string is a finite sequence of symbols from it, with length |s| and empty string ε; a language is any countable set of strings over a fixed alphabet — so ∅ and {ε} are both languages, and they differ. For length n: n + 1 prefixes and n + 1 suffixes including ε and the whole string, n − 1 proper ones of each, n(n+1)/2 non-empty substrings by position, and 2ⁿ subsequences.

Distinguish substring from subsequence.

A substring is obtained by deleting a prefix and a suffix, so its symbols are contiguous. A subsequence is obtained by deleting any symbols, not necessarily consecutive, keeping order. For banana, nan is a substring and bnn is only a subsequence. Proper means neither ε nor the whole string.

Give the four operations on languages and the closure relationships.

Union L ∪ M; concatenation LM = {st}; Kleene closure L* = ∪Lⁱ from i = 0, always containing ε; positive closure L⁺ = ∪Lⁱ from i = 1. L* = L⁺ ∪ {ε} and L⁺ = LL* = L*L.

State the inductive definition of a regular expression and the precedence.

Basis: ε is a regular expression denoting {ε}, and each symbol a in Σ is one denoting {a}. Induction: (r)|(s) denotes L(r) ∪ L(s); (r)(s) denotes L(r)L(s); (r)* denotes (L(r))*; and (r) denotes L(r). Precedence, highest first: closure, then concatenation, then alternation, all left-associative.

Give the regular definitions for identifiers and unsigned numbers.

letter_ → A|…|Z|a|…|z|_ ; digit → 0|…|9 ; id → letter_ (letter_ | digit)*. And: digits → digit digit* ; optFraction → . digits | ε ; optExponent → E (+|−|ε) digits | ε ; number → digits optFraction optExponent. The ε alternatives are what make the fraction and exponent optional.

Give the three shorthands and note what they add.

r⁺ means one or more, equal to r r*; r? means zero or one, equal to r | ε; [abc] and [a–z] are character classes for a|b|c and a|…|z. They add no expressive power — every one is definable in the basic notation — they only shorten what you write.

Give the four templates for writing regular expressions.

Contains at least one x: Σ* x Σ*. Starts with x: x Σ*; ends with x: Σ* x. Exactly k occurrences of a over {a,b}: b* a b* a b* … with k a's and k+1 gaps. Length divisible by k: (Σ…Σ)* with k copies inside.

What can regular expressions not describe, and why does it matter?

They cannot count without bound, so balanced parentheses and aⁿbⁿ are not regular — a finite automaton has no stack. That is exactly why tokens are specified by regular expressions and recognised by finite automata, while syntax needs a context-free grammar and a pushdown automaton, and it is the theoretical justification for separating lexical analysis from parsing.
