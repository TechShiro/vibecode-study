Finite automata

Definition A finite automaton is a recogniser: it takes a string x and answers “yes” if x is in the language and “no” otherwise. Formally it is a five-tuple (Q, Σ, δ, q0, F):

Q — a finite set of states
Σ — the input alphabet; ε is never in Σ
δ — the transition function
q0 — the start state, exactly one
F — the set of accepting (final) states, F ⊆ Q
 NFA — non-deterministicDFA — deterministic
ε-transitionsAllowedNot allowed
Transitions per symbolZero, one or many — δ(q, a) is a set of statesExactly one — δ(q, a) is a single state
δ signatureQ × (Σ ∪ {ε}) → 2QQ × Σ → Q
Easier toBuild from a regular expressionSimulate — no backtracking, no guessing
Number of statesFew — at most 2·|r| for a regular expression of length |r|Can be up to 2n for an n-state NFA
Simulation cost for a string of length |x|O(|r| × |x|) — a set of states must be trackedO(|x|) — one table lookup per character
SpaceSmallPotentially exponential
PowerExactly equal — both recognise precisely the regular languages
The trade-off that motivates the whole lesson

An NFA is small and easy to build but slow to run; a DFA is fast to run but can be large. Since a scanner is built once and run on every character of every program ever compiled, we build the NFA for convenience and then convert it to a DFA for speed. That sentence is why the subset construction exists.

Transition diagrams for real tokens

Before the formal constructions, this is how a scanner is actually laid out by hand — one diagram per token, tried in order.

Identifiers and keywords

start →(9)— letter →(10)— other →((11))*
                                  return( getToken(), installID() )
The keyword problem. if matches the identifier pattern too. Two standard solutions: (1) install the keywords in the symbol table first, marked as reserved, so installID looks a lexeme up and returns the keyword token if it finds one — this is the usual choice; or (2) give each keyword its own transition diagram, placed BEFORE the identifier diagram, so it is tried first.

The longest-match rule matters here. Scanning 6.336E4, the machine could stop at 6 or at 6.336, but it must go as far as it can. Hence the three exits, each retracting one character.

where delim is blank, tab or newline. This is the one accepting state that returns nothing — it simply restarts the scanner, which is how whitespace gets stripped.

Thompson's construction — regular expression to NFA

The four rules BASIS 1 — for ε:   start →(i)— ε →((f))

BASIS 2 — for a symbol a:   start →(i)— a →((f))

INDUCTION — for r = s | t (UNION): a new start state with ε to the starts of N(s) and N(t), and ε from both their finals to a new final state.

INDUCTION — for r = st (CONCATENATION): the final state of N(s) is merged with the start state of N(t). No new states.

INDUCTION — for r = s* (CLOSURE): a new start i and new final f, with ε from i to the start of N(s), ε from N(s)'s final back to N(s)'s start (the loop), ε from N(s)'s final to f, and ε directly from i to f (the “zero occurrences” bypass).
The four properties of the result — quote them

The NFA produced by Thompson's construction always has: (1) exactly one start state and exactly one accepting state; (2) no edge entering the start state and no edge leaving the accepting state; (3) at most two edges leaving any state; and (4) at most 2|r| states for a regular expression of length |r|. Those properties are what make the subset construction manageable.

Q. Construct an NFA for (a|b)*abb by Thompson's construction.

Step 1 — the pieces. Build a as 2—a→3 and b as 4—b→5.

Step 2 — the union a|b. New start 1, new final 6:

1 —ε→ 2 —a→ 3 —ε→ 6   and   1 —ε→ 4 —b→ 5 —ε→ 6

Step 3 — the closure (a|b)*. New start 0, new final 7; add the loop 6→1 and the bypass 0→7:

0 —ε→ 1  ·  6 —ε→ 7  ·  6 —ε→ 1 (loop)  ·  0 —ε→ 7 (bypass)

Step 4 — concatenate abb. Merge and chain: 7—a→8, 8—b→9, 9—b→10.

The complete NFA — 11 states, start 0, accepting 10

The subset construction — NFA to DFA

The two operations you must define first ε-closure(s) — the set of NFA states reachable from state s on ε-transitions alone, including s itself.

ε-closure(T) — the union of ε-closure(s) over all s in T.

move(T, a) — the set of NFA states to which there is a transition on input symbol a from some state in T. ε-transitions are not followed here.

The order is always move first, then ε-closure — that is, the new DFA state is ε-closure(move(T, a)).
The algorithm
Start state of the DFA = ε-closure(s0), marked unmarked;
while there is an unmarked DFA state T {
    mark T;
    for each input symbol a {
        U = ε-closure( move(T, a) );
        if U is not already a DFA state, add it unmarked;
        Dtran[T, a] = U;
    }
}
A DFA state is ACCEPTING iff it contains at least one accepting NFA state.
Q. Convert the NFA above for (a|b)*abb into a DFA by the subset construction.

Start state. ε-closure(0): from 0 take ε to 1 and 7; from 1 take ε to 2 and 4. Nothing more.

A = {0, 1, 2, 4, 7}

From A.

move(A, a): only state 2 and state 7 have a-edges → {3, 8}.
ε-closure({3,8}): 3→6; 6→1,7; 1→2,4. Add all.   = {1, 2, 3, 4, 6, 7, 8} = B

move(A, b): only state 4 has a b-edge → {5}.
ε-closure({5}): 5→6; 6→1,7; 1→2,4.   = {1, 2, 4, 5, 6, 7} = C

From B = {1,2,3,4,6,7,8}.

move(B, a) = {3, 8} (from 2 and 7) → ε-closure = B again.

move(B, b) = {5, 9} (from 4 and 8) → ε-closure: add 6, then 1, 7, then 2, 4. State 9 has no ε-edge.   = {1, 2, 4, 5, 6, 7, 9} = D

From C = {1,2,4,5,6,7}.

move(C, a) = {3, 8} → B.    move(C, b) = {5} → C.

From D = {1,2,4,5,6,7,9}.

move(D, a) = {3, 8} → B.

move(D, b) = {5, 10} (from 4 and 9) → ε-closure = {1, 2, 4, 5, 6, 7, 10} = E. E contains 10, the accepting NFA state, so E is accepting.

Sanity checks worth running:

  • Every row is complete — each of the five states has exactly one entry per input symbol. A DFA has no missing transitions.
  • On a, every state goes to B. That is right: seeing an a always means “I may have just started the final abb”, so the machine resets to the same position.
  • Trace abb: A —a→ B —b→ D —b→ E. Accepted. ✓
  • Trace babb: A —b→ C —a→ B —b→ D —b→ E. Accepted. ✓
  • Trace ab: A —a→ B —b→ D. D is not accepting — correctly rejected. ✓
The three things to write in every subset-construction answer

1. The ε-closure of the start state, shown as a set. 2. A table with one row per DFA state, giving both the NFA state set and the transitions. 3. The statement of which states are accepting and why — “E is accepting because it contains NFA state 10”. Then trace one accepted and one rejected string as a check.

Simulating a DFA

The scanner's inner loop
s = s0;
c = nextChar();
while ( c != eof ) {
    s = move(s, c);  /* one array lookup */
    c = nextChar();
}
if ( s is in F ) return "yes"; else return "no";
One table lookup per input character — O(|x|) total, independent of the size of the pattern. That is the speed the whole conversion was for.

In the worked example, E is accepting solely because it contains NFA state 10 — the other six states in E are ordinary.

For (a|b)*abb that gives A = {0,1,2,4,7}: 0 reaches 1 and 7 by ε, and 1 reaches 2 and 4. Forgetting to close the start state is the most common error.

3. The correct order of operations for a new DFA state is:

T is already ε-closed when it was created, so closing again changes nothing; the closure must be applied after the symbol transition, to absorb any ε-edges reachable from the new states.

4. Thompson's construction for r = st (concatenation):

Union adds a new start and final with four ε-edges; closure adds a new start and final plus a loop and a bypass. Concatenation is the only rule that adds nothing.

5. For (a|b)*abb, the NFA has 11 states and the DFA has:

A, B, C, D and E, with E the only accepting state. The 2ⁿ bound is the worst case, not the usual outcome — most conversions shrink the machine, as here.

6. Simulating an NFA on a string of length |x| costs:

A DFA costs O(|x|) — one table lookup per character, independent of pattern size. That gap is exactly why we pay the conversion cost once at scanner-build time.

The alternative is a separate transition diagram per keyword, placed before the identifier diagram so it is tried first. Both are standard; the symbol-table method is the usual choice.

8. Which is true of NFAs and DFAs?

The subset construction is the proof: every NFA can be converted to an equivalent DFA. The difference is only in size and simulation speed, not in power.

Recall without looking

Give the five-tuple definition of a finite automaton and compare NFA with DFA.

(Q, Σ, δ, q₀, F): states, input alphabet not containing ε, transition function, one start state, set of accepting states. NFA: ε-transitions allowed, δ maps to a set of states, easy to build, few states — at most 2|r| — but simulation costs O(|r|×|x|). DFA: no ε, exactly one transition per symbol, easy to simulate at O(|x|), but up to 2ⁿ states. Their expressive power is exactly equal.

Give Thompson's four construction rules.

For ε and for a single symbol a: a two-state machine with that label. For s|t: a new start with ε-edges to both sub-machines' starts, and ε-edges from both finals to a new final. For st: merge the final of N(s) with the start of N(t), adding no states. For s*: a new start i and final f, with ε from i to N(s)'s start, ε from N(s)'s final back to its start, ε from N(s)'s final to f, and ε directly from i to f.

State the four properties of a Thompson NFA.

Exactly one start and one accepting state; no edge enters the start and none leaves the accepting state; at most two edges leave any state; and at most 2|r| states for a regular expression of length |r|.

Define ε-closure and move, and give the subset-construction algorithm.

ε-closure(s) is the set of states reachable from s on ε-transitions alone, including s. move(T, a) is the set of states reachable from any state of T on input a, following no ε-edges. The DFA start state is ε-closure(s₀); while an unmarked state T exists, mark it and for each symbol a set U = ε-closure(move(T,a)), adding U as a new state if unseen, and Dtran[T,a] = U. A DFA state is accepting if it contains any accepting NFA state.

Give the NFA and the DFA for (a|b)*abb.

NFA, 11 states, start 0, accepting 10: 0→ε→1,7; 1→ε→2,4; 2→a→3; 3→ε→6; 4→b→5; 5→ε→6; 6→ε→1,7; 7→a→8; 8→b→9; 9→b→10. DFA: A={0,1,2,4,7} start; B={1,2,3,4,6,7,8}; C={1,2,4,5,6,7}; D={1,2,4,5,6,7,9}; E={1,2,4,5,6,7,10} accepting. Transitions: A→B,C; B→B,D; C→B,C; D→B,E; E→B,C on a and b respectively.

How are keywords and whitespace handled in transition diagrams?

Keywords either are pre-installed in the symbol table as reserved, so installID returns the keyword token, or get their own transition diagrams placed before the identifier diagram. Whitespace has a diagram whose accepting state returns no token at all and simply restarts the scanner — the only accepting state that returns nothing.

Give the DFA simulation loop and its cost.

s = s₀; c = nextChar(); while c ≠ eof { s = move(s,c); c = nextChar(); } accept if s is in F. One array lookup per input character, so O(|x|) total, independent of the size of the pattern.
