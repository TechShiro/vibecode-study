What is code optimization?

Optimization is the transformation of intermediate code into functionally equivalent code that executes faster, uses fewer machine resources (registers, cache, energy), or occupies less memory space.

Three cardinal criteria for a compiler optimizer
  1. Semantics preservation: The transformed program must produce the exact same observable output for all valid inputs as the unoptimized version.
  2. Measurable speedup: Transformations must noticeably reduce running time or resource footprint on average.
  3. Reasonable compile-time overhead: The optimization pass must terminate quickly without exponential analysis slowdown.

Function-preserving transformations

These transformations preserve the input-output behavior of a basic block or control flow graph without restructuring loop iteration headers.

1. Common Subexpression Elimination (CSE)

An expression E is a common subexpression if E was previously computed, and the values of the operands of E have not changed since that prior computation.

Worked comparison — CSE
Unoptimized Three-Address CodeOptimized Three-Address Code
 
t1 = 4 * i
t2 = a[t1]
t3 = 4 * i    /* redundant computation */
t4 = b[t3]
 
t1 = 4 * i
t2 = a[t1]
/* t3 reused from t1 */
t4 = b[t1]

Eliminating t3 = 4 * i saves an expensive multiplication operation.

2. Copy Propagation

Assignments of the form x = y are called copies. Copy propagation replaces subsequent occurrences of x with y, provided neither x nor y has been reassigned along the execution path.

Worked trace — Copy propagation enabling CSE 
/* Before: */
x = t3
a[i] = x
t5 = x * 4

/* After copy propagation: */
x = t3
a[i] = t3
t5 = t3 * 4

If x is no longer needed afterwards, the assignment x = t3 becomes dead code.

3. Dead-Code Elimination

A variable is dead at a point if its value is never used along any path starting from that point. Code that computes values that are never subsequently read is dead code and can be eliminated.

/* Example: debug flag known at compile time */
debug = 0;
if (debug) {
    print_status();  /* Unreachable code: pruned completely */
}

4. Constant Folding and Constant Propagation

  • Constant Folding: Evaluating expressions with compile-time known constants directly during compilation (e.g., replacing r = 3.14159 * 2 with r = 6.28318).
  • Constant Propagation: If a variable is assigned a constant c = 10, replacing all subsequent uses of c with 10 as long as c is not modified.

Loop transformations

Programs spend roughly 90% of their runtime executing inside 10% of their code (mostly inner loops). Optimizing loops yields the greatest performance gains.

1. Code Motion (Loop-Invariant Code Motion)

An expression is loop-invariant if its value does not change throughout iterations of the loop. Code motion hoists the computation of such expressions outside the loop to the loop preheader.

Before vs After Hoisting
Inside Loop (N iterations)Hoisted to Preheader (1 execution)
 
while (i <= limit) {
    x = y + z;      /* invariant: y & z never change */
    a[i] = a[i] + x;
    i = i + 1;
}
 
t1 = y + z;         /* executed once */
while (i <= limit) {
    a[i] = a[i] + t1;
    i = i + 1;
}

2. Induction Variables and Reduction in Strength

A variable x is an induction variable if every time it changes value, it is incremented or decremented by a loop-invariant constant.

Reduction in Strength: Replacing an expensive operation (like multiplication) with an equivalent cheaper operation (like addition or bit-shift).

Strength reduction on induction variable 
/* Before: Multiplication by 4 on each step */
for (i = 0; i < n; i++) {
    t1 = i * 4;       /* multiplication inside loop */
    b[i] = a[t1];
}

/* After: Strength reduction replaces multiplication with addition */
t1 = 0;
for (i = 0; i < n; i++) {
    b[i] = a[t1];
    t1 = t1 + 4;      /* cheap addition */
}

Recall without looking

The three criteria of code optimization.

1. Must preserve program semantics. 2. Must speed up execution or reduce resource usage. 3. Compilation time must remain reasonable.

Four primary function-preserving transformations.

Common subexpression elimination, copy propagation, dead-code elimination, and constant folding/propagation.

Loop-invariant code motion vs reduction in strength.

Loop-invariant code motion hoists loop-unchanging expressions to the loop preheader. Strength reduction replaces expensive operations (e.g., multiplications in induction variables) with cheaper ones (e.g., additions).
