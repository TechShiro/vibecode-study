Issues in the design of a code generator

The code generator is the final phase of a compiler. It maps the intermediate representation (IR) into equivalent target machine assembly or binary code.

IssueCore challenge & design choices
1. Target program formatCan emit absolute machine code (runs immediately in fixed memory), relocatable machine code (requires linker/loader), or assembly code (easier to debug, delegates instruction encoding).
2. Instruction selectionMapping IR trees/quadruples to target instruction sets. CISC architectures offer multiple instructions for one IR statement; choosing the best sequence minimizes cycle count.
3. Register allocation vs assignmentAllocation: deciding which variables reside in fast CPU registers rather than slow RAM. Assignment: choosing the specific physical register (e.g., R1 vs R2) for each variable.
4. Evaluation orderThe order in which subexpressions are computed dictates the number of temporary registers needed simultaneously (register pressure).
5. Memory managementMapping symbolic variable names to activation record offsets, static data labels, or heap pointers.

Register Allocation via Graph Coloring

Accessing variables in CPU registers takes 1 clock cycle, whereas memory accesses take tens to hundreds of cycles. Because physical registers are scarce ($k$ registers), optimizing register allocation is critical.

The Interference Graph

  • Nodes: Variables or temporaries (their live ranges).
  • Edges: An undirected edge $(u, v)$ exists if variable $u$ and variable $v$ are simultaneously live at some program point. If an edge exists, $u$ and $v$ cannot share the same register.
The $k$-Coloring Analogy Finding a register assignment for $k$ physical registers is equivalent to coloring the interference graph using at most $k$ distinct colors such that no two adjacent nodes have the same color.
Chaitin's Graph Coloring Algorithm (Kempe's Heuristic)
  1. Build: Construct the interference graph from live variable analysis.
  2. Simplify: Find a node $v$ with degree $< k$ (fewer than $k$ neighbors). Remove $v$ from the graph and push $v$ onto a stack. (Since $v$ has $< k$ neighbors, whenever its neighbors are colored, there will always be at least one free color left for $v$).
  3. Repeat: Continue removing nodes of degree $< k$.
  4. Spill: If all remaining nodes have degree $\ge k$, pick a candidate variable (one with low use frequency or long live range) to spill into memory. Mark it and remove it.
  5. Select / Color: Pop nodes from the stack one by one, restore them to the graph, and assign any color not used by its already colored neighbors.

Peephole Optimization

Peephole optimization is a local target-code optimization technique that examines a small sliding window (a “peephole”, typically 2 to 4 instructions) of target assembly code and replaces inefficient instruction sequences with shorter, faster equivalents.

Primary Characteristics and Techniques

1. Elimination of Redundant Loads and Stores

If a value is stored in memory and immediately reloaded into another (or the same) register without intervening modification:

Target assembly beforePeephole optimized
 
MOV R0, a
MOV a, R0    /* Redundant store: 'a' already holds R0 */
 
MOV R0, a
/* second instruction deleted */
 
MOV a, R0
MOV R0, b    /* If R0 is not needed later */
 
MOV a, b     /* Direct memory copy if supported */
2. Unreachable Code Elimination

An instruction that immediately follows an unconditional jump and does not have an attached jump target label can never be reached:

/* Before: */
    JMP L2
    ADD R1, R2, R3   /* Unreachable dead code */
L2: ...

/* After: 'ADD' instruction pruned completely */
3. Flow-of-Control Optimizations (Jump Chaining)

Replaces jumps that branch to other jump instructions with a single direct jump:

BeforeAfter
 
    GOTO L1
    ...
L1: GOTO L2
 
    GOTO L2
    ...
L1: GOTO L2
4. Algebraic Simplification and Reduction in Strength
  • ADD R0, #0 → Deleted (no-op).
  • MULT R0, #1 → Deleted (no-op).
  • MULT R0, #2 → SHL R0, #1 (bit-shift left is much faster than hardware multiplication).
  • MULT R0, #8 → SHL R0, #3.
5. Use of Machine Idioms

Hardware architectures often provide specialized instructions that perform common operations in fewer clock cycles:

  • ADD R0, #1 → INC R0 (increment register).
  • SUB R0, #1 → DEC R0 (decrement register).
  • Auto-increment / auto-decrement addressing modes in loops (e.g. MOV (R1)+, R2).

Check yourself

Retrieval practice

1. In register allocation via graph coloring, what does an edge between two variables indicate?

Interference means overlapping live ranges; adjacent nodes cannot receive the same color/register.

2. What distinguishes register allocation from register assignment?

Allocation decides who gets a register; assignment decides whether it is R0, R1, or R2.

3. Replacing `MULT R0, #4` with `SHL R0, #2` during peephole optimization is an example of:

Replacing an expensive multiplication by a power of 2 with a cheap left shift is strength reduction.

Recall without looking

The five design issues in code generation.

1. Target program format. 2. Instruction selection. 3. Register allocation and assignment. 4. Evaluation order. 5. Memory management.

How does Chaitin's heuristic color the interference graph?

Repeatedly removes nodes with degree < k and pushes them to a stack. If stuck, spills a variable. Once empty, pops nodes and colors them with available registers.

Five techniques of peephole optimization.

1. Redundant load/store elimination. 2. Unreachable code elimination. 3. Flow-of-control optimization (jump chaining). 4. Algebraic simplification / strength reduction. 5. Use of machine idioms (INC/DEC).
