1. What is Syntax-Directed Translation?

Syntax-Directed Translation (SDT) augments a Context-Free Grammar with semantic information by associating attributes with grammar symbols and semantic rules (or actions) with productions.

Components of Syntax-Directed Translation $$\text{SDT} = \text{Context-Free Grammar} + \text{Attributes} + \text{Semantic Rules}$$ The parsing process drives semantic computation — evaluating types, checking scope, computing values, or emitting intermediate code.

2. Synthesised vs Inherited Attributes

Grammar attributes are categorized according to how their values are computed across parse tree nodes:

PropertySynthesised AttributeInherited Attribute
Definition Computed from the attribute values of the children of that node in the parse tree (or the node itself). Computed from the attribute values of the parent and/or siblings of that node.
Flow Direction Bottom-Up (from leaves up toward the root). Top-Down & Left-to-Right (from root and left siblings downward).
Production Rule Form For production $A \to X_1 X_2 \dots X_k$:
$$A.s = f(X_1.a_1, X_2.a_2, \dots, X_k.a_k)$$ (LHS attribute defined by RHS symbols).		 For production $A \to X_1 X_2 \dots X_k$:
$$X_j.i = f(A.a, X_1.a_1, \dots, X_{j-1}.a_{j-1})$$ (RHS attribute defined by LHS or left-siblings).
Terminal Symbols Terminals can have synthesised attributes (supplied by the Lexical Analyser via yylval). Terminals cannot have inherited attributes (their values are fixed by lexical tokens).
Parsing Mechanism Naturally evaluated during bottom-up LR parsing as handles are reduced on the stack. Naturally evaluated during top-down LL parsing or via depth-first traversals.
Typical Example Evaluating arithmetic expressions: E.val = E1.val + T.val. Type declarations: passing int down to a list of variables in int a, b, c;.

3. Annotated Parse Tree — Full Worked Example

An annotated parse tree (or decorated parse tree) displays the values of all attributes at each respective parse tree node.

Worked Example: Desk Calculator SDD for “3 * 5 + 4”

Consider the standard arithmetic grammar with synthesised attribute .val:

ProductionSemantic Rule
$L \to E$L.val = E.val (print result)
$E \to E_1 + T$E.val = E1.val + T.val
$E \to T$E.val = T.val
$T \to T_1 * F$T.val = T1.val * F.val
$T \to F$T.val = F.val
$F \to \textbf{digit}$F.val = digit.lexval

Annotated Parse Tree Structure for $3 * 5 + 4$:

                    L [val = 19]
                      |
                    E [val = 19]
                   /  |  \
       [val = 15] E   +   T [val = 4]
                  |       |
       [val = 15] T       F [val = 4]
                / | \     |
     [val = 3] T  *  F    digit [lexval = 4]
               |     |    [val = 5]
     [val = 3] F   digit [lexval = 5]
               |
             digit [lexval = 3]

Evaluation Steps (Bottom-Up):
1. Leaves scanned: digit.lexval = 3, 5, 4.
2. Reductions: $F.val = 3$, $T_1.val = 3$, $F.val = 5$.
3. Multiplication: $T.val = T_1.val \times F.val = 3 \times 5 = 15$.
4. Reductions: $E_1.val = 15$, $F.val = 4$, $T.val = 4$.
5. Addition: $E.val = E_1.val + T.val = 15 + 4 = 19$.
6. Root: $L.val = 19$. All attributes flow upwards → purely S-attributed.

4. Dependency Graphs and Evaluation Order

A dependency graph depicts the flow of information between attribute instances in a parse tree:

  • For each node attribute $X.a$, there is a vertex in the dependency graph.
  • If attribute $Y.b$ is computed using the value of $X.a$, an edge is directed from $X.a \longrightarrow Y.b$.
Attribute Dependency & Topological Sorting
X₁.a (Child 1) Leaves / Subtree Attributes
X₂.b (Child 2) Leaves / Subtree Attributes
A.s = f(X₁.a, X₂.b) Evaluation Order: Topological Sort of Dependency DAG
Circular Dependency Warning

If a dependency graph contains any directed cycle, the SDD is circular and mathematically undefined — there is no possible order to evaluate the attributes! A valid SDD must yield an Acyclic Directed Graph (DAG), allowing a topological sort to determine evaluation order.

5. S-Attributed vs L-Attributed Definitions

FeatureS-Attributed SDDL-Attributed SDD
Attribute Types Allowed Uses ONLY synthesised attributes. Uses synthesised attributes AND restricted inherited attributes.
Inherited Attribute Restriction Inherited attributes are strictly forbidden. An inherited attribute $X_j.i$ for production $A \to X_1 X_2 \dots X_n$ may depend ONLY on:
1. Attributes of symbols to its left: $X_1, X_2, \dots, X_{j-1}$, or
2. Inherited attributes of the parent $A$.
(It can never depend on right siblings or synthesised parent attributes!)
Evaluation Strategy Evaluated during Bottom-Up parsing directly on the LR parser stack (at handle reduction time). Evaluated in a single depth-first, left-to-right traversal (compatible with top-down LL parsing).
Expressive Hierarchy ∅ ⊂ S-Attributed ⊂ L-Attributed ⊂ General SDD
Every S-attributed definition is automatically an L-attributed definition (since it places zero illegal dependencies on right siblings).
Inherited Attribute Example: Type Declarations

Consider the declaration grammar D → T L,   T → int | float,   L → L₁, id | id:

ProductionSemantic RuleAttribute Category
$D \to T\ L$L.type = T.typeInherited (passed from sibling $T$ to $L$)
$T \to \textbf{int}$T.type = integerSynthesised (from terminal)
$T \to \textbf{float}$T.type = floatSynthesised (from terminal)
$L \to L_1,\ \textbf{id}$L1.type = L.type
addType(id.entry, L.type)		Inherited (passed from parent $L$ to child $L_1$)
$L \to \textbf{id}$addType(id.entry, L.type)Inherited (passed from parent $L$)

Because $L.type$ depends only on the left sibling $T$ and parent $L$, this SDD is strictly L-attributed.

6. Syntax-Directed Translation Schemes (SDTs)

A Syntax-Directed Translation Scheme (SDT) is a Context-Free Grammar where program fragments called semantic actions (enclosed in braces { ... }) are embedded directly within the production bodies.

Postfix SDT for Infix-to-Postfix Translation E → E₁ + T   { printf("+"); }
E → T
T → T₁ * F   { printf("*"); }
T → F
F → ( E )
F → id    { printf("%s", id.name); }

When an SDT has all semantic actions placed at the extreme right end of every production, it is called a Postfix SDT. Postfix SDTs execute naturally during bottom-up LR parsing exactly when a production reduction is applied.

7. Bottom-Up Evaluation of S-Attributed Definitions on the Value Stack (Yacc)

S-attributed syntax-directed definitions can be evaluated directly during bottom-up LR parsing without explicitly building a parse tree in memory. The parser maintains a Value Stack (val stack) in parallel with the parse state and symbol stacks.

How Yacc/Bison Implements S-Attributed Evaluation (Mam's Semantic Analysis.pdf)

Whenever a token is shifted onto the parser stack, its synthesized lexical attribute (from yylval) is pushed onto the top of the val stack.

When reducing by a production $A \to X_1 X_2 \dots X_k$:

  • The top of the stack points to $X_k$ at index top.
  • The attribute of $X_1$ resides at val[top - k + 1] — accessed in Yacc as $1.
  • The attribute of $X_i$ resides at val[top - k + i] — accessed in Yacc as $i.
  • The attribute of the left-hand side non-terminal $A$ is computed and stored at val[top - k + 1] — accessed in Yacc as $$.
  • The stack pointer is decremented by $k - 1$ ($top \leftarrow top - k + 1$).

8. Eliminating Left Recursion from Translation Schemes (SDTs)

When implementing syntax-directed translation top-down (e.g. in predictive or recursive-descent parsers), left-recursive productions cause infinite recursion. However, simply eliminating left recursion from the grammar alone destroys the order and binding of semantic actions! We must systematically transform the semantic actions alongside the grammar rules.

General SDT Left-Recursion Elimination Rule Left-Recursive SDT:
$$A \to A_1 \, Y \, \{ A.a = g(A_1.a, Y.y) \} \mid X \, \{ A.a = f(X.x) \}$$
Equivalent Right-Recursive SDT (using Inherited Attribute $i$ and Synthesized Attribute $s$ for $A'$):
$$A \to X \, \{ A'.i = f(X.x) \} \, A' \, \{ A.a = A'.s \}$$
$$A' \to Y \, \{ A'_1.i = g(A'.i, Y.y) \} \, A'_1 \, \{ A'.s = A'_1.s \} \mid \epsilon \, \{ A'.s = A'.i \}$$
Concrete Example · Infix to Postfix Translation Scheme

Original Left-Recursive Translation Scheme:
E → E₁ + T { print('+'); } | T

Transformed Right-Recursive Scheme (embed actions right where symbols are consumed):
E → T R
R → + T { print('+'); } R | ε

Tracing on 9 - 5 + 2 correctly outputs postfix string 9 5 - 2 +, fully preserving operator associativity without left recursion!

Check yourself

Retrieval practice

1. In an L-attributed SDD, an inherited attribute of a symbol on the RHS may depend on which of the following?

The L in L-attributed stands for Left-to-right. Attributes may only depend on information that has already been visited in a depth-first, left-to-right traversal.

2. An S-attributed Syntax-Directed Definition can always be evaluated during which type of parsing?

Because S-attributed definitions only compute synthesized attributes from children, all required attribute values are already available on the stack when the handle is reduced.

3. What does a cycle in an attribute dependency graph indicate?

A cycle means attribute X depends on attribute Y, which in turn depends on X. No topological ordering exists to compute these values.

4. What is a Postfix SDT?

In a Postfix SDT, every action occurs at the end of the RHS, matching the exact moment an LR parser reduces the production.

Recall without looking

Contrast Synthesised vs Inherited attributes.

Synthesised attributes flow bottom-up: calculated from children's attributes or lexical values. Inherited attributes flow top-down or sideways: calculated from parent or left-sibling attributes.

State the relationship between S-attributed and L-attributed definitions.

All S-attributed definitions are L-attributed definitions ($S \subset L$). S-attributed definitions use only synthesised attributes, while L-attributed definitions allow synthesised plus inherited attributes restricted to left-siblings and parent.
