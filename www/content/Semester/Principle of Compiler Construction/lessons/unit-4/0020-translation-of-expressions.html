1. Translation of Arithmetic Expressions

2. Array Addressing — 1D and 2D Formula Derivations

Memory Layouts: Row-Major vs Column-Major Storage
Row-Major Order (C / C++ / Java) Row 0 elements consecutive, then Row 1, ... [A[0,0], A[0,1], A[1,0], A[1,1]]
Column-Major Order (Fortran / MATLAB) Col 0 elements consecutive, then Col 1, ... [A[0,0], A[1,0], A[0,1], A[1,1]]

1-Dimensional Array Addressing

For an array declared as $A[low \dots high]$ with element width $w$ bytes and starting base address $Base$:

1D Array Address Formula $$\text{Address}(A[i]) = Base + (i - low) \times w = (Base - low \times w) + i \times w$$ The subexpression $(Base - low \times w)$ is a compile-time invariant constant $C$. At runtime, the compiler only computes $C + i \times w$.

2-Dimensional Array Addressing

Let array $A$ have bounds $[low_1 \dots high_1]$ along dimension 1 (rows) and $[low_2 \dots high_2]$ along dimension 2 (columns).
Let number of columns $n_2 = (high_2 - low_2 + 1)$ and number of rows $n_1 = (high_1 - low_1 + 1)$.

Memory Storage ModelAddress Calculation FormulaCompile-Time vs Runtime Breakdown
Row-Major Order
(Elements of row $i_1$ stored contiguously)		 To reach $A[i_1, i_2]$, we skip $(i_1 - low_1)$ complete rows (each having $n_2$ elements), plus $(i_2 - low_2)$ elements in the current row:

$$\text{Address}(A[i_1, i_2]) = Base + ((i_1 - low_1) \times n_2 + (i_2 - low_2)) \times w$$ 		Invariant Constant $C$:
$C = Base - (low_1 \times n_2 + low_2) \times w$

Runtime Address:
$\text{Address} = C + (i_1 \times n_2 + i_2) \times w$
Column-Major Order
(Elements of column $i_2$ stored contiguously)		 To reach $A[i_1, i_2]$, we skip $(i_2 - low_2)$ complete columns (each having $n_1$ elements), plus $(i_1 - low_1)$ elements in the current column:

$$\text{Address}(A[i_1, i_2]) = Base + ((i_2 - low_2) \times n_1 + (i_1 - low_1)) \times w$$ 		Invariant Constant $C$:
$C = Base - (low_2 \times n_1 + low_1) \times w$

Runtime Address:
$\text{Address} = C + (i_2 \times n_1 + i_1) \times w$
Numerical Exam Problem: Calculating 2D Array Address

Problem: An array $A[1 \dots 10, 1 \dots 20]$ of 4-byte integers ($w = 4$) is stored beginning at $Base = 1000$. Find the memory address of element $A[3, 5]$ in both Row-Major and Column-Major order.

Given: $low_1 = 1$, $high_1 = 10 \implies n_1 = 10$.
$low_2 = 1$, $high_2 = 20 \implies n_2 = 20$.
$i_1 = 3, i_2 = 5, w = 4, Base = 1000$.

Case 1: Row-Major Order:
$$\text{Offset} = ((3 - 1) \times 20 + (5 - 1)) \times 4 = (2 \times 20 + 4) \times 4 = (40 + 4) \times 4 = 44 \times 4 = 176$$ $$\text{Address}(A[3, 5]) = 1000 + 176 = \mathbf{1176}$$

Case 2: Column-Major Order:
$$\text{Offset} = ((5 - 1) \times 10 + (3 - 1)) \times 4 = (4 \times 10 + 2) \times 4 = (40 + 2) \times 4 = 42 \times 4 = 168$$ $$\text{Address}(A[3, 5]) = 1000 + 168 = \mathbf{1168}$$

3. Boolean Expressions — Short-Circuit Evaluation

In programming languages like C, Java, and Python, boolean expressions are evaluated via short-circuit evaluation: evaluation ceases as soon as the overall truth value is definitively resolved.

Boolean ExpressionShort-Circuit Semantic RuleGenerated TAC Pattern
B₁ || B₂ If $B_1$ evaluates to true, do NOT evaluate $B_2$; jump directly to L_true. Evaluate $B_2$ only if $B_1$ is false. 
    if B₁ goto L_true
    if B₂ goto L_true
    goto L_false
B₁ && B₂ If $B_1$ evaluates to false, do NOT evaluate $B_2$; jump directly to L_false. Evaluate $B_2$ only if $B_1$ is true. 
    ifFalse B₁ goto L_false
    ifFalse B₂ goto L_false
    goto L_true

5. Full Master Exam Problem — Combined TAC Generation

Complete Worked TAC: Nested Loop and Conditional Array Update

Translate the following C loop into Three-Address Code, assuming array $A$ has 4-byte integers ($w = 4$) with $low = 0$:

while (i < 10) {
    if (A[i] > max)
        max = A[i];
    i = i + 1;
}

Generated Three-Address Code with Instructions & Labels:

L1: ifFalse i < 10 goto L_exit    // While loop entry condition test
    t1 = i * 4                     // Compute byte offset for A[i]
    t2 = A[t1]                     // Load A[i] into temporary t2
    ifFalse t2 > max goto L2       // If A[i] <= max, skip if-body
    max = t2                       // If-body: update max = A[i]
L2: t3 = i + 1                     // Loop increment: t3 = i + 1
    i = t3                         // i = i + 1
    goto L1                        // Jump back to loop start
L_exit: ...                        // Execution resumes here after loop terminates

6. Static Checking · Type Systems and Type Equivalence (Mam's Material)

Static checking is the validation performed by the compiler at compile-time to ensure that the source program adheres to the syntactic and semantic conventions of the language. In contrast, dynamic checking is performed at run-time by the generated target program (e.g. detecting division by zero, array index out of bounds, or null pointer dereference).

Static Check CategoryWhat the Compiler EnforcesExample Violation Caught at Compile-Time
1. Type ChecksAn operator or function must only be applied to operands of compatible data types.Applying modulo % to floating-point numbers; passing a string into a function expecting an int pointer.
2. Flow-of-Control ChecksStatements that cause execution flow to leave a construct must have somewhere to transfer control to.A break or continue statement placed outside a for/while loop or switch body; a missing return in a non-void function.
3. Uniqueness ChecksAn entity must be defined exactly once within a given scope.Two variables with the same identifier declared in the same block; duplicate case constants inside the same switch statement.
4. Name-Related ChecksWhere a name must appear two or more times, names must match exactly.In Ada/PL/I where loop or block labels must match at opening and closing: LoopA: ... end LoopA;.

Type Expressions & Graph Representations

The compiler represents the type of any language construct using a formal type expression. A type expression is formed recursively:

  • Basic types: Atomic types such as integer, real, char, boolean, void, and special sentinel type_error.
  • Type constructors:
    • Array: $\text{array}(I, T)$ where $I$ is an index set/range and $T$ is the element type (e.g. $\text{array}(1..10, \text{integer})$).
    • Product / Cartesian Product: $T_1 \times T_2$ (used for function parameter lists or pair tuples).
    • Record / Struct: Named field-type pairs: $\text{record}((\text{field}_1 \times T_1) \times \dots \times (\text{field}_k \times T_k))$.
    • Pointer: $\text{pointer}(T)$ denoting a memory address referencing an object of type $T$.
    • Function / Mapping: $D \to R$ mapping domain type expression $D$ to range type expression $R$.

Name vs Structural Equivalence
Name Equivalence: Two types are equal if and only if their type names are identical. Fast to check ($O(1)$ string compare), but rigid (two identical structs with different names cannot be assigned).

Structural Equivalence: Two types are equal if they have identical internal structures (recursively matching fields and constructors). Flexible, but requires cycle detection for recursive types.

Master Comparison: Name Equivalence versus Structural Equivalence

FeatureName EquivalenceStructural Equivalence
DefinitionTwo type expressions are equivalent if and only if they have the exact same name.Two type expressions are equivalent if they have the same constructor applied to structurally equivalent components.
ImplementationVery simple — symbol table lookup and direct name pointer / string comparison ($O(1)$).Recursive tree/graph traversal algorithm; must detect and handle cycles in recursive types ($O(V+E)$).
Aliasing (typedef)Under strict name equivalence, a typedef creates a new distinct type incompatible with the original.A typedef is purely an alias; typedef int Age; Age x; int y; x = y; is completely legal.
Code Example
type Point = record x, y: real end;
type Vector = record x, y: real end;
var p: Point; v: Vector;
p = v; // ERROR under Name Equivalence!
type Point = record x, y: real end;
type Vector = record x, y: real end;

7. Translation of Declarations · Types, Widths & Symbol Table Offsets

During the compilation of variable declarations, the compiler must accomplish two crucial tasks:

  1. Determine the type expression and byte width of every declared variable.
  2. Assign each variable a relative memory address (offset) within the data segment or activation record stack frame.

Syntax-Directed Definition for Declarations (Mam's Static checking slides)

The compiler maintains a global variable offset initialized to $0$ before declarations start.

Grammar & Semantic Rules: $$\begin{aligned} P &\to D \; S \\ D &\to D \; ; \; D \\ D &\to \mathbf{id} : T & \{ &\text{enter}(\mathbf{id}.\text{name}, \, T.\text{type}, \, \text{offset}); \\ & & &\text{offset} = \text{offset} + T.\text{width}; \} \\ T &\to \mathbf{integer} & \{ &T.\text{type} = \text{integer}; \quad T.\text{width} = 4; \} \\ T &\to \mathbf{real} & \{ &T.\text{type} = \text{real}; \quad T.\text{width} = 8; \} \\ T &\to \mathbf{char} & \{ &T.\text{type} = \text{char}; \quad T.\text{width} = 1; \} \\ T &\to \mathbf{array} \, [ \, \mathbf{num} \, ] \, \mathbf{of} \, T_1 & \{ &T.\text{type} = \text{array}(\mathbf{num}.\text{val}, \, T_1.\text{type}); \\ & & &T.\text{width} = \mathbf{num}.\text{val} \times T_1.\text{width}; \} \\ T &\to \uparrow T_1 & \{ &T.\text{type} = \text{pointer}(T_1.\text{type}); \quad T.\text{width} = 4; \} \end{aligned}$$

Worked Example · Symbol Table Entry Generation

Suppose the source program contains declarations: 

x : integer;
y : real;
A : array[10] of integer;
p : ^real;
The SDD calculates the following symbol table offsets sequentially:
  • x: Type = integer, width = $4$, offset assigned = $\mathbf{0}$. $\text{offset} \leftarrow 0 + 4 = 4$.
  • y: Type = real, width = $8$, offset assigned = $\mathbf{4}$. $\text{offset} \leftarrow 4 + 8 = 12$.
  • A: Type = $\text{array}(10, \text{integer})$, width = $10 \times 4 = 40$, offset assigned = $\mathbf{12}$. $\text{offset} \leftarrow 12 + 40 = 52$.
  • p: Type = $\text{pointer}(\text{real})$, width = $4$, offset assigned = $\mathbf{52}$. $\text{offset} \leftarrow 52 + 4 = 56$.
Total memory allocated in this activation frame = 56 bytes.

8. Type Checking Rules · Coercion vs Conversion

A type system is a formal collection of rules for assigning type expressions to the various parts of a program. A type checker validates expressions and statements using type synthesis and type inference rules.

Type Checking Rules for Expressions and Functions Binary Arithmetic Operator ($E \to E_1 + E_2$):
$$E.\text{type} = \begin{cases} \text{integer} & \text{if } E_1.\text{type} == \text{integer} \text{ and } E_2.\text{type} == \text{integer} \\ \text{real} & \text{if } E_1.\text{type} == \text{real} \text{ and } E_2.\text{type} == \text{real} \\ \text{type\_error} & \text{otherwise} \end{cases}$$
Function Invocations ($E \to E_1(E_2)$):
$$E.\text{type} = \begin{cases} \beta & \text{if } E_1.\text{type} == (\alpha \to \beta) \text{ and } E_2.\text{type} == \alpha \\ \text{type\_error} & \text{otherwise} \end{cases}$$

Widening vs Narrowing Conversions

Widening conversions preserve numeric information without loss of precision (e.g. char → int → float → double). Compilers safely perform widening conversions automatically via coercion.

Narrowing conversions can lose information or overflow (e.g. double → int, truncating the fractional part). Strict compilers forbid implicit narrowing coercion and require explicit type casting.

Check yourself

Retrieval practice

1. In Row-Major order storage of a 2D array $A[low_1 \dots high_1, low_2 \dots high_2]$, the offset of $A[i, j]$ depends on which dimension count?

In Row-Major order, each full row skipped contains $n_2$ elements (the column dimension size). Hence, row index is multiplied by $n_2$.

2. In short-circuit evaluation of `if (a < b && c < d)`, what happens if `a < b` evaluates to false?

In boolean AND (`&&`), if the first operand is false, the compound condition is guaranteed to be false. Evaluating the second condition is redundant and skipped.

3. Why does the compiler isolate the term $(Base - low \times w)$ as an invariant constant $C$ during array address calculation?

Base, lower bound, and element width are all fixed at compile-time. Folding them into a single constant $C$ eliminates runtime arithmetic.

4. Which instruction pattern correctly translates the while loop `while (E) S`?

A while loop evaluates condition E at loop entry. If false, it jumps past the body to L_exit. At the end of body S, it loops unconditionally back to L_start.

Recall without looking

State the Row-Major address formula for $A[i, j]$.

$\text{Address}(A[i, j]) = Base + ((i - low_1) \times n_2 + (j - low_2)) \times w$, where $n_2 = high_2 - low_2 + 1$ is the number of columns.

How does short-circuit evaluation of $B_1 \textbf{ or } B_2$ translate into TAC?

`if B₁ goto L_true`
`if B₂ goto L_true`
`goto L_false`
If $B_1$ is true, execution branches immediately to `L_true` without evaluating $B_2$.
