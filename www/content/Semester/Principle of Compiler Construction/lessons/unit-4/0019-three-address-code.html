1. Role of Intermediate Code in Compiler Architecture

Intermediate Code Generation (ICG) sits precisely between the syntax/semantic analysis frontend and the target-dependent code generation backend:

The $M \times N$ to $M + N$ Engineering Advantage Source ($M$ Languages) → Frontend → Intermediate Representation (TAC) → Backend → Target ($N$ Machines)

By translating source programs into a machine-independent intermediate form, a compiler for $M$ source languages and $N$ target architectures requires only $M$ frontends + $N$ backends (instead of $M \times N$ individual translators).

2. Formal Definition of Three-Address Code (TAC)

Three-Address Code is an intermediate language where every statement contains at most three memory addresses: at most two source operands and at most one result destination.

General TAC Format $$\textbf{x = y op z}$$ where x is the destination, op is a binary operator, and y, z are operands (variables, constants, or compiler-generated temporaries).

1. Quadruples

A quadruple record contains four fields: (op, arg1, arg2, result).

  • The result field stores an explicit temporary variable name (e.g. t1) or user identifier.
  • For unary operations, arg2 is left blank. For unconditional jumps, op is goto and the target label is placed in result.

2. Triples

A triple record contains only three fields: (op, arg1, arg2).

  • Temporaries are eliminated completely: the result of an operation is identified implicitly by its record index position: (0), (1), (2), ....
  • Whenever a subsequent instruction uses the result of a prior triple, it references the index of that triple in parentheses.

3. Indirect Triples

Indirect triples store the triples in a sequential array, and maintain a separate array of pointers that defines the execution sequence.

  • During compiler optimization (such as instruction scheduling, code motion, or dead-code elimination), only the pointer array is modified.
  • The triple records themselves remain fixed in place, completely avoiding the need to search and rewrite instruction index references!

Check yourself

Retrieval practice

1. Why does instruction reordering cause severe problems in the Triples representation?

In triples, `(1)` means the result of the instruction at index 1. If instructions are moved, deleted, or reordered, all index references throughout the entire code block break.

2. How do Indirect Triples resolve the reordering bottleneck while preserving the compact size of triples?

The statement triples stay at fixed memory addresses. Reordering execution involves swapping pointers in the auxiliary pointer table.

3. In a Quadruple record for the unconditional jump `goto L`, which fields are populated?

In quadruples, jump target labels are conventionally placed in the `result` field, with operands left blank.

4. Three-Address Code statements contain at most how many memory addresses?

TAC instructions have at most three addresses. Some instructions (like copies `x = y` or jumps `goto L`) have fewer.

Recall without looking

Contrast Quadruples and Triples in terms of temporaries.

Quadruples explicitly store temporary variables ($t_1, t_2$) in a 4th `result` field, requiring symbol table space. Triples omit the result field and designate temporary values implicitly by the index of the triple that computed them.

What are the eight standard instruction forms of Three-Address Code?

1. Binary assignment ($x = y\ op\ z$)
2. Unary assignment ($x = op\ y$)
3. Copy ($x = y$)
4. Unconditional jump ($goto\ L$)
5. Conditional jump ($if\ x\ relop\ y\ goto\ L$)
6. Indexed array access ($x = y[i]$, $x[i] = y$)
7. Address/Pointer operations ($x = \&y$, $x = *y$, $*x = y$)
8. Procedure calls ($param\ x$, $call\ p, n$, $return\ y$).
