1. The Forward Jump Dilemma in Single-Pass Compilers

In a single-pass compiler, syntax analysis, intermediate code generation, and target code emission occur concurrently in one pass over the source program.

When translating conditional statements such as:

if (a < b) x = 1; else x = 0;

The compiler generates a conditional jump on a < b to reach the else branch. However, at the moment a < b is parsed, the instruction address of the else block has not been generated yet! It is a forward reference.

The Core Problem of Forward References 100: if a < b goto ___   (What label goes here? Target instruction address is unknown!)
101: goto ___        (Target instruction address is unknown!)

2. The Backpatching Solution

Backpatching solves this dilemma by:

  1. Emitting jump instructions with their target address fields left blank (unspecified).
  2. Maintaining lists of instruction indices that jump to the same destination.
  3. Passing these lists up the parse tree as synthesized attributes.
  4. When the correct target instruction index is finally determined, backpatching the target address into every instruction on the list in a single step!
The Backpatching Lifecycle
1. Emit Incomplete Quad
100: if a < b goto _
Leaves target slot blank; index added to truelist = {100}
2. Merge Lists via Syntax Tree
B.truelist = merge(B₁.truelist, B₂.truelist)
Combines pending jump targets across operators
3. Backpatch when Target Resolved
backpatch({100}, 104) ⇒ 100: if a < b goto 104
Fills target label into all linked instructions simultaneously

3. The Three Core Primitive Functions

Function SignatureFormal OperationImplementation Mechanism
makelist(i) Creates a new list containing only instruction index $i$. Allocates a single node with value $i$ and returns a pointer to the list.
merge(p1, p2) Concatenates the two lists pointed to by $p_1$ and $p_2$. Returns a pointer to the concatenated list containing all indices of $p_1$ and $p_2$.
backpatch(p, L) Fills target address $L$ into all instructions on list $p$. Traverses list $p$; for each index $i$ on the list, updates instruction $i$ so its target slot holds $L$.

The compiler maintains a global integer counter nextquad that stores the index of the next instruction to be emitted.

4. Synthesized Attributes for Boolean Expressions

Every boolean expression $B$ maintains two synthesized list attributes:

  • B.truelist: List of instruction indices whose target field must be backpatched with the label to jump to when $B$ is true.
  • B.falselist: List of instruction indices whose target field must be backpatched with the label to jump to when $B$ is false.

Marker Non-Terminal $M$

To capture the instruction address where an operand begins, we introduce a marker non-terminal $M \to \epsilon$ with semantic rule:

M → ε   { M.quad = nextquad; }

SDD Translation Rules for Boolean Expressions

5. Backpatching Control Flow Statements

Every statement $S$ maintains attribute S.nextlist: the list of instruction indices that jump to the instruction immediately following $S$.

To bypass the else body, we introduce marker $N \to \epsilon$:

N → ε   { N.nextlist = makelist(nextquad); emit("goto _"); }
Grammar RuleSemantic Actions
$S \to \textbf{if } B\ \textbf{then } M\ S_1$ backpatch(B.truelist, M.quad);
S.nextlist = merge(B.falselist, S1.nextlist);
$S \to \textbf{if } B\ \textbf{then } M_1\ S_1\ N\ \textbf{else } M_2\ S_2$ backpatch(B.truelist, M1.quad);
backpatch(B.falselist, M2.quad);
S.nextlist = merge(S1.nextlist, merge(N.nextlist, S2.nextlist));
$S \to \textbf{while } M_1\ B\ \textbf{do } M_2\ S_1$ backpatch(S1.nextlist, M1.quad);
backpatch(B.truelist, M2.quad);
S.nextlist = B.falselist;
emit("goto " M1.quad);
$S \to S_1\ ;\ M\ S_2$ backpatch(S1.nextlist, M.quad);
S.nextlist = S2.nextlist;

6. Full Worked Numerical Exam Problem

Complete Worked Problem: Backpatching Boolean Expression

Translate the expression into Three-Address Code using backpatching, beginning at nextquad = 100:

if (a < b || c < d) and e < f then x = 1 else x = 0

Step 1: Translate subexpression $(a < b \text{ or } c < d)$:

  • For $a < b$: 
    100: if a < b goto _   // truelist = {100}
101: goto _             // falselist = {101}
  • Marker $M_1$: $M_1.quad = 102$. Backpatch $(a < b)\text{.falselist} \longrightarrow \mathbf{102}$.
    Instruction 101 becomes: 101: goto 102.
  • For $c < d$: 
    102: if c < d goto _   // truelist = {102}
103: goto _             // falselist = {103}
  • Result of OR ($B_1$):
    • $B_1.truelist = merge(\{100\}, \{102\}) = \mathbf{\{100, 102\}}$.
    • $B_1.falselist = \mathbf{\{103\}}$.

Step 2: Translate AND with $e < f$:

  • Marker $M_2$: $M_2.quad = 104$. Backpatch $B_1.truelist \longrightarrow \mathbf{104}$.
    Instructions 100 and 102 become: 100: if a < b goto 104, 102: if c < d goto 104.
  • For $e < f$: 
    104: if e < f goto _   // truelist = {104}
105: goto _             // falselist = {105}
  • Compound boolean expression ($B$):
    • $B.truelist = \mathbf{\{104\}}$.
    • $B.falselist = merge(B_1.falselist, \{105\}) = merge(\{103\}, \{105\}) = \mathbf{\{103, 105\}}$.

Step 3: Translate Statements and Backpatch Branches:

  • Marker $M_3$: $M_3.quad = 106$. Backpatch $B.truelist \longrightarrow \mathbf{106}$.
    Instruction 104 becomes: 104: if e < f goto 106.
  • Then body ($x = 1$): 
    106: x = 1
  • Marker $N$ emits skip jump: 
    107: goto _             // N.nextlist = {107}
  • Marker $M_4$: $M_4.quad = 108$. Backpatch $B.falselist = \{103, 105\} \longrightarrow \mathbf{108}$.
    Instructions 103 and 105 become: 103: goto 108, 105: goto 108.
  • Else body ($x = 0$): 
    108: x = 0
  • Nextquad is now 109. Backpatch $N.nextlist = \{107\} \longrightarrow \mathbf{109}$.
    Instruction 107 becomes: 107: goto 109.

Check yourself

Retrieval practice

1. What specific problem does backpatching eliminate in a single-pass compiler?

In single-pass compilation, when a branch is emitted, its destination address is often forward in the source code. Backpatching leaves the slot blank and fills it when the destination is generated.

2. For the expression $B_1 \textbf{ and } M\ B_2$, what does `backpatch(B1.truelist, M.quad)` do?

In a boolean AND, if the first operand $B_1$ is true, the overall result depends on $B_2$. Hence, jumps on $B_1$ true are directed to $M.quad$, the start of $B_2$.

3. The function `merge(p1, p2)` returns:

`merge(p1, p2)` takes two pointers to lists of instruction indices and joins them into a single combined list.

4. In the translation rule for `while M1 B do M2 S1`, what instruction is backpatched with `M1.quad`?

When body $S_1$ finishes execution, control must loop back to test the condition at $M_1.quad$. Hence, $backpatch(S_1.nextlist, M_1.quad)$.

Recall without looking

Name the three primitive operations of backpatching and their purposes.

`makelist(i)`: Creates a new list containing index $i$.
`merge(p1, p2)`: Concatenates lists $p_1$ and $p_2$.
`backpatch(p, L)`: Fills label/address $L$ into the target slot of each instruction indexed on list $p$.

What are the `truelist` and `falselist` of $B_1 \textbf{ or } M\ B_2$?

$B.truelist = merge(B_1.truelist, B_2.truelist)$ (true if either is true).
$B.falselist = B_2.falselist$ ($B_1$'s false jumps are backpatched to $M.quad$; false only if $B_2$ is also false).
