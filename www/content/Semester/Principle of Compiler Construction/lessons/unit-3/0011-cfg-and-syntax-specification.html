1. Context-Free Grammars (CFG)

Formal Definition of a CFG A Context-Free Grammar $G$ is formally defined as a 4-tuple:

G = (V, T, P, S)

• V (or N): A finite set of non-terminal characters (variables) that represent syntactic categories.
• T (or Σ): A finite set of terminals (tokens) emitted by the lexical analyser.
• P: A finite set of production rules of the form $A \to \alpha$, where $A \in V$ and $\alpha \in (V \cup T)^*$.
• S: The designated start symbol ($S \in V$).

Standard Arithmetic Expression Grammar

Unambiguous Precedence Grammar E → E + T | T       (Addition: Lowest precedence, Left-associative)
T → T * F | F       (Multiplication: Higher precedence, Left-associative)
F → ( E ) | id      (Primary: Highest precedence — brackets and identifiers)

2. Derivations and Parse Trees

A derivation is a sequence of production rule applications replacing non-terminals with right-hand sides, starting from $S$ and terminating in a sentence of terminals:

  • Leftmost Derivation (LMD): The leftmost non-terminal is replaced at every single step ($S \Rightarrow_{lm}^* w$).
  • Rightmost Derivation (RMD): The rightmost non-terminal is replaced at every step ($S \Rightarrow_{rm}^* w$). A rightmost derivation in reverse is called a canonical parse.

3. Grammar Ambiguity

Definition of Ambiguity A context-free grammar $G$ is ambiguous if there exists at least one string $w \in L(G)$ for which there are two or more distinct parse trees (or equivalently, two distinct leftmost derivations).
Visual Proof of Ambiguity: Dual Parse Trees for id + id * id

Under ambiguous grammar: E → E + E | E * E | id

Parse Tree 1 · Left-Heavy (+ first)
        E
      / | \
    E   *  E
  / | \     |
E   +  E    id
|      |
id     id

Evaluates: (id + id) * id — Violates standard arithmetic precedence!

Parse Tree 2 · Right-Heavy (* first)
        E
      / | \
    E   +  E
    |     / | \
   id   E   *  E
        |      |
       id     id

Evaluates: id + (id * id) — Standard arithmetic precedence.

Conclusion: The existence of two valid parse trees proves that E → E + E | E * E | id is ambiguous.

The Classic "Dangling-Else" Ambiguity

Consider the conditional statement grammar:

stmt → if expr then stmt | if expr then stmt else stmt | other

The nested statement: if E1 then if E2 then S1 else S2 is ambiguous because the else can bind to either the inner if or the outer if. Compilers resolve this using the rule: match each else with the closest preceding unmatched then.

4. Left Recursion Elimination

A production of the form $A \to A\alpha$ is directly left-recursive. Top-down parsers (recursive descent and LL(1)) enter an infinite loop when encountering left recursion because they repeatedly try to expand $A$ without consuming any input tokens.

Mathematical Formula: Immediate Left Recursion Elimination
Left-Recursive Form
A → Aα1 | Aα2 | … | β1 | β2 | …
(where no β begins with A)
⇒
Equivalent Right-Recursive Form
A → β1A' | β2A' | …
A' → α1A' | α2A' | … | ε
(Completely safe for top-down parsing)
Worked Problem · Eliminate Left Recursion from Arithmetic Grammar

Original Grammar:

E → E + T | T
T → T * F | F
F → ( E ) | id

Applying formula to E: $A = E, \alpha = + T, \beta = T$

E → T E'
E' → + T E' | ε

Applying formula to T: $A = T, \alpha = * F, \beta = F$

T → F T'
T' → * F T' | ε

Production for F has no left recursion:

F → ( E ) | id

Final transformed grammar is ready for LL(1) parsing!

Algorithm for General (Indirect) Left Recursion Elimination

Systematic Algorithm for Indirect Cycles ($A \to B \to \dots \to A$) 1. Arrange non-terminals in some arbitrary order: $A_1, A_2, \dots, A_n$.
2. for $i = 1$ to $n$ do:
    for $j = 1$ to $i-1$ do:
        replace each production $A_i \to A_j\gamma$ with $A_i \to \delta_1\gamma \mid \delta_2\gamma \mid \dots$, where $A_j \to \delta_1 \mid \delta_2 \mid \dots$
    eliminate immediate left recursion among the $A_i$ productions using the standard formula.

5. Left Factoring

When two or more production alternatives for a non-terminal share a common prefix, a top-down parser cannot determine which alternative to select based on a single lookahead token. Left factoring defers the decision until enough of the input has been observed.

Left Factoring Transformation Rule Given production: $A \to \alpha\beta_1 \mid \alpha\beta_2 \mid \dots \mid \gamma$

Factor out common prefix $\alpha$:
A → αA' | γ
A' → β1 | β2 | …
Worked Example · Left Factoring Conditional Statements

S → i E t S | i E t S e S | a

Both first alternatives share common prefix: $\alpha = \text{iEtS}$

Transformed Grammar:

S → i E t S S' | a
S' → e S | ε

Check Yourself

1. A context-free grammar is classified as ambiguous if:

Ambiguity implies that a sentence possesses multiple grammatical interpretations, creating non-deterministic parsing paths.

2. Left recursion must be eliminated because:

Top-down parsers expand non-terminals from left to right; a rule A → Aα triggers unbounded recursive calls without advancing the input lookahead pointer.

3. The left-factored form of A → abB | abC is:

The common prefix 'ab' is factored out, delaying the decision between B and C until after 'ab' is consumed.

Recall Without Looking

Define the 4-tuple of a Context-Free Grammar.

G = (V, T, P, S) where V is non-terminals (variables), T is terminals (tokens), P is production rules (A → α where A ∈ V and α ∈ (V ∪ T)*), and S is the start symbol (S ∈ V).

How do you prove that a grammar is ambiguous on an exam?

Select a specific input string generated by the grammar and draw two distinctly structured parse trees (or write two different leftmost derivations) for that exact string.

State the formula to eliminate immediate left recursion.

For A → Aα | β (where β does not begin with A): replace with A → βA' and A' → αA' | ε.

What is left factoring and why is it needed?

When productions share a common prefix (A → αβ1 | αβ2), it is factored into A → αA' and A' → β1 | β2. It is needed so predictive parsers can choose the correct rule based on one lookahead symbol.
