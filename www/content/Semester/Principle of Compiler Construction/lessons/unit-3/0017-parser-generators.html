1. What is Yacc?

Yacc (Yet Another Compiler-Compiler), originally developed by Stephen C. Johnson at Bell Labs, is an automated parser generator. GNU Bison is its modern, backward-compatible free-software equivalent.

Given a Context-Free Grammar augmented with semantic actions, Yacc automatically produces an optimized, table-driven LALR(1) parser in C (implementing the yyparse() function).

2. The Lex–Yacc Cooperative Architecture

Lex and Yacc work together in a producer-consumer relationship:

  • Yacc (Consumer / Master): Drives the entire parsing process through yyparse(). Whenever it needs the next token to decide its LR action, it calls yylex().
  • Lex (Producer / Slave): Scans the input character stream inside yylex(), matches lexemes, assigns semantic values to the global variable yylval, and returns an integer token identifier to Yacc.
  • y.tab.h (The Bridge): Generated by yacc -d. It defines numeric #define constants for each declared %token so both Lex and Yacc share identical token codes.

3. Three-Section Structure of a Yacc Specification

Every Yacc file (.y) follows the standard Unix three-section format delimited by %%:

%{
  /* ----------------------------------------------------
     SECTION 1: DECLARATIONS (C Headers + Yacc Directives)
     C headers, prototypes, and global variables
     ---------------------------------------------------- */
  #include <stdio.h>
  #include <stdlib.h>
  int yylex(void);
  void yyerror(const char *s);
%}

/* Yacc token & precedence declarations */
%token NUMBER
%left '+' '-'
%left '*' '/'
%right UMINUS

%%

/* ----------------------------------------------------
   SECTION 2: GRAMMAR RULES & SEMANTIC ACTIONS
   Context-free grammar rules with C action blocks
   ---------------------------------------------------- */
expr : expr '+' expr           { $$ = $1 + $3; }
     | expr '-' expr           { $$ = $1 - $3; }
     | expr '*' expr           { $$ = $1 * $3; }
     | expr '/' expr           { 
                                 if ($3 == 0) yyerror("divide by zero");
                                 else $$ = $1 / $3; 
                               }
     | '-' expr %prec UMINUS   { $$ = -$2; }
     | '(' expr ')'            { $$ = $2; }
     | NUMBER                  { $$ = $1; }
     ;

%%

/* ----------------------------------------------------
   SECTION 3: SUPPORTING C CODE
   main(), yyerror(), helper routines
   ---------------------------------------------------- */
int main(void) {
    printf("Enter expression: ");
    return yyparse();
}

void yyerror(const char *s) {
    fprintf(stderr, "Parse Error: %s\n", s);
}

4. Attribute Values and Semantic Actions

Yacc associates semantic attribute values with each symbol on the parsing stack using the dollar notation:

Pseudo-VariableSyntactic MeaningStack Position
$$Semantic attribute value of the Left-Hand Side (LHS) non-terminalStack top after reduction
$1Attribute value of the 1st symbol on the RHSStack offset $-|\beta| + 1$
$2Attribute value of the 2nd symbol on the RHSStack offset $-|\beta| + 2$
$nAttribute value of the $n$-th symbol on the RHSStack offset $-|\beta| + n$

By default, $$ and $i are of type int. For composite compiler data structures (AST nodes, symbol table pointers), the %union directive defines the multi-type union stored in YYSTYPE.

5. Conflict Resolution Directives in Yacc

When an ambiguous grammar produces conflicts in the LALR(1) parsing table, Yacc applies two standard mechanisms:

Mechanism 1: Built-in Default Rules

  • Shift/Reduce Conflict: Yacc defaults to SHIFT. This resolves the classic dangling-else ambiguity by pairing an else with the innermost pending if.
  • Reduce/Reduce Conflict: Yacc defaults to REDUCING by the rule that appears earlier in the specification file. (Note: Reduce/Reduce conflicts almost always signal a grammar defect and should be eliminated).

Mechanism 2: Precedence and Associativity Declarations

Precedence is declared in Section 1 using directives listed in order of increasing precedence from top to bottom:

DirectiveAssociativityAction on AmbiguityTypical Use Case
%leftLeft-associativeResolves conflict by REDUCEBinary +, -, *, /
%rightRight-associativeResolves conflict by SHIFTAssignment =, Exponentiation ^
%nonassocNon-associativeTriggers a SYNTAX ERROR if chainedRelational ops: a < b < c is illegal
%precContextual overrideGives a specific rule the precedence of named tokenUnary minus: - expr %prec UMINUS
How Yacc Evaluates Precedence at Runtime

Suppose the stack holds expr + expr and the incoming terminal is *:

  • The production expr → expr + expr has the precedence of its operator +.
  • The incoming lookahead token is *, which has higher precedence than +.
  • Since incoming token precedence > rule precedence, Yacc decides to SHIFT *.
  • Conversely, if stack holds expr * expr and input sees +, the rule precedence (*) exceeds token precedence (+), so Yacc REDUCES immediately.

6. Error Recovery in Yacc

When a syntax error occurs, yyparse() calls yyerror("syntax error"). Without recovery logic, parsing halts abruptly.

Yacc provides a designated error token error for graceful recovery:

stmt : expr ';'
     | error ';'    { yyerrok; printf("Recovered from statement error\n"); }
     ;
  • When an error occurs, Yacc pops states from the stack until finding a state that can shift the error token.
  • It shifts error and discards incoming input tokens until a synchronizing token (here, semicolon ;) is encountered.
  • The macro yyerrok resets the parser state, suppressing further error reports until normal parsing resumes.

Check yourself

Retrieval practice

1. When Yacc encounters a Shift/Reduce conflict without explicit precedence declarations, how does it resolve the conflict by default?

Yacc's default for shift/reduce conflicts is always to shift. This naturally binds the dangling 'else' to the closest inner 'if'.

2. In a Yacc grammar, which directive overrides the natural precedence of a production with that of another token?

The `%prec` tag (e.g. `- expr %prec UMINUS`) assigns the precedence of the specified token (UMINUS) to that individual rule instance.

3. Which header file is generated by Yacc when invoked with the `-d` flag to share token numbers with Lex?

`yacc -d` generates `y.tab.c` and `y.tab.h`. The header contains integer macro definitions for all declared `%token`s so that `yylex()` can return them.

4. In the semantic action `{ $$ = $1 + $3; }`, what does `$$` represent?

`$$` designates the synthesized semantic attribute of the production's left-hand side non-terminal symbol.

Recall without looking

Name the three sections of a Yacc specification file.

Section 1: Declarations (C headers `%{ %}`, `%token`, `%left`, `%right`).
Section 2: Grammar rules and semantic actions (`A : B C { $$ = ... };`).
Section 3: Supporting C code (`main()`, `yyerror()`). Delimited by `%%`.

How does Yacc use operator precedence to decide between Shift and Reduce?

If the precedence of the incoming lookahead terminal is higher than the precedence of the rule currently on stack, Yacc shifts. If rule precedence is higher, it reduces. If equal, `%left` dictates reduce and `%right` dictates shift.
