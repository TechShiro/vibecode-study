1. The Non-Recursive Table-Driven Parser

An LL(1) parser is a non-recursive, table-driven top-down parser. The name signifies:

  • L (First): Scans input from Left to right.
  • L (Second): Produces a Leftmost derivation.
  • (1): Uses strictly 1 lookahead token at each step.

2. Formal Definition of FIRST and FOLLOW Sets

FIRST(α)

Definition and Construction Rules FIRST(α) is the set of terminals that can appear as the first symbol of a string derived from α. If $\alpha \Rightarrow^* \epsilon$, then $\epsilon \in \text{FIRST}(\alpha)$.

Rule 1: If $X$ is a terminal, $\text{FIRST}(X) = \{X\}$.
Rule 2: If $X \to \epsilon$ is a production, then add $\epsilon$ to $\text{FIRST}(X)$.
Rule 3: If $X \to Y_1 Y_2 \dots Y_k$ is a production:
  • Add all non-$\epsilon$ symbols of $\text{FIRST}(Y_1)$ to $\text{FIRST}(X)$.
  • If $\epsilon \in \text{FIRST}(Y_1)$, add $\text{FIRST}(Y_2) \setminus \{\epsilon\}$, and so on until $Y_i$ does not derive $\epsilon$.
  • If all $Y_1, \dots, Y_k$ derive $\epsilon$, add $\epsilon$ to $\text{FIRST}(X)$.

FOLLOW(A)

Definition and Construction Rules FOLLOW(A) is the set of terminals that can appear immediately to the right of non-terminal $A$ in some sentential form ($S \Rightarrow^* \alpha A a \beta$).

Rule 1: Put $ (input end-marker) into $\text{FOLLOW}(S)$, where $S$ is the start symbol.
Rule 2: If there is a production $A \to \alpha B \beta$, then everything in $\text{FIRST}(\beta)$ (except $\epsilon$) is in $\text{FOLLOW}(B)$.
Rule 3: If there is a production $A \to \alpha B$, OR a production $A \to \alpha B \beta$ where $\epsilon \in \text{FIRST}(\beta)$, then everything in $\text{FOLLOW}(A)$ is in $\text{FOLLOW}(B)$.
Critical Rule

$\epsilon$ is NEVER an element of any FOLLOW set. FOLLOW sets contain only terminals and the end-marker symbol $.

4. Constructing the LL(1) Parsing Table

Table Construction Algorithm For each production $A \to \alpha$ of the grammar:
1. For each terminal $a \in \text{FIRST}(\alpha)$, add $A \to \alpha$ to table entry $M[A, a]$.
2. If $\epsilon \in \text{FIRST}(\alpha)$, then for each terminal (or $) $b \in \text{FOLLOW}(A)$, add $A \to \alpha$ to $M[A, b]$.

5. The Formal LL(1) Grammar Conditions

A context-free grammar $G$ is LL(1) if and only if for every pair of distinct productions $A \to \alpha \mid \beta$:

  1. Disjoint FIRST sets: $\text{FIRST}(\alpha) \cap \text{FIRST}(\beta) = \emptyset$.
  2. At most one derives $\epsilon$: At most one of $\alpha$ or $\beta$ can derive the empty string $\epsilon$.
  3. Disjoint FOLLOW and FIRST: If $\beta \Rightarrow^* \epsilon$, then $\text{FIRST}(\alpha) \cap \text{FOLLOW}(A) = \emptyset$.

7. Error Recovery in Predictive Parsing (Panic Mode & SYNCH Tokens)

In a non-recursive table-driven predictive parser, a syntax error is detected under two exact circumstances:

  1. The non-terminal on top of the stack is $A$, the current input token is $a$, and the parsing table entry $M[A, a]$ is blank (empty).
  2. The symbol on top of the stack is a terminal, but it does not match the current input token $a$.
Without error recovery, the parser would halt immediately at the first syntax error, failing to inspect the rest of the source file. High-quality compilers implement Panic-Mode Recovery using synchronizing tokens (synch).

How SYNCH Tokens are Placed in the LL(1) Table (Mam's SA-1.pdf)

To enable panic-mode recovery without altering grammar logic, the compiler designer fills blank cells with synch markers using the following formal heuristics:

  • Heuristic 1 (The Standard FOLLOW Rule): For every non-terminal $A$, add a synch marker in table entry $M[A, b]$ for all input terminals $b \in \text{FOLLOW}(A)$. If the parser sees an unexpected token that can legally follow $A$, it pops $A$ off the stack, effectively assuming $A$ successfully parsed.
  • Heuristic 2 (Blank cells / Skip Input): If entry $M[A, a]$ is completely blank (neither a production nor synch), the current token $a$ is completely unexpected. The parser discards (skips) input token $a$ and reads the next token from the input buffer.
  • Heuristic 3 (Terminal Mismatch): If a terminal on top of the stack fails to match the current input terminal, pop the terminal off the stack and emit an error message indicating that the expected terminal was inserted.

Recall Without Looking

State the 3 rules for computing FIRST sets.

1. If X is a terminal, FIRST(X) = {X}. 2. If X → ε, add ε to FIRST(X). 3. If X → Y1 Y2 ... Yk, add FIRST(Y1)−{ε}; if ε ∈ FIRST(Y1), add FIRST(Y2)−{ε}, etc. If all derive ε, add ε.

State the 3 rules for computing FOLLOW sets.

1. Put $ in FOLLOW(S). 2. If A → αBβ, add FIRST(β)−{ε} to FOLLOW(B). 3. If A → αB, or A → αBβ where ε ∈ FIRST(β), add FOLLOW(A) to FOLLOW(B). Note: ε is NEVER in a FOLLOW set.

How is an LL(1) parsing table constructed?

For each A → α: 1. For each terminal a in FIRST(α), add A → α to M[A, a]. 2. If ε in FIRST(α), for each b in FOLLOW(A), add A → α to M[A, b]. If any cell has >1 entry, the grammar is not LL(1).
