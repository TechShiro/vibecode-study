1. Top-Down Parsing Principles

Top-down parsing attempts to construct the parse tree starting at the root (start symbol $S$) and working down toward the leaves (input terminal string $w$). This corresponds directly to searching for a leftmost derivation of the input string:

S = γ0 ⇒lm γ1 ⇒lm γ2 ⇒lm … ⇒lm w

2. Recursive Descent Architecture

A Recursive Descent Parser is a top-down parser composed of a set of mutually recursive procedures — exactly one procedure for each non-terminal in the grammar.

E → T E' 
void E() {
    T();
    E_prime();
}
E' → + T E' | ε 
void E_prime() {
    if (lookahead == '+') {
        match('+');
        T();
        E_prime();
    }
    /* else ε: do nothing and return */
}
T → F T' 
void T() {
    F();
    T_prime();
}
T' → * F T' | ε 
void T_prime() {
    if (lookahead == '*') {
        match('*');
        F();
        T_prime();
    }
    /* else ε: do nothing */
}
F → ( E ) | id 
void F() {
    if (lookahead == '(') {
        match('(');
        E();
        match(')');
    } else if (lookahead == ID) {
        match(ID);
    } else {
        error("Syntax error in factor");
    }
}

4. The Problem of Backtracking

Definition of Backtracking Backtracking occurs when a non-terminal procedure has multiple production alternatives and makes a tentative choice. If that choice fails downstream, the parser must undo parse tree construction, rewind the input pointer, and try the next alternative.
Visual Trace: Backtracking During Top-Down Parsing

Grammar: S → cAd, A → ab | a · Input string: cad

Attempt 1 · Try A → ab
  1. Procedure S() matches terminal c. (Input pointer at 'a').
  2. Procedure A() chooses first production: A → ab.
  3. Matches a. Next symbol expected is b.
  4. Input sees d ≠ b → MISMATCH / FAILURE!
← BACKTRACK: Rewind input pointer back to 'a'
Attempt 2 · Try A → a
  1. Procedure A() chooses second production: A → a.
  2. Matches a. Procedure A() succeeds and returns.
  3. Control returns to S(), which expects d.
  4. Matches d → SUCCESSFUL PARSE!
Parse accepted without further rewind
Why Production Compilers Disallow Backtracking

General backtracking parsers suffer from three fatal drawbacks:

  • Exponential Time Complexity: In the worst case, backtracking takes $O(k^n)$ time where $n$ is sentence length.
  • Buffer Management Overhead: Discarded characters must remain buffered in memory so pointers can rewind arbitrarily far.
  • Semantic Side Effects: If actions have already altered the symbol table or output files, rolling them back is prohibitively difficult.

The Solution: By transforming grammars to be LL(1) (Predictive), the parser can predict the exact correct production using strictly one lookahead token — eliminating backtracking completely!

Recall Without Looking

What is recursive descent parsing?

A top-down parsing technique where each non-terminal in the grammar is implemented as a distinct recursive procedure. Procedures call each other to match productions against input tokens.

What is the purpose of the match() function?

It checks whether the current lookahead token matches the expected terminal symbol. If it matches, it advances the lookahead pointer via getNextToken(); otherwise, it triggers a syntax error.

Why is backtracking undesirable in compiler design?

It leads to worst-case exponential parsing time, requires large lookahead buffers to rewind pointers, and makes rolling back symbol table side effects extremely complex.
