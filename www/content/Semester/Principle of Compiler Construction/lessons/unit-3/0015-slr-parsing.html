1. LR(0) Items and Categories

An LR(0) item of a grammar $G$ is a production of $G$ with a distinguished dot symbol (•) placed at some position on the right-hand side.

Semantics of the Dot Position A → α • β

Indicates that substring α has already been seen (shifted onto the stack), and substring β is expected next in the input.

For a production with $n$ symbols on its right-hand side ($A \to X_1 X_2 \dots X_n$), there are exactly $n + 1$ distinct LR(0) items. For an $\epsilon$-production $A \to \epsilon$, there is only 1 item: $[A \to \cdot]$.

Item ClassificationDot PositionExampleParser Meaning
Initial ItemDot at extreme leftA → • X YParsing of $A$ has not started yet; expecting to see symbols deriving $X$.
Intermediate Item (Shift Item)Dot between symbolsA → X • YPrefix $X$ has been recognized; expecting symbols deriving $Y$.
Complete Item (Reduce Item)Dot at extreme rightA → X Y •Entire RHS has been matched on the stack; ready to reduce to non-terminal $A$.

Kernel vs Non-Kernel Items

  • Kernel Items: The initial item $S' \to \cdot S$ and all items whose dots are NOT at the beginning of the RHS. These define the "core" identity of a state.
  • Non-Kernel Items: All items whose dots are at the extreme beginning of the RHS (except $S' \to \cdot S$), generated dynamically during closure calculation.

2. The Augmented Grammar

If grammar $G$ has start symbol $S$, its augmented grammar $G'$ introduces a new start symbol $S'$ and the production:

Augmented Production S′ → S

Why is this necessary? It ensures that the parser accepts if and only if it reduces by $S' \to S$. When the item $[S' \to S \cdot]$ is reached with lookahead $\$$, the parser halts and announces success without ambiguity.

3. Canonical Collection Operations: CLOSURE and GOTO

The parser tracks viable prefixes using a Deterministic Finite Automaton (DFA) whose states are sets of LR(0) items. Two fundamental functions construct this DFA:

Algorithm: CLOSURE(I) Input: A set of items $I$.
Output: The closure of $I$.
1. Initialize $CLOSURE(I) = I$.
2. If $[A \to \alpha \cdot B \beta] \in CLOSURE(I)$ and $B \to \gamma$ is a production, then add $[B \to \cdot \gamma]$ to $CLOSURE(I)$, provided it is not already present.
3. Repeat step 2 until no new items can be added.
Algorithm: GOTO(I, X) Input: A set of items $I$ and a grammar symbol $X$ (terminal or non-terminal).
Output: The set of items that the parser transitions to after recognizing $X$.
$$GOTO(I, X) = CLOSURE(\{[A \to \alpha X \cdot \beta] \mid [A \to \alpha \cdot X \beta] \in I\})$$ Simply advance the dot past symbol $X$ for all matching items in $I$, then compute the closure of that result.

Step 3: Compute FIRST and FOLLOW Sets

FIRST & FOLLOW Sets Calculation
  • $FIRST(C) = \{c, d\}$
  • $FIRST(S) = FIRST(C) = \{c, d\}$
  • $FOLLOW(S) = \{\$\}$  (Start symbol rule)
  • $FOLLOW(C)$:
    • From production $S \to C C$, the first $C$ is followed by non-terminal $C$, so $FIRST(C) = \{c, d\} \subseteq FOLLOW(C)$.
    • The second $C$ is at the end of $S \to C C$, so $FOLLOW(S) = \{\$\} \subseteq FOLLOW(C)$.
    • Therefore: $FOLLOW(C) = \{c, d, \$\}$.

5. SLR(1) Table Construction Rules

SLR(1) Parsing Table Construction Algorithm For each state $i$ corresponding to item set $I_i$ in the canonical collection:
1. Shift: If $[A \to \alpha \cdot a \beta] \in I_i$ and $GOTO(I_i, a) = I_j$ (where $a$ is a terminal), set ACTION[i, a] = $s_j$.
2. Reduce: If $[A \to \alpha \cdot] \in I_i$ (where $A \neq S'$), set ACTION[i, a] = $r_k$ for all $a \in FOLLOW(A)$, where $k$ is the production number $A \to \alpha$.
3. Accept: If $[S' \to S \cdot] \in I_i$, set ACTION[i, \$] = acc.
4. Goto: If $GOTO(I_i, A) = I_j$ (where $A$ is a non-terminal), set GOTO[i, A] = $j$.
5. All undefined table cells are marked as Error (blank).

7. SLR Conflicts — The Classic Non-SLR Grammar

An SLR conflict occurs whenever an entry in the ACTION table receives multiple actions (either a Shift/Reduce conflict or a Reduce/Reduce conflict).

Classic Exam Proof: Why is this Grammar Not SLR(1)?

Consider the assignment grammar:

S → L = R  |  R
L → * R  |  id
R → L

Step 1: Augmented grammar adds $S' \to S$.

Step 2: Compute state $I_0$:

I₀ = CLOSURE({S' → • S}) =
     S' → • S
     S  → • L = R
     S  → • R
     L  → • * R
     L  → • id
     R  → • L

Step 3: Compute $I_2 = GOTO(I_0, L)$:

I₂ = S → L • = R
     R → L •

Step 4: Check conflicts in $I_2$:

  • Item $S \to L \cdot = R$ says: on input terminal =, SHIFT to next state ($s_6$).
  • Item $R \to L \cdot$ is complete, so it instructs: REDUCE by $R \to L$ on all terminals in $FOLLOW(R)$.
  • What is $FOLLOW(R)$? Since $S \Rightarrow L = R \Rightarrow * R = R$, the terminal = can legally appear after $R$ in a sentential form! Hence, = $\in FOLLOW(R)$ (along with $\$$).
  • Therefore, in State 2 on input =, the table contains BOTH Shift and Reduce by $R \to L$: $$\text{ACTION}[2, =] = \{s_6, r_{R \to L}\}$$

Conclusion: The grammar has an SLR Shift/Reduce conflict in State 2. Hence, this grammar is NOT SLR(1).

Why CLR/LALR Solves This

Although = is in $FOLLOW(R)$ in general, in the specific context of State $I_2$, we just saw $L$ at the very beginning of the string. $R$ can only follow $L$ if it is reduced in a valid derivation. For $S \to R$, the lookahead is strictly $, NOT =. CLR and LALR track exact context lookaheads and avoid this false conflict!

Check yourself

Retrieval practice

1. In SLR(1) parsing, on what set of terminals is a reduction $A \to \alpha$ placed in the ACTION table?

SLR relies on the coarse FOLLOW(A) set for all reductions. This is simpler than CLR, but can cause false conflicts when a terminal in FOLLOW(A) cannot legally follow A in that specific state.

2. An item set contains $[A \to \alpha \cdot a \beta]$ and $[B \to \gamma \cdot]$. An SLR Shift/Reduce conflict occurs if and only if:

The parser wants to shift on $a$ due to the first item, and simultaneously wants to reduce by $B \to \gamma$ on all terminals in $FOLLOW(B)$. If $a \in FOLLOW(B)$, cell ACTION[i, a] has both actions.

3. Why is an augmented grammar $S' \to S$ added prior to LR item construction?

Without $S' \to S$, if the start symbol $S$ appeared on the RHS of another rule, the parser could not distinguish between a sub-reduction and full sentence acceptance.

4. If a production is $A \to X_1 X_2 X_3$, how many distinct LR(0) items can be formed from it?

A production with $n$ RHS symbols produces $n + 1$ items corresponding to placing the dot before each symbol plus at the end.

Recall without looking

SLR parsing table construction rules.

Shift: If $[A \to \alpha \cdot a \beta] \in I_i$ and $GOTO(I_i, a) = I_j$, ACTION[i, a] = $s_j$.
Reduce: If $[A \to \alpha \cdot] \in I_i$, ACTION[i, a] = $r_k$ for every $a \in FOLLOW(A)$.
Accept: If $[S' \to S \cdot] \in I_i$, ACTION[i, \$] = acc.
Goto: If $GOTO(I_i, A) = I_j$, GOTO[i, A] = $j$.

Why does $S \to L = R \mid R$ cause an SLR Shift/Reduce conflict?

In state $I_2 = \{S \to L \cdot = R, R \to L \cdot\}$, the dot before $=$ indicates shift on $=$. The complete item $R \to L \cdot$ calls for reduce on all terminals in $FOLLOW(R)$. Because $S \Rightarrow L = R \Rightarrow *R = R$, the terminal $=$ is in $FOLLOW(R)$, triggering both shift and reduce on $=$.
