Definitions verbatim

Translator: a program converting a program in a source language into an equivalent program in a target language.

Compiler: reads a high-level program and translates it as a whole into an equivalent low-level program, reporting errors during translation.

Interpreter: directly executes the operations of the source program, statement by statement, on inputs supplied by the user — producing no target program.

The language processing system — draw vertically, label what flows source with directives → PREPROCESSOR → modified source → COMPILER → target assembly → ASSEMBLER → relocatable machine code → LINKER / LOADER (← libraries) → target machine code

Preprocessor expands macros and includes — output still high-level. Assembler → relocatable machine code (addresses relative to an unfixed start). Linker resolves external references. Loader places it in memory and fixes addresses.

Six translators: compiler · interpreter · assembler · cross-compiler (runs on A, targets B) · decompiler / disassembler · preprocessor (the only one whose target = its source language). Transpiler = high-level to high-level.

Java hybrid: javac → machine-independent bytecode → interpreted by the JVM, with JIT compiling hot paths to native code.

Analysis (front end) = source-dependent, machine-independent; builds the IR and fills the symbol table. Synthesis (back end) = machine-dependent, source-independent. Payoff: m languages and n machines need m + n components, not m × n.

The trace of position = initial + rate * 60 — memorise all six outputs 1. Tokens: ⟨id,1⟩ ⟨=⟩ ⟨id,2⟩ ⟨+⟩ ⟨id,3⟩ ⟨*⟩ ⟨60⟩  (1,2,3 are symbol-table pointers)

2. Syntax tree: = at the root; left ⟨id,1⟩; right + over ⟨id,2⟩ and (* over ⟨id,3⟩ and ⟨60⟩)

3. Semantic: same tree with an inttofloat node inserted above ⟨60⟩

4. Three-address code:   t1 = inttofloat(60)  ·  t2 = id3 * t1  ·  t3 = id2 + t2  ·  id1 = t3

5. Optimised:   t1 = id3 * 60.0  ·  id1 = id2 + t1   (four instructions become two)

6. Code:   LDF R2, id3 · MULF R2, R2, #60.0 · LDF R1, id2 · ADDF R1, R1, R2 · STF id1, R1

Symbol table — a record per name with its attributes, designed for fast lookup (a hash table). Stores name, type, scope, storage size and location, and for procedures the argument count and types. Created by phase 1, filled and read by phase 3, read by phase 6.

Error handler goals: report clearly and accurately · recover fast enough to find further errors · add little overhead to correct programs.

Phase vs pass: a phase is a logical operation transforming one representation into another — there are six. A pass is one complete traversal of the program, and several phases may share one pass. Typical: six phases in three passes. Pascal was designed for one pass, which is why declarations must precede use.

Imperative = HOW (C, Java, Python). Declarative = WHAT (SQL, Prolog, Haskell). von Neumann (program counter + mutable storage) vs object-oriented (Simula 67 first). Scripting = interpreted glue languages.

Static = decidable by reading the program text (also lexical scoping); dynamic = needs the program running. Environment maps name → location; state maps location → value.

Applications of compiler technology five headings

  1. Implementation of high-level languages — the abstraction a language can afford is limited by how well a compiler optimises it. C's register keyword became obsolete once register allocation was solved.
  2. Optimisations for computer architectures — parallelism (instruction-level pipelining and VLIW; processor-level loop parallelisation) and memory hierarchies (loop reordering for cache locality).
  3. Design of new computer architectures — RISC succeeded because compilers schedule simple instructions better than humans; VLIW, SIMD and GPUs depend entirely on compiler support.
  4. Program translations — binary translation, hardware synthesis (Verilog → circuits), database query interpreters, compiled simulation.
  5. Software productivity tools — type checking, bounds checking, memory-management tools such as garbage collectors and Valgrind.

Transition diagrams

Conventions: circles are states · one start state with an incoming arrow · double circle = accepting, with the action beside it · asterisk * = one extra character was read; retract the input pointer by one · edge labelled other = any character not otherwise covered.

Relational operators: from state 0 on < → 1; then = → LE, > → NE, other → LT with retract. On = → EQ. On > → 6; then = → GE, other → GT with retract.

Bootstrapping the examinable one

T-diagram notation and the composition rule A compiler is (Source, Target, Implementation) — left arm what it reads, right arm what it produces, bottom what it is written in.

To RUN a compiler, its implementation language must be your machine.

(S, T, I)  compiled by  (I, M, M)  →  (S, T, M)
Only the implementation arm changes. If your SOURCE arm ever changes, you have made a mistake.
Two-step bootstrap — no compiler exists for L on M
1Hand-write (S, M, M) for a small subset S of L, in machine code
2Write (L, M, S) — the full compiler, in the subset S
3Compile 2 with 1 → (L, M, M). Then optionally rewrite in L as (L,M,L) and recompile — self-hosting
Three-step cross-compiler — have (L, A, A), want (L, B, B)
1Retarget the back end, in L(L, B, L)Runs on nothing
2Compile it with (L, A, A)(L, B, A)The CROSS-COMPILER — runs on A, emits B
3Compile (L,B,L) with (L,B,A)(L, B, B)Move it to machine B

Advantages: written in a high-level language, so easier to write and maintain · it tests itself · portability — retarget once. Disadvantages: the initial subset compiler must be hand-written · an early bug propagates invisibly · slow and awkward to debug.

Just-in-time compilation

Definition: compilation performed during execution, translating bytecode into native machine code immediately before it runs, and caching the result. Also called dynamic translation.

How: AOT-compile to bytecode → VM starts interpreting → profiles execution → code crossing a threshold is a hot spot and is compiled natively → cached → run-time information allows optimisations a static compiler cannot make, guarded by deoptimisation.

 AOTInterpreterJIT

JIT costs: warm-up delay · compilation time counts against run time · higher memory · unpredictable timing, so unsuitable for hard real-time.
