The lexical analyser

Primary task: read the character stream, group characters into lexemes, and emit a token ⟨token-name, attribute-value⟩ for each. It runs as a subroutine of the parser (called via getNextToken), not a separate pass.

Other jobs: strip whitespace and comments · count newlines so errors get line numbers · enter identifiers into the symbol table · sometimes expand macros.

Token, pattern, lexeme — the one-line test PATTERN = the RULE (a regular expression).   LEXEME = the actual TEXT in the file.   TOKEN = the CATEGORY the parser is told about.

“The lexeme count matches the pattern for identifiers, so the analyser emits the token ⟨id, ptr⟩.”

Attributes: identifier → pointer to its symbol-table entry · number → its value · comparison operator → a code (LT, LE, EQ, NE, GT, GE) · keywords and punctuation → none.

Each keyword is its OWN token; all comparison operators share one token, distinguished by attribute.

Three reasons to separate lexical from syntax analysis SIMPLICITY of design · EFFICIENCY — specialised buffering can be applied to the character-reading task · PORTABILITY — input-device and character-set peculiarities are confined to one phase.

The deeper reason: tokens form a regular language recognisable by a finite automaton; syntax is context-free and needs a stack.

Token counting four rules

1. A double-quoted string literal is ONE token, however long. 2. Every punctuation mark counts separately. 3. Multi-character operators (<=, ==, ++, **) are one token each. 4. Whitespace and comments are not tokens. Check whether the question says distinct.

Lexical errors occur only when no pattern matches — illegal character, unterminated string, malformed number. fi for if is not a lexical error (it is a valid identifier). Recovery: panic mode — delete characters until a well-formed token appears (simplest and most used) · minimal-distance: delete, insert, replace, transpose one character.

Input buffering

Why: speed (the only phase reading character by character) and lookahead (cannot decide the token without reading past the lexeme, then retracting).

One buffer fails when a lexeme straddles the end — a reload destroys the scanned part.

Buffer pairs Two halves of N characters, N = one disk block (1024 or 4096), each filled by one read command, used alternately and cyclically.
lexemeBegin — start of the current lexeme.   forward — scans ahead.
Cost: TWO tests per character. Requires no lexeme longer than N.
With sentinels — the code, and the point Each half becomes N + 1 characters, the extra one holding eof, which cannot appear in the source.

forward = forward + 1;
if ( *forward == eof ) {
    if (at end of first half) { reload second half; forward++; }
    else if (at end of second half) { reload first half; forward = start of first half; }
    else terminate lexical analysis;  /* real eof */
}
Two tests per character become ONE. And the same test detects genuine end of input.

Numerical — 100,000 characters, N = 4096: reads = ⌈100000/4096⌉ = 25, the same either way. Tests without sentinels = 2 × 100000 = 200,000; with sentinels = 100000 + 2×25 = 100,050. Saving ≈ 50 %. Character-at-a-time reading would need 100,000 system calls instead of 25.

Operations: union · concatenation LM · L* = ∪Li from 0, always contains ε · L+ = ∪Li from 1.   L* = L+ ∪ {ε},   L+ = LL* = L*L.

Regular expressions Basis: ε denotes {ε}; each symbol a denotes {a}.
Induction: (r)|(s) → L(r) ∪ L(s) · (r)(s) → L(r)L(s) · (r)* → (L(r))* · (r) → L(r).

Precedence, highest first: *  >  concatenation  >  | — all left-associative. So a | b*c means a, or zero-or-more b's then c.

Laws: | is commutative, associative, idempotent · concatenation is associative and distributes over | · εr = rε = r · r** = r* · r* = (r|ε)*. Concatenation is NOT commutative.

The four conversions all worked on (a|b)*abb

1. Thompson's construction — RE to NFA ε and a: two states with that edge.   s|t: new start with ε to both sub-starts, ε from both sub-finals to a new final.   st: merge N(s)'s final with N(t)'s start — no new states.   s*: new start i and final f, with ε i→start, ε final→start (loop), ε final→f, ε i→f (bypass).

Properties: one start and one accepting state · no edge in to start, none out of final · at most two edges leave any state · at most 2|r| states.

NFA for (a|b)*abb — 11 states, start 0, accepting 10:
0→ε→1,7 · 1→ε→2,4 · 2→a→3 · 3→ε→6 · 4→b→5 · 5→ε→6 · 6→ε→1,7 · 7→a→8 · 8→b→9 · 9→b→10

2. Subset construction — NFA to DFA ε-closure(s) = states reachable from s on ε alone, including s.   move(T, a) = states reachable on a, following no ε.

Start = ε-closure(s0). For each unmarked T and symbol a: U = ε-closure(move(T, a)) — move FIRST, then close. A state is accepting iff it contains any accepting NFA state.

3. Minimisation by partitioning Two states are equivalent if no string distinguishes them. The minimal DFA is unique.

Π0 = { non-accepting, accepting }; split any group whose members go to different groups on some symbol; stop when a full pass causes no split; then remove dead and unreachable states.

Worked: Π0 = {{A,B,C,D},{E}} → on b, D reaches E, so Π1 = {{A,B,C},{D},{E}} → on b, B reaches {D}, so Π2 = {{A,C},{B},{D},{E}}, stable. Five states become four; A and C merge.

Start = firstpos(root); from S on a, next = ∪ followpos(p) for every p in S whose symbol is a; accepting iff it contains the # position.

Lex

Structure — three sections, separated by %% declarations (regular definitions; C code in %{ … %} copied verbatim)
%%
translation rules — Pattern   { Action }
%%
auxiliary functions (C, often main())

Pipeline: lex.l → Lex compiler → lex.yy.c → C compiler → a.out → input → tokens.

Names: yytext = the lexeme matched · yyleng = its length · yylval = the attribute for the parser · yylex() = the generated scanner · yywrap() — 1 = stop, 0 = another file follows · yyin/yyout · ECHO = default action · yyless(n) pushes back.

Conflict resolution — in this order RULE 1: LONGEST MATCH.    RULE 2: FIRST RULE LISTED, only to break a tie.

Input if → both match 2 chars → tie → rule 2 → IF.
Input ifx → {id} matches 3 vs 2 → rule 1 → ID.
Hence keyword rules must be listed BEFORE the identifier rule.

How Lex works: Thompson NFA per pattern → combined under a new start with ε to each, accepting states labelled with their pattern → subset construction (or direct followpos). Rule 2 = label a multi-accepting DFA state with the earliest pattern. Rule 1 = keep running past accepting states, remember the last one and retract to it.

Lookahead r1 / r2 matches r1 only when followed by r2, and r2 is not part of the lexeme (the Fortran DO case).
